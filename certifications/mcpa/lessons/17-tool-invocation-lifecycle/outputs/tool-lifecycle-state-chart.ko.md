# 도구 호출 수명 주기 상태 차트

MCPA '상호작용과 실행' 도메인을 위한 한 페이지 참고 자료입니다. MCP 2026-07-28 기준입니다. 수명 주기나 오류 처리 코드를 쓸 때 클라이언트나 서버 구현 곁에 두고 보세요.

## 여덟 개의 체크포인트

| 체크포인트 | 와이어에 오르나 | 무엇을 결정하나 | 어떻게 끝나나 |
|---|---|---|---|
| Discover | 예, `server/discover`(캐시 가능) | 서버가 제공하는 버전과 기능(capabilities) | 클라이언트 버전이 지원되지 않으면 `-32022` |
| List | 예, `tools/list`(캐시 가능, 결정적 순서) | 어떤 도구, 스키마, 어노테이션이 존재하는지 | 도구 관련 사항 없음. 안정적인 목록 |
| Select | 아니요 | 이미 손에 쥔 컨텍스트에서 모델이 어떤 도구를 고르는지 | 해당 없음. 전적으로 호스트 안에서 |
| Confirm | 아니요 | 호출이 아직 보내지기도 전에 사람이 승인하는지 | 거부되면 수명 주기가 그냥 여기서 끝남 |
| Call | 예, `tools/call` | 요청이 실제로 클라이언트를 떠남 | 아직 아무것도 없음. 다음 체크포인트를 시작할 뿐 |
| Validate | 새 메시지 없음. 응답을 가로지름 | 서버가 이 이름의 도구를 노출하는지 | 모르면 프로토콜 오류 `-32602`, 실행도 결과도 없음 |
| Execute | 새 메시지 없음. 응답을 가로지름 | 인자가 스키마에 맞는지, 핸들러가 성공하는지 | 잘못된 입력이나 비즈니스 실패에는 `isError` 결과. 진짜 예상치 못한 고장에만 `-32603` |
| Result | 예, `tools/call`에 대한 응답 | `resultType`은 `complete` 또는 `input_required` | `input_required`는 호출로 되돌아감. `complete`가 최종 |

## 두 개의 오류 채널

| 채널 | 모양 | 쓰이는 곳 | 모델이 스스로 고칠 수 있나 |
|---|---|---|---|
| 프로토콜 오류 | JSON-RPC `error` | 모르는 도구(`-32602`), 잘못된 형식의 요청, 진짜 서버 고장(`-32603`) | 아니요. 그래서 클라이언트가 맹목적으로 재시도해서는 안 됨 |
| 도구 실행 오류 | `isError: true`를 담은 complete 결과 | 잘못된 인자, 업스트림 API 실패, 비즈니스 규칙 위반 | 예. 이런 일을 위해 만들어진 채널 |

경험 법칙: validate는 프로토콜 오류만 낳습니다. execute는 거의 언제나 도구 실행 오류를 낳고, 호출자의 입력으로는 어차피 막을 수 없었던 고장일 때만 프로토콜 오류에 손을 뻗습니다.

## 일시 정지, 취소, 재발행

| 상황 | 무슨 일이 일어나나 | 호출자가 하는 일 |
|---|---|---|
| `resultType: "input_required"` | 서버에 입력이 더 필요함. `inputRequests`, `requestState`, 또는 둘 다 포함됨 | 새 JSON-RPC id로 재시도. 맞춰진 `inputResponses` 키, `requestState`는 바이트 그대로 에코 |
| 하드 타임아웃 | 이 시도에 대한 resultType은 끝내 나오지 않음 | Streamable HTTP: 요청의 스트림을 닫음. stdio: `requestId`와 선택적 이유를 실어 `notifications/cancelled` 전송 |
| 끊어진 스트림 | 요청과 그 결과가 모두 잃어버림. 여기선 아무것도 재개할 수 없음 | 새 id로 재발행. 부수 효과가 있는 호출을 반복하기 전에 `idempotentHint`를 보장이 아니라 힌트로 취급 |
| 취소 후 늦게 도착한 응답 | 호출자가 이미 포기한 id에 결과나 오류가 여전히 도착함 | 무시함 |

## tools/call 경로를 출시하기 전 체크리스트

- 모르는 도구 이름은 언제나 `-32602`를 돌려준다. 절대 `-32601`이 아니다.
- 인자 스키마 실패와 비즈니스 규칙 실패는 `isError: true` 결과로 돌아온다. JSON-RPC 오류로 오는 일은 없다.
- 재시도를 포함한 모든 요청은 `_meta`에 프로토콜 버전과 클라이언트 기능(capabilities)을 실는다.
- `input_required` 이후의 모든 재시도는 새 id를 쓰고 `requestState`를 바이트 단위로 에코한다.
- 끊어진 스트림 이후의 모든 재발행은 새 id를 쓰고, 부수 효과가 있는 도구는 명시적이고 불투명한 핸들을 돌려준다. 그래야 재발행이 추측 대신 상태를 다룰 수 있다.
- 타임아웃에는 진행 알림이 계속 도착하는 동안에도 적용되는 하드 최대치가 있다.
- stdio에서의 취소는 알림이지 답을 기다리는 요청이 아니다.
