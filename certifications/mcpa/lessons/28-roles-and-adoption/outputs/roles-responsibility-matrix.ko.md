# 역할과 책임 매트릭스

MCPA '사용 사례와 생태계' 도메인을 위한 한 페이지 참고 자료입니다. MCP 2026-07-28 기준입니다.

## 여섯 개의 역할

| 역할 | 소유하는 것 |
|------|------|
| 서버 작성자 | 구현 자체: 도구, 스키마, server/discover, 스테이트리스 |
| 호스트·클라이언트 개발자 | 애플리케이션과 그 클라이언트: 기능(capability) 선언, OAuth 클라이언트, 동의 화면 |
| 플랫폼·게이트웨이 운영자 | 실행 중인 프로세스: stdio 환경, 연결 종료, 네트워크 정책, 가장자리에서의 헤더 검사 |
| 보안·거버넌스 책임자 | 한 구현자가 소유하지 않는 횡단 요구 사항: 토큰 처리, requestState 보호, 동의 정책 |
| 레지스트리 게시자 | server.json, 네임스페이스 검증, 레지스트리가 서버에 대해 서비스하는 내용 |
| 최종 사용자 | 동의. 호스트가 자기를 대신해 하는 일에 대한 책임 당사자 |

## 세 가지 도입 경로

| 경로 | 무엇이 달라지나 |
|------|---------------|
| 로컬 stdio | 만들 OAuth 클라이언트가 없음. 운영자가 프로세스 시작 전에 환경으로 자격 증명을 공급 |
| OAuth를 붙인 원격 Streamable HTTP | 서버 작성자가 Protected Resource Metadata와 Origin 검증을 직접 구현. 호스트·클라이언트 개발자가 OAuth 클라이언트와 Resource Indicators를 구현 |
| 확장을 곁들인 게이트웨이 앞의 엔터프라이즈 | Origin 검증과 헤더 검사가 플랫폼·게이트웨이 운영자 쪽으로 이동. 보안·거버넌스 책임자가 게이트웨이가 강제할 정책을 정함. 확장 지원은 조직의 허용 목록이 됨 |

## 실전 예제: Origin 검증

Streamable HTTP 전송은 DNS 리바인딩 공격을 막기 위해 서버가 들어오는 모든 연결의 Origin 헤더를 반드시(MUST) 검증한다고 말합니다. 순수 HTTP: 서버 작성자가 소유합니다. 요청이 처음 닿는 것이 서버 자신의 코드이기 때문입니다. 게이트웨이 앞: 플랫폼·게이트웨이 운영자가 소유합니다. 게이트웨이가 연결을 먼저 종료하기 때문입니다. 명세 속 요구 사항은 결코 움직이지 않았습니다. 소유자가 배포 형태와 함께 움직였을 뿐입니다.

## 거버넌스 한 페이지 요약

- 관리 주체: Agentic AI Foundation의 프로젝트.
- 위계: Lead Maintainers(최종 거부권) > Core Maintainers(명세와 프로젝트 방향) > Maintainers(각자 한 영역) > Contributors. 꾸준히 기여한 Contributor은 먼저 Member가 됩니다.
- 워킹 그룹(Working Group): 구체적인 산출물, 보통 SEP와 참조 구현을 만듭니다.
- 관심 그룹(Interest Group): 문제를 논의하고 구속력 없는 권고를 낼 뿐, 설계를 만들지는 않습니다.
- SEP 상태 경로: draft, in-review, 그리고 accepted 또는 rejected. 참조 구현과 필요한 적합성 테스트가 모두 자리 잡으면 final이 됩니다.
- 기능 수명 주기: Active, 이후 선택적으로 Deprecated(마이그레이션 경로 필수, 최소 12개월 기간), 그리고 언젠가 Removed.

## SDK 티어: 도입 판단 기준으로

| 티어 | 적합성 | 신규 기능 | 치명적 버그 |
|------|-------------|---------------|-----------------|
| Tier 1 | 100퍼센트 | 명세 릴리스와 함께 또는 그 이전 | 7일 안에 수정 |
| Tier 2 | 80퍼센트 | 6개월 안에 | 2주 안에 수정 |
| Tier 3 | 최소 기준 없음 | 일정 약속 없음 | 요구 사항 없음 |

## 시험을 위해 기억하기

- 호스트, 클라이언트, 서버는 와이어 토폴로지를 말합니다. 위의 여섯 역할은 실제 배포에서 어떤 요구 사항에 누가 책임지는지를 말합니다. 두 목록은 서로 다른 질문에 답합니다.
- 같은 MUST라도 배포 형태에 따라 다른 소유자를 가질 수 있습니다. 게이트웨이가 이전에는 지지 않아도 됐던 책임을 흡수합니다.
- 팀의 매트릭스에 소유자가 없는 MUST는 건너뛸 세부 사항이 아니라 메워야 할 빈틈입니다.
