# MCPA 준비도 체크리스트

MCP 2026-07-28을 위한 시험 전 체크리스트입니다. `certifications/mcpa/tracks/mcpa-f.json`에 맞춰져 있습니다. 가중치가 매겨진 다섯 도메인의 18개 학습 목표 전부가 여기에 나열되어 있고, 각각은 실제로 해볼 수 있는 형태로 바꿔 놓았습니다. 이 캡스톤의 트랜스크립트(`code/main.py`, `docs/en.md`)가 그것을 연습하는 곳을 가리키는 포인터나, 처음 가르친 이전 레슨을 함께 적어 두었습니다. 이 레슨 직후에 한 번, 그리고 시험 전날 밤에 다시 한 번 풀어 보세요.

## MCP 기초 (16퍼센트)

- [ ] MCP가 표준화하는 통합 문제, 즉 N 곱하기 M의 맞춤 통합이 N 더하기 M으로 무너져 드는 것, 그리고 프로토콜이 일부러 호스트 애플리케이션에 맡겨 두는 것을 설명할 수 있다. 레슨 02에서 처음 배움. 이 캡스톤은 돌리는 모든 교환의 배경 지식으로 가정한다.
- [ ] 호스트, 클라이언트, 서버, 프리미티브, 스테이트리스 JSON-RPC 요청 모델을 설명할 수 있다. 어떤 요청도 이전 요청이 세워둔 것에 기대면 안 되는 이유까지 포함해서. 레슨 04가 깊이 있게 다룬다. 이 캡스톤의 서버는 모든 호출에 새로운, 자기완결적인 요청으로 답한다.
- [ ] 프로토콜 버전 관리와, 시스템별 맞춤 통합보다 하나의 열린 프로토콜이 나은 이유를 추론할 수 있다. 직접 연습됨: 트랜스크립트의 첫 호출은 프로토콜 버전 2025-11-25를 썼다가 UnsupportedProtocolVersionError를 받고, 고쳐진 호출이 그제서야 진행된다.
- [ ] 명세와 그 리비전 이력과 그 기능 수명 주기를 읽어서 현재, 폐기, 제거된 동작을 구분할 수 있다. 레슨 01, 05, 15가 이것을 다룬다. 이 캡스톤은 제거된 메서드를 절대 쓰지 않으며 roots, sampling, logging을 사라진 것이 아니라 폐기된 것으로 다룬다.

## 아키텍처와 구성 요소 (14퍼센트)

- [ ] MCP 메시지, 도구 정의, 기능(capabilities), 서버 매니페스트를 정의하는 스키마와 구조화 데이터를 읽을 수 있다. 직접 연습됨: restart_service의 inputSchema는 빠진 환경 인자를 조용한 성공이 아니라 isError 결과로 바꾸는 존재다.
- [ ] 호스트, 클라이언트, 서버의 책임과 탐색·기능 협상이 그것들을 어떻게 연결하는지 구분할 수 있다. 직접 연습됨: server/discover가 어떤 클라이언트도 쓰기 전에 tasks 확장을 광고하고, 이후 모든 호출도 여전히 자신의 기능을 요청별로 선언한다.
- [ ] 사용자 요청이 호스트, 모델, 클라이언트, 서버를 지나 모델 컨텍스트로 돌아오는 모델 상호작용 흐름을 추적할 수 있다. 레슨 10이 전체 루프를 만든다. 이 캡스톤의 restart_service 시퀀스는 그 한 번의 구체적인 통과다. 요청, 스키마 검사, 동의, 결과.

## 상호작용과 실행 (26퍼센트)

- [ ] 요청, 알림, 구독, MRTR 상호작용 패턴을 적용하고 각 결과 타입을 처리할 수 있다. 직접 연습됨: 이 트랜스크립트는 한 번의 실행에서 complete, input_required, task 결과와 notifications/progress까지 내놓는다.
- [ ] 프로토콜 오류와 도구 실행 오류를 다룰 수 있다. 버전, 기능, 헤더, 검증 실패까지 포함해서. 직접 연습됨: 버전에는 -32022, 기능에는 -32021, 헤더 검사 영역인 -32020은 레슨 19에서 다루고, 검증 실패에는 isError true가 쓰인다. 모두 하나의 서버 안에서.
- [ ] 도구 호출 수명 주기를 탐색과 선택부터 호출, 사용자 입력, 진행, 취소, 결과까지 걸어갈 수 있다. 직접 연습됨: scan_fleet_health는 진행을 결과까지 실어 가고, restart_service는 사용자 입력을 MRTR을 통해 결과까지 전달하고, 두 번째 진단 태스크는 결과에 도달하기 전에 취소된다.
- [ ] 프로토콜 프리미티브와 유틸리티를 식별할 수 있다. 도구, 리소스, 프롬프트, completion, 캐싱, 페이지네이션, 전송 방식, 폐기된 클라이언트 기능. 이 캡스톤의 트랜스크립트 자체가 도구, 캐싱 힌트, stdio 방식과 Streamable HTTP 전송 양쪽을 다룬다. 리소스, 프롬프트, completion, 페이지네이션은 이 레슨이 반복하지 않는 깊이로 레슨 12, 13, 15, 20이 다룬다.

## 보안과 거버넌스 (24퍼센트)

- [ ] 호스트, 클라이언트, 서버, 모델, 그리고 서버가 노출하는 도구와 콘텐츠 사이의 신뢰 경계를 찾아낼 수 있다. 레슨 22가 경계를 이름 짓는다. 이 캡스톤의 acknowledge_incident 위의 OAuth 게이트가 와이어에서 강제되는 그 경계다.
- [ ] 사용자가 서버가 보고 할 수 있는 것을 승인하도록 OAuth 기반 인가, 클라이언트 등록, 스코프(scope), 동의를 적용할 수 있다. 직접 연습됨: 다른 리소스 서버 audience를 위해 발행된 bearer 토큰은 401로 거부되고, 올바른 스코프의 토큰은 성공한다. 레슨 23과 24가 이 호출이 가정하는 전체 인가·등록 흐름을 만든다.
- [ ] 도구 오염, 인젝션, 토큰 오용, 지나치게 넓은 접근에 대비한 위험·안전 통제를 고를 수 있다. 직접 연습됨: restart_service는 호출자의 말만으로는 절대 실행되지 않는다. 선언된 기능, 서명된 requestState, 명시적인 accept를 요구한다. 레슨 26이 더 넓은 통제 카탈로그를 다룬다.
- [ ] 프로토콜 활동이 추적되고 귀속되고 검토될 수 있도록 감사 가능성과 관측 가능성을 설계할 수 있다. 직접 연습됨: 하나의 W3C trace id가 이 트랜스크립트의 모든 홉을 꿰고, 해시로 사슬 지은 감사 로그는 누가 무엇을 했는지 기록하며 여전히 검증되거나, 그렇지 않다면 정확히 변조된 항목을 지목한다.

## 사용 사례와 생태계 (20퍼센트)

- [ ] MCP를 만들고 배포하는 팀들의 역할, 책임, 거버넌스, 도입 패턴을 짝지을 수 있다. 레슨 28이 깊이 있게 다룬다. 이 캡스톤의 incident-console은 운영 팀의 서버의 한 사례이지 장난감이 아니다.
- [ ] 운영 사용 사례와 각각에 어울리는 프리미티브나 확장을 고를 수 있다. 직접 연습됨: 빠른 읽기 전용 스캔은 평범한 호출로 남고, 파괴적인 재시작은 MRTR 동의를 받고, 긴 진단 순회는 tasks 확장을 받는다. 세 개의 다른 문제가 세 개의 다른 메커니즘에 맞는다. 레슨 29가 더 많이 카탈로그화한다.
- [ ] 클라이언트, 서버, SDK, 확장, 게이트웨이, 레지스트리를 넘나드는 생태계 이식성을 추론할 수 있다. 레슨 30부터 32까지가 이것을 만든다. 이 캡스톤의 확장 협상, 즉 capabilities에 있는 tasks 확장이 양쪽이 모두 선언할 때만 쓰이는 것은, 그 레슨들이 묘사하는 이식성 메커니즘이 동작하는 모습이다.

## 최종 시험 함정 복습

- 모르는 도구는 언제나 -32602이지 절대 -32601이 아니다. -32601은 서버가 진짜로 들어본 적 없는 JSON-RPC 메서드를 위해 남겨진 것이다.
- 스키마에 맞지 않는 도구 호출은 도구 실행 오류, isError true이지 프로토콜 오류가 절대 아니다.
- 2026-07-28에는 initialize 핸드셰이크도 세션도 없다. 모든 요청이 자기 프로토콜 버전과 기능(capabilities)을 실어 보낸다.
- MRTR 재시도는 언제나 새 JSON-RPC id를 쓰고 requestState를 정확히 에코한다. 원래 id의 재사용은 틀렸다.
- 리소스 not-found와 커스텀 애플리케이션 오류 둘 다, 규격을 따르는 2026-07-28 서버에서는 -32000부터 -32019와 -32020부터 -32099의 바깥에 있다.
- Roots, sampling, logging은 폐기됐지만 제거되지 않았다. 여전히 동작하며, 단지 새 설계의 출발점이 아니어야 할 뿐이다.
- 한 리소스 서버 audience를 위해 발행된 토큰은 다른 곳에서 절대 받아들여져서는 안 된다. 호출자의 토큰을 업스트림으로 전달하는 것은 금지다.
- cacheScope public은 응답이 사용자들을 넘나들며 공유될 수 있다는 뜻이지, 접근 통제를 건너뛰어도 안전하다는 뜻이 절대 아니다.
