# MCP 범위 브리프

MCPA 'MCP 기초' 도메인을 위한 한 페이지 참고 자료입니다. MCP 2026-07-28 기준입니다.

## 핵심 논리

공유 프로토콜이 없으면 AI 애플리케이션 N개와 시스템 M개를 연결하려면 N 곱하기 M개의 맞춤 통합이 필요합니다. MCP가 있으면 애플리케이션은 클라이언트를 한 번만, 시스템은 서버를 한 번만 구현하면 됩니다. 즉 N 더하기 M이죠. 애플리케이션 4개와 시스템 6개라면 통합 24개가 10개로 줄어들고, 새 시스템이 추가될 때 구현 4개 대신 1개만 하면 됩니다.

## MCP가 표준화하는 것

- 서버가 자신을 소개하는 방법: `server/discover`가 지원 버전, 기능(capabilities), 식별 정보를 돌려줍니다.
- 클라이언트가 서버의 능력을 알아내는 방법: `tools/list`, `resources/list`, `prompts/list`.
- 도구를 호출하고 결과와 오류를 받는 방법: `tools/call`, `CallToolResult`, JSON-RPC 오류.
- 모든 요청이 `params._meta`에 실어 보내는 요청 단위 메타데이터: 프로토콜 버전과 클라이언트 기능(capabilities)(필수), 클라이언트 식별 정보(권장).

## MCP가 애플리케이션에 맡기는 것

호스트가 어떤 모델을 쓰는지, 프롬프트를 어떻게 만드는지, 대화를 어떻게 화면에 그리는지, 사용자 승인을 언제 요청할지입니다.

## 참여자와 프리미티브

| 구성 요소 | 한 줄 설명 | 통제 주체 |
|------|--------------|---------------|
| 호스트(Host) | 사용자가 작업하는 애플리케이션 | 사용자 |
| 클라이언트(Client) | 호스트를 대신해 하나의 서버와 대화 | 호스트 |
| 서버(Server) | 도구, 리소스, 프롬프트를 노출 | 서버 운영자 |
| 도구(Tool) | 이름, 설명, 입력 스키마를 가진 동작 | 모델 |
| 리소스(Resource) | URI로 식별되는 읽을 수 있는 데이터 | 애플리케이션 |
| 프롬프트(Prompt) | 재사용 가능한 템플릿 | 사용자 |

## 두 개의 오류 채널

| 상황 | 채널 | 예 |
|-----------|---------|---------|
| 요청 자체가 잘못됨 | JSON-RPC 오류 | 모르는 도구: `-32602` |
| 도구가 모델이 고칠 수 있는 문제에 부딪힘 | `isError: true`를 담은 결과 | 인자 누락 또는 잘못됨 |
| 요청이 서버에 없는 버전을 사용함 | JSON-RPC 오류 | `data.supported`를 담은 `-32022` |

## 시험을 위해 기억하기

- 2026-07-28에는 `initialize` 핸드셰이크도 세션도 없습니다.
- 모든 결과에는 `resultType`이 들어 있습니다.
- 모르는 도구는 `-32601`이 아니라 `-32602`입니다.
