# 리소스 설계 가이드

MCP 리소스를 설계하고 검토하기 위한 한 페이지 참고 자료입니다. MCP 2026-07-28 기준입니다.

## 세 가지 메서드

| 메서드 | 돌려주는 것 | 캐시 가능 |
|---|---|---|
| `resources/list` | 호출자에게 보이는 리소스 카탈로그: uri, name, description, mimeType, icons | 예: ttlMs, cacheScope |
| `resources/templates/list` | 리소스 군(family)을 위한 RFC 6570 URI 템플릿 | 예: ttlMs, cacheScope |
| `resources/read` | 주어진 uri에 대한 `contents` 안의 콘텐츠 항목 하나 이상 | 예: ttlMs, cacheScope |

## URI 스킴 고르기

| 스킴 | 이럴 때 사용 | 비고 |
|---|---|---|
| `https://` | 능력이 되는 클라이언트가 웹에서 직접 같은 바이트를 가져올 수 있을 때 | 콘텐츠로 가는 길이 서버뿐이라면 다른 스킴이 낫다 |
| `file://` | 콘텐츠가 파일시스템처럼 동작할 때 | 실제 파일시스템에 대응할 필요는 없음. 모든 경로 세그먼트를 살균(sanitize)할 것 |
| `git://` | 콘텐츠가 버전 관리될 때 | ref는 쿼리 문자열이 아니라 authority나 경로로 식별할 것 |
| 커스텀 | 그 밖의 모든 것 | RFC 3986을 따라야 함. 서버의 도메인으로 네임스페이스화할 것 |

## 콘텐츠 형태

- 텍스트: `{"uri": ..., "mimeType": ..., "text": ...}`
- 바이너리: `{"uri": ..., "mimeType": ..., "blob": "<base64>"}`
- 한 번의 read가 `contents`에 항목을 둘 이상 돌려줄 수 있습니다(예: 디렉터리 같은 리소스가 그 아래 모든 파일을 돌려주는 경우).

## 오류 처리 체크리스트

- [ ] 없거나 잘못된 리소스는 JSON-RPC 오류 `-32602`(Invalid params)를 돌려준다. 절대 `-32601`도 `-32002`도 아니다.
- [ ] `error.data.uri`가 요청받은 리소스를 지목한다.
- [ ] 없는 리소스가 빈 `contents` 배열을 담은 complete 결과로 돌아오는 일은 없다.
- [ ] 내부 실패는 리소스 모양의 오류가 아니라 `-32603`을 쓴다.
- [ ] 클라이언트는 오래된 서버의 구버전 `-32002`도 여전히 알아들을 수 있어야 한다. 2026-07-28 서버가 그것을 내보내서는 안 되더라도.

## 캐시 스코프 판단 표

| 콘텐츠 | cacheScope | 일반적인 ttlMs |
|---|---|---|
| 호출자와 무관하게 똑같은 공개 카탈로그나 체인지로그 | `public` | 몇 분에서 몇 시간 |
| 인증된 호출자에 따라 달라지는 리소스 | `private` | 몇 초에서 몇 분 |
| 읽을 때마다 바뀌는 콘텐츠 | 아무거나 | `0` |

`cacheScope`는 공유 경계이지 접근 통제가 아닙니다. 캐시 힌트가 뭐라 하든 모든 읽기는 인가하세요.

## 보안 체크리스트

- [ ] 모든 URI가 저장소나 데이터베이스 쿼리에 닿기 전에 검증한다.
- [ ] 가상의 루트를 기준으로 경로 세그먼트를 살균한다(예: `posixpath.normpath("/" + tail)`). 그래야 `..` 시퀀스가 그 루트 밖으로 빠져나갈 수 없다.
- [ ] 읽기마다 개별적으로 인가한다. `resources/list`에 보인다고 해서 모든 호출자가 읽을 수 있는 게 아니다.
- [ ] 바이너리 콘텐츠는 `blob`에 base64로 담는다. 원시 바이트를 `text`에 박아 넣지 않는다.
- [ ] 리소스 콘텐츠는 모델에 도달하면 지시문이 아니라 신뢰할 수 없는 데이터로 취급한다.

## 시험을 위해 기억하기

- 리소스는 애플리케이션이 이끕니다. 컨텍스트에 언제 들어갈지 고르는 건 모델이 아니라 호스트입니다.
- `-32602`가 현대식 not-found 코드이며 `data.uri`를 실어 옵니다. `-32002`는 구버전 전용입니다.
- 빈 `contents` 배열은 없는 리소스를 알리는 유효한 방법이 절대 아닙니다.
- `resources/read`는 complete 결과가 `ttlMs`와 `cacheScope`를 반드시 실어야 하는 여섯 연산 중 하나입니다.
- 현대식 구독 요청은 `subscriptions/listen`에 `resourceSubscriptions` 필터를 쓰는 것이지, 은퇴한 `resources/subscribe`가 아닙니다.
