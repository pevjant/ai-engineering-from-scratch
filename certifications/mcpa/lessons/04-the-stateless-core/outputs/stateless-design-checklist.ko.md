# 스테이트리스 설계 체크리스트

MCPA 'MCP 기초' 도메인을 위한 한 페이지 체크리스트입니다. MCP 2026-07-28 기준입니다.

## 불변의 원칙

모든 요청은 서버가 답을 하는 데 필요한 모든 것을 실어 보냅니다. 서버는 기능(capabilities), 프로토콜 버전, 식별 정보를 이전 요청에서 유추하면 안 됩니다. 같은 연결 위에서 온 요청이라도 마찬가지입니다.

## 스테이트리스가 주는 이점

- 어떤 복제본(replica)이든 어떤 요청이든 처리할 수 있습니다. 고정 세션도 없고, 동기화해 둘 인스턴스별 메모리도 없습니다.
- 연결이 끊겨도 다른 복제본에 안전하게 재시도할 수 있습니다. 그곳에는 아무것도 저장해 둔 게 없기 때문입니다.
- 로드 밸런서가 세션 어피니티가 아니라 평범한 규칙으로만 라우팅하면 됩니다.

## 연결 vs 세션

| 질문 | 답 |
|---|---|
| 열려 있는 stdio 프로세스나 HTTP 연결이 세션을 만드는가? | 아니요. 클라이언트는 하나의 전송(transport) 위에서 서로 관련 없는 요청들을 섞어 보낼 수 있습니다. |
| tools/list, resources/list, prompts/list가 연결마다 달라질 수 있는가? | 아니요. |
| 같은 요청에 실려 온 인가(authorization)에 따라서는 달라질 수 있는가? | 예. 그건 연결 상태가 아니라 요청별 입력입니다. |
| 서버가 이전 호출의 부수 효과로 도구 목록을 바꿀 수 있는가? | 아니요. 도구는 무조건 노출하고, 핸들(handle) 인자로 접근을 통제하세요. |

## 서버가 발급한 핸들로 상태를 갖는 도구 설계하기 (SEP-2567)

1. 생성 도구(예: create_basket)를 노출하고, structuredContent에 불투명한(opaque) 핸들을 담아 돌려줍니다.
2. 그 상태를 다루는 모든 도구는 그 핸들을 평범한 인자로 받아들입니다.
3. 호출할 때마다 핸들 기준으로 호출자를 인가합니다. 핸들은 이름일 뿐, 권한(capability)이 아닙니다.
4. 핸들의 수명을 생성 도구 설명에 적어 둡니다. 모델이 상태를 만들기 전에 정책을 보게 하기 위해서입니다.
5. 핸들이 만료됐거나, 모르는 핸들이거나, 남의 핸들이라면 핸들 이름을 밝히는 도구 실행 오류(isError: true)를 돌려줍니다. 그래야 모델이 새 핸들을 만들어 복구할 수 있습니다.

## 출시 전 체크리스트

- [ ] 모든 요청 핸들러가 params._meta에서 protocolVersion과 clientCapabilities를 읽는다. 연결 위 이전 요청에서 읽는 건 아무것도 없다.
- [ ] tools/list, resources/list, prompts/list는 인가 조건이 같다면 어느 연결이 물었든 같은 결과를 돌려준다.
- [ ] 어떤 도구 호출도 이후 list 호출의 결과를 바꾸지 않는다. 조건부 도구는 무조건 노출하고 핸들 인자로 접근을 통제한다.
- [ ] 호출 간 상태는 명시적이고 불투명한 서버 발급 핸들로 참조하며, 이 핸들은 평범한 인자로 전달된다. 연결 식별 정보로 유추하지 않는다.
- [ ] 핸들의 인가, 불투명성, 수명 정책이 생성 도구에 문서화되어 있다.
- [ ] 만료된 핸들, 모르는 핸들, 남의 핸들에는 설명을 붙인 isError: true를 돌려준다. JSON-RPC 오류가 아니다.
- [ ] 서버는 clientInfo, serverInfo, 그 밖의 스스로 보고한 어떤 필드로도 인가 판단을 하지 않는다.
- [ ] 오케스트레이터와 그 서브에이전트처럼 같은 인증 주체의 두 연결은 동일한 list 결과를 보며 캐시를 공유할 수 있다.

## 2026-07-28에서 제거된 것

- initialize 요청과 notifications/initialized: 여는 핸드셰이크가 없습니다.
- Mcp-Session-Id 헤더와 프로토콜 수준 세션.
- 연결에 묶인 기능(capabilities): 이제 기능은 요청마다 `_meta`로 이동합니다.

## 시험을 위해 기억하기

- 스테이트리스는 프로토콜의 기본 동작이지, 골라 쓰는 옵션이 아닙니다.
- 핸들은 도구 결과에서 평범한 문자열이고 도구 인자에서도 평범한 문자열입니다. 프로토콜 자체는 핸들 타입이나 전송 형식을 정의하지 않습니다.
- 오래된 자료의 '세션' 표현은 이미 제거된 개념을 말하는 것이지 현재 동작이 아닙니다.
