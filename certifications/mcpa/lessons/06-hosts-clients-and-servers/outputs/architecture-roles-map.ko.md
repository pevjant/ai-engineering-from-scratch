# 아키텍처 역할 지도

MCPA '아키텍처와 구성 요소' 도메인을 위한 한 페이지 참고 자료입니다. MCP 2026-07-28 기준입니다.

## 세 명의 참여자

| 역할 | 정체 | 담당하는 것 |
|------|------------|------------------|
| 호스트(Host) | 사용자가 작업하는 애플리케이션 프로세스(채팅 어시스턴트, IDE, 배치 파이프라인) | 클라이언트 생성·관리, 보안과 동의 강제, 여러 서버의 컨텍스트 통합, 모델 조율 |
| 클라이언트(Client) | 호스트가 만드는 객체로, 서버 연결 하나당 하나 | 모든 요청에 프로토콜 버전과 기능(capabilities) 붙이기, 한 서버의 데이터를 다른 서버와 격리 유지 |
| 서버(Server) | 컨텍스트와 기능을 노출하는 별도 프로그램 | 도구·리소스·프롬프트·completion 구현, 자신의 기능 선언, 전체 대화는 절대 못 봄 |

기억할 규칙: 클라이언트 하나, 연결 하나, 서버 하나. 서버 다섯 개에 연결된 호스트는 클라이언트 다섯 개를 돌립니다. 클라이언트 하나가 다섯 서버의 대화를 굴리는 게 절대 아닙니다.

## 로컬 서버 vs 원격 서버

| | 로컬 서버 | 원격 서버 |
|---|---|---|
| 전송 방식 | stdio(서브프로세스, 줄바꿈으로 구분된 JSON-RPC) | Streamable HTTP(메시지마다 POST, 선택적으로 SSE) |
| 신뢰가 걸리는 경계 | 프로세스 경계, 같은 머신 | 네트워크 경계, 별개의 오리진 |
| 일반적인 클라이언트 수 | 보통 프로세스 수명 내내 클라이언트 하나 | 여러 호스트 인스턴스에 걸쳐 클라이언트가 많은 경우가 많음 |
| 자격 증명 | 환경에서 읽음. stdio 구현체는 OAuth 흐름을 돌리지 말아야 함 | OAuth 2.1 흐름의 Bearer 토큰이 권장 경로 |

## 서버 기능 vs 클라이언트 기능

| 기능 | 쪽 | 통제 주체 | 2026-07-28 상태 |
|---|---|---|---|
| Tools | 서버 | 모델 | Active |
| Resources | 서버 | 애플리케이션 | Active |
| Prompts | 서버 | 사용자 | Active |
| Completion | 서버 | 애플리케이션(인자 자동완성) | Active |
| Elicitation | 클라이언트 | MRTR 왕복을 통한 사용자 | Active |
| Sampling | 클라이언트 | 사용자 승인, 클라이언트가 중개 | Deprecated, LLM 제공자 API 직접 호출로 전환 |
| Roots | 클라이언트 | 호스트, 참고용일 뿐 | Deprecated, 도구 매개변수·리소스 URI·서버 설정으로 전환 |

## 서버가 많은 호스트를 위한 통합(aggregation) 체크리스트

1. 연결된 모든 서버를 `server/discover`로 각각 독립적으로 탐색합니다. 한 서버의 기능이 다른 서버에도 적용된다고 가정하지 마세요.
2. 도구 레지스트리는 실제로 `tools` 기능을 선언한 서버만을 대상으로 `tools/list`에서 만듭니다.
3. 모든 레지스트리 항목과 모든 라우팅 판단의 키는 호스트가 연결할 때 직접 부여한 연결 식별자(설정 키나 슬롯 인덱스 등)로 합니다. `serverInfo.name`을 키로 쓰면 안 됩니다. 스스로 보고한 값이고, 따로 만들어진 두 서버가 같은 이름을 보고할 수 있습니다.
4. 도구 이름은 서버 안에서는 유일해야 하지만, 서버끼리는 충돌을 예상해야 합니다. 충돌이 나면 첫 번째 서버의 이름을 정식(canonical) 항목으로 유지하고, 이후 충돌들은 `<server-id>/<tool-name>` 형태로 노출합니다.
5. 호출은 레지스트리 항목을 찾아본 뒤, 그 항목을 소유한 하나의 연결로 `tools/call`을 보내는 방식으로 라우팅합니다. 받는 서버는 여전히 자기 오류를 독자적으로 강제합니다(모르는 도구는 `-32602`, 잘못된 인자는 도구 실행 오류). 호스트가 어떻게 통합했는지와 무관합니다.
6. 한 서버의 도구, 리소스, 프롬프트는 다른 모든 서버의 것과 격리돼 있다고 취급합니다. 전체를 가로질러 보는 존재는 호스트뿐입니다.

## 시험을 위해 기억하기

- 호스트는 서버마다 클라이언트를 하나씩 끼워 넣습니다. 클라이언트 하나가 두 서버를 거느리는 일은 없습니다.
- 도구는 모델이 통제하고, 리소스는 애플리케이션이 이끌고, 프롬프트는 사용자가 통제합니다.
- Sampling과 roots는 2026-07-28에서 폐기(deprecated)됐지만 제거된 건 아닙니다. 둘 다 여전히 동작합니다.
- `serverInfo.name`은 표시와 로깅용입니다. 식별이나 라우팅용으로 절대 쓰지 않습니다.
