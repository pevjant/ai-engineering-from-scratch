# 주문 상태 어시스턴트 런북(운영 대응 절차서)

## 서비스 목표

시크릿을 노출하지 않고, 테넌트 경계를 넘지 않고, 변경(mutation)을 수행하지 않으면서, 검증된 주문 상태 또는 명확한 에스컬레이션을 반환합니다.

## 첫 대응

1. 트레이스 또는 요청 ID를 확인합니다.
2. 재시도 전에 실패를 분류합니다.
3. 도구가 실행되었는지 확인합니다.
4. 권위 있는(authoritative) 주문 상태를 조사합니다.
5. 보안 문제나 교차 테넌트 접근 가능성이 있으면 영향받은 능력을 봉쇄(contain)합니다.

## 실패 유형

### 주문 ID 누락 또는 형식 오류

- 대응: 정확한 공개 ID를 요청합니다.
- 재시도: 사용자가 주도할 때만.
- 검증: 조회 도구가 실행되지 않았는지 확인.

### 완전한 응답 전 프로바이더 타임아웃

- 대응: 시도를 미완료로 표시합니다.
- 재시도: 도구 부수 효과가 없었다면 한 번만, 범위가 한정된 백오프(backoff)로.
- 검증: 트레이스에서 완료된 터미널 이벤트와 도구 연산을 확인.

### 레이트 리밋

- 대응: 대기열에 넣거나, 서비스 목표 안에서 명확한 '일시적 사용 불가' 상태를 반환합니다.
- 재시도: 프로바이더 가이드를 따르되 범위가 한정된 백오프로.
- 검증: 도구 연산이 중복되지 않았는지 확인.

### 프로토콜 또는 스키마 오류

- 대응: 부분 출력을 최종 결과로 표시하지 않습니다.
- 재시도: 유효한 메시지 상태를 재구성한 후, 또는 범위가 한정된 구조화 출력 복구 정책 안에서만.
- 검증: 계약 테스트와 와이어 트레이스로 복구된 경계를 확인.

### 정책 거부

- 대응: 거부를 보존하고 안전한 다음 단계를 설명합니다.
- 재시도: 유효한 외부 승인 또는 교정된 저위험 요청 이후에만.
- 검증: 금지된 도구가 실행되지 않았는지 확인.

### 주문을 찾을 수 없음

- 대응: 상태를 추측하지 않고, 승인된 지원 경로로 에스컬레이션합니다.
- 재시도: 교정된 인증 식별자가 있을 때만.
- 검증: 조회가 현재 사용자의 승인된 주문 범위를 사용했는지 확인.

### 도구 사용 불가

- 대응: 현재 상태를 검증할 수 없다고 명시합니다.
- 재시도: 범위가 한정된 읽기 전용 재시도 한 번, 또는 서비스 목표에 따라 대기열 처리.
- 검증: 조작된 상태가 나타나지 않는지 확인.

### 보안 사고 또는 시크릿 노출

- 봉쇄: 영향받은 도구, MCP 서버, 플러그인, 훅, 네트워크 경로를 비활성화합니다.
- 폐기: 노출 가능성이 있는 크리덴셜은 즉시 교체(rotate)합니다.
- 조사: 가려진(redacted) 트레이스를 보존하고 권위 있는 접근 로그를 조회합니다.
- 복구: 실패한 신뢰 경계를 고치고 해당 픽스처를 보안 평가에 추가합니다.
- 복원: 최소 권한과 활성 모니터링으로 카나리아 배포합니다.

### 모델 또는 구성 변경 후 회귀(regression)

- 봉쇄: 모델, 프롬프트, 스키마, 도구, 스킬, 훅, 플러그인, 서버 버전을 롤백합니다.
- 진단: 짝지어진 평가 케이스와 트레이스를 비교합니다.
- 복구: 실패하는 특정 경계를 해결합니다.
- 검증: 전체 필수 스위트와 보안 스위트가 통과한 뒤에 배포를 재개합니다.

## 모호한 변경(mutation) 규칙

현재 애플리케이션은 읽기 전용입니다. 미래 버전이 변경 기능을 추가한다면, 첫 시도가 완료되었는지를 안정적인 멱등성 키(idempotency key)와 원본 기록 시스템(system-of-record) 정합화가 증명할 때까지는 모호한 타임아웃을 절대 재시도하지 마세요.

## 에스컬레이션 증거

운영자에게 트레이스 ID, 실패 유형, (허용 시) 주문 ID, 컴포넌트 버전, 정책 결정, 도구 결과 분류, 현재 권위 있는 상태를 제공합니다. 원시 크리덴셜, 전체 비공개 콘텐츠, 제약 없는 프롬프트는 포함하지 않습니다.
