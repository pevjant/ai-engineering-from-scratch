# 참조 아키텍처 패킷: 지역별 지원(서포트) 해결

## 1. 경영진 결정

여섯 주짜리, 영어 전용, 사람 검토 방식의 파일럿을 승인합니다. 지원 운영이 성과를 소유합니다: 정책에 맞는 첫 응답 시간을 11분에서 3분 미만으로 줄입니다. 자동 환불이나 계정 삭제는 없습니다. 환불 권한은 재무에 남습니다. 보안, 개인정보, 지역 데이터 소유자가 각자의 경계를 승인합니다.

## 2. 발굴(Discovery)

시스템은 청구와 배송 티켓을 분류하고, 활성 지역 정책을 검색하고, 배정된 계정만 읽고, 응답 초안을 작성하며, 행동을 추천만 하고 실행하지 않습니다. 품질 목표는 소스에 근거한 초안이 최소 98퍼센트입니다. P95 목표는 8초입니다. 논외 항목: 자동 전송, 직원 순위 매기기, 계정 해지, 파일럿 범위 밖 언어.

## 3. 아키텍처 결정

결정론적인 접수 → 검색 → 초안 작성 → 검증 → 리뷰 워크플로를 선택합니다. 증강 단일 호출은 출처(provenance)와 실패가 한 덩어리로 뭉개지므로 기각합니다. 적응형 에이전트는 정상 경로가 알려져 있고, 가변적 도구 선택을 정당화할 측정된 이득이 없으므로 기각합니다. 수용된 티켓의 20퍼센트를 넘게 안전하면서 모델링되지 않은 탐색이 필요해지면 다시 검토합니다.

## 4. 시스템과 데이터 뷰

인증된 접수가 티켓과 지역을 검증합니다. 메타데이터 필터링 검색은 활성 정책 ID를 반환합니다. 범위가 한정된 초안 단계는 최소화된 계정 정보를 받습니다. 스키마, 의미, 출처, 정책 검증기가 리뷰 대기열 전에 실행됩니다. 모든 엣지(경계)에는 주체(principal), 테넌트, 스키마 버전, 타임아웃, 오류 분류, 트레이스 ID, 소유자가 실려 갑니다. 부분 증거는 어떤 행동 추천도 만들지 않습니다.

## 5. RAG과 지식

정책 운영팀이 버전 관리되는 소스를 소유합니다. 헤딩을 인식하는 청크는 규칙, 예외, 지역, 시행일, 권위, 접근 메타데이터를 유지합니다. 하이브리드 검색은 순위 매기기 전에 필터링됩니다. 검증된 인덱스가 원자적으로(atomic) 활성화되고, 이전 인덱스는 롤백용으로 남습니다. 검색 게이트는 재현율, 신선도, 충돌, 오래된 버전, 무단 소스, 공격 콘텐츠를 다룹니다.

## 6. 통합과 신원

첫 단일 호스트 파일럿에는 직접 만든 타입 지정 서비스 호출이 맞습니다. 각 호출은 신뢰할 수 있는 주체와 테넌트 클레임을 전파합니다. 도구는 정책 읽기, 배정된 계정 읽기, 초안 저장으로 나뉩니다. 환불 실행은 없습니다. 미래의 실행기(executor)에는 정확한 주체, 계정, 금액, 사유, 만료, 일회용, 멱등성(idempotency), 원본 기록 시스템(system-of-record) 정합화가 필요합니다.

## 7. 평가와 관측 가능성(옵저버빌리티)

골든 셋(golden set)은 일반, 모호, 오래됨, 충돌, 무단, 공격, 지역, 고위험 케이스를 계층화합니다. 릴리스 요건: 하드 통제 100퍼센트 통과, 정책 뒷받침 최소 98퍼센트, P95 8초 미만, 고위험 회귀 없음, 수용된 초안당 비용이 예산 안. 트레이스는 검색, 도구, 검증, 리뷰, 결과를 크리덴셜 저장 없이 연결합니다.

## 8. 거버넌스

위험 등록부는 오래된 정책, 교차 테넌트 접근, 프롬프트 인젝션, 근거 없는 환불, 언어별 불공정 성능, 리뷰어 과부하를 다룹니다. 모든 통제에는 소유자, 테스트, 증거, 실패 대응, 리뷰 트리거가 있습니다. 자격을 갖춘 리뷰어는 소스 우선 증거와 이유 코드가 붙은 행동을 받습니다. 법무, 개인정보, 보안, 재무, 도메인 소유자가 각자의 의무를 결정합니다.

## 9. 운영과 인수인계

배포는 섀도우 → 5퍼센트 카나리아 → 보호된 지역 확대 → 전체 파일럿 순으로 진행됩니다. 하드 통제, 작업 품질, P95, 신선도, 리뷰 부하, 비용 알림에는 소유자와 런북이 지정됩니다. 운영팀은 소유권을 넘겨받기 전에 오래된 정책, 인가 장애, 티켓 인젝션, 평가기 드리프트, 안전 종료, 롤백을 리허설합니다.

## 10. 열린 결정
