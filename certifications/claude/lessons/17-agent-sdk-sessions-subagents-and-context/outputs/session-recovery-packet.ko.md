# 세션 복구 패킷: 클라이언트 마이그레이션

## 목표와 범위

공개 동작은 바꾸지 않으면서 HTTP 클라이언트를 마이그레이션합니다. 범위는 `src/client.py`와 `tests/test_client.py`이며, 배포와 외부 쓰기는 차단되어 있습니다.

## 지속 상태(Durable State)

매니페스트 `migration-v2`는 현재 브랜치, 의존성 버전, 작업 상태, 파일 해시 `4cc0-demo`, 통과한 12개 테스트, 차단된 1개 타임아웃 케이스, 산출물 ID를 기록합니다. 대화 히스토리는 신뢰할 수 있는 기준( authoritative)이 아닙니다.

## 재검증

다음 편집 전에 브랜치, 의존성 동작, 파일 해시, 대상 테스트, 현재 승인을 다시 검증합니다. 의존성이 바뀌면 기존 계획은 무효가 됩니다.

## 부수 효과 정리(Side Effect Reconciliation)

도구 호출 `write-018`의 결과는 알 수 없습니다. 재시도 전에 저장된 해시와 비교하세요. 멱등성 키(idempotency key) `migration-client-v2-write-018`를 재사용하고, 정리(reconciliation)가 끝날 때까지 새로운 쓰기 식별자를 발급하지 마세요.

## 컨텍스트 예산

20퍼센트는 목표와 제약 조건, 20퍼센트는 현재 매니페스트 상태, 45퍼센트는 판단에 필요한 증거, 15퍼센트는 출력 계약에 배분합니다. 원시 로그는 산출물 참조 뒤(별도 보관)에 남깁니다.

## 독립 리뷰

격리된 리뷰어는 diff, 요구 사항, 테스트, 루브릭을 받습니다. 증거와 함께 완료(complete), 부분(partial), 차단(blocked)을 돌려주며, 구현 트랜스크립트(대화 기록)는 받지 않습니다.
