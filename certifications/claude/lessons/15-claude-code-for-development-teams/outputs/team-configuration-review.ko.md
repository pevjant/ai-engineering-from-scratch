# 팀 구성 리뷰: Support Router

상태: 팀 리뷰 준비 완료

## 범위(Scope)

소유 주체: developer-platform. 리뷰 대상 잡(job)은 풀 리퀘스트 diff에서 패치를 제안합니다. 병합, 배포, 코멘트 작성, 무관한 저장소 읽기는 할 수 없습니다.

## 능력 목록(Capability Inventory)

읽기는 격리된 체크아웃으로 제한됩니다. 편집은 패치 작업 공간으로 제한됩니다. 이 잡은 `python3 -m unittest`를 실행할 수 있지만, 네트워크와 프로덕션(운영 환경) 크리덴셜은 아예 없습니다. 병합과 외부 커뮤니케이션은 사람이 소유합니다.

## 퍼미션 모드

인터랙티브 작업은 `default` 모드로 시작합니다. `acceptEdits`는 파일 편집을 미리 승인해 줄 수 있지만, 푸시, 배포, 네트워크 호출, 외부 메시지 전송을 허가하지는 않습니다. 헤드리스(사람 없는) 리뷰는 좁은 allow 규칙과 함께 `dontAsk`를 사용하고, deny 규칙은 모든 일반 모드에서 크리덴셜과 퍼블리싱을 차단합니다. 이 잡에서 `bypassPermissions`는 허용되지 않습니다.

## 컨텍스트 복구

운영자는 `/context`로 소비량을 확인하고, 같은 작업을 이어가기 위해 명시적 초점(포커스)과 함께 `/compact`를 사용합니다. `/clear`는 대화 컨텍스트를 비운 채로 무관한 작업을 시작할 때 씁니다. `/rewind`는 추적 중인 편집이나 대화를 복원할 수 있지만, 궁극의 복구 기록은 Git과 신뢰할 수 있는 외부 상태입니다.

## 자율 작업 경계

`/goal`은 측정 가능한 수용 조건, 평가자가 볼 수 있는 턴 예산, 외부에서 강제되는 턴 상한이 있을 때만 허용됩니다. `/loop`은 세션이 열려 있는 동안 CI를 폴링할 수 있지만, 새 작업을 만들어 내거나 퍼블리싱 권한을 넓힐 수는 없습니다. 두 기능 모두 현재 퍼미션 경계를 그대로 유지합니다.

## 워크트리 소유권

병렬 작업 하나하나는 `claude --worktree <owner-task>`로 시작합니다. 각 브랜치와 파일 영역마다 이름 붙은 소유자가 한 명씩 있습니다. 워크트리 격리가 막아 주는 것은 편집 충돌이지, 크리덴셜이나 네트워크 접근이 아니며, 공유되는 Git 메타데이터는 여전히 저장소 정책이 지켜 줍니다.

## 훅(Hook) 결정

`permission-request-decision.json`은 `PermissionRequest` 이벤트를 위한 exit 0 구조화 응답입니다. 외부 퍼블리싱을 메시지와 함께 거부합니다. exit 2를 사용하는 커맨드 훅은 stderr로 차단하는 방식이며, JSON과 exit 2를 함께 출력하는 일은 없습니다.

## 예약 실행

세션 안의 `/loop`은 짧은 폴링을 처리합니다. 클라우드 루틴은 필요한 저장소와 커넥터만 가진 자율 아이덴티티(주체)로 검토됩니다. 저장소가 관리하는 크론 잡은 GitHub Actions가 최소 워크플로 권한으로 소유합니다.

## 리뷰 자동화

2026-08-09 기준으로 확인한 바, 관리형 Code Review는 Team 및 Enterprise 플랜용 리서치 프리뷰입니다. 인라인으로 발견 사항을 보고할 수는 있지만, 풀 리퀘스트를 승인하거나 막지는 않습니다. 저장소 자동화는 고정된 프롬프트, 명시적 도구, 턴 제한, 보호된 병합 경로와 함께 `anthropics/claude-code-action@v1`을 사용합니다.

## 허용 픽스처(테스트 케이스)

allow 픽스처는 `src/router.py`를 읽고, 짝이 되는 테스트를 편집하고, 대상 테스트 스위트를 실행하고, 정확한 테스트 증거와 함께 패치 산출물을 만들어 냅니다. `acceptEdits`는 이러한 로컬 편집을 빠르게 해 줄 수 있지만, 공개적인 동작은 아무것도 허락하지 않습니다.

## 거부 픽스처

deny 픽스처는 `.env` 읽기, 보호된 브랜치 푸시, 승인되지 않은 서버 호출을 시도합니다. 실행 전 정책(pre-action policy)이 세 가지 모두를 실행 전에 차단합니다.

## 버전 증거

Claude Code 구성 버전 `team-review-1.2`와 리뷰 절차는 저장소에 고정되어 있습니다. 모델 별칭, 플러그인 버전, 테스트 명령은 매 실행마다 산출물 메타데이터에 기록됩니다.

## 롤백

롤백은 잡을 비활성화하고, 격리된 패치를 버리고, 구성을 `team-review-1.1`로 되돌린 뒤, 다시 활성화하기 전에 allow 픽스처와 deny 픽스처를 재실행합니다.
