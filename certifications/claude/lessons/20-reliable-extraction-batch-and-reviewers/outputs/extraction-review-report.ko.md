# 추출(Extraction) 리뷰 보고서: 지원 정책 변경

## 추출 계약

각 레코드에는 정책 ID, 시행일 또는 `null`, 지역, 액션 유형, 임계값 또는 `null`, 증거 구간(evidence span), 소스 버전, 리뷰 상태가 들어갑니다. '알 수 없음'도 표현 가능해야 하고, 추가 필드는 거부합니다.

## 배치 매니페스트

잡 `policy-w32-review`는 안정적인 `custom_id`, 소스 버전, 스키마 `policy-change-2`, 기대 출력으로 묶인 40개 입력을 담습니다. 픽스처는 결과를 섞어서 반환하고 두 개의 의존성 실패가 있으며 38개의 성공 레코드를 보존합니다. 날짜가 명시된 계획 가정은 다음과 같습니다: Message Batches 비용 50% 절감, 최대 24시간의 서비스 처리 기간, 보장되는 지연 시간 SLA는 없음. 배포 시에는 반드시 현재 API 문서를 다시 확인해야 합니다.

## 검증 계층

구문 분석은 40개 중 40개 통과. 스키마는 40개 수용. 의미 검증은 소스 시행일보다 앞선 마감일 하나를 거부했습니다. 출처(provenance) 검증은 증거 구간에 없는 조작된 임계값 하나를 거부했습니다.

## 리뷰어 발견 사항

독립 리뷰어는 필드, 소스 구간, 이유, 처리(disposition)와 함께 안정적인 발견 항목 `REV-017`과 `REV-018`을 돌려주었습니다. 리뷰어가 출력을 몰래 고치지는 않았습니다.

## 판정(Adjudication)

자격을 갖춘 정책 소유자가 근거 없는 임계값을 `null`로 설정하고, 마감일 예외를 확인했으며, 이유 코드를 기록했습니다. 반복되는 모호함은 재시도를 또 하지 말고 에스컬레이션(상위 보고)합니다.
