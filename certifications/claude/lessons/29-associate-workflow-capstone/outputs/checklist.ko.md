# 어소시에이트 워크플로 캡스톤 체크리스트

이 체크리스트를 캡스톤(종합 프로젝트)의 릴리스 기록으로 사용하세요. 대괄호 안의 안내 문구를 증거로 바꾸세요. 초안이 그럴듯해 보인다는 이유로 항목을 완료로 표시하면 안 됩니다.

## 월요일: 목적과 접점(Surface)

- [ ] 결정, 마감일, 청중, 책임 있는 소유자가 명시되어 있다.
- [ ] 허용되는 행동과 금지되는 행동이 문서화되어 있다.
- [ ] 데이터와 결과(파급력)가 조직 정책 기준으로 분류되어 있다.
- [ ] 선택한 Claude 접점이 해당 목적과 데이터 등급에 대해 승인되어 있다.
- [ ] 현재 약관, 보존(retention) 동작, 통제, 제약을 확인했다.
- [ ] 검증 날짜와 공식 또는 계약상 소스를 기록했다.

증거:

```text
[접점 선택 기록과 정책 승인]
```

## 화요일: 소스와 컨텍스트

- [ ] 모든 소스에 ID, 소유자, 권위(authority), 시행일, 검토일, 민감도가 있다.
- [ ] 대체되었거나 중복된 자료는 활성 검색 대상 밖에 있다.
- [ ] 권위 순서(어느 소스가 우선인지)가 명시되어 있다.
- [ ] 필요한 지역이나 사업부가 있거나, 없으면 '없음'으로 표시되어 있다.
- [ ] 주간 소스 스냅샷과 컷오프(cutoff, 기준 시점)가 고정되어 있다.
- [ ] 충돌, 오래된 소스, 권한 빈틈에 각각 소유자가 있다.

증거:

```text
[레지스트리 버전, 스냅샷 ID, 소스 예외 사항]
```

## 수요일: 프롬프트와 작업 설계

- [ ] 결과, 컨텍스트, 작업, 증거, 제약, 형식, 수용 검사가 모두 들어 있다.
- [ ] 추출, 정합화(reconciliation), 분석, 초안 작성이 별도 단계로 나뉘어 있다.
- [ ] 각 단계에 테스트 가능한 입력, 출력, 게이트(통과 기준)가 있다.
- [ ] 증거가 없으면 추측하지 않고 보류(abstention) 또는 에스컬레이션한다.
- [ ] 소스 내용은 도구 승인이 아니라 데이터로 취급한다.
- [ ] 프롬프트와 워크플로 버전을 기록했다.

증거:

```text
[프롬프트 버전과 단계별 계약]
```

## 목요일: 검증과 거버넌스

- [ ] Python 검증기가 릴리스 후보에서 통과한다.
- [ ] 일부러 만든 실패 패킷 3개 이상이 차단되거나 수정 대상으로 표시된다.
- [ ] 정확한 합계와 스키마는 결정론적 검사를 사용한다.
- [ ] 결과에 영향을 주는 모든 클레임이 권위 있는 뒷받침 증거에 매핑된다.
- [ ] 독립 리뷰가 수정 작업과 분리되어 발견 사항을 보고한다.
- [ ] 개인정보, 편향, 범위, 행동 권한 검사를 통과한다.
- [ ] 모든 차단 요인(blocker)이 인수인계 전에 해결된다.

명령과 결과:

```text
python3 code/main.py
python3 -m unittest discover -s code/tests -v

[간결한 상태와 테스트 개수 붙여 넣기]
```

## 금요일: 인수인계와 복구

- [ ] 인수인계에 정확한 결정, 마감일, 결정 소유자가 명시되어 있다.
- [ ] 소스 스냅샷, 초안 버전, 워크플로 버전이 포함되어 있다.
- [ ] 통과한 검사, 실패한 검사, 충돌, 불확실성이 보인다.
- [ ] 승인, 수정, 거부, 에스컬레이션 경로가 준비되어 있다.
- [ ] 수동 폴백이 최신 상태로 유지되고 리허설되었다.
- [ ] 외부 동작은 초안 작성과 분리되어 있고, 중복 실행으로부터 보호된다.
- [ ] 승인 후 소스가 바뀌면 델타(변경분) 리뷰가 트리거된다.

결정 기록:

```text
Decision:
Decision owner:
Evidence snapshot:
Conditions:
Fallback:
```

## 평가 커버리지

- [ ] 대표적인 정상 케이스 4개가 통과한다.
- [ ] 엣지 케이스 3개가 누락, 충돌, 오래된 증거를 다룬다.
- [ ] 거버넌스 또는 공격(adversarial) 케이스 3개가 무단 목적, 민감 데이터, 프롬프트 인젝션을 다룬다.
- [ ] 고위험 성능은 전체 집계 성능과 분리해서 보고한다.
- [ ] 보류(held-out) 케이스 하나가 프롬프트 튜닝 중 사용되지 않고 남아 있다.

## 릴리스 권고

- [ ] 수동으로 유지한다.
- [ ] 섀도우 모드(실제 흐름에 넣되 결과만 관찰)로 계속한다.
- [ ] 사람 검토를 거치는 보조 도구로 릴리스한다.
- [ ] 결과가 가벼운 단계에는 범위가 한정된 자동화를 허용한다.
- [ ] 목적, 데이터, 권한, 증거가 해결되지 않았으므로 중단하고 에스컬레이션한다.

근거:

```text
[무엇을 테스트했고, 무엇이 통과했고, 무엇이 아직 불확실한지, 결정을 누가 소유하는지 서술한다.]
```
