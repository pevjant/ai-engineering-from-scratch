# 메모리 블록과 Sleep-Time Compute

> 모델이 직접 편집할 수 있는 개별 기능별 메모리 블록, 그리고 본 에이전트가 쉬는 동안 메모리를 비동기로 정리하는 sleep-time 에이전트. 이 두 아이디어가 메모리를 한 대화 너머로 확장하는 방법입니다.

**유형:** Build
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 14 · 07 (MemGPT)
**시간:** ~75분

## 학습 목표

- Letta가 쓰는 세 메모리 계층(코어, 리콜, 아카이벌)과 각각의 역할을 말합니다.
- 메모리 블록 패턴을 설명합니다. Human 블록, Persona 블록, 사용자 정의 블록이 일급 타입 객체라는 것.
- sleep-time compute가 무엇인지, 왜 임계 경로에서 벗어나 있는지, 왜 본 에이전트보다 강한 모델을 쓸 수 있는지 설명합니다.
- 본 에이전트가 응답을 처리하고 sleep-time 에이전트가 턴 사이에서 블록을 정리하는, 스크립트된 두 에이전트 루프를 구현합니다.

## 문제 상황

MemGPT(레슨 07)는 가상 메모리 제어 흐름을 해결했습니다. 그런데 프로덕션(운영 환경) 문제가 셋 나타났습니다:

1. **지연 시간.** 모든 메모리 연산이 임계 경로 위에 있습니다. 사용자가 기다리는 동안 에이전트가 가지치기, 요약, 조정까지 해야 한다면 꼬리 지연 시간이 폭발합니다.
2. **메모리 부패.** 쓰기는 쌓입니다. 반박된 사실은 남습니다. 검색이 낡은 콘텐츠에 잠깁니다.
3. **구조 상실.** 평면적인 아카이벌 저장소로는 "Human 블록은 언제나 프롬프트 안에, Persona 블록도 언제나 프롬프트 안에, Task 블록은 세션마다 교체"를 표현할 수 없습니다.

Letta(letta.com)는 원래 MemGPT 프로젝트가 2024년에 택한 플랫폼 이름입니다 — 논문의 패턴은 계속 MemGPT라는 이름을 유지하고, 2026년 Letta V1 재작성은 그다음의 별개 단계입니다. 메모리 블록이 구조를 명시적으로 만들고, sleep-time compute가 정리 작업을 임계 경로 밖으로 옮깁니다.

## 개념

### 세 계층

| 계층 | 범위 | 사는 곳 | 쓰는 주체 |
|------|-------|----------------|------------|
| 코어(Core) | 언제나 보임 | 메인 프롬프트 안 | 에이전트 도구 호출 + sleep-time 재작성 |
| 리콜(Recall) | 대화 이력 | 검색 가능 | 자동 턴 기록 |
| 아카이벌(Archival) | 임의의 사실 | 벡터 + KV + 그래프 | 에이전트 도구 호출 + sleep-time 흡수 |

코어가 MemGPT의 코어입니다. 리콜은 축출된 꼬리까지 포함한 대화 버퍼입니다. 아카이벌은 외부 저장소입니다. 이 분할이 MemGPT 2계층의 기능 과적을 정리해 줍니다.

### 메모리 블록

블록은 코어 계층의 타입이 지정되고, 영속적이며, 편집 가능한 섹션입니다. 원래 MemGPT 논문은 두 개를 정의했습니다:

- **Human 블록** — 사용자에 대한 사실(이름, 역할, 선호, 목표).
- **Persona 블록** — 에이전트의 자기 인식(정체성, 어조, 제약).

Letta는 임의의 사용자 정의 블록으로 일반화합니다. 현재 목표를 위한 `Task` 블록, 코드베이스 사실을 위한 `Project` 블록, 절대 제약을 위한 `Safety` 블록 같은 것들입니다. 각 블록에는 `id`, `label`, `value`, `limit`(문자 수 상한), `description`(모델이 언제 편집해야 하는지 알도록)이 있습니다.

블록은 도구 표면으로 편집합니다:

- `block_append(label, text)`
- `block_replace(label, old, new)`
- `block_read(label)`
- `block_summarize(label)` — 한도에 가까워진 블록을 압축합니다.

### Sleep-time compute

2025년 Letta가 더한 것: 두 번째 에이전트를 배경에서, 임계 경로 밖에서 돌립니다. sleep-time 에이전트는 대화 트랜스크립트와 코드베이스 맥락을 처리하고, `learned_context`를 공유 블록에 쓰고, 아카이벌 레코드를 정리하거나 무효화합니다.

자연스럽게 따라 오는 성질들:

- **지연 시간 비용 없음.** 본 응답은 메모리 연산을 기다리지 않습니다.
- **더 강한 모델 허용.** sleep-time 에이전트는 더 비싸고 느린 모델이어도 됩니다. 지연 시간에 제약받지 않으니까요.
- **자연스러운 정리 구간.** 사용자가 기다리지 않을 때 중복 제거, 요약, 반박된 사실 무효화를 합니다.

형태는 사람의 일하는 방식과 같습니다. 일을 하고, 잠들고, 장기 기억은 밤사이에 자리를 잡습니다.

### 고유 추론(native reasoning)

Letta V1(`letta_v1_agent`, 2026)은 `send_message`/하트비트와 인라인 `Thought:` 토큰을 폐기하고 고유 추론을 채택했습니다. Responses API(OpenAI)와 확장 사고가 붙은 Messages API(Anthropic)는 추론을 별도 채널로 내보내고, 그 채널이 턴 사이에서 전달됩니다(프로덕션에서는 프로바이더 간에 암호화). 제어 루프는 여전히 ReAct입니다. 생각 트레이스가 프롬프트 모양이 아니라 구조로 존재합니다.

### 이 패턴이 잘못 가는 곳

- **블록 비대.** 무한 `block_append`는 한도를 금방 칩니다. 상한을 넘기는 쓰기 앞에 블록 요약기를 연결하세요.
- **조용한 표류.** sleep-time 에이전트가 블록을 고쳐도 본 에이전트는 눈치채지 못합니다. 블록에 버전을 달고 트레이스에 차이(diff)를 드러내세요.
- **오염된 정리.** sleep-time 에이전트가 공격자가 닿을 수 있는 콘텐츠를 코어로 밀어 넣습니다. 레슨 27은 sleep-time 표면에도 적용됩니다.

## 만들어 보기

`code/main.py`는 다음을 구현합니다:

- `Block` — id, label, value, limit, description.
- `BlockStore` — CRUD + `near_limit(label)` 도우미.
- 두 개의 스크립트된 에이전트 — `PrimaryAgent`는 한 턴을 처리하고, `SleepTimeAgent`는 턴 사이에서 정리합니다.
- 블록 쓰기가 오가는 세 턴 대화와, 블록 하나를 요약하고 낡은 사실 하나를 무효화하는 sleep-time 패스를 보여 주는 트레이스.

실행:

```
python3 code/main.py
```

트랜스크립트는 분업을 보여 줍니다. 본 턴은 빠르고 raw 쓰기를 남기고, sleep 패스가 압축하고 청소합니다.

## 활용하기

- **Letta** (letta.com) — 참조 구현으로. 자체 호스팅 또는 관리형 클라우드.
- **Claude Agent SDK 스킬** — 블록 형태의 지식으로. 스킬은 에이전트가 필요할 때 불러 오는, 이름 있고 버전이 달리고 검색 가능한 지시 블록입니다.
- **커스텀 구현** — 저장소 백엔드에 대한 통제가 필요한 팀을 위해. 나중에 이전할 수 있도록 Letta API 계약을 따르세요.

## 연습 문제

1. `near_limit`이 참일 때 블록 값을 모델이 만든 요약으로 교체하는 `block_summarize` 도구를 추가해 보세요. 요약 호출과 블록 넘침을 모두 최소화하는 트리거 임계값은 어디일까요?
2. 아카이벌 위의 sleep-time 중복 제거를 구현해 보세요. 텍스트 겹침이 90%를 넘는 두 레코드는 하나로 합칩니다. sleep 패스에서만 하고 임계 경로에서는 절대 하지 마세요.
3. 블록에 버전을 달아 보세요. 모든 쓰기마다 이전 값과 차이(diff)를 기록합니다. 운영자가 "에이전트가 왜 X를 잊었나" 디버깅할 수 있게 `block_history(label)`을 노출하세요.
4. sleep-time 에이전트를 신뢰할 수 없는 작성자로 취급해 보세요. Persona나 Safety 블록을 만질 때는 확정 전에 두 번째 에이전트의 검토를 요구합니다.
5. 예제를 Letta API(`letta_v1_agent`)로 이식해 보세요. 블록 스키마에서는 무엇이 바뀌고, 고유 추론은 트레이스 형태를 어떻게 바꿀까요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 메모리 블록(Memory block) | "편집 가능한 프롬프트 섹션" | 타입이 지정되고, 영속적이며, LLM이 편집하는 코어 메모리 조각 |
| Human 블록 | "사용자 메모리" | 사용자에 대한 사실, 코어에 고정 |
| Persona 블록 | "에이전트 정체성" | 자기 인식, 어조, 제약, 코어에 고정 |
| Sleep-time compute | "비동기 메모리 작업" | 임계 경로 밖에서 정리를 하는 두 번째 에이전트 |
| 코어 / 리콜 / 아카이벌 | "계층" | 3층 메모리 분할: 언제나 보임 / 대화 / 외부 |
| 블록 한도(Block limit) | "상한" | 블록별 문자 수 한도, 요약을 강제 |
| 고유 추론(Native reasoning) | "생각 채널" | 프롬프트 수준 `Thought:`가 아니라 프로바이더 수준의 추론 출력 |
| 학습된 컨텍스트(Learned context) | "sleep 출력물" | sleep-time 에이전트가 공유 블록에 쓰는 사실 |
