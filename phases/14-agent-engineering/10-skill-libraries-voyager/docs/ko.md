# 스킬 라이브러리와 평생 학습 (Voyager)

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> Voyager(Wang 외, TMLR 2024)는 실행 가능한 코드를 스킬로 취급합니다. 스킬은 이름이 붙고, 검색 가능하고, 조합 가능하며, 환경 피드백으로 다듬어집니다. Claude Agent SDK 스킬, skillkit, 그리고 2026년 스킬 라이브러리 패턴의 참조 아키텍처가 바로 이것입니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 14 · 07 (MemGPT), 페이즈 14 · 08 (Letta Blocks)
**시간:** 약 75분

## 학습 목표

- Voyager의 세 구성 요소 — 자동 커리큘럼, 스킬 라이브러리, 반복 프롬프팅 — 를 각각의 역할과 함께 말할 수 있습니다.
- Voyager가 행동 공간을 원시 명령이 아니라 코드로 만드는 이유를 설명할 수 있습니다.
- 등록, 검색, 조합, 실패 기반 정제를 갖춘 스킬 라이브러리를 표준 라이브러리로 구현합니다.
- Voyager의 패턴을 2026년 Claude Agent SDK 스킬과 skillkit 생태계에 대응시킵니다.

## 문제

매 세션마다 모든 능력을 처음부터 다시 만드는 에이전트는 세 가지를 잘못합니다:

1. **토큰을 낭비합니다.** 같은 추론을 태스크마다 다시 뽑아 냅니다.
2. **진전을 잃습니다.** 세션 A에서 배운 교정이 세션 B로 이어지지 않습니다.
3. **장기 조합에서 실패합니다.** 복잡한 태스크에는 능력의 계층이 필요한데, 한 방 프롬프트로는 이를 표현할 수 없습니다.

Voyager의 답: 재사용 가능한 능력 하나하나를 이름이 붙은 코드 덩어리로 취급해 라이브러리에 저장하고, 유사도로 검색하며, 다른 스킬과 조합하고, 실행 피드백으로 다듬는 것입니다.

## 개념

### 세 가지 구성 요소

Voyager(arXiv:2305.16291)는 에이전트를 다음을 중심으로 구성합니다:

1. **자동 커리큘럼.** 호기심 주도의 제안자가 에이전트의 현재 스킬 세트와 환경 상태를 바탕으로 다음 태스크를 고릅니다. 탐색은 아래에서 위로(bottom-up) 흘러갑니다.
2. **스킬 라이브러리.** 각 스킬은 실행 가능한 코드입니다. 태스크가 성공하면 새 스킬이 추가됩니다. 스킬은 질의-설명 유사도로 검색됩니다.
3. **반복 프롬프팅 메커니즘.** 실패하면 에이전트가 실행 오류, 환경 피드백, 자기 검증 결과를 받아 스킬을 다듬습니다.

Minecraft 평가(Wang 외, 2024)에서는 베이스라인 대비 고유 아이템 3.3배 더 많이, 돌 도구 8.5배, 철 도구 6.4배 더 빠르게, 지도 탐험 2.3배 더 길게 수행했습니다. 수치 자체는 Minecraft 전용이지만 패턴은 그대로 옮겨 집니다.

### 행동 공간 = 코드

대부분의 에이전트는 원시 명령을 내놓습니다. Voyager는 JavaScript 함수를 내놓습니다. 스킬은 이런 모양입니다:

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

하위 스킬들로 조합됩니다. 설명과 임베딩을 키로 저장되고, 프롬프트가 아니라 프로그램으로 검색됩니다.

이것이 바로 2026년 Claude Agent SDK 스킬입니다: 이름이 붙고 검색 가능한 코드 덩어리에, 에이전트가 필요할 때 불러 오는 지침이 더해진 형태죠.

### 스킬 검색

새 태스크 "다이아몬드 곡괭이 만들기"가 들어왔습니다. 에이전트는:

1. 태스크 설명을 임베딩합니다.
2. 스킬 라이브러리에 유사한 상위 k개 스킬을 물어봅니다.
3. `craftIronPickaxe`, `mineDiamond`, `placeCraftingTable` 등을 가져옵니다.
4. 가져온 기본 스킬 + 새 로직으로 새 스킬을 조합합니다.

MCP 리소스(페이즈 13)와 Agent SDK 스킬이 구현하는 패턴이 바로 이것입니다: 지식/코드 표면 위에서 현재 태스크 범위로 검색하는 것.

### 반복 정제

Voyager의 피드백 루프:

1. 에이전트가 스킬을 작성합니다.
2. 스킬이 환경에서 실행됩니다.
3. 세 가지 신호 중 하나가 돌아옵니다: `success`, `error`(스택 트레이스 포함), `self-verification failure`.
4. 에이전트는 그 신호를 문맥 삼아 스킬을 다시 씁니다.
5. 성공하거나 최대 라운드에 도달할 때까지 반복합니다.

이것은 환경에 기반한 검증을 얹어 코드 생성에 적용한 Self-Refine(레슨 05)입니다. CRITIC(레슨 05)은 검증자를 외부 도구로 바꾼 같은 패턴입니다.

### 커리큘럼과 탐색

Voyager의 커리큘럼 모듈은 에이전트가 가진 것과 아직 하지 않은 것을 근거로 "호숫가 근처에 피난처 짓기" 같은 태스크를 제안합니다. 제안자는 환경 상태 + 스킬 목록을 이용해 현재 능력보다 살짝 위인 태스크 — 탐색의 스위트 스팟 — 를 고릅니다.

프로덕션 에이전트에서는 이것이 "무엇이 빠졌나" 연산자로 번역됩니다: 현재 스킬 라이브러리와 도메인이 주어졌을 때, 아직 커버하지 못하는 스킬은 무엇인가? 팀들은 보통 이 작업을 커리큘럼 리뷰라는 이름으로 수동으로 수행합니다.

### 이 패턴이 잘못되는 지점

- **스킬 라이브러리 부패.** 같은 스킬이 설명만 조금씩 다르게 10번 추가됩니다. 쓰기 시점에 중복 제거를 넣어 검색에는 하나만 걸리게 하세요.
- **조합 스킬 드리프트.** 부모 스킬이 정제된 자식 스킬에 의존합니다. 스킬에 버전을 붙이세요. v1에 고정된 부모가 v3를 저절로 따라가지는 않습니다.
- **검색 품질.** 스킬 설명 위의 벡터 검색은 라이브러리가 수백 개를 넘어서면 나빠집니다. 태그 필터와 강한 제약("`category=tooling`인 스킬만")으로 보완하세요.

```figure
voyager-skills
```

## 직접 만들기

`code/main.py`가 표준 라이브러리 기반 스킬 라이브러리를 구현합니다:

- `Skill` — 이름, 설명, 코드(문자열), 버전, 태그, 의존성.
- `SkillLibrary` — 등록, 검색(토큰 겹침), 조합(의존성 위상 정렬), 정제(갱신 시 버전 올림).
- 기본 스킬 세 개를 등록하고, 네 번째를 조합하고, 실패를 겪고, 정제하는 스크립트형 에이전트.

실행 방법:

```
python3 code/main.py
```

추적 결과에는 라이브러리 쓰기, 검색, 조합, 실패한 실행, v2 정제까지 — Voyager의 루프가 처음부터 끝까지 나옵니다.

## 활용하기

- **Claude Agent SDK 스킬**(Anthropic) — 2026년의 기준점: 각 스킬은 설명, 코드, 지침을 가지며, 에이전트 세션 중 필요할 때 불러 옵니다.
- **skillkit**(npm: skillkit) — 32개 이상의 AI 코딩 에이전트를 위한 교차 에이전트 스킬 관리 도구.
- **자체 스킬 라이브러리** — 도메인 전용(데이터 에이전트용 SQL 스킬, 인프라 에이전트용 Terraform 스킬). Voyager 패턴은 작게 줄여도 잘 통합니다.
- **OpenAI Agents SDK `tools`** — 가장 가벼운 단계. 각 도구가 곧 경량 스킬입니다.

## 산출물 내보내기

`outputs/skill-skill-library.md`는 등록, 검색, 버전 관리, 정제가 연결된 Voyager 스타일 스킬 라이브러리를 어떤 대상 런타임에든 맞춰 생성합니다.

## 연습 문제

1. `compose()`에 의존성 순환 감지기를 추가하세요. 스킬 A가 B에 의존하고 B가 다시 A에 의존하면 어떻게 되나요? 오류로 처리할까요, 경고로 할까요?
2. 스킬별 버전 고정을 구현하세요. 부모 스킬이 자식 `crafting@1`을 조합하고 있을 때, `crafting@2`로의 정제가 부모를 몰래 끌어올려서는 안 됩니다.
3. 토큰 겹침 검색을 sentence-transformers 임베딩(또는 표준 라이브러리로 짠 BM25)으로 바꾸세요. 50개 스킬짜리 연습용 라이브러리에서 retrieval@5를 측정합니다.
4. "커리큘럼" 에이전트를 추가하세요: 현재 라이브러리와 도메인 설명을 주면 빠진 스킬 5개를 제안합니다. 주간 단위로 돌리세요.
5. Anthropic의 Claude Agent SDK 스킬 문서를 읽어 보세요. 연습용 라이브러리를 SDK의 스킬 스키마로 옮겨 보고, 검색 가능성(discoverability)에는 어떤 변화가 생기는지 살펴보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| 스킬 | "재사용 가능한 능력" | 유사도로 검색되는, 이름 있는 코드 덩어리 + 설명 |
| 스킬 라이브러리 | "에이전트의 노하우 메모리" | 스킬의 영구 저장소. 검색과 조합이 가능 |
| 커리큘럼 | "태스크 제안자" | 현재 능력 격차가 이끄는, 아래에서 위로의 목표 생성기 |
| 조합 | "스킬 DAG" | 스킬이 스킬을 부르는 구조. 실행 시 위상 정렬 |
| 반복 정제 | "자기 교정 루프" | 환경 피드백 + 오류 + 자기 검증이 다음 버전으로 되돌아 들어감 |
| 코드로서의 행동 공간 | "프로그래밍 방식 행동" | 시간적으로 이어지는 행동은 원시 명령이 아니라 함수로 표현 |
| 쓰기 시 중복 제거 | "스킬 축소" | 거의 같은 설명의 스킬은 하나의 대표 스킬로 합침 |
