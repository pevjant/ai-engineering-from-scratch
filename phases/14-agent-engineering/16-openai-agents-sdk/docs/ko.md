# OpenAI Agents SDK: 핸드오프, 가드레일, 추적

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> OpenAI Agents SDK는 Responses API 위에 지어진 경량 멀티 에이전트 프레임워크입니다. 다섯 가지 기본 요소: Agent, Handoff, Guardrail, Session, Tracing. 핸드오프는 `transfer_to_<agent>`라는 이름의 도구입니다. 가드레일은 입력이나 출력에서 작동합니다. 추적은 기본으로 켜져 있습니다.

**유형:** 학습 + 빌드
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 14 · 01 (에이전트 루프), 페이즈 14 · 06 (도구 사용)
**시간:** 약 75분

## 학습 목표

- OpenAI Agents SDK의 다섯 기본 요소를 말할 수 있습니다.
- 핸드오프를 설명할 수 있습니다: 왜 도구로 모델링되는지, 모델이 보는 이름 모양은 무엇인지, 컨텍스트는 어떻게 옮겨지는지.
- 입력 가드레일, 출력 가드레일, 도구 가드레일을 구분하고, `run_in_parallel`과 차단 모드의 차이를 설명할 수 있습니다.
- 핸드오프 + 가드레일 + 스팬 방식 추적을 갖춘 표준 라이브러리 런타임을 구현합니다.

## 문제

깔끔하게 위임하지 못하는 에이전트는 결국 모든 걸 프롬프트 하나에 욱여 넣습니다. 가드레일 없는 에이전트는 개인정보(PII)를 흘리거나, 정책을 어기는 출력을 내놓거나, 영원히 루프를 돕니다. OpenAI의 SDK는 멀티 에이전트 작업을 다룰 만하게 만드는 세 가지 기본 요소를 정식화합니다.

## 개념

### 다섯 가지 기본 요소

1. **Agent.** LLM + 지침 + 도구 + 핸드오프.
2. **Handoff.** 다른 에이전트로의 위임. 모델에게는 `transfer_to_<agent_name>`이라는 이름의 도구로 표현됩니다.
3. **Guardrail.** 입력(첫 에이전트만), 출력(마지막 에이전트만), 도구 호출(함수 도구마다)에 대한 검증.
4. **Session.** 턴을 넘나드는 자동 대화 이력.
5. **Tracing.** LLM 생성, 도구 호출, 핸드오프, 가드레일에 대한 내장 스팬.

### 도구로서의 핸드오프

모델은 도구 목록에서 `transfer_to_billing_agent`를 봅니다. 이걸 호출하면 런타임에 다음을 지시합니다:

1. 대화 컨텍스트를 복사합니다(또는 `nest_handoff_history` 베타로 접어 압축합니다).
2. 대상 에이전트를 자기 지침으로 초기화합니다.
3. 대상 에이전트로 실행을 이어 갑니다.

이것이 제품화된 슈퍼바이저 패턴(레슨 13 / 레슨 28)입니다.

### 가드레일

세 가지 맛:

- **입력 가드레일.** 첫 에이전트의 입력에 작동합니다. LLM 호출 전에 위험하거나 범위를 벗어난 요청을 거부합니다.
- **출력 가드레일.** 마지막 에이전트의 출력에 작동합니다. PII 누출, 정책 위반, 잘못된 형식의 응답을 잡습니다.
- **도구 가드레일.** 함수 도구마다 작동합니다. 인자를 검증하고, 권한을 확인하고, 실행을 감사합니다.

모드:

- **병렬**(기본값). 가드레일 LLM이 본 LLM과 나란히 돕니다. 꼬리 지연 시간이 낮습니다. 작동하면 본 LLM의 작업은 폐기됩니다(토큰 낭비).
- **차단**(`run_in_parallel=False`). 가드레일 LLM이 먼저 돕니다. 작동하면 본 호출에 쓰인 토큰이 없습니다.

트립와이어는 `InputGuardrailTripwireTriggered` / `OutputGuardrailTripwireTriggered` 예외를 던집니다.

### 추적

기본으로 켜져 있습니다. 모든 LLM 생성, 도구 호출, 핸드오프, 가드레일이 스팬을 내보냅니다. `OPENAI_AGENTS_DISABLE_TRACING=1`로 빠져나올 수 있습니다. `add_trace_processor(processor)`는 스팬을 OpenAI 것과 함께 여러분의 백엔드로도 흘려 보냅니다.

### 세션

`Session`은 대화 이력을 백엔드(SQLite, Redis, 커스텀)에 저장합니다. `Runner.run(agent, input, session=session)`은 자동으로 불러 오고 덧붙입니다.

### 이 패턴이 잘못되는 지점

- **핸드오프 드리프트.** 에이전트 A가 B에 넘기고 B가 다시 A로 넘깁니다. 홉 카운터를 추가하세요.
- **가드레일 우회.** 도구 가드레일은 함수 도구에만 발동합니다. 내장 도구(파일 읽기, 웹 가져오기)는 별도 정책이 필요합니다.
- **과잉 추적.** 스팬에 민감한 내용이 들어갑니다. OTel GenAI 콘텐츠 수집 규칙(레슨 23)과 짝지으세요 — 외부에 저장하고 ID로 참조합니다.


## 직접 만들기

`code/main.py`는 SDK 모양을 표준 라이브러리로 구현합니다:

- `Agent`, `FunctionTool`, `Handoff`(전송 의미를 가진 함수 도구로서).
- 입력/출력/도구 가드레일, 핸드오프 디스패치, 홉 카운터를 갖춘 `Runner`.
- 추적 모양을 보여 주는 간단한 스팬 방출기.
- 사용자 질의에 따라 청구 또는 지원으로 넘기는 분류 에이전트. 한 입력에서 가드레일이 발동합니다.

실행 방법:

```
python3 code/main.py
```

추적 결과에는 성공한 핸드오프 두 번, 입력 가드레일 발동 한 번, 그리고 진짜 SDK가 내보내는 것을 그대로 옮긴 스팬 트리가 나옵니다.

## 연습 문제

1. 핸드오프 홉 카운터를 추가하세요: N번 전송 후에는 거부합니다. 동작을 추적합니다.
2. `nest_handoff_history`를 옵션으로 구현하세요 — 전송 전에 이전 메시지를 요약 하나로 접어 넣습니다.
3. 차단식 출력 가드레일을 작성하세요. 발동할 프롬프트와 통과할 프롬프트의 지연 시간을 비교합니다.
4. `add_trace_processor`를 JSON 로거에 연결하세요. 스팬마다 어떤 모양을 내보내나요?
5. SDK 문서를 읽어 보세요. 표준 라이브러리 연습용 구현을 `openai-agents-python`으로 옮깁니다. 어떤 걸 잘못 모델링했나요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| Agent | "LLM + 지침" | SDK의 Agent 타입. 도구와 핸드오프를 소유 |
| Handoff | "전송" | 모델이 다른 에이전트에 위임하려고 부르는 도구 |
| Guardrail | "정책 검사" | 입력/출력/도구 호출에 대한 검증 |
| 트립와이어 | "가드레일 작동" | 가드레일이 거부할 때 던지는 예외 |
| Session | "이력 저장소" | 실행 사이에 유지되는 대화 메모리 |
| Tracing | "스팬" | LLM + 도구 + 핸드오프 + 가드레일을 덮는 내장 관측 기능 |
| 차단 가드레일 | "순차 검사" | 가드레일이 먼저 돎. 작동해도 토큰 낭비 없음 |
| 병렬 가드레일 | "동시 검사" | 가드레일이 나란히 돎. 지연 시간은 낮지만 작동 시 토큰 낭비 |
