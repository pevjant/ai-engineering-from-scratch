> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-init-script.md](skill-init-script.md)


저장소, 에이전트 제품, 그 의존성 면(dependency surface)이 주어지면, 프로젝트 전용 초기화 스크립트와 CI 연결을 만들어 냅니다.

만들 것:

1. `tools/init_agent.py` — 다음 점검 포함: 런타임 버전, 나열된 의존성, 테스트 명령 해석 가능 여부, 필수 환경 변수, 상태 파일 신선도.
2. `init_report.json` 스키마를 스크립트 옆에 문서화. 각 점검은 `(name, status: pass|warn|fail, detail)`을 반환합니다.
3. `.github/workflows/agent-init.yml`(또는 이에 준하는 것) — 스크립트를 실행하고 fail 심각도 점검이 있으면 에이전트 잡을 막습니다.
4. 에이전트 런타임이 각 세션 시작 전에 호출할 수 있는 `pre-task` 훅 스크립트.
5. `docs/init.md` 문서 — 모든 점검, 그 심각도, 실패를 고치는 방법을 나열합니다.

하드 거부(hard reject) 항목:

- 타임아웃 없이 네트워크를 호출하는 점검. 초기화는 빠르고 오프라인에서도 안전해야 합니다.
- LLM 호출이 필요한 점검. 초기화는 결정론적 배관입니다.
- 래퍼가 삼켜버리는 0이 아닌 종료 코드. 큰 소리로 실패하는 것이 핵심입니다.
- 멱등성 없이 상태를 건드리는 점검. 타임스탬프를 빼면 연달아 두 번 실행한 리포트가 동일해야 합니다.

거부 규칙:

- 프로젝트에 테스트 명령이 없다면, 스크립트 출시를 거부합니다. 대신 그 공백을 워크벤치 감사 목록에 기록합니다.
- 환경 변수 목록에 스크립트가 출력하게 될 비밀 값(secrets)이 있다면, 거부하고 마스킹(redaction)을 강제합니다. 초기화 리포트에 비밀 값이 담겨서는 안 됩니다.
- 드라이 런에서 어떤 점검이 3초보다 오래 걸린다면, 출시 전에 그 시간 측정 결과를 먼저 드러냅니다. 긴 점검은 초기화를 의식(儀式)으로 만듭니다.

출력 구조:

```
<repo>/
├── tools/
│   ├── init_agent.py
│   └── pre_task.sh
├── docs/
│   └── init.md
└── .github/
    └── workflows/
        └── agent-init.yml
```
