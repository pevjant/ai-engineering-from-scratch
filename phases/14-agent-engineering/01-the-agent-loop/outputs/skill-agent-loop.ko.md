> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-agent-loop.md](skill-agent-loop.md)

대상 런타임(Python async, Python sync, Node, Rust async, Go)과 도구 목록(이름, 입력 스키마, 호출 가능 객체)이 주어지면, 첫 시도에서 올바른 ReAct 에이전트 루프를 만들어 냅니다.

산출물:

1. 역할 {user, assistant, tool, final}을 갖춘 메시지 버퍼 타입과 대상 프로바이더가 기대하는 스키마(Anthropic `tool_use` / `tool_result` 블록, OpenAI 함수 호출 메시지, Responses API 추론 채널). 프로바이더 사이에서 스키마를 조용히 바꿔치기하지 않습니다.
2. name -> 호출 가능 객체 디스패치, 입력 검증, 타입이 지정된 결과를 갖춘 도구 레지스트리. 오류는 반드시 잡아서 관찰 문자열로 바꿔야 하며, 루프로 예외를 던져서는 안 됩니다.
3. 다음 중 하나가 될 때까지 도는 루프: 명시적 `finish` 액션, 어시스턴트 턴에 도구 호출 없음, 최대 턴, 최대 총 토큰, 가드레일 발동. 기본 정지 조건은 정확히 하나만 고르고, 나머지는 안전벨트입니다.
4. 과제 부류에 맞게 조정된 턴 예산 — 짧은 과제 10, computer-use 200, 딥 리서치 400. 선택을 명시적으로 밝힙니다.
5. 모든 생각, 행동, 관찰, 정지 사유를 기록하는 트레이스 레코드. 런타임에 OTel SDK가 있으면 OpenTelemetry GenAI 스팬(`invoke_agent`, `tool_call`)을 내보냅니다.

절대 거부 항목:

- 턴 상한 없이 도는 루프. 이것은 최적화가 아니라 신뢰성 문제입니다.
- 도구 오류를 빈 관찰로 삼켜 버리는 것. 모델이 고칠 수 있으려면 실패 텍스트를 봐야 합니다.
- 검색해 온 콘텐츠를 신뢰할 수 있는 지시로 취급하는 것. 모든 도구 출력은 신뢰할 수 없는 입력이며 — 사용자 메시지만이 권한을 실어 줍니다(OpenAI CUA 문서 참고).
- 스키마 번역 계층 없이 프로바이더를 섞어 쓰는 것. Anthropic과 OpenAI는 도구 스키마와 메시지 형태가 서로 다릅니다.

거부 규칙:

- 대상이 "프레임워크 없이 bash만"이라면 거부하고 최소한 타입이 지정된 메시지 스키마를 권합니다. 에이전트 루프는 타입 없는 셸 접착제로 만들기엔 실수가 너무 잘 생깁니다.
- "모델에게 피드백 없이 실패한 도구 호출을 자동 재시도"해 달라는 요청은 거부합니다. 재시도는 모델을 거치거나(CRITIC/Self-Refine, 레슨 05) 도구 자체의 멱등성 계약에 속해야 합니다.
- 도구 목록에 사람 확인(human-in-the-loop) 절차 없는 파괴적 도구가 있다면 거부하고 레슨 09(권한 + 샌드박싱)를 알려 줍니다.

출력: 언어 대상마다 파일 하나씩, 그리고 정지 조건 선택과 턴 예산 근거를 설명하고 단계별 생각-행동-관찰이 담긴 예시 트레이스 하나를 보여 주는 `README.md` 하나. 마지막은 "다음에 읽을 것"으로 끝냅니다. 과제가 장기 지속형이라면 레슨 02(ReWOO 계획), 이전의 반복이라면 레슨 03(Reflexion), 도구가 신뢰할 수 없는 콘텐츠를 다룬다면 레슨 27(프롬프트 인젝션)을 가리킵니다.
