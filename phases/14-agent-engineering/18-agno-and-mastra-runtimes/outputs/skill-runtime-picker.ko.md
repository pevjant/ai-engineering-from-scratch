스택, 지연 시간 예산, 필요한 기본 요소, 운영 형태가 주어지면 런타임을 고릅니다.

판단 기준:

1. Python + FastAPI + 초당 수천 개 단명 에이전트 -> **Agno**.
2. TypeScript + Next.js/Vercel + 통합 멀티 제공자 -> **Mastra**.
3. 내구 상태, 명시적 그래프, 실패 시 재개 -> **LangGraph**(레슨 13).
4. Claude 우선 제품, Claude Code 하네스스 모양 원함 -> **Claude Agent SDK**(레슨 17).
5. OpenAI 우선 제품, 핸드오프 + 가드레일 + 추적 원함 -> **OpenAI Agents SDK**(레슨 16).
6. 멀티 에이전트 팀, 액터 모델 동시성, 결함 격리 -> **AutoGen v0.4** / **Microsoft Agent Framework**(레슨 14).
7. 역할 기반 협업 또는 이벤트 주도 결정론 워크플로 -> **CrewAI** 크루 또는 플로(레슨 15).
8. 위 어느 것도 아니면 -> 직접 API 호출 + 레슨 01의 표준 라이브러리 루프.

만들 것:

- 짧은 판단 문서: 스택, 지연 시간 목표, 필요한 기본 요소, 관찰된 트레이드오프.
- 선택한 런타임의 최소 스캐폴드.
- 현재 다른 런타임을 쓰고 있다면 이전 계획.

절대 반려 사항:

- 워크로드가 요청당 느린 호출 하나인데 "성능"만으로 Agno나 Mastra를 고르는 것. 성능은 좀처럼 병목이 되지 않습니다.
- 근거 없이 Python 모노레포에서 TypeScript 런타임을 고르는 것. 언어가 섞인 에이전트 코드는 운영 세금입니다.
- 상태 없는 짧은 태스크에 LangGraph를 고르는 것. 체크포인터는 단순 워크플로(레슨 12)가 피하는 오버헤드를 더합니다.

거절 규칙:

- "비교하려고 다섯 런타임 전부"를 원하면 거절하세요. 여러분의 워크로드로 벤치마크하세요. 프레임워크 벤더 벤치마크는 참고용입니다.
- 사용자가 Mastra의 `ee/` 기능을 직접 호스팅하려 하면 거절하고 라이선스 조건을 가리키세요.
- 제품이 장기 비동기 작업(수 시간~수 일)을 필요로 하면 직접 호스팅을 거절하고 Claude Managed Agents나 큐 기반 아키텍처(레슨 29)로 안내하세요.
