> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-rewoo-planner.md](skill-rewoo-planner.md)

사용자 요청과 도구 카탈로그(이름, 입력 스키마, 설명)가 주어지면 ReWOO 계획, 즉 도구 호출과 증거 참조(`#E1`, `#E2`, ...)를 담은 단계들의 DAG를 만들어 냅니다. 실행기에 넘기기 전에 계획을 검증합니다.

산출물:

1. 계획 DAG. 각 노드는 id(`E1`, `E2`, ...), 도구 이름, 인자 딕셔너리(문자열 안에 `#E<k>` 참조가 들어갈 수 있음), 선택적 `parallel_group` 라벨을 갖습니다.
2. 검증 출력. 위상 정렬로 비순환 검사; 참조 해석 검사(모든 `#E<k>`에는 앞선 생산자가 있어야 함); 도구 존재 검사(모든 도구 이름이 카탈로그에 있어야 함); 인자 스키마 검사(각 인자가 도구의 입력 스키마와 맞아야 함).
3. 병렬성 힌트. 모든 위상 층마다 동시에 실행할 수 있는 노드를 나열합니다.
4. 플래너/솔버 분리 권고. 계획이 3단계 미만이면 ReAct를 권합니다. 계획에 무한 루프 요구(매 단계 재계획)가 있으면 재계획기가 붙은 Plan-and-Execute를 권합니다. 계획이 30단계를 넘거나 웹/모바일을 대상으로 하면 합성 계획 데이터를 쓰는 Plan-and-Act를 권합니다.

절대 거부 항목:

- 순환이 있는 계획. ReWOO는 DAG를 전제합니다. 순환은 ReAct나 LATS의 영역입니다.
- 위상 정렬 순서에서 아직 존재하지 않는 `#E<k>`를 참조하는 계획. 실패하는 정확한 간선을 내보냅니다.
- 카탈로그에 없는 도구를 호출하는 계획. 계획이 성립하게 하려고 도구를 지어내지 않습니다.
- 참조의 인자 타입이 도구 스키마와 맞지 않는 계획(예: `#E1`은 문자열로 치환되는데 도구는 int를 기대함).

거부 규칙:

- 과제가 열린 탐색(필요한 도구도 단계도 미지수)이라면 거부하고 ReAct나 LATS(레슨 04)를 권합니다.
- 도구 카탈로그에 승인 게이트 도구 없이 파괴적 도구가 있다면 거부하고 레슨 09(권한, 샌드박싱)를 가리킵니다.

출력: 구조화된 계획(JSON 또는 YAML), 검증 보고서, 병렬성 맵, 그리고 실행기(ReWOO Worker), 재계획기(Plan-and-Execute), 더 큰 궤적 샘플링 루프(Plan-and-Act) 중 어디로 이어지는지 알려 주는 후속 행동.

마지막은 "다음에 읽을 것" 노트로 끝냅니다. 그 과제 부류를 전에 시도한 적이 있으면 레슨 03(Reflexion), 계획이 탐색의 이득을 볼 것 같으면 레슨 04(LATS)를 가리킵니다.
