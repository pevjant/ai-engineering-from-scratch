> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-hybrid-memory.md](skill-hybrid-memory.md)

대상 런타임, 벡터 백엔드(Qdrant, pgvector, Chroma, sqlite-vec), KV 백엔드(Postgres, Redis, dict), 그래프 백엔드(Neo4j, 인메모리 엣지)가 주어지면, 퓨전 메모리 시스템을 만들어 냅니다.

만들 것:

1. `add(text, user_id, session_id, scope, importance, tags)` 파사드 뒤에 세 개의 저장소 클래스를 둡니다. 쓰기 시점에 추출기가 `text`를 레코드, KV 트리플, 그래프 트리플로 분해합니다. 어느 저장소도 선택 사항이 아닙니다.
2. 퓨전 스코어러: `score = w_rel * relevance + w_imp * importance + w_rec * recency`. 세 가지 가중치를 모두 설정(config)으로 노출합니다. 호출마다가 아니라 제품별로 튜닝합니다.
3. 스코프 분류: `user`, `session`, `agent`. 검색은 반드시(MUST) 스코프를 존중해야 합니다. 어떤 사용자 질의도 다른 사용자의 레코드를 새어 나가게 해서는 안 됩니다.
4. 시간 무효화. 모순이 생기면 기존 엣지/레코드를 무효 표시만 하고 절대 삭제하지 않습니다. 과거 시점 질의를 위해 `search(query, as_of=timestamp)`를 노출합니다.
5. 추출기 인터페이스. 기본값은 LLM 기반이어도 되지만, 테스트를 위해 결정론적인 정규식 폴백도 허용합니다. 폭발을 막기 위해 `add()`당 그래프 엣지 수에 상한을 둡니다.

절대 반려 사항:

- 저장소 하나짜리 메모리를 "Mem0 스타일"이라고 부르는 것. 벡터만, KV만, 그래프만 있는 제품도 괜찮지만 하이브리드 메모리는 아닙니다. 이름을 잘못 붙이지 마세요.
- 스코프별 가중치도, 명시적인 `scope=` 필터도 없이 스코프를 넘나드는 검색. 스코프 누출은 컴플라이언스·프라이버시 사고입니다.
- 모순이 생겼을 때 삭제하는 것. 무효화하고 타임스탬프를 찍으세요. 삭제는 버그를 숨기고 감사를 깨뜨립니다.

거절 규칙:

- 사용자가 "중요도 가중치는 빼달라"고 하면 거절하세요. 백만 개 레코드 위에 평면적인 관련성 랭킹만 얹는 구조는 검색 실패를 예약해 둔 것과 같습니다.
- 그래프 백엔드에 충돌 감지기가 없다면, 결과물을 "Mem0 스타일"이라 부르는 것을 거절하세요. 이름을 한 단계 낮춰 부릅니다.
- 제품에 개인정보(PII, 의료·법률·인사)가 얽혀 있다면, 제품 책임자의 감사를 거치지 않은 추출기를 두고 출시하는 것을 거절하세요.

출력: 저장소마다 파일 하나씩, 그리고 `memory.py`(파사드), `config.py`(가중치), 퓨전 가중치·스코프 정책·추출기 계약·무효화 의미론을 설명하는 `README.md`. 마지막은 "다음에 읽을 것"으로 끝냅니다 — 에이전트가 새 스킬을 배워야 하면 레슨 10, 메모리 연산에 OTel 스팬이 필요하면 레슨 23, 검색에서 신뢰할 수 없는 입력 처리가 필요하면 레슨 27을 가리킵니다.
