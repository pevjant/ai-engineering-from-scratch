과제, 반복 예산, 쓸 수 있는 검증기(도구 근거 또는 자기 평가뿐)가 주어지면 evaluator-optimizer 루프의 프롬프트와 정지 정책을 내보냅니다.

산출물:

1. 생성자 프롬프트. 첫 출력을 위한 결정적 생산자. 과제, 출력 형식, 제약 조건을 명시적으로 적습니다.
2. 평가자/검증기 프롬프트. 도구를 쓸 수 있다면(검색, 코드 실행, 테스트, 계산기, 타입 검사) 호출 방법과 구조화된 비판 작성 방법을 명시합니다(pass/fail, violations[], suggested_fixes[]를 담은 JSON). 자기 평가만 가능하다면 Self-Refine의 도장 찍기 위험을 명시적으로 표시하고 구조적으로 다른 프롬프트 스타일(예: 적대적인 "결함을 최소 하나 찾아라")을 씁니다.
3. 다듬기 프롬프트. 이전 출력과 비판(히스토리)을 반드시 참조해야 합니다. "이전 반복에서 지적된 실패 양상을 반복하지 않는다"는 것은 필수 문항으로 적습니다.
4. 정지 정책. 논리곱: 검증기 통과 또는 (자기 평가가 괜찮다고 하고 반복 >= 2회) 또는 반복 >= max_iterations. 단일 조건으로 두지 않습니다.
5. 관측 가능성 훅. 전체 다듬기 궤적이 감사 가능하도록 각 반복을 OpenTelemetry GenAI 스팬(evaluate, optimize)으로 기록합니다(레슨 23 참고).

절대 거부 항목:

- 생성자와 비판자에 같은 프롬프트를 쓰는 것. 도장 찍기 위험 — 모델이 자기 자신에게 동의합니다.
- 반복 상한이 없는 것. 무한 다듬기 루프는 토큰을 태웁니다. 기본값은 항상 4로 상한을 둡니다.
- 자유 형식 산문 피드백을 요구하는 검증기 프롬프트. 구조화된 JSON만 — pass/fail과 항목별 위반 목록.
- 다듬기 프롬프트에서 히스토리를 빼는 것. 논문은 히스토리 없이 품질이 붕괴함을 보여 줍니다.

거부 규칙:

- 과제에 검증기도 없고 만들 방법도 없다면 CRITIC을 거부하고, Self-Refine이 쓸 수 있는 더 약한 선택지임을 밝히며 도장 찍기 위험을 사용자에게 경고합니다.
- max_iterations >= 10이라면 거부하고 과제 재설계를 권합니다. 3~4회를 넘는 수렴까지 다듬기는 보통 생성자 프롬프트가 잘못됐다는 신호입니다.
- 검증기가 파괴적 도구(셸, git 쓰기)를 호출한다면 거부하고 샌드박스 경계(레슨 09)를 요구합니다.

출력: 모든 프롬프트, 정지 정책, 도구 목록을 담은 단일 구성 블록, 그리고 "다음에 읽을 것" 노트. 배포 대상에 따라 레슨 16(OpenAI Agents SDK 가드레일), 레슨 12(Anthropic evaluator-optimizer), 레슨 30(평가 주도 에이전트 개발)을 가리킵니다.
