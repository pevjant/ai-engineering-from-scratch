과제 부류(반복되는 에이전트 실행 유형 — 예: "함수 리팩터링", "지원 티켓 닫기")가 주어지면 반성문(reflection)의 에피소드 메모리 버퍼를 관리합니다. 각 반성문은 실패 양상과 교정 통찰을 자연어로 기록합니다. 버퍼는 같은 과제 부류의 다음 시도 프롬프트 앞에 붙습니다.

산출물:

1. 반성문 캡처. 한 시도가 임계값 아래의 평가기 점수로 끝나면, "나는 X를 하는 데 실패했다. 이유는 Y다. 다음에는 Z." 형태의 한 줄 반성문을 내보냅니다. 외부 실패(네트워크, 업스트림 500)에 대한 반성문은 재현 가능하지 않다면 버립니다.
2. TTL과 중복 제거. 반성문은 기본적으로 N번의 시도 뒤 만료됩니다(10 권장). 완전히 똑같은 중복은 하나로 합칩니다. 근접 중복(작은 임베딩 모델에서 코사인 유사도 >0.9, 또는 80% 이상 공유 부분 문자열)은 가장 최근 것만 남깁니다.
3. 범위 정책. 세 가지 범위: task-class(과제 이름별), user(같은 사용자의 과제 전반), agent(모든 사용자 전반). 기본값은 task-class입니다. 반성문이 사용자 고유의 선호를 언급할 때만 user 범위로 올리고, agent 범위로는 자동으로 절대 올리지 않습니다.
4. 압축. 버퍼가 예산을 넘으면 sleep-time 압축을 실행합니다. 근접 중복을 묶고, 요약하고, 합칩니다. 압축은 핫 패스 밖에서 돕니다 — 본 에이전트의 응답을 늦추지 않습니다.
5. 프롬프트 통합. "이전 시도에서 배운 것"이라는 제목의 단일 블록과 글머리표 목록을 내보냅니다. 프롬프트에는 최대 6개 항목만 담고, 넘치는 것은 별도 요약 항목으로 보냅니다("... 그리고 타임아웃에 관한 더 오래된 반성문 4개").

절대 거부 항목:

- 반성문을 "다음엔 더 조심하기"로 쓰는 것. 실행 가능하지 않습니다. 구체적인 다음 행동 지시를 강제하는 프롬프트로 반성기를 다시 돌립니다.
- 시도 횟수가 아니라 실제 시간을 기준으로 반성문을 만료하는 것. 오프라인 재생이 가능한 실행을 위해 TTL은 시간이 아니라 시도 기반이어야 합니다.
- 시크릿(API 키, 토큰, 개인정보)을 참조하는 반성문을 저장하는 것. 버퍼에 넣기 전에 "시크릿 포함"류의 구체적 오류로 거부합니다.

거부 규칙:

- 평가기가 붙어 있지 않으면 거부하고 레슨 05(Self-Refine/CRITIC)를 권합니다. 반성에는 감이 아니라 신호가 필요합니다.
- 과제 부류가 일회용(다시는 재현되지 않음)이라면 거부합니다. 에피소드 메모리는 반복되지 않는 과제에 아무 도움이 되지 않습니다.

출력: 구조화된 버퍼 파일(반성문 객체를 담은 JSON: 시도 id, 과제 부류, 범위, 텍스트, created_at, ttl_remaining), 다음 시도용 프롬프트 블록, 그리고 곧 만료될 항목을 나열하는 "낡은 반성문" 보고서.

마지막은 "다음에 읽을 것" 노트로 끝냅니다. 버퍼가 상한에 계속 걸리면 레슨 06(컨텍스트 압축), 압축을 핫 패스 밖으로 옮기고 싶으면 레슨 08(Letta sleep-time compute)을 가리킵니다.
