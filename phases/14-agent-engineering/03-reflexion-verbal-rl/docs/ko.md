# Reflexion: 언어적 강화 학습

> 경사 기반 RL로는 실패 양상 하나를 고치는 데 수천 번의 시도와 GPU 클러스터가 필요합니다. Reflexion(Shinn 등, NeurIPS 2023)은 그걸 자연어로 해 냅니다. 실패한 시도마다 에이전트가 반성문(reflection)을 써서 에피소드 메모리에 저장하고, 다음 시도가 그 메모리를 보고 출발합니다. Letta의 sleep-time compute, Claude Code의 CLAUDE.md 학습 내용, pro-workflow의 learn-rule 뒤에 있는 패턴이 바로 이것입니다.

**유형:** Build
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 14 · 01 (에이전트 루프), 페이즈 14 · 02 (ReWOO)
**시간:** ~60분

## 학습 목표

- Reflexion의 세 구성 요소(Actor, Evaluator, Self-Reflector)와 에피소드 메모리의 역할을 말합니다.
- 이진 평가기, 반성문 버퍼, 깨끗한 재시도를 갖춘 표준 라이브러리 기반 Reflexion 루프를 구현합니다.
- 주어진 과제에 대해 스칼라, 휴리스틱, 자기 평가 피드백 소스 중 무엇을 쓸지 고릅니다.
- 언어적 강화 학습이 경사 기반 RL이라면 수천 번의 시도가 필요한 오류를 잡아 내는 이유를 설명합니다.

## 문제 상황

에이전트가 과제에 실패했습니다. 표준 RL이라면 시도를 수천 번 더 돌리고, 경사를 계산하고, 가중치를 업데이트합니다. 비싸고, 느리고, 대부분의 프로덕션(운영 환경) 에이전트에는 실패 하나하나마다 학습 예산이 없습니다.

Reflexion(Shinn 등, arXiv:2303.11366)은 다른 질문을 던집니다. 에이전트가 실패 이유를 그냥 생각해 보고, 그 생각을 프롬프트에 넣은 채 다시 시도하면 어떨까? 가중치 업데이트 없음. 경사 없음. 시도 사이에 자연어만 저장할 뿐입니다.

결과: ALFWorld에서는 ReAct와 파인튜닝하지 않은 다른 베이스라인을 이깁니다. HotpotQA에서는 ReAct를 능가합니다. 코드 생성(HumanEval/MBPP)에서는 당시 최고 수준(state of the art)을 기록합니다. 경사 한 번 없이 전부.

## 개념

### 세 가지 구성 요소

```
Actor         : 궤적을 생성합니다 (ReAct식 루프)
Evaluator     : 궤적을 채점합니다 — 이진(binary), 휴리스틱, 또는 자기 평가
Self-Reflector: 실패에 대한 자연어 반성문을 씁니다
```

그리고 자료 구조 하나:

```
Episodic memory: 이전 반성문의 목록, 다음 시도의 프롬프트 앞에 붙음
```

한 번의 시도는 Actor를 돌립니다. Evaluator가 채점합니다. 점수가 낮으면 Self-Reflector가 반성문을 만들어 냅니다("질문이 Y를 묻는 건데 X를 묻는 걸로 잘못 읽어서 엉뚱한 도구를 골랐다"). 반성문은 에피소드 메모리로 들어갑니다. 다음 시도는 깨끗하게 시작하지만 반성문을 봅니다.

### 세 가지 평가기 유형

1. **스칼라** — 외부 이진 신호. ALFWorld는 성공하거나 실패합니다. HumanEval 테스트는 통과하거나 실패합니다. 가장 단순하고 신호가 가장 강합니다.
2. **휴리스틱** — 미리 정의된 실패 시그니처. "에이전트가 같은 행동을 연달아 두 번 내놓으면 막힌 것으로 표시한다." "궤적이 50단계를 넘으면 비효율로 표시한다."
3. **자기 평가** — LLM이 자기 궤적을 스스로 채점합니다. 정답(ground truth)이 없을 때 필요합니다. 신호는 약한 편이고, 도구에 근거한 검증(레슨 05 — CRITIC)과 잘 어울립니다.

2026년의 기본값은 혼합입니다. 있으면 스칼라, 없으면 자기 평가, 휴리스틱은 안전 난간으로.

### 이것이 일반화되는 이유

Reflexion은 새로운 알고리즘이라기보다 이름이 붙은 패턴입니다. 프로덕션의 "자가 치유" 에이전트는 거의 전부 어떤 변형을 돌립니다:

- Letta의 sleep-time compute (레슨 08): 별도 에이전트가 과거 대화를 되돌아보고 메모리 블록에 기록합니다.
- Claude Code의 `CLAUDE.md` / "메모리 저장" 패턴: 반성문을 배운 것(learning)으로 포착해 미래 세션 앞에 붙입니다.
- pro-workflow의 `/learn-rule` 명령: 교정 내용을 명시적 규칙으로 포착합니다.
- LangGraph의 반성 노드: 출력을 채점하고 필요하면 다듬기로 보내는 노드.

전부 같은 통찰에서 나옵니다. 자연어는 "실패에서 배운 것"을 실행 사이에 나르기에 충분히 풍부한 매체라는 것입니다.

### 잘 되는 때와 안 되는 때

Reflexion이 잘 동작하는 조건:

- 명확한 실패 신호가 있다(테스트 실패, 도구 오류, 틀린 답).
- 과제 부류가 재현 가능하다(같은 유형의 질문을 다시 물을 수 있다).
- 반성문이 궤적을 개선할 여지가 있다(충분한 행동 예산).

Reflexion이 도움이 되지 않는 조건:

- 에이전트가 이미 첫 시도에서 성공한다.
- 실패가 외부 요인이다(네트워크 다운, 도구 고장) — "네트워크가 죽어 있었다"는 반성은 미래 실행에 도움이 되지 않습니다.
- 반성문이 미신이 되어 버린다 — 한 번 우연히 삐걱거린 실행에 대한 서사를 저장하는 경우.

2026년의 함정: 메모리 부패(memory rot). 반성문은 쌓이고, 그중 일부는 낡았거나 틀리며, 에피소드 버퍼가 자랄수록 재실행은 느려집니다. 완화책: 주기적 압축(레슨 06), 반성문에 TTL 두기, 또는 별도의 sleep-time 청소 에이전트(Letta).

## 만들어 보기

`code/main.py`는 장난감 퍼즐 위에서 Reflexion을 구현합니다. 합이 목표값이 되는 3개 원소짜리 리스트를 만들기입니다. Actor는 후보 리스트를 내놓고, Evaluator는 합을 검사하고, Self-Reflector는 무엇이 잘못됐는지 한 줄을 씁니다. 반성문은 다음 시도를 위해 에피소드 메모리로 들어갑니다.

구성 요소:

- `Actor` — 반성문을 보면 개선되는 스크립트된 정책.
- `Evaluator.binary()` — 목표 합 기준 통과/실패.
- `SelfReflector` — 실패에 대한 한 줄 진단을 생성.
- `EpisodicMemory` — TTL 의미를 갖춘 크기 제한 리스트.

실행:

```
python3 code/main.py
```

트레이스는 세 번의 시도를 보여 줍니다. 시도 1이 실패하고, 반성문이 저장되고, 시도 2는 반성문을 보고 개선되지만 여전히 실패하고, 시도 3이 성공합니다. 베이스라인 실행(반성문 없음)과 비교해 보세요 — 베이스라인은 시도 1의 답에 갇힌 채입니다.

## 활용하기

LangGraph는 반성을 노드 패턴으로 제공합니다. Claude Code의 `/memory` 명령과 pro-workflow의 `/learn-rule`은 에피소드 버퍼를 마크다운 파일로 밖에 내놓습니다. Letta의 sleep-time compute는 쉬는 시간에 Self-Reflector를 돌려서 본 에이전트는 지연 시간에 묶이지 않게 합니다. OpenAI Agents SDK는 Reflexion을 직접 제공하지 않습니다. 궤적을 점수로 거부하는 커스텀 가드레일과 실행 사이에서 살아남는 메모리 `Session`으로 직접 만들면 됩니다.

## 출시하기

`outputs/skill-reflexion-buffer.md`는 반성문 캡처, TTL, 중복 제거를 갖춘 에피소드 버퍼를 만들고 관리합니다. 과제 부류와 실패가 주어지면 다음 시도에 실제로 도움이 되는 반성문을 내놓습니다("더 조심하세요" 같은 만능 문구가 아니라).

## 연습 문제

1. 이진 평가기를 거리 지표(목표에서 얼마나 멀리 떨어졌는지)를 반환하는 스칼라 평가기로 바꿔 보세요. 더 빨리 수렴할까요?
2. 반성문에 10시도짜리 TTL을 붙여 보세요. 그 시점 이후 오래된 반성문은 해가 될까요 도움이 될까요?
3. 휴리스틱 평가기를 구현해 보세요. 같은 행동이 반복되면 그 시도를 막힌 것으로 표시합니다. 이것은 Self-Reflector와 어떻게 상호작용할까요?
4. 반성문을 무시하는 적대적 Actor로 Reflexion을 돌려 보세요. Actor가 반성문을 알아보도록 강제하는 최소한의 반성문 프롬프트 엔지니어링은 무엇일까요?
5. Reflexion 논문의 AlfWorld 4절을 읽어 보세요. 130% 성공률 개선을 개념적으로 재현해 보세요. 기본 ReAct 대비 핵심 차이는 무엇일까요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| Reflexion | "자기 교정" | Shinn 등 2023 — Actor, Evaluator, Self-Reflector에 에피소드 메모리까지 |
| 언어적 강화 학습(Verbal reinforcement) | "경사 없는 학습" | 다음 시도의 프롬프트 앞에 붙는 자연어 반성문 |
| 에피소드 메모리(Episodic memory) | "과제별 반성문" | 한 과제 부류를 위한 이전 반성문의 크기 제한 버퍼 |
| 스칼라 평가기(Scalar evaluator) | "이진 성공 신호" | 정답에서 나온 통과/실패 또는 수치 점수 |
| 휴리스틱 평가기(Heuristic evaluator) | "패턴 기반 탐지기" | 미리 정의된 실패 시그니처(예: 막힌 루프, 과도한 단계 수) |
| 자기 평가기(Self-evaluator) | "자기 궤적 위의 LLM 재판관" | 정답이 없을 때의 저신호 대안 — 도구에 근거한 검증과 함께 쓰기 |
| 메모리 부패(Memory rot) | "낡은 반성문" | 에피소드 버퍼에 낡은 항목이 쌓임 — 압축/TTL로 해결 |
| sleep-time 반성(Sleep-time reflection) | "비동기 자기 성찰" | Self-Reflector를 핫 패스 밖에서 돌려 본 에이전트는 빠르게 유지 |
