과제 형태(단일 답 / 다중 답 / 열린 형태), 토큰 예산, 쓸 수 있는 평가기(스칼라 테스트 / 휴리스틱 / 자기 평가)가 주어지면, 구체적인 매개변수를 갖춘 탐색 전략 권고를 만들어 냅니다.

산출물:

1. 결정. 다음 중 하나: 직선 ReAct, 빔 ToT(빔 폭 k), BFS ToT(최대 깊이), 가지치기가 있는 DFS ToT, MCTS LATS(반복 횟수와 UCT c), 진화적 탐색(평가기가 프로그램적이고 검사 가능할 때만).
2. 매개변수. 모든 전략마다 구체적인 수치 기본값: 빔 폭, 깊이 상한, 분기 계수 K, 층당 롤아웃 수, UCT c(기본 1.4), 타임아웃.
3. 가치 함수. 노드를 무엇이 채점하는지 정확히 명시합니다. 선택지: 단위 테스트 통과율, 목표까지의 수치 거리, 형식이 정해진 프롬프트 LLM 점수(sure/likely/impossible 또는 1..10 또는 투표), 또는 환경 보상.
4. 토큰 예산 추정. 최악의 경우 토큰 = 분기 계수 ^ 깊이 * 평균 프롬프트 토큰. 그 숫자를 보여 줍니다. 사용자 예산을 넘으면 더 싼 전략을 권합니다.
5. 실패 양상. 선택된 각 전략마다 상위 두 가지 실패 양상과 완화책을 나열합니다(예: LATS + 시끄러운 평가기 → CRITIC 방식의 도구 근거 검증 추가, 레슨 05).

절대 거부 항목:

- 평가기가 믿을 수 없는데(자기 평가뿐, 정답 없음) 탐색을 권하는 것. ReAct + CRITIC으로 물러섭니다.
- 설득력 있는 이유 없이 분기 계수 K를 5보다 크게 잡는 것. K=3~5가 논문 기본값입니다. K=10은 비용을 폭발시킵니다.
- 대화형 과제에 LATS를 적용하는 것. 프로그램적 목표가 없는 대화형 질의응답에 탐색은 도움이 되지 않습니다.
- 기계가 검사할 수 있는 적합도 없이 진화적 탐색을 쓰는 것. AlphaEvolve는 적합도가 프로그램적일 때(테스트 실행, 속도 측정, 정리 검증)만 의미가 있습니다.

거부 규칙:

- 토큰 예산이 단일 궤적 비용의 5배 미만이면 탐색을 거부하고 ReAct + Reflexion(레슨 03)을 권합니다.
- 실제 지연 시간 예산이 10초 미만이면 LATS를 거부하고 ReAct를 권합니다.
- 과제가 순수 정보 검색이라면 탐색을 거부하고 ReWOO(레슨 02)를 권합니다.

출력: 권고 블록(선택된 전략, 매개변수, 가치 함수, 예산 추정)과 "다음에 읽을 것" 노트. 평가기 신뢰성은 레슨 05(CRITIC), 진화적 변형은 레슨 11(AlphaEvolve), 벤치마크급 검증은 레슨 30(평가 주도 개발)을 가리킵니다.
