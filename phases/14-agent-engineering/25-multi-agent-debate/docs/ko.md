# 멀티 에이전트 토론과 협업

> Du et al.(ICML 2024, "Society of Minds")은 N개의 모델 인스턴스가 독립적으로 답을 제안한 뒤, R라운드에 걸쳐 서로를 반복적으로 비판하며 수렴하는 방법을 제안했습니다. 사실성, 규칙 준수, 추론 능력을 끌어올립니다. 토큰 비용 면에서는 완전 메시(full mesh)보다 희소(sparse) 토폴로지가 유리합니다.

**유형:** Learn + Build(학습 + 구축)
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 14 · 12(워크플로 패턴), 페이즈 14 · 05(셀프 리파인과 CRITIC)
**시간:** 약 60분

## 학습 목표

- 토론 프로토콜을 설명할 수 있습니다. N명의 제안자, R라운드, 공유 답으로의 수렴입니다.
- 토론이 사실성, 규칙 준수, 추론을 왜 개선하는지 설명할 수 있습니다.
- 희소 토폴로지를 설명할 수 있습니다. 모든 토론자가 다른 모두를 볼 필요는 없습니다.
- 스크립트화된 LLM 위에서 완전 메시와 희소 변형 토론을 표준 라이브러리로 구현하고, 토큰 비용과 정확도를 측정할 수 있습니다.

## 문제 상황

셀프 리파인(레슨 05)은 하나의 모델이 스스로를 비판하는 방식이라 집단 사고(groupthink) 위험이 있습니다. CRITIC(레슨 05)은 비판을 외부 도구에 근거시키지만, 항상 사용할 수 있는 것은 아닙니다. 토론은 세 번째 방식을 도입합니다. 여러 인스턴스, 교차 비판, 그리고 의견 차이를 통한 수렴입니다.

## 핵심 개념

### Society of Minds (Du et al., ICML 2024)

- N개의 모델 인스턴스가 같은 질문에 독립적으로 답을 제안합니다.
- R라운드 동안 각 모델은 다른 모델들의 제안을 읽고 비판합니다.
- 모델들은 비판을 바탕으로 자기 답을 갱신합니다.
- R라운드가 끝나면 수렴된 답을 반환합니다.

원본 실험은 비용 때문에 N=3, R=2를 사용했습니다. 어려운 문제(MMLU, GSM8K, 체스 착수 타당성, 인물 전기 생성)에서는 에이전트와 라운드가 늘어날수록 정확도가 올라갑니다.

모델을 섞은 조합이 단일 모델 토론보다 낫습니다. ChatGPT + Bard를 함께 쓰는 것이 어느 하나 단독보다 우수했습니다.

### 희소 토폴로지

"Improving Multi-Agent Debate with Sparse Communication Topology"(arXiv:2406.11776, 2024-2025)는 완전 메시 토론이 항상 최적은 아님을 보였습니다. 희소 토폴로지(스타, 링, 허브-스포크)는 더 낮은 토큰 비용으로 비슷한 정확도를 낼 수 있습니다. 각 토론자는 동료들의 일부만 봅니다.

시사점:

- 완전 메시 N=5, R=3 = 5 × 3 = 15개 제안, 각 제안이 4명의 동료를 읽음 = 비판 연산 60회.
- 스타 N=5, R=3 (허브 1 + 스포크 4) = 15개 제안, 스포크는 허브만 읽음 = 비판 연산 12회.

### 토론이 도움이 되는 경우

- **사실성.** N개의 독립된 제안과 교차 검증이 환각을 줄입니다.
- **규칙 준수.** 체스 착수 타당성 — 한 모델이 놓친 규칙을 다른 모델이 잡아 줍니다.
- **개방형 추론.** 여러 관점이 올바른 답으로 좁혀 갑니다.

### 토론이 해가 되는 경우

- **지연 시간에 민감한 UX.** N × R 직렬 라운드는 감당하기 어려운 지연 시간일 수 있습니다.
- **비용에 민감한 대규모 서비스.** 질문 하나당 N × R 토큰이 듭니다.
- **단순 사실 조회.** 다섯 번 토론하는 것보다 한 번 조회하는 게 쌉니다.

### 2026년 실전 구현 사례

- **Anthropic 오케스트레이터-워커** (레슨 12) — 종합(synthesis) 단계를 붙인 토론의 한 변형입니다.
- **LangGraph 슈퍼바이저** (레슨 13) — 중앙 라우터 + 전문가 에이전트 구조로 토론을 노드 하나로 구현할 수 있습니다.
- **OpenAI Agents SDK** (레슨 16) — 에이전트들이 핸드오프를 주고받으며 반복 비판을 수행합니다.
- **멀티 에이전트 평가** — 토론 + 평가자-최적화자를 짝지어 평가 신호를 만듭니다.

### 이 패턴이 잘못되기 쉬운 지점

- **수렴 붕괴.** 모든 에이전트가 첫 번째 잘못된 답에 수렴해 버립니다. 필수 이견 라운드로 완화할 수 있습니다.
- **허브 실패.** 스타 토폴로지에서 나쁜 허브는 모두를 오염시킵니다. 허브를 순환시키거나 여러 개 두세요.
- **프롬프트 동질화.** 모든 에이전트가 같은 프롬프트를 쓰면 같은 답을 냅니다. 다양한 프롬프트와 모델을 사용하세요.

```figure
debate-converge
```

## 만들어 보기

`code/main.py`는 표준 라이브러리 기반 토론을 구현합니다.

- `Debater` 클래스(토론자마다 의견이 조금씩 흐르는 스크립트화된 LLM).
- `FullMeshDebate`와 `SparseDebate` 러너.
- 세 가지 질문: 사실형 하나, 규칙 기반 하나, 추론형 하나.
- 메트릭: 수렴된 답, 수렴까지 걸린 라운드 수, 총 비판 연산 수.

실행 방법:

```
python3 code/main.py
```

출력: 프로토콜별 정확도와 비용. 희소 방식이 완전 메시보다 낮은 비용으로 3문제 중 2문제에서 같은 정확도를 냅니다.

## 활용하기

- **Anthropic 오케스트레이터-워커** — 간단한 2~3워커 토론에 적합합니다.
- **LangGraph** — 체크포인팅이 있는 상태 기반 다중 라운드 토론에 적합합니다.
- **커스텀** — 연구 목적이나 특수한 정확성 보장이 필요할 때.

## 출시하기

`outputs/skill-debate.md`는 토폴로지, N, R, 수렴 규칙을 설정할 수 있는 멀티 에이전트 토론의 뼈대를 잡아 줍니다.

## 연습 문제

1. "강제 이견" 규칙을 구현해 보세요. 1라운드에서는 모든 토론자가 서로 다른 제안을 내야 합니다. 수렴 속도에 미치는 영향을 측정하세요.
2. 신뢰도 가중 집계를 추가해 보세요. 토론자가 (답, 신뢰도)를 반환하면 집계기가 신뢰도로 가중합니다. 도움이 되나요?
3. 에이전트 하나를 다른 의견을 가진 스크립트화된 LLM으로 교체해 보세요. 이질성이 정확도를 높이나요?
4. 세 질문에 대해 완전 메시와 희소 방식의 토큰 비용을 측정해 보세요. 비용-정확도 그래프를 그려 보세요.
5. Society of Minds 논문을 읽고 장난감 구현을 N=5, R=3으로 늘려 보세요. 무엇이 무너지나요? 무엇이 좋아지나요?
