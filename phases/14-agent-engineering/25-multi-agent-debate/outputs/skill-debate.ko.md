질문 유형과 정확도 목표가 주어지면 토론 프로토콜의 뼈대를 만듭니다.

산출물:

1. 동질화를 피하기 위해 서로 다른 프롬프트(가능하면 서로 다른 모델)를 가진 `Debater`.
2. 라운드 러너: 완전 메시, 스타, 또는 링 토폴로지.
3. 수렴 규칙: 다수결, 신뢰도 가중, 또는 폴백이 있는 특별 다수(supermajority-with-fallback).
4. 1라운드 강제 이견: 가능하면 모든 토론자가 서로 다른 제안을 반환합니다.
5. 비용 회계: 질문당 총 비판 연산 수 + 토큰 비용.

하드 리젝(무조건 거절):

- 모든 토론자가 같은 프롬프트이고 같은 모델인 경우. 집단 사고가 보장되는 구성입니다.
- 비용 확인 없이 N >= 6 완전 메시. 토론 연산은 O(N*R)로 늘어납니다.
- 수렴 규칙이 없는 경우. 토론자 0의 R라운드 답을 반환하는 것은 수렴이 아닙니다.

거절 규칙:

- 지연 시간에 민감한 제품(1초 미만 예산)이면 토론을 거절합니다. 대신 셀프 리파인(레슨 05)이나 병렬 투표(레슨 12)를 사용하세요.
- 질문이 단순 사실 조회(수도, 날짜, 정의)라면 토론을 거절합니다. 조회 + CRITIC(레슨 05)이 더 쌉니다.
- 평가 집합의 어떤 질문에서든 1라운드 이후 이견이 없으면 프로토콜을 거절합니다. 모델/프롬프트 다양성이 필요합니다.

출력: N/R 선택, 토폴로지 근거, 평가 집합에서의 비용-정확도 측정을 설명하는 `debater.py`, `topology.py`, `convergence.py`, `runner.py`, `README.md`. 마지막에는 "다음에 읽을 것"으로, 과제가 더 단순하면 레슨 12(워크플로 패턴)를, 더 큰 시스템에 토론을 넣으려면 레슨 28(오케스트레이션 패턴)을 가리킵니다.
