> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-failure-detector.md](skill-failure-detector.md)

제품 도메인과 트레이스 저장소가 주어지면 에이전트 실패 모드 감지기를 만듭니다.

산출물:

1. 모드별 감지기: `hallucinated_action`, `scope_creep`, `cascading_errors`, `context_loss`, `tool_misuse`, `success_hallucination`.
2. 도메인 고유 감지기(예: 개발 도구라면 "이슈 링크 없이 PR 생성", 마케팅 도구라면 "확인 없이 수신자 5명 초과 이메일 발송").
3. 모든 감지기를 각 트레이스에 적용하고 분포를 내놓는 태거.
4. 임계값 기반 알림: 오늘 트레이스의 5% 이상이 어떤 모드로 태깅되면 호출하거나 티켓을 엽니다.
5. 샘플 보존: 태깅된 각 트레이스마다 입력 + 출력 + 상태 스냅샷을 보존해 운영자 검토에 대비합니다.

하드 리젝(무조건 거절):

- 프로덕션에서 트레이스마다 LLM 호출이 필요한 감지기. 패턴 기반 감지기를 쓰고, LLM 판정은 표본 검토용으로 남겨 둡니다.
- 크래시에만 태깅. 대부분의 실패는 멀쩡해 보이는 출력을 냅니다. 콘텐츠 + 상태에 대한 시그니처 검사가 필요합니다.
- PII 마스킹 없이 태깅된 트레이스 저장. 실패 샘플에는 최악의 콘텐츠가 담기므로 저장 전에 스크러빙합니다.

거절 규칙:

- "모든 트레이스를 영원히 저장"을 원하면 비용 + 컴플라이언스 이유로 거절합니다. 태그 + 비율로 샘플링하세요.
- 제품에 "알려진 정상" 베이스라인이 없으면 드리프트 알림을 거절합니다. 드리프트에는 기준점이 필요합니다.
- 감지기가 버전 관리되지 않으면 거절합니다. 감지기의 레그레션은 예고 없이 신호를 망가뜨립니다.

출력: 임계값, 보존 정책, 알림 라우팅을 설명하는 `detectors.py`, `tagger.py`, `alerts.py`, `retention.py`, `README.md`. 마지막에는 "다음에 읽을 것"으로 레슨 24(관측 가능성 백엔드), 또는 적대적 실패 모드는 레슨 27(프롬프트 인젝션)을 가리킵니다.
