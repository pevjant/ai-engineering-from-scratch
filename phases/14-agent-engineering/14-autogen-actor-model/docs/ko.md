# 에이전트를 위한 액터 모델 — 비동기 메시지와 타입 지정 런타임

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> 에이전트를 액터로: 비동기 메시지 교환, 이벤트 주도 핸들러, 결함 격리, 자연스러운 동시성. AutoGen v0.4(Microsoft Research, 2025년 1월)는 이 모델을 중심으로 에이전트 오케스트레이션을 다시 설계했습니다. 프레임워크는 현재 유지보수 모드이며, 프로덕션 후계자는 Microsoft Agent Framework(2025년 10월 퍼블릭 프리뷰)입니다.

**유형:** 학습 + 빌드
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 14 · 01 (에이전트 루프), 페이즈 14 · 12 (워크플로 패턴)
**시간:** 약 75분

## 학습 목표

- 액터 모델 — 에이전트를 액터로, 메시지를 유일한 IPC로, 액터별 실패 격리 — 를 설명할 수 있습니다.
- AutoGen v0.4의 세 API 레이어 — Core, AgentChat, Extensions — 와 각각의 용도를 말할 수 있습니다.
- 메시지 전달과 처리를 분리하면 결함 격리와 자연스러운 동시성이 생기는 이유를 설명할 수 있습니다.
- Python으로 표준 라이브러리 액터 런타임을 구현하고, 두 에이전트 코드 리뷰 흐름을 그 위로 옮깁니다.

## 문제

대부분의 에이전트 프레임워크는 동기식입니다: 호출 스택 안에서 한 에이전트가 만들고 한 에이전트가 받습니다. 실패는 스택을 깨뜨리고, 동시성은 나중에 억지로 붙이는 것이며, 분산은 재작성을 요구합니다.

AutoGen v0.4의 답: 액터 모델. 각 에이전트는 개인 수신함을 가진 액터입니다. 메시지가 유일한 상호작용입니다. 런타임이 전달과 처리를 분리합니다. 실패는 한 액터에 격리됩니다. 동시성은 기본 제공입니다. 분산은 그저 다른 전송 계층일 뿐입니다.

## 개념

### 액터

액터는 이런 것을 가집니다:

- 개인 상태(외부에서 직접 만지지 않습니다).
- 수신함(메시지 큐).
- 핸들러: `receive(message) -> effects`. 효과는 "응답", "다른 액터에게 전송", "새 액터 생성", "상태 갱신", "스스로 정지"가 될 수 있습니다.

두 액터는 메모리를 공유할 수 없습니다. 메시지를 보낼 뿐입니다.

### 세 가지 API 레이어

AutoGen v0.4는 표면을 셋으로 나눕니다:

1. **Core.** 저수준 액터 프레임워크. `AgentRuntime`, `Agent`, `Message`, `Topic`. 이벤트 주도의 비동기 메시지 교환.
2. **AgentChat.** 태스크 주도의 고수준 API(v0.2의 ConversableAgent를 대체). `AssistantAgent`, `UserProxyAgent`, `RoundRobinGroupChat`, `SelectorGroupChat`.
3. **Extensions.** 연동 — OpenAI, Anthropic, Azure, 도구, 메모리.

### 분리가 중요한 이유

v0.2 모델에서는 `agent_a.chat(agent_b)`를 호출하면 agent_b가 돌아올 때까지 agent_a가 동기적으로 막힙니다. v0.4에서는 `send(agent_b, msg)`가 메시지를 agent_b의 수신함에 넣고 바로 돌아옵니다. 런타임이 나중에 전달합니다. 결과는 세 가지:

- **결함 격리.** 에이전트 B가 죽어도 에이전트 A는 죽지 않습니다 — 런타임이 B의 핸들러에서 실패를 잡아 어떻게 할지 결정합니다(로그, 재시도, 데드레터).
- **자연스러운 동시성.** 여러 메시지가 한 번에 진행 중입니다. 액터들은 각자 수신함을 동시에 처리합니다.
- **분산 준비 완료.** 수신함 + 전송은, 액터가 같은 프로세스에 있든 다른 호스트에 있든 같은 추상화입니다.

### 토폴로지

- **RoundRobinGroupChat.** 에이전트들이 고정 순번으로 차례를 돕니다.
- **SelectorGroupChat.** 셀렉터 에이전트가 대화 문맥을 보고 다음 차례를 고릅니다.
- **Magentic-One.** 웹 탐색, 코드 실행, 파일 처리를 위한 참조 멀티 에이전트 팀. AgentChat 위에 지어졌습니다.

### 관측 가능성(옵저버빌리티)

OpenTelemetry 지원이 내장되어 있습니다. 모든 메시지가 스팬을 내보내고, 도구 호출은 2026년 OTel GenAI 시맨틱 컨벤션(레슨 23)에 따라 `gen_ai.*` 속성을 실어 나릅니다.

### 현황: 유지보수 모드

2026년 초 기준: AutoGen v0.7.x는 연구와 프로토타이핑에는 안정적입니다. Microsoft는 활발한 개발을 프로덕션 후계자인 Microsoft Agent Framework로 옮겼습니다(2025년 10월 1일 퍼블릭 프리뷰; 1.0 GA는 2026년 1분기 말 목표). AutoGen 패턴은 앞으로도 깔끔하게 이식됩니다 — 오래가는 아이디어는 액터 모델이니까요.

```figure
actor-mailbox
```

## 직접 만들기

`code/main.py`는 표준 라이브러리 기반 액터 런타임을 구현합니다:

- `Message` — `sender`, `recipient`, `topic`, `body`를 담은 타입 지정 페이로드.
- `Actor` — `receive(message, runtime)`을 가진 추상 클래스.
- `Runtime` — 공유 큐, 전달, 결함 격리를 갖춘 이벤트 루프.
- 두 액터 데모: `ReviewerAgent`가 코드를 리뷰하고 `ChecklistAgent`가 체크리스트를 돌리며, 합의에 이를 때까지 메시지를 주고받습니다.

실행 방법:

```
python3 code/main.py
```

추적 결과에는 메시지 전달, 한 액터의 시뮬레이션된 실패(다른 액터는 멀쩡), 그리고 공동 판정으로의 수렴이 나옵니다.

## 활용하기

- **AutoGen v0.4/v0.7**(유지보수) — 연구, 프로토타이핑, 멀티 에이전트 패턴에 안정적입니다.
- **Microsoft Agent Framework** — 프로덕션 후계자(2025년 10월 퍼블릭 프리뷰). 같은 액터 모델 아이디어를 새로 단장한 API로.
- **LangGraph 스웜 토폴로지**(레슨 13) — 공유 도구 인계를 통한 비슷한 패턴.
- **자체 액터 런타임** — 특정 전송 계층(NATS, RabbitMQ, gRPC)이 필요할 때.

## 산출물 내보내기

`outputs/skill-actor-runtime.md`는 주어진 멀티 에이전트 태스크를 위해 최소 액터 런타임과 팀 템플릿(RoundRobin 또는 Selector)을 생성합니다.

## 연습 문제

1. 데드레터 큐를 추가하세요: 핸들러가 예외를 던지면 실패한 메시지를 사람이 살펴보도록 세워 둡니다. 연습용 구현에서 DLQ는 얼마나 자주 찾히나요?
2. `SelectorGroupChat`을 구현하세요: 셀렉터 액터가 대화 상태를 보고 다음 메시지를 처리할 액터를 고릅니다.
3. 분산 전송을 추가하세요: 프로세스 내 큐를 JSON-over-HTTP 서버로 바꿔 액터가 별개 프로세스에서 돌게 만듭니다.
4. 메시지마다 OTel 스팬(또는 아무 일도 안 하는 대체품)을 연결하세요. 레슨 23에 따라 `gen_ai.agent.name`, `gen_ai.operation.name`을 내보냅니다.
5. AutoGen v0.4의 아키텍처 글을 읽어 보세요. 연습용 구현을 진짜 `autogen_core` API로 옮겨 봅니다. 프로덕션에서 중요한데 건너뛴 것은 무엇이었나요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| 액터 | "에이전트" | 개인 상태 + 수신함 + 핸들러. 공유 메모리 없음 |
| 메시지 | "이벤트" | 타입 지정 페이로드. 액터가 상호작용하는 유일한 방법 |
| 수신함 | "메일박스" | 액터별 대기 메시지 큐 |
| 런타임 | "에이전트 호스트" | 메시지를 배차하고 실패를 격리하는 이벤트 루프 |
| 토픽 | "채널" | 액터 사이의 이름 붙은 발행-구독 경로 |
| 결함 격리 | "죽게 내버려 두기" | 한 액터의 실패가 다른 액터를 죽이지 않음 |
| RoundRobinGroupChat | "고정 순번 팀" | 에이전트들이 순서대로 차례를 돎 |
| SelectorGroupChat | "문맥 기반 팀" | 셀렉터가 다음 차례를 고름 |
| Magentic-One | "참조 팀" | 웹 + 코드 + 파일을 위한 멀티 에이전트 스쿼드 |
