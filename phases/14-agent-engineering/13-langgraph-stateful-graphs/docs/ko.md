# 상태 기반 그래프 오케스트레이션 — 내구 실행과 체크포인트

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> 에이전트는 상태 기계입니다. 노드는 함수, 엣지는 전이, 상태는 매 노드 뒤에 체크포인트로 저장됩니다. 실패가 나면 마지막 성공 체크포인트부터 이어 갑니다. LangGraph는 이런 저수준 상태 기반 오케스트레이션 모델의 2026년 기준점입니다.

**유형:** 학습 + 빌드
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 14 · 01 (에이전트 루프), 페이즈 14 · 12 (워크플로 패턴)
**시간:** 약 75분

## 학습 목표

- LangGraph의 핵심 모델 — 타입이 지정된 상태를 가진 상태 기계, 함수 노드, 조건부 엣지, 노드 뒤 체크포인트 — 를 설명할 수 있습니다.
- 문서가 강조하는 네 가지 능력 — 내구 실행(durable execution), 스트리밍, 휴먼인더루프(human-in-the-loop), 포괄적 메모리 — 를 말할 수 있습니다.
- LangGraph가 지원하는 세 가지 오케스트레이션 토폴로지 — 슈퍼바이저, 피어투피어(스웜), 계층형(중첩 서브그래프) — 를 설명할 수 있습니다.
- 타입이 지정된 상태, 조건부 엣지, 체크포인트/재개 사이클을 갖춘 상태 그래프를 표준 라이브러리로 구현합니다.

## 문제

에이전트와 워크플로는 같은 문제를 공유합니다: 40단계짜리 실행이 38단계에서 실패하면, 처음부터 다시 하는 게 아니라 38단계부터 이어 가고 싶어집니다. 상태를 이등 시민으로 취급하는 모델은, 처음부터 새로 돌린다고 가정한 라이브러리 주위에서 운영자가 재시도 코드를 짜느라 애를 먹게 만듭니다.

LangGraph의 설계적 답: 상태는 일급 타입 객체이고, 변경은 명시적이며, 체크포인트는 매 노드 뒤에 저장됩니다. 재개는 `load_state(session_id)` 호출 하나입니다.

## 개념

### 그래프

그래프는 다음으로 정의됩니다:

- **상태 타입.** 모든 노드가 읽고 변경하는 타입이 지정된 딕셔너리(또는 Pydantic 모델).
- **노드.** 순수 함수 `(state) -> state_update`. 업데이트는 반환 후 상태에 병합됩니다.
- **엣지.** 노드 사이의 조건부 또는 직접 전이.
- **시작과 끝.** `START`와 `END` 센티널 노드가 경계를 표시합니다.

예: `classify`, `refund`, `bug`, `sales`, `done` 노드를 가진 에이전트 — 라우팅 워크플로를 그래프로 표현한 것입니다.

### 내구 실행

각 노드가 반환될 때마다 런타임은 상태를 직렬화해 체크포인터(SQLite, Postgres, Redis, 커스텀)에 기록합니다. N단계에서 실패하면 런타임은 `resume(session_id)`로 정확한 상태를 그대로 들고 N+1단계부터 이어 갑니다.

LangGraph 문서는 이런 점이 중요한 프로덕션 사용자들을 명시적으로 소개합니다: Klarna, Uber, J.P. Morgan. 주장은 그래프 모양이 아니라, 그래프 모양에 체크포인팅을 더하면 복구가 값싸진다는 것입니다.

### 스트리밍

모든 노드는 부분 출력을 내보낼 수 있습니다. 그래프는 노드별 델타 이벤트를 호출자에게 스트리밍해, 그래프가 도는 동안 UI가 갱신되게 합니다.

### 휴먼인더루프

노드 사이에서 상태를 들여다보고 수정합니다. 구현 방식: 중요한 노드 전에 멈추고, 상태를 사람에게 보여주고, 수정을 받아들이고, 이어서 재개합니다. 상태가 이미 직렬화되어 있기 때문에 체크포인터 덕분에 이게 쉽습니다.

### 메모리

단기(한 번의 실행 안 — 상태에 든 대화 이력)와 장기(실행을 넘어 — 체크포인터와 별도의 장기 저장소로 영속화)가 있습니다. LangGraph는 도구를 통해 외부 메모리 시스템(Mem0, 커스텀)과 연동됩니다.

### 세 가지 토폴로지

1. **슈퍼바이저.** 중앙 라우터 LLM이 전문 서브에이전트에게 작업을 보냅니다. `langgraph-supervisor`의 `create_supervisor()`가 이 역할입니다(다만 2026년 LangChain 팀은 컨텍스트 통제를 더 하려면 이걸 도구 호출로 직접 하는 편이 낫다고 권합니다).
2. **스웜/피어투피어.** 에이전트들이 공유 도구 표면을 통해 직접 인계합니다. 중앙 라우터가 없습니다.
3. **계층형.** 슈퍼바이저가 하위 슈퍼바이저를 관리하며, 중첩 서브그래프로 구현합니다.

### 이 패턴이 잘못되는 지점

- **너무 작은 체크포인트.** 대화 턴만 체크포인트에 담으면 도구 상태와 메모리 기록은 복구할 수 없습니다. 전체 상태를 직렬화해야 합니다.
- **비결정론적 노드.** 재개는 노드 입력이 같은 상태 업데이트를 만든다고 가정합니다. 난수 시드, 실제 시계, 외부 API는 반드시 기록해 둬야 합니다.
- **조건부 엣지 남용.** 모든 엣지가 조건부인 그래프는 추론할 수 없는 상태 기계입니다. 가끔 갈라지는 선형 체인을 우선하세요.

```figure
langgraph-state
```

## 직접 만들기

`code/main.py`는 표준 라이브러리 기반 상태 그래프를 구현합니다:

- `State` — `messages`, `step`, `route`, `output`, `human_approval`을 담은 타입 지정 딕셔너리.
- `Node` — 상태를 받아 업데이트 딕셔너리를 돌려주는 호출 가능 객체.
- `StateGraph` — 노드 + 엣지 + 조건부 엣지 + 실행 + 재개.
- `SQLiteCheckpointer`(인메모리 가짜) — 매 노드 뒤 상태를 직렬화하고, `load(session_id)`로 복원합니다.
- 데모 그래프: classify -> 분기(refund / bug / sales) -> 사람 게이트 -> send.

실행 방법:

```
python3 code/main.py
```

추적 결과에는 사람 게이트에서 멈춘 첫 실행, 영속화, 그리고 최종 출력을 만들어 내는 재개가 나옵니다.

## 활용하기

- **LangGraph** — 기준점이자 프로덕션 준비 완료. `create_react_agent`, `create_supervisor`를 쓰거나 자신만의 그래프를 만드세요.
- **AutoGen v0.4**(레슨 14) — 높은 동시성 시나리오를 위한 액터 모델 대안.
- **Claude Agent SDK**(레슨 17) — 세션 저장소가 내장된 관리형 하네스스.
- **자체 구현** — 상태 모양이나 체크포인터 백엔드를 정밀하게 통제해야 할 때.

## 산출물 내보내기

`outputs/skill-state-graph.md`는 체크포인팅과 재개가 연결된 LangGraph 스타일 상태 그래프를 어떤 대상 런타임에든 생성합니다.

## 연습 문제

1. 분류 신뢰도가 임계값 아래일 때 `classify`에서 `end`로 가는 조건부 엣지를 추가하세요. 사람이 `route`를 직접 설정한 뒤 실행을 재개합니다.
2. SQLite 비슷한 가짜를 진짜 SQLite 체크포인터로 바꾸세요. 단계당 직렬화 오버헤드를 측정합니다.
3. 병렬 엣지를 구현하세요: 두 노드가 동시에 돌고 커스텀 리듀서로 병합합니다. 불변 상태가 여기서 얻어 주는 건 무엇일까요?
4. `langgraph-supervisor` 레퍼런스를 읽어 보세요. 연습용 구현을 `create_supervisor`로 옮기고 추적 모양을 비교합니다.
5. 스트리밍을 추가하세요: 각 노드가 도는 동안 부분 상태를 내보냅니다. 델타가 도착하는 대로 출력합니다.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| 상태 그래프 | "상태 기계로서의 에이전트" | 타입 지정 상태 + 노드 + 엣지 + 리듀서 |
| 체크포인터 | "영속화 백엔드" | 매 노드 뒤 상태를 직렬화해 재개를 가능하게 함 |
| 리듀서 | "상태 병합기" | 현재 상태와 노드의 업데이트를 합치는 함수 |
| 조건부 엣지 | "분기" | 상태의 함수가 고르는 엣지 |
| 서브그래프 | "중첩 그래프" | 다른 그래프 안에서 노드로 쓰이는 그래프 |
| 내구 실행 | "실패 지점에서 재개" | 정확한 상태를 들고 마지막 성공 노드부터 재시작 |
| 슈퍼바이저 | "라우터 LLM" | 전문 서브에이전트를 지휘하는 중앙 디스패처 |
| 스웜 | "P2P 에이전트" | 공유 도구로 인계하는 에이전트들. 중앙 라우터 없음 |
