> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-tool-registry.md](skill-tool-registry.md)

과제 도메인이 주어지면, 에이전트가 BFCL V4의 축들(에이전틱, 멀티 턴, 라이브, 논라이브, 환각)에서 믿음직하게 쓸 수 있는 도구 카탈로그를 만들어 냅니다.

산출물:

1. 도구 정의. 각 도구마다: `name`(snake_case), `description`(모델에게 언제 쓰고 언제 쓰지 말지 알려 줌), 타입이 지정된 속성, 필수 필드, 필요한 곳의 열거값, 수치의 최소/최대, 도구별 타임아웃, 도구별 샌드박스 정책(파일 시스템 표면, 네트워크, 메모리 상한)이 포함된 JSON Schema 입력.
2. 설명 품질 검사. 각 설명을 "이 설명은 모델에게 다른 도구 대신 이 도구를 골라야 할 때를 알려 주는가?"로 통과시킵니다. 두 도구의 설명이 겹치면 거부하고 다시 씁니다.
3. 병렬 디스패치 계획. 현실적인 각 과제마다 어떤 도구 호출이 독립적인지(병렬화 가능) 어떤 것이 순차여야 하는지 식별합니다. 기대되는 디스패치 그래프를 내보냅니다.
4. 검증 정책. 열거값 검사, 타입 강제 변환 규칙(예: "int-문자열은 받고, float-문자열은 거부"), 필수 필드 강제. 모든 실패는 구조화된 관찰 문자열로 돌아가고, 루프로 예외를 던지지 않습니다.
5. 관측 가능성. 각 도구는 `gen_ai.tool.name`, `gen_ai.tool.call.id`, `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result`(콘텐츠 정책이 요구하면 인라인이 아니라 참조) 속성을 가진 OpenTelemetry GenAI `tool_call` 스팬을 내보냅니다.

절대 거부 항목:

- 만능 셸/명령 실행 도구. 거부하고 구체적인 동사들(`git_status`, `fs_read`, `npm_test`)로 쪼갭니다.
- 매개변수가 닫힌 값 집합을 갖는데 열거값이 없는 것. 열거값 검증이 흐트러짐을 잡는 가장 싼 방법입니다.
- 서로 다른 두 도구에 같은 설명. 모델은 둘 사이를 믿음직하게 고를 수 없습니다.
- 도구 이름만 적는 `description`("두 수를 더합니다"). 무엇 대신 이것을 골라야 하는지(WHEN)를 반드시 포함합니다.
- 타임아웃 없음. 모든 도구 호출에는 상한이 있어야 합니다.

거부 규칙:

- 단일 에이전트의 도구 목록이 30개를 넘으면 거부하고 서브에이전트 위임(레슨 17)을 권합니다.
- 어떤 도구가 확인 게이트 없이 파괴적 동작을 한다면 거부하고 레슨 09(권한, 샌드박싱)를 가리킵니다.
- 과제가 computer use(클릭, 입력, 스크린샷)라면 거부하고 레슨 21을 가리킵니다 — 비전 기반 행동이라는 별개의 도구 형태입니다.

출력: Anthropic / OpenAI / Gemini SDK 호출에 바로 붙일 수 있는 JSON 도구 카탈로그, 디스패치 그래프 다이어그램, 검증 정책 문서, 그리고 레지스트리가 통과해야 할 BFCL식 미니 평가.

마지막은 "다음에 읽을 것" 포인터로 끝냅니다: 레슨 09(샌드박싱), 레슨 23(OTel GenAI 스팬), 또는 레슨 30(평가 주도).
