# HTN과 진화 탐색으로 계획하기

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> 기호적 계획은 계획의 옳음을 증명할 수 있는 경우를 다룹니다. 진화적 코드 탐색은 적합도 함수가 기계로 검증 가능한 경우를 다룹니다. ChatHTN(2025)과 AlphaEvolve(2025)는 각각 LLM과 짝을 이룰 때 무엇이 열리는지 보여줍니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 14 · 02 (ReWOO와 Plan-and-Execute)
**시간:** 약 75분

## 학습 목표

- 계층적 태스크 네트워크(Hierarchical Task Network)의 태스크, 메서드, 연산자, 사전조건, 효과를 설명할 수 있습니다.
- ChatHTN의 하이브리드 루프 — 기호 탐색에 LLM 폴백 분해를 얹은 구조 — 를 설명할 수 있습니다.
- AlphaEvolve의 진화 루프와, 프로그램 방식 평가기가 있어야만 동작하는 이유를 설명할 수 있습니다.
- 연습용 HTN 플래너와 연습용 진화 탐색을 표준 라이브러리로 구현합니다.

## 문제

ReWOO(레슨 02), Plan-and-Execute, ReAct가 대부분의 에이전트 계획을 커버합니다. 하지만 두 가지 경우는 잘 커버하지 못합니다:

1. **옳음을 증명할 수 있는 계획.** 스케줄링, 항공 경로, 컴플라이언스 워크플로 — 계획은 구조 자체로 타당해야 합니다. 가끔 한 단계를 환각하는 유창한 LLM 계획은 용납할 수 없습니다.
2. **기계로 검증 가능한 적합도 함수가 있는 최적화.** 행렬 곱셈, 스케줄링 휴리스틱, 컴파일러 패스 — 목표는 "올바른 계획"이 아니라 "가장 좋은 계획"입니다.

HTN 계획과 AlphaEvolve는 서로 다른 두 문제를 풉니다. 둘 다 LLM을 대체재가 아니라 증폭기로 씁니다.

## 개념

### 계층적 태스크 네트워크

HTN은 이렇게 구성됩니다:

- **태스크** — 복합(분해해야 하는)과 원시(바로 실행 가능한)로 나뉩니다.
- **메서드** — 사전조건을 갖고, 복합 태스크를 하위 태스크로 분해하는 방법입니다.
- **연산자** — 사전조건과 효과를 가진 원시 행동입니다.
- **상태** — 사실(fact)들의 집합입니다.

계획이란: 목표 태스크와 초기 상태가 주어졌을 때, 사전조건이 순서대로 충족되는 원시 연산자들로의 분해를 찾는 것입니다.

HTN은 LLM보다 오래된 기술이지만, 여전히 옳음을 증명할 수 있는 계획의 기준점입니다.

### ChatHTN (Gopalakrishnan 외, 2025)

ChatHTN(arXiv:2505.11814)은 기호 HTN과 LLM 질의를 엮어 냅니다:

1. 현재 복합 태스크를 기존 메서드로 분해해 봅니다.
2. 맞는 메서드가 없으면 LLM에게 묻습니다: "상태 `s`에서 `task`를 어떻게 분해하겠습니까?"
3. LLM 응답을 후보 하위 태스크로 번역합니다.
4. 연산자 스키마로 검증해 잘못된 분해는 거부합니다.
5. 재귀합니다.

논문의 핵심 주장: 생산되는 모든 계획은 타당함을 증명할 수 있습니다. LLM 제안은 후보 분해로만 들어올 뿐, 계획을 직접 수정하지는 않기 때문입니다. 옳음은 기호 레이어가 책임지고, LLM은 메서드 라이브러리를 넓힙니다.

온라인 메서드 학습(OpenReview `gwYEDY9j2x`, 2025 후속 연구)은 LLM이 만든 분해를 회귀로 일반화하는 학습기를 더해 LLM 질의 빈도를 최대 75%까지 줄입니다.

### AlphaEvolve (Novikov 외, 2025)

AlphaEvolve(arXiv:2506.13131, DeepMind, 2025년 6월)는 정체가 다릅니다: Gemini 2.0 Flash/Pro 앙상블이 지휘하는 진화적 코드 탐색입니다.

루프:

1. 시드 프로그램 + 프로그램 방식 평가기(적합도 점수를 돌려줌)로 시작합니다.
2. LLM 앙상블이 변이를 제안합니다.
3. 변이를 평가기에 돌립니다.
4. 최고를 남기고 다시 변이합니다.

공개된 성과:

- 4x4 복소 행렬 곱셈에서 56년 만에 처음으로 Strassen을 넘어선 기록(스칼라 곱 48회).
- Borg 스케줄링 휴리스틱으로 구글 컴퓨팅 0.7% 회수.
- 최전선 워크로드에서 FlashAttention 32% 가속.

까다로운 제약 하나: 적합도 함수는 기계로 검증 가능해야 합니다. 산문 답변을 대상으로 한 진화 탐색은 수렴하지 않습니다.

### 언제 무엇을 쓸까

| 문제 유형 | 사용할 것 | 이유 |
|---------------|-----|-----|
| 강한 제약이 있는 스케줄링 | HTN + ChatHTN | 타당성 증명 가능 |
| 컴파일러 최적화 | AlphaEvolve | 기계 검증 가능한 적합도 |
| 여러 단계 태스크 실행 | ReAct / ReWOO | 루프 안에 LLM, 형식적 보장은 없음 |
| 테스트가 있는 코드 개선 | AlphaEvolve | 테스트가 곧 평가기 |
| 정책에 묶인 자동화 | HTN | 사전조건이 정책을 부호화 |

### 이 패턴이 잘못되는 지점

- **연산자 없는 HTN.** 사전조건/효과 스키마가 없으면 타당성 주장이 무너집니다. ChatHTN의 "LLM이 분해 제안"에는 잘못된 수를 거부할 스키마가 필요합니다.
- **진짜 평가기 없는 AlphaEvolve.** "코드가 더 나은지 LLM에게 물어보기"는 적합도 함수가 아닙니다. 평가기는 결정론적이고 빨라야 합니다.
- **과잉 엔지니어링.** 대부분의 에이전트 태스크는 둘 다 필요 없습니다. 먼저 ReAct나 ReWOO부터 손대세요.

## 직접 만들기

`code/main.py`는 연습용 두 가지를 구현합니다:

- 연산자, 메서드, 사전조건, 효과를 갖추고, 복합 태스크에 맞는 메서드가 없으면 `LLMFallback`이 발동하는 표준 라이브러리 기반 HTN 플래너. "LLM"은 스크립트로 짠 분해기라 플래너가 오프라인에서도 돌아갑니다.
- 산술 프로그램 위의 표준 라이브러리 기반 진화 탐색: 테스트 집합 위에서 `|f(x) - target|`을 최소화하는 식을 키워 갑니다. 평가기는 결정론적입니다.

실행 방법:

```
python3 code/main.py
```

추적 결과에는 복합 태스크를 분해하는 HTN 플래너(계획 도중 LLM 폴백 발동)와, 목표 식에 수렴하는 진화 루프가 나옵니다.

## 활용하기

- **HTN 플래너** — `pyhop`, `SHOP3`를 쓰거나, 도메인 전용 정책 강제를 위해 직접 만듭니다.
- **ChatHTN** — 연구 코드입니다. 패턴(기호 + LLM 폴백)은 어떤 HTN 플래너에도 깔끔하게 이식됩니다.
- **AlphaEvolve** — DeepMind 논문입니다. 패턴(앙상블 + 평가기)은 재현 가능합니다. OpenEvolve 같은 오픈소스 포크들도 나오고 있습니다.
- **에이전트 프레임워크** — 아직 어디도 일급 HTN이나 AlphaEvolve를 기본 제공하지 않습니다. 서브에이전트나 백그라운드 워커로 만드세요.

## 연습 문제

1. HTN 플래너에 백트래킹을 추가하세요: 실행 중 연산자의 사후조건이 실패하면 되돌아가 다음 메서드를 시도합니다.
2. ChatHTN에 LLM 메서드 캐시를 추가하세요: LLM이 상태 패턴 `P`에서 태스크 `T`를 분해하면 결과를 저장합니다. 다음 호출에서는 먼저 메서드 라이브러리를 다시 확인합니다.
3. 진화 탐색 평가기를 실제 테스트 스위트로 바꾸세요. 테스트 케이스 20개를 통과하는 정렬 함수를 진화시키고, 수렴까지 걸린 세대 수를 보고합니다.
4. AlphaEvolve의 평가기 설계 노트를 읽어 보세요. 관심 있는 도메인(SQL 질의 최적화, 테스트 스위트 최소화, 배포 YAML)에 대한 평가기를 설계합니다.
5. 조합해 보세요: HTN으로 복합 태스크를 하위 태스크로 분해한 뒤, 각 하위 태스크의 원시 연산자에 진화 탐색을 적용합니다. 어디서 빛나고, 어디서 과잉 엔지니어링이 될까요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| HTN | "계층적 플래너" | 연산자·사전조건·효과를 갖춘 태스크 분해 |
| 메서드 | "분해 규칙" | 복합 태스크를 하위 태스크로 쪼개는 방법 |
| 연산자 | "원시 행동" | 사전조건과 효과를 가진 구체적 단계 |
| ChatHTN | "LLM + HTN" | 맞는 메서드가 없을 때 기호 플래너가 LLM에게 물어봄 |
| AlphaEvolve | "진화적 코드 탐색" | LLM 앙상블이 코드를 변이하고, 결정론적 평가기가 선택 |
| 적합도 함수 | "평가기" | 출력 위에서 매기는, 결정론적이고 기계 검증 가능한 점수 |
| 온라인 메서드 학습 | "캐시된 LLM 분해" | LLM 계획을 저장·일반화해 질의 비용을 절감 |
