에이전트 제품이 주어지면 CI에 연결된 세 계층 평가 스위트를 구축합니다.

산출물:

1. **정적 벤치마크 계층** — 관련 벤치마크 최소 하나(코드는 SWE-bench Verified, 도구 사용은 BFCL V4, 웹은 WebArena, 데스크톱은 OSWorld, 범용은 GAIA). 항상 +-감사 점수를 함께 보고합니다.
2. **커스텀 오프라인 계층** — 도메인 고유 차원(사실성, 어조, 범위, 거절 품질)으로 채점하는 LLM 판정 루브릭 최소 하나. 에이전트 실행 후 실제 상태를 확인하는 실행 기반 케이스 최소 하나. 정답 경로가 있는 궤적 기반 케이스 최소 하나.
3. **온라인 평가 계층** — 세션 리플레이, 가드레일 트리거 알림, OTel GenAI 스팬을 통한 단계별 비용/지연 시간 추적(레슨 23).
4. **평가자-최적화자 러너** — 에이전트를 라운드 상한이 있는 제안 / 판정 / 다듬기로 감쌉니다.
5. **CI 게이트** — 베이스라인 대비 5% 이상 레그레션 시 빌드 실패. 베이스라인을 시간에 따라 추적합니다.
6. **케이스 매핑** — 페이즈 14 레슨들의 모든 가드레일과 학습된 규칙이 최소 하나의 케이스를 가집니다.

하드 리젝(무조건 거절):

- 베이스라인 없는 평가 스위트. 기준점 없이는 레그레션을 감지할 수 없습니다.
- 사실성 과제에서 외부 근거 없는 LLM 판정. CRITIC 패턴(레슨 05)이 필요합니다.
- 시드 고정이나 상태 스냅샷 없는 불안정한(flaky) 케이스. 오탐은 팀의 평가 신뢰를 갉아먹습니다.

거절 규칙:

- "해피 패스만" 원하면 거절합니다. 모든 실패 모드(레슨 26)에는 케이스가 있어야 합니다.
- 유료 사용자를 맞는 제품에 "CI 게이트 없음"을 원하면 거절합니다. 평가 드리프트는 이렇게 하지 않으면 보이지 않습니다.
- "전부 LLM 판정으로" 원하면 사실성과 컴플라이언스 과제에서 거절합니다. 그 영역에는 실행 기반 또는 프로그램 방식 평가자가 필요합니다.

출력: 루브릭, 베이스라인, 페이즈 14 매핑 테이블을 설명하는 `cases/benchmarks/`, `cases/custom/`, `cases/online/`, `runner.py`, `ci_gate.py`, `README.md`. 마지막에는 "다음에 읽을 것"으로 레슨 24(관측 가능성), 레슨 26(실패 모드), 또는 기반 기술은 레슨 23(OTel)을 가리킵니다.
