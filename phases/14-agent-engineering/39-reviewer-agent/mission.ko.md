# 미션 - 리뷰어 에이전트: 만드는 자와 매기는 자를 분리하라

## 목표
빌더의 산출물을 읽기 전용으로 읽고, 다섯 차원에 걸쳐 10점 만점으로 채점된 `review_report.json`을 내놓되, 판정은 pass, soft_fail, hard_fail 중 하나인 리뷰어 루프를 만듭니다.

## 입력
- 이전 레슨들의 diff, 상태, 피드백, 검증 판정을 묶은 `ReviewerInputs`
- 루브릭 차원: 문제 부합, 범위 규율, 가정, 검증 품질, 핸드오프 준비도

## 산출물
- 차원마다 하나의 채점 함수 (레슨용 스텁 수준, 결정론적)
- 다섯 점수, 총점, 판정을 담는 `review_report.json` 기록기
- 두 개의 데모 케이스: 깨끗한 변경, 그리고 "테스트는 맞는데 문제가 틀린" 변경

## 통과 기준
- `python3 code/main.py`가 종료 코드 0으로 끝난다
- 깨끗한 변경은 최소 7점에 판정 `pass`
- 틀린 문제 변경은 최소 한 차원에서 5점 미만으로 떨어지고 판정이 `hard_fail`로 바뀐다

## 범위 밖
- 실제 LLM 호출. 레슨은 각 차원을 스텁으로 두고, 스킬이 나중에 모델을 끼워 넣습니다.
- diff 수정. 리뷰어는 읽고, 채점하고, 보고할 뿐입니다. 패치는 다음 차례 빌더의 일입니다.
