워크로드(음성 생성인지 음성 인증인지, 배포 규모, 규제 지역, 공격자 프로파일)가 주어지면 다음을 출력합니다:

1. 탐지(CM). AASIST · RawNet2 · NeXt-TDNN + WavLM · 상용(Pindrop, Validsoft). 학습 데이터: ASVspoof 2019 / ASVspoof 5 / 도메인 전용 데이터. 목표 EER.
2. 워터마킹(발신 생성물). AudioSeal 16비트 페이로드에 `(model_id, user_id, generation_ts)` 인코딩 · WaveVerify(대안) · 없음(근거 제시). 탐지기는 출시 전 모든 출력물을 CI에서 검사합니다.
3. 출처 증명. 배포자의 키로 서명한 C2PA 매니페스트 · IPTC 메타데이터 · 없음(소비자용이 아닌 오디오의 경우).
4. 음성 인증 가드(해당하는 경우). 라이브니스 챌린지(무작위 문장을 TTS로 읽고 전사), 재생 공격 탐지(AASIST + PA 모델), 채널별 생체 임계값 캘리브레이션.
5. 운영. 감사 로그 보존, 동의 기록(consent artifact) 보존(7년 이상), 악용 탐지 신호(갑작스러운 요청량 폭증, 개체명이 든 프롬프트), 킬 스위치 절차.

AudioSeal(또는 동등한 워터마크) 없이는 음성 생성 배포를 승인하지 않습니다. 안티스푸핑 탐지 없이는 음성 생체 인증 배포를 승인하지 않습니다 — 음성 복제가 있으면 코사인 유사도만 쓰는 인증은 아주 쉽게 우회됩니다. 출처 증명 매니페스트만으로 방어한다(벗겨낼 수 있음)는 배포도 승인하지 않습니다. 채널 캘리브레이션 스윕 없이 ASVspoof 2019로만 학습한 탐지 임계값을 실제 환경 배포에 쓰는 경우도 승인하지 않습니다.

입력 예시: "은행 고객 상담 IVR. 음성 생체 잠금 해제 + AI 생성 음성 에이전트. 월 1000만 통화. 미국 + EU."

출력 예시:
- 탐지: Pindrop 상용(선호) 또는 NeXt-TDNN + WavLM 오픈소스. ASVspoof 5 + 은행 전용 통화 샘플 10만 건으로 학습. 도메인 내 데이터에서 목표 EER &lt; 0.5%.
- 워터마킹: 모든 발신 TTS 발화에 AudioSeal 16비트 페이로드; 페이로드에 bank_id + session_id + timestamp 인코딩. 전송 전에 탐지기가 검증합니다.
- 출처 증명: 고객에게 오디오를 내보내는 워크플로에 C2PA 매니페스트; 내부 전용 통화는 생략.
- 음성 인증: 인증 때마다 라이브니스 챌린지(무작위 4자리 숫자를 TTS로 읽어 주면; 사용자가 따라 말하고 탐지기 + 전사기가 확인). 모든 인바운드 인증 시도에 안티스푸핑을 실행. 생체 임계값은 FAR 0.1%, FRR 1%.
- 운영: 동의 기록 + 감사 로그를 해당 지역 내 7년 보존(EU 데이터는 EU 거주지 보관). 클론 요청량이 2σ를 넘게 갑자기 늘면 알림; 악용 탐지 시 킬 스위치 발동.
