과제(생성 LM, 압축, 완전 이중 대화, 음악 편집, 충실도 목표)가 주어지면 다음을 출력한다:

1. 코덱. EnCodec-24k · EnCodec-48k · DAC-44.1k · SNAC-24k · Mimi · (대안: 뉴럴이 아닌 압축이라면 Opus). 한 문장 근거.
2. 프레임 레이트 + 코드북. 비트레이트 예산, 코드북 수(보통 4~12), 목표 클립 길이에 대한 시퀀스 길이.
3. 토큰화 방식. 플랫 vs 계층형 (SNAC) vs 의미+음향 (Mimi). LM이 토큰을 소비하는 방식.
4. 디코더. 코덱 내장 디코더 · 외부 보코더 (HiFi-GAN) · LM 전용 (보코더 없이 코덱 토큰을 직접 예측). 이유를 설명한다.
5. 학습 파급 효과. 인코더/디코더를 학습해야 하나? 도메인 오디오로 파인튜닝 (음성 전용 → 도메인 특화 음악)? 아니면 그대로 동결?

지연 시간 예산이 빡빡한 AR-LM 워크로드에 DAC는 거부한다 — 86 Hz 프레임 레이트 × 8 코드북 = 10초당 5,504 토큰, 빠른 생성에는 너무 길다. 음악에 Mimi는 거부한다 — 음성에 맞춰 튜닝됐다. 의미 조건부 생성에 EnCodec은 거부한다 — 의미 코드북이 없어 텍스트에서 흐릿한 음성이 나온다.

예시 입력: "텍스트 음성 변환 TTS용 AR LM. 목표 TTFA 200 ms. 영어 전용."

예시 출력:
- 코덱: Mimi. 의미+음향 분리가 텍스트 → 코드북 0 → 코드북 1~7이라는 분해를 가능하게 하며, 이것이 빠르면서도 음성 복제를 지원한다.
- 프레임 레이트 + 코드북: 12.5 Hz · 코드북 8개 · 4.4 kbps. 10초 = 1,000 토큰.
- 토큰화: 텍스트 + 화자 참조로 코드북 0을 먼저 예측. 그다음 코드북 0 + 화자 참조를 조건으로 코드북 1~7 예측 (depth-transformer 패턴).
- 디코더: Mimi 내장 디코더. 외부 보코더 불필요.
- 학습: 텍스트-투-코덱 LM을 학습하고, Mimi는 동결.
