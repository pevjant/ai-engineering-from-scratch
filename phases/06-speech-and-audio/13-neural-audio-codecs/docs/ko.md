# 뉴럴 오디오 코덱 — EnCodec, SNAC, Mimi, DAC, 그리고 의미-음향 분리

> 2026년 오디오 생성은 거의 전부 토큰으로 이루어집니다. EnCodec, SNAC, Mimi, DAC은 연속적인 파형을 트랜스포머가 예측할 수 있는 이산 시퀀스로 바꿉니다. 의미 토큰 vs 음향 토큰 분리 — 첫 코드북은 의미, 나머지는 음향 — 는 오디오 분야에서 트랜스포머 이후 가장 중요한 아키텍처 변화입니다.

**유형:** Learn
**언어:** Python
**선수 지식:** 페이즈 6 · 02 (스펙트로그램), 페이즈 10 · 11 (양자화), 페이즈 5 · 19 (서브워드 토큰화)
**소요 시간:** 약 60분

## 문제 상황

언어 모델은 이산 토큰으로 동작합니다. 오디오는 연속적이죠. 음성 / 음악용 LLM 스타일 모델 — MusicGen, Moshi, Sesame CSM, VibeVoice, Orpheus — 을 만들려면 먼저 **뉴럴 오디오 코덱**이 필요합니다. 오디오를 작은 어휘의 토큰으로 이산화하는 학습된 인코더, 그리고 파형을 복원하는 짝꿍 디코더입니다.

두 계열이 등장했습니다:

1. **재구성 우선 코덱** — EnCodec, DAC. 지각적 음질을 최적화합니다. 토큰은 "음향적"입니다 — 화자 정체성, 음색, 배경 소음까지 전부 담죠.
2. **의미 우선 코덱** — Mimi (Kyutai), SpeechTokenizer. 첫 코드북이 언어적 / 음성학적 내용을 담도록 강제합니다(보통 WavLM에서 증류). 이후 코드북은 음향 디테일입니다.

2024-2026년의 통찰: **순수 재구성 코덱으로는 텍스트에서 음성을 생성하려 할 때 흐릿한(blurry) 음성이 나옵니다.** 코덱 토큰 위의 LLM은 같은 코드북 안에서 언어 구조와 음향 구조를 둘 다 배워야 하는데, 이건 확장이 안 됩니다. 둘을 분리하는 것 — 코드북 0은 의미, 코드북 1-N은 음향 — 이 Moshi와 Sesame CSM이 동작할 수 있게 만드는 열쇠입니다.

## 개념

![네 코덱 지도: EnCodec, DAC, SNAC (멀티스케일), Mimi (의미+음향)](../assets/codec-comparison.svg)

### 핵심 기술: 잔차 벡터 양자화 (RVQ)

거대한 코드북 하나(좋은 품질을 내려면 수백만 개의 코드가 필요합니다) 대신, 모든 현대 오디오 코덱은 **RVQ**를 씁니다: 작은 코드북들의 폭포입니다. 첫 코드북이 인코더 출력을 양자화하고, 두 번째가 잔차(residual)를 양자화하는 식이죠. 코드북 하나는 1024개의 코드입니다. 코드북 8개면 사실상의 어휘는 1024^8 = 10^24.

추론 때 디코더는 프레임마다 선택된 모든 코드를 합쳐 복원합니다.

### 2026년에 중요한 네 코덱

**EnCodec (Meta, 2022).** 베이스라인. 파형 위의 인코더-디코더, RVQ 병목. 24 kHz, 코드북 최대 32개, 기본은 1.5 kbps에 코드북 4개. `1D conv + transformer + 1D conv` 아키텍처입니다. MusicGen이 사용합니다.

**DAC (Descript, 2023).** L2 정규화된 코드북, 주기적 활성 함수, 개선된 손실을 갖춘 RVQ. 오픈 코덱 중 최고의 재구성 충실도 — 코드북 12개로는 원본 음성과 구분이 안 되기도 합니다. 44.1 kHz 풀밴드.

**SNAC (Hubert Siuzdak, 2024).** 멀티스케일 RVQ — 거친(coarse) 코드북은 세밀한(fine) 코드북보다 낮은 프레임 레이트로 동작합니다. 오디오를 사실상 계층적으로 모델링합니다: 약 12 Hz의 거친 "스케치"에 50 Hz의 디테일을 얹죠. Orpheus-3B가 사용합니다. 계층 구조가 LM 기반 생성에 잘 맞기 때문입니다.

**Mimi (Kyutai, 2024).** 2026년의 게임 체인저. 12.5 Hz 프레임 레이트(극도로 낮음), 4.4 kbps에 코드북 8개. 코드북 0은 **WavLM에서 증류**됩니다 — WavLM의 음성 내용 특성을 예측하도록 학습된 것이죠. 코드북 1~7은 음향 잔차입니다. 이 분리가 Moshi (레슨 15)와 Sesame CSM을 떠받칩니다.

### 언어 모델링에서 프레임 레이트가 중요한 이유

프레임 레이트가 낮을수록 시퀀스가 짧아지고 LM이 빨라집니다.

| 코덱 | 프레임 레이트 | 1초 = N 프레임 | 적합 용도 |
|-------|-----------|----------------|---------|
| EnCodec-24k | 75 Hz | 75 | 음악, 일반 오디오 |
| DAC-44.1k | 86 Hz | 86 | 고충실도 음악 |
| SNAC-24k (coarse) | ~12 Hz | 12 | AR-LM에 효율적 |
| Mimi | 12.5 Hz | 12.5 | 스트리밍 음성 |

12.5 Hz에서 10초짜리 발화는 코덱 프레임 고작 125개 — 트랜스포머가 충분히 예측할 수 있습니다.

### 의미 토큰 vs 음향 토큰

```
frame_t → [semantic_token_t, acoustic_token_0_t, acoustic_token_1_t, ..., acoustic_token_6_t]
```

- **의미 토큰 (Mimi의 코드북 0).** 무엇이 말했는지 — 음소, 단어, 내용을 담습니다. 보조 예측 손실로 WavLM에서 증류됩니다.
- **음향 토큰 (코드북 1~7).** 음색, 화자 정체성, 운율, 배경 소음, 세밀한 디테일을 담습니다.

AR LM은 먼저 의미 토큰을 예측하고(텍스트 조건), 그다음 음향 토큰을 예측합니다(의미 + 화자 참조 조건). 바로 이 분해 때문에 현대 TTS가 음성을 제로샷 복제할 수 있는 겁니다. 의미 모델이 내용을, 음향 모델이 음색을 맡거든요.

### 2026년 재구성 품질 (초당 비트, 비트레이트가 낮을수록 유리)

| 코덱 | 비트레이트 | PESQ | ViSQOL |
|-------|---------|------|--------|
| Opus-20kbps | 20 kbps | 4.0 | 4.3 |
| EnCodec-6kbps | 6 kbps | 3.2 | 3.8 |
| DAC-6kbps | 6 kbps | 3.5 | 4.0 |
| SNAC-3kbps | 3 kbps | 3.3 | 3.8 |
| Mimi-4.4kbps | 4.4 kbps | 3.1 | 3.7 |

비트당 지각 품질은 여전히 Opus 같은 전통 코덱이 이깁니다. 뉴럴 코덱이 이기는 곳은 **이산 토큰**(Opus는 만들어 주지 않음)과 **생성 모델 품질**(LM이 그 토큰으로 해낼 수 있는 일)입니다.

## 직접 만들어 보기

### 단계 1: EnCodec으로 인코딩

```python
from encodec import EncodecModel
import torch

model = EncodecModel.encodec_model_24khz()
model.set_target_bandwidth(6.0)  # kbps

wav = torch.randn(1, 1, 24000)
with torch.no_grad():
    encoded = model.encode(wav)
codes, scale = encoded[0]
# codes: (1, n_codebooks, n_frames), dtype=int64
```

6 kbps에서 `n_codebooks=8`. 각 코드는 0~1023 (10비트).

### 단계 2: 디코딩하고 재구성 품질 측정

```python
with torch.no_grad():
    wav_recon = model.decode([(codes, scale)])

from torchaudio.functional import compute_deltas
import torch.nn.functional as F

mse = F.mse_loss(wav_recon[:, :, :wav.shape[-1]], wav).item()
```

### 단계 3: 의미-음향 분리 (Mimi 스타일)

```python
from moshi.models import loaders
mimi = loaders.get_mimi()

with torch.no_grad():
    codes = mimi.encode(wav)  # shape (1, 8, frames@12.5Hz)

semantic = codes[:, 0]
acoustic = codes[:, 1:]
```

의미 코드북 0은 WavLM에 정렬되어 있습니다. 텍스트-투-의미 트랜스포머를 학습할 수 있습니다 — 오디오로 바로 가는 것보다 훨씬 작은 어휘죠. 그다음 별도의 음향-투-파형 디코더가 화자 참조를 조건으로 동작합니다.

### 단계 4: 코덱 토큰 위의 AR LM이 잘 되는 이유

Mimi의 12.5 Hz × 8 코드북 기준 10초 음성 클립:

```
N_tokens = 10 * 12.5 * 8 = 1000 tokens
```

1000개 토큰은 트랜스포머에게 사소한 컨텍스트입니다. 256M 파라미터 트랜스포머라면 요즘 GPU에서 10초짜리 음성을 밀리초 단위로 만들어 냅니다.

## 함정들

- **코드북 과다.** 코드북을 늘리면 충실도는 선형으로 오르지만 LM 시퀀스 길이도 선형으로 늘어납니다. 8~12에서 멈추세요.
- **프레임 레이트 불일치.** 12.5 Hz Mimi로 LM을 학습한 뒤 50 Hz EnCodec으로 파인튜닝하면 조용히 실패합니다.
- **모든 코드북이 똑같다는 착각.** Mimi에서 코드북 0은 내용을 나릅니다. 잃으면 알아듣는 것 자체가 무너집니다. 코드북 7을 잃는 건 거의 안 보입니다.
- **재구성 품질만을 지표로 삼기.** 코덱이 재구성은 훌륭해도 의미 구조가 나쁘면 LM 기반 생성에는 쓸모가 없습니다.

## 연습 문제

1. **쉬움.** `code/main.py`를 실행해 보세요. 장난감 스칼라 + 잔차 양자화기를 구현하고, 코드북을 늘려 갈 때 재구성 오차를 측정합니다.
2. **보통.** `encodec`를 설치해 홀드아웃 음성 클립에서 코드북 1, 4, 8, 32개를 비교합니다. PESQ 또는 MSE를 비트레이트에 대해 그래프로 그립니다.
3. **어려움.** Mimi를 불러 클립을 인코딩하세요. 코드북 0을 무작위 정수로 바꾸고 디코딩합니다. 이어서 코드북 7도 같은 식으로 바꿉니다. 두 손상을 비교해 보세요 — 코드북 0 손상은 알아듣기가 파괴되어야 하고, 코드북 7 손상은 거의 변화가 없어야 합니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|-----------------------|
| RVQ | 잔차 양자화 | 작은 코드북들의 폭포. 각 코드북이 이전 잔차를 양자화한다. |
| 프레임 레이트 | 코덱의 속도 | 초당 토큰 프레임 수. 낮을수록 LM이 빠르다. |
| 의미 코드북 | 코드북 0 (Mimi) | SSL 특성에서 증류한 코드북. 내용을 담는다. |
| 음향 코드북 | 나머지 전부 | 음색, 운율, 소음, 세밀한 디테일. |
| PESQ / ViSQOL | 지각 품질 | MOS와 상관되는 객관 지표. |
| EnCodec | Meta의 코덱 | RVQ 베이스라인. MusicGen이 사용한다. |
| Mimi | Kyutai의 코덱 | 12.5 Hz 프레임 레이트. 의미-음향 분리. Moshi의 동력. |
