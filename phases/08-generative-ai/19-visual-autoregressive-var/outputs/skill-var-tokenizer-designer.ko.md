> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-var-tokenizer-designer.md](skill-var-tokenizer-designer.md)

이미지 목표(해상도, 채널, 컬러 vs 그레이스케일, 데이터셋 크기, 다운스트림 LM 연산 예산, 목표 FID)가 주어지면 다음을 출력합니다:

1. 스케일 일정. 1x1부터 (H/p) x (W/p)까지 K개 해상도 레벨 목록. 256x256에는 기본 10개, 512x512에는 14개 스케일. K를 LM의 실효 시퀀스 길이(스케일 면적의 합) 및 패스당 스케일 내 병렬 예산과 대조하여 정당화하세요.
2. 코드북. 모든 스케일에서 공유하는 단일 코드북 크기 V(일반적으로 4096 / 8192 / 16384). 데이터셋 크기와 디코더 용량에서 V를 고르세요. 캘리브레이션 배치에서 코드북 사용률이 50퍼센트 이상 유지되는지 확인하고, 그렇지 않으면 V를 줄이세요.
3. 잔차 공유. 스케일 1..K가 합쳐서 업샘플된 임베딩의 합으로 잠재 표현을 복원하는지 확인하세요(잔차 VQ). 패치 크기 p와 VAE 백본(VQGAN 스타일 판별자 on/off, 지각 손실 가중치)을 명시하세요.
4. 디코더. 합산된 잠재 표현을 다시 픽셀로 되돌리는 VAE 디코더. VQGAN 디코더, VAR 논문 디코더, 더 가벼운 MAGVIT 스타일 디코더 중에서 고르세요. FID 목표와 디코더 VRAM에 대조하여 정당화하세요.
5. 위치 임베딩. (scale_index, row, col) 트리플, 스케일별 학습된 임베딩 + 스케일 내 2D sin-cos 구성을 확인하세요. 평평한 1D 위치는 거부하세요. LM은 올바른 조건을 적용하려면 스케일 레이블이 필요합니다.

VAR용 비(非)잔차 멀티스케일 토크나이저는 거부하세요. 합산 잔차가 없으면 다음 스케일 조건부가 잘 정의되지 않고, LM이 논문이 증명한 목표와 다른 목적함수를 최적화하게 됩니다. V가 더 작은 스케일의 픽셀 수에 맞춰 보정되어 있고 코드북 붕괴(codebook collapse)가 완화되어 있지 않다면 스케일별 별도 코드북도 거부하세요. K x 평균 스케일 면적이 LM의 최대 시퀀스 길이에서 텍스트 조건화를 위한 여유분을 뺀 값을 넘는다면, 아예 다음 스케일 예측 자체를 거부하세요.

예시 입력: "ImageNet 클래스 조건부 256x256, 데이터셋 1.2M, LM 예산 1.5B 파라미터, 목표 FID 5.0 미만."

예시 출력:
- 스케일 일정: K=10, 크기 1, 2, 3, 4, 5, 6, 8, 10, 13, 16. 총 토큰 671.
- 코드북: 공유, V=4096. 256 해상도 ImageNet에서 70-80퍼센트 사용률 예상.
- 잔차 공유: 확인됨; p=16, 지각 손실 + 적대적 손실을 갖춘 VQGAN 백본, 잔차 합이 f를 복원.
- 디코더: VQGAN 디코더, 업샘플링 블록 4개, 추가 리파이너 없음.
- 위치 임베딩: (scale, row, col) 트리플, 학습된 스케일 토큰 + 스케일 내 2D sin-cos.
