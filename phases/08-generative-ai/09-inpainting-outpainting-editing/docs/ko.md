# 인페인팅, 아웃페인팅, 그리고 이미지 편집

> 텍스트-이미지는 새로운 것을 만듭니다. 인페인팅은 기존 것을 고칩니다. 프로덕션에서 청구 가능한 이미지 작업의 70%는 편집입니다 — 배경 바꾸기, 로고 지우기, 캔버스 늘리기, 손 다시 만들기. 확산이 진짜 가치를 증명하는 곳은 인페인팅입니다.

**유형:** Build
**언어:** Python
**선수 지식:** 페이즈 8 · 07(잠재 확산), 페이즈 8 · 08(ControlNet과 LoRA)
**시간:** 약 75분

## 문제 상황

고객이 배경에 거슬리는 간판이 있는 완벽한 제품 사진을 보냅니다. 간판만 지우고 나머지는 픽셀 단위로 그대로 두고 싶습니다. 텍스트-이미지를 백지부터 돌릴 수는 없습니다 — 색도, 조명도, 제품 각도도 달라지겠죠. 마스크된 영역*만* 다시 만들고, 그 재생성이 주변 맥락을 존중하길 원합니다.

그것이 인페인팅입니다. 변형들:

- **인페인팅.** 마스크 안쪽을 재생성하고 바깥 픽셀은 유지.
- **아웃페인팅.** 마스크 바깥(또는 캔버스 너머)을 재생성하고 안쪽은 유지.
- **이미지 편집.** 이미지 전체를 다시 만들되 원본에 대한 의미적·구조적 충실도는 유지(SDEdit, InstructPix2Pix).

2026년의 모든 확산 파이프라인은 인페인팅 모드를 실어 나릅니다. Flux.1-Fill, Stable Diffusion Inpaint, SDXL-Inpaint, DALL-E 3 Edit. 원리는 모두 같습니다.

## 개념

![인페인팅: 맥락을 보존하는 재주입을 곁들인 마스크 인지 잡음 제거](../assets/inpainting.svg)

### 순진한 접근(그리고 왜 틀렸는지)

마스크를 쓰고 표준 텍스트-이미지를 돌립니다. 샘플링 스텝마다 잡음 섞인 잠재의 마스크되지 않은 영역을 순방향 확산한 깨끗한 이미지로 교체합니다. 작동은 합니다... 형편없이요. 모델이 마스크 안에 뭐가 있는지 알 길이 없으니 경계 아티팩트가 번져 나옵니다.

### 제대로 된 인페인팅 모델

4채널 대신 9채널 입력을 받는 변형 U-Net을 학습시킵니다:

```
input = concat([ noisy_latent (4ch), encoded_image (4ch), mask (1ch) ], dim=channel)
```

추가 채널은 VAE로 인코딩한 원본 이미지 복사본과 단일 채널 마스크입니다. 학습 때는 이미지의 영역을 무작위로 마스킹하고, 마스크되지 않은 영역은 깨끗한 조건 신호로 주어진 채 마스크된 영역의 잡음만 제거하도록 모델을 학습시킵니다. 추론 때는 모델이 마스크 주변을 "볼" 수 있어 일관된 채움을 만들어 냅니다.

SD-Inpaint, SDXL-Inpaint, Flux-Fill이 모두 이 9채널(또는 유사) 입력을 씁니다. Diffusers의 `StableDiffusionInpaintPipeline`, `FluxFillPipeline`.

### SDEdit (Meng 외, 2022) — 공짜 편집

원본 이미지에 중간 단계 `t`까지 잡음을 섞은 뒤, 새 프롬프트로 `t`부터 0까지 역 연쇄를 돌립니다. 재학습 불필요. 시작 `t`의 선택이 충실도와 창의적 자유를 맞바꿉니다:

- `t/T = 0.3` → 원본과 거의 동일, 작은 스타일 변화
- `t/T = 0.6` → 중간 정도 편집, 대략적 구조는 보존
- `t/T = 0.9` → 거의 잡음에서 생성, 원본 보존 최소

### InstructPix2Pix (Brooks 외, 2023)

`(입력 이미지, 지시문, 출력 이미지)` 삼중 항목으로 확산 모델을 파인튜닝합니다. 추론 때는 입력 이미지와 텍스트 지시문("노을로 만들어 줘", "용을 추가해 줘") 둘 다로 조건화합니다. CFG 스케일이 두 개입니다: 이미지 스케일과 텍스트 스케일.

### RePaint (Lugmayr 외, 2022)

표준 무조건부 확산 모델을 그대로 씁니다. 역방향 스텝마다 리샘플링합니다 — 가끔 더 시끄러운 상태로 되돌아갔다가 다시 생성합니다. 경계 아티팩트를 피합니다. 학습된 인페인팅 모델이 없을 때 씁니다.

## 만들어 보기

`code/main.py`는 5차원 데이터로 장난감 1차원 인페인팅 스킴을 구현합니다. 5차원 혼합 데이터 — 각 샘플이 두 클러스터 중 하나에 속하는 부동소수점 5개 — 로 DDPM을 학습시킵니다. 추론 때는 5차원 중 2차원을 "마스크"하고, 매 스텝 마스크되지 않은 세 차원의 순방향 잡음 섞인 버전을 주입하며, 마스크된 차원만 재생성합니다.

### 단계 1: 5차원 DDPM 데이터

```python
def sample_data(rng):
    cluster = rng.choice([0, 1])
    center = [-1.0] * 5 if cluster == 0 else [1.0] * 5
    return [c + rng.gauss(0, 0.2) for c in center], cluster
```

### 단계 2: 5차원 전체에 대해 잡음 제거기 학습

표준 DDPM입니다. 네트워크는 5차원 잡음 섞인 입력에 대해 5차원 잡음 예측을 출력합니다.

### 단계 3: 추론 때는 마스크 인지 역방향

```python
def inpaint_step(x_t, mask, clean_image, alpha_bars, t, rng):
    # 마스크되지 않은 차원을 깨끗한 원본의 갓 잡음 섞인 버전으로 교체
    a_bar = alpha_bars[t]
    for i in range(len(x_t)):
        if not mask[i]:
            x_t[i] = math.sqrt(a_bar) * clean_image[i] + math.sqrt(1 - a_bar) * rng.gauss(0, 1)
    # ...그다음 x_t에 대해 평범한 역방향 스텝을 수행
```

이것이 순진한 접근이고, 장난감 1차원 데이터에서는 통합니다. 실제 이미지 인페인팅은 텍스처 일관성이 훨씬 중요하기 때문에 9채널 입력을 씁니다.

### 단계 4: 아웃페인팅

아웃페인팅은 마스크를 뒤집은 인페인팅입니다: 새로운(원래 존재하지 않던) 캔버스를 마스크하고, 나머지는 원본으로 채웁니다. 학습 목표는 동일합니다.

## 함정들

- **이음새.** 순진한 접근은 그래디언트 정보가 마스크를 넘어 흐르지 않아 눈에 보이는 경계를 남깁니다. 해결: 마스크를 8-16픽셀 팽창하거나, 제대로 된 인페인팅 모델을 쓰세요.
- **마스크 누출.** 조건 이미지의 마스크 밖 영역이 저품질이거나 잡음이 많으면 마스크 안쪽 생성을 오염시킵니다. 살짝 잡음 제거하거나 블러하세요.
- **CFG가 마스크 크기와 상호작용합니다.** 작은 마스크에 높은 CFG = 포화된 패치. 작은 편집에는 CFG를 낮추세요.
- **SDEdit 충실도 절벽.** `t/T = 0.5`에서 `t/T = 0.6`으로 가는 것만으로 소재의 신원을 잃을 수 있습니다. 스윕하고 체크포인트를 남기세요.
- **프롬프트 불일치.** 프롬프트는 새 내용만이 아니라 *전체* 이미지를 묘사해야 합니다. "고양이"가 아니라 "의자에 앉은 고양이".

## 사용해 보기

| 과제 | 파이프라인 |
|------|----------|
| 물체 제거, 작은 마스크 | SD-Inpaint 또는 Flux-Fill, 표준 프롬프트 |
| 하늘 교체 | SD-Inpaint + "노을 지는 푸른 하늘" |
| 캔버스 확장 | SDXL 아웃페인트 모드(8px 페더) 또는 아웃페인트 마스크를 쓴 Flux-Fill |
| 손 / 얼굴 재생성 | 소재를 다시 묘사하는 프롬프트를 얹은 SD-Inpaint + ControlNet-Openpose |
| 한 영역의 스타일 변경 | 마스크된 영역에 `t/T=0.5`의 SDEdit |
| "노을로 만들어 줘" | InstructPix2Pix 또는 Flux-Kontext |
| 배경 교체 | SAM 마스크 → SD-Inpaint |
| 초고충실도 | 가장 어려운 케이스는 Flux-Fill 또는 GPT-Image(호스팅) |

## 프로덕션 노트: 편집 파이프라인은 지연 시간에 민감합니다

이미지를 편집하는 사용자는 5초 미만의 왕복을 기대합니다. 1024²의 30스텝 SDXL-Inpaint는 L4에서 3-4초, 여기에 SAM 마스크 생성(약 200 ms)과 VAE 인코딩/디코딩(합쳐서 약 500 ms)이 더해집니다. 프로덕션 관점에서 이것은 처리량보다 TTFT에 묶인 작업입니다 — 배치 1, 낮은 동시성, 모든 단계를 최소화하세요:

- **느린 것은 SAM-H입니다.** 1024² 기준 SAM-H는 약 200 ms; SAM-ViT-B는 품질 손실이 사소한 수준이며 약 40 ms입니다. SAM 2(비디오)는 시간축 처리 비용이 추가되므로 단일 이미지 편집에 쓰지 마세요.
- **가능하면 인코딩을 건너뛰세요.** `pipe.image_processor.preprocess(img)`는 이미지를 잠재로 인코딩합니다. 이전 생성의 잠재가 이미 있다면(반복 편집 UI에서는 흔한 일입니다) `latents=...`로 직접 넘겨 VAE 인코딩 한 번을 건너뛰세요.
- **마스크 팽창은 처리량에도 중요합니다.** 작은 마스크는 U-Net 순전파 대부분이 낭비된다는 뜻입니다(마스크 밖 픽셀은 어차피 고정됩니다). `diffusers`의 `StableDiffusionInpaintPipeline`은 어차피 전체 U-Net을 돌립니다; 마스크된 연산만 활용하는 것은 9채널 proper-inpaint 변형들뿐입니다.
- **Flux-Kontext가 2025년의 답입니다.** `(원본 이미지, 지시문)` 위의 단일 순전파 — 별도 마스크 없음, SDEdit 잡음 스윕 없음. H100에서 편집 하나를 약 1.5초에 내놓습니다. 아키텍처 교훈: 단계를 접어 하나로 만들어라.
