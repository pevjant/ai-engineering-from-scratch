# 비디오 생성

> 이미지는 2차원 텐서입니다. 비디오는 3차원 텐서죠. 이론은 같은데 계산량은 10~100배 어렵습니다. OpenAI의 Sora(2024년 2월)는 가능하다는 것을 증명했습니다. 2026년까지 Veo 2, Kling 1.5, Runway Gen-3, Pika 2.0, WAN 2.2가 1080p 텍스트 기반 프로덕션 비디오를 내놓고, 오픈 가중치 스택(CogVideoX, HunyuanVideo, Mochi-1, WAN 2.2)은 12개월 뒤를 따라갑니다.

**유형:** Build
**언어:** Python
**선수 지식:** 페이즈 8 · 07(잠재 확산), 페이즈 7 · 09(ViT), 페이즈 8 · 06(DDPM)
**시간:** 약 45분

## 문제 상황

24fps 10초짜리 1080p 비디오는 1920×1080×3 픽셀짜리 프레임 240개입니다. 클립 하나당 원본 데이터 약 1.5GB입니다. 픽셀 공간 확산은 불가능합니다. 필요한 것:

1. **시공간 압축.** 프레임이 아니라 비디오를 공간-시간 패치의 나열로 인코딩하는 VAE.
2. **시간적 일관성.** 프레임들이 몇 초에 걸쳐 내용, 조명, 물체 신원을 공유해야 합니다. 네트워크가 움직임을 모델링해야 하죠.
3. **계산 예산.** 같은 모델 크기에서 비디오 학습은 이미지보다 10~100배 비쌉니다.
4. **조건화.** 텍스트, 이미지(첫 프레임), 오디오, 또는 다른 비디오. 대부분의 프로덕션 모델은 넷 모두를 받습니다.

이 문제를 푼 아키텍처는 시공간 패치에 적용된 **Diffusion Transformer(DiT)**로, 거대한 (프롬프트, 캡션, 비디오) 데이터셋으로 학습됩니다. 손실은 레슨 06과 같은 확산 손실입니다.

## 개념

![비디오 확산: 패치화, DiT, 디코드](../assets/video-generation.svg)

### 패치화

비디오를 3D VAE(학습된 시공간 압축)로 인코딩합니다. 잠재는 `[T_latent, H_latent, W_latent, C_latent]` 모양입니다. `[t_p, h_p, w_p]` 크기의 패치로 쪼갭니다. Sora 스타일 모델은 `t_p = 1`(프레임별 패치) 또는 `t_p = 2`(두 프레임마다)를 씁니다. 10초짜리 1080p 비디오는 약 20,000~100,000개 패치로 압축됩니다.

### 시공간 DiT

트랜스포머가 평평한 패치 나열을 처리합니다. 각 패치는 3D 위치 임베딩(시간 + y + x)을 갖습니다. 어텐션은 보통 분해(factorize)합니다:

- **공간 어텐션** — 각 프레임의 패치들 안에서.
- **시간 어텐션** — 같은 공간 위치의 프레임들 사이에서.
- **완전한 3D 어텐션**은 16~100배 비쌉니다; 저해상도나 연구에서만 씁니다.

### 텍스트 조건화

큰 텍스트 인코더를 곁들인 크로스 어텐션입니다(Sora는 T5-XXL, CogVideoX-5B도 T5-XXL). 긴 프롬프트가 중요합니다 — Sora의 학습 세트는 클립마다 평균 200 토큰의 GPT가 만든 촘촘한 재캡션을 실었습니다.

### 학습

시공간 잠재 위의 표준 확산 손실(ε 또는 v 예측). 데이터: 웹 비디오 + 엄선된 클립 약 1억 개 + 합성 텍스트 캡션. 계산: 작은 연구 규모조차 GPU 10,000시간 이상; Sora 규모는 100,000 이상입니다.

## 만들어 보기

`code/main.py`는 시공간 DiT의 핵심 아이디어를 시뮬레이션합니다: 작은 합성 비디오를 패치화하고, 패치별 위치 임베딩을 더하고, 패치들에 대한 트랜스포머 스타일 어텐션으로 전체 시퀀스의 잡음을 제거합니다. numpy 없이 순수 Python입니다. 인접 프레임 패치가 같은 잡음 제거기와 위치 잡음 임베딩을 공유하면 1차원에서도 시간적 일관성이 자연스럽게 나타난다는 것을 보여 줍니다.

### 단계 1: 합성 1차원 "비디오" 패치화

```python
def make_video(T_frames=8, rng=None):
    # "비디오"는 매끄러운 궤적을 따르는 1차원 값들의 나열
    base = rng.gauss(0, 1)
    return [base + 0.3 * t + rng.gauss(0, 0.1) for t in range(T_frames)]
```

### 단계 2: 프레임별 위치 임베딩

```python
def pos_embed(t, dim):
    return sinusoidal(t, dim)
```

### 단계 3: 잡음 제거기가 시퀀스 전체를 봄

각 프레임을 따로따로 잡음 제거하는 대신, 우리 작은 네트워크는 모든 프레임 값과 위치 임베딩을 연결해 모든 프레임의 잡음을 공동으로 예측합니다.

### 단계 4: 시간적 일관성 테스트

학습 후 비디오를 샘플링합니다. 프레임 간 델타를 측정합니다. 모델이 시간 구조를 배웠다면 델타가 각 프레임을 독립적으로 샘플링할 때보다 작게 유지됩니다.

## 함정들

- **프레임별 독립 샘플링 = 깜빡임.** 각 프레임에 이미지 확산을 따로 돌리면 각 프레임의 잡음이 독립이라 출력이 깜빡입니다. 비디오 확산은 어텐션이나 공유 잡음으로 프레임을 결합해 이를 고칩니다.
- **천진한 3D 어텐션 = OOM.** 10초 1080p 잠재에 대한 완전한 3D 어텐션은 수천억 번의 연산입니다. 공간 + 시간으로 분해하세요.
- **데이터 크기보다 캡셔닝이 중요합니다.** 이전 연구 대비 Sora의 주요 업그레이드는 약 10배 더 자세한 캡션(GPT-4가 재라벨링한 클립)으로 학습한 것이었습니다. OpenAI 기술 보고서가 이를 명시합니다.
- **첫 프레임 조건화.** 대부분의 프로덕션 모델은 이미지를 첫 프레임으로 받기도 합니다. "이미지-비디오" 모드이며, 학습에 이 변형이 포함됩니다.
- **물리 표류.** 긴 클립(10초 초과)은 미세한 불일치가 누적됩니다. 슬라이딩 윈도우 생성 + 키프레임 앵커링이 도움이 됩니다.

## 프로덕션 노트: 비디오 잠재는 메모리 대역폭의 문제

24fps 10초짜리 1080p 클립은 240 프레임 × 1920 × 1080 × 3 ≈ 1.5GB의 원시 픽셀입니다. 4배 비디오 VAE 압축(`공간 2배 × 시간 2배`)을 거치면 잠재는 요청당 약 100MB입니다. 이것을 배치 1로 시공간 DiT에 30스텝 통과시키면 HBM을 통해 스텝당 약 3GB를 움직이게 됩니다 — 병목은 FLOPs가 아니라 메모리 대역폭입니다.

세 가지 프로덕션 노브, 모두 프로덕션 추론 문헌 추론 챕터에서 바로 가져온 것입니다:

- **DiT에 걸치는 TP.** 텍스트-비디오 모델은 보통 10B 파라미터 이상입니다. H100 4장에 TP=4가 표준이고, 405B급 모델은 PP=2 × TP=2입니다. 스텝당 지연 시간은 all-reduce 벽에 도달할 때까지 대략 TP에 선형적으로 줄어듭니다.
- **프레임 배칭 = 연속 배칭.** 생성 시점에 비디오는 개념적으로 어텐션으로 연결된 프레임들의 배치입니다. 연속 배칭(in-flight 스케줄링)이 적용됩니다: 모델 아키텍처가 슬라이딩 윈도우 생성을 허용한다면, 프레임 `t-1`이 반환되는 동안 프레임 `t+1` 렌더링을 시작하세요.
- **클립 수준 프리필 캐시.** 이미지-비디오에서 첫 프레임 조건화는 LLM의 프롬프트 프리필과 유사합니다: 한 번 계산하고 시간 디코더 패스에 걸쳐 재사용합니다. 사실상 비디오용 KV-캐시입니다.
