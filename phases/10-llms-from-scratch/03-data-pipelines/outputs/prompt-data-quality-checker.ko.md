# LLM 사전학습용 데이터 품질 검사기

LLM 사전학습용 데이터 파이프라인을 구축하거나 감사할 때는 이 프레임워크로 문제가 모델에 도달하기 전에 잡아 내세요.

## 파이프라인 출력의 위험 신호

**중복 제거가 웹 데이터의 20% 미만을 걸러 냈다.** Common Crawl에는 보통 30-40%의 중복이 있습니다. 중복 제거 단계가 20% 미만을 걸러 냈다면 MinHash 파라미터가 너무 보수적이거나 임계값이 너무 높은 것입니다. 확인할 것: 샤들(shingle) 크기 k, 해시 함수 수, LSH 밴드 수, 자카드 임계값.

**압축률이 토큰당 2.0자 미만이다.** 토크나이저가 너무 공격적으로 쪼개고 있다는 뜻입니다. 병합 수를 늘려 재학습하거나, 어휘 크기를 늘리거나, 사전 토큰화가 텍스트를 불필요하게 조각내고 있지 않은지 확인하세요.

**압축률이 토큰당 6.0자를 넘는다.** 토크나이저가 일반화되지 않을 수 있는 아주 도메인 특화적인 병합을 배웠습니다. 도메인 특화 모델이라면 괜찮지만 범용 모델에는 경고 신호입니다.

**시퀀스 활용률이 90% 미만이다.** 패딩이 너무 많다는 뜻입니다. 문서가 매우 짧거나(필터링하거나 최소 문서 길이를 늘리세요) 시퀀스 패킹이 비효율적입니다(무식한 패딩에서 다중 문서 패킹으로 전환하세요).

**어휘 활용률이 50% 미만이다.** 어휘의 절반 이상이 이 말뭉치에서 쓰이지 않고 있습니다. 어휘가 도메인에 비해 너무 크거나, 토크나이저가 아주 다른 데이터로 학습된 것입니다.

## 품질 필터 보정

각 파이프라인 단계에서 문서 1,000개의 무작위 표본으로 다음 검사를 돌리세요:

1. **정제 후 무작위 문서 20개를 읽는다.** HTML, JavaScript, 내비게이션 텍스트, 상투적 문구가 남아 있나? 있다면 HTML 제거가 불완전한 것이다.

2. **품질 필터를 통과한 무작위 문서 20개를 읽는다.** 스팸, 키워드 나열, 기계 생성 콘텐츠가 있나? 있다면 필터 임계값을 조여야 한다.

3. **품질 필터에서 탈락한 무작위 문서 20개를 읽는다.** 진짜 좋은 콘텐츠가 있나? 있다면 필터가 너무 공격적인 것이다. 임계값을 완화하거나 특정 패턴에 대한 예외를 추가하라.

4. **중복 제거에서 나온 근사 중복 쌍 20개를 무작위로 읽는다.** 실제로 비슷한가? 그렇지 않다면 자카드 임계값을 낮추거나 해시 함수 수를 늘려라.

## 데이터 배합 비율

만능 공식은 없습니다. 아래 베이스라인에서 시작해 평가 결과에 따라 조정하세요:

| 카테고리 | Llama 3 비율 | 출발점 |
|----------|--------------|----------------|
| 웹 텍스트 | 50% | 50% |
| 코드 | 25% | 15-25% |
| 책/학술 | 13% | 10-15% |
| 수학 | 8% | 5-10% |
| 다국어 웹 | 4% | 5-10% |

프로그래밍 능력이 중요하면 코드 비율을 올리세요. 추론이 중요하면 수학 비율을 올리세요. 노이즈를 줄이고 싶으면 웹 비율을 내리세요. 비율을 바꾼 후에는 반드시 벤치마크로 평가하세요.

## 스케일 추정

목표 토큰 수가 주어졌을 때:

- 웹에서 1T 토큰: 로우 텍스트 약 3-5TB, 정제와 중복 제거 후 약 1.5-2TB 예상
- 토큰화 속도 (Rust): 코어당 초당 약 1억 토큰
- 토큰화 속도 (Python): 코어당 초당 약 100만~1,000만 토큰
- MinHash 중복 제거(128개 해시, 16개 밴드): 코어당 초당 약 1만 문서
- 시퀀스 패킹: I/O 병목, 10GB를 넘는 말뭉치는 메모리 매핑 파일을 사용

15T 토큰(Llama 3 규모)이라면 로우 입력 데이터 약 30-50TB, 64코어 머신에서 1-2주의 전처리, 중간 파일용 디스크 100TB 이상을 계획하세요.

## 학습 전 체크리스트

1. 총 토큰 수가 컴퓨트 예산과 일치한다 (Chinchilla 스케일링 또는 Llama 3 과잉 학습 비율을 가이드로)
2. 중복 제거가 웹 데이터의 30-40%를 걸러 냈다
3. 품질 필터가 남은 데이터의 10-20%를 걸러 냈다
4. 압축률이 영어 기준 토큰당 3-5자다
5. 시퀀스 활용률이 95%를 넘는다
6. 무작위 표본 검사에서 모든 파이프라인 단계의 텍스트가 깨끗하고 일관된다
7. 데이터 배합 비율이 소규모 학습 실행으로 검증됐다
8. PII 제거가 표본으로 확인됐다
9. 모든 이진 형식(패킹된 시퀀스, 토큰 ID 배열)이 인코딩/디코딩 왕복 테스트를 통과한다
10. 파이프라인이 재현 가능하다: 고정된 무작위 시드로 같은 입력이 동일한 출력을 만든다
