> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-speculative-tuning.md](skill-speculative-tuning.md)

타깃 모델(크기, 계열, 토크나이저), 작업 부하 텔레메트리(작업 믹스, 프롬프트 대비 디코드 토큰 비율, p50/p99 디코드 지연 시간, 가속기와 HBM 여유분, 평균 배치 크기, 샘플링 temperature 분포), 그리고 사용 가능한 드래프트 체크포인트가 주어지면 다음을 출력합니다:

1. 드래프트 선택. 같은 계열의 소형 모델(Llama-70B에는 Llama-3.2-1B), 증류된 드래프트(Qwen3-0.6B-spec), 타깃에 얹는 Medusa 헤드 중에서 고르거나, FLOP 비용 비율이 30%보다 가까운 드래프트가 없으면 "스펙 디코딩 없음"을 고릅니다. 토크나이저가 타깃과 바이트 단위로 일치하는지 확인하고, 일치하지 않으면 거부합니다.
2. 드래프트 길이 K. `E[tokens] / (1 + K x c)`의 아르그맥스. c는 드래프트 대비 타깃 비용 비율입니다. 분포 내 데이터 5,000토큰으로 칼리브레이션 실행에서 측정한 알파를 사용해 K = 2, 3, 4, 5, 6에 대한 계산 과정을 보여줍니다. 기본값: 채팅 K=4, 코드 K=6, 고온 창작 글쓰기 K=2.
3. Temperature 게이트. 이 값을 넘으면 스펙 디코딩을 끄는 temperature 임계값을 정합니다. 기본값 0.8. 칼리브레이션에서 알파가 더 일찍 무너지면 0.6으로 낮춥니다. 요청별 검사를 요구해 50마이크로초 이상 추가하는 temperature 게이트는 거부합니다.
4. 트리 예산. 서빙 스택이 트리 드래프팅을 지원한다면, 배치 8 미만에는 작은 고정 트리(깊이 2, 분기 3-2)를, 배치 32 초과에는 평면 사슬을 고릅니다. 검증기의 KV 스크래치 크기를 바이트 단위로 밝히고 HBM 여유분에 들어가는지 확인합니다.
5. 폴백 정책. 지표(최근 1,000회 검증에 대한 슬라이딩 윈도우 측정 알파)와 임계값(알파 0.4 미만)을 밝힙니다. 이 조건에서 서버는 해당 요청 스트림을 평범한 자기회귀 디코딩으로 되돌립니다. 폴백 결정의 요청별 수명도 함께 명시합니다.

검증기가 연산 병목이 되기 시작하는 지점을 넘는 배치 크기에서는 스펙 디코드를 거부합니다. 그 지점을 넘으면 스페큘레이터가 흡수하도록 설계된 남는 FLOPs가 더 이상 존재하지 않아 처리량이 떨어집니다. 측정된 알파가 0.4 미만인 작업 계열에는 스펙 디코드를 거부합니다. 드래프트 오버헤드가 지배하고 실제 시간 지연이 더 나빠집니다. 타깃에 대해 홀드아웃 1,000토큰 샘플로 검증되지 않은 드래프트는 거부합니다. 검증되지 않은 드래프트는 소리 없는 KL 드리프트입니다.

입력 예: "8xH100의 Llama-3.3-70B, 채팅 작업, 배치 16, p50 디코드 28 ms, p99 60 ms, temperature 분포 평균 0.4 / 최대 1.2, 칼리브레이션 결과 채팅 알파 0.78, 코드 0.61."

출력 예:
- 드래프트: Llama-3.2-1B-Instruct-spec. 같은 토크나이저, 같은 계열, 비율 c 약 0.03.
- K: 4. E[tokens/verify] = 채팅 3.4, 코드 2.5. K=5는 채팅에서 0.1토큰 이득에 c 0.03 추가 비용. 거부.
- Temperature 게이트: 0.8. 0.8을 넘으면 칼리브레이션 세트에서 알파가 0.45 아래로 떨어짐.
- 트리 예산: 깊이 2, 분기 (3, 2). 배치 16에서 KV 스크래치 480 MB, 들어감.
- 폴백: 최근 1,000회 검증의 슬라이딩 윈도우 알파가 0.40 미만이면 해당 스트림의 스펙 디코딩을 30초 동안 끈 뒤 다시 시도(probe).
