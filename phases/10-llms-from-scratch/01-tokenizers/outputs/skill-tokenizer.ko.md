# 토크나이저 선택과 구현

LLM 프로젝트를 시작할 때는 이 의사결정 프레임워크로 토크나이저를 고르세요.

## 각 토크나이저를 쓰는 경우

**바이트 수준 BPE (tiktoken):** GPT 계열 모델 위에서 빌드하거나 파인튜닝할 때. 어떤 입력 바이트 시퀀스도 반드시 처리해야 할 때. 미지 토큰이 없기를 원할 때.

**WordPiece (Hugging Face):** 분류, 개체명 인식(NER), 임베딩 작업 등 BERT 계열 모델을 다룰 때. 단어 경계 신호에 의존하는 다운스트림 작업을 위해 "##" 연속 접두사가 필요할 때.

**SentencePiece (BPE 또는 Unigram):** 처음부터 학습할 때. 언어 중립 토큰화가 필요할 때. 데이터에 CJK(한중일) 언어, 태국어처럼 공백이 단어 경계가 아닌 문자 체계가 포함될 때. LLaMA, T5, 그리고 대부분의 다국어 모델이 이것을 씁니다.

## 어휘 크기 가이드라인

- 32K 토큰: 단일 언어 모델의 좋은 기본값, 임베딩 층이 작게 유지됨
- 50K-64K 토큰: 다국어 또는 코드 위주 모델에 더 적합
- 100K+ 토큰: 방대한 학습 데이터가 있고 짧은 시퀀스를 원할 때만

어휘가 커지면 시퀀스가 짧아져(추론이 저렴해짐) 임베딩 행렬의 파라미터는 늘어납니다. 4096차원 임베딩에 100K 어휘를 쓰면 임베딩 층만 4억 파라미터입니다.

## 중요한 사전 토큰화 규칙

1. BPE 전에 공백으로 나눠 단어를 가로지르는 병합을 막는다
2. 모델이 산술을 배우길 원한다면 숫자는 개별로 분리한다
3. 일관된 동작을 위해 토큰화 전에 유니코드를 정규화한다(NFC)
4. 용도에 맞는 특수 토큰을 추가한다: `<pad>`, `<eos>`, `<bos>`, `<unk>`, 그리고 작업별 마커

## 토크나이저 동작의 위험 신호

- 대상 언어의 다산성(fertility)이 2.0 초과: 모델이 컨텍스트 윈도우를 낭비한다
- 흔한 도메인 단어가 토큰 3개 이상으로 쪼개짐: 도메인 데이터로 재학습하라
- 숫자의 비일관한 토큰화: 숫자 분리 규칙을 확인하라
- 한 번만 쓰이는 토큰이 많은 과도한 어휘: 어휘 크기를 줄여라

## 커스텀 토크나이저 구축 - 체크리스트

1. 대표적인 학습 데이터를 수집한다 (대상 도메인 텍스트 최소 1GB)
2. 알고리즘을 고른다: 일반 용도는 BPE, 다국어는 Unigram
3. 위 가이드라인에 따라 어휘 크기를 정한다
4. 사전 토큰화를 설정한다: 공백 분리, 숫자 처리, 구두점
5. 특수 토큰을 추가한다
6. Hugging Face tokenizers 라이브러리로 학습한다 (Rust 백엔드, 빠름)
7. 검증한다: 모든 대상 언어에 대해 홀드아웃 텍스트의 다산성을 확인한다
8. 엣지 케이스를 테스트한다: 빈 문자열, 매우 긴 입력, 이진 데이터, 이모지, RTL(오른쪽에서 왼쪽) 텍스트
9. 토크나이저를 모델 체크포인트와 함께 저장하고 버전 관리한다
