> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-deepseek-v3-reader.md](skill-deepseek-v3-reader.md)

DeepSeek 계열 모델(V3, R1 또는 어떤 파생 모델이든)과 설정값(hidden_size, layers, num_experts, kv_lora_rank 등)이 주어지면, 모델을 구성 요소별로 분해하고 어떤 DeepSeek 고유 혁신을 사용하는지 식별하는 아키텍처 분석을 산출합니다.

산출물:

1. 필드별 설정값 독해. 각 필드에 대해 어떤 구성 요소에 해당하는지, 얼마만큼의 파라미터를 기여하는지 밝힙니다. 형식: `field_name: value → 해석 → 파라미터 기여량`.
2. 파라미터 분석. 전체 파라미터, 활성 파라미터, 활성 비율. 임베딩, 레이어당 어텐션, 레이어당 MLP(밀집 vs 전문가), 라우터, MTP 모듈, LM 헤드, RMSNorm 합계로 나눕니다.
3. 목표 컨텍스트 길이에서의 KV 캐시. BF16과 FP8 값을 모두 보고합니다. 같은 컨텍스트와 은닉 크기에서 Llama-3 스타일 GQA(8/128) 베이스라인과의 비교도 포함합니다.
4. 혁신 체크리스트. MLA, MTP, 보조 손실 없는 라우팅, DualPipe 각각에 대해 모델이 사용하는지, 그리고 설정값/논문의 어디에서 이를 확인할 수 있는지 식별합니다.
5. 온전성 검사. 특정 배포 대상(H100 80GB, H200 141GB, MI300X 192GB, 단일 노드 vs 멀티 노드)에서 모델의 추론 메모리 예산(가중치 + KV 캐시 + 활성값)을 계산합니다. 들어가는지 여부와 어떤 양자화가 필요한지 보고합니다.

하드 리젝(무조건 거부):

- DeepSeek-V3를 GPT류 밀집 모델과 혼동하는 분석. 아키텍처는 본질적으로 다릅니다.
- 컨텍스트 길이를 밝히지 않고 MLA가 GQA보다 빠르다고 주장하는 것. 짧은 컨텍스트(4k 미만)에서는 둘이 비슷하고, 긴 컨텍스트에서 MLA가 이깁니다.
- MTP를 스페큘레이티브 디코딩의 대체재로 해석하는 것. MTP는 사전학습 목적 함수이며, 부수적으로 드래프트 역할도 하는 것입니다.

거부 규칙:

- 제공된 설정값에 `kv_lora_rank`, `num_experts`, `first_k_dense_layers` 중 하나라도 없으면 거부합니다. DeepSeek 계열 모델이 아닙니다.
- 공개된 파라미터 수와 정확히 일치하는지(1억 단위까지) 확인해 달라는 요청은 거부하고, 공개 숫자에는 구현 고유의 구조 파라미터가 포함되어 있어 단순화된 계산기로는 정확히 재현할 수 없음을 설명합니다. 논문 2장 부록을 안내하세요.
- 배포 대상이 소비자용 GPU(24GB 이하)라면 거부하고, 양자화된 증류(quantized distilled) DeepSeek 계열 파생 모델을 대신 권합니다.

출력: 필드 목록, 파라미터 분석, KV 캐시, 혁신 체크리스트, 배포 적합성을 담은 한 페이지짜리 아키텍처 분석. 마지막에 "다음에 읽을 것" 문단으로 끝내며, 분석에서 드러난 질문에 따라 NSA(페이즈 10 · 17), V2 논문의 MLA 어블레이션, 또는 V3 기술 보고서 2장 부록 중 하나를 지목합니다.
