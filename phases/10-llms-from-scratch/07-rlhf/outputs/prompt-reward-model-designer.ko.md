# 보상 모델 디자이너(Reward Model Designer)

언어 모델을 목표 행동(유용성, 코딩 능력, 안전성, 정직함) 쪽으로 정렬하는 RLHF 파이프라인을 만들 때, 이 프레임워크를 사용해 데이터 수집 프로토콜을 설계하고 보상 모델을 학습시키며 PPO를 구성하세요.

## 입력 요구 사항

다음을 준비해 주세요:
- **목표 행동** (예: "유용하고 무해한 어시스턴트", "전문가 수준의 Python 코더", "안전성을 갖춘 의료 Q&A")
- **베이스 모델** (예: SFT를 마친 Llama 3 8B, Mistral 7B Chat)
- **보상 모델 크기** (보통 정책 모델과 같은 크기 또는 그 이상)
- **주석 예산** (확보 가능한 인간 작업 시간 또는 비교 쌍 수)
- **컴퓨팅 예산** (보상 모델 학습 + PPO에 쓸 GPU 시간)

## 단계 1: 선호 데이터 수집

### 주석 프로토콜

1. **프롬프트 선정**: SFT 학습 분포에서 뽑되, 분포 밖 프롬프트도 섞습니다(10-20%는 처음 보는 프롬프트)
2. **응답 생성**: SFT 모델로 프롬프트당 2-4개의 응답을 서로 다른 온도(0.3, 0.7, 1.0)로 생성합니다
3. **비교 형식**: 주석자에게 정확히 2개의 응답을 보여 주고 "어느 응답이 더 나은가요?"라고 묻습니다
4. **기준 루브릭**: 여러분의 용도에서 "더 낫다"가 무엇인지 정의합니다

### 루브릭 템플릿

| 기준 | 가중치 | 설명 |
|-----------|--------|-------------|
| 유용성 | 40% | 질문에 완전하고 정확하게 답했나요? |
| 무해성 | 25% | 유해하거나 편향된, 오해를 부르는 내용을 피했나요? |
| 정직함 | 20% | 환각을 일으키는 대신 불확실성을 인정했나요? |
| 간결성 | 15% | 응답 길이가 질문에 알맞은가요? |

용도에 맞게 가중치를 조정하세요. 코딩 어시스턴트라면 정확성에 60%, 간결성에 20%를 줄 수 있습니다.

### 데이터 크기 가이드라인

| 규모 | 비교 쌍 수 | 주석 시간 | 기대 보상 모델 정확도 |
|-------|-----------------|-----------------|---------------------|
| 최소 실행 가능 | 5,000-10,000 | 400-800 | 60-65% |
| 프로덕션 v1 | 20,000-50,000 | 1,600-4,000 | 65-72% |
| 프로덕션 v2 | 100,000-500,000 | 8,000-40,000 | 72-78% |

InstructGPT는 40명의 계약자에게서 33,000건의 비교를 받았고, Anthropic의 초기 논문은 20명의 주석자에게서 22,000건을 받았습니다. 주석자 간 일치율은 보통 70-75%입니다. 즉 보상 모델은 인간의 일치율을 넘을 수 없습니다.

### 품질 관리

- **일치율 필터링**: 주석자 동의율이 70% 미만인 쌍은 버립니다
- **주석자 보정(calibration)**: 실제 주석 전에 정답을 아는 쌍으로 보정 라운드를 돌립니다
- **편향 감지**: 주석자가 긴 응답, 격식 있는 표현, 특정 패턴을 일관되게 선호하는지 지켜봅니다
- **적대적 예시**: 대충 훑어 보는 주석자를 걸러 내기 위한 예시를 5-10% 섞어 넣습니다

## 단계 2: 보상 모델 구조

### 구조 결정 사항

| 결정 | 권장 사항 | 근거 |
|----------|---------------|-----------|
| 베이스 구조 | 정책 모델과 같은 트랜스포머 | SFT 체크포인트에서 가중치를 초기화하면 좋은 출발 특성을 얻습니다 |
| 출력 헤드 | 마지막 은닉 상태에서 선형 투영 하나 | 가장 완전한 위치 표현에서 스칼라 보상을 뽑아 냅니다 |
| 모델 크기 | 정책 모델 크기 이상 | 작은 보상 모델은 불안정한 신호를 내놓아 PPO를 흔듭니다 |
| 초기화 | 새 출력 헤드를 단 SFT 체크포인트 | 사전 학습된 특성이 이미 언어 품질을 담고 있습니다 |

### 학습 설정

| 파라미터 | 범위 | 비고 |
|-----------|-------|-------|
| 학습률 | 1e-5 ~ 5e-5 | 작업이 더 단순하므로 SFT보다 낮게 |
| 에포크 수 | 1-3 | 비교 데이터가 적어 과적합 위험이 큽니다 |
| 배치 크기 | 64-256 | "예시" 하나가 쌍이므로 실효 데이터는 2배 |
| 손실 함수 | 브래들리-테리: -log(sigmoid(r_preferred - r_rejected)) | 쌍별 비교의 표준 |
| 검증 분할 | 10-20% | 홀드아웃 쌍에서 정확도를 관찰합니다 |

### 평가 지표

1. **쌍별 정확도**: 홀드아웃 선호 쌍 중 보상 모델이 몇 퍼센트를 올바르게 순위 매기나요? 목표: 65% 초과
2. **마진 분포**: (r_preferred - r_rejected)의 분포를 그려 보세요. 0보다 위를 중심으로 하고 음수는 드물어야 합니다.
3. **보정(calibration)**: sigmoid(r_preferred - r_rejected)가 실제 인간 선호 확률과 가까운가요?
4. **OOD 일반화**: 학습과 다른 분포의 프롬프트로 테스트하세요. 정확도 하락은 10% 미만이어야 합니다.

## 단계 3: PPO 구성

### 하이퍼파라미터

| 파라미터 | 일반적인 값 | 너무 높을 때 영향 | 너무 낮을 때 영향 |
|-----------|--------------|-------------------------|------------------------|
| KL 계수 (beta) | 0.01-0.05 | 모델이 거의 배우지 못하고 SFT에 너무 붙어 있음 | 보상 해킹, 기괴한 출력 |
| 학습률 | 5e-6 ~ 3e-5 | 학습 불안정, 발산 | 수렴이 느리고 컴퓨팅 낭비 |
| 클립 비율 (epsilon) | 0.1-0.3 | 크고 불안정할 수 있는 업데이트 | 지나치게 보수적인 업데이트, 느린 학습 |
| 배치당 PPO 에포크 | 1-4 | 현재 배치에 과적합 | 배치를 충분히 활용하지 못함 |
| 생성 배치 크기 | 128-512 | 메모리 문제 | 노이즈 섞인 그래디언트 추정 |
| 최대 응답 길이 | 256-1024 | 생성이 느리고 메모리 문제 | 유용한 응답이 잘림 |

### 모니터링 대시보드

PPO 학습 중 이 지표들을 추적하세요:

1. **평균 보상**: 학습이 진행되며 증가해야 합니다. 정체는 괜찮지만, 감소는 불안정의 신호입니다.
2. **KL 발산**: 10-20 nat 이하를 유지해야 합니다. 급등 = 보상 해킹입니다.
3. **응답 길이**: 안정적으로 유지되어야 합니다. 단조 증가 = 장황함 보상 해킹입니다.
4. **엔트로피**: 토큰 분포 엔트로피는 천천히 줄어야 합니다. 급감 = 모드 붕괴(mode collapse)입니다.
5. **보상 모델 일치도**: PPO 응답을 보상 모델로 채점해 보세요. 일치도가 점점 좋아져야 합니다.

### PPO 중 위험 신호

| 증상 | 가능성 높은 원인 | 처방 |
|---------|-------------|-----|
| 보상은 오르는데 출력 품질은 나빠짐 | 보상 해킹 | KL 계수를 올리고, 적대적 예시로 보상 모델 재학습 |
| KL 발산 폭증 | 학습률이 너무 높거나 KL 계수가 너무 낮음 | 학습률을 낮추고 beta를 올림 |
| 응답 길이가 단조 증가 | 보상 모델이 장황함에 보상을 줌 | 보상에 길이 페널티를 추가하고, 길이를 통제한 쌍으로 보상 모델 재학습 |
| 모든 응답이 똑같아짐 | 모드 붕괴(mode collapse) | 생성 온도를 올리고 PPO 에포크를 줄임 |
| 보상이 크게 출렁임 | PPO 불안정 | 학습률을 낮추고 클립 비율을 올림 |

## 단계 4: 엔드투엔드 검증

RLHF로 학습한 모델을 배포하기 전에:

1. **SFT 대비 A/B 테스트**: SFT 모델과 RLHF 모델을 200개 이상의 테스트 프롬프트로 돌립니다. 평가자 3명 이상이 응답을 비교하게 하세요. RLHF 모델이 60%를 넘는 경우에 이겨야 합니다.
2. **안전성 평가**: 알려진 적대적 프롬프트(탈옥 공격, 유해 요청)로 테스트하세요. RLHF 모델은 적절하게 거절해야 합니다.
3. **회귀 점검**: 표준 벤치마크(MMLU, HumanEval, MT-Bench)를 돌려 RLHF 모델이 핵심 능력을 잃지 않았는지 확인합니다.
4. **망각 점검**: 일반 텍스트 코퍼스에서 퍼플렉시티(perplexity)를 측정하세요. SFT 모델 대비 증가는 10% 미만이어야 합니다.
5. **길이 분석**: SFT 모델과 RLHF 모델의 평균 응답 길이를 비교합니다. RLHF가 50% 이상 길다면 보상 모델에 장황함 편향이 있는 것일 가능성이 큽니다.
