# 정렬 방법 선택기(Alignment Method Selector)

언어 모델의 정렬 방법을 고를 때, 이 프레임워크로 데이터·컴퓨팅·품질 요구 사항을 평가한 뒤 여러분의 제약 조건에 가장 잘 맞는 방법을 선택하세요.

## 입력 요구 사항

다음을 준비해 주세요:
- **베이스 모델** (예: Llama 3 8B, Mistral 7B, Qwen 2.5 72B)
- **출발점** (베이스 모델인가요, 아니면 이미 SFT를 마쳤나요?)
- **확보 가능한 데이터** (지시 쌍, 선호 쌍, 비쌍 평가 데이터, 또는 없음)
- **컴퓨팅 예산** (GPU 시간, GPU 대수)
- **품질 목표** (프로토타입으로 충분, 오픈소스에 필격, 최고 수준)
- **일정** (며칠, 몇 주, 몇 달)

## 의사결정 매트릭스

### 빠른 선택

| 여러분의 상황 | 추천 방법 | 이유 |
|---------------|-------------------|-----|
| 선호 데이터가 없고 지시 쌍만 있음 | SFT만 | 선호 신호 없이는 정렬할 수 없습니다 |
| 선호 쌍 5,000개 미만, 컴퓨팅 부족 | DPO | 파이프라인이 단순하고 작은 데이터로도 잘 동작합니다 |
| 비쌍 피드백(좋아요/싫어요만 있음) | KTO | 쌍별 비교 없이 동작하는 유일한 방법입니다 |
| 학습 한 번으로 정렬까지 끝내고 싶음 | ORPO | SFT + 정렬을 합치고, 참조 모델도 없습니다 |
| 메모리 제약(참조 모델을 못 올림) | SimPO | 참조 모델이 필요 없습니다 |
| 대규모, 다목적 정렬 | RLHF (PPO) | 별도 보상 모델이 복잡한 선호를 담습니다 |
| 온라인 데이터로 반복 정렬 | RLHF (PPO) | 생성-평가-재학습 루프를 돌릴 수 있습니다 |
| RLHF 이후의 마무리 다듬기 | DPO | RLHF 모델을 표적화된 선호로 파인튜닝합니다 |

### 상세 비교

| 방법 | 데이터 요구 사항 | 메모리 상주 모델 수 | 학습 루프 | 안정성 | 적합한 규모 |
|--------|-----------------|-----------------|----------------|-----------|------------|
| SFT | 지시 쌍 (1만 개 이상) | 1 | 1 | 높음 | 모든 규모 |
| RLHF | 선호 쌍 (2만 개 이상) | 3-4 | 3 | 낮음 | 대규모 (70B 이상) |
| DPO | 선호 쌍 (5천 개 이상) | 2 | 2 (SFT + DPO) | 높음 | 소규모~중규모 (7B-70B) |
| KTO | 비쌍 평가 데이터 (5천 개 이상) | 2 | 2 (SFT + KTO) | 높음 | 모든 규모 |
| ORPO | 선호 쌍 (1만 개 이상) | 1 | 1 | 높음 | 소규모~중규모 |
| SimPO | 선호 쌍 (5천 개 이상) | 1 | 2 (SFT + SimPO) | 높음 | 소규모~중규모 |

## 방법별 설정

### SFT

- **멈춰야 할 때**: 1-3 에포크 후, 또는 검증 손실이 더 이상 내려가지 않을 때
- **핵심 하이퍼파라미터**: 학습률 (1e-5 ~ 5e-5, 모델이 클수록 낮게)
- **중요한 디테일**: 손실 계산에서 지시 토큰은 마스킹합니다
- **주의점**: 3 에포크를 넘기면 암기가 시작됩니다. 사전 학습 데이터를 2-5% 섞어 주세요

### RLHF (PPO)

- **언제 쓰나**: 비교 쌍 2만 개 이상이 있거나, 다목적 정렬이 필요하거나, 반복 온라인 학습을 원할 때
- **핵심 하이퍼파라미터**: KL 계수 (0.01-0.05), PPO 클립 비율 (0.1-0.3), 학습률 (5e-6 ~ 3e-5)
- **중요한 디테일**: 보상 모델은 정책 모델 크기 이상이어야 합니다
- **주의점**: PPO는 불안정합니다. KL 발산과 보상 곡선을 계속 지켜봐야 합니다

### DPO

- **언제 쓰나**: 선호 쌍이 있고 RLHF보다 단순한 파이프라인을 원할 때
- **핵심 하이퍼파라미터**: Beta (0.1-0.5, 작을수록 참조 모델에서 크게 벗어나는 것을 허용)
- **중요한 디테일**: 참조 모델은 SFT 체크포인트의 고정된 복사본이어야 합니다
- **주의점**: beta에 아주 민감합니다. [0.05, 0.1, 0.2, 0.5] 범위로 스윕해 보세요

### KTO

- **언제 쓰나**: 쌍별 비교 없이 "좋음"/"나쁨" 레이블만 있을 때
- **핵심 하이퍼파라미터**: Beta (DPO와 동일), 손실 회피 배율 (나쁜 응답에 1.5배)
- **중요한 디테일**: 좋음/나쁨 예시가 대체로 균형 잡혀야 합니다 (40-60% 비율)
- **주의점**: 쌍이 없으면 그래디언트 신호가 약합니다. DPO보다 데이터가 더 필요할 수 있습니다

### ORPO

- **언제 쓰나**: SFT를 완전히 건너뛰고 베이스 모델에서 곧바로 정렬까지 가고 싶을 때
- **핵심 하이퍼파라미터**: Lambda (선호 항 대비 SFT 항의 가중치)
- **중요한 디테일**: 하나의 데이터셋에 지시 레이블과 선호 쌍이 모두 필요합니다
- **주의점**: 결합 목적 함수는 균형을 잡기 어려울 수 있습니다. SFT 손실이 지배하면 정렬이 약해집니다

### SimPO

- **언제 쓰나**: 참조 모델을 메모리에 둘 수 없는 메모리 제약 환경
- **핵심 하이퍼파라미터**: Beta, gamma (길이 정규화 지수)
- **중요한 디테일**: 길이 정규화가 모델이 짧은 응답만 선호하는 것을 막아 줍니다
- **주의점**: 참조 모델이라는 닻이 없으면 모델이 더 멀리 표류할 수 있습니다. 꼼꼼히 관찰하세요

## 파이프라인 템플릿

### 템플릿 1: 빠른 프로토타입 (1-2일)

```
Base Model -> SFT (1 epoch, 10K examples) -> DPO (3 epochs, 5K pairs)
```

컴퓨팅: A100에서 7B 모델 기준 약 4 GPU시간
품질: 탄탄한 지시 수행, 기본적인 선호 정렬

### 템플릿 2: 프로덕션 품질 (1-2주)

```
Base Model -> SFT (2 epochs, 50K examples) -> DPO (5 epochs, 20K pairs) -> Eval -> Iterate
```

컴퓨팅: 7B 기준 약 40 GPU시간, 70B 기준 약 200 GPU시간
품질: 오픈소스 RLHF 모델에 필적하는 수준

### 템플릿 3: 최고 수준 (1-3개월)

```
Base Model -> SFT (2 epochs, 100K+ examples) -> RLHF (PPO, 50K+ pairs) -> DPO (targeted refinement) -> Eval -> Iterate
```

컴퓨팅: 70B 기준 500 GPU시간 이상
품질: 최상위 프론티어 모델의 정렬에 근접

### 템플릿 4: 최소 데이터 (1-2일)

```
Base Model -> SFT (1 epoch, 5K examples) -> KTO (unpaired thumbs up/down from users)
```

컴퓨팅: 7B 기준 약 2 GPU시간
품질: 최소한의 데이터 수집 비용으로 SFT만 한 모델보다 나음

## 평가 프로토콜

정렬 후 다음 차원에서 평가하세요:

1. **선호 승률**: 정렬된 모델과 SFT 모델을 200개 이상의 테스트 프롬프트로 비교하고 사람이 판정합니다. 목표: 승률 60% 초과.
2. **벤치마크 유지**: MMLU, HumanEval 또는 도메인 특화 벤치마크. SFT 베이스라인 대비 5% 이상 떨어지면 안 됩니다.
3. **MT-Bench 또는 AlpacaEval**: 표준 정렬 품질 벤치마크. 공개된 베이스라인과 비교하세요.
4. **안전성 평가**: 적대적 프롬프트, 탈옥 공격, 유해 요청 유형으로 테스트합니다.
5. **응답 다양성**: 100개 프롬프트에 대한 응답 엔트로피를 측정합니다. 엔트로피가 낮으면 모드 붕괴입니다.

## 흔한 실패 양상

| 증상 | 원인 | 방법별 처방 |
|---------|-------|-------------------|
| 장황하고 늘어진 응답 | 보상 모델/암시적 보상이 길이를 선호 | DPO: beta를 올립니다. RLHF: 길이 페널티를 추가합니다. SimPO: gamma를 조정합니다. |
| 모델이 뭐든 다 동의함 | 선호 데이터 편향에서 온 아첨(sycophancy) | 올바른 응답이 사용자에게 동의하지 않는 선호 쌍을 추가합니다 |
| 무해한 요청도 거절함 | 안전 데이터에 대한 과잉 정렬 | 안전 예시 비율을 줄이고, 정상 요청은 거절하지 않는 쌍을 더 추가합니다 |
| 출력이 SFT와 거의 똑같음 | Beta가 너무 높음(DPO/KTO) 또는 KL 계수가 너무 높음(PPO) | beta/KL 계수를 내립니다. 모델이 아무것도 배우지 못하고 있는 상태입니다 |
| 학습 손실이 출렁임 | 학습률이 너무 높거나 데이터 부족 | 학습률을 2-3배 낮추고, 선호 데이터를 늘립니다 |
