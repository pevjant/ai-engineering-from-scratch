> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-open-model-picker.md](skill-open-model-picker.md)

배포 대상(GPU 종류, GPU당 VRAM, GPU 수, 목표 컨텍스트 길이, 목표 p50/p99 지연 시간, 피크 동시 요청 수)과 작업 프로필(채팅, 코드, 추론, 긴 컨텍스트 검색, 도구 사용)이 주어지면, 레슨 14의 여섯 가지 아키텍처 노브 각각에 대한 명시적 근거와 함께 오픈 모델과 서빙 스택을 추천합니다.

산출물:

1. 모델 숏리스트. 후보 세 개로, 각각 전체 파라미터 수, 활성 파라미터 수(MoE 반영), 아키텍처 플래그(정규화 / 활성화 / 위치 / 어텐션 / MoE / 컨텍스트), 그리고 숏리스트에 오른 단 하나의 이유를 적습니다.
2. 메모리 예산 검사. 최상위 후보에 대해: BF16 기준과 선택한 양자화 기준의 가중치 메모리, 목표 배치 크기에서 목표 컨텍스트의 KV 캐시, 활성화 여유분. 가중치 + KV 캐시 + 활성화가 가용 VRAM을 넘으면 추천을 중단합니다.
3. 양자화 선택. GPTQ-4비트, AWQ-4비트, FP8, 또는 BF16. 작업의 정확도 민감도에 근거해 정당화합니다(코드 / 수학 / 추론 작업은 채팅이나 검색보다 공격적인 양자화에 더 큰 타격을 입습니다).
4. 추론 스택. vLLM, TensorRT-LLM, SGLang, 또는 llama.cpp. 연속 배칭 필요 여부, 추측 디코딩(speculative decoding) 지원, 양자화 포맷 호환성, 단일 노드 대 다중 노드 토폴로지에 근거해 정당화합니다.
5. 처리량 상식 검사. GPU 메모리 대역폭(디코드)과 TFLOPs(프리필)에 기반한 프리필 토큰/초 및 디코드 토큰/초 추정. 디코드 처리량이 목표의 동시 사용자 하한에 못 미치면 추천을 기각합니다.
6. 폴백. 최상위 후보가 VRAM이나 처리량 예산을 넘을 경우의 두 번째 선택. 반드시 하나를 명시합니다.

무조건 기각:
- 오프로딩이나 공격적인 양자화 없이 24GB 소비자용 GPU 한 장에 30B를 넘는 밀집 모델.
- 전문가 병렬화(expert-parallel)를 지원하지 않는 서빙 스택 위의 MoE 모델.
- GQA나 MLA가 없는 아키텍처에서의 긴 컨텍스트(128k+). KV 캐시가 폭발합니다.
- 구체적인 모델 리비전을 명시하지 않는 추천(예: "Llama 3"가 아니라 "Llama 3 8B Instruct v3.1").

출력: 모델, 양자화, 스택을 나열하고 각 결정마다 번호를 붙인 근거를 달린 한 페이지짜리 추천서. 마지막에 "다음 조건이라면 다시 고려할 가치가 있다..." 문단으로, 선택을 뒤집을 만한 구체적인 능력이나 배포 파라미터를 명시합니다.
