# 추측 디코딩과 EAGLE-3

> 페이즈 7 · 레슨 16은 수학을 증명했습니다. Leviathan 기각 규칙은 검증기(verifier)의 분포를 정확히 보존한다는 것이죠. 이 레슨은 2026년 프로덕션(운영 환경) 추측 디코딩(speculative decoding)을 학습 스택 관점에서 다룹니다. EAGLE-3는 드래프트(draft) 모델을 값싼 근사치에서, 검증기 자신의 은닉 상태로 학습한 전용 소형 네트워크로 바꾸고, 거기에 학습·추론 분포를 일치시키는 학습 시점 테스트(training-time test) 루프를 더했습니다. 결과는 이렇습니다: 엔드투엔드 3배~6.5배 가속, 채팅에서 0.9를 넘는 토큰별 수용률, 분포상의 트레이드오프 없음. 2026년의 모든 프로덕션 추론 스택이 기본으로 탑재합니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 7 · 16 (추측 디코딩 수학), 페이즈 10 · 12 (추론 최적화)
**시간:** 약 75분

## 학습 목표

- Leviathan 정리를 한 문장으로 서술하고, 추측 루프가 검증기와 동일한 분포의 표본을 만들어 냄을 증명합니다
- 기본(vanilla) 추측 디코딩(Leviathan 2023)부터 EAGLE, EAGLE-2, EAGLE-3에 이르는 2년의 발전 과정을 따라가며, 각 단계가 정확히 어떤 한계를 제거했는지 짚습니다
- 수용률 `α`와 드래프트 대 검증기 비용 비율 `c`로 기대 가속비를 계산하고, 구간마다 최적 드래프트 길이 `N`을 고릅니다
- 추측 루프 전체를 직접 구현합니다: 드래프트, 검증, 잔여 분포(residual)에서의 기각 샘플링, 기각 시 KV 캐시 롤백, 전부 수용 시 보너스 토큰 발급

## 문제

70B 모델의 자기회귀 디코딩은 H100에서 초당 35토큰 정도밖에 나오지 않습니다. GPU는 턱없이 놀고 있죠. 천장은 메모리 대역폭입니다. 토큰 하나를 만들려면 70B짜리 가중치를 HBM에서 통째로 읽어 들이고, 산술 한 스텝을 하고, float 하나를 뱉습니다. 연산 유닛은 대부분 가만히 있습니다.

추측 디코딩은 이것을 실제로 풀 수 있는 처리량 문제로 바꿉니다. 값싼 드래프트가 작은 순전파 `N`번으로 토큰 `N`개를 제안합니다. 검증기는 프리픽스에 드래프트 `N`개를 모두 얹어 단 한 번 실행합니다. 검증기의 위치 `i` 분포가 드래프트와 (곧 정밀하게 정의할 통계적 의미에서) 일치하면 수용하고, 아니면 기각한 뒤 잔여 분포에서 교정 토큰을 뽑습니다. 대형 모델의 순전파 한 번이 토큰 하나 대신 최대 `N+1`개의 수용된 토큰을 만들어 냅니다.

중요한 정리는 Leviathan, Kalman, Matias(ICML 2023)입니다. 출력 분포가 검증기에서 직접 샘플링했을 때와 동일하다는 것입니다. 근사가 아니라 동일합니다. 추측 디코딩이 프로덕션에서 허용되는 이유가 전부 여기에 있습니다. 품질 트레이드오프가 전혀 없는 순수한 지연 시간 최적화라는 점이죠.

페이즈 7 · 레슨 16이 준 것은 수학입니다. 이 레슨이 주는 것은 학습 스택입니다. 좋은 드래프트는 값싼 드래프트보다 2배 더 큰 가속을 가져다줍니다. EAGLE, EAGLE-2, EAGLE-3(Li et al., 2024–2025)는 "드래프트 = 같은 모델의 축소판"이라는 발상을 정밀한 엔지니어링 규율로 바꿔 놓았습니다. 2026년 프로덕션 추론 서버의 기본값은 EAGLE-3입니다.

## 개념

### 불변량: Leviathan 기각 샘플링

프리픽스가 주어졌을 때 다음 토큰에 대한 드래프트의 분포를 `p(t)`, 검증기의 분포를 `q(t)`라 하겠습니다. 드래프트 토큰 `d ~ p`를 뽑고, 확률 `min(1, q(d) / p(d))`로 수용합니다. 기각되면 잔여 분포 `(q - p)_+ / ||(q - p)_+||_1`에서 샘플링합니다. 그 결과 표본은 `q`를 따라 분포합니다. 이것은 `p`가 얼마나 나쁜지와 무관하게 성립합니다. 나쁠수록 기각이 잦을 뿐, 출력은 정확히 유지됩니다.

이 호출을 `N`번 연달아 쌓되, 검증기 순전파는 `prefix + d_1 + ... + d_N`에 대해 한 번만 돌립니다. 검증기는 `q_1, q_2, ..., q_{N+1}`을 동시에 돌려줍니다. 왼쪽에서 오른쪽으로 훑습니다. 위치 `j`에서 처음 기각되면 `residual(q_j, p_j)`에서 샘플링하고 멈춥니다. 전부 수용되면 `q_{N+1}`에서 보너스 토큰 하나를 뽑습니다.

### 가속비를 결정하는 것

드래프트된 토큰 하나의 기대 수용률을 `α`, 비용 비율을 `c = cost(draft) / cost(verifier)`라 하겠습니다. 검증기 순전파 한 번당 기대 수용 토큰 수는:

```
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

수용 토큰 하나당 기대 총 소요 시간은 `(N * c + 1) / E[accepted]`입니다. 이것을 `N`에 대해 최소화하면 스위트 스팟이 나옵니다. `α = 0.8, c = 0.05`일 때: 최적 `N`은 대략 5–7, 가속비는 3.2배입니다. `α = 0.95, c = 0.02`일 때: 최적 `N`은 대략 8–10, 가속비는 5배에 육박합니다.

가장 큰 레버는 `α` 하나입니다. `N = 5`로 고정한 채 `α = 0.6`(기본 드래프트)에서 `α = 0.9`(EAGLE-3)로 올리면, 검증기 순전파당 기대 수용 토큰이 2.2개에서 4.1개로 늘어납니다. 같은 검증기로 거의 2배의 처리량입니다.

### 2년간의 발전 과정

**기본 추측 디코딩(Leviathan, 2023).** 드래프트 모델은 같은 계열에서 독립적으로 학습한 더 작은 LLM입니다. 연결하기 쉽고, `α ≈ 0.6`, 가속비는 잘해야 2배 안팎입니다.

**EAGLE-1(Li et al., 2024).** 드래프트는 작은 트랜스포머(보통 한두 개 레이어)로, 검증기의 마지막 레이어 은닉 상태를 입력받아 다음 토큰을 바로 예측합니다. 드래프트가 검증기의 특성(feature) 표현을 보기 때문에 분포가 검증기에 훨씬 가깝습니다. `α`가 0.7–0.8로 오릅니다.

**EAGLE-2(Li et al., 2024).** 동적 드래프트 트리를 더합니다. 토큰 `N`개짜리 시퀀스 하나를 제안하는 대신 작은 후보 트리를 제안하고, 검증기로 한 번의 순전파로 각 후보를 채점(트리 어텐션)한 뒤 확률이 가장 높은 경로를 따라갑니다. 드래프트 길이가 단계마다 적응합니다. 수용 경로 토큰 기준 `α`가 0.85를 넘습니다.

**EAGLE-3(Li et al., 2025, NeurIPS).** 두 가지가 더 바뀌었습니다. 첫째, 특성 예측 손실을 완전히 버립니다. EAGLE-1/2는 드래프트를 검증기의 은닉 상태에 맞춰 학습시켰는데, 이것이 데이터가 주는 이득에 상한을 걸었죠. EAGLE-3는 토큰 예측으로 직접 학습합니다. 둘째, 학습 시점 테스트(TTT): 드래프트 학습 중에 드래프트 자신의 이전 예측을 여러 스텝에 걸쳐 입력으로 되먹입니다. 추론 때 작동하는 방식 그대로죠. 이렇게 학습 분포와 테스트 분포를 일치시켜 오차 누적을 막습니다. 측정된 가속비: 채팅에서 최대 6.5배, H100의 SGLang에서 배치 64 기준 처리량 38% 향상.

### KV 캐시 롤백

검증은 검증기의 KV 캐시를 한 번의 패스로 `N`개 항목만큼 늘립니다. 위치 `j`에서 기각이 일어나면 위치 `j-1` 너머의 캐시 내용은 이제 틀린 값입니다. 흔한 구현은 둘 중 하나입니다. 스크래치 버퍼에 쓰다가 수용 시 커밋하거나(vLLM, TensorRT-LLM), 물리 KV 캐시에 논리 길이를 더해 두고 기각 시 잘라내는 방식입니다. 어느 쪽이든 롤백 비용은 레이어·헤드당 몇 바이트 수준이라 순전파 비용에 비하면 무시할 수 있습니다.

EAGLE-2 트리 탐색에서는 검증기가 트리 토폴로지를 존중하는 비인과(non-causal) 마스크로 어텐션을 돌립니다. 엔지니어링은 까다롭지만 계산 자체는 커스텀 마스크를 넣은 표준 flash-attention 호출입니다.

### 2026년의 드래프트 아키텍처

| 기본(vanilla) | 별도의 소형 LLM | 0.55-0.70 | 1.8-2.3배 | 없음 (기존 소형 모델 재활용) |

## 만들어 보기

`code/main.py`를 보십시오. 여기에는 Leviathan 추측 루프의 모든 조각이 들어 있습니다. N개 드래프트, 검증기 병렬 패스, 위치별 기각, 잔여 샘플링, 보너스 토큰, KV 롤백, 그리고 출력 분포가 `q`에서의 직접 샘플링과 일치하는지의 경험적 검증까지요.

### 단계 1: 기각 규칙

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 단계 2: 잔여 분포

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 단계 3: 추측 스텝 전체

`spec_step` 함수는 `p`에서 토큰 `N`개를 드래프트한 뒤, 병렬 `q` 평가 한 번으로 전부 검증합니다. 드래프트 토큰마다 기각 규칙을 적용하고, 처음 기각되는 자리에서 잔여 분포로 교정 토큰을 뽑습니다. 모두 수용되면 `q_{N+1}`에서 보너스 토큰을 하나 내보냅니다.

### 단계 4: KV 롤백 장부 관리

시뮬레이터는 워커마다 논리적 `kv_length`를 추적합니다. 드래프트 `k`개가 수용되면 `kv_length += k`입니다. 위치 `j`에서 기각되면 캐시는 이미 `j` 너머까지 써져 있지만, 논리 길이는 `prefix_length + j + 1`(교정 토큰 바로 다음)로 설정합니다. 이후 읽기는 논리 길이까지만 잘라 냅니다.

### 단계 5: Leviathan 검증

추측 스텝을 50,000번 실행합니다. 수용된 토큰의 경험적 분포를 세고, `q`에서 직접 뽑은 50,000개 표본과 비교합니다. 카이제곱 통계량이 임계값보다 충분히 작아야 합니다. 정리가 실전에서도 통과합니다.

### 단계 6: 가속비 대 α

`p`를 `q`에서 서로 다른 진폭으로 비께겨 드래프트 품질을 쓸어(sweep) 봅니다. `α`를 측정한 다음, 검증기 호출당 기대 토큰 수를 `α`와 `N`의 함수로 그립니다. 코드는 EAGLE-3급 드래프트 품질(`α ≈ 0.9`)이 검증기 호출당 4–5개 토큰을 열어 주는 모습을 표로 출력합니다.

H100에서 배치 64로 EAGLE-3을 쓰는 SGLang: EAGLE-3 논문 기준, 배치 64 기본 디코딩보다 처리량이 약 1.38배 높습니다.

추측 디코딩을 쓰면 좋은 경우:

- p50 지연 시간이 피크 처리량보다 중요한 모든 대화형 채팅 워크로드.
- 코드 생성과 구조화된 출력(JSON, SQL). 목표 분포가 매우 예측 가능해서 `α`가 0.9를 넘습니다.
- 긴 글 생성(수천 토큰). 분할상환된 가속이 계속 이자를 냅니다.

쓰지 말아야 할 때:

- 아주 작은 모델(3B 미만). 드래프트가 검증기보다 그렇게까지 싸지는 않습니다.
- 작은 배치-1 CPU 배포. 드래프트 모델의 메모리 오버헤드가 값어치를 못 할 수 있습니다.
- `α`가 무너지는 아주 높은 온도의 창작 샘플링.

## 연습 문제

1. `code/main.py`를 실행해 보세요. 50,000개 표본에서 Leviathan 분포 검증의 카이제곱 통계량이 95% 임계값 아래에 머무는지 확인합니다.

2. `α`는 0.9, `c`는 0.04로 고정한 채 `N`을 1부터 10까지 쓸어 보세요. 검증기 호출당 기대 토큰 수와 토큰당 실제 소요 시간을 그래프로 그립니다. 소요 시간을 최소화하는 `N`을 찾고, 곡선이 그런 모양이 되는 이유를 설명해 보세요.

3. 코드를 고쳐 EAGLE-2 트리 탐색을 시뮬레이션해 보세요. 각 단계에서 드래프트가 `[2, 2, 2]` 모양의 트리(후보 경로 여덟 개)를 제안합니다. 검증기는 한 번만 실행되고 확률이 가장 높은 수용 경로가 이깁니다. 리프당 `α`와 검증기 호출당 총 토큰 수를 계산하고, 동등한 연산량의 선형 체인 추측 디코딩과 비교해 보세요.

4. 동시에 실행되는 두 시퀀스용 배치 KV 롤백 시뮬레이터를 구현해 보세요. 시퀀스 A는 모든 드래프트가 수용되고, 시퀀스 B는 위치 2에서 기각됩니다. 올바른 `kv_length`가 시퀀스별로 갱신되고 낭비되는 작업이 없음을 보여 주세요.

5. EAGLE-3 논문의 4절(Training-Time Test)을 읽어 보세요. TTT가 없는 소박한 드래프트 학습이 노출 편향(exposure bias)에 시달리는 이유와, 학습 중에 드래프트 자신의 예측을 입력으로 먹이면 그것이 고쳐지는 이유를 두 문장으로 설명합니다. 이것을 seq2seq의 scheduled sampling 문헌과 연결해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 방식 | 실제 의미 |
|------|----------------|------------------------|
| Leviathan 규칙 | "min(1, q over p)" | 확률 `min(1, q(d)/p(d))`의 베르누이 수용/기각. 기각 시 잔여 분포에서 샘플링하면 검증기 분포를 정확히 보존함 |
| 잔여 분포 | "(q 빼기 p)의 양수부, 정규화" | 0에서 잘라낸 `(q - p)_+`를 다시 정규화한 것 — 기각 시 샘플링해야 할 올바른 분포 |
| 수용률 α | "드래프트가 맞는 빈도" | 기각 규칙 아래에서 토큰당 기대 베르누이 성공 확률. 모든 가속 수학을 지배함 |
| EAGLE-1 | "은닉 상태 드래프트" | 검증기의 마지막 레이어 은닉 상태로 조건화된 작은 트랜스포머 드래프트(Li et al., 2024) |
| EAGLE-2 | "동적 드래프트 트리" | EAGLE-1에 후보 이어지기 트리를 더한 것. 검증기 패스 한 번으로 트리 어텐션으로 채점함 |
| EAGLE-3 | "학습 시점 테스트" | 특성 예측 손실을 버리고 토큰 예측으로 직접 학습하며, 학습 중에는 드래프트 자신의 출력을 입력으로 먹임 |
| 학습 시점 테스트(TTT) | "노출 편향 해결책" | 학습 중에 드래프트를 자기회귀적으로 돌려 학습·테스트 입력 분포를 일치시킴 — scheduled sampling의 직접적인 대응물 |
| KV 롤백 | "기각된 드래프트 되돌리기" | 기각 후 검증기의 KV 캐시를 수용된 프리픽스 길이로 되돌리는 장부 관리 |
| 보너스 토큰 | "공짜 토큰" | 드래프트 `N`개가 모두 수용되면 `q_{N+1}`에서 토큰 하나를 검증기 추가 비용 없이 샘플링 |
| 트리 어텐션 | "후보 여럿을 한 번에 검증" | 드래프트 트리의 토폴로지를 존중하는 비인과 마스크의 어텐션. 트리의 모든 노드에 대한 `q_i`를 순전파 한 번으로 계산 |
