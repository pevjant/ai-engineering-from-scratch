# 다중 토큰 예측(MTP)

> GPT-2부터 Llama 3까지 모든 자기회귀 LLM은 위치당 하나의 손실로 학습합니다. 다음 토큰을 예측하는 것이죠. DeepSeek-V3는 위치당 두 번째 손실을 더했습니다. 그다음 토큰을 예측하는 손실입니다. 추가된 14B 파라미터(671B 모델 위에 얹힌)는 그레이디언트 흐름을 통해 본 모델로 되돌아가 증류되었고, 학습된 MTP 헤드는 추론에서 80% 이상의 수용률을 내는 추측 디코딩 드래프터로 용도가 바뀌었습니다. 생성 처리량 1.8배가 공짜로 따라온 셈입니다. 이 레슨은 DeepSeek 기술 보고서의 순차(sequential) MTP 모듈을 만들고, 손실과 헤드 공유 파라미터 배치를 계산하며, MTP는 인과 체인을 지키는 반면 Gloeckle et al.의 원조 병렬 MTP는 그것을 깨뜨렸는지 설명합니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 10 · 04 (미니 GPT 사전 학습), 페이즈 10 · 15 (추측 디코딩)
**시간:** 약 60분

## 학습 목표

- MTP 학습 목표를 서술하고 예측 깊이 전반의 결합 손실을 유도합니다
- Gloeckle et al.(2024)의 병렬 MTP 헤드와 DeepSeek-V3의 순차 MTP 모듈의 차이, 그리고 순차 설계가 인과 체인을 보존하는 이유를 설명합니다
- 사전 학습 실행에 MTP 모듈을 추가할 때의 파라미터·메모리 오버헤드를 계산합니다
- MTP 모듈 하나를 직접 구현합니다. 공유 임베딩, 깊이별 트랜스포머 블록, 투영, 공유 출력 헤드

## 문제

다음 토큰 예측이 표준 LLM 학습 목표입니다. 모든 은닉 상태는 정확히 한 가지, 바로 다음에 오는 토큰을 예측하도록 지도됩니다. 이것은 놀랄 만큼 약한 신호입니다. 시퀀스에 담긴 대부분의 정보는 한 토큰을 넘어섭니다. 구조, 일관성, 사실성, 산술의 흐름이요. 모델은 조 단위 토큰에 걸쳐 한 토큰짜리 신호를 수없이 쌓는 방식으로 그것들을 배워야 합니다.

MTP는 이렇게 묻습니다. 모든 은닉 상태가 여러 미래 토큰을 한 번에 예측하도록 지도되면 어떨까? Gloeckle et al.(Meta, 2024)은 이것이 도움이 됨을 보였습니다. 그들의 구현은 백본 위에 여러 독립 출력 헤드를 얹고 각각 다른 오프셋을 예측하게 했습니다. 병렬이고 단순하지만, 헤드들은 계층적 정제 없이 같은 은닉 상태만 봤고, 예측들이 인과적으로 이어지지 않아 추측 디코딩에는 쓸 수 없었습니다.

DeepSeek-V3(2024년 12월)는 MTP를 예측 깊이마다 인과 체인을 지키는 순차 모듈로 다시 설계했습니다. 모델은 `h_i^(0)`에서 `t+1`을 예측하고, 이어서 `h_i^(0)`를 `E(t+1)` 임베딩과 결합한 새 은닉 상태 `h_i^(1)`에서 `t+2`를 예측하는 식으로 나아갑니다. 각 깊이는 자기만의 작은 트랜스포머 블록입니다. 공유 임베딩과 공유 출력 헤드가 파라미터 오버헤드를 적당하게 유지합니다. DeepSeek-V3 규모에서는 671B 본 모델 가중치 위에 MTP 모듈로 추가 파라미터 14B입니다. 그 2% 오버헤드가 더 촘촘한 학습 신호와, 추론 시 바로 쓸 수 있는 추측 디코딩 드래프트를 동시에 사다 준 것입니다.

이 레슨은 MTP 모듈 하나와 D-깊이 손실을 직접 만듭니다. 수학은 깔끔합니다. 구현은 150줄입니다.

## 개념

### 순차 MTP 레시피

DeepSeek-V3는 본 모델 위에 `D`개의 MTP 모듈을 얹습니다. 각 모듈 `k`(`k = 1..D`)는 깊이 `k`의 토큰, 즉 위치 `i`까지의 프리픽스가 주어졌을 때 `t_{i+k}`를 예측합니다.

모듈 `k`는 다음으로 이루어집니다:

- 자기만의 어텐션과 MLP를 갖춘 트랜스포머 블록 `T_k`.
- 이전 깊이의 은닉 상태를 다음 깊이의 정답 토큰 임베딩과 결합하는 투영 행렬 `M_k`.
- 공유 임베딩 `E`(본 모델과 같은 것).
- 공유 출력 헤드 `Out`(본 모델과 같은 것).

학습 시 위치 `i`까지의 프리픽스에 대해 깊이별 은닉 상태는:

```
h_i^(0) = main model backbone at position i
h_i^(k) = T_k( M_k * concat(RMSNorm(h_i^(k-1)), RMSNorm(E(t_{i+k}))) )   for k >= 1
```

깊이별 예측은:

```
logits_{i+k} = Out(h_i^(k-1))   for k = 1..D
```

깊이별 손실은 정답 `t_{i+k}`에 대한 교차 엔트로피입니다:

```
L_k = CE(logits_{i+k}, t_{i+k})
```

깊이 전반의 결합 손실:

```
L_MTP = (lambda / D) * sum_{k=1..D} L_k
```

`lambda`는 작은 가중치 계수입니다. DeepSeek-V3는 학습 처음 10% 동안 0.3을, 이후에는 0.1을 씁니다. 전체 학습 손실은 `L_main + L_MTP`입니다.

### 병렬이 아니라 순차인 이유

Gloeckle의 원조 병렬 MTP는 D개의 출력 헤드가 각각 `h_i^(0)`에 바로 붙는 형태였습니다. 각 헤드가 같은 백본 은닉 상태에서 `t_{i+k}`를 예측합니다. 학습은 잘 되지만 예측들이 서로를 조건으로 삼지 않습니다. `head_1`의 출력으로 `head_2`를 돕는 일은 불가능합니다. 헤드들이 병렬로 발화하니까요.

DeepSeek-V3의 순차 설계는 `h_i^(k-1)`에 실제 다음 토큰 임베딩 `E(t_{i+k})`를 더해 `h_i^(k)`를 만듭니다. 이것이 인과 체인을 지킵니다. `t_{i+k+1}`을 예측하려면 깊이 `k+1`의 모듈이 `t_{i+k}`에 무엇이 있었는지 보는 식이죠. 이것은 자기회귀 디코더가 자기 출력을 소비하는 방식과 구조적으로 동일합니다. 덕분에 MTP 모듈을 추측 디코딩 드래프터로 바로 쓸 수 있습니다.

추론에서는 이렇습니다: `h_i^(k-1)`과 드래프트된 `t_{i+k}`를 모듈 `k+1`에 넣어 `t_{i+k+1}` 예측을 얻습니다. 반복합니다. 학습된 MTP 모듈을 드래프트 네트워크로 쓰는, 정확히 EAGLE식 드래프트입니다. DeepSeek-V3는 첫 MTP 모듈에서 80% 이상 수용률과 약 1.8배 가속을 보고합니다.

### 파라미터 장부

은닉 크기 `h`, 어휘 `V`인 모델의 경우:

- 본 모델: 수십억 개의 파라미터에 더해 크기 `V * h`의 출력 헤드 하나.
- 공유 출력 헤드: 본 모델의 헤드를 재사용. 추가 파라미터 없음.
- 공유 임베딩: 본 모델의 임베딩을 재사용. 추가 파라미터 없음.
- MTP 모듈 하나당:
  - 투영 `M_k`: `(2h) * h = 2h^2`.
  - 트랜스포머 블록 `T_k`: 어텐션(MHA 기준 `4h^2`) 더하기 MLP(8/3 비율 SwiGLU 기준 보통 `8h^2`). 블록당 약 `12h^2`.

총 추가(모듈당): `~14h^2`. DeepSeek-V3의 `h = 7168`, D = 1 모듈이면: 서류상 `~14 * 7168^2 = ~720M` 파라미터입니다. DeepSeek-V3는 14B를 보고하는데, 그 차이는 대개 MTP 모듈의 전문가 레이어도 MoE라는 점에서 옵니다.

### 추측 디코딩 보수

사전 학습 중 MTP 모듈은 학습을 약 10% 느리게 합니다(순전파 연산 증가, 추가 손실). 보수는 두 겹입니다:

1. 더 촘촘한 학습 신호. 각 은닉 상태가 D+1개의 감독 대상을 봅니다. MMLU, GSM8K, MATH, HumanEval에서 측정된 효과: DeepSeek-V3의 소거 실험에서 일관된 몇 퍼센트포인트 개선.

2. 추론에서 공짜 추측 디코딩 드래프트. MTP 모듈은 이미 다음 몇 개 토큰을 예측하도록 학습돼 있습니다. 드래프트 네트워크로 용도를 바꾸면 80% 이상 수용률을 냅니다. 그 수준이면 N=3 또는 N=5 추측 디코딩이 1.8배 처리량을 줍니다. 10%의 학습 시간 비용은 추론을 처음 돌리는 순간 본전을 넘습니다.

### EAGLE과의 관계

EAGLE은 사전 학습이 끝난 뒤 작은 드래프트 모델을 따로 학습시킵니다. MTP는 드래프트를 사전 학습 안에 구워 넣습니다. 두 접근은 비슷한 수용률에 도달하지만 파이프라인이 다릅니다:

| 차원 | EAGLE-3 | MTP (DeepSeek-V3) |
|-----------|---------|------------------|
| 학습 시점 | 사전 학습 이후 | 사전 학습 중 |
| 기존 가중치와의 하위 호환 | 예 | 아니오 (재학습 필요) |
| 드래프트 파라미터 | 트랜스포머 1-2개 레이어 | 트랜스포머 블록 1개 + 투영 |
| 수용률 | 0.88-0.92 | 깊이 1에서 0.80 이상 |
| 가속 외 이득 | 추측 디코딩뿐 | 더 촘촘한 학습 신호 + 가속 |

## 만들어 보기

`code/main.py`는 MTP 모듈 하나를 엔드투엔드로 만듭니다. 공유 임베딩, 투영, 트랜스포머 블록, 공유 출력 헤드. 그다음 짧은 합성 시퀀스에서 깊이별 교차 엔트로피 손실을 계산하고 구성 요소별 파라미터 수를 출력합니다. 32토큰짜리 장난감 어휘가 숫자를 읽기 쉽게 유지합니다.

### 단계 1: 공유 임베딩 테이블

`vocab_size x hidden` 테이블 하나가 본 모델과 모든 깊이의 모든 MTP 모듈에 쓰입니다. 사본이 아니라 문자 그대로 같은 텐서입니다.

### 단계 2: 깊이별 결합

```python
def combine(prev_hidden, next_token_embed, M_k):
    # 특성 차원을 따라 이어 붙인 뒤 hidden으로 다시 투영
    concat = rms_norm(prev_hidden) + rms_norm(next_token_embed)  # 벡터 덧셈으로 대체한 것
    projected = matvec(M_k, concat)
    return projected
```

실제 DeepSeek-V3는 RMSNorm된 두 벡터를 `[2h]`로 이어 붙인 뒤 `h x 2h` 행렬로 투영합니다. 장난감 구현은 표준 라이브러리 간결함을 위해 벡터 덧셈을 씁니다.

### 단계 3: 깊이 k의 트랜스포머 블록

셀프 어텐션 더하기 MLP. 장난감 구현에서는 한 층짜리 선형 어텐션 블록과 SwiGLU MLP가 numpy 없이도 구조를 보이게 유지합니다.

### 단계 4: 공유 출력 헤드

본 모델의 출력 투영을 재사용합니다. 어휘 전체에 대한 로짓.

### 단계 5: 깊이별 손실

오프셋 `k`의 정답 토큰에 대한 softmax(logits)의 교차 엔트로피. 깊이 전반에 걸쳐 `lambda / D` 스케일링 계수로 집계합니다.

### 단계 6: 파라미터 장부

전체 파라미터 수, 공유(임베딩, 헤드) 수, 모듈당 추가 수를 출력합니다. MTP 추가분 대 본 모델 크기 비율을 보여 줍니다.

## 사용해 보기

MTP는 DeepSeek-V3(2024년 12월)와 DeepSeek-R1 계열에 통합돼 있습니다. 추론에서는:

- DeepSeek 자체 서빙 스택은 MTP 모듈을 별도 설정 없이 추측 디코더로 소비합니다.
- vLLM과 SGLang은 2026년 4월 기준 DeepSeek-V3 MTP 통합 경로를 갖추고 있습니다.
- AMD의 ROCm SGLang 튜토리얼은 V3 체크포인트에서 측정된 1.8배 가속을 내는 구체적인 MTP 추측 디코딩 설정을 보여 줍니다.

새 사전 학습 실행에서 MTP를 쓸 때:

- 사전 학습 파이프라인 전체를 통제하고 있고 더 촘촘한 학습 신호를 저축해 두고 싶을 때.
- 모델을 규모 있게 서빙할 것을 알고 있고 추측 디코딩을 공짜로 얻고 싶을 때.
- 은닉 크기가 최소 4096일 때. 1B 규모에서는 오버헤드가 이득보다 해롭습니다.

쓰지 말아야 할 때:

- 기존 사전 학습 밀집 모델을 파인튜닝할 때. MTP 모듈은 학습돼 있지 않습니다.
- 비교할 깨끗한 베이스라인이 필요한 연구 모델일 때. MTP는 아키텍처를 바꿉니다.

## 연습 문제

1. `code/main.py`를 실행해 보세요. 합성 신호가 강해질수록 깊이별 손실이 단조 감소함을 보여 줍니다. 합성 데이터를 고정 패턴으로 바꿔 깊이-1과 깊이-2 손실이 모두 수렴하는지 확인합니다.

2. D=1 MTP 모듈을 얹은 밀집 70B 모델(hidden 8192, 80개 레이어)의 파라미터 오버헤드를 계산해 보세요. DeepSeek-V3가 보고한 14B 오버헤드와 비교합니다. DeepSeek의 숫자가 더 큰 이유를 설명합니다. MTP 트랜스포머 블록이 같은 MoE 구조를 물려받아 모듈당 파라미터 수가 불어나기 때문입니다.

3. 장난감 구현에서 D=2를 만들어 보세요. h^(1)을 받아 `t_{i+2}`를 예측하는 두 번째 MTP 모듈을 추가합니다. 결합 손실과 파라미터 장부가 DeepSeek 논문의 19-21식과 일치하는지 검증합니다.

4. 장난감 구현을 병렬 MTP(Gloeckle식)로 바꿔 보세요. 본 은닉 상태 위에 D개 출력 헤드를 얹고 각각 다른 오프셋을 예측하게 합니다. 같은 합성 신호에서 깊이별 손실이 순차 버전과 어떻게 비교되는지 측정합니다. 순차 버전은 중간 예측을 조건으로 삼기 때문에 k > 1인 깊이-k 손실이 더 낮게 나와야 합니다.

5. 학습된 MTP 모듈을 EAGLE식 드래프트로 써 보세요. 추론에서 모듈 k를 호출해 `t_{i+k}`를 제안합니다. 홀드아웃 시퀀스에서 이 드래프트 토큰의 수용률을 본 모델의 예측과 비교해 측정합니다. 장난감에서 50% 이상이 나오면 MTP-as-draft의 경험적 성질을 재현한 것입니다.

## 핵심 용어

| 용어 | 사람들이 말하는 방식 | 실제 의미 |
|------|----------------|------------------------|
| MTP 모듈 | "추가 손실 블록" | 본 모델보다 `k`칸 앞선 토큰을 예측하는 작은 트랜스포머 블록 + 투영 |
| 예측 깊이 | "몇 번째 오프셋" | 모듈 `k`가 위치 `i`까지의 프리픽스에서 `t_{i+k}`를 예측할 때의 정수 `k` |
| 병렬 MTP | "Gloeckle식" | 같은 백본 은닉 상태 위의 D개 독립 헤드. 조건 체인 없음 |
| 순차 MTP | "DeepSeek-V3식" | 각 모듈이 이전 깊이의 은닉 상태와 다음 토큰 임베딩을 조건으로 삼음. 인과 체인 보존 |
| 공유 출력 헤드 | "본 헤드 재사용" | MTP 모듈이 별도 출력 투영이 아니라 본 모델의 LM 헤드를 호출 |
| 공유 임베딩 | "본 테이블 재사용" | 같은 어휘 임베딩 테이블을 어디서나 사용. 중복 파라미터 없음 |
| 투영 행렬 M_k | "은닉 + 다음 토큰 결합" | 이전 은닉 상태와 목표 토큰 임베딩을 다음 깊이의 입력으로 접어 넣는 `h x 2h` 선형 레이어 |
| 결합 손실 L_MTP | "추가 손실 평균" | 깊이별 교차 엔트로피 손실의 산술 평균에 `lambda`를 곱한 것 |
| 깊이 1 수용률 | "MTP 드래프트가 맞는 빈도" | D=1 MTP 모듈의 top-1 예측이 본 모델의 top-1 예측과 같은 비율. DeepSeek-V3에서 80% 이상 |
| Lambda 가중치 | "추가 손실 중요도" | 깊이별 스케일링 계수. DeepSeek-V3는 학습 초기 0.3, 이후 0.1 |
