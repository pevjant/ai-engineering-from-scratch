작업 부하 명세(컨텍스트 길이 프로파일 p50/p99, 작업 믹스, GPU당 메모리 예산, 목표 처리량, 품질-속도 우선순위)가 주어지면, 순수 트랜스포머(+MoE +MLA), Jamba 스타일 하이브리드, 순수 Mamba 모델 중 하나를 추천합니다.

산출물:

1. 컨텍스트 길이 구간 분류. 짧음(16k 미만), 중간(16k-64k), 김(64k-256k), 초장형(256k 이상). 첫 번째 의사결정의 기준이 됩니다.
2. 아키텍처 추천. 순수 트랜스포머, 1:7 하이브리드, 1:3 하이브리드, 1:15 하이브리드, 순수 Mamba 중 하나를 고릅니다. 컨텍스트 구간과 해당 작업의 인컨텍스트 회상 요구를 근거로 정당화합니다.
3. 메모리 예산 확인. 목표 컨텍스트에서 KV 캐시 + SSM 상태를 계산합니다. 가중치와 활성값 메모리(보통 가중치와 KV 캐시 위에 10~20 GB 추가)까지 반영한 뒤 목표 가속기에 들어가는지 확인합니다.
4. 품질 트레이드오프 공개. 선택한 희소(sparsity) 수준의 품질 비용을 문서화합니다. 1:7보다 어텐션 비율이 낮은 하이브리드는 인컨텍스트 검색에서 측정 가능한 수준으로 성능이 떨어지고, 순수 Mamba는 일부 상태 추적 작업에서 실패합니다.
5. 추론 스택 호환성. 선택한 아키텍처가 대상 스택(vLLM, TensorRT-LLM, SGLang, llama.cpp)에서 지원되는지 확인합니다. 하이브리드는 순수 트랜스포머보다 도구 지원이 얇습니다.

하드 리젝(무조건 거부):

- 컨텍스트 16k 미만에 대한 Jamba 스타일 하이브리드. 아키텍처 오버헤드를 정당화할 수 없습니다.
- 추론 집중적이거나 다중 문서 교차 참조 작업에 대한 순수 Mamba. 상태 추적 한계가 발목을 잡습니다.
- 1:15보다 낮은 하이브리드 비율. 이보다 낮으면 인컨텍스트 회상이 불안정합니다.
- 지정된 가속기에서 계산된 메모리 예산에 맞지 않는 모든 추천.

거부 규칙:

- 작업 부하가 짧은 컨텍스트와 긴 컨텍스트가 진짜로 섞여 있다면, 하이브리드 추천을 거부하고 순수 트랜스포머(가능하면 MLA 포함)를 권합니다. 하이브리드는 특히 롱컨텍스트 작업에서 빛을 발하는 것입니다.
- 가속기가 소비자용(24GB 이하)이라면 하이브리드 크기 모델을 거부하고, 증류된 소형 하이브리드나 양자화된 순수 트랜스포머를 권합니다.
- 지연 시간에 민감한 배치-1(batch-1) 생성 작업이면서 모델이 새 것(기존 배포 경로가 없음)이라면 거부하고, 더 단순한 경로로서 스페큘레이티브 디코딩(페이즈 10 · 15)이 적용된 잘 지원되는 순수 트랜스포머를 권합니다.

출력: 컨텍스트 구간, 아키텍처 선택, 목표 컨텍스트에서의 KV 캐시, 품질 트레이드오프 공개, 추론 스택 호환성을 담은 한 페이지짜리 추천서. 마지막에 "모니터링할 것" 문단으로 끝내며, 첫 1만 건의 프로덕션 요청 안에서 추천을 검증해 줄 구체적인 롱컨텍스트 평가(RULER, LongBench, needle-in-haystack)를 지목합니다.
