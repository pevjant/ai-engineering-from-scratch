# Jamba — SSM-트랜스포머 하이브리드

> 상태 공간 모델(SSM)과 트랜스포머는 원하는 것이 다릅니다. 트랜스포머는 어텐션으로 품질을 사지만 2차(제곱) 비용을 치릅니다. SSM은 순환 구조를 통해 선형 시간 추론과 고정 메모리를 얻지만 품질이 뒤처집니다. AI21의 Jamba(2024년 3월)와 Jamba 1.5(2024년 8월)는 이 둘을 한 모델에 넣었습니다. Mamba 레이어 7개마다 트랜스포머 레이어 1개, 블록마다 건너서 MoE, 그리고 80GB GPU 한 장에 들어가는 256k 컨텍스트 윈도우입니다. Mamba-3(ICLR 2026)는 복소수 값 상태 공간과 MIMO 프로젝션으로 SSM 쪽을 한층 다듬었습니다. 이 레슨에서는 두 아키텍처를 처음부터 끝까지 읽고, 순수 SSM 시도도 순수 트랜스포머 롱컨텍스트 시도도 버티지 못한 3년 동안 하이브리드 레시피는 왜 살아남았는지 설명합니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, 레이어 배합 계산기)
**선수 지식:** 페이즈 10 · 14 (오픈 모델 아키텍처), 페이즈 10 · 17 (네이티브 스파스 어텐션)
**시간:** 약 60분

## 학습 목표

- Jamba 블록의 세 가지 기본 요소 — 트랜스포머 레이어, Mamba 레이어, MoE — 와 1:7:짝수 인터리빙(교차 배치) 레시피를 설명할 수 있다.
- SSM의 순환 구조가 고수준에서 어떤 모습인지, 그리고 왜 고정 메모리 추론을 가능하게 하는지 말할 수 있다.
- 256k 컨텍스트에서 Jamba 모델의 KV 캐시 크기를 계산하고, 순수 트랜스포머가 감당해야 할 크기와 비교할 수 있다.
- Mamba-3의 세 가지 혁신(지수 사다리꼴 이산화, 복소수 값 상태 갱신, MIMO)과 각각이 겨냥하는 문제를 꼽을 수 있다.

## 문제 상황

어텐션은 시퀀스 길이에 대해 2차(quadratic)입니다. 상태 공간 모델은 선형입니다. 이 차이는 누적됩니다. 256k 토큰에서 트랜스포머 어텐션 맵은 헤드당 65B개 항목이지만, SSM의 순환 상태는 시퀀스 길이와 무관하게 고정 크기입니다.

순수 SSM 모델(Mamba, Mamba-2)은 작은 규모에서는 트랜스포머 퍼플렉서티를 따라잡지만, 상태 추적(state-tracking) 작업에서는 뒤처지고 일부 종류의 인컨텍스트 검색에서는 실패합니다. 직관적인 이유는 이렇습니다. SSM은 역사를 고정된 상태로 압축하는데, 역사가 길어지면 정보가 새어 나갑니다. 어텐션은 모든 것을 정확히 기억하지만 2차 비용을 치릅니다.

뻔한 해법: 둘 다 쓰기. 정확한 회상(recall)이 중요한 곳에는 트랜스포머 레이어를 배치하고, 나머지에는 SSM 레이어를 씁니다. 비율을 조정합니다. Jamba는 이 하이브리드 레시피를 대규모로 출시한 최초의 프로덕션(운영 환경)급 모델입니다(총 52B, 활성 12B, 256k 컨텍스트, 80GB GPU 한 장). Jamba 1.5는 이 계열을 총 398B / 활성 94B까지 확장했습니다. Mamba-3(ICLR 2026)는 하이브리드가 다시 세워질 수 있는 현재 최고의 순수 SSM 베이스라인입니다.

이 레슨은 세 논문을 모두 읽고 "올바른 비율 고르기"에 대한 멘탈 모델을 만들어 줍니다.

## 개념

### 한 페이지로 보는 SSM

상태 공간 모델은 고정 크기 상태 `h`로 시퀀스 `x_1, ..., x_N`을 처리합니다:

```
h_t = A h_{t-1} + B x_t
y_t = C h_t
```

각 단계에서 상태는 선형 동역학 `A`에 따라 변하고, 입력 `B x_t`를 받아 출력 `C h_t`를 내보냅니다. `A, B, C`는 학습할 수 있습니다. 결정적인 성질에 주목하세요. `y_t`를 계산하는 데는 `h_{t-1}`과 `x_t`만 필요하고, 더 이전의 `x`는 필요 없습니다. 메모리는 일정합니다. 토큰당 추론은 O(1)입니다.

모델링 품질의 관건은 `A`의 구조입니다. S4(Gu 2021)는 학습 중에 긴 합성곱으로 효율적으로 계산할 수 있는 고도로 구조화된 행렬을 사용했습니다. Mamba(Gu, Dao 2023)는 고정된 `A, B, C`를 데이터에 의존하는 값으로 바꿨습니다("선택적(selective)" 부분). Mamba-2(2024)는 구조를 더 단순화했습니다. Mamba-3(2026)는 특정 지점에 복잡성을 다시 더합니다.

핵심 성질: 디코더 LLM에서 SSM 레이어는 어텐션 레이어의 갈아 끼우기(drop-in) 대체재입니다. 늘어나는 KV 캐시 대신 레이어당 고정 크기 상태를 씁니다.

### Jamba 블록

Jamba 블록은 두 숫자에 따라 레이어를 섞습니다:

- `l`: 어텐션 대 Mamba 비율. Jamba는 `l = 8`을 사용합니다. 즉 Mamba 레이어 7개마다 트랜스포머 레이어 1개입니다(그룹당 Mamba 7 + 어텐션 1 = 8레이어).
- `e`: MoE 빈도. Jamba는 `e = 2`를 사용합니다. 즉 한 레이어 걸러 한 레이어에 MoE를 적용합니다.

블록 안의 레이어 순서:

```
M  M  M  M  M  M  M  A    (Mamba 7 + Attention 1)
|  M  |  M  |  M  |  M    (|는 MoE가 적용되는 위치)
```

각 Jamba 블록은 8레이어입니다. 4블록 깊이(총 32레이어)에서 Mamba 28개와 어텐션 4개가 나옵니다. 이 중 16개는 MoE를 사용합니다.

### 1:7 비율인 이유

AI21은 어블레이션(제거 실험)을 돌려봤습니다. 어텐션 대 Mamba 비율이 얼마일 때 파라미터당 퍼플렉서티와 롱컨텍스트 평가에서의 인컨텍스트 회상이 모두 가장 좋을까요?

- 어텐션이 너무 많으면(1:1): 품질은 올라가지만 메모리와 속도가 나빠집니다.
- 어텐션이 너무 적으면(1:15): 메모리는 훌륭하지만 인컨텍스트 검색이 실패합니다.
- 스위트 스팟: 1:7 또는 1:8.

직관적인 이유: 트랜스포머 레이어가 정확한 회상과 상태 추적을 맡고, Mamba 레이어가 값싼 대량 처리를 맡습니다.

### 위치 인코딩

Mamba 레이어는 그 자체로 위치를 인지합니다(순환 구조 덕분입니다). 원래 Mamba 기반 하이브리드의 어텐션 레이어는 RoPE를 쓰지 않았습니다. SSM 레이어가 위치 정보를 제공했기 때문입니다. Jamba 1.5는 더 긴 컨텍스트 일반화를 위해 어텐션 레이어에 RoPE를 추가했는데, 이는 경험적 롱컨텍스트 평가에 기반한 사후 보완입니다.

### 메모리 예산

Jamba-1 형태(32레이어: Mamba 28 + 어텐션 4, 은닉 4096, 어텐션 헤드 32)의 경우:

- KV 캐시(어텐션 레이어만): 256k BF16 기준 `2 * 4 * 32 * 128 * 256k * 2 = 8.4 GB`. 어텐션 4레이어만 기여합니다.
- SSM 상태: 토큰 접두사당 `28 * hidden * state_size`이지만, 이는 레이어당 고정 크기이고 시퀀스 길이에 따라 늘지 않습니다. 전형적인 Mamba 상태는 특성당 16, 은닉 4096이면 합계 `28 * 4096 * 16 * 2 = 3.7 MB`입니다.

같은 은닉 크기에 32헤드 풀 MHA를 쓰는 32레이어 순수 트랜스포머와 비교해 보면: 256k BF16 기준 `2 * 32 * 32 * 128 * 256k * 2 = 128 GB`. KV 캐시가 8배 줄어듭니다. 2024년 모델 대부분이 쓰는 GQA(8) 베이스라인(`2 * 32 * 8 * 128 * 256k * 2 = 32 GB`)과 비교해도, Jamba의 1:7 하이브리드는 16 GB로 여전히 2배 작습니다.

이것이 AI21이 말하는 "80GB GPU 한 장에서 256k 컨텍스트"입니다. 풀 MHA 순수 트랜스포머의 KV 캐시는 아예 들어가지 않고, GQA 베이스라인조차 가중치와 활성값을 담을 자리가 남지 않습니다. Jamba는 들어갑니다.

### Mamba-3: 2026년의 순수 SSM 베이스라인

Mamba-3(ICLR 2026, arXiv:2603.15569)는 순수 SSM 쪽에 세 가지 혁신을 도입합니다:

1. **지수 사다리꼴 이산화(exponential-trapezoidal discretization).** Mamba-2의 오일러 방식 이산화를 더 표현력 있는 순환 구조로 교체합니다. `x_t`에 대한 외곽 합성곱이 아니라, 핵심 순환 안에서 상태-입력에 합성곱 비슷한 연산을 적용합니다.

2. **복소수 값 상태 갱신.** 이전 Mamba들은 상태 행렬을 복소수(S4)에서 실수 대각(Mamba)으로, 다시 스케일된 항등행렬(Mamba-2)로 줄여 왔습니다. Mamba-3는 복소수 값을 다시 더합니다. 이는 상태에 대한 데이터 의존형 회전 임베딩(rotary embedding)과 동등합니다. 이전의 실수 값 단순화가 잃어버린 상태 추적 능력을 되찾아 줍니다.

3. **다중 입력 다중 출력(MIMO) 프로젝션.** 특성별 스칼라 프로젝션 대신 행렬 값 프로젝션을 사용합니다. 디코드 지연 시간을 늘리지 않으면서 모델링 능력과 추론 시 하드웨어 활용률을 높입니다.

1.5B 파라미터에서 Mamba-3는 Gated DeltaNet 대비 평균 다운스트림 정확도를 0.6포인트 끌어올립니다. MIMO 변형은 여기에 1.2포인트를 더해 총 1.8포인트의 이득입니다. 같은 상태 크기에서 Mamba-3는 Mamba-2를 절반의 상태로 따라잡습니다.

Mamba-3는 아직 대규모 프로덕션 하이브리드에 탑재되지는 않았습니다. 하지만 다음 Jamba급 모델의 SSM 쪽 후보로는 가장 유력한 존재입니다.

### 하이브리드가 필요한 순간

하이브리드가 이기는 경우:

- 컨텍스트가 길어서 순수 트랜스포머의 KV 캐시가 부담스러울 때(64k 이상).
- 작업이 짧은 범위 구조(SSM에 유리)와 긴 범위 회상(트랜스포머 필요)을 섞고 있을 때.
- 트랜스포머 KV 캐시만으로도 메모리가 부족한 단일 GPU 예산에 배포해야 할 때.

하이브리드가 지는 경우:

- 컨텍스트가 짧을 때(16k 미만). SSM 오버헤드가 낭비됩니다. 순수 트랜스포머면 충분합니다.
- 작업이 모든 곳에서 모든 곳으로의 어텐션을 필요로 할 때(깊은 추론, 다중 문서 교차 참조). 하이브리드의 어텐션 레이어 희소성이 발목을 잡습니다.
- 조 단위(trillion) 파라미터 프론티어 모델로 확장할 때. 순수 트랜스포머 + MLA + MoE(DeepSeek-V3 스타일)가 현재 능력 경쟁에서 앞서고 있습니다.

### 경쟁 구도

| 모델 | 계열 | 규모 | 고유 주장 |
|-------|--------|------|-------------|
| Mamba-2 | 순수 SSM | 3B | 선형 시간, 고정 메모리 |
| Jamba | 하이브리드 | 52B/12B | 80GB에서 256k |
| Jamba 1.5 Large | 하이브리드 | 398B/94B | 엔터프라이즈급 롱컨텍스트 |
| Mamba-3 | 순수 SSM | 1.5B (논문) | 상태 추적 회복 |
| DeepSeek-V3 | 순수 트랜스포머 + MoE | 671B/37B | 프론티어급 능력 |

2026년의 구도: 순수 트랜스포머 MoE가 프론티어를 지배하지만, 256k 이상 컨텍스트라는 틈새시장은 하이브리드의 영토입니다. Mamba-3의 상태 추적 성과는 다음 세대에서 하이브리드 비율을 낮추는(SSM을 늘리고 어텐션을 줄이는) 밀대가 될 수 있습니다.

## 사용해 보기

`code/main.py`는 하이브리드 아키텍처용 메모리 계산기입니다. SSM-트랜스포머 비율과 은닉 크기/레이어 수 설정이 주어지면 다음을 계산합니다:

- 목표 컨텍스트에서의 KV 캐시.
- SSM 상태 메모리.
- 다양한 모델 형태에 대한 컨텍스트 N에서의 총 메모리.

계산기가 지원하는 형태:

- 순수 트랜스포머 베이스라인(KV 캐시가 N에 비례해 증가).
- Jamba 스타일 1:7 하이브리드.
- 순수 SSM(KV 캐시 없음).

공개된 형태에 대한 숫자는 Jamba-1과 Jamba-1.5 논문에서 그대로 가져왔고, 가상 변형에 대해서는 외삽(extrapolation)한 값입니다.

실제 배포를 위한 통합 고려사항:

- 대부분의 프로덕션 추론 서버(vLLM, SGLang)는 Jamba와 Mamba를 지원합니다. 구체적인 버전을 확인하세요.
- 256k 컨텍스트에서는 Jamba의 메모리 이점이 동시 요청 처리량으로 나타납니다. 같은 VRAM에서 트랜스포머 시퀀스보다 더 많은 Jamba 시퀀스를 담을 수 있습니다.
- 단독 모델로서의 Mamba-3는 아직 프로덕션에 배포되지 않았습니다. 1.5B 연구 프리뷰 단계입니다.

## 연습 문제

1. `code/main.py`를 실행해 32레이어 순수 트랜스포머(은닉 4096, 헤드 32)와 같은 형태의 Jamba-1 하이브리드에 대한 256k 컨텍스트 KV 캐시를 계산하세요. AI21 논문이 주장하는 약 8배 메모리 감소를 검증해 보세요.

2. 계산기를 수정해 1:3 하이브리드(Mamba 4 : 어텐션 1)와 1:15 하이브리드(Mamba 14 : 어텐션 1)를 모델링해 보세요. 비율에 따른 KV 캐시를 그래프로 그려보세요. 어느 비율에서 KV 캐시가 SSM 상태 메모리와 같아지나요?

3. Jamba 논문(arXiv:2403.19887)의 3장을 읽으세요. Mamba-2가 더 빠른데도 AI21이 Mamba-1을 쓰는 이유를 설명해 보세요. 힌트: 하이브리드 어블레이션 섹션에 이 내용이 기록되어 있습니다.

4. Jamba 1.5 Large(총 398B, 활성 94B)에서 레이어마다 건너서 MoE를 두는 방식의 파라미터 오버헤드를 계산하세요. 활성 비율을 DeepSeek-V3(37B/671B)와 비교하고, Jamba 아키텍처가 활성 비율을 더 높게 만드는 이유를 설명해 보세요.

5. Mamba-3 논문(arXiv:2603.15569)의 3장을 읽으세요. 복소수 값 상태 갱신이 데이터 의존형 회전 임베딩과 동등한 이유를 세 문장으로 설명하고, 답을 페이즈 7 · 레슨 04의 RoPE 유도와 연결해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| State space model (SSM) | "고정 상태를 가진 순환 구조" | 학습된 순환 `h_t = A h_{t-1} + B x_t`를 사용하는 레이어. 토큰당 고정 메모리 |
| Selective SSM | "Mamba의 비결" | 데이터에 따라 달라지는 A, B, C 파라미터로 선형 시간에 게이팅 비슷한 선택성을 부여 |
| Attention-to-Mamba ratio | "어텐션 레이어가 몇 개인지" | Jamba에서 `l = 8`은 Mamba 레이어 7개당 어텐션 레이어 1개라는 뜻 |
| Jamba block | "8레이어 그룹" | 어텐션 1 + Mamba 7 + 짝수 위치마다 MoE |
| SSM state | "숨겨진 버퍼" | Mamba 레이어에서 KV 캐시를 대체하는 레이어당 고정 크기 상태 |
| 256k context | "Jamba의 간판 숫자" | Jamba-1이 80GB GPU 한 장에 담아내는 시퀀스 길이. 같은 크기의 순수 트랜스포머는 불가능 |
| Mamba-3 | "2026년의 순수 SSM" | 복소수 상태 + MIMO를 갖춘 현재 최고의 순수 SSM 아키텍처. 하이브리드가 다시 세우는 기준점 |
| MIMO | "다중 입력 다중 출력" | 특성별 스칼라 대신 행렬 값을 쓰는 Mamba-3 혁신 |
| Exponential-trapezoidal discretization | "Mamba-3의 순환 구조" | Mamba-2의 오일러 방식 이산화를 포섭하는 더 표현력 있는 순환 구조 |
| Hybrid architecture | "어텐션과 SSM을 섞은 것" | 트랜스포머와 SSM 레이어를 교차 배치하는 모델. Jamba가 프로덕션 원형(archetype) |
