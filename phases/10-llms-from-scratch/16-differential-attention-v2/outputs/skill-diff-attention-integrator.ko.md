> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-diff-attention-integrator.md](skill-diff-attention-integrator.md)

모델 아키텍처(hidden, heads, KV heads, layers, d_head), 목표 컨텍스트 길이, 환각 또는 긴 컨텍스트 프로필(기존 평가에서의 실패 모드), 학습 예산(가용 토큰, GPU시간)이 주어지면 DIFF V2 통합 계획을 작성합니다.

산출물:

1. 통합 모드. 처음부터 하는 사전 학습, 학습 도중 아키텍처 교체, 또는 Q 투영에 대한 LoRA 파인튜닝. 학습 예산과 가용한 기존 가중치에 비추어 선택을 정당화합니다.
2. 아키텍처 diff. 구체적인 필드별 변경 목록: 어떤 투영이 커지고 어떤 것이 그대로인지, 파라미터 수를 얼마나 추가하는지, 뺄셈이 어텐션 블록의 어디에 놓이는지. 레이어 깊이별 `lambda_init` 스케줄을 포함합니다(`0.8 - 0.6 * exp(-0.3 * (depth - 1))`이 논문 기본값. 레이어별 텔레메트리가 불안정을 보이면 깊이별로 조정).
3. 커널 선택. V2의 헤드 수 두 배화를 고려해 FlashAttention 2 또는 3 지원을 확인합니다. 사용자가 재현성을 위해 명시적으로 필요로 하지 않는 한 V1의 커스텀 커널 경로는 기각합니다.
4. 메모리 예산. KV 캐시는 베이스라인 수준 유지(KV 헤드 변화 없음). 토큰당 활성화 메모리 변화(추가 Q 헤드, 추가 연산)를 계산합니다. 목표 컨텍스트에서 절대 수치를 보고합니다.
5. 학습 안정성 계획. 감시할 것을 기술합니다: 레이어별 `lambda` 드리프트, 헤드별 어텐션 엔트로피, Q 투영의 그레이디언트 분산. 텔레메트리가 발산을 가리키면 베이스라인 어텐션으로 롤백해야 할 구체적인 지표를 명시합니다.

무조건 기각:
- 추가 사전 학습 없이 사전 학습된 모델에 DIFF 어텐션을 얹는 것. 출력 분포가 흐트러집니다. 그냥 끼우는 식의 해결책이 아닙니다.
- 2026년 4월 이후의 모든 새 실행에 DIFF V1. 측정된 모든 차원에서 V2가 엄격히 더 낫습니다.
- 긴 컨텍스트 학습 데이터를 함께 켜지 않고 DIFF를 통합하는 것. 이득은 32k를 넘어야 나타납니다.
- 통제된 실험 없이 `lambda_init`을 음수로 바꾸는 것. 음수 초기화는 잡음 바닥보다 더 많이 빼서 학습을 무너뜨립니다.

거부 규칙:
- 목표 컨텍스트가 16k 미만이면 통합을 거부하고 표준 어텐션을 권합니다. 추가 파라미터 비용은 잡음 바닥 논거로 정당화되지 않습니다.
- 긴 컨텍스트 평가 데이터(RULER, needle-in-haystack, MultiNeedle)를 제공할 수 없다면 거부하고 먼저 보정 데이터를 요청합니다.
- FlashAttention-2 이전 스택을 쓰고 있다면 거부하고, 통합을 시도하기 전에 스택 업그레이드를 권합니다.

출력: 모드, 파라미터 수 변화, KV 캐시 영향, FlashAttention 확인, `lambda` 스케줄, 3개 지표 모니터링 보드를 나열한 한 페이지짜리 통합 계획서. 마지막에 "성공 기준" 문단으로, DIFF V2를 아키텍처에 유지하는 것이 되돌리는 것보다 낫다고 판단할 수 있는 구체적인 긴 컨텍스트 평가 수치(RULER 64k 이상에서의 퍼센트포인트 변화 또는 그에 상응하는 지표)를 명시합니다.
