# 차등 어텐션(V2)

> 소프트맥스 어텐션은 맞지 않는 토큰마다 조금씩 확률을 흩뿌립니다. 10만 토큰 규모에서는 이 잡음이 쌓여 신호를 파묻습니다. Differential Transformer(Ye et al., ICLR 2025)는 어텐션을 두 소프트맥스의 차로 계산해 공유되는 잡음 바닥(noise floor)을 빼 버리는 방식으로 이것을 고칩니다. DIFF V2(Microsoft, 2026년 1월)는 프로덕션(운영 환경) 스택에 맞게 다시 쓴 버전입니다. 디코드 지연 시간을 베이스라인 트랜스포머에 맞추고, 커스텀 커널이 없으며, FlashAttention과 호환됩니다. 이 레슨은 V1부터 V2까지 엔드투엔드로 다루며, 표준 라이브러리 Python으로 돌릴 수 있는 동작하는 장난감(toy) 구현으로 차 연산을 만들어 봅니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 7 · 02 (셀프 어텐션), 페이즈 7 · 15 (어텐션 변형), 페이즈 10 · 14 (아키텍처 둘러보기)
**시간:** 약 60분

## 학습 목표

- 소프트맥스 어텐션에 잡음 바닥이 존재하는 이유와, 그것이 컨텍스트 길이에 따라 커지는 이유를 정확히 서술합니다
- 차등 어텐션 공식을 유도하고, 뺄셈이 신호를 지키면서 공유 잡음 성분을 상쇄하는 이유를 설명합니다
- V1에서 V2로의 diff를 따라갑니다. 무엇이 빨라지고, 무엇이 단순해지고, 무엇이 안정해졌는지, 그리고 각 변경이 프로덕션 사전 학습에 왜 필요했는지입니다
- 순수 Python으로 차등 어텐션을 직접 구현하고, 합성 신호+잡음 질의에서 잡음 상쇄 특성을 경험적으로 검증합니다

## 문제

표준 소프트맥스 어텐션에는 규모가 커지면 운영상의 골칫거리가 되는 수학적 성질이 있습니다. 질의(query) `q`에 대한 어텐션 가중치는 `softmax(qK^T / sqrt(d))`입니다. 소프트맥스는 정확한 0을 만들어 내지 못합니다. 맞지 않는 토큰마다 양수 확률 질량을 조금씩 얻습니다. 이 잔여 질량이 잡음이고, 컨텍스트 길이에 비례해 커집니다. 128k 토큰에서는 맞지 않는 토큰 하나가 확률의 0.001%만 받더라도 127,999개가 합쳐지면 전체의 약 12%를 차지합니다. 모델은 컨텍스트와 함께 커지는 잡음 바닥을 우회하는 법을 배워야만 합니다.

경험적으로 이것은 어텐션 헤드 간섭으로 나타납니다. 긴 컨텍스트 RAG(검색 증강 생성)에서 환각된 인용, 10만 토큰 검색 과제에서의 lost-in-the-middle 실패, 32k를 넘는 바늘 건초 더미(needle-in-haystack) 벤치마크에서의 미세한 정확도 하락이죠. Differential Transformer 논문(arXiv:2410.05258, ICLR 2025)은 이 격차를 측정했습니다. DIFF 트랜스포머는 같은 크기 베이스라인보다 낮은 퍼플렉시티, 더 높은 긴 컨텍스트 정확도, 더 적은 환각을 기록했습니다.

DIFF V1에는 최전선 사전 학습 파이프라인에서 배제된 세 가지 문제가 있었습니다. 값 캐시(value cache)를 디코드 스텝마다 두 번 읽어야 했고, FlashAttention 호환성을 깨는 커스텀 CUDA 커널이 필요했고, 헤드별 RMSNorm이 70B 이상 규모의 장기 학습을 불안정하게 만들었습니다. DIFF V2(Microsoft unilm 블로그, 2026년 1월 20일)는 이 세 가지를 모두 고쳤습니다. 이 레슨은 두 버전을 모두 따라가고, 차 연산자를 만들고, 장난감 질의에서 잡음 상쇄를 벤치마크합니다.

## 개념

### 소프트맥스의 잡음 바닥

질의 `q`와 키 `K = [k_1, ..., k_N]`에 대해 어텐션 가중치는:

```
w_i = exp(q . k_i / sqrt(d)) / sum_j exp(q . k_j / sqrt(d))
```

어떤 `w_i`도 0이 되지 않습니다. `k_i`가 `q`와 완전히 무관하더라도 점수 `q . k_i`는 0이 아닙니다. 분산 `||q||^2 / d`로 0 주변을 요동칩니다. 소프트맥스 정규화를 거친 뒤에도 무관한 토큰 하나는 가중 합에 여전히 `O(1/N)`을 기여합니다. 무관한 토큰 전체의 기여는 `O((N-1)/N) = O(1)`로, 작은 양이 아닙니다.

모델이 원하는 것은 하드 top-k 비슷한 것입니다. 맞는 토큰에는 높은 가중치, 그 외에는 거의 0. 소프트맥스는 너무 매끄러워서 이것을 직접 해내지 못합니다.

### 차등의 발상

각 헤드의 Q, K 투영을 둘로 쪼갭니다: Q = (Q_1, Q_2), K = (K_1, K_2). 어텐션 맵 두 개를 계산합니다:

```
A_1 = softmax(Q_1 K_1^T / sqrt(d))
A_2 = softmax(Q_2 K_2^T / sqrt(d))
```

출력:

```
DiffAttn = (A_1 - lambda * A_2) V
```

뺄셈은 두 맵이 공유하는 잡음 분포를 상쇄합니다. 두 맵이 12.7만 개의 무관한 토큰에 거의 균일한 가중치를 갖는다면(무작위 초기화에서 실제로 그렇습니다) 그것들은 서로 지워집니다. 신호, 즉 실제로 관련 있는 몇몇 토큰에 쏠린 가중치는 두 맵에 같은 크기로 나타나야만 지워지는데, 모델이 학습을 시작하고 나면 그렇게 되지 않습니다.

`lambda`는 헤드별 학습 가능한 스칼라로, `lambda = exp(lambda_q1 dot lambda_k1) - exp(lambda_q2 dot lambda_k2) + lambda_init`로 매개변수화됩니다. 음수가 될 수 있습니다. `lambda_init`의 기본값은 0.8 같은 작은 양수입니다.

### 헤드폰 노이즈 캔슬링과 같은 원리인 이유

같은 목소리를 녹음하는 잡음 섞인 마이크 두 개를 떠올려 보세요. 둘 다 화자 목소리에 상관된 배경 잡음을 더해 담습니다. 하나에서 다른 하나를 빼면 공유 잡음은 사라집니다. 목소리는 살아남는데, 두 신호가 위상이나 진폭에서 충분히 달라 완전 상쇄를 막기 때문입니다. 헤드별 `lambda`가 정확히 이 균형을 학습합니다.

### V1 대 V2: diff

V1은 파라미터 수를 베이스라인 트랜스포머와 동일하게 유지했습니다. 헤드당 두 개의 쿼리를 얻으려고 헤드 차원을 절반으로 줄였죠. 이것은 헤드 표현력을 희생시켰고, 더 아픈 것은 헤드당 값 캐시를 절반으로 만들었다는 점입니다. 디코드는 스텝마다 값 캐시를 두 번(소프트맥스 가지마다 한 번) 읽어야 했습니다. 결과: 파라미터 수는 같은데 디코드는 베이스라인보다 느립니다.

V2는 쿼리 헤드 수를 두 배로 늘리고 KV 헤드는 그대로 둡니다(up-projection에서 파라미터를 빌려 옵니다). 헤드 차원은 베이스라인과 같습니다. 뺄셈 후에는 여분의 차원을 다시 줄여 베이스라인 트랜스포머의 O_W 투영에 맞춥니다. 세 가지가 동시에 일어납니다:

1. 디코드 속도가 베이스라인과 같아집니다(KV 캐시를 한 번만 읽습니다).
2. FlashAttention이 수정 없이 그대로 돌아갑니다(커스텀 커널 없음).
3. 디코드 시 산술 강도가 올라갑니다(HBM에서 읽는 바이트당 더 많은 연산).

V2는 또한 V1이 뺄셈을 안정시키려고 쓴 헤드별 RMSNorm을 제거합니다. 70B급 사전 학습 규모에서 그 RMSNorm은 학습 후반부를 불안정하게 만들었습니다. V2는 더 단순한 초기화 방식으로 바꿔, 별도 모듈 없이도 학습을 안정적으로 유지합니다.

## 만들어 보기

`code/main.py`는 순수 Python으로 차등 어텐션을 구현합니다. 신호+잡음 구조를 알고 있는 장난감 질의로 잡음 상쇄 비율을 직접 측정할 수 있습니다.

### 단계 1: 표준 소프트맥스 어텐션

표준 라이브러리 행렬 연산: 리스트의 리스트, 수동 행렬 곱, 수치 안정성을 위한 최댓값 뺄셈이 들어간 소프트맥스.

```python
def softmax(row):
    m = max(row)
    exps = [math.exp(x - m) for x in row]
    s = sum(exps)
    return [e / s for e in exps]
```

### 단계 2: Q, K를 두 조각으로 나누기

V1 방식: 헤드 차원을 절반으로. V2 방식: 헤드 차원은 유지하고 헤드 수를 두 배로. 장난감 구현은 교육적 명료함을 위해 V1을 씁니다. 수학은 동일하고 장부 기록 방식만 다릅니다.

### 단계 3: 두 소프트맥스 가지 + 뺄셈

```python
A1 = [softmax([dot(q1, k) / scale for k in K1]) for q1 in Q1]
A2 = [softmax([dot(q2, k) / scale for k in K2]) for q2 in Q2]
diff_weights = [[a1 - lam * a2 for a1, a2 in zip(r1, r2)] for r1, r2 in zip(A1, A2)]
out = [[sum(w * v[j] for w, v in zip(row, V)) for j in range(d_v)] for row in diff_weights]
```

참고: 출력 가중치는 음수가 될 수 있습니다. 괜찮습니다. 값 캐시는 부호 있는 기여를 그대로 처리하고, 이어지는 V 투영이 부호를 흡수합니다.

### 단계 4: 잡음 상쇄 측정

길이 1024짜리 합성 시퀀스를 만듭니다. 신호 토큰을 알려진 위치에 놓고 나머지는 잡음으로 채웁니다. (a) 신호 위치의 표준 소프트맥스 어텐션 가중치와 (b) 차등 어텐션 가중치를 계산합니다. 각각의 신호 대 잡음 비율을 측정합니다. DIFF 어텐션은 두 가지가 얼마나 다르도록 학습됐는지에 따라 3배~10배 높은 신호 대 잡음 비율을 안정적으로 냅니다.

### 단계 5: V1 대 V2 파라미터 장부

설정(hidden=4096, heads=32, d_head=128)이 주어지면 다음을 출력합니다:

- 베이스라인 트랜스포머: Q, K, V 각각 `hidden * hidden`, MLP는 `4 * hidden`.
- DIFF V1: Q, K 각각 `hidden * hidden`, V는 `hidden * hidden`(변화 없음), 헤드 차원은 내부적으로 절반. 헤드별 `lambda` 파라미터 추가(O(heads * d_head)).
- DIFF V2: Q는 `2 * hidden * hidden`, K는 `hidden * hidden`, V는 `hidden * hidden`. 여분 차원은 O_W 전에 다시 축소. 동일한 `lambda` 파라미터 추가.

장난감 구현은 V2의 추가 파라미터 비용(어텐션 블록당 대략 `hidden * hidden` 추가)을 측정해 출력합니다.

## 사용해 보기

2026년 4월 기준 DIFF V2는 아직 모든 프로덕션 추론 서버에 실리지는 않았지만, vLLM과 SGLang에서 통합이 진행 중입니다. 한편 이 패턴은 다음에서 나타납니다:

- Microsoft 내부의 긴 컨텍스트 프로덕션 모델.
- 256k 이상 컨텍스트를 겨냥한 여러 오픈 모델 학습 실행에서의 연구 재현.
- DIFF 어텐션과 슬라이딩 윈도우 어텐션을 레이어마다 번갈아 결합한 하이브리드 아키텍처.

2026년에 이것을 쓰게 될 경우:

- 64k 이상 실효 컨텍스트를 겨냥해 새 모델을 처음부터 학습할 때. 처음부터 차등 어텐션을 넣으십시오. 나중에 재학습하는 것은 비쌉니다.
- 평가에서 lost-in-the-middle 실패가 지배적인 긴 컨텍스트 모델을 파인튜닝할 때. Q 투영에 LoRA를 얹으면 DIFF 구조를 근사할 수 있습니다.

쓰지 말아야 할 때:

- 긴 컨텍스트 성능이 안정적인 사전 학습 밀집 모델을 서빙 중일 때. 재학습 비용이 기존 가중치에서 회수되는 경우는 드뭅니다.
- 컨텍스트가 항상 16k 미만일 때. 잡음 바닥은 무시할 수준입니다.

## 연습 문제

1. `code/main.py`를 실행해 보세요. 합성 질의에서 차등 어텐션의 신호 대 잡음 비율이 표준 소프트맥스 어텐션보다 높게 보고되는지 확인합니다. 잡음 진폭을 바꿔 가며 표준 어텐션이 쓸모없어지는 교차점을 보여 주세요.

2. 7B급 모델(hidden=4096, heads=32, d_head=128, 32개 레이어)에 대해 베이스라인에서 DIFF V1까지, 베이스라인에서 DIFF V2까지의 파라미터 수 변화를 계산해 보세요. 어떤 구성 요소가 파라미터를 얻고 어떤 것이 그대로인지 보여 주세요.

3. DIFF V1 논문(arXiv:2410.05258)의 3절과 DIFF V2 Hugging Face 블로그의 2절을 읽어 보세요. V1의 헤드별 RMSNorm이 왜 필요했는지, 그리고 V2가 왜 학습 발산 없이 그것을 제거할 수 있었는지 두 문장으로 설명합니다.

4. 소거 실험(ablation)을 구현해 보세요. `lambda = 0`(순수 첫 소프트맥스)과 `lambda = 1`(완전 뺄셈)로 차등 어텐션을 계산합니다. 합성 질의에서 쓸어 보는 동안 신호 대 잡음이 어떻게 변하는지 측정하고, 신호 대 잡음을 최대화하는 `lambda`를 찾아 보세요.

5. 장난감 구현을 GQA + DIFF V2로 확장해 보세요. KV 헤드 8개, Q 헤드 32개로 정합니다. KV 캐시 크기가 같은 (8, 32) 구성의 베이스라인 GQA 모델과 일치함을 보여 주세요.

## 핵심 용어

| 용어 | 사람들이 말하는 방식 | 실제 의미 |
|------|----------------|------------------------|
| 차등 어텐션(Differential attention) | "두 소프트맥스끼리 빼기" | Q, K를 둘로 쪼개 소프트맥스 맵 두 개를 계산하고, 첫째에서 둘째(lambda 스케일)를 뺀 뒤 V를 곱함 |
| 잡음 바닥(Noise floor) | "소프트맥스의 0 아닌 꼬리" | 소프트맥스가 무관한 토큰마다 얹는 O(1/N) 가중치. 긴 컨텍스트에서는 합쳐 O(1)이 됨 |
| lambda | "뺄셈 스케일" | 헤드별 학습 가능 스칼라. `exp(lq1.lk1) - exp(lq2.lk2) + lambda_init`으로 매개변수화. 음수 가능 |
| DIFF V1 | "ICLR 2025 버전" | 원조 Differential Transformer. 파라미터 수를 지키려고 헤드 차원을 절반으로 줄이고, 커스텀 커널이 필요하며, 디코드가 느림 |
| DIFF V2 | "2026년 1월의 수정판" | KV 헤드는 유지한 채 Q 헤드를 두 배로. 베이스라인 디코드 속도에 맞고 FlashAttention과 호환 |
| 헤드별 RMSNorm | "V1의 안정 장치" | V1이 차를 계산한 뒤에 적용한 추가 정규화. V2는 후반 학습 불안정을 막으려고 이것을 제거함 |
| 신호 대 잡음 비율 | "어텐션이 얼마나 낭비되나" | 진짜 신호 위치의 가중치 대 무관한 위치의 평균 가중치 비율 |
| Lost in the middle | "긴 컨텍스트 실패 모드" | 긴 컨텍스트 중간쯤에 있는 문서에 대해 검색 정확도가 떨어지는 경험적 현상 — DIFF 어텐션이 이것을 줄임 |
| 산술 강도(Arithmetic intensity) | "읽은 바이트당 FLOPs" | V2가 KV 로드당 쿼리를 두 배로 늘려 디코드에서 끌어올린 비율. 메모리 병목 디코드에서 중요 |

## 더 읽을거리

- [Ye et al. — Differential Transformer (arXiv:2410.05258, ICLR 2025)](https://arxiv.org/abs/2410.05258) — 잡음 상쇄 이론과 긴 컨텍스트 소거 실험을 담은 원논문
- [Microsoft unilm — Differential Transformer V2 (Hugging Face blog, January 2026)](https://huggingface.co/blog/microsoft/diff-attn-v2) — 프로덕션 스택 재작성. 베이스라인 디코드에 맞추고 FlashAttention 호환
- [Understanding Differential Transformer Unchains Pretrained Self-Attentions (arXiv:2505.16333)](https://arxiv.org/abs/2505.16333) — 뺄셈이 왜 사전 학습된 어텐션 구조를 회복하는지에 대한 이론 분석
- [Shared DIFF Transformer (arXiv:2501.17900)](https://arxiv.org/html/2501.17900) — 파라미터 공유 변형
- [Vaswani et al. — Attention Is All You Need (arXiv:1706.03762)](https://arxiv.org/abs/1706.03762) — DIFF가 빼는 대상인 베이스라인 트랜스포머
- [Liu et al. — Lost in the Middle (arXiv:2307.03172)](https://arxiv.org/abs/2307.03172) — DIFF 어텐션이 겨냥하는 긴 컨텍스트 벤치마크
