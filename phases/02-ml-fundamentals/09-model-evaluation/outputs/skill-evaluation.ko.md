# 모델 평가 전략

어떤 ML 모델이든 올바르게 평가하기 위한 체크리스트입니다. 이 순서를 따르면 가장 흔한 평가 실수를 피할 수 있습니다.

## 단계 1: 데이터를 올바르게 분할하기

- 어떤 전처리(스케일링, 대체, 인코딩)보다 먼저 분할하기
- 분류 작업에는 층화(stratified) 분할 사용하기
- 테스트 세트는 따로 두고, 맨 마지막에 딱 한 번만 만지기
- 작은 데이터셋은 단일 분할 대신 5-폴드 또는 10-폴드 교차 검증 사용하기
- 시계열 데이터는 시간 기반 분할 사용하기 (절대 섞지 않기)

## 단계 2: 올바른 지표 고르기

### 분류

| 상황 | 이 지표 사용 | 이유 |
|-----------|----------------|-----|
| 클래스가 균형 잡혀 있고 단순 비교가 목적 | 정확도 | 해석이 쉽고, 클래스가 균등할 때 의미 있음 |
| 거짓 양성 비용이 큼 (스팸 필터, 사기 경보) | 정밀도 | 표시된 항목 중 실제 양성이 얼마나 되는지 측정 |
| 거짓 음성 비용이 큼 (암 검진, 보안) | 재현율 | 실제 양성 중 몇 개를 잡아내는지 측정 |
| 정밀도와 재현율의 균형이 필요 | F1 점수 | 조화 평균이라 극단적인 불균형에 벌을 줌 |
| 여러 임계값을 통틀어 모델 비교 | AUC-ROC | 임계값에 독립적인 랭킹 품질 |
| 불균형 데이터 | F1, AUC-ROC 또는 PR-AUC | 클래스가 불균형하면 정확도는 기만적 |

### 회귀

| 상황 | 이 지표 사용 | 이유 |
|-----------|----------------|-----|
| 표준 회귀, 이상치가 그리 크지 않음 | RMSE | 타깃과 같은 단위, 큰 오차에 벌을 줌 |
| 이상치에 강건한 평가 | MAE | 모든 오차를 똑같이 다뤄서 이상치가 좌우하지 못함 |
| 스케일이 다른 모델끼리 비교 | R-제곱 | 0~1로 정규화된 척도 (설명된 분산 비율) |
| 비즈니스에서 금액 단위가 필요 | MAE 또는 RMSE | 오차의 크기로 바로 해석 가능 |

## 단계 3: 베이스라인 세우기

모델을 평가하기 전에 베이스라인 성능을 계산하세요:
- 분류: 다수 클래스 예측기 (가장 흔한 클래스만 무조건 예측)
- 회귀: 학습 타깃의 평균만 무조건 예측
- 이 베이스라인조차 못 이기는 모델은 아무것도 배우지 못한 것입니다

## 단계 4: 교차 검증하기

- 안정적인 추정값을 위해 K-폴드(K=5 또는 K=10) 사용
- 분류에는 층화 K-폴드 사용
- 폴드 전체의 평균과 표준편차를 보고
- 평균=0.85, 표준편차=0.02인 모델이 평균=0.87, 표준편차=0.10인 모델보다 더 신뢰할 만함

## 단계 5: 모델을 통계적으로 비교하기

- 유의성을 확인하지 않은 채 평균 점수가 가장 높은 모델을 고르지 않기
- 교차 검증 폴드를 대상으로 대응 표본 t-검정(paired t-test) 사용
- |t| < 2.78이면 (K=5, df=4, p<0.05 기준) 그 차이는 우연일 수 있음
- 성능 차이가 유의하지 않다면 더 단순한 모델을 고려하기

## 단계 6: 흔한 실수 점검하기

- 데이터 누수: 테스트 데이터 정보가 학습으로 흘러 들어가지 않았나? (분할 전 스케일링, 타깃에서 파생된 특성)
- 클래스 불균형: 정확도가 소수 클래스의 처참한 성능을 가려주고 있지는 않나?
- 과적합: 학습 성능과 검증 성능 사이의 간격이 크지 않나?
- 과도한 평가: 테스트 세트를 두 번 이상 들여다보지 않았나?

## 단계 7: 최종 성능 보고하기

- 학습 세트 + 검증 세트를 합쳐서 학습하기
- 따로 둔 테스트 세트에서 정확히 한 번만 평가하기
- 가능하다면 선택한 지표를 신뢰 구간과 함께 보고하기
- 베이스라인과의 비교도 밝히기 (무작위/평균 대비 얼마나 나은지)
