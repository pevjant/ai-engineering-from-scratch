# 앙상블 방법 선택 가이드

앙상블은 여러 모델을 결합해서 어떤 단일 모델보다도 나은 예측을 만들어 냅니다. 늘 묻게 되는 질문은: 어떤 종류의 앙상블을, 언제 쓸 것인가?

## 의사 결정 체크리스트

1. 지금 모델의 주된 문제는 무엇인가?
   - 높은 분산 (과적합): 배깅 사용 (랜덤 포레스트)
   - 높은 편향 (과소적합): 부스팅 사용 (그래디언트 부스팅, XGBoost)
   - 둘 다이거나, 최대 정확도를 원함: 스태킹 사용

2. 데이터가 얼마나 있는가?
   - 1,000행 미만: 랜덤 포레스트 (강건하고 잘못 설정하기 어려움)
   - 1,000~100,000행: XGBoost 또는 LightGBM (테이블 데이터 전반에서 최고)
   - 100,000행 초과: LightGBM (가장 빠른 그래디언트 부스팅, 대용량 데이터에 강함)

3. 튜닝에 시간을 얼마나 쓸 수 있는가?
   - 최소한으로: 기본값 랜덤 포레스트 (거의 항상 통함)
   - 중간 정도: learning_rate=0.1인 XGBoost, 조기 종료로 n_estimators 튜닝
   - 최대한으로: 베이지안 하이퍼파라미터 탐색을 곁들인 LightGBM 또는 XGBoost

4. 해석 가능성이 필요한가?
   - 필요함: 단일 결정 트리, 또는 특성 중요도를 제공하는 소형 랜덤 포레스트
   - 부분적으로: SHAP 값을 곁들인 그래디언트 부스팅
   - 불필요: 스태킹 또는 딥 앙상블

5. 데이터가 이상치를 많이 품은 잡음인가?
   - 그렇다: 랜덤 포레스트 (배깅은 잡음에 강건함)
   - 아니다: 그래디언트 부스팅 (깨끗한 데이터에서는 정확도를 더 끌어올릴 수 있음)

## 각 방법을 언제 쓰나

**랜덤 포레스트(배깅)**: 안전한 첫 번째 선택입니다. 부트스트랩 샘플로 많은 트리를 학습시키고 평균 냅니다. 편향을 늘리지 않고 분산을 줄입니다. 적당한 크기의 데이터에서는 과적합하기 거의 불가능합니다. 튜닝은 최소로: n_estimators=100-500만 정하고 나머지는 기본값으로 두세요.

**AdaBoost**: 샘플 가중치 재조정으로 하는 순차적 부스팅입니다. 단순한 베이스 학습기(결정 스텀프)와 잘 맞습니다. 잘못 분류된 점에 가중치를 더 주기 때문에 이상치와 잡음 레이블에 민감합니다. 실전에서는 대체로 그래디언트 부스팅으로 밀려났습니다.

**그래디언트 부스팅**: 각 새 트리를 지금까지의 앙상블의 잔차에 적합시킵니다. 편향을 줄입니다. 테이블 데이터에서 가장 강력한 방법입니다. 튜닝이 필요합니다: learning_rate, n_estimators, max_depth, min_child_weight, subsample.

**XGBoost**: 정규화, 2차 최적화, 시스템 수준 속도 향상을 얹은 그래디언트 부스팅입니다. 결측값을 기본으로 처리합니다. Kaggle 대회와 테이블 데이터 프로덕션(운영 환경) ML의 기본값입니다.

**LightGBM**: 리프 단위(leaf-wise) 성장(레벨 단위 대신)을 쓰는 그래디언트 부스팅입니다. 큰 데이터셋에서 XGBoost보다 빠릅니다. 히스토그램 기반 분기를 사용합니다. 5만 행이 넘는 데이터셋에 가장 좋습니다.

**CatBoost**: 범주형 특성을 기본으로 처리하는 그래디언트 부스팅입니다. 원-핫 인코딩이 필요 없습니다. 범주형 특성이 많을 때 좋습니다.

**스태킹**: 다양한 베이스 모델 여러 개의 예측으로 메타 학습기를 학습시킵니다. 절대 최고의 정확도가 필요하고 연산 여력이 있을 때 쓰세요. 누수를 피하려면 베이스 모델 예측은 반드시 교차 검증으로 생성하세요.

**투표**: 가장 단순한 앙상블입니다. 하드 투표(다수결 클래스) 또는 소프트 투표(확률 평균)입니다. 메타 학습기 없이 다양한 모델 2-3개를 빠르게 결합하는 방법입니다.

## 흔한 실수

- 조기 종료 없이 그래디언트 부스팅 사용 (너무 많은 라운드를 돌리면 과적합됨)
- learning_rate를 너무 높게 설정 (0.3을 넘으면 보통 불안정해짐)
- 그래디언트 부스팅의 max_depth를 튜닝하지 않음 (무제한 또는 아주 깊은 트리 기본값은 과적합됨)
- 전부 같은 유형의 모델로 스태킹하기 (다양성이야말로 스태킹의 존재 이유)
- 잡음 섞인 데이터에 AdaBoost 사용 (이상치가 라운드마다 점점 더 높은 가중치를 받음)
- 랜덤 포레스트가 과소적합을 고쳐 주길 기대하기 (분산을 줄이지 편향을 줄이지 않음)

## 방법별 튜닝 우선순위

**랜덤 포레스트:**
1. n_estimators: 100-500 (많을수록 나빠지는 일은 드물고, 그저 느려질 뿐)
2. max_depth: None (트리를 끝까지 자라게) 또는 속도를 위해 10-20으로 제한
3. max_features: 분류는 "sqrt", 회귀는 "log2" 또는 n/3

**XGBoost / LightGBM:**
1. learning_rate: 0.01-0.3 (더 많은 트리를 돌릴 연산이 있다면 낮을수록 좋음)
2. n_estimators: 감으로 정하지 말고 검증 세트에서 조기 종료 사용
3. max_depth: 3-8 (6으로 시작)
4. min_child_weight / min_data_in_leaf: 1-20 (높일수록 과적합을 막음)
5. subsample: 0.7-1.0
6. colsample_bytree: 0.7-1.0
7. reg_alpha (L1)와 reg_lambda (L2): 0-10

## 빠른 참조표

| 방법 | 줄이는 것 | 속도 | 튜닝 노력 | 가장 잘 맞는 곳 |
|--------|---------|-------|--------------|----------|
| 랜덤 포레스트 | 분산 | 빠름 | 낮음 | 잡음 섞인 데이터, 빠른 베이스라인 |
| AdaBoost | 편향 | 빠름 | 낮음 | 단순한 베이스 학습기, 깨끗한 데이터 |
| 그래디언트 부스팅 | 편향 | 중간 | 높음 | 테이블 데이터, 대회 |
| XGBoost | 둘 다 | 빠름 | 높음 | 프로덕션(운영 환경) 테이블 ML |
| LightGBM | 둘 다 | 가장 빠름 | 높음 | 대용량 데이터셋 (5만 행 이상) |
| CatBoost | 둘 다 | 중간 | 중간 | 범주형 특성이 많은 경우 |
| 스태킹 | 둘 다 | 느림 | 높음 | 최대 정확도, 다양한 모델 |
| 투표 | 분산 | 빠름 | 없음 | 모델 2-3개의 빠른 결합 |
