# 특성 선택 전략

올바른 특성 선택 방법을 고르고 적용하기 위한 빠른 참조 자료입니다.

## 단계 1: 청소부터 시작

어떤 방법을 적용하기 전에, 명백히 쓸모없는 특성을 제거하세요:

- **상수 특성**: 분산 = 0. 제거합니다.
- **준상수 특성**: 분산 < 0.01(또는 여러분의 임계값). 제거합니다.
- **중복 특성**: 완전히 동일한 열. 하나만 남기고 나머지는 버립니다.
- **ID 열**: 행마다 고유하며 일반화 가능한 정보가 없습니다. 제거합니다.

이 작업은 몇 초 걸리고, 지저분한 실제 데이터셋에서는 특성의 10-30%를 없애줍니다.

## 단계 2: 상황에 맞는 방법 고르기

### 빠른 의사 결정 트리

1. **특성이 50개 미만인가?** 상호 정보량 순위로 시작하세요. 상위 K개를 남깁니다.
2. **50~500개인가?** 먼저 분산 임계값을 쓰고, 선형 모델이면 L1(라쏘), 트리면 트리 중요도를 씁니다.
3. **500개 초과인가?** 방법을 연결하세요: 분산 임계값 -> 상호 정보량 필터(상위 50%) -> 생존자에 RFE.
4. **해석 가능성이 필요한가?** L1 정규화는 정확한 0/0 아님 구분을 줍니다. 트리 중요도는 순위가 매겨진 점수를 줍니다.
5. **비선형 관계를 잡아야 하는가?** 상호 정보량 또는 트리 기반 중요도. L1(선형 전용)은 피하세요.
6. **특성 상호작용이 필요한가?** RFE 또는 트리 기반 중요도. 필터 방법은 상호작용을 놓칩니다.

### 방법 참조

| 방법 | 언제 사용 | 언제 피함 |
|--------|------------|---------------|
| 분산 임계값 | 항상, 첫 단계로 | 절대 건너뛰지 마세요 |
| 상호 정보량 | 빠른 순위 매기기, 비선형 관계 | 특성 상호작용 탐지가 필요할 때 |
| RFE | 철저한 선택, 중간 규모 특성 수 | 아주 비싼 모델, 특성 1,000개 초과 |
| L1 / 라쏘 | 선형 모델, 빠른 임베디드 선택 | 비선형 문제, 고도로 상관된 특성 |
| 트리 중요도 | 비선형 관계, 특성 상호작용 | 높은 카디널리티 특성에 편향됨 |
| 순열 중요도 | 모델 불문 검증, 최종 확인 | 초기 스크리닝에는 너무 느림 |

## 단계 3: 선택 검증

- 선택한 특성으로 학습한 모델과 전체 특성으로 학습한 모델의 성능을 비교
- 단일 train/test 분할이 아니라 교차 검증 사용
- 성능이 1-2% 이상 떨어지면 유용한 특성을 제거했을 수 있음
- 성능이 좋아진다면 잡음을 성공적으로 제거한 것

## 단계 4: 흔한 함정 다루기

### 상관된 특성
- L1은 상관 그룹에서 임의로 하나를 고르고 나머지는 0으로 만듦
- 먼저 상관 행렬을 계산하고 어떤 상관 특성을 남길지 결정
- 트리 중요도는 상관된 특성들에 중요도를 분산시킴

### 데이터 누수
- 특성 선택은 학습 데이터에만 fit
- 같은 선택을 테스트 데이터에 적용
- 교차 검증에서는 특성 선택이 각 폴드 안에서 일어나야 함

### 특성 선택에 대한 과적합
- 반복이 너무 많은 RFE는 학습 세트에 과적합할 수 있음
- 선택에 쓴 데이터가 아니라 보류 데이터로 검증
- 더 견고한 결과를 위해 안정성 선택(부분표집 반복) 사용

## 단계 5: 프로덕션(운영 환경) 체크리스트

- [ ] 분산 임계값을 첫 필터로 적용함
- [ ] 특성 선택을 학습 데이터에만 fit함
- [ ] 선택된 특성을 문서화함(이름, 사용한 방법, 점수)
- [ ] 성능 비교를 수행함: 선택 특성 vs 전체 특성
- [ ] 단일 분할이 아닌 교차 검증으로 평가함
- [ ] 특성 선택이 학습 파이프라인에 통합됨(수동으로 수행하지 않음)
- [ ] 특성 드리프트 모니터링이 마련되어 있음(선택된 특성은 낡을 수 있음)
