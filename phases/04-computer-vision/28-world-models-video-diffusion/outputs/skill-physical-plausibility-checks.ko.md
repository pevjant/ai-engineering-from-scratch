# 물리적 타당성 검사 (Physical Plausibility Checks)

생성 비디오의 프로덕션(운영 환경) 배포에는 자동화된 가드레일이 필요합니다. 사람이 검수하는 방식은 확장성이 없고, 물리 검사가 고전적인 실패 사례들을 잡아 줍니다.

## 사용 시점

- 텍스트나 이미지 프롬프트로 비디오를 만드는 모든 제품.
- 비디오 생성 API 엔드포인트의 QA 자동화.
- 파인튜닝이나 베이스 모델 업데이트 이후 비디오 모델의 품질 변화(drift) 모니터링.

## 입력

- `video`: `(T, H, W, 3)` 텐서 또는 mp4 경로.
- 선택적 참고 정보: 예상 물체 수, 초기 장면 설명.

## 검사 항목

### 1. 물체 지속성(object permanence)
SAM 3.1 Object Multiplex로 모든 검출을 프레임에 걸쳐 추적한다. 안정적인 트랙이 3프레임 이하 사라졌다가 다시 나타나면 표시한다 — 모델이 그 물체를 잠시 잃어버린 것이다. 프레임 중앙 근처(가장자리가 아님)에서 물체가 사라지면 hard fail, 가장자리에서는 soft fail.

### 2. 움직임 부드러움
연속 프레임 사이의 옵티컬 플로우(optical flow)는 대체로 연속적이어야 한다. 픽셀 단위 플로우가 갑자기 튀면 순간이동이 일어난 것이다. RAFT로 플로우를 계산하고, 99백분위 플로우 크기가 중앙값의 10배를 넘는 프레임을 표시한다.

### 3. 중력 / 지지
단단한 물체(음식, 공, 도구)로 검출된 것은, 들어 올리는 행동이 없는데도 수직 위치가 증가하지 않는지 확인한다. 물체 근처에서 "잡는 손"이 검출되지 않는데 위로 뜨면 표시한다.

### 4. 정체성 일관성
사람이나 캐릭터에는 프레임에 걸쳐 얼굴 인식 임베딩을 사용한다. 지속되는 정체성이라면 5프레임 윈도우에서 코사인 유사도가 0.8보다 높게 유지되어야 한다. 임계값 아래로 떨어지면 캐릭터의 얼굴이 변형(morph)된 것이다.

### 5. 손과 팔다리
포즈 추정기(레슨 21)를 실행한다. 손가락이 보이는 개수가 5개 초과 또는 4개 미만인 프레임, 팔 길이가 프레임 사이에 두 배가 되는 순간, 팔다리가 표면을 뚫고 몸과 교차하는 순간을 표시한다.

### 6. 텍스트 렌더링 (프롬프트가 텍스트를 요구한 경우)
사용자 프롬프트에 따옴표로 묶인 문자열이 있었다면, 생성된 프레임에 OCR을 돌려 요구된 문자열과의 CER(문자 오류율)을 계산한다. CER이 20%를 넘으면 표시한다.

## 보고서

```
[plausibility]
  video frames:           <T>
  permanence violations:  <N>
  smoothness violations:  <N>
  gravity violations:     <N>
  identity drift:         <N of 5-frame windows>
  limb anomalies:         <N>
  OCR CER vs requested:   <float>

[verdict]
  ship | hold | reject

[samples for review]
  frame ranges where each failure occurred
```

## 규칙

- 검사 하나로 무조건 막지 않는다. 점수를 종합하고, 전체 이상 개수가 임계값을 넘으면 검수 보류(hold)로 넘긴다.
- 정체성 드리프트와 물체 지속성 위반에 가장 높은 가중치를 준다 — 사용자가 가장 먼저 눈치채는 문제다.
- 검사별 실패율을 시간 순으로 기록한다. 상승 추세는 보통 베이스 모델이 업데이트됐거나 프롬프트 분포가 바뀌었다는 뜻이다.
- 표시된 비디오를 절대 삭제하지 않는다. 모델 디버깅과 사후 분석을 위해 보관한다.
- 민감한 콘텐츠(사람, 아동, 공인 인물)는 점수와 관계없이 모든 비디오에 사람 검수를 요구한다.
