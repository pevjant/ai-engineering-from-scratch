# 보안 — 시크릿, API 키 로테이션, 감사 로그, 가드레일

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> 중앙화된 볼트(HashiCorp Vault, AWS Secrets Manager, Azure Key Vault)로 시크릿이 널려 있는 상태를 없앱니다. 자격 증명을 설정 파일, VCS에 들어가는 env 파일, 스프레드시트에 저장하는 일은 없어야 합니다. 정적 키보다는 IAM 역할을, CI/CD에는 OIDC를 사용하세요. AI 게이트웨이 패턴이 2026년의 해법입니다. 앱 → 게이트웨이 → 모델 공급자 구조에서 게이트웨이가 실행 시점에 볼트에서 자격 증명을 가져옵니다. 볼트에서 키를 로테이션하면 모든 앱이 몇 분 안에 새 키를 씁니다 — 재배포도, 슬랙의 "새 키 누가 갖고 있어요?" 메시지도 필요 없습니다. 로테이션 정책은 90일 이하이고, TruffleHog / GitGuardian / Gitleaks로 매 커밋을 검사합니다. 제로 트러스트: MFA, SSO, RBAC/ABAC, 단기 수명 토큰, 디바이스 상태 확인. PII 스크러빙은 개체 인식으로 전송 전에 PHI/PII를 마스킹합니다. 일관된 토큰화(Mesh 방식)는 민감한 값을 안정적인 플레이스홀더에 매핑해 LLM이 코드/관계 의미를 유지하게 합니다. 네트워크 이그레스: LLM 서비스를 전용 VPC/VNet 서브넷에 두고 `api.openai.com`, `api.anthropic.com` 등만 화이트리스트에 올리고, 나머지 아웃바운드는 전부 차단합니다. 2026년의 사고 원인: Vercel 공급망 공격이 침해된 CI/CD 자격 증명을 통해 수천 개의 고객 배포에서 환경 변수를 유출했습니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, 장난감 수준의 PII 스크러버 + 감사 로그 라이터)
**선수 지식:** 페이즈 17 · 19 (AI 게이트웨이), 페이즈 17 · 13 (관측 가능성)
**시간:** 약 60분

## 학습 목표

- 시크릿 관리의 네 가지 안티패턴(VCS 속 설정 파일, 하드코딩된 env, 스프레드시트, 정적 키)을 나열하고, 각각의 대체재를 말할 수 있습니다.
- AI 게이트웨이가 볼트에서 키를 가져오는 패턴을 2026년 프로덕션 표준으로 설명할 수 있습니다.
- 의미가 살아남도록 일관된 토큰화(같은 값 → 같은 플레이스홀더)로 PII 스크러버를 구현할 수 있습니다.
- 2026년 Vercel 공급망 사고와, 그것이 CI/CD 자격 증명 위생에 대해 가르쳐 준 교훈을 말할 수 있습니다.

## 문제 상황

인턴이 API 키가 든 `.env`를 커밋했습니다. 재빨리 삭제했지만, 키는 이미 git 히스토리 속에 있습니다. GitGuardian 검사가 잡아 냈고, 여러분의 로테이션 절차는 "팀에 슬랙으로 알리고, 설정 파일 40개를 고치고, 모든 서비스를 재배포"입니다. 8시간 후, 서비스의 절반은 새 키로 살아 있고 절반은 배포 창구를 기다리고 있습니다.

별개로, 사용자 프롬프트에 "제 주민번호는 123-45-6789입니다"가 들어왔습니다. 프롬프트는 OpenAI로 전송됩니다. BAA(영업 보조 계약)는 있지만 내부 정책상 전송 전에 PII를 마스킹하기로 되어 있습니다. 하지만 하지 않았습니다.

또 별개로, EKS 클러스터의 LLM 파드는 인터넷의 어떤 호스트에도 접근할 수 있습니다. 누군가 공격자가 소유한 도메인으로 DNS 조회를 통해 데이터를 유출했습니다. 막아 준 것이 아무것도 없었습니다.

LLM 서비스의 보안은 이 세 개의 공격 경로를 모두 다뤄야 합니다. 볼트 기반 자격 증명. PII 스크러빙. 네트워크 이그레스 필터링. 감사 로그.

## 개념

### 중앙화된 볼트 + IAM 역할 기반 조회

**볼트**: HashiCorp Vault, AWS Secrets Manager, Azure Key Vault, GCP Secret Manager. 단 하나의 진실 공급원.

**IAM 역할**: 앱/게이트웨이가 정적 키가 아니라 IAM 아이덴티티로 인증합니다. 볼트는 토큰 수명 동안만 시크릿을 돌려 줍니다.

**AI 게이트웨이 패턴**: 게이트웨이가 요청 시점에 볼트에서 `OPENAI_API_KEY`를 가져옵니다. 볼트에서 로테이션하면 다음 요청부터 새 키를 씁니다. 재배포가 필요 없습니다.

### 로테이션 정책 ≤ 90일

모든 API 키, 볼트 루트 토큰, CI/CD 자격 증명이 대상입니다. 가능하면 자동 로테이션으로. 수동 로테이션은 기록으로 남기고 추적합니다.

### 시크릿 검사

- **TruffleHog** — 커밋에 대해 정규식 + 엔트로피 검사.
- **GitGuardian** — 상용, 높은 정확도.
- **Gitleaks** — 오픈소스, CI에서 실행.

매 커밋마다 실행합니다. 새 시크릿이 감지되면 PR을 차단합니다.

### 제로 트러스트 자세

- 모든 계정에 MFA 필수.
- SAML/OIDC 기반 SSO.
- 세밀한 접근 제어를 위한 RBAC(역할 기반) 또는 ABAC(속성 기반).
- 단기 수명 토큰(일 단위가 아니라 시간 단위).
- 디바이스 상태 — 디스크 암호화가 켜진 회사 디바이스만 허용.

### PII / PHI 스크러빙

프롬프트가 여러분의 인프라를 떠나기 전에:

1. 개체 인식(spaCy NER, Presidio, 상용 제품).
2. 매칭된 개체를 마스킹: `"My SSN is 123-45-6789"` → `"My SSN is [SSN_TOKEN_A3F]"`.
3. 일관된 토큰화(Mesh 방식): 같은 값은 항상 같은 플레이스홀더로 매핑되어 LLM이 관계를 유지합니다.
4. LLM 응답을 위한 선택적 역매핑.

정적 정규식 필터는 기본 패턴을 잡고, NER은 더 많이 잡습니다. 둘 다 쓰세요.

### 입력 + 출력 가드레일

입력: 알려진 탈옥(jailbreak) 시도, 금지 주제 차단, 사용자별 속도 제한.

출력: 유출된 시크릿에 대한 정규식 검사(API 키 패턴, 거부 문맥 속 이메일 패턴), 정책 위반 분류기.

### 네트워크 이그레스 화이트리스트

전용 서브넷에 둔 LLM 서비스:
- 화이트리스트: `api.openai.com`, `api.anthropic.com`, 벡터 DB 엔드포인트, 볼트 엔드포인트.
- 나머지 전부: 폐기(drop).
- DNS는 허용 목록 전용 리졸버로 (DNS 터널링 유출 방지).

### 감사 로그

모든 LLM 호출에 대한 불변(immutable) 로그. 항목:
- 타임스탬프.
- 사용자 / 테넌트.
- 프롬프트 해시 (프라이버시를 위해 원문 프롬프트가 아님).
- 모델 + 버전.
- 토큰 수.
- 비용.
- 응답 해시.
- 가드레일 발동 여부.

규제 요건에 따라 보관합니다 (SOC 2는 1년, HIPAA는 6년).

### 2026년 Vercel 사고

공급망 공격: 침해된 CI/CD 자격 증명이 수천 개의 고객 배포에서 환경 변수를 유출했습니다. 교훈: CI/CD 자격 증명은 프로덕션 등급의 자격 증명과 같습니다. 볼트에 저장하고, 범위를 좁게 잡고, 공격적으로 로테이션하세요.

### 기억해야 할 숫자들

- 로테이션 정책: 90일 이하.
- 매 커밋 검사: TruffleHog / GitGuardian / Gitleaks.
- Vercel 2026: CI/CD 자격 증명 침해 → 수천 개 고객 환경 변수 유출.
- 감사 로그 보관: SOC 2 = 1년, HIPAA = 6년.

## 연습 문제

1. `code/main.py`를 실행해 보세요. 같은 주민번호를 언급하는 프롬프트 두 개를 보내고, 둘 다 같은 플레이스홀더를 받는지 확인하세요.
2. OpenAI + Anthropic + Weaviate를 호출하는 vLLM-on-EKS 배포를 위한 네트워크 이그레스 정책을 설계하세요.
3. git 히스토리에서 2년 전 키를 발견했습니다. 올바른 대응은 무엇일까요 — 키 로테이션, 히스토리 정리, 아니면 둘 다? 근거를 대세요.
4. 감사 로그가 하루 10GB씩 늘어납니다. 보관 계층을 설계하세요(핫 30일, 웜 12개월, 콜드 6년).
5. 역토큰화(LLM 응답에 실제 값을 다시 치환)가 복잡성을 감수할 가치가 있는지, 아니면 플레이스홀더를 그대로 보여 주는 게 나은지 논증해 보세요.
