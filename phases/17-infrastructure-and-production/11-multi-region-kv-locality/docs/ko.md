# 멀티 리전 LLM 서빙과 KV 캐시 지역성

> 라운드 로빈 로드 밸런싱은 캐시된 LLM 추론에 적극적으로 해롭습니다. 자신의 프리픽스를 쥔 노드에 못 들어간 요청은 프리필 비용을 통째로 냅니다 — 긴 프롬프트 기준 P50 약 800ms vs 캐시 적중 시 약 80ms. 2026년의 프로덕션 패턴은 KV 캐시 이벤트를 받아 프리픽스 해시 일치로 라우팅하는 캐시 인식 라우터(러스트로 만든 vLLM Router, llm-d router)입니다. 최근 연구(GORGO)는 리전 간 네트워크 지연을 라우팅 목적 함수에 명시적인 항으로 넣었습니다. 상용 "크로스 리전 추론" 제품(Bedrock 크로스 리전 추론, GKE 멀티 클러스터 게이트웨이)은 추론을 불투명한 것으로 취급합니다 — 가용성은 챙기지만 TTFT는 아닙니다. JPMorgan과 Mayo Clinic은 2024년 11월 us-east-1 페일오버 훈련을 약 22분 만에 통과했습니다. 재해 복구(DR)의 현실: LLM DR 실패의 32%는 팀이 가중치는 백업했지만 토크나이저 파일이나 양자화 설정을 잊었기 때문입니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, 장난감 수준 프리픽스 캐시 인식 라우터 시뮬레이터)
**선수 지식:** Phase 17 · 04 (vLLM 서빙), Phase 17 · 06 (SGLang RadixAttention)
**시간:** 약 60분

## 학습 목표

- 라운드 로빈 로드 밸런싱이 캐시된 추론을 왜 깨는지 설명하고 TTFT 페널티를 수치로 말할 수 있다.
- 캐시 인식 라우터를 그림으로 그릴 수 있다: 입력(KV 캐시 이벤트), 알고리즘(프리픽스 해시 일치), 동점 결정자(GPU 활용률).
- LLM DR 실패의 32% 원인(토크나이저 파일 / 양자화 설정 누락)을 말하고, 세 파일 DR 체크리스트를 제시할 수 있다.
- 상용 크로스 리전 제품(Bedrock CRI, GKE 멀티 클러스터 게이트웨이)과 KV 인식 라우팅을 구별할 수 있다.

## 문제 상황

여러분의 서비스가 us-east-1, us-west-2, eu-west-1에서 돌아갑니다. 앞에 라운드 로빈 ALB를 두었습니다. 프로덕션(운영 환경)에서 프리픽스 캐시 적중률이 8%로 떨어집니다. TTFT P50이 세 배가 됩니다. vLLM 로그를 보면 모든 요청이 프리필 비용을 통째로 내고 있습니다.

라운드 로빈은 스테이트리스 서비스에는 최적입니다. LLM 추론은 설계상 스테이트풀입니다 — KV 캐시가 모델이 본 모든 것을 부호화하니까요. 눈 감고 라우팅한다는 건 잘못된 캐시로 라우팅하는 겁니다.

따로, 팀에 DR 계획이 있습니다. 모델 가중치를 S3 크로스 리전에 백업합니다. 어느 리전 장애가 터지고, 페일오버를 시도하고, 복제본이 기동을 거부합니다. tokenizer.json과 양자화 설정, RoPE 스케일링 설정이 싱크하지 않은 별개 버킷에 있었던 겁니다.

멀티 리전 LLM 서빙은 캐시 문제, 라우팅 문제, DR 위생 문제입니다 — 로드 밸런서 문제가 아닙니다.

## 개념

### 캐시 인식 라우팅

프롬프트를 실은 요청이 도착합니다. 라우터가 프리픽스(예: 처음 512토큰)를 해시하고, 각 레플리카에게 "이 프리픽스 캐시 돼 있어?"라고 묻습니다. 레플리카들은 블록을 할당하고 내쫓을 때 pub/sub 채널에 KV 캐시 이벤트를 발행합니다. 라우터는 일치하는 레플리카를 고르고, 아무도 없으면 GPU 활용률 기반 동점 결정자로 넘어갑니다.

**vLLM Router** (러스트, 2026 production-stack): `kv.cache.block_added` 이벤트를 구독하고, 프리픽스 해시 → 레플리카 색인을 유지하며, O(1) 조회로 라우팅합니다. 일치가 없으면 큐가 가장 짧은 곳으로 넘어갑니다.

**llm-d router**: 같은 패턴의 쿠버네티스 네이티브 버전. ControlPlane API로 이벤트를 발행합니다.

**SGLang RadixAttention**(Phase 17 · 06)은 레플리카 안쪽(intra-replica)의 대응물입니다. 레플리카 간 라우팅은 엄밀히 그 상류에 해당합니다.

### 숫자들

2K 토큰 프롬프트, Llama 3.3 70B FP8, H100에서의 TTFT P50:
- 캐시 적중(같은 레플리카, 프리픽스 상주): 약 80ms.
- 캐시 미스(콜드 프리필): 약 800ms.

10배 격차입니다. 라우터가 레플리카 전체에서 프리픽스 캐시의 60~80%를 적중시키면, N개 레플리카 용량으로 단일 레플리카 성능에 근접합니다. 10%만 적중시키면 순진한 스케일링에 근접합니다.

### 크로스 리전에는 새 제약이 있다 — 네트워크 지연

리전 간 RTT:
- us-east-1 ↔ us-west-2: 약 65ms.
- us-east-1 ↔ eu-west-1: 약 75ms.
- us-east-1 ↔ ap-southeast-1: 약 220ms.

us-east-1의 요청을 ap-southeast-1의 뜨거운 프리픽스로 보내면, 아낀 프리필(800 → 80ms)이 왕복 440ms에 묻힙니다. GORGO(2026 연구)가 이를 명시적으로 다룹니다 — 프리필만이 아니라 `prefill_time + network_latency`를 함께 최소화하세요. 종종 정답은, 프리필이 지배하는 거대한 멀티 MB 프리픽스가 아니면 라우팅을 리전 안에 묶어 두는 것입니다.

### 상용 "크로스 리전 추론"은 여기서 도움이 안 된다

AWS Bedrock 크로스 리전 추론은 용량 압박 시 요청을 다른 리전으로 자동 라우팅합니다. 가용성을 최적화하지 TTFT는 최적화하지 않고, 추론을 불투명하게 취급합니다. GKE 멀티 클러스터 게이트웨이도 같습니다 — 서비스 수준 페일오버일 뿐, KV 캐시 인식이 없습니다.

이 제품들을 쓰더라도 앱 계층의 캐시 인식 라우터는 여전히 필요합니다. 이들은 "us-east-1에 불이 났을 때"를 다룹니다. 캐시 인식 라우팅은 TTFT 문제를 다룹니다.

### DR 위생 — 32% 누락 파일 문제

2026년 널리 인용되는 통계: LLM DR 실패의 32%는 팀이 가중치는 백업했지만 아래를 잊었기 때문입니다:

- `tokenizer.json` 또는 `tokenizer.model`
- 양자화 설정(`quantize_config.json`, AWQ 스케일, GPTQ 제로 포인트)
- 모델별 설정(RoPE 스케일링, 어텐션 마스크, 채팅 템플릿)
- 엔진 설정(`vllm_config.yaml`, 샘플링 기본값, LoRA 어댑터 매니페스트)

해법은 세 파일 최소 DR 매니페스트입니다:

1. HF 모델 저장소의 모든 파일(가중치 + 설정 + 토크나이저).
2. 엔진별 서빙 설정.
3. 배포 매니페스트(K8s YAML, Dockerfile, 의존성 잠금 파일).

게다가: DR 훈련을 분기별로 돌리세요. 2024년 11월 JPMorgan의 us-east-1 훈련이 22분 복구를 기록한 것은 플레이북을 리허설해 봤기 때문입니다.

### 데이터 레지던시(데이터 소재지)는 별개 축이다

EU 고객의 PHI는 EU를 떠날 수 없습니다. 캐시 인식 라우터가 파리에서 온 요청을 프리픽스 일치 때문에 us-east-1으로 보내면, TTFT 이득과 무관하게 GDPR을 위반한 것입니다. 캐시를 위해 최적화하기 전에, 레지던시 경계로 라우터를 먼저 분할하세요.

### 기억해야 할 숫자들

- 캐시 적중 vs 미스 TTFT 격차: 약 10배(2K 프롬프트에서 80ms vs 800ms).
- 리전 간 RTT 미국-유럽: 약 75ms.
- DR 실패: 32%가 토크나이저/양자화 설정 누락.
- JPMorgan us-east-1 페일오버 2024년 11월: 22분(30분 SLA).

## 연습 문제

1. `code/main.py`를 실행하세요. RTT 75ms를 감안할 때, 프롬프트 길이가 얼마부터 크로스 리전 라우팅이 리전 전용 라우팅을 이기나요?
2. 캐시 적중률이 70%에서 12%로 떨어졌습니다. 가능한 원인 셋과, 각각을 확인해 줄 관측 가능한 신호를 진단하세요.
3. vLLM에서 5개 LoRA 어댑터와 함께 서빙되는 70B AWQ 양자화 모델의 DR 매니페스트를 설계하세요. 파일과 설정을 전부 나열하세요.
4. 엄격한 TTFT SLO를 가진 핀테크에 Bedrock 크로스 리전 추론이 "충분한지" 논하세요. 구체적인 동작을 인용하세요.
5. 파리에서 온 요청이 us-east-1의 프리픽스와 일치합니다. 라우팅할 건가요? 정책을 작성하세요.
