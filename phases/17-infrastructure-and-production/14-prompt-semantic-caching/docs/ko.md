# 프롬프트 캐싱과 시맨틱 캐싱 경제학

> **2026-04 기준 가격 스냅샷입니다.** 아래 수치 주장들은 이 레슨 출판 시점에 캡처한 벤더 요금표를 반영합니다. 다른 곳에 인용하기 전에 링크된 문서에서 다시 확인하세요.

> 캐싱은 두 계층에서 일어납니다. L2(프로바이더 수준) 프롬프트/프리픽스 캐싱은 반복되는 프리픽스의 어텐션 KV를 재사용합니다 — Anthropic의 프롬프트 캐싱 문서는 긴 프롬프트에서 최대 90% 비용 절감, 85% 지연 시간 절감을 내세웁니다. Claude 3.5 Sonnet 기준 캐시 읽기는 신규 입력 $3.00/M에 비해 $0.30/M이고, TTL은 5분이 기본이며 1시간 TTL 옵션에는 2배의 쓰기 프리미엄이 붙습니다(docs.anthropic.com, 2026-04). OpenAI 프롬프트 캐싱은 1024 토큰 이상 프롬프트에 자동 적용되며, 캐시된 입력을 신규 입력 대비 대략 90% 할인 가격에 팝니다(platform.openai.com, 2026-04). 모델별 정확한 캐시 요금은 실시간 요금표를 따릅니다. L1(앱 수준) 시맨틱 캐싱은 임베딩 유사도 적중 시 LLM을 아예 건너뜁니다. 벤더가 말하는 "95% 정확도"는 적중률이 아니라 매칭의 정확성을 가리킵니다 — 실제 프로덕션(운영 환경) 적중률 보고는 개방형 채팅 10%부터 구조화된 FAQ 70%까지 분포하며, 어느 프로바이더도 공식 베이스라인을 내놓지 않으므로 보장이 아니라 커뮤니티 텔레메트리로 취급하세요. 프로덕션 함정 두 가지: 병렬화는 캐싱을 망칩니다(첫 캐시 쓰기가 끝나기 전에 쏟아지는 N개의 병렬 요청이 비용을 몇 배로 불림), 그리고 프리픽스 안의 동적 콘텐츠는 캐시 적중을 완전히 막습니다. ProjectDiscovery는 동적 텍스트를 캐시 가능한 프리픽스 밖으로 옮겨 적중률을 7%에서 74%로 올렸다고 보고했습니다(2025-11).

**유형:** 학습
**언어:** Python (표준 라이브러리, 두 계층 캐시 시뮬레이터 장난감 버전)
**선수 지식:** 페이즈 17 · 04 (서빙 엔진 내부 구조), 페이즈 17 · 06 (SGLang RadixAttention)
**시간:** 약 60분

## 학습 목표

- L2 프롬프트/프리픽스 캐싱(프로바이더에서 KV 재사용)과 L1 시맨틱 캐싱(비슷한 프롬프트에서 LLM 우회)을 구분할 수 있습니다.
- Anthropic의 `cache_control` 명시적 표시 방식과 두 가지 TTL 옵션(5분 vs 1시간), 그 가격 배수를 설명할 수 있습니다.
- 적중률, 프롬프트/응답 구성, 토큰 가격이 주어지면 예상 월간 절감액을 계산할 수 있습니다.
- 청구서를 5-10배 불리는 병렬화 안티패턴과 적중률을 무너뜨리는 동적 콘텐츠 안티패턴의 이름을 말할 수 있습니다.

## 문제 상황

RAG 서비스에 프롬프트 캐싱을 추가했습니다. 청구서는 그대로입니다. 적중률을 재보니 7%입니다. 프롬프트는 정적처럼 보이지만 사실이 아닙니다 — 시스템 프롬프트에 분 단위까지 표기된 현재 날짜, 요청 ID, 다양성을 위한 무작위 예시 재배열이 들어 있습니다. 모든 요청이 새 캐시 항목을 쓰고, 읽는 것은 0입니다.

따로 따로, 당신의 에이전트는 사용자 질문 하나에 열 개의 도구 호출을 병렬로 날립니다. 열 개 모두 첫 캐시 쓰기가 완료되기 전에 프로바이더에 도착합니다. 쓰기 10번, 읽기 0번. 청구서는 "캐싱 적용 시" 예상 비용의 5-10배입니다.

캐싱은 플래그가 아니라 프로토콜입니다. 두 개의 계층, 두 가지 서로 다른 실패 양상이 존재합니다.

## 개념

### L2 — 프로바이더 프롬프트/프리픽스 캐싱

프로바이더가 캐시 가능한 프리픽스의 어텐션 KV를 저장해 두고, 그 프리픽스에 매칭되는 다음 요청에서 재사용합니다. 쓰기 비용은 한 번 내고, 읽기는 거의 공짜입니다.

**Anthropic (Claude 3.5 / 3.7 / 4 시리즈)**: 요청에 명시적인 `cache_control` 마커를 붙입니다. 어떤 블록이 캐시 가능한지 직접 태깅합니다. TTL: 5분(쓰기 비용이 기본의 1.25배) 또는 1시간(쓰기 비용이 기본의 2배). 캐시 읽기: Claude 3.5 Sonnet 기준 신규 $3.00/M에 비해 $0.30/M — 10배 저렴합니다(docs.anthropic.com, 2026-04 기준). 모델별로 요율이 다릅니다(Opus/Haiku는 별도 공개). 항상 실시간 가격 페이지와 대조하세요.

**OpenAI**: 1024 토큰 이상 프롬프트에 자동 캐싱(platform.openai.com, 2026-04 기준). 명시적 플래그 없음. 현재 gpt-4o/gpt-5 요금표 기준 캐시된 입력은 신규 입력보다 대략 10배 저렴합니다. 문서나 릴리스 노트 어디도 공식 적중률 베이스라인을 공개하지 않으며, 커뮤니티 보고는 신중한 프롬프트 설계 시 30-60% 부근에 모입니다. `usage.cached_tokens`를 모니터링해 스스로 측정하세요.

**Google (Gemini)**: 명시적 API를 통한 컨텍스트 캐싱; 1M 토큰 컨텍스트라서 캐싱이 더 큰 값을 냅니다.

**셀프호스팅 (vLLM, SGLang)**: 페이즈 17 · 06에서 RadixAttention을 다룹니다 — 같은 패턴을 여러분의 컴퓨팅 위에서 돌리는 것입니다.

### L1 — 앱 수준 시맨틱 캐싱

LLM을 부르기 전에 프롬프트를 해시하고 임베딩해서, 비슷한 캐시된 요청이 있는지 찾아봅니다(코사인 유사도가 임계값 이상, 보통 0.95 이상). 적중하면 캐시된 응답을 돌려줍니다. 놓치면 LLM을 호출하고 결과를 캐시합니다.

오픈소스: Redis Vector Similarity, GPTCache, Qdrant. 상용: Portkey Cache, Helicone Cache.

벤더의 정확도 주장은 돌려준 캐시 응답이 의미상 적절했던 빈도를 가리키지, 적중한 빈도가 아닙니다. 프로덕션 적중률:

- 개방형 채팅: 10-15%.
- 구조화된 FAQ / 지원: 40-70%.
- 코드 질문: 20-30% (작은 변형들이 적중을 깨뜨립니다).
- 프롬프트를 반복하는 음성 에이전트: 50-80% (음성 정규화 결과가 고정된 집합).

### 병렬화 안티패턴

에이전트가 도구 호출 10개를 병렬로 만듭니다. 10개 모두 같은 4K 토큰 시스템 프롬프트를 씁니다. Anthropic 캐시 쓰기는 요청 단위이고, 첫 캐시 쓰기는 프롬프트가 프로바이더에 도착한 뒤 약 300ms에 완료됩니다. 요청 2~10은 같은 밀리초 창에 도착하고 각자 캐시 미스를 봅니다. 쓰기 프리미엄 10번, 읽기 할인 0번입니다.

해법: 순차 우선 배치 — 요청 1을 혼자 먼저 보내고, 1의 캐시가 채워진 뒤에 2~10을 쏩니다. 첫 도구 호출에 300ms가 더해지지만, 청구서는 5-10배 절약됩니다.

### 동적 콘텐츠 안티패턴

시스템 프롬프트가 이렇게 생겼다면:

```
You are a helpful assistant. The current time is 14:32:17.
User ID: abc123. Today is Tuesday...
```

모든 요청이 유니크합니다. 모든 요청이 씁니다. 적중은 0입니다.

해법: 진짜 정적인 것을 모두 캐시 가능한 프리픽스로 옮기고, 동적 콘텐츠는 캐시 경계 뒤에 붙입니다:

```
[cacheable]
You are a helpful assistant. [rules, examples, instructions]
[/cacheable]
[dynamic, not cached]
Current time: 14:32:17. User: abc123.
```

ProjectDiscovery는 이 방식으로 캐시 적중률을 7%에서 74%로 올렸고 그 해부 결과를 공개했습니다.

### 밤새 돌리는 워크로드에는 배치 + 캐시 스택

배치 API(페이즈 17 · 15)는 24시간 처리 기준 50% 할인을 줍니다. 그 위에 캐시된 입력까지 얹으면 거기서 다시 약 10배를 얻습니다. 하룻밤 분류, 라벨링, 보고서 생성 워크로드는 스택으로 묶으면 동기식 무캐시 비용의 약 10%까지 내려올 수 있습니다.

### 기억해야 할 숫자들

가격 수치는 2026-04에 링크된 벤더 문서에서 캡처한 것이며 몇 달마다 흔듭니다 — 의존하기 전에 다시 확인하세요.

- Anthropic 캐시 읽기: Claude 3.5 Sonnet 기준 $0.30/M, 신규 입력보다 대략 10배 저렴 (docs.anthropic.com).
- Anthropic 캐시 쓰기 프리미엄: 1.25배(5분 TTL) 또는 2배(1시간 TTL).
- OpenAI 자동 캐시: 1024 토큰 이상 프롬프트에 적용; 현재 요금표 기준 캐시된 입력은 신규 입력의 대략 10% 가격 (platform.openai.com).
- 시맨틱 캐시 적중률(커뮤니티 보고): 개방형 채팅 약 10%; 구조화된 FAQ 최대 약 70%. 벤더가 문서화한 베이스라인이 아닙니다.
- ProjectDiscovery: 동적 콘텐츠를 프리픽스 밖으로 옮겨 적중률 7% → 74% (프로젝트 블로그, 2025-11).
- 병렬화 안티패턴: N개 병렬 요청이 첫 캐시 쓰기를 놓칠 때 청구서가 5-10배 불어난다는 보고가 일반적.

## 활용하기

`code/main.py`는 혼합 워크로드에서 L1 + L2 캐싱을 시뮬레이션합니다. 적중률과 청구액을 보고하고 병렬화 페널티를 보여줍니다.

## 출시하기

이 레슨은 `outputs/skill-cache-auditor.md`를 산출합니다. 프롬프트 템플릿과 트래픽이 주어지면 캐시 적합성을 감사하고 재구성을 권고합니다.

## 연습 문제

1. `code/main.py`를 실행하세요. 병렬화 플래그를 켜고 꺼 보세요. 청구액이 얼마나 바뀌나요?
2. 시스템 프롬프트에 날짜가 들어 있습니다. 밖으로 옮기세요. 적중률 계산의 전/후를 보여주세요.
3. 요청 도착률이 주어졌을 때 1시간 TTL(2배 쓰기)과 5분 TTL(1.25배 쓰기)의 손익분기점을 계산하세요.
4. 시맨틱 캐시가 0.95 임계값에서 20% 적중합니다. 0.85에서는 50% 적중이지만 잘못된 캐시 응답이 보입니다. 올바른 임계값을 고르고 근거를 대세요.
5. 사용자 질문 하나에 병렬 하위 질의 10개를 배치합니다. 종단 지연 시간을 늘리지 않고 캐시 친화적으로 다시 설계하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| L2 프롬프트 캐시 | "프리픽스 캐시" | 프로바이더가 반복 프리픽스의 KV를 저장 |
| `cache_control` | "Anthropic 캐시 마커" | 캐시 가능한 블록을 표시하는 명시적 속성 |
| 캐시 쓰기 프리미엄 | "쓰기 세금" | 첫 미스-투-캐시(최초 캐시 등록)의 추가 비용 (1.25배 또는 2배) |
| L1 시맨틱 캐시 | "임베딩 캐시" | LLM 호출 전에 앱 수준에서 해시·임베딩 |
| GPTCache | "LLM 캐싱 라이브러리" | 널리 쓰이는 오픈소스 L1 캐시 라이브러리 |
| 캐시 적중률 | "적중 / 전체" | 캐시에서 서빙된 요청의 비율 |
| 병렬화 안티패턴 | "N-write 트랩" | N개 병렬 요청이 캐시를 N번 놓침 |
| 동적 콘텐츠 트랩 | "프롬프트 속 시간 트랩" | 프리픽스 안의 동적 바이트가 적중률을 죽임 |
| RadixAttention | "복제본 내부 캐시" | SGLang의 프리픽스 캐시 구현 |
