# LLM 기능 A/B 테스팅 — GrowthBook, Statsig, 그리고 감(vibes)의 문제

> 전통적 A/B 테스팅은 비결정적인 LLM을 위해 만들어지지 않았습니다. 결정적인 구분: 평가(eval)는 "모델이 일을 해낼 수 있는가?"에 답합니다. A/B 테스트는 "사용자가 관심 있는가?"에 답합니다. 둘 다 필요하고; 감으로 출시하던 시대는 끝났습니다. 2026년에 테스트할 것: 프롬프트 엔지니어링(표현), 모델 선택(GPT-4 vs GPT-3.5 vs 오픈소스; 정확도 vs 비용 vs 지연), 생성 파라미터(temperature, top-p). 실제 사례: 챗봇 보상 모델 변형이 대화 길이 +70%, 유지율 +30%를 냈습니다; Nextdoor의 AI 제목 실험은 보상 함수 개선 후 CTR +1%를 냈습니다; Khan Academy의 Khanmigo는 지연 vs 수학 정확도 축에서 반복 조정을 했습니다. 플랫폼 구도: **Statsig**(2025년 9월 OpenAI가 11억 달러에 인수) — 순차 테스팅, CUPED, 올인원. **GrowthBook** — 오픈소스, 웨어하우스 네이티브, 베이지안 + 빈도주의 + 순차 엔진, CUPED, SRM 검사, Benjamini-Hochberg + Bonferroni 보정. 웨어하우스-SQL 선호도와 "OpenAI 인수"가 조직에 중요한지에 따라 고르면 됩니다.

**유형:** 학습
**언어:** Python (표준 라이브러리, 순차 검정 시뮬레이터 장난감 버전)
**선수 지식:** 페이즈 17 · 13 (관측 가능성), 페이즈 17 · 20 (점진적 배포)
**시간:** 약 60분

## 학습 목표

- 평가("모델이 일을 해낼 수 있는가")와 A/B 테스트("사용자가 관심 있는가")를 구분할 수 있습니다.
- 세 가지 테스트 축(프롬프트, 모델, 파라미터)을 나열하고 각각의 메트릭을 고를 수 있습니다.
- CUPED, 순차 테스팅, Benjamini-Hochberg 다중 비교 보정을 설명할 수 있습니다.
- 웨어하우스-SQL 입장과 기업 인수에 대한 입장에 따라 Statsig 또는 GrowthBook을 고를 수 있습니다.

## 문제 상황

시스템 프롬프트를 손으로 다듬었습니다. 더 나아 보입니다. 출시합니다. 전환율은 노이즈 수준으로 움직입니다. 여러분은 메트릭을 탓합니다. 아니면 새 모델을 출시했는데 전환이 움직이지 않았습니다 — 모델이 나빠진 걸까요, 변화가 감지할 수 없을 만큼 작았던 걸까요? 모릅니다. A/B 없이 출시했으니까요.

평가는 레이블 달린 세트에서 모델이 과제를 해내는지에 답합니다. 사용자가 출력을 선호하는지에는 답하지 않습니다. 그것에 답하는 것은 통제된 온온라인 실험뿐이고, 그것도 실험이 충분한 검정력을 갖고, 비결정성을 통제하고, 다중 비교를 보정할 때만 가능합니다.

## 개념

### 평가 vs A/B 테스트

**평가** — 오프라인, 레이블 달린 세트, 심사기(루브릭 또는 LLM-as-judge 또는 사람). 답하는 질문: "이 고정된 분포 위에서 출력이 정확한가 / 유용한가 / 안전한가?"

**A/B 테스트** — 온라인, 실제 사용자, 무작위화. 답하는 질문: "새 변형이 중요한 사용자 수준 메트릭을 움직이는가?"

둘 다 필수입니다. 평가는 노출 전에 회귀를 잡고; A/B는 그 후에 제품 영향을 확인합니다.

### 무엇을 테스트하나

1. **프롬프트 엔지니어링** — 표현, 시스템 프롬프트 구조, 예시. 메트릭: 과제 성공, 사용자 유지율, 요청당 비용.
2. **모델 선택** — GPT-4 vs GPT-3.5-Turbo vs Llama 오픈소스. 메트릭: 정확도(과제) + 요청당 비용 + 지연 P99. 다중 목표.
3. **생성 파라미터** — temperature, top-p, max_tokens. 메트릭: 과제별(출력 다양성 vs 결정성).

### CUPED — 분산 축소

Controlled-experiments Using Pre-Experiment Data(실험 전 데이터를 활용한 통제 실험). 사후 기간을 비교하기 전에 사전 기간의 분산을 회귀분석으로 걸러냅니다. 전형적인 분산 축소: 30-70%. 실효 표본 크기가 공짜로 올라갑니다.

구현: Statsig와 GrowthBook 양쪽 모두 구현돼 있습니다.

### 순차 테스팅

고전적 A/B는 고정 표본 크기를 가정합니다. 순차 검정("들여다보고 결정")은 반복해서 들여다보는 동안의 위양성률을 통제합니다. 항상 타당한(always-valid) 순차 절차(mSPRT, Howard의 신뢰도 시퀀스)는 명확한 승자에서 조기 중단을 허용합니다.

### 다중 비교 보정

95% 신뢰도로 A/B 테스트 20개를 돌리면 우연히 하나의 위양성이 나옵니다. Bonferroni 보정은 검정별 α를 조이고; Benjamini-Hochberg는 위발견률(false-discovery rate)을 통제합니다. GrowthBook은 둘 다 구현합니다.

### SRM — 표본 비율 불일치

할당 해시가 사용자를 변형들에 무작위 배분합니다. 50/50 분할이 47/53을 내놓는다면 뭔가 고장난 것입니다 — SRM 검사가 이를 표시합니다. 두 플랫폼 모두 구현합니다.

### Statsig vs GrowthBook

**Statsig**:
- OpenAI가 11억 달러에 인수(2025년 9월). 호스티드, SaaS.
- 순차 테스팅, CUPED, 홀드아웃 모집단.
- 올인원: 피처 플래그 + 실험 + 관측.
- 가장 잘 맞는 곳: 묶음 제품을 이미 원하는 팀, OpenAI 소유 여부에 무관심한 팀.

**GrowthBook**:
- 오픈소스(MIT); 웨어하우스 네이티브(Snowflake/BigQuery/Redshift에서 직접 읽음).
- 복수 엔진: 베이지안, 빈도주의, 순차.
- CUPED, SRM, Bonferroni, BH 보정.
- 셀프호스팅 또는 관리형 클라우드.
- 가장 잘 맞는 곳: 웨어하우스-SQL 조직, 데이터 팀이 메트릭 계층을 통제, 오픈소스를 원하는 곳.

### 비결정성이 검정력을 복잡하게 만듭니다

같은 프롬프트가 제각각의 출력을 냅니다. 전통적 검정력 계산은 IID 관측을 가정합니다. LLM 비결정성이 있으면 실효 표본 크기는 명목치보다 낮습니다. 필요한 표본 크기에 안전 마진으로 약 1.3-1.5배를 곱하세요.

### 실제 사례 결과

- 챗봇 보상 모델 변형: 대화 길이 +70%, 유지율 +30%.
- Nextdoor 제목: 보상 함수 개선 후 CTR +1%.
- Khan Academy Khanmigo: 지연 vs 수학 정확도 트레이드를 반복 조정.

### 안티패턴: 감으로 출시하기

시니어 엔지니어라면 "더 나아 보여서" A/B 없이 출시된 기능을 하나쯤 꼽을 수 있습니다. 그 대부분은 팀이 몇 달 동안 눈치채지 못한 사이 제품 메트릭을 떨어뜨렸습니다. A/B가 바로 강제 함수입니다.

### 기억해야 할 숫자들

- Statsig의 OpenAI 인수: 11억 달러, 2025년 9월.
- GrowthBook: 오픈소스 MIT; 베이지안 + 빈도주의 + 순차.
- CUPED 분산 축소: 30-70%.
- LLM 비결정성 → 표본 크기 버퍼 +30-50%.

## 연습 문제

1. `code/main.py`를 실행하세요. 베이스라인 전환율 3%에서 예상 향상 5%일 때, 80% 검정력을 위한 표본 크기는 얼마인가요?
2. 헬스케어 규제 온프레미스 고객에게 Statsig 또는 GrowthBook을 고르세요.
3. 해결된 티켓당 비용으로 GPT-4 vs GPT-3.5를 테스트하는 A/B를 설계하세요. 기본 메트릭, 가드레일 메트릭, 부차 메트릭은 무엇인가요?
4. 카나리는 통과했는데 A/B가 -1.2% 전환을 보여줍니다. 출시할까요? 에스컬레이션 기준을 작성하세요.
5. 사후 분산의 60%에 해당하는 사전 기간에 CUPED를 적용하세요. 실효 표본 크기 증가분을 계산하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| 평가(Eval) | "오프라인 테스트" | 모델 능력에 대한 레이블 세트 평가 |
| A/B 테스트 | "실험" | 사용자를 대상으로 한 실시간 무작위 비교 |
| CUPED | "분산 축소" | 분산을 줄이는 사전 기간 회귀분석 |
| 순차 검정 | "들여다봐도 되는 검정" | 조기 중단을 허용하는 항상 타당한 절차 |
| 다중 비교 | "가족 오류" | 많은 테스트를 돌리면 위양성이 부풀어 오름 |
| Bonferroni | "엄격 보정" | α를 검정 수로 나눔 |
| Benjamini-Hochberg | "BH FDR" | 위발견률 통제, 덜 보수적 |
| SRM | "나쁜 분할" | 표본 비율 불일치; 할당 버그 |
| Statsig | "OpenAI 소유" | 상용 올인원, 2025년 인수 |
| GrowthBook | "그 오픈소스제" | MIT 웨어하우스 네이티브 플랫폼 |
| mSPRT | "순차 확률비 검정" | 고전적 순차 절차 |
