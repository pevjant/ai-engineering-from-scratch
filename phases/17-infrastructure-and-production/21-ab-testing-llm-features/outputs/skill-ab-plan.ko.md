> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-ab-plan.md](skill-ab-plan.md)

기능 변경(프롬프트 / 모델 / 생성 파라미터), 베이스라인 메트릭, 예상 향상, 팀 입장(웨어하우스 네이티브 오픈소스 vs 묶음 SaaS)이 주어지면 A/B 계획을 만들어 냅니다.

산출물:

1. 플랫폼. Statsig(묶음 SaaS, OpenAI 소유) 또는 GrowthBook(MIT 오픈소스, 웨어하우스 네이티브). 근거를 댑니다.
2. 기본 메트릭 + 가드레일. 기본 메트릭은 움직이려는 대상이고; 가드레일은 절대 나빠지면 안 되는 것입니다(요청당 비용, 지연 P99, 거절률).
3. 표본 크기. 고전적 검정력 계산 × 1.4(LLM 비결정성 버퍼).
4. 설계. 고정 관측 기간(fixed-horizon) 또는 순차. 강한 신호를 예상하면 순차; 변화가 미묘하면 고정.
5. CUPED. 기본 메트릭의 사전 기간 데이터가 있으면 활성화; 회귀변수를 명시합니다.
6. 보정. 테스트 수가 적으면 Bonferroni; 관련된 테스트가 많으면 Benjamini-Hochberg.
7. SRM. 모든 실험에서 SRM 검사를 요구; 표시되면 중단하고 디버깅합니다.

하드 리젝(무조건 거절):

- 감으로 출시하는 것. 거절하세요 — A/B 또는 문서화된 A/B 생략 예외를 요구합니다.
- BH/Bonferroni 없이 같은 기본 메트릭 위에 실험 5개 초과를 돌리는 것. 거절하세요 — 위발견은 확정입니다.
- SRM 검사를 생략하는 것. 거절하세요 — 할당 버그는 흔합니다.

거절 규칙:

- 기능의 트래픽이 주간 사용자 1000명 미만이면 고정 A/B를 거절 — 대신 섀도우 + 카나리(페이즈 17 · 20)를 요구합니다.
- 기본 메트릭이 객관적 대리 지표 없이 주관적이라면(예: "품질"), 병행하는 사람 평가를 요구합니다.
- 향상 가설이 LLM 노이즈 바닥보다 작으면 거절 — 현실적인 표본 크기로는 실험이 그것을 감지할 수 없습니다.

출력: 플랫폼, 기본 + 가드레일, 표본 크기, 설계, CUPED, 보정, SRM 정책을 담은 한 페이지짜리 계획서. 의사결정 규칙으로 마무리합니다: 기본 메트릭 유의 + 모든 가드레일이 유의미한 악화 아님 → 출시; 가드레일 위반이 하나라도 → 기본 메트릭과 무관하게 출시 금지.
