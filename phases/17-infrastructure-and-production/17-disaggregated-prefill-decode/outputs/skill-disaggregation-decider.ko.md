워크로드 프로필(프롬프트/출력 길이 분포, 모델, 동시성), 클러스터 토폴로지(GPU, 패브릭, RDMA 가용성), 현재 서빙 비용이 주어지면 분리 결정을 만들어 냅니다.

산출물:

1. 분리하는가? 예 / 아니오, 번호를 붙인 근거와 함께. 기준: 프롬프트 512 초과 그리고 출력 200 초과. 패브릭: RDMA가 있으면 유리; TCP 전용이면 손익분기가 더 멀어집니다.
2. 스택 선택. NVIDIA Dynamo(vLLM/SGLang/TRT-LLM 위의 관리형 오케스트레이터) 또는 llm-d(Kubernetes 네이티브 Service). 운영 환경에 맞춥니다.
3. 프리필:디코드 비율. Dynamo Planner Profiler 판독값을 쓰거나, 워크로드 형태(프리필 TFLOPS vs 디코드 바이트/초)에서 계산합니다. 예: RAG 위주는 프리필 2 : 디코드 1; 출력 위주는 1:2.
4. KV 전송 계획. 명시된 전송 계층(NIXL, InfiniBand / RDMA / TCP 폴백). 프롬프트 P99 기준 요청당 전송세를 계산합니다.
5. 라우터 통합. 캐시 인지 라우터(페이즈 17 · 11)가 앞단에 있어야 합니다 — 프리픽스 매칭 없는 분리는 캐시 승리를 놓칩니다.
6. 예상 절감액. 동거 베이스라인 대비 계산; 공개 사례를 인용합니다(동일 SLA에서 30-40%).

하드 리젝(무조건 거절):

- 짧은 프롬프트(512 토큰 미만) 워크로드를 분리하는 것. 거절하세요 — 전송세가 지배합니다.
- 캐시 인지 라우터 없이 배포하는 것. 거절하세요 — 맹목적 라우팅은 KV 지역성을 무효화합니다.
- 토폴로지(랙 패킹)를 무시하는 것. 거절하세요 — 멀티랙 홉을 넘는 KV 전송은 같은 랙 위 RDMA보다 비쌉니다.

거절 규칙:

- 클러스터가 GPU 4장 미만이면 거절 — 분리가 값을 내기엔 풀 다양성이 부족합니다.
- RDMA/InfiniBand가 없고 계획도 없다면, TCP는 손익분기를 프롬프트 2K 초과로 끌어올린다고 명시하고 재평가합니다.
- 팀이 역할별 스케일링이 가능한 GPU 풀 둘을 운영할 수 없다면 llm-d를 거절하고 관리형 대안으로 Dynamo를 요구합니다.

출력: 분리 예/아니오, 스택 선택, 비율, 전송 계층, 라우터, 예상 절감액을 담은 한 페이지짜리 결정서. 검증용 단 하나의 지표로 마무리합니다: KV 전송 P99 지연; 계획서가 정한 임계값을 넘으면 관문을 쳐서 막습니다.
