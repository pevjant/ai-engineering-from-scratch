> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-batch-triager.md](skill-batch-triager.md)

워크로드(이름, 지연 시간에 대한 사용자 기대, 트래픽 볼륨, 공유 프롬프트 구조)가 주어지면 분류 + 비용 계획을 만들어 냅니다.

산출물:

1. 차선. 대화형(TTFT 제약, 동기식), 준대화형(몇 분 OK, 비동기 큐), 배치(아침까지 OK, 배치 API) 중 하나. 구체적인 사용자 기대를 근거로 정당화합니다.
2. 현재 비용. 현재 구성(동기식, 캐시 없음 등) 기준 월간 비용을 계산합니다.
3. 목표 비용. 권고 구성(배치 + 캐시 또는 동기 + 캐시) 이후의 비용을 계산합니다. 현재 대비 %로 표현합니다.
4. 마이그레이션 계획. 프로바이더별 절차(워크로드의 모델에 맞는 것 하나만 고릅니다):
   - OpenAI: `/v1/batches`로 마이그레이션. 자격이 되는 프롬프트(1024 토큰 이상)에는 프롬프트 캐싱이 자동 활성화됩니다 — 설정할 `cache_control`이 없습니다. 더 촘촘한 귀속(attribution)을 원하면 `prompt_cache_key`를 선택적으로 전달합니다.
   - Anthropic: Message Batches로 마이그레이션. 캐시 재사용에는 캐시 가능한 프롬프트 구간에 명시적 `cache_control` 블록(예: `{"type": "ephemeral"}`)이 필요합니다; 배치 할인은 캐시 읽기 가격과 스택으로 묶입니다.
   - 공통: 성공/실패 웹훅과, 처리 시간을 놓친 배치를 동기로 보내는 스플오버 차선을 계측합니다.
5. 위험. 배치 처리가 P99에서 20시간이면 어떻게 됩니까? 다운스트림 시스템 동작(이메일 전달, 동기로 넘기는 큐 스플오버)을 명시합니다.
6. 관측 지표. 오분류를 잡아내는 메트릭: 배치 작업 완료 지연 P95; 12시간을 넘으면 알림.

하드 리젝(무조건 거절):

- 사용자가 "아침까지" 지연만 필요한데 하룻밤 파이프라인을 배치 없이 동기 모드로 돌리는 것. 거절하세요 — 유출되는 지출 약 90%를 지목합니다.
- 사용자 기대가 15분 미만인 모든 것에 배치를 약속하는 것. 거절하세요 — 배치 SLA는 24시간입니다.
- 공유 시스템 프롬프트가 있는 배치 워크로드에서 프롬프트 캐싱을 무시하는 것. 거절하세요 — 스택 할인이 바로 핵심입니다.

거절 규칙:

- 워크로드가 "실시간"으로 마케팅되는데 실제 사용자 기대는 몇 분 수준이라면, 배치를 권고하기 전에 명시적 확인을 요구합니다.
- 워크로드가 배치에서 프롬프트 캐싱을 지원하지 않는 프로바이더를 타깃으로 한다면(KV 프리픽스 재사용이 없는 커스텀/셀프호스팅 스택 등), 배치 할인만 적용된다고 명시하고 스택 절감을 빼고 다시 계산합니다. OpenAI 배치 캐싱은 자동입니다; Anthropic 배치 캐싱은 명시적 `cache_control` 블록이 필요합니다.
- 워크로드에 엄격한 지연 SLA(예: P99 < 60초)가 있다면 배치를 아예 거절합니다 — 다른 차선에 속합니다.

출력: 차선, 현재 비용, 목표 비용, 마이그레이션 절차, 위험, 관측 지표를 담은 한 페이지짜리 분류서. 주기(cadence)로 마무리합니다: 제품 표면이 바뀔 때마다 분기마다 모든 워크로드를 재분류할 것.
