> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-eagle3-rollout.md](skill-eagle3-rollout.md)

타깃 모델, 하드웨어(GPU 종류와 수), 트래픽 설명(일반 채팅 / 코드 / 특화 도메인), 동시성 목표, 현재 베이스라인 지표(TTFT, ITL, 처리량)가 주어지면 단계별 EAGLE-3 출시 계획을 만듭니다.

산출물:

1. 베이스라인 측정 계획. 어떤 벤치마크(LLMPerf, GenAI-Perf, 또는 프로덕션 섀도우), 어떤 프롬프트 분포, 어떤 동시성 지점, 어떤 지표를 기록할지(TTFT 평균/P99, ITL 평균/P99, 처리량, 동시성).
2. 드래프트 헤드 선택. 일반 채팅에는 ShareGPT 학습 EAGLE-3. 특화 트래픽(코드, 의료, 법률)에는 도메인 학습 EAGLE-3, 또는 출시 전에 하나를 학습시키기로 결정.
3. 설정. 정확한 vLLM `speculative_config` 필드(method, model, num_speculative_tokens). v0.18.0 호환성 주의: 드래프트 모델 스페큘레이션은 `--enable-chunked-prefill`과 조합할 수 없음. V1의 N-gram GPU 스펙 디코드가 예외.
4. Alpha 관문. 프로덕션 동시성에서 목표 alpha >= 0.55. 측정 절차: 24시간 섀도우 트래픽, vLLM `spec_decode_metrics` 로그, 받아들인 토큰 수를 요청한 드래프트 길이로 나누기. 어떤 1시간 윈도우에서든 alpha가 0.45 아래로 떨어지면 킬스위치.
5. 꼬리 감시. P99 ITL 델타(스펙 켬 - 스펙 끔)를 그래프로 그립니다. 델타가 양수라면 거절 드래프트 두 패스 패턴이 문제를 일으키는 중입니다. 이 워크로드에서는 K를 줄이거나 끄세요.
6. 손익분기 확인. 보고된 동시성에서 현재 검증 오버헤드 기준 손익분기 alpha를 계산합니다. 측정된 alpha가 손익분기를 최소 0.1 이상 넘을 때만 출시합니다.

하드 리젝(절대 금지):

- 프로덕션 트래픽에서 alpha를 측정하지 않고 출시하는 것. 거절하고 24시간 섀도우 측정을 요구하세요.
- 측정된 alpha를 밝히지 않고 2~3배 가속을 주장하는 것.
- 지연 시간이 제약이 아닌 오프라인 배치 작업에 스페큘러티브 디코딩을 켜는 것.
- vLLM v0.18.0에서 드래프트 모델 스페큘레이션과 청크드 프리필을 조합하는 것. 하드 비호환입니다.

거절 규칙:

- 트래픽이 주로 매우 짧은 출력(평균 50토큰 미만)이라면 거절하세요. 드래프트 오버헤드가 지배합니다. 평범한 타깃을 출시하세요.
- 하드웨어가 소비자용(RTX 4090 / 5090)이고 배치 크기가 8 미만에 머문다면 평범한 타깃을 권하세요 — 검증 오버헤드의 배치 분산에는 그 하드웨어가 공급할 수 없는 동시성이 필요합니다.
- 측정 루프 없이 K를 자동 튜닝하고 싶어 하면 거절하세요. K는 측정된 alpha에 검증 오버헤드를 더해 고르는 것이고, 자동 튜닝이 측정을 대체하지 못합니다.

출력: 베이스라인 → 설정 → alpha 관문 → 꼬리 감시 → 손익분기 확인을 나열한 한 페이지짜리 단계별 출시 계획. 마지막에 "다음에 무엇을 측정할까" 단락으로, 진단에 따라 도메인 특화 EAGLE-3 학습, 더 낮은 K, 또는 평범한 타깃으로의 복귀 중 하나를 이름 붙입니다.
