# 프로덕션(운영 환경)의 EAGLE-3 스페큘러티브 디코딩

> 스페큘러티브 디코딩은 빠른 드래프트(draft) 모델을 타깃 모델에 짝지어 씁니다. 드래프트가 K개 토큰을 제안하면, 타깃이 포워드 한 번으로 전부 검증하고, 받아들여진 토큰들은 사실상 공짜입니다. 2026년에 프로덕션급 변형은 EAGLE-3입니다. 원시 토큰이 아니라 타깃 모델의 히든 스테이트(hidden state) 위에 드래프트 헤드를 학습시키기 때문에, 일반 채팅에서 수용률(acceptance rate) alpha가 0.6~0.8 구간까지 올라갑니다. 올바른 질문은 "드래프트가 얼마나 빠른가"가 아니라 "내 트래픽에서 alpha가 얼마인가"입니다. alpha가 약 0.55 아래로 떨어지면, 높은 동시성에서 스페큘러티브 디코딩은 순손실입니다 — 거절된 드래프트 하나하나가 타깃 포워드를 한 번 더 요구하니까요. 이 레슨은 alpha를 먼저 측정하고 플래그를 나중에 켜는 법을 가르칩니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, 장난감 수준 수용률 시뮬레이터)
**선수 지식:** Phase 17 · 04 (서빙 엔진 내부 구조), Phase 10 · 18 (멀티 토큰 예측)
**시간:** 약 60분

## 학습 목표

- 스페큘러티브 디코딩의 세 세대를 말하고, EAGLE-3가 EAGLE-2와, 그리고 고전적 드래프트 모델과 무엇이 다른지 설명할 수 있다.
- 수용률 alpha를 정의하고, alpha와 K(드래프트 길이)로 기대 가속 배율을 계산하며, 목표 동시성에서의 손익분기 alpha를 찾을 수 있다.
- vLLM 2026에서 스페큘러티브 디코딩이 기본값이 아니라 옵트인(opt-in)인 이유, 그리고 alpha를 측정하지 않고 켜는 것이 프로덕션 안티패턴인 이유를 설명할 수 있다.
- 측정 계획을 작성할 수 있다: 어떤 벤치마크, 어떤 프롬프트 분포, 어떤 동시성 지점, 어떤 지표로 관문(gate)을 만들지.

## 문제 상황

디코드는 메모리 바운드입니다. H100에서 Llama 3.3 70B FP8을 돌리면, 토큰 하나를 디코드할 때마다 가중치 약 140GB/s를 읽고 토큰 하나를 내놓습니다. 디코드 동안 GPU 컴퓨트는 거의 놀고 있습니다 — 병목은 matmul 처리량이 아니라 HBM 대역폭입니다.

스페큘러티브 디코딩은 이 간격을 이용합니다. 값싼 드래프트 모델로 후보 토큰 K개를 만들고, 타깃 모델에게 그 K개를 포워드 한 번으로 전부 검증하게 합니다. 검증된 토큰 하나하나는 사실상 공짜입니다(어차피 해야 했던 '배치 K개짜리 포워드'에 분산되니까요).

고전적 드래프트 모델 방식은 같은 계열의 더 작은 모델을 씁니다(Llama 3.3 70B에 Llama 3.2 1B가 드래프트). 동작은 하지만 수용률이 애매합니다 — 작은 모델의 분포가 타깃에서 벗어나니까요. EAGLE, EAGLE-2, EAGLE-3로 오며, 타깃 모델의 내부 상태에 가벼운 드래프트 헤드를 직접 학습시켜서 드래프트의 분포가 타깃을 훨씬 밀접하게 따라가게 합니다. 그래서 alpha가 드래프트 모델의 0.4에서 EAGLE-3의 0.6~0.8로 올라갑니다.

함정은 이것입니다. vLLM 2026에서 EAGLE-3는 옵트인입니다. `speculative_config`를 명시적으로 설정해야 합니다. 플래그가 없으면 가속도 없습니다. 실제 트래픽에서 alpha를 측정하지 않고 켠 팀들은 꼬리 지연이 좋아지기는커녕 나빠지는 경우가 많습니다.

## 개념

### 스페큘러티브 디코딩이 실제로 사다 주는 것

스펙 디코딩이 없으면 토큰당 비용은 타깃 포워드 한 번입니다. 드래프트 길이 K, 수용률 alpha인 스펙 디코딩에서는 타깃 포워드당 기대 토큰 수가 `1 + K * alpha`입니다. 가속 배율은 `(1 + K * alpha) / (1 + epsilon)`이고, epsilon은 드래프트+검증 오버헤드입니다. K=5, alpha=0.7이면 `(1 + 5*0.7) / (1 + 0.1) = 4.5 / 1.1 = 4.1배`입니다. 실제 숫자들은 2~3배에 모입니다. 프로덕션 트래픽에서 alpha가 그만큼 높게 나오는 경우가 드물고, 배치가 커지면 epsilon도 커지기 때문입니다.

### alpha만이 유일하게 중요한 지표인 이유

거절된 토큰은 사라지지 않습니다 — 거절된 첫 토큰 때문에 타깃 포워드가 한 번 더 필요해집니다. alpha가 0.4로 떨어지는 워크로드에서는 드래프트 오버헤드 + 검증 + 재시도(re-roll)를 전부 지불합니다. 높은 동시성(예: 동시 256)에서는 디코드 배치가 이미 충분히 커서 "타깃 단독"과 "타깃 + 검증" 사이의 메모리 대역폭 격차가 줄어듭니다. 대부분의 2026년 하드웨어에서 alpha 0.55 미만이면 스펙 디코딩은 순손실입니다.

alpha는 워크로드마다 다릅니다. ShareGPT식 일반 채팅에서는 ShareGPT로 학습한 EAGLE-3가 0.6~0.8을 기록합니다. 도메인 특화 트래픽(코드, 의료, 법률)에서는 일반 데이터로 학습한 드래프트 헤드가 0.4~0.6으로 떨어집니다. 도메인 특화 드래프트 헤드를 학습시키면 alpha가 회복됩니다 — 타깃 파인튜닝에 비하면 가볍고 빠른 학습 작업입니다.

### 한눈에 보는 EAGLE 세대

- **고전적 드래프트 모델**: 같은 계열의 작은 모델. Alpha 0.3~0.5. 인프라는 단순 — 모델 두 개를 띄우고, 타깃 포워드 하나에 드래프트가 K번 포워드.
- **EAGLE-1 (2024)**: 타깃 히든 스테이트(마지막 레이어) 위에 학습한 단일 드래프트 헤드. Alpha 약 0.5~0.6. 타깃 위에 파라미터 부담이 작음.
- **EAGLE-2 (2025)**: 적응형 드래프트 길이와 트리 기반 드래프트(여러 분기를 타깃 패스 한 번으로 검증). Alpha 약 0.6~0.7. 드래프트 스케줄러가 더 복잡함.
- **EAGLE-3 (2025-2026)**: 마지막 레이어만이 아니라 타깃의 여러 레이어 위에 드래프트 헤드를 학습, 정렬(alignment)이 더 좋음. 일반 채팅에서 Alpha 약 0.6~0.8.

### 2026년 프로덕션 레시피

1. 타깃 모델을 평범하게(plain) 출시합니다. 목표 동시성에서 베이스라인 TTFT, ITL, 처리량을 측정합니다.
2. vLLM `speculative_config`로 EAGLE-3 드래프트를 켭니다. 벤치마크를 다시 돌립니다.
3. 수용률 alpha를 로그로 남깁니다. vLLM V1은 이것을 `spec_decode_metrics.accepted_tokens_per_request`로 보고합니다. 요청한 드래프트 길이로 나누면 alpha가 나옵니다.
4. 프로덕션 트래픽 분포에서 alpha < 0.55라면 스펙 디코딩을 끄거나, 도메인 특화 EAGLE-3 드래프트를 학습합니다.
5. 프로덕션 동시성에서 다시 실행합니다. P99 ITL이 나빠지지 않았는지 확인합니다.

### 프로덕션 함정: P99 꼬리

평균 ITL은 스펙 디코딩으로 떨어집니다. 튜닝하지 않으면 P99는 나빠질 수 있습니다. 거절된 드래프트는 두 패스 시퀀스(드래프트 + 검증 실패 + 재시도)를 유발하는데, 배치가 꽉 차면 이 두 패스는 직렬화됩니다. P50이 아니라 P99 ITL을 보세요.

### EAGLE-3가 이미 배포된 곳

Google은 2025년 AI Overviews에 스페큘러티브 디코딩을 배포했습니다(같은 품질, 더 빠른 응답). vLLM V1은 `speculative_config`를 문서화된 인터페이스로 제공하고, V1의 N-gram GPU 스페큘러티브 디코딩은 청크드 프리필과 호환되는 변형입니다. SGLang은 프리픽스가 많은 워크로드에 권장되는 드래프트 경로로 EAGLE-3를 지원합니다.

### 한 줄 손익분기 계산

기대 가속 배율: `S(alpha, K) = (1 + K*alpha) / (1 + verify_overhead)`. `S = 1`로 풀면 `alpha_breakeven = verify_overhead / K`. 전형적인 verify_overhead 약 0.15, K=5이면 `alpha_breakeven = 0.03`입니다. 하지만 이건 날것의 디코드 계산입니다. 높은 동시성에서는 검증 오버헤드가 올라가고, 디코드 배치가 이미 메모리 읽기를 여러 시퀀스에 분산해 버리기 때문에, 실질적인 alpha_breakeven은 실전에서 약 0.45~0.55까지 올라갑니다.

### 스페큘러티브 디코딩을 쓰면 안 되는 때

- 지연 시간이 상관없는 배치 1 오프라인 생성. 평범한 타깃을 쓰세요.
- 매우 짧은 출력(50토큰 미만). 드래프트 오버헤드와 검증 비용이 지배합니다.
- 도메인 학습된 드래프트 헤드가 없는 특화 도메인. alpha가 너무 낮습니다.
- vLLM v0.18.0 + 드래프트 모델 스펙 디코드 + `--enable-chunked-prefill`. 이 조합은 컴파일되지 않습니다. 문서화된 예외는 V1의 N-gram GPU 스펙 디코딩입니다.

## 직접 써보기

`code/main.py`는 여러 alpha 값과 드래프트 길이 K 범위에서, 스페큘러티브 디코딩을 켠 경우와 끈 경우의 디코드 루프를 시뮬레이션합니다. 손익분기 alpha, 측정된 가속 배율, 꼬리 동작을 출력합니다. 여러 (alpha, K) 조합으로 실행해 보면 스페큘러티브 디코딩이 더 이상 이득이 되지 않는 지점이 정확히 어디인지 보입니다.

## 산출물

## 연습 문제

1. `code/main.py`를 실행하세요. K=5일 때 2배 가속에는 alpha가 얼마나 필요한가요? 3배는요? verify_overhead에 얼마나 민감한가요?
2. 프로덕션 트래픽이 일반 채팅 70%, 코드 30%로 갈린다고 상상해 보세요. 일반 채팅은 ShareGPT 학습 EAGLE-3에서 alpha 0.7, 코드는 alpha 0.4입니다. 혼합 alpha는 얼마이고, 스펙 디코딩이 순이익인가요?
3. vLLM `speculative_config` 문서를 읽으세요. 세 가지 모드(드래프트 모델, EAGLE, N-gram)를 말하고, 청크드 프리필과 호환되는 것은 어느 것인지 답하세요.
4. EAGLE-3를 켠 뒤 평균 ITL은 25% 떨어졌는데 P99 ITL은 15% 올랐습니다. 진단하고 완화 방안을 제안하세요.
5. Llama 3.3 70B를 위한 EAGLE-3 드래프트 헤드의 메모리 비용을 계산하세요. 고전적 드래프트로 Llama 3.2 1B를 도는 것과 비교하면 어떤가요?

|------|----------------|------------------------|
| 스페큘러티브 디코딩 | "드래프트 + 검증" | 값싼 모델로 K개 토큰을 제안하고, 타깃 포워드 한 번으로 전부 검증 |

| 드래프트 길이 K | "스펙 k" | 타깃 포워드 하나에 드래프트가 제안하는 토큰 수. 보통 4~8 |
| 검증 오버헤드 epsilon | "스펙 오버헤드" | 평범한 타깃 포워드 대비 검증+재시도의 추가 비용. 배치가 커질수록 증가 |
| EAGLE-3 | "최신 EAGLE" | 2025-2026 변형. 타깃 여러 레이어 위에 드래프트 헤드 학습. 일반 채팅에서 alpha 0.6~0.8 |
| `speculative_config` | "vLLM 스펙 설정" | vLLM V1의 명시적 옵트인. 기본값이 없으면 가속도 없음 |
| N-gram 스펙 디코드 | "N-gram 드래프트" | 프롬프트 안의 N-gram 조회로 도는 GPU 측 드래프트. 청크드 프리필 호환 |
| 손익분기 alpha | "제로 이득 alpha" | 스펙 디코딩이 가속을 하나도 못 주는 alpha. 프로덕션 동시성에서 이것을 보라 |
| 거절 드래프트 두 패스 | "재시도 비용" | 드래프트가 거절될 때 타깃 포워드 두 번. P99 꼬리를 밀어 올림 |
