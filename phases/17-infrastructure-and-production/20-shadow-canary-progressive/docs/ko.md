# LLM을 위한 섀도우 트래픽, 카나리 롤아웃, 점진적 배포

> LLM 롤아웃은 소프트웨어 배포에서 가장 어려운 부분들을 결합합니다: 유닛 테스트가 없고, 실패 양상이 분산되어 있고, 신호가 늦게 옵니다. 순서는 이렇습니다. (1) 섀도우 모드 — 운영 요청을 후보 모델에 복제해 기록하고, 사용자 영향 없이 비교합니다; 눈에 띄는 분포 문제는 잡아주지만 품질 보장은 아닙니다. (2) 카나리 롤아웃 — 트래픽을 10% → 25% → 50% → 75% → 100%로 점진적으로 옮기며 각 단계마다 관문을 겁니다; 지연 백분위, 요청당 비용, 오류/거절률, 출력 길이 분포, 사용자 피드백률을 추적합니다. (3) 안정성이 확인된 뒤 뚜렷이 다른 대안들을 위해 A/B 테스트. 비결정성은 줄일 수 없습니다 — GPU 부동소수점 연산의 결합 법칙 위반(non-associativity)에 배치 크기 편차가 더해져, 같은 입력으로도 실행마다 최대 15% 정확도 편차가 납니다. 비용은 상수가 아니라 변수입니다 — 20% 더 나은 모델이 호출당 3배 비쌀 수 있습니다. 롤백 속도가 결정적입니다: 롤백에 재배포가 필요하다면 너무 느린 것입니다. 정책은 설정/플래그에 있고; 모델은 다이제스트를 고정해 레지스트리에 있으므로; 롤백 = 정책 플립 + 임계값 복귀 + 이전 모델 고정이 몇 초 안에 끝납니다.

**유형:** 학습
**언어:** Python (표준 라이브러리, 카나리 진행 시뮬레이터 장난감 버전)
**선수 지식:** 페이즈 17 · 13 (관측 가능성), 페이즈 17 · 21 (A/B 테스팅)
**시간:** 약 60분

## 학습 목표

- 섀도우 모드(영향 없는 비교), 카나리(실트래픽 점진), A/B(안정성 확인 후 비교)를 구분할 수 있습니다.
- LLM 특화 카나리 메트릭 다섯 가지(지연, 요청당 비용, 오류/거절, 출력 길이 분포, 사용자 피드백)를 나열할 수 있습니다.
- LLM 비결정성(최대 15%)이 왜 롤아웃에서 "안정적"의 의미를 바꾸는지 설명할 수 있습니다.
- 몇 시간(재배포)이 아니라 몇 초(정책 플립) 만에 끝나는 롤백 경로를 설계할 수 있습니다.

## 문제 상황

새 모델을 출시했습니다. 오프라인 평가는 3% 정확도 향상을 보여줍니다. 프로덕션(운영 환경)에서 켭니다. 24시간 안에 비용은 40% 오르고, 사용자 싫어요는 8% 오르고, 고객 티켓 세 개가 "이상한 답변"을 보고합니다. 롤백합니다. 재배포에 3시간 걸립니다. 주말이 망했습니다.

그 모든 것은 피할 수 있었습니다. 섀도우 모드가 있었다면 어떤 사용자도 보기 전에 40% 비용 폭증을 잡았을 겁니다. 카나리가 있었다면 싫어요가 움직이는 시점의 10%에서 멈췄을 겁니다. 정책 플래그 롤백이었다면 30초면 끝났을 겁니다. 이 규율이 "오프라인 평가가 좋아 보임"과 "실제 사용자가 만족함" 사이의 간극을 메웁니다.

## 개념

### 섀도우 모드

후보 모델은 운영과 같은 요청을 받습니다; 출력은 기록만 되고 사용자에게 돌려주지 않습니다. 사용자 영향 제로. 기록할 것:

- 출력 내용(운영과의 diff).
- 토큰 수(비용 델타).
- 지연 시간.
- 거절과 오류.

잡아주는 것: 비용 폭증, 길이 회귀, 눈에 띄는 거절 변화, 하드 오류. 잡아주지 못하는 것: 사용자가 느낄 품질 차이. 섀도우는 스모크 테스트이지 품질 테스트가 아닙니다.

### 카나리 롤아웃

관문을 걸면서 트래픽을 점진적으로 옮깁니다. 전형적인 진행: 1% → 10% → 25% → 50% → 75% → 100%. 각 단계에서 5가지 메트릭에 관문을 겁니다:

1. **지연 백분위** — P50, P95, P99. 위반: 카나리의 P99가 베이스라인의 1.5배 초과.
2. **요청당 비용** — 혼합 달러. 위반: 베이스라인 대비 20% 초과.
3. **오류 / 거절률** — 5xx와 명시적 거절 합산. 위반: 베이스라인의 2배.
4. **출력 길이 분포** — 평균 + P99. 위반: 분포 변화.
5. **사용자 피드백률** — 싫어요 / 티켓 접수. 위반: 베이스라인의 1.5배.

### 비결정성이 새로운 분산입니다

같은 입력이 같지 않은 출력을 냅니다. 이유:

- GPU FP 비결합성(부동소수점 축소 순서가 배치마다 다름).
- 배치 크기 편차(같은 프롬프트가 128짜리 배치와 16짜리 배치에서 다름).
- 샘플링(temperature > 0).

측정 결과: 동일한 평가 세트에서 실행마다 최대 15% 정확도 편차. 롤아웃에서 "안정적"은 베이스라인과 동일하다는 뜻이 아니라 메트릭이 예상 분산 안에 있다는 뜻입니다. 관문은 노이즈 바닥 위에 설정하세요.

### 비용은 변수입니다

20% 더 나은 모델이 호출당 3배 비쌀 수 있습니다. 요청당 비용은 다섯 관문 중 하나입니다. 단위 경제학을 깨는 "더 나은" 모델 출시는 롤백 사례입니다.

### 롤백이 곧 무기입니다

- 정책 플래그(피처 플래그 시스템): 설정에서 비율을 플립; 몇 초 걸립니다.
- 모델 고정(레지스트리 다이제스트): 고정된 모델은 자동 업그레이드되지 않습니다.
- 롤백 = 플래그 복귀 + 고정 다이제스트를 이전으로. 몇 초지, 몇 시간이 아닙니다.

스택이 롤백에 재배포를 요구한다면, 롤링하기 전에 그것부터 고치세요.

### 도구

**Argo Rollouts** / **Flagger** — Kubernetes 점진적 배포 컨트롤러. Istio/Linkerd 가중 라우팅과 통합됩니다.

**Istio 가중 라우팅** — 서비스 메시 수준의 트래픽 분할.

**KServe / Seldon Core** — 카나리가 내장된 모델 서빙.

**피처 플래그** — LaunchDarkly, Flagsmith, Unleash. 정책 수준 플립, 재배포 없음.

### 메트릭 주기

카나리 관문은 트래픽 볼륨에 따라 5-15분마다 검사합니다. 분당 10 요청짜리 1% 트래픽은 창당 50-150개 데이터 포인트를 줍니다 — 지연에는 충분하지만 사용자 피드백에는 노이즈가 큽니다. 10%면 약 10배 더 줍니다. 진행 단계는 각 단계에서 충분한 샘플이 쌓일 만큼 오래 멈춰 있어야 합니다.

### A/B 단계는 선택입니다

새 모델이 뚜렷이 다르다면(다른 동작, 다른 비용 곡선, 다른 톤), 카나리 통과 후 50%에서 A/B 테스트를 합니다. 그저 개선된 버전이라면 카나리 관문이 통과하면 곧바로 100%로 갑니다.

### 기억해야 할 숫자들

- 카나리 진행: 1% → 10% → 25% → 50% → 75% → 100%.
- 비결정성 상한: 동일 입력에서 실행 간 최대 15% 편차.
- 카나리 메트릭 다섯 가지: 지연, 비용, 오류/거절, 출력 길이, 사용자 피드백.
- 비용 관문: 베이스라인 대비 20% 초과면 위반.
- 롤백: 몇 초지, 몇 시간이 아닙니다.

## 출시하기

이 레슨은 `outputs/skill-rollout-runbook.md`를 산출합니다. 후보 모델, 베이스라인, 위험 허용도가 주어지면 섀도우→카나리→100% 계획을 설계합니다.

## 연습 문제

1. `code/main.py`를 실행하세요. 25% 비용 회귀를 주입하세요. 카나리는 어느 단계에서 멈추나요?
2. 새 모델이 오프라인에서 3% 정확도 향상이지만 요청당 비용이 +18%입니다. 출시할까요? 정책에 달렸습니다 — 양쪽 경로를 작성하세요.
3. 종단 간 60초 미만의 롤백을 설계하세요. 필요한 인프라를 나열하세요.
4. 평가에서 ±7%의 비결정성이 보입니다. 오탐을 내지 않도록 카나리 관문을 설정하세요. 어떤 배수를 쓰시겠습니까?
5. 섀도우 모드가 카나리 전에 40% 비용 폭증을 잡습니다. 섀도우에서 작동할 알림 규칙을 작성하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| 섀도우 모드 | "신규로 복제" | 기록을 위해 후보에게 영향 없이 전송 |
| 카나리 | "점진적 트래픽" | 관문을 건 점진적 사용자 노출 롤아웃 |
| 관문(Gates) | "롤아웃 검사" | 진행을 막는 메트릭 임계값 |
| 비결정성 | "LLM 분산" | 줄일 수 없는 실행 간 차이 |
| 정책 플래그 | "플래그 플립 롤백" | 설정 수준 롤백, 몇 시간 아닌 몇 초 |
| 모델 고정(Pin) | "레지스트리 다이제스트" | 모델 버전에 대한 불변 참조 |
| Argo Rollouts | "K8s 점진 배포" | Kubernetes 네이티브 카나리/롤백 컨트롤러 |
| KServe | "추론 K8s" | 카나리 프리미티브를 갖춘 모델 서빙 |
| Istio 가중 | "메시 분할" | 서비스 메시 트래픽 분할기 |
