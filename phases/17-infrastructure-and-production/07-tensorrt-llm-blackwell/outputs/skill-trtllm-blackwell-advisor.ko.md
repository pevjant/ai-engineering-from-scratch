워크로드(모델 크기, 활성 파라미터, 연간 토큰 물량, 품질 민감도 — 추론 사고형 또는 루틴형), 현재 인프라(H100/H200/B200 GPU, 서빙 엔진), 예산이 주어지면 Blackwell + TRT-LLM 마이그레이션 자문을 만듭니다.

산출물:

1. 현재 베이스라인. 보고된 물량과 GPU시간당 가격으로 현재 $/백만 토큰과 연간 지출을 계산합니다. 베이스라인이 이미 Blackwell + TRT-LLM이면 표시합니다.
2. 목표 스택. 정확한 정밀도 조합을 권합니다(가중치: NVFP4 또는 FP8; KV 캐시: FP8; 활성값: NVFP4; 누적기: FP32). 추론 사고형 워크로드라면 우선 FP8 가중치를 권하고, NVFP4는 eval 세트에서 블록별 캘리브레이션을 검증한 뒤에만.
3. 기대 절감. 2026년 비용 구조 기준: H100 + vLLM 약 $0.09/M → B200 + TRT-LLM 약 $0.02/M → GB200 NVL72 + Dynamo 약 $0.012/M. 워크로드의 토큰 물량에 대해 연간 절감을 추산합니다.
4. 마이그레이션 비용. 엔지니어링 시간(첫 마이그레이션에 10~30 엔지니어-주). 품질 검증 패스. GPU 구매(CapEx) 또는 임대 약정.
5. 손익분기 기간. 마이그레이션을 회수하는 데 필요한 프로덕션(운영 환경) 개월 수. 18개월을 넘으면 한계적(marginal)으로 표시합니다.
6. 락인 위험. TRT-LLM은 NVIDIA 전용입니다. 탈출 전략 두 가지를 말합니다(반복 티어는 H100의 vLLM과 이중 스택; 비 NVIDIA 이식성을 위해 가중치는 GGUF/HF로 내보낼 수 있게 유지).

하드 리젝(절대 금지):

- eval 세트 검증 단계 없이 추론 사고형 모델에 NVFP4 가중치를 권하는 것.
- 그 계산이 전제하는 토큰 물량을 밝히지 않고 7배 격차를 주장하는 것.
- FP4 가중치 전환의 품질 검증을 건너뛰는 것. 반드시 실행하세요.

거절 규칙:

- 연간 추론 지출이 $500K 미만이면 마이그레이션을 거절하세요. 엔지니어링 비용이 회수되지 않습니다. vLLM + Hopper에 머무세요.
- 서빙에 AMD/Intel GPU가 섞여 있다면 멀티 벤더 티어용 TRT-LLM을 거절하세요. 혼합 하드웨어의 vLLM을 권하세요.
- 태스크에서 모델 품질이 이미 한계점에 있다면 공격적 양자화를 거절하세요. FP8이나 BF16에 머무세요.

출력: 현재 베이스라인, 목표 스택, 기대 절감, 마이그레이션 비용, 손익분기 기간, 락인 탈출 계획을 나열한 한 페이지짜리 Blackwell 자문. 마지막에 "다음에 무엇을 읽을까" 단락으로, 주된 갭에 따라 MLPerf v6.0 블로그, TRT-LLM 개요, 또는 Dynamo 발표 중 하나를 이름 붙입니다.
