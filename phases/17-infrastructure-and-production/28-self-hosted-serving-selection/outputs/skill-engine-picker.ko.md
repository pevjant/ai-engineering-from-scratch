> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-engine-picker.md](skill-engine-picker.md)

하드웨어(CPU / Apple Silicon / AMD / NVIDIA Hopper / NVIDIA Blackwell), 규모(단일 사용자 / 소규모 팀 / 프로덕션 / 엔터프라이즈), 워크로드(일반 챗 / 에이전트형 / RAG / 긴 컨텍스트 / 코드)를 입력받아 엔진 추천을 만듭니다.

산출물:

1. 엔진. 구체적인 엔진을 지목합니다. 하드웨어 우선, 규모 두 번째, 워크로드 세 번째 트리를 근거로 인용합니다.
2. 왜 대안들이 아닌지. 각 대안 엔진마다 선택되지 않은 이유를 밝힙니다(TGI 유지보수 모드, AMD는 TRT-LLM 배제, Ollama는 개발 전용).
3. 파이프라인. 프로덕션이라면 파이프라인 패턴(개발 Ollama → 스테이징 llama.cpp → 프로덕션 vLLM/SGLang)을 명시하고, 가중치 포맷(GGUF 또는 HF)이 흐름을 타는지 확인합니다.
4. 프로덕션 스태킹. 프로덕션 규모라면 조합을 위해 페이즈 17 · 18(프로덕션 스택), · 17(이기종 분리 배치), · 11(캐시 인지 라우터)을 가리킵니다.
5. TGI 마이그레이션. 기존 인프라가 TGI라면 마이그레이션 계획과 일정을 명시합니다 — 급하진 않지만 6개월 안에는 시작해야 합니다.
6. 하드웨어 함정. 두 가지 확실한 제약을 짚습니다: CPU 전용 → llama.cpp. AMD → TRT-LLM 불가.

절대 거부 사항:
- 2026년 새 프로젝트의 기본값을 TGI로 잡는 것. 거부 — 유지보수 모드입니다.
- 동시 사용자 1명을 넘는 공유 프로덕션에서 Ollama를 쓰는 것. 거부 — 처리량 격차가 있습니다.
- NVIDIA 전용임을 확인하지 않고 TRT-LLM을 제안하는 것. 거부 — AMD / 비 NVIDIA는 확실한 차단 사항입니다.

거부 규칙:
- 하드웨어가 섞여 있다면(일부 AMD, 일부 NVIDIA) 클러스터별 엔진 결정을 요구하세요. 하나의 엔진을 강요하지 않습니다.
- 프로덕션 규모인데 워크로드가 "미지수/일반"이라면 vLLM을 기본으로 하고, 3개월의 트래픽 데이터가 쌓인 뒤 재평가를 계획하세요.
- 팀이 "Blackwell 가용성 없이 GPU당 최고 속도"를 원하고 Hopper 전용을 고집한다면 확인하세요 — TRT-LLM과 vLLM 둘 다 받아들일 수 있습니다.

출력: 엔진, 기각된 대안, 파이프라인, 프로덕션 스태킹, TGI 마이그레이션 자세를 담은 한 페이지짜리 추천서. 마지막에 단 하나의 분기 리뷰를 붙입니다: 워크로드 형태가 실질적으로 바뀌면 엔진 선택을 재평가합니다.
