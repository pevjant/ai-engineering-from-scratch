> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-chaos-plan.md](skill-chaos-plan.md)

스택(Kubernetes / VM / 매니지드), SLI/SLO 성숙도, 관측 가능성 품질, 팀 온콜 성숙도를 입력받아 카오스 계획을 만듭니다.

산출물:

1. 필수 조건 점검. SLI/SLO 정의 여부, 관측 가능성 연결 여부, 자동 롤백 여부, 런북 구조화 여부, 온콜 로테이션 여부를 확인합니다. 하나라도 빠져 있으면 프로덕션 카오스 실행을 거부합니다.
2. 네 개의 평면. 각 평면(제어, 대상, 안전, 관측 가능성)에 쓸 도구를 정합니다. 관측 가능성은 페이즈 17 · 13을 참조합니다.
3. 초기 실험 세 가지. 파드 킬로 시작합니다. 그다음 공급자 429, 그다음 메모리 과부하. 각 실험마다 폭발 반경 상한, 지속 시간, 성공 기준을 명시합니다.
4. 안전 게이트. 번 레이트(예상의 2배 초과), 폭발 반경(플릿의 30% 미만), 트레이스-ID 태깅, 억제 윈도우.
5. 주기. 주간 소규모 카나리. 월간 게임 데이(팀 간). 분기 복원력 감사.
6. 도구. LitmusChaos (오픈소스, CNCF 졸업), Chaos Mesh (오픈소스, CNCF 샌드박스), Harness Chaos (상용, AI 지원), AWS FIS / Azure Chaos Studio (매니지드 클라우드 네이티브).

절대 거부 사항:
- 다섯 가지 필수 조건 없이 프로덕션에서 카오스 실행. 거부 — 실제 인시던트가 됩니다.
- 폭발 반경 상한 없는 실험. 거부.
- 트레이스-ID 태깅 없는 실험. 거부 — 알림 중복 제거가 불가능합니다.

거부 규칙:
- 팀이 스테이징에서 성공적인 실험을 단 한 번도 해 본 적이 없다면, 스테이징에서 하나가 그린이 될 때까지 프로덕션 카오스를 거부하세요.
- 인시던트 발생량이 이미 많다면(주 2건 초과) 카오스 추가를 거부하세요 — 먼저 안정화부터.
- 팀에 SLO가 없다면, 어떤 실험보다 먼저 SLO 정립을 요구하세요.

출력: 필수 조건 점검, 네 평면 도구, 초기 실험 세 가지, 안전 게이트, 주기를 담은 한 페이지짜리 계획서. 마지막에 분기별 의존성 맵 업데이트 약속을 붙입니다.
