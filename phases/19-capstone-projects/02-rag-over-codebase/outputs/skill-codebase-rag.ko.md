> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-codebase-rag.md](skill-codebase-rag.md)

총 200만 줄 이상의 코드를 담은 저장소 10개 이상이 주어지면, 수집 파이프라인과 하이브리드 인덱스, 그리고 검증 가능한 file:line 앵커로 교차 저장소 질문에 답하는 인용 강제 질의 에이전트를 만듭니다.

만들기 계획:

1. 모든 파일을 tree-sitter로 파싱합니다. 함수/클래스 노드 경계에서 청크를 자릅니다. `{repo, path, start_line, end_line, symbol, body}`를 저장합니다.
2. 모든 청크를 프롬프트 캐싱이 켜진 시스템 프롬프트로 Claude Haiku 4.5 또는 Gemini 2.5 Flash에 요약시킵니다. 한 문장 요약을 청크 옆에 저장합니다.
3. 세 구조로 색인합니다: Qdrant(dense, Voyage-code-3 또는 nomic-embed-code), Tantivy(필드 가중 BM25), kuzu(임포트·호출·상속의 심볼 그래프 에지).
4. 노드 세 개를 가진 LangGraph 질의 에이전트를 만듭니다: retrieve(dense 병렬 BM25), rerank(Cohere rerank-3 또는 bge-reranker-v2-gemma-2b), synth(프롬프트 캐싱과 file:line 인용 요구를 적용한 Claude Sonnet 4.7).
5. 후처리 필터: 검증 가능한 `(repo/path:start-end)` 앵커 없는 주장은 거부합니다. 재질문하거나 버립니다.
6. 심볼 수준 diff를 계산해 바뀐 청크만 다시 임베딩하는 git push 웹훅을 연결합니다. 목표: 200만 LOC 규모에서 50파일 커밋을 60초 안에 검색 가능하게.
7. 100질문 홀드아웃 세트로 평가합니다. MRR@10, nDCG@10, 인용 충실도, 지연 시간 백분위를 보고합니다.
8. 매주 평가를 다시 실행하고 MRR@10이 5% 넘게 떨어지면 알리는 드리프트 작업을 돌립니다.

채점 기준:

| 가중치 | 기준 | 측정 |
|:-:|---|---|
| 25 | 검색 품질 | 100질문 홀드아웃 세트에서 MRR@10과 nDCG@10 |
| 20 | 인용 충실도 | 검증 가능한 file:line 앵커를 가진 답변 주장의 비율 |
| 20 | 지연 시간과 규모 | 색인된 코퍼스 규모에서 10k QPS의 p95 질의 지연 시간 |
| 20 | 증분 색인 정확성 | 50파일 커밋이 git push부터 검색 가능해질 때까지 걸린 시간 |
| 15 | UX와 답변 포맷 | 인용 클릭 가능성, 스니펫 미리보기, 후속 질문 편의성 |

하드 리젝트(무조건 반려):

- AST 인식 청킹 대신 고정 크기 토큰 청킹. 생성 코드가 많은 코퍼스를 오염시킵니다.
- BM25나 재순위화 없이 코사인만 쓰는 검색. 정확한 심볼 이름 질의에서 실패하는 것으로 알려져 있습니다.
- file:line 인용을 의무화하지 않은 답변.
- git push마다 코퍼스 전체를 다시 임베딩하는 것. 반드시 증분이어야 합니다.

거절 규칙:

- 라이선스를 읽지 않고 저장소를 색인하는 것을 거절하세요. 제3자 벡터 저장소에의 임베딩을 금지하는 경우가 있습니다.
- 인덱스가 본 적 없는 파일을 인용한다고 주장하는 질의에는 답하는 것을 거절하세요. 돌려주기 전에 반드시 앵커를 검증합니다.
- p95가 4초를 넘는 상태로 답변을 서빙하는 것을 거절하세요. 대신 후속 질의 핸들을 붙인 부분 결과를 돌려줍니다.

출력: 수집 파이프라인, LangGraph 질의 에이전트, 100질문 라벨 평가 세트, Langfuse 대시보드 링크, 그리고 고친 검색 실패 모드 세 가지(생성 코드 오염, 긴 꼬리 심볼 리콜, 교차 저장소 심볼 해석)와 각각을 고친 정확한 변경 내용을 이름으로 적은 보고서가 담긴 저장소.
