# Pipeline Parallel and Bubble Analysis(파이프라인 병렬과 버블 분석)

> 텐서 병렬화는 행렬 곱을 랭크에 걸쳐 쪼갭니다. 파이프라인 병렬화는 모델을 랭크에 걸쳐 쪼개 랭크당 스테이지 하나를 놓습니다. 마이크로배치가 파이프라인을 따라 흐릅니다. 시작과 끝의 빈 시간이 바로 버블(bubble)이고, 이것을 최소화하는 것이 이 기술의 전부입니다.

**유형:** 빌드
**언어:** Python
**선수 지식:** 페이즈 19 트랙 C, 레슨 42-49
**시간:** ~90분

## 학습 목표

- 순차 모델을 N개 스테이지로 쪼개고 N개 랭크에 걸친 포워드 파이프라인을 시뮬레이션합니다.
- GPipe 스케줄(포워드로 채우기, 그다음 백워드)로 M개 마이크로배치를 파이프라인에 흘려 보내고 버블 비율을 계산합니다.
- Megatron-LM과 PipeDream이 쓰는 인터리브 방식 1F1B 스케줄과 버블을 비교합니다.
- 스테이지 배분을 방어합니다. 스테이지당 파라미터 수보다 스테이지당 연산량을 맞추는 게 훨씬 중요합니다.

## 문제 상황

fp16 기준 700억 파라미터 모델은 파라미터만 140GB입니다. 소비자용 GPU는 어느 것도 이걸 담지 못합니다. ZeRO-3는 파라미터를 랭크에 걸쳐 샤딩하지만, 각 포워드 스텝마다 모든 랭크가 풀 레이어를 allgather해야 하고 레이어당 log(N) 홉을 치릅니다. 파이프라인 병렬은 다른 길을 갑니다. 모델을 N개 스테이지로 자르고 랭크마다 스테이지 하나씩 얹는 것입니다. 레이어 1의 포워드가 랭크 0에서 끝나면 활성화 텐서를 랭크 1에 넘기고, 랭크 1은 레이어 2를 돌려 랭크 2에 넘기는 식입니다. 백워드는 반대 방향으로 흐릅니다. 각 랭크가 스테이지 하나만 들고 있으므로 메모리는 선형으로 줄어듭니다. 대신 연산이 순차적인데, 이것이 바로 버블 문제입니다.

버블은 파이프라인 시작 부분의 대기 시간(첫 마이크로배치가 마지막 스테이지에 도착하기를 기다림)과 끝 부분의 대기 시간(마지막 마이크로배치가 되돌아 흐르며 빠져나가기를 기다림)입니다. M개 마이크로배치와 N개 스테이지에서 스테이지당 버블 비율은 (N-1)/(M+N-1)입니다. M=8, N=4이면 27%입니다. M=64, N=4이면 4.5%입니다. 스텝당 마이크로배치를 많이 쓸수록 버블이 줄어드는데, 이는 마이크로배치당 배치 크기가 작아진다는 뜻이고, 이 제약이 마이크로배치 설계를 이끕니다.

## 개념

```mermaid
flowchart LR
  R0[rank 0: stage 0 / layer 0] --> R1[rank 1: stage 1 / layer 1]
  R1 --> R2[rank 2: stage 2 / layer 2]
  R2 --> R3[rank 3: stage 3 / loss]
  R3 -.backward.-> R2
  R2 -.backward.-> R1
  R1 -.backward.-> R0
```

### GPipe 스케줄

어떤 백워드도 시작하기 전에 파이프라인의 포워드를 M개 마이크로배치 전부로 채웁니다. 그다음 백워드를 역순으로 빼 냅니다. 모든 마이크로배치의 활성화는 각자의 백워드가 올 때까지 들고 있어야 하므로, 메모리는 M에 선형으로 늘어납니다. 포워드가 M+N-1사이클, 백워드가 또 M+N-1사이클 걸립니다. 스테이지당 유용한 작업은 2M사이클이고, 스테이지당 버블은 2(N-1)사이클입니다. 포워드와 백워드가 각각 시간 단위 하나를 쓴다고 하면 버블 비율은 (N-1)/(M+N-1)입니다. M을 N보다 훨씬 크게 잡으면 버블이 가려집니다.

### 1F1B 스케줄

인터리브 방식: 한 마이크로배치의 포워드가 마지막 스테이지에 닿는 즉시 그 백워드를 시작해 되돌아 흐르게 합니다. 이 스케줄은 스테이지마다 포워드 하나, 백워드 하나를 번갈아 수행합니다. 버블은 여전히 N-1이지만, 활성화 메모리가 마이크로배치 수가 아니라 파이프라인 깊이로 제한됩니다. 프로덕션 파이프라인은 1F1B를 씁니다(Megatron, PipeDream). 이 레슨은 더 단순한 GPipe를 먼저 구현하고, 1F1B는 연습 문제로 남깁니다.

### 스테이지당 연산량 균형이 중요한 이유

스테이지 0이 50ms, 스테이지 1이 100ms를 쓴다면 모든 사이클은 스테이지 1에 묶입니다. 다른 스테이지들은 스테이지 1이 놓아 주기를 기다리며 사이클마다 50ms씩 놉니다. 파라미터 수를 맞추는 건 잘못된 축입니다. 트랜스포머의 연산은 레이어당 어텐션 + MLP가 지배하고, 임베딩 레이어는 파라미터는 많지만 연산은 거의 없습니다. 스테이지 배분은 스테이지당 가중치 수가 아니라 스테이지당 FLOPs를 균등하게 맞춰야 합니다.

### 마이크로배치 대 배치

파이프라인은 크기 B짜리 마이크로배치 M개를 돌립니다. 실효 배치 크기는 M*B입니다. 파이프라인 스텝이 끝났을 때의 그래디언트는 합쳐진 M*B개 예제에 대한 그래디언트입니다. 버블 비율은 M에 달려 있고, 옵티마이저가 보는 것은 M*B입니다. M을 조율한다는 것은 버블(M이 클수록 작아짐)과 마이크로배치당 메모리(GPipe에서는 M이 클수록 활성화 메모리가 커짐) 사이의 거래를 뜻합니다.

## 만들기

`code/main.py`는 다음을 구현합니다.

- `PipelineStage`: 한 스테이지의 파라미터를 담고 `forward(activation)`를 노출하는 작은 `nn.Module`
- `Pipeline(stages, num_microbatches)`: 스테이지별 시뮬레이션된 벽시계 시간을 써서 시뮬레이션 스테이지 위에서 GPipe 스케줄을 지휘합니다.
- `bubble_fraction(num_stages, num_microbatches)`: 닫힌 형식의 (N-1)/(M+N-1).
- 마이크로배치별 트레이스와 측정된 버블 비율을 출력하는 4스테이지 데모

실행:

```bash
python3 code/main.py
```

출력: 스테이지 x 마이크로배치 간트 차트와, 닫힌 형식 예측치 대비 버블 백분율.

## 실전에서 쓰는 프로덕션 패턴

파이프라인 병렬을 출시 가능한 수준으로 튼튼하게 만드는 패턴 세 가지입니다.

**활성화 체크포인팅은 파이프라인과 짝이 됩니다.** GPipe에서 M개 마이크로배치가 동시에 진행 중이면 활성화 메모리는 '마이크로배치 하나의 M배'입니다. 활성화 체크포인팅은 백워드 시점에 포워드를 다시 계산해 연산을 메모리로 바꿉니다. 이 조합 덕분에 긴 시퀀스에서도 파이프라인을 다룰 수 있게 됩니다.

**스테이지 균형은 측정하는 것이지 가정하는 게 아닙니다.** 프로덕션 팀은 대상 하드웨어에서 실제 레이어별 연산량(FLOPs와 벽시계 시간)을 측정하는 프로파일링 패스를 돌린 뒤, 그 측정값으로 파티션을 나눕니다. Megatron-LM의 `--num-layers-per-stage` 플래그는 리스트를 받아서, 스테이지별 레이어당 비용이 다를 때 레이어 수를 비균등하게 배분할 수 있게 해 줍니다.

**send-recv 스케줄은 데드락을 피해야 합니다.** 모든 스테이지가 받기 전에 보내는 파이프라인은 와이어 위에서 데드락에 빠집니다. 표준 해법은 인터리브입니다. 짝수 랭크 스테이지는 보내기를 먼저 하고 받기를 하고, 홀수 랭크 스테이지는 받기를 먼저 하고 보냅니다. 이 레슨은 랭크 스케줄을 명시적으로 잡아 패턴이 눈에 보이게 합니다.

## 사용법

프로덕션 패턴:

- **Megatron-LM.** 규모 있는 파이프라인 병렬의 참조 구현. 1F1B를 쓰고 텐서 + 파이프라인 + 데이터 병렬을 결합해 지원합니다.
- **DeepSpeed Pipeline.** ZeRO와 통합됩니다. ZeRO-1 + 파이프라인은 가장 큰 오픈 모델들의 흔한 조합입니다.
- **PyTorch Pipe.** PyTorch 네이티브 파이프라인 래퍼로, `torch.distributed.pipeline.sync.Pipe` 위에 만들어져 있습니다.

## 연습 문제

1. 1F1B를 구현하고, 버블 비율은 GPipe와 같으면서 활성화 메모리는 제한되는지 확인하세요.
2. 더 깊은 모델에서 실제 스테이지별 시간을 프로파일링하고, 측정된 벽시계 시간으로 스테이지를 재조정하세요.
3. 파이프라인 마이크로배치에 걸친 그래디언트 누적을 추가하고, 그 그래디언트가 동등한 풀배치 포워드의 그래디언트와 같은지 확인하세요.
4. 파이프라인에 활성화 체크포인팅을 짝지어 메모리 절감과 연산 비용을 측정하세요.
5. 파이프라인과 DDP를 결합하고(각 파이프라인 랭크를 데이터 병렬 그룹으로 복제), 2차원 스케줄을 머릿속으로 훑어 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| Pipeline | "깊이 방향 모델 병렬" | 랭크당 스테이지 하나, 활성화가 스테이지에서 스테이지로 흐름 |
| Bubble | "파이프라인 유휴 시간" | 시작과 끝의 (N-1)스텝 동안 일부 스테이지가 할 일 없음 |
| Microbatch | "배치의 조각" | 포워드/백워드 한 단위. M이 커질수록 버블이 줄어듦 |
| GPipe | "채우고 나서 비우기" | 어떤 백워드보다 M개 포워드를 모두 먼저. 활성화 메모리 큼 |
| 1F1B | "인터리브 스케줄" | 스테이지마다 포워드 하나 백워드 하나. 활성화 메모리 제한됨 |
