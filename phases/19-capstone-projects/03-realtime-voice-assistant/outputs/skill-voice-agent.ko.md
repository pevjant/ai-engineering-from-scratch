> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-voice-agent.md](skill-voice-agent.md)

도메인(고객 지원, 일정 관리, 리테일 비서)이 주어지면, 끼어들기와 도구 호출, 패킷 손실을 처리하면서 끝까지 첫 오디오 출력 800ms 미만을 유지하는 WebRTC 음성 에이전트를 배포합니다.

만들기 계획:

1. 마이크 오디오를 스트리밍하는 웹 클라이언트와 함께 LiveKit Agents 1.0 룸을 세웁니다. 전화 커버리지를 위해 Twilio PSTN 게이트웨이를 추가합니다.
2. 스트리밍 ASR을 돌립니다(호스티드 Deepgram Nova-3 또는 g5.xlarge의 faster-whisper Whisper-v3-turbo). 부분 전사와 최종 전사를 구독합니다.
3. 20ms 프레임에 Silero VAD v5를 돌립니다. 발화 종료 시 최신 부분 전사를 LiveKit 발화 전환 검출기로 점수 매기고, VAD 침묵 >= 500ms이고 완성 점수 >= 0.6일 때만 발화 완료로 확정합니다.
4. LLM을 스트리밍합니다(GPT-4o-realtime, Gemini 2.5 Flash Live, 또는 캐스케이드 Claude Haiku 4.5). 첫 토큰을 200ms 안에 TTS로 넘깁니다.
5. TTS를 스트리밍합니다(Cartesia Sonic-2 또는 ElevenLabs Flash v3). 첫 오디오 청크는 첫 LLM 토큰에서 200ms 안에 서버를 떠나야 합니다.
6. 끼어들기: SPEAKING 또는 THINKING 중에 VAD가 새 사용자 발화를 감지하면 TTS를 취소하고, 남은 LLM 출력을 버리고, ASR을 다시 무장합니다. `tts_canceled` 스팬을 발행합니다.
7. 도구 사이드 채널: 함수 호출을 동시에 실행합니다. 지연이 300ms를 넘으면 인지 필러를 흘려 보내 오디오 스트림이 절대 멈추지 않게 합니다.
8. 통화 100건을 녹음합니다. 홀드아웃 전사 대비 WER, Hamming VAD 벤치마크의 오차단 비율, 첫 오디오 출력 p50, NISQA MOS, 패킷 3% 드롭에서의 동작을 측정합니다.
9. 합성 발신자로 g5.xlarge 한 대에서 동시 통화 50건 부하 테스트를 하고, 지속 가능한 첫 오디오 출력 p95를 보고합니다.

채점 기준:

| 가중치 | 기준 | 측정 |
|:-:|---|---|
| 25 | 끝까지 지연 시간 | 녹음된 100통에서 첫 오디오 출력 p50 800ms 미만 |
| 20 | 발화 전환 품질 | Hamming VAD 벤치마크에서 오차단 비율 3% 미만 |
| 20 | 도구 사용 정확성 | 대화 중 도구 호출이 오디오를 멈추지 않고 올바른 데이터를 돌려줌 |
| 20 | 패킷 손실 하 신뢰성 | 패킷 3% 드롭 주입 시 WER과 발화 전환 안정성 |
| 15 | 평가 하니스 완전성 | 공개 설정으로 재현 가능한 측정 |

하드 리젝트(무조건 반려):

- 비스트리밍 파이프라인(배치 ASR, 배치 TTS)은 지연 시간 목표를 맞출 수 없습니다.
- TTS 버퍼를 즉시 취소하지 않는 끼어들기 정책. 늦은 취소는 최악의 사용자 경험 퇴보를 만듭니다.
- LLM 스트림을 동기적으로 막는 도구 호출. 반드시 사이드 채널에서 돌아야 합니다.

거절 규칙:

- VAD나 발화 전환 검출기 없이 배포하는 것을 거절하세요. 고정 타임아웃 발화 전환은 받아들일 수 없는 차단율을 냅니다.
- 사람이 평가한 것인지 NISQA 대체치인지 문서화하지 않고 MOS를 보고하는 것을 거절하세요.
- 최소 100통의 녹음과 통화 트레이스 공개 없이 "p50 지연 시간 X 미만"을 보고하는 것을 거절하세요.

출력: LiveKit 에이전트 워커, PSTN 게이트웨이 설정, 100통 평가 하니스, 공개 Langfuse 음성 대시보드, 호스티드 경쟁품 하나(Retell, Vapi, 또는 OpenAI Realtime API 직접 사용)와의 나란히 비교, 그리고 관찰된 가장 큰 발화 전환 실패 세 가지와 각각을 고친 검출기 튜닝에 대한 보고서가 담긴 저장소.
