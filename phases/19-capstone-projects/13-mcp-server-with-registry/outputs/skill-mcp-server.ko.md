내부 플랫폼 요구가 주어지면, 프로토콜 개정판 `2026-07-28`을 겨냥한 상태 비저장 MCP 서버와 거버넌스 경계를 설계합니다.

만들기 계획:

1. 역방향 DNS 이름이 퍼블리셔의 인증된 네임스페이스와 일치하는, 스키마가 유효한 `server.json`.
2. 실시간 버전, 기능, 확장, 서버 신원을 위한 필수 `server/discover`.
3. 모든 요청 `_meta`에 버전과 클라이언트 기능; 모든 결과에 `resultType`과 서버 신원.
4. `ttlMs`와 `cacheScope`를 갖춘 결정론적 `tools/list`.
5. 필수 버전·메서드·이름 헤더를 갖춘 POST 전용 Streamable HTTP; 프로토콜 세션, GET 스트림, 세션 DELETE, 리플레이 헤더 없음.
6. 모든 호출에서 발급자, 대상, 만료, 범위를 검증하는 인가.
7. 행위자, 도구, 대상, 정규화된 인자에 대한 정책. 고위험 승인을 정확한 작업과 만료에 묶은 다음, 인자 하나만 바꿔도 재생(replay)이 거부됨을 증명합니다.
8. 모델이 볼 수 있는 컨텍스트 바깥의 삭제된(redacted) 감사 및 트레이스 증거.
9. `server.json`을 검증하고 `server/discover`를 프로브하며 메타데이터/런타임 드리프트를 보고하는 레지스트리 어댑터.
10. 서로 맞바꿀 수 있는 복제본 두 개와 세션 친화성 없이 도는 동시 부하 프로브.

평가 루브릭:

| 가중치 | 기준 | 측정 |
|:-:|---|---|
| 25 | 프로토콜 정확성 | 상태 비저장 봉투, 디스커버리, 결과, 헤더, 부정 케이스 |
| 20 | 인가 | 발급자, 대상, 만료, 범위, 정확한 작업 승인 케이스 |
| 15 | 레지스트리 무결성 | 유효한 `server.json`, 실시간 프로브, 드리프트 보고서 |
| 15 | 정책과 안전 | 허용, 거부, 형식 오류, 오래된 승인, 민감 데이터 케이스 |
| 15 | 확장성 | 친화성 의존 없는 복제본 두 개 + 취소 및 복구 |
| 10 | 감사 가능성 | 삭제된 수신 측 감사와 트레이스 증거 |

즉각 탈락(Hard rejects):

- `initialize`, `notifications/initialized`, 또는 `Mcp-Session-Id`를 쓰는 현재 시점의 MCP 설계.
- `server.json`을 실시간 기능 디스커버리처럼 다루거나, `.well-known/mcp-capabilities`를 MCP 요구사항으로 지어내는 경우.
- 해당 퍼블리셔가 인증된 네임스페이스 밖의 서버 이름을 공개하는 경우.
- 발급자와 대상 또는 리소스 검증 없이 토큰을 받아들이는 경우.
- 도구 어노테이션이나 채팅 승인을 인가로 취급하는 경우.
- 비밀이나 원본 민감 데이터를 저장하는 감사 기록.

거절 규칙(Refusal rules):

- 로컬 시뮬레이션만으로 프로덕션 준비 완료를 주장하는 일을 거절합니다.
- 정책과 작업에 묶인 승인 증거 없이 상태 변경 도구를 노출하는 일을 거절합니다.
- 실시간 디스커버리가 검증될 수 없는 엔드포인트를 가리키는 메타데이터를 공개하는 일을 거절합니다.

산출물: 공개 메타데이터, 실시간 디스커버리, 상태 비저장 전송, 도구 스키마, 인가, 정책, 승인, 감사, 확장을 다루는 만들기 계획과 증거 매트릭스. 마지막으로 최고 위험 경계와 그것이 실패 시 닫히는(fail closed) 모습을 증명하는 정확한 실패 테스트를 제시하세요.
