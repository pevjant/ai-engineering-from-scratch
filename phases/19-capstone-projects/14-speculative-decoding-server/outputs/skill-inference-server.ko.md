> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-inference-server.md](skill-inference-server.md)

오픈 대상 모델 두 개(Llama 3.3 70B와 Qwen3-Coder-30B MoE 또는 GPT-OSS-120B)가 주어지면, 추측 디코딩, 양자화, Kubernetes 오토스케일링을 갖춘 프로덕션(운영 환경) 서빙 스택을 출시합니다. 실측 가속 배수와 꼬리 지연 수치를 공개합니다.

만들기 계획:

1. FP8 Marlin 양자화를 적용해 vLLM 0.7(또는 SGLang 0.4) 아래에 대상 모델을 배포합니다.
2. Red Hat Speculators에서 정합 EAGLE-3 드래프트를 받아 옵니다(또는 SpecForge로 학습합니다).
3. 베이스라인 수치: 추측 없이 배치 1/8/32에서의 토큰/초와 p50/p99 지연.
4. EAGLE-3를 켭니다. 같은 벤치마크를 다시 돌립니다. 가속 배수, 수용률, p99 꼬리 지연 변화를 보고합니다.
5. P-EAGLE 병렬 추측을 켭니다; 더 깊은 트리가 도움 되는 지점과 해가 되는 지점의 변곡점을 보고합니다.
6. 분포를 넘나들며 벤치마크를 돌립니다: ShareGPT, HumanEval, 도메인 데이터. 수용률 드리프트를 공개합니다.
7. 두 번째 대상 모델(MoE)에서 반복합니다; 드래프트 수용률의 라우팅 노이즈 민감도를 찾아냅니다.
8. `queue_wait_ms`를 추적하는 HPA와 함께 Kubernetes에 배포합니다. 부하가 3배가 될 때 확장되는 모습을 시연합니다.
9. 짝을 맞춘 평가에서 Anthropic Claude Sonnet 4.7과 OpenAI GPT-5.4 대비 100만 토큰당 달러를 비교합니다.

평가 루브릭:

| 가중치 | 기준 | 측정 |
|:-:|---|---|
| 25 | 베이스라인 대비 실측 가속 | 두 모델 모두에서 품질을 맞춘 상태의 2.5배 이상 처리량 |
| 20 | 현실적 트래픽 수용률 | 분포별 수용률 보고서 |
| 20 | P99 꼬리 지연 규율 | 추측 사용/미사용 배치 1/8/32에서의 p99 |
| 20 | 운영 | K8s 배포, 큐 대기 기준 HPA, 매끄러운 롤아웃, 드레인 선(upgrade) 방식 |
| 15 | 보고서와 방법론 | 지표의 명확한 도출, 짝이 맞는 베이스라인 |

즉각 탈락(Hard rejects):

- 꼬리 지연 없이 안정 상태 처리량만 보고하는 경우.
- 큐 대기 대신 CPU 기준 HPA. GPU 포화 상태에서 심하게 흔들립니다(thrash).
- 드래프트-대상 버전 정합을 무시하는 경우. 어긋난 드래프트는 추측을 안 쓰는 것보다 비쌉니다.
- 호스팅 API의 프롬프트 캐싱 할인을 빼놓는 비용 비교.

거절 규칙(Refusal rules):

- 롤아웃 드레인 없이 서빙하는 일을 거절합니다. 요청이 처리 중인데 그 자리에서 업그레이드하면 실격입니다.
- 분포를 합쳐 집계한 수용률을 보고하는 일을 거절합니다. 분포별 보고는 필수입니다.
- 짝이 맞는 비추측 수치 없이 bs=32에서 추측 디코딩이 이긴다고 주장하는 일을 거절합니다.

산출물: vLLM / SGLang 설정, EAGLE-3 드래프트 다운로드 스크립트, K8s 배포 매니페스트, 큐 대기 기준 HPA 설정, ShareGPT / HumanEval / 도메인 데이터용 벤치마크 하니스, 100만 토큰당 달러 비교표, 그리고 추측 디코딩이 만들어 낸 꼬리 지연 퇴보(regression) 세 가지와 각각을 고친 완화책(배치 게이팅, ngram 폴백, 양자화 조정)을 적은 보고서를 담은 저장소.
