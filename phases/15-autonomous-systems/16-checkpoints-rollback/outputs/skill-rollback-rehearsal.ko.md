> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-rollback-rehearsal.md](skill-rollback-rehearsal.md)

제안된 장기 자율 워크플로가 주어지면, 멱등성 + 사전 조건 + 검증 + 롤백 스택이 실제로 엔드투엔드로 작동함을 증명하는 롤백 리허설 테스트를 설계하고, 규제 준비를 위해 체크포인트 백엔드를 감사합니다.

작성할 내용:

1. **리허설 스크립트.** (a) 워크플로를 시작하고, (b) 확정 중간에 크래시시키고, (c) 재개하고, (d) 행동이 정확히 한 번 발화함을 단언하고, (e) 검증 실패를 주입하고, (f) 롤백이 발동하고 상태가 복원됨을 단언하는 구체적인 테스트. 이 테스트를 최소 한 번 통과하지 않고 실행되어야 할 프로덕션 워크플로는 없습니다.
2. **멱등성 감사.** 멱등성 키가 제안 내용에서 도출되는지(레슨 15)와 확정 로직이 명시적인 실행 상태(`pending` -> `executing` -> `committed`/`failed`)를 사용하는지 확인합니다. 부작용 전에 멱등성 키로 예약/잠금하고, 부작용이 검증된 뒤에만 `committed`로 표시합니다.
3. **사전 조건 목록.** 워크플로가 확정 시점에 다시 검사해야 하는 모든 사전 조건을 나열합니다. 검사 시점 vs 사용 시점 격차(time-of-check vs time-of-use)가 가장 흔한 프로덕션 버그입니다; 사전 조건은 제안 시점이 아니라 확정 시점에 평가되어야 합니다.
4. **검증 목록.** 모든 중대 행동에 대해 부작용이 일어났음을 확인하는 구체적인 읽기를 명시합니다. "200을 반환했다"는 수용할 수 없습니다.
5. **롤백 목록.** 모든 중대 행동에 대해 롤백을 인밴드, 보상 트랜잭션, 또는 아웃오브밴드 경보로 분류합니다. no-op 롤백("이것은 되돌릴 수 없습니다")은 제안에 명시적으로 밝혀져야 합니다(레슨 15 메타데이터).

하드 리젝(무조건 거부):
- 리허설된 롤백이 없는 워크플로.
- 배포 시 데이터를 잃는 체크포인트 백엔드.
- 상태가 실행 뒤에 쓰이는(실행 전이 아니라) 확정 경로.
- 도구 호출의 반환 코드만 검사하는 "검증됨" 상태.
- 확정 시점이 아니라 제안 시점에만 실행되는 사전 조건 검사.

거부 규칙:
- 사용자가 스테이징에서 리허설 스크립트를 최소 한 번 실행하지 않았다면, 프로덕션 롤아웃을 거부하세요.
- 사용자가 체크포인트 저장소 스키마를 제시하지 못하면 거부하고, 스키마 문서를 먼저 요구하세요. 규제 기관은 질의 가능한 상태를 원합니다.
- 워크플로가 (영속이 없는) 메모리 내 체크포인트에 의존하면 거부하세요.

출력 형식:

다음을 포함한 리허설 계획을 반환합니다:
- **테스트 스크립트 개요** (단언이 붙은 단계들)
- **멱등성 표** (키 구성, 상태 쓰기 순서)
- **사전 조건 표** (검사, 평가 시점, 결과)
- **검증 표** (행동, 확인하는 읽기)
- **롤백 표** (행동, 유형, 대상 상태)
- **백엔드 증명** (저장소, 배포 생존 여부 y/n, 질의 준비 여부 y/n)
- **준비도** (프로덕션 / 스테이징 / 연구 전용)
