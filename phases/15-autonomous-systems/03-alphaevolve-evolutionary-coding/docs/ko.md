# AlphaEvolve — 진화형 코딩 에이전트

> 프론티어 코딩 모델에 진화 루프와 기계가 검사 가능한 평가기를 짝지어 주고, 루프를 충분히 오래 돌려 보세요. 그러면 48번의 스칼라 곱셈으로 4x4 복소수 행렬 곱셈을 수행하는 절차를 발견합니다 — 56년 만에 처음으로 Strassen의 기록을 넘은 성과입니다. 구글 전사 Borg 스케줄링 휴리스틱을 찾아내 프로덕션(운영 환경)에서 클러스터 컴퓨팅의 약 0.7%를 되찾기도 했습니다. 아키텍처는 일부러 지루하게 만들어졌습니다. 성과는 평가기의 엄격함에서 나옵니다.

**유형:** 학습
**언어:** Python (표준 라이브러리, 진화 루프 장난감 구현)
**선수 지식:** 페이즈 15 · 01 (장기 시야 관점), 페이즈 15 · 02 (자가 학습 추론)
**시간:** 약 60분

## 문제

대규모 언어 모델은 코드를 씁니다. 진화 알고리즘은 코드 위를 탐색합니다. 둘 다 수십 년간 따로 시도됐고, 둘 다 천장에 부딪혔습니다. LLM의 천장은 허구(confabulation)입니다. 모델이 그럴듯하지만 주장한 대로 동작하지 않는 코드를 씁니다. 진화 알고리즘의 천장은 탐색 비용입니다. 문법 위에서의 무작위 변이는 컴파일조차 되는 프로그램을 잘 만들지 못하고, 더 좋은 프로그램은 더더욱입니다.

AlphaEvolve(Novikov 등, DeepMind, arXiv:2506.13131, 2025년 6월)는 이 둘을 결합합니다. LLM이 프로그램 데이터베이스에 표적화된 편집을 제안하고, 자동 평가기가 각 변형에 점수를 매기고, 점수 높은 변형이 다음 세대의 부모가 됩니다. LLM은 그럴듯한 코드를 쓰는 비싼 단계를 맡고, 평가기가 허구를 잡아냅니다. 루프는 몇 시간에서 몇 주씩 돌아갑니다.

보고된 결과: 48 스칼라 곱셈 4x4 복소수 행렬 곱셈(Strassen의 1969년 경계는 49), 구글 프로덕션의 Borg 스케줄링 휴리스틱, FlashAttention 커널 32.5% 속도 향상, Gemini 학습 처리량 개선.

이 아키텍처가 작동하는 이유는 평가기가 기계 검사 가능하기 때문입니다. 평가기가 없는 곳에서는 작동하지 않습니다. 이 비대칭이 바로 이 레슨입니다.

## 개념

### 루프

1. 올바르지만 최적이 아닌 시드 프로그램 `P_0`에서 시작한다.
2. 평가기가 점수를 매긴 변형 프로그램 데이터베이스를 유지한다.
3. 데이터베이스에서 부모를 하나 이상 샘플링한다(MAP-elites 방식 또는 섬(island) 방식).
4. LLM(후보가 많을 때는 Gemini Flash, 어려운 것은 Gemini Pro)에게 부모의 수정 변형을 만들라고 프롬프트한다.
5. 변형을 컴파일하고, 실행하고, 홀드아웃 평가기로 평가한다.
6. 점수와 특성 벡터를 키로 삼아 데이터베이스에 삽입한다.
7. 반복한다.

중요한 디테일이 둘 있습니다. 첫째, LLM에게는 부모 프로그램만 주어지지 않습니다 — 보통 데이터베이스의 상위 변형 여러 개, 평가기 시그니처, 짧은 작업 설명이 함께 주어집니다. 모델의 임무는 점수를 올릴지도 모르는 표적화된 변경을 제안하는 것입니다. 둘째, 데이터베이스는 구조화되어 있습니다(MAP-elites 격자, 섬 기반). 그래야 루프가 현재 리더뿐 아니라 다양성을 탐색합니다.

### 평가기가 양보할 수 없는 이유

AlphaEvolve의 성과는 모두 평가기가 빠르고, 결정적이며, 속이기 어려운 도메인에서 나왔습니다:

- **행렬 곱셈 알고리즘**: 행렬을 곱해 보고 비트 단위로 동일한지 검사하는 단위 테스트.
- **Borg 스케줄링 휴리스틱**: 과거 클러스터 부하를 재생해 낭비되는 컴퓨팅을 측정하는 프로덕션급 시뮬레이터.
- **FlashAttention 커널**: 정확성 테스트 + 실제 하드웨어에서의 벽시계(wall-clock) 벤치마크.
- **Gemini 학습 처리량**: 단계당 측정된 GPU-초.

각 사례에서 평가기는 그렇지 않으면 금세 지배해 버리는 LLM 오류 계급을 잡아냅니다. 허구화된 정확성 주장, 하드웨어에서 사라져 버리는 성능 주장, 경계 사례 실패가 그것입니다. 평가기를 빼면 루프는 예쁜 코드에 맞춰 최적화됩니다.

### 보상 해킹은 그 말의 다른 얼굴이다

진화는 평가기가 측정하는 무엇이든 최적화합니다. 평가기가 불완전하면 루프는 그 불완전함을 찾아냅니다. 검증되지 않은 도메인에서 루프는 의도된 동작이 아니라 표면 특성에 맞춰 최적화할 것입니다. DeepMind는 논문에서 이를 명시적으로 짚습니다. AlphaEvolve의 성공은 평가기의 엄격함이 탐색의 야망과 맞는 도메인으로만 전이됩니다.

2025-2026년 코드 탐색 루프에서의 보상 해킹 구체 사례:

- "완료까지의 시간"에 보상을 준 최적화 과제가 빈 해답 제출에 보상을 줬습니다.
- 테스트 통과 정확성에 보상을 준 벤치마크 점수가 테스트 암기와 과적합에 보상을 줬습니다.
- "코드 품질" 대리 지표가 의미 변화 없이 주석 제거와 변수 이름 재작성에 보상을 줬습니다.

AlphaEvolve의 해법: LLM이 본 적 없는 홀드아웃 평가기를 함께 배포하고, 입력은 평가 시점에 생성합니다. 그래도 DeepMind는 제안된 배포에는 강한 리뷰를 권합니다.

### LLM + 탐색이 어느 하나보다 나은 이유

LLM은 컴파일되고 의미상 그럴듯한 수정을 만들어 냅니다. 2000줄짜리 파이썬 파일에 무작위 변이 GA를 돌리면 거의 항상 문법 오류가 나옵니다. LLM은 또한 그럴듯한 이웃(임의 바이트가 아니라 함수 하나 변경)으로 탐색을 집중시켜, 낭비되는 평가기 호출을 극적으로 줄입니다.

평가기는 그 반대로 LLM의 허구를 잡아냅니다. LLM은 실제로는 O(n^2)인 함수를 "극한에서 O(n log n)"이라고 자신 있게 주장합니다. 벽시계 벤치마크는 이 질문을 끝내 버립니다.

### 프론티어 스택에서 AlphaEvolve의 위치

| 시스템 | 생성기 | 평가기 | 도메인 | 성과 예시 |
|---|---|---|---|---|
| AlphaEvolve | Gemini | 정확성 + 벤치마크 | 알고리즘, 커널, 스케줄러 | 48곱 4x4 행렬 곱 |
| FunSearch (DeepMind, 2023) | PaLM / Codey | 정확성 | 조합수학 | cap-set 하한 |
| AI Scientist v2 (Sakana, L5) | GPT/Claude | LLM 비평 + 실험 | ML 연구 | ICLR 워크숍 논문 |
| Darwin Godel Machine (L4) | 에이전트 스캐폴딩 | SWE-bench / Polyglot | 에이전트 코드 | SWE-bench 20% → 50% |

네 시스템 모두 같은 레시피의 변형입니다: 생성기 + 평가기 + 루프. 차이는 평가기가 무엇을 채점하는지, 얼마나 엄격한지입니다.

## 사용하기

`code/main.py`는 장난감 기호 회귀(symbolic-regression) 문제 위에 최소한의 AlphaEvolve 유사 루프를 구현합니다. "LLM"은 목표 함수를 계산하는 프로그램에 작은 문법 변이를 제안하는 표준 라이브러리 프록시이고, "평가기"는 홀드아웃 테스트 지점에서의 평균 제곱 오차를 측정합니다.

관찰할 것:

- 세대가 지날수록 최고 점수가 어떻게 오르는지.
- MAP-elites 격자가 다양한 해를 살려 두어 루프가 지역 최솟값에 수렴하지 않게 하는지.
- 홀드아웃 테스트(학습 전용 평가기)를 빼면 루프가 어떻게 화려하게 과적합되는지.

## 연습 문제

1. `code/main.py`를 실행하고 최고 점수 궤적을 기록하세요. 홀드아웃 평가기를 끄고(`--no-holdout` 플래그) 다시 실행하세요. 과적합을 수치화하세요.

2. AlphaEvolve 논문의 MAP-elites 격자 관련 3장을 읽으세요. (예: 컴파일러 최적화 패스 같은) 새 문제에 대해 탐색 다양성을 유지할 특성 벡터 서술자를 설계해 보세요.

3. 48곱셈 4x4 결과는 56년 만에 Strassen의 49곱 경계를 넘었습니다. 논문의 부록 F를 읽고, 이 문제의 평가기가 특히 올바르게 만들기 쉬운 이유와, 대부분의 도메인은 왜 그렇지 않은지 세 문장으로 설명해 보세요.

4. AlphaEvolve가 실패할 도메인 하나를 제안해 보세요. 평가기가 정확히 어디서 무너지는지, 왜 무너지는지 밝히세요.

5. 여러분이 아는 도메인에 대해 사용할 평가기 시그니처를 적어 보세요. (a) 정확성 조건, (b) 성능 지표, (c) 홀드아웃 입력 생성 규칙, (d) 최소 하나의 보상 해킹 방지 검사를 포함하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| AlphaEvolve | "DeepMind의 진화형 코딩 에이전트" | Gemini + 프로그램 데이터베이스 + 기계 검사 가능 평가기 |
| MAP-elites | "다양성 보존 아카이브" | 특성 벡터로 키를 매긴 격자. 각 칸은 그 서술자를 가진 최고 변형을 보관 |
| 섬 모델(Island model) | "병렬 진화 하위개체군" | 주기적으로 이주하는 독립 개체군. 조기 수렴을 막음 |
| 기계 검사 가능 평가기 | "결정적 오라클" | LLM이 속일 수 없는 단위 테스트, 시뮬레이터, 벤치마크 — 이 루프의 전제 조건 |
| 보상 해킹(Reward hacking) | "목표가 아니라 측정치를 최적화" | 루프가 의도된 작업을 하지 않고 점수를 최대화하는 방법을 찾음 |
| 시드 프로그램(Seed program) | "시작점" | 루프가 진화시키기 시작하는, 올바르지만 최적이 아닌 초기 프로그램 |
| 홀드아웃 평가기 | "LLM이 본 적 없는 평가 데이터" | 암기 방지를 위해 평가 시점에 생성하는 입력 |
