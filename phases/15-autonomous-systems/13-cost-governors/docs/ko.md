# 액션 예산, 반복 상한, 비용 거버너

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> 어느 중형 전자상거래 에이전트의 월간 LLM 비용이 팀이 "주문 추적" 스킬을 켠 뒤 $1,200에서 $4,800로 뛰었습니다. 이것은 가격 버그가 아닙니다. 새로운 루프를 발견한 에이전트가 그 안에서 계속 돈을 쓴 것입니다. Microsoft의 Agent Governance Toolkit(2026년 4월 2일)은 이 부류에 대한 방어를 규정합니다: 요청별 `max_tokens`, 태스크별 토큰/달러 예산, 일/월별 상한, 반복 상한, 계층형 모델 라우팅, 프롬프트 캐싱, 컨텍스트 윈도잉, 비싼 행동에 대한 HITL 체크포인트, 예산 위반 시 킬 스위치. Anthropic의 Claude Code Agent SDK는 같은 프리미티브를 다른 이름으로 출시합니다. 금융 속도 제한 — 예: 10분 안에 $50을 넘으면 접근 차단 — 은 월간 상한보다 루프를 더 빨리 잡아냅니다.

**유형:** 학습(Learn)
**언어:** Python (표준 라이브러리, 계층화된 비용 거버너 시뮬레이터)
**선수 지식:** 페이즈 15 · 10 (권한 모드), 페이즈 15 · 12 (내구 실행)
**시간:** 약 60분

## 문제

자율 에이전트는 매 턴마다 진짜 돈을 씁니다. 챗봇의 나쁜 출력은 나쁜 답장이지만; 에이전트의 나쁜 루프는 고지서입니다. 업계에서 이 실패 양상을 부르는 이름은 "Denial of Wallet"입니다 — 에이전트는 추론을 계속하고, 도구 호출을 계속하고, 청구를 계속하는데, 그것을 멈추도록 설계된 것이 없기 때문에 아무것도 멈추지 않습니다.

해결책은 숫자 하나가 아닙니다. 서로 다른 시간 규모와 입자 크기를 가진 상한들의 스택입니다: 요청별, 태스크별, 시간별, 일별, 월별. 잘 설계된 스택은 폭주하는 루프를 몇 분 안에, 느린 누출을 몇 시간 안에, 나쁜 릴리스를 하루 안에 잡아냅니다. 같은 스택이 에이전트가 장기이고 자율적일 때도 예산을 지켜 줍니다.

이것은 공학 레슨입니다: 수학은 사소하고, 팀이 실패하는 곳은 규율입니다. 아래 상한 목록은 전부 Microsoft Agent Governance Toolkit이나 Anthropic Claude Code Agent SDK 문서에 이름이 나옵니다.

## 개념

### 비용 거버너 스택

1. **요청별 `max_tokens`.** 단순합니다. 어떤 한 호출도 무한한 완성을 내보내지 못하게 합니다.
2. **태스크별 토큰 예산.** 실행 전체에서 N 토큰을 넘지 않습니다. 상한에서 하드 스톱.
3. **태스크별 달러 예산.** 토큰과 같지만 화폐 단위입니다. Claude Code의 `max_budget_usd`.
4. **도구별 호출 상한.** `WebFetch`는 N번 이하, `shell_exec`는 N번 이하 등.
5. **반복 상한(`max_turns`).** 에이전트 루프 반복의 총량; 무한 추론 루프를 막습니다.
6. **분/시간/일/월별 상한.** 롤링 윈도우. 서로 다른 시간 규모의 누출을 잡습니다.
7. **금융 속도 제한.** 예: "10분 안에 지출이 $50을 넘으면 접근 차단." 월간 상한이 발동되기 전에 루프 기반 소진을 잡습니다.
8. **계층형 모델 라우팅.** 기본은 작은 모델; 분류기가 태스크가 그만한 가치가 있다고 판단할 때만 더 큰 모델로 확대.
9. **프롬프트 캐싱.** 시스템 프롬프트와 안정적인 컨텍스트를 제공자 캐시에 저장; 재전송의 토큰 비용은 거의 0.
10. **컨텍스트 윈도잉.** 압축/요약으로 활성 컨텍스트를 임계값 아래로 유지; 토큰 비용 직접 절감.
11. **비싼 행동에 대한 HITL 체크포인트.** 비용이 비싸다고 알려진 행동(긴 도구 호출, 대용량 다운로드, 비싼 모델 업그레이드) 전에는 사람의 탭을 요구.
12. **예산 위반 시 킬 스위치.** 어느 상한이든 발동하면 세션 중단. 상한 기록; 별도의 재활성화 절차 필요.

### 상한 하나가 아니라 스택인 이유

월간 상한 하나는 지갑이 텅 빈 뒤에야 폭주하는 에이전트를 잡습니다. 요청별 상한 하나는 세션 수준에서 아무것도 잡지 못합니다. 서로 다른 실패 양상에는 서로 다른 시간 규모가 필요합니다:

- **폭주 루프** (5초 재시도에 갇힌 에이전트): 속도 제한이 잡습니다.
- **느린 누출** (태스크당 예상의 약 2배를 하는 에이전트): 일별 상한이 잡습니다.
- **나쁜 릴리스** (새 버전이 5배 토큰을 사용): 주간/월간 상한이 잡습니다.
- **정당한 급증** (진짜 수요, 버그 아님): 명확한 로그와 함께 시간/일별 상한이 잡습니다.

### 하네스의 예산 표면

Claude Code Agent SDK가 노출하는 것(공개 문서):

- `max_turns` — 반복 상한.
- `max_budget_usd` — 달러 상한; 위반 시 세션 중단.
- `allowed_tools` / `disallowed_tools` — 도구 허용 목록과 거부 목록.
- 도구 사용 전 커스텀 비용 회계를 위한 훅 지점.

권한 모드 사다리(레슨 10)와 결합하세요. `max_budget_usd` 없는 `autoMode` 세션은 통제 없는 자율입니다. Anthropic은 Auto Mode가 예산 통제를 요구한다고 명시적으로 프레이밍합니다; 분류기는 비용과 직교합니다.

### EU AI Act, OWASP Agentic Top 10

Microsoft의 Agent Governance Toolkit은 OWASP Agentic Top 10과 EU AI Act 제14조(사람 감독) 요건을 다룹니다. EU에서의 프로덕션에서는 로깅과 상한 강제가 선택 사항이 아닙니다.

### 관찰된 $1,200 → $4,800 사례

Microsoft 문서의 실제 사례: 새 도구가 추가된 뒤 월간 비용이 세 배가 된 전자상거래 에이전트. 그 도구는 에이전트가 매 세션에서 주문 상태를 폴링할 수 있게 해 줬습니다. 루프 탐지 없음. 도구별 상한 없음. 주간 대비 성장 경보 없음. 해결책은 도구별 상한에 일일 성장 경보를 더한 것이었습니다. 이것이 템플릿입니다: 모든 새 도구 표면은 새로운 잠재적 루프입니다; 모든 새 도구에는 자신만의 상한과 자신만의 경보가 필요합니다.

## 사용해 보기

`code/main.py`는 계층화된 비용 거버너 스택이 있을 때와 없을 때의 에이전트 실행을 시뮬레이션합니다. 시뮬레이션된 에이전트는 몇 턴 뒤 폴링 루프로 표류합니다; 계층화된 스택은 그것을 속도 윈도우 안에서 잡지만, 월간 상한 하나만으로는 며칠 뒤에야 발동합니다.

## 출시해 보기

`outputs/skill-agent-budget-audit.md`는 제안된 에이전트 배포의 비용 거버너 스택을 감사하고 빠진 계층을 표시합니다.

## 연습 문제

1. `code/main.py`를 실행해 보세요. 폴링 루프 궤적에서 속도 제한이 반복 상한보다 먼저 발동함을 확인하세요. 이제 속도 제한을 끄고, 반복 상한이 잡기 전에 에이전트가 얼마를 "쓰는지" 측정하세요.

2. 브라우저 에이전트(레슨 11)를 위한 도구별 상한 집합을 설계해 보세요. 어떤 도구가 가장 타이트한 상한이 필요한가요? 어떤 도구는 위험 없이 무제한으로 돌 수 있나요?

3. Microsoft Agent Governance Toolkit 문서를 읽어 보세요. 툴킷이 언급하는 모든 상한 유형을 나열하세요. 각각을 실패 양상(폭주 루프, 느린 누출, 나쁜 릴리스, 급증) 하나에 대응시키세요.

4. 현실적인 태스크(예: "저장소의 이슈 50개 분류")에 대한 밤새 무인 실행의 가격을 매겨 보세요. `max_budget_usd`를 추정치의 2배로 설정하세요. 그 2배를 정당화하세요.

5. Claude Code의 `max_budget_usd`는 세션 총 비용에서 발동합니다. 외부에서 강제할 보완적인 속도 제한을 설계해 보세요. 무엇이 차단을 촉발하고, 재활성화는 어떤 모습인가요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| Denial of Wallet | "폭주 고지서" | 멈추게 할 상한 없이 지출을 만드는 에이전트 루프 |
| max_tokens | "요청별 상한" | 단일 완성 크기의 천장 |
| max_turns | "반복 상한" | 세션에서 에이전트 루프 반복의 천장 |
| max_budget_usd | "달러 킬 스위치" | 세션 비용 상한; 위반 시 중단 |
| 속도 제한 | "속도 상한" | 짧은 윈도우당 지출 한계 (예: $50 / 10분) |
| 계층형 라우팅 | "작은 모델 먼저" | 저렴한 모델이 기본; 분류기가 정당화할 때만 확대 |
| 프롬프트 캐싱 | "캐시된 시스템 프롬프트" | 제공자 측 캐시가 재전송 토큰 비용을 거의 0으로 |
| HITL 체크포인트 | "사람 승인 게이트" | 비싼 행동 전에 사람의 탭 필요 |
