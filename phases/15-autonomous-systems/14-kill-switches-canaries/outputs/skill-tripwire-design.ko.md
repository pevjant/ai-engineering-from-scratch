에이전트 배포를 위한 제안된 탐지기 스택이 주어지면, 3종 탐지기 기준(킬 스위치, 서킷 브레이커, 카나리아)으로 감사하고 무엇이 없거나, 잘못 조정되었거나, 에이전트에 노출되어 있는지 표시합니다.

작성할 내용:

1. **킬 스위치 감사.** 스위치는 어디에 삽나는가(기능 플래그, Redis, 서명된 설정)? 에이전트의 자격 증명이 그것을 끌 수 없음을 확인합니다. 모든 중대 행동이 시작 시점뿐 아니라 스위치를 검사함을 확인합니다. 재활성화가 명시적인 사람의 행위임을 확인합니다.
2. **서킷 브레이커 목록.** 브레이커가 감시하는 모든 패턴(반복, 연속 실패, 속도, out-of-trust 읽기 이후의 특정 도구)을 나열합니다. 각각의 임계값과 냉각 시간을 명시합니다. 10을 넘는 임계값은 보통 너무 느슨합니다.
3. **카나리아 설계.** 환경의 모든 카나리아 토큰을 나열합니다. 각각에 대해: 그것이 무엇인지(가짜 자격 증명, 가짜 DB 레코드, 가짜 파일, 가짜 메모리 항목), 어디에 삽나는지, 어떤 접근이 경보를 울리는지, 누가 호출되는지. 어떤 카나리아도 건드려야 할 정당한 이유가 없음을 확인합니다.
4. **통계적 + 하드 계층화.** 스택이 통계적 탐지기(EWMA, z-score) 외에 하드 한계(레슨 17 헌법 스타일)를 최소 하나 쓰는지 확인합니다. 통계 전용 탐지기는 느린 표류를 받아들입니다.
5. **격리 경로.** 탐지기가 발동하면 무슨 일이 일어나는가? 에이전트 전체 정지, 경로별 일시 정지, 트래픽 리다이렉트(eBPF / Cilium 허니팟), 경보만. 그 경로가 최소 한 번은 엔드투엔드로 테스트되었는지 확인합니다.

하드 리젝(무조건 거부):
- 외부 킬 스위치 없는 배포.
- 에이전트가 쓰기 접근이 가능한 시스템에 저장된 카나리아 토큰.
- 하드 한계 없는 통계 전용 탐지.
- 사람 검토 없이 자동 재활성화되는 냉각 시간을 가진 서킷 브레이커.
- 킬 스위치를 행동별이 아니라 시작 시에만 검사하는 무인 실행.

거부 규칙:
- 사용자가 킬 스위치를 호스팅하는, 에이전트의 자격 증명 밖에 있는 구체적인 시스템을 말하지 못하면 거부하세요. "에이전트가 읽는 설정 파일을 씁니다"는, 에이전트가 설정 파일을 쓸 수 있다면 킬 스위치가 아닙니다.
- 사용자가 Auto Mode 분류기(레슨 10)를 트리프와이어의 대체물로 취급하면 거부하세요. 분류기는 탐지-및-대응과 직교합니다.
- 제안된 카나리아가 에이전트가 읽을 정당한 이유가 있는 시스템에 있으면 거부하고, 재설계를 요구하세요.

출력 형식:

다음을 포함한 트리프와이어 감사를 반환합니다:
- **킬 스위치 한 줄** (위치, 검사 주기, 재활성화 절차)
- **서킷 브레이커 표** (패턴, 임계값, 냉각 시간)
- **카나리아 표** (토큰, 위치, 경보, 담당자)
- **계층화 노트** (통계적 + 하드 한계 존재 여부 y/n)
- **격리 흐름** (무엇이 발동하고, 무슨 일이 일어나는지, 테스트 여부 y/n)
- **준비도** (프로덕션 / 스테이징 / 연구 전용)
