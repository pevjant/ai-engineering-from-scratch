# 킬 스위치, 서킷 브레이커, 카나리아 토큰

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> 킬 스위치는 에이전트의 수정 범위 밖에서 유지되는 불리언 — Redis 키, 기능 플래그, 서명된 설정 — 으로, 에이전트 전체를 비활성화합니다. 서킷 브레이커는 더 세밀합니다: 특정 패턴(연속 다섯 번의 동일한 도구 호출)에서 작동(trip)하여, 문제의 경로를 일시 정지하고 사람에게 확대합니다. 카나리아 토큰은 고전적 기만(deception)에서 물려받은 것입니다: 에이전트가 건넬 정당한 이유가 없는 가짜 자격 증명이나 허니팟 레코드로, 그것에 접근하면 경보가 울립니다. eBPF 기반 데이터패스(예: Cilium)는 커널 계층에서 격리된 파드의 외부 통신(egress)을 포렌식 허니팟으로 재작성할 수 있습니다; 공개된 Cilium 벤치마크는 부하 상황에서도 1밀리초 미만의 P99 데이터패스 지연 시간을 보고합니다 (전파 예산은 데이터패스 자체가 아니라 정책 업데이트가 노드에 도달하는 방식에 달려 있습니다). 움직이는 베이스라인에 적응하는 통계적 탐지기(EWMA, CUSUM)는 표류를 조용히 받아들입니다 — 굽히지 않는 하드 헌법적 한계와 계층화하세요.

**유형:** 학습(Learn)
**언어:** Python (표준 라이브러리, 3종 탐지기 시뮬레이터: 킬 스위치, 서킷 브레이커, 카나리아)
**선수 지식:** 페이즈 15 · 13 (비용 거버너), 페이즈 15 · 10 (권한 모드)
**시간:** 약 60분

## 문제

비용 거버너(레슨 13)는 에이전트가 쓸 수 있는 돈을 한계 짓습니다. 예산 안에서 에이전트가 할 수 있는 일은 한계 짓지 않습니다. $50 속도 제한이 있는 에이전트도 여전히 비밀을 유출하거나, 잘못된 글을 게시하거나, 리소스를 삭제할 수 있습니다 — 비싼 행동이 종종 토큰으로는 가장 싼 행동입니다.

이 레슨은 비용 계층 옆에 앉는 세 가지 탐지기를 다룹니다:

1. **킬 스위치**: 에이전트가 닿지 않는 곳에 있는 불리언 오프 버튼.
2. **서킷 브레이커**: 특정 경로를 일시 정지시키는 행동 패턴 탐지기.
3. **카나리아 토큰**: 건넬 정당한 이유가 없는 에이전트가 건드리는 순간 자신을 드러내는 미끼.

세 가지 모두 LLM 이전의 공학입니다. 고전적 기만, 속도 제한 차단기, 기능 플래그 킬은 자율 에이전트보다 앞섭니다. 새로운 것은 공격 표면입니다: 에이전트는 신뢰할 수 없는 콘텐츠를 읽고(레슨 11), 자기 메모리를 수정하며, 안전해 보이는 많은 행동을 조합해 안전하지 않은 하나로 만들 수 있습니다. 여기 소개된 탐지기들이 작동하는 이유는 에이전트의 자기 보고를 신뢰하지 않기 때문입니다.

## 개념

### 킬 스위치

킬 스위치는 에이전트가 읽을 수는 있지만 쓸 수 없는 불리언입니다. 구현 선택지:

- **관리형 서비스의 기능 플래그.** LaunchDarkly, Statsig, Unleash. 업데이트가 수 초 안에 전파됩니다.
- **에이전트가 폴링하는 Redis 키.** 단순합니다; 에이전트 프로세스가 매 턴 확인해야 합니다.
- **오브젝트 스토리지의 서명된 설정.** 에이전트가 부팅 시 서명을 검증합니다; 서명 없는 상태는 거부합니다.
- **OS 수준 신호 또는 컨테이너 수명 주기 킬.** Docker `kill`, Kubernetes `kubectl delete pod`, systemd stop.

올바른 킬 스위치가 갖는 성질:

- 에이전트가 그것을 `off`로 설정할 수 없습니다. (에이전트의 자격 증명이 쓰지 않는 시스템에 삽니다.)
- 시작 시점뿐 아니라 모든 중대 행동에서 검사됩니다.
- 꺼져 있을 때, 에이전트는 외부에서 관찰 가능한 어떤 일도 하지 않습니다. 에이전트가 닿을 수 있는 시스템에 로그를 남기는 것조차 포함해서요.
- 다시 켜는 것은 자동 타임아웃이 아니라 명시적인 사람의 행위입니다.

### 서킷 브레이커

서킷 브레이커는 에이전트 전체가 아니라 특정 패턴을 일시 정지합니다. 고전적인 형태(2007년 Nygard 책에서, 여전히 유효):

- **닫힘(Closed)**: 행동이 허용됩니다.
- **열림(Open)**: 행동이 차단됩니다.
- **반열림(Half-open)**: 냉각 시간 후 1~3번의 탐지 시도가 허용됩니다(기본 1); 성공하면 브레이커가 닫히고, 남아 있는 실패가 있으면 다시 열립니다.

에이전트와 관련된 트리거:

- 연속 다섯 번의 동일한 도구 호출 (반복 루프).
- 다른 입력으로 같은 도구에서 연속 다섯 번의 실패 (체계적 실패).
- 임계값을 넘는 도구 호출 속도 (레슨 13의 속도).
- out-of-trust 콘텐츠 읽기(레슨 11) 이후의 특정 도구 호출 (예: `file.delete`).

### 카나리아 토큰

카나리아 토큰(honeytoken이라고도 함)은 에이전트가 절대 건드리면 안 되는 입력입니다. 접근 자체가 경보입니다.

에이전트를 위한 예시:

- 실제 권한이 없는 가짜 `AWS_SECRET_ACCESS_KEY`를 환경에 넣어 둡니다. 유출 시도가 즉시 귀속됩니다.
- 알려진 센티널 값으로 표시된 가짜 데이터베이스 레코드. 이 레코드를 읽거나 갱신하면 경보가 울립니다.
- 워크스페이스의 가짜 파일. 이 파일을 읽거나 편집하면 수상합니다.
- 세션 시작 시 주입된 가짜 메모리 항목. 이후 출력에 그것이 나타나면 메모리가 유출된 것입니다.

카나리아 설계는 워크플로에 특화됩니다. 에이전트가 건넬 정당한 이유가 있는 카나리아는 소음일 뿐입니다.

### 통계적 한계와 하드 한계를 계층화하는 이유

통계적 탐지기(EWMA, CUSUM, 도구 호출률의 z-score)는 움직이는 베이스라인에 적응합니다. 이것은 정당한 표류에는 기능이지만 적대적 표류에는 버그입니다. 인내심 있는 공격자는 경보가 울리지 않을 만큼 충분히 천천히 베이스라인을 옮길 수 있습니다.

하드 헌법적 한계(레슨 17)는 굽히지 않습니다. "`secrets@`로는 절대 이메일을 보내지 않는다"는 헌법 규칙은 더 단순하고, 감사 가능하고, 느린 표류로 속일 수 없습니다. 계층화 패턴: 통계적 탐지기가 대부분의 소음을 잡고, 하드 한계가 탐지기를 지나쳐 간 공격을 잡습니다.

### eBPF 데이터패스 리다이렉트를 통한 격리

Cilium의 eBPF 기반 네트워크 정책은 커널 계층에서 격리된 파드의 외부 통신을 포렌식 허니팟으로 재작성할 수 있습니다. Cilium의 공개 벤치마크는 TCP_RR에서 1밀리초 미만의 P99 데이터패스 지연 시간을 보고합니다; 클러스터에서 격리를 *촉발하는* 데 드는 실제 시간은 정책 업데이트가 컨트롤 플레인에서 노드로 전파되는 방식이 지배합니다 (operator가 미리 로드된 Kubernetes에서 수백 밀리초가 현실적입니다; 꼬리 지연은 클러스터 크기와 조정(reconcile) 주기에 따라 달라집니다). 이것은 두 가지를 줍니다: 에이전트가 진짜 아무것도 유출하지 않고, 포함된 상태에서 허니팟 안에서의 에이전트 행동이 완전히 관찰됩니다. 같은 패턴, 다른 계층 — 카나리아 토큰과 같습니다: 에이전트는 포함된 상태에서 무엇을 하려 하는지로 의도를 드러냅니다.

### 어떤 탐지기도 잡지 못하는 것

- **허용된 프리미티브를 조합한 의미론적 공격.** 개별 행동은 모든 탐지기를 통과합니다; 조합이 문제입니다. 레슨 10의 Auto Mode 복합 실패입니다.
- **탐지기를 페이로드의 일부로 삼는 공격.** 에이전트가 "행동하기 전에 카나리아를 비활성화하라"는 페이지를 읽고 에이전트가 그 능력을 갖고 있다면, 탐지기는 무력화됩니다. 카나리아 토큰은 에이전트가 수정할 수 없는 시스템에 있어야 합니다.

## 연습 문제

1. `code/main.py`를 실행해 보세요. 서킷 브레이커가 5턴(다섯 번째 동일 호출)에 발동하고 카나리아가 9턴(가짜 키 읽기)에 발동함을 확인하세요.

2. 통계적 탐지기를 추가해 보세요: 도구 호출률의 EWMA z-score. 천천히 표류하는 궤적을 넣고 탐지기가 절대 발동하지 않음을 보여주세요. 이제 하드 한계(10분 안에 50번 이상 도구 호출 금지)를 추가하고 같은 궤적에서 하드 한계가 발동함을 보여주세요.

3. 브라우저 에이전트(레슨 11)를 위한 카나리아 토큰 집합을 설계해 보세요. 최소 세 개의 카나리아와 각각이 무엇을 탐지할지 나열하세요.

4. Cilium 네트워크 정책 문서를 읽어 보세요. 외부 통신 리다이렉트 격리 흐름을 구체적으로 묘사하세요: 어떤 정책 셀렉터, 어떤 파드, 어떤 egress 재작성, 어떤 경보. "격리 결정"부터 "첫 리다이렉트 패킷"까지의 실제 시간을 지배하는 것은 무엇인가요?

5. 킬 스위치가 작동된 에이전트의 재활성화 절차를 정의해 보세요. 누가 재활성화할 수 있나요? 무엇이 문서화되어야 하나요? 재활성화 전에 에이전트의 무엇이 바뀌어야 하나요?

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| 킬 스위치 | "오프 버튼" | 에이전트의 수정 범위 밖의 불리언; 모든 중대 행동에서 검사됨 |
| 서킷 브레이커 | "패턴 일시 정지" | 반복, 실패율, 또는 속도 제한에서 행동별로 작동 |
| 카나리아 토큰 | "허니토큰" | 에이전트가 건넬 정당한 이유가 없는 미끼; 접근이 경보를 울림 |

| EWMA | "이동 평균" | 지수 가중; 표류에 적응 (기능이자 버그) |
