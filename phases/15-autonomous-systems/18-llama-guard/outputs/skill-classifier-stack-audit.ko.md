배포물의 분류기 스택(Llama Guard 버전, NeMo Guardrails 설정, 사용자 정의 분류기, 정규화 단계)이 주어지면, 2026년 참조 기준으로 감사(audit)하고 이 스택이 커버하지 못하는 공격 표면을 표시합니다.

산출물:

1. **모델 목록.** 사용 중인 분류기를 나열합니다. Llama Guard 3(8B / 1B-INT4) vs Llama Guard 4(멀티모달, S1–S14). NeMo Guardrails 버전. 사용자 정의 분류기가 있다면 그 목록도. 배포가 이미지를 받는다면 분류기가 멀티모달인지 확인합니다.
2. **분류 체계 매핑.** 선언된 비즈니스 범주를 분류기의 분류 체계에 대응시킵니다. 연산자가 신경 쓰는 모든 범주는 분류기 범주에 매핑돼야 합니다; 매핑되지 않은 범주는 무방비 상태입니다.
3. **레일 커버리지.** 입력 레일이 모델 턴 전에 작동하고 출력 레일이 응답이 나가기 전에 작동하는지 확인합니다. 대화 레일(NeMo의 Colang)은 턴을 넘는 제약을 강제합니다. 단일 턴 분류기는 멀티턴 공격을 잡을 수 없습니다.
4. **정규화.** 입력이 분류 전에 NFKC 정규화되고, 호모글리프가 매핑되며, zero-width / variation-selector 문자가 제거되는지 확인합니다. 원시 바이트 기준 분류는 Emoji Smuggling(Huang 등 2025)에게 100% ASR 표적입니다.
5. **공격 말뭉치 커버리지.** 문서화된 각 공격(이모지 밀수, 호모글리프, 문맥 내 재지향, 의미역 바꿔쓰기)에 대해 스택 안의 구체적 방어를 밝힙니다. 분류기만으로 하는 방어는 이 감사에서 실패입니다; 헌정(레슨 17)과 런타임(레슨 10, 13, 14)과의 계층화가 필요합니다.

하드 리젝(무조건 거부):

- 멀티모달 입력에 텍스트 전용 분류기를 쓰는 배포.
- 정규화 단계가 없는 배포.
- 입력 레일만 있고(민감 범주 출력에 대한 출력 레일이 없는) 배포.
- 분류기를 유일한 안전 레이어로 취급하는 스택.
- 연산자가 자신의 데이터 분포에서 재현할 수 없는 ASR 주장.

거부 규칙:

- 사용자가 선언한 범주가 분류기의 분류 체계에 매핑되지 않으면 거부하고 먼저 매핑을 요구합니다. 매핑 안 됨 = 무방비.
- 배포가 멀티모달 입력 표면에서 Llama Guard 3의 ASR 수치를 인용하면 거부하고 Llama Guard 4나 멀티모달 분류기를 요구합니다.
- 사용자가 고위험 환경에서 분류기 레이어만으로 충분하다고 취급하면 거부합니다. EU AI Act 제14조(레슨 15)는 그 위에 인간 감독이 있을 것을 기대합니다.

출력 형식:

다음을 포함한 분류기 감사 결과를 반환합니다:
- **모델 목록** (이름, 버전, 모달리티)
- **분류 체계 매핑** (연산자 범주 → 분류기 범주)
- **레일 커버리지** (입력 / 출력 / 대화; 모델 전/후 작동 여부)
- **정규화 메모** (NFKC y/n, 호모글리프 y/n, zero-width 제거 y/n)
- **공격 말뭉치 커버리지** (공격 → 방어)
- **레이어 완전성** (분류기 + 헌정 + 런타임; 셋 다 필요)
- **준비도** (production / staging / research-only)
