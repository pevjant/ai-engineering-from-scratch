# 자율 코딩 에이전트의 현황 (2026)

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> SWE-bench Verified는 3년도 안 되어 4%에서 80.9%로 올라갔습니다. 같은 Claude Sonnet 4.5가 SWE-agent v1에서는 43.2%, Cline 자율(autonomous) 스캐폴드에서는 59.8%를 기록했습니다 — 이제는 모델 주위의 스캐폴딩(뼈대 구조)이 모델 자체만큼 중요하다는 뜻입니다. OpenHands(구 OpenDevin)는 가장 활발한 MIT 라이선스 플랫폼이며, 그 CodeAct 루프는 JSON 도구 호출 대신 파이썬 액션을 샌드박스에서 직접 실행합니다. 화려한 수치 뒤에는 방법론적 문제가 숨어 있습니다: SWE-bench Verified의 500개 태스크 중 161개는 1~2줄 변경만으로 풀리고, SWE-bench Pro(10줄 이상 태스크)에서는 같은 최전선(frontier) 모델들도 23~59%에 머물러 있습니다.

**유형:** 학습(Learn)
**언어:** Python (표준 라이브러리, CodeAct vs JSON 도구 호출 비교)
**선수 지식:** 페이즈 14 · 07 (도구 사용), 페이즈 15 · 01 (장기 에이전트)
**시간:** 약 45분

## 문제

"어떤 코딩 에이전트가 가장 좋은가"는 잘못된 질문입니다. 올바른 질문은 이것입니다: 나의 작업과 맞닿은 태스크 분포에서, 내가 프로덕션(운영 환경)에서 돌릴 스캐폴딩을 썼을 때, 어느 정도의 엔드투엔드 신뢰성을 얻을 수 있는가?

2022년부터 2026년 사이에 이 분야는 스캐폴딩 — 검색 계층, 플래너, 샌드박스, 편집-검증 루프, 피드백 형식 — 이 건축물의 기둥(load-bearing)이라는 것을 배웠습니다. SWE-agent v1 안의 Claude Sonnet 4.5는 SWE-bench Verified에서 43.2%를 기록했지만, 같은 모델이 Cline의 자율 스캐폴드 안에서는 59.8%를 기록했습니다. 절대 16.6점의 차이, 같은 가중치. 베이스 모델은 부품이고, 루프가 곧 제품입니다.

짝을 이루는 문제는 벤치마크 포화가 회귀를 가려준다는 것입니다. SWE-bench Verified는 거의 포화 상태이고, 쉬운 태스크 꼬리(500개 중 161개가 2줄 이하 변경)가 상위 점수를 끌어올립니다. 실제 환경의 품질은 SWE-bench Pro(10줄 이상 변경) 같은 분포에서 더 잘 측정되는데, 같은 선두 주자들도 여기서는 23~59%에 그칩니다.

## 개념

### SWE-bench, 한 단락 요약

SWE-bench(Jimenez 외)는 정답 패치가 있는 실제 GitHub 이슈를 가져와, 에이전트가 테스트 스위트를 통과시키는 패치를 만들어내도록 합니다. SWE-bench Verified(OpenAI, 2024)는 모호하고 깨진 태스크를 제거한, 사람이 검수한 500개 태스크 부분집합입니다. SWE-bench Pro는 더 어려운 후속 벤치마크로 — 10줄 이상의 변경이 필요한 태스크들로 이루어져 있으며, 현재 최전선 에이전트들이 23~59%에 머물러 있습니다.

### 2022 → 2026 곡선이 실제로 보여주는 것

- **2022**: 연구용 모델들이 원본 SWE-bench에서 약 4%.
- **2024**: GPT-4 + Devin 스타일 스캐폴딩이 약 14%; SWE-agent는 약 12%.
- **2025**: Aider와 SWE-agent 안의 Claude 3.5/3.7 Sonnet이 40~55% 구간으로 진입.
- **2026**: Claude Sonnet 4.5와 최전선 경쟁 모델들이 SWE-bench Verified에서 70~80%+. Epoch AI의 리더보드가 이를 실시간 추적합니다.

그 기울기는 세 가지가 누적된 결과입니다: 더 좋은 베이스 모델, 더 좋은 스캐폴딩(CodeAct, 반성(reflection), 검증기 루프), 더 좋은 벤치마크(Verified가 노이즈 제거).

### CodeAct vs JSON 도구 호출

OpenHands(All-Hands-AI, arXiv:2407.16741, 구 OpenDevin)는 특정한 아키텍처 베팅을 했습니다: 모델이 JSON 도구 호출을 내보내 호스트가 이를 해석해 실행하는 대신, 모델이 파이썬 코드를 내보내면 Jupyter 스타일 커널이 샌드박스에서 그것을 실행합니다. 에이전트는 하나의 액션 안에서 파일을 순회하고, 도구를 연결하고, 자기 예외를 잡아낼 수 있습니다.

트레이드오프:

- **JSON 도구 호출**: 모든 액션이 한 턴; 감사하기 쉬움; 조합성은 제한적; 각 호출이 명시적 검증기를 거치므로 기본적으로 안전.
- **CodeAct**: 하나의 액션이 프로그램 전체일 수 있음; 조합 가능; 튼튼하게 강화된 샌드박스가 필요 (OpenHands는 Docker 격리 사용); 실패 양상은 샌드박스 런타임이 허용하는 무엇이든 될 수 있음.

두 아키텍처 모두 프로덕션에 있습니다. CodeAct는 오픈 플랫폼(OpenHands, smolagents)에서 우세합니다. JSON 도구 호출은 제공자가 실행기를 통제하는 관리형 서비스(Anthropic Managed Agents, OpenAI Assistants)에서 여전히 우세합니다.

### 2026년 현황판의 스캐폴드들

| 스캐폴드 | 라이선스 | 실행 모델 | 주목할 특성 |
|---|---|---|---|
| OpenHands (OpenDevin) | MIT | Docker 안의 CodeAct | 가장 활발한 오픈 플랫폼; 이벤트 스트림 재생 가능 |
| SWE-agent | MIT | 에이전트-컴퓨터 인터페이스(ACI) | 최초의 엔드투엔드 SWE-bench 스캐폴드 |
| Aider | Apache-2 | 로컬 저장소의 diff 기반 편집 | 미니멀한 스캐폴드, 강한 회귀 안정성 |
| Cline | Apache-2 | 도구 정책이 있는 VS Code 에이전트 | Sonnet 4.5 기준 최고 점수 오픈 스캐폴드 |
| Devin (Cognition) | 사유(Proprietary) | 관리형 VM + 플래너 | 최초의 "AI 소프트웨어 엔지니어" 제품 카테고리 |
| Claude Code | 사유(Proprietary) | 권한 모드 + 루틴 | 레슨 10에서 에이전트 루프를 자세히 다룸 |

### 스캐폴딩이 지배적인 이유

코딩 실행은 장기 궤적입니다(레슨 1). 신뢰성은 단계마다 누적됩니다. 스캐폴딩이 점수를 벌어오는 세 지점:

1. **검색**: 어떤 파일을 읽을지 찾는 것이 소리 없는 병목입니다. SWE-agent의 ACI, OpenHands의 파일 인덱스, Aider의 repo-map이 모두 여기를 노립니다.
2. **검증기 루프**: 테스트를 돌리고, 스택 트레이스를 읽고, 다시 시도하는 것은 SWE-bench에서 10점 이상의 절대 차이를 만듭니다.
3. **실패 봉쇄**: 오류 시 롤백하는 샌드박스는 피해가 누적되는 것을 막습니다. 검증기 루프가 있고 없고의 같은 모델은 서로 다른 두 제품처럼 보입니다.

### 벤치마크 포화와 실제 분포

OpenHands 저자들과 Epoch AI는 모두 SWE-bench Verified에 쉬운 꼬리가 있다고 지적합니다: 500개 중 161개 태스크는 1~2줄 변경만 필요합니다. 높은 점수는 부분적으로 이 꼬리 때문입니다. SWE-bench Pro는 10줄 이상 변경으로 한정하며, 최전선 시스템이라도 23~59% 범위의 점수로 돌아옵니다. 여러분의 프로덕션 분포는 거의 확실히 Verified보다 Pro에 가깝습니다.

에이전트 선택에 주는 시사점: 자신의 버그 백로그에서 Pro 스타일 부분집합을 만들어 실행해 보세요. 중요한 점수는 여러분이 출시하는 것과 유사한 태스크 위에서의 점수입니다.

## 사용해 보기

`code/main.py`는 고정된 미니 태스크 분포에서 두 개의 장난감 에이전트 스캐폴드를 비교합니다:

1. 턴당 하나의 액션을 취하는 **JSON 도구 호출** 스캐폴드.
2. 액션당 작은 파이썬 스니펫을 내보낼 수 있는 **CodeAct** 스캐폴드.

둘 다 스텁 "모델"(결정론적 규칙)을 사용하므로, 비교가 모델 품질을 배제하고 스캐폴드만 분리해 봅니다. 출력은 CodeAct 스캔폴드가 더 적은 턴으로 더 많은 태스크를 해결하지만, 액션 하나의 폭발 반경(blast radius)이 더 크다는 것을 보여줍니다.

`outputs/skill-scaffold-audit.md`는 채택 전에 제안된 코딩 에이전트 스캐폴드를 감사하도록 돕습니다: 검색 품질, 검증기 유무, 샌드박스 격리, 벤치마크-분포 적합성.

## 연습 문제

1. `code/main.py`를 실행해 보세요. 같은 태스크 집합에서 각 스캐폴드는 몇 턴이 걸리나요? 각각의 액션당 폭발 반경은 얼마인가요?

2. OpenHands 논문(arXiv:2407.16741)을 읽어 보세요. 논문은 복잡한 태스크에서 CodeAct가 JSON 도구 호출을 이긴다고 주장합니다. 논문이 인정하는 실패 양상 하나를 찾아, 그 양상이 프로덕션에서 지배적이 될 상황을 한 문장으로 써 보세요.

3. 버그 백로그에서 두 파일에 걸쳐 10줄 이상의 변경이 필요한 태스크 하나를 고르세요. (a) JSON 도구 호출과 (b) CodeAct에서 최전선 모델의 엔드투엔드 성공 확률을 추정해 보세요. 그 격차를 정당화하세요.

4. SWE-bench Verified에는 단일 파일, 1~2줄 태스크가 161개 있습니다. 이것들을 제외하는 점수를 만들어 보세요. 리더보드는 어떻게 재편되나요?

5. "Introducing SWE-bench Verified"(OpenAI)를 읽어 보세요. 모호한 태스크를 제거할 때 사용된 구체적인 방법론을 설명하고, 그 검수가 놓칠 수 있는 카테고리 하나를 찾아보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| SWE-bench | "코딩 벤치마크" | 정답 패치와 테스트 스위트가 붙은 실제 GitHub 이슈들 |
| SWE-bench Verified | "정제된 부분집합" | 사람이 검수한 500개 태스크, 쉬운 꼬리 존재 |
| SWE-bench Pro | "더 어려운 부분집합" | 10줄 이상 변경; 최전선도 23~59% |
| CodeAct | "코드 곧 액션" | 에이전트가 파이썬을 내보냄; Jupyter 스타일 커널이 샌드박스에서 실행 |
| JSON 도구 호출 | "함수 호출" | 각 액션이 실행 전에 검증되는 구조화된 JSON 페이로드 |
| 스캐폴드 | "에이전트 프레임워크" | 베이스 모델 주위의 검색 + 플래너 + 실행기 + 검증기 루프 |
| ACI (Agent-Computer Interface) | "SWE-agent의 형식" | 사람용 셸이 아니라 LLM 사용성에 맞춰 설계된 명령 집합 |
| 검증기 루프 | "테스트하고 재시도" | 테스트 실행, 출력 읽기, 패치 수정; 모델 외 요인 중 가장 큰 신뢰성 향상 |
