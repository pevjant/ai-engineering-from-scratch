> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-scaffold-audit.md](skill-scaffold-audit.md)

제안된 코딩 에이전트 스캐폴드(SWE-agent, OpenHands, Aider, Cline, Devin, Claude Code, 또는 자체 제작)가 주어지면, 네 축으로 점수를 매기고 벤치마크 숫자가 프로덕션 품질을 과장하게 되는 지점을 표시합니다.

작성할 내용:

1. **검색.** 스캐폴드가 에이전트가 행동하기 전에 어떤 파일을 읽을지 고르는 방식을 설명합니다. 저장소 맵, 임베딩 검색, 명시적 파일 목록, 또는 에이전트 주도의 `grep` 호출. 검색 품질은 소리 없이 지배적인 신뢰성 요인입니다.
2. **검증기 루프.** 스캐폴드가 테스트를 실행하고, 스택 트레이스를 읽고, 실패를 다음 턴에 피드백하는가? 검증기 루프가 없으면 누락으로 표시하세요 — SWE-bench류 태스크에서 보통 절대 10점 이상의 차이를 만드는 부분입니다.
3. **샌드박스와 폭발 반경.** 액션은 어디에서 실행되는가? 로컬 파일 시스템, 임시 컨테이너, 관리형 VM. CodeAct 스타일 스캐폴드라면 샌드박스가 강화되어 있는지 확인하세요(외부 통신 차단, 호스트 마운트 없음, 시간 제한). JSON 도구 호출 스캐폴드라면 도구 검증기가 의도하지 않은 모든 부작용을 거부하는지 확인하세요.
4. **벤치마크 적합성.** 보고된 숫자(예: "SWE-bench Verified 80.9%")가 실제로 어떤 분포를 커버하는가? 벤치마크에서 1~2줄 태스크가 차지하는 비율을 세어 보고; 같은 모델의 보고 점수를 SWE-bench Pro(10줄 이상 태스크) 점수와 비교하세요. 화려한 숫자가 쉬운 꼬리에서 나온 스캐폴드는 프로덕션 신호가 아닙니다.

하드 리젝(무조건 거부):
- 사소한 수준을 넘는 태스크에 검증기 루프 없이 쓰이는 스캐폴드.
- 실제 저장소를 겨냥하면서 샌드박스 격리가 없는(Docker도, 루트리스 컨테이너도, VM도 없는) CodeAct 스캐폴드.
- 분포를 공개하지 않는(쉬운 꼬리 비율, Pro 환산 점수) 벤치마크 주장.
- 검증기 없이 임의 경로에 접근할 수 있는 도구가 하나라도 있는 도구 호출 스캐폴드 (예: 모델에 노출된 날것의 `shell_exec` 도구).

거부 규칙:
- 사용자가 대표적인 내부 분포에서의 스캐폴드 테스트 스위트 통과율을 제시하지 못하면 거부하고, 소규모 샘플 측정을 먼저 요구하세요. 공개 벤치마크는 절대 품질이 아니라 순위를 예측할 뿐입니다.
- 제안된 스캐폴드가 스테이징 리허설 없이 프로덕션 저장소에 실행될 것이라면 거부하고, 스테이징을 먼저 요구하세요. 코딩 에이전트는 파일을 다시 씁니다; 검색이 나쁜 코딩 에이전트는 잘못된 파일을 다시 씁니다.
- 사용자가 자체 평가 없이 벤치마크 점수만으로 go/no-go 결정을 내리려 한다면 거부하고, 내부 평가 데이터를 요구하세요.

출력 형식:

다음을 포함한 점수 메모를 반환합니다:
- **검색 점수** (0–5, 메커니즘 설명 포함)
- **검증기 루프 점수** (0–5, 피드백 형식 포함)
- **샌드박스 점수** (0–5, 격리 메커니즘 포함)
- **벤치마크 적합성 점수** (0–5, 내부 분포 차이 포함)
- **배포 권고** (프로덕션 / 스테이징 / 연구 전용)
- **한 줄 위험 요약** (가장 유력한 첫 프로덕션 실패)
