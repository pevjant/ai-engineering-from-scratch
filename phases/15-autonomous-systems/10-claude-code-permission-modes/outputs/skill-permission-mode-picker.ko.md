> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-permission-mode-picker.md](skill-permission-mode-picker.md)

제안된 Claude Code 태스크가 주어지면, 권한 모드를 고르고, 예산을 정하고, 에이전트가 시작을 허가받기 전에 필요한 최소한의 격리를 명시합니다.

작성할 내용:

1. **태스크 프로필.** 태스크가 하는 일을 한 문장으로, 잘못됐을 때의 폭발 반경(blast radius)을 한 문장으로.
2. **모드 권고.** `plan`, `default`, `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions` 중 하나. 폭발 반경을 언급하는 한 문장으로 정당화합니다.
3. **예산 숫자.** `max_turns`, `max_budget_usd`, 그리고 도구별 상한의 구체적인 값. 한 시간을 넘는 무인 실행에는, 롤백할 수 없는 사람의 실수에 지불할 의향이 있는 금액과 같거나 그 이하의 달러 상한을 지정합니다.
4. **격리 요건.** 파일 시스템 범위 (프로젝트 디렉터리만, 스크래치 디렉터리, 임시 컨테이너). 네트워크 정책 (외부 통신 없음, 허용 목록만, 전체). 자격 증명 노출 범위 (없음, 범위가 한정된 토큰, 넓은 토큰). `bypassPermissions`나 `dontAsk`의 경우, 실행은 프로덕션 자격 증명이 마운트되지 않은 임시 컨테이너 안에 있어야 합니다.
5. **궤적 감사 계획.** 실행 후 사람이 궤적을 어떻게 검토할 것인가? `auto`, `dontAsk`, 그리고 30분을 넘는 모든 실행에 필수입니다.

하드 리젝(무조건 거부):
- 커밋되지 않은 변경이 있는 저장소에 대한 `bypassPermissions`.
- 예산 상한 없는 `auto`.
- 환경에 넓은 자격 증명이 있는 상태에서의 `acceptEdits`보다 위의 모드 (repo 스코프가 있는 AWS, GCP, GitHub PAT).
- 궤적 감사가 예정되지 않은 채 한 시간을 넘는 무인 실행.
- 새로운 태스크 분포에 대해 Auto Mode 분류기만으로 충분하다는 주장.

거부 규칙:
- 사용자가 실패의 폭발 반경을 말하지 못하면 거부하고, 시작 전에 명시적인 최악의 시나리오 문장을 요구하세요.
- 프로덕션 데이터베이스 자격 증명이 닿을 수 있는 워크스페이스에서 `auto`를 요청하면 거부하고, 범위가 한정된 자격 증명이나 임시 컨테이너를 먼저 요구하세요.
- 제안된 예산 상한이 사용자가 나쁜 실행에서 잃을 의향이 있는 금액을 넘으면 거부하고, 더 낮은 상한을 요구하세요.

출력 형식:

다음을 포함한 한 페이지 실행 카드를 반환합니다:
- **태스크 요약** (한 문장)
- **폭발 반경** (한 문장, 최악의 경우)
- **모드** (명시적으로)
- **예산** (`max_turns`, `max_budget_usd`, 도구별 상한)
- **격리** (fs 범위, 네트워크 정책, 자격 증명 노출 범위)
- **감사 계획** (누가 궤적을 검토하는지, 언제, 어떤 기준으로)
