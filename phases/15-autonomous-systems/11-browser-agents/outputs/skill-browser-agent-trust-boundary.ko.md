제안된 브라우저 에이전트 워크플로가 주어지면, 모든 읽기와 모든 쓰기, 그리고 첫 실행에 필요한 최소 방어 스택을 나열하는 신뢰 경계 범위 문서를 작성합니다.

작성할 내용:

1. **읽기 표면.** 에이전트가 가져올 모든 오리진(origin)을 나열합니다. 각각을 in-trust(사용자 조직이 운영하는 자사 사이트) 또는 out-of-trust(모든 제3자, 모든 사용자 생성 콘텐츠, 모든 검색 결과)로 분류합니다. 모든 out-of-trust 읽기는 잠재적 프롬프트 인젝션 채널로 취급되어야 합니다.
2. **쓰기 표면.** 에이전트가 취하도록 허가된 모든 중대 행동(폼 제출, 콘텐츠 게시, 백엔드 도구 호출, 메모리 쓰기)을 나열합니다. 각각에 대해 폭발 반경과 그 행동이 되돌릴 수 있는지를 밝힙니다.
3. **필요한 방어.** 최소 스택: 콘텐츠 살균기, 읽기/쓰기 경계(content_origin이 out-of-trust일 때 쓰기에는 새 승인 필요), 태스크별 도구 허용 목록, 범위가 한정된 자격 증명을 쓰는 세션 격리, 영속 메모리에 카나리아 토큰, 되돌릴 수 없는 행동에 대한 HITL.
4. **벤치마크-분포 적합성.** 에이전트가 BrowseComp, OSWorld, 또는 WebArena-Verified 점수를 보고한다면, 벤치마크와 실제 태스크 사이의 분포 겹침을 명시합니다. 높은 BrowseComp 점수는 예약 흐름의 신뢰성을 예측하지 못합니다.
5. **알려진 공격 체크리스트.** 배포가 다음에 대해 강화되어 있는지 확인합니다: (a) 보이는 텍스트 인젝션, (b) URL 프래그먼트/쿼리 인젝션, (c) 메모리 결합 공격(Tainted Memories류), (d) 인증된 세션에 대한 CSRF형 공격, (e) 원클릭 하이재킹. 각각에 대해 구체적인 방어와 그것이 어디서 발동되는지를 명시합니다.

하드 리젝(무조건 거부):
- 프로덕션 자격 증명에 접근하면서 세션 격리가 없는 브라우저 에이전트.
- out-of-trust 콘텐츠에서 시작된 쓰기에 새 HITL 승인이 필요하지 않은 배포.
- 콘텐츠 살균기만 의존하는 배포 (살균기는 쉬운 공격을 잡습니다; 정교한 페이로드는 통과합니다).
- 카나리아 항목이 없는 영속 메모리.
- 쓰기에 HITL 없이 금융 거래나 고객 데이터를 건드리는 워크플로.

거부 규칙:
- 사용자가 인젝션으로 인한 잘못된 쓰기의 폭발 반경을 말하지 못하면 거부하고, 명시적인 문장을 요구하세요.
- 범위가 한정된 자격 증명을 쓸 수 없는 스택 위에서 브라우저 에이전트를 제안하면 거부하고, 별도의 신원(identity)을 먼저 요구하세요.
- 사용자가 프로덕션 태스크를 에이전트가 "할 수 있다는" 증거로 벤치마크 점수(BrowseComp, OSWorld, WebArena)를 인용하면 거부하고, 실제 분포에 대한 내부 평가를 요구하세요.

출력 형식:

다음을 포함한 신뢰 경계 메모를 반환합니다:
- **읽기 표면 표** (오리진, in-trust / out-of-trust)
- **쓰기 표면 표** (행동, 폭발 반경, 되돌릴 수 있음 y/n)
- **방어 스택** (구성된 계층의 불릿 목록)
- **벤치마크 적합성 노트** (해당하는 경우)
- **알려진 공격 체크리스트** (다섯 행, 행마다 방어 명시)
- **배포 판정** (프로덕션 / 스테이징 / 연구 전용)
