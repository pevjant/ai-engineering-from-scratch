# 브라우저 에이전트와 장기 웹 태스크

> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [en.md](en.md)

> ChatGPT agent(2025년 7월)는 Operator와 딥 리서치를 하나의 브라우저/터미널 에이전트로 통합하고 BrowseComp SOTA를 68.9%로 기록했습니다. OpenAI는 2025년 8월 31일 Operator를 종료했습니다 — 제품 계층에서의 통합입니다. Anthropic의 Vercept 인수는 OSWorld에서의 Claude Sonnet을 15% 미만에서 72.5%로 끌어올렸습니다. WebArena-Verified(ServiceNow, ICLR 2026)는 원본 WebArena의 11.3퍼센트포인트에 달하는 거짓 음성(false-negative) 비율을 고치고 258개 태스크의 Hard 부분집합을 출시했습니다. 수치는 실제입니다. 공격 표면도 실제입니다: OpenAI의 준비성 책임자는 브라우저 에이전트에 대한 간접 프롬프트 인젝션이 "완전히 패치할 수 있는 버그가 아니다"라고 공개적으로 밝혔습니다. 문서화된 2025~2026년 공격: Tainted Memories(Atlas CSRF), HashJack(Cato Networks), 그리고 Perplexity Comet의 원클릭 하이재킹.

**유형:** 학습(Learn)
**언어:** Python (표준 라이브러리, 간접 프롬프트 인젝션 공격 표면 모델)
**선수 지식:** 페이즈 15 · 10 (권한 모드), 페이즈 15 · 01 (장기 에이전트)
**시간:** 약 45분

## 문제

브라우저 에이전트는 신뢰할 수 없는 콘텐츠를 읽고 결과가 중대한 행동을 취하는 장기 에이전트입니다. 에이전트가 방문하는 모든 페이지는 사용자가 작성하지 않은 입력입니다. 모든 페이지의 모든 폼은 잠재적 명령 채널입니다. 2025~2026년 공격 사례 집합은 이것이 가설이 아님을 보여줍니다: Tainted Memories는 공격자가 조작된 페이지를 통해 에이전트의 메모리에 악성 지시를 묶어 둘 수 있게 하고, HashJack은 에이전트가 방문하는 URL 프래그먼트에 명령을 숨기며, Perplexity Comet 하이재킹은 클릭 한 번으로 터집니다.

방어 측면의 상황은 편하지 않습니다. OpenAI의 준비성 책임자는 조용한 부분을 큰 소리로 말했습니다: 간접 프롬프트 인젝션은 "완전히 패치할 수 있는 버그가 아니다"라고요. 그 이유는 공격이 에이전트의 읽기-행동 경계에 살고 있는데, 이 경계가 구조적으로 모호하기 때문입니다 — 모델이 읽는 모든 토큰은 원리상 지시로 읽힐 수 있습니다.

이 레슨은 공격 표면의 이름을 붙이고, 벤치마크 현황(BrowseComp, OSWorld, WebArena-Verified)을 짚으며, 최소한의 간접 프롬프트 인젝션 시나리오를 모델링해서 레슨 14와 18에서 실제 방어를 reasoning할 수 있게 합니다.

## 개념

### 2026년 현황, 시스템당 한 단락

**ChatGPT agent (OpenAI).** 2025년 7월 출시. Operator(브라우징)와 Deep Research(수 시간 리서치)를 통합. 2025년 8월 31일 독립형 Operator를 종료. BrowseComp에서 68.9%의 SOTA; OSWorld와 WebArena-Verified에서도 강한 수치.

**Claude Sonnet + Vercept (Anthropic).** Anthropic의 Vercept 인수는 컴퓨터 사용 능력에 집중했습니다. OSWorld에서의 Claude Sonnet을 15% 미만에서 72.5%로 옮겼습니다. Claude Computer Use는 도구 API로 출시됩니다.

**Gemini 3 Pro with Browser Use (DeepMind).** Browser Use 통합은 컴퓨터 사용 컨트롤을 제공합니다; FSF v3(2026년 4월, 레슨 20)는 특히 ML R&D 도메인에서의 자율성을 추적합니다.

**WebArena-Verified (ServiceNow, ICLR 2026).** 잘 문서화된 문제를 고칩니다: 원본 WebArena는 약 11.3%의 거짓 음성 비율(실제로는 풀었는데 실패로 표시된 태스크)이 있었습니다. Verified 릴리스는 사람이 검수한 성공 기준으로 재채점하고 258개 태스크의 Hard 부분집합을 추가합니다(ICLR 2026 논문, openreview.net/forum?id=94tlGxmqkN).

### BrowseComp vs OSWorld vs WebArena

| 벤치마크 | 측정하는 것 | 수행 시간 |
|---|---|---|
| BrowseComp | 시간 압박 속에서 열린 웹에서 특정 사실 찾기 | 수 분 |
| OSWorld | 에이전트가 완전한 데스크톱(마우스, 키보드, 셸)을 운영 | 수십 분 |
| WebArena-Verified | 시뮬레이션된 사이트에서의 트랜잭션성 웹 태스크 | 수 분 |
| Hard 부분집합 | 다중 페이지 상태 전이가 있는 WebArena-Verified 태스크 | 수십 분 |

서로 다른 축입니다. 높은 BrowseComp 점수는 에이전트가 사실을 찾는다는 말이지, 비행기를 예약할 수 있다는 말이 아닙니다. OSWorld 점수는 "내 데스크톱에서 동작하는가"에 더 가깝습니다. WebArena-Verified는 "흐름 하나를 끝낼 수 있는가"에 더 가깝습니다. 모든 프로덕션 결정에는 태스크 분포와 맞는 벤치마크가 필요합니다.

### 공격 표면, 이름 붙이기

1. **간접 프롬프트 인젝션.** 신뢰할 수 없는 페이지 콘텐츠에 지시가 들어 있습니다. 에이전트가 그것을 읽습니다. 에이전트가 그것을 실행합니다. 공개된 사례: 2024 Kai Greshake 외, 2025 Tainted Memories 논문, 2026 HashJack(Cato Networks).
2. **URL 프래그먼트 / 쿼리 인젝션.** 크롤된 URL의 `#fragment`나 쿼리 문자열에 명령이 들어 있습니다. 화면에는 절대 렌더링되지 않지만; 여전히 에이전트의 컨텍스트 안에 있습니다.
3. **메모리 결합 공격.** 페이지가 에이전트에게 영속 메모리에 쓰라고 지시합니다(레슨 12가 영속 상태를 다룹니다). 다음 세션에서 그 메모리가 눈에 보이는 트리거 없이 페이로드를 발사합니다.
4. **인증된 세션에 대한 CSRF형 공격.** Tainted Memories류: 에이전트가 어딘가에 로그인해 있고; 공격자의 페이지가 에이전트가 사용자의 쿠키로 실행하는 상태 변경 요청을 발행합니다.
5. **원클릭 하이재킹.** 겉보기에 무해한 버튼이 에이전트가 따르는 페이로드를 태우고 갑니다. Comet류.
6. **에이전트 호스트 표면의 콘텐츠 보안 정책(CSP) 구멍.** 렌더링 계층과 도구 계층 자체가 공격 벡터가 될 수 있습니다; 브라우저 안의 브라우저 에이전트 스택은 넓습니다.

### "완전히 패치할 수 없는" 이유

공격은 에이전트의 능력과 동형(isomorphic)입니다. 에이전트는 일을 하려면 신뢰할 수 없는 콘텐츠를 읽어야 합니다. 에이전트가 읽는 어떤 콘텐츠든 지시를 담고 있을 수 있습니다. 에이전트가 따르는 어떤 지시든 사용자의 실제 요청과 어긋날 수 있습니다. 방어(신뢰 경계, 분류기, 도구 허용 목록, 중대한 행동에 대한 HITL)는 공격의 비용을 올리고 폭발 반경을 줄입니다. 하지만 이 공격 부류를 닫지는 못합니다.

이것은 뵈의 정리(레슨 8)와 같은 논리 구조입니다: 에이전트는 다음 토큰이 안전하다고 증명할 수 없습니다; 안전하지 않은 토큰이 더 잘 탐지되는 시스템을 세울 수 있을 뿐입니다.

### 실제로 출시되는 방어 자세

- **읽기/쓰기 경계.** 읽기는 절대 중대하지 않습니다. 쓰기(폼 제출, 콘텐츠 게시, 부작용이 있는 도구 호출)는, 그것을 촉발한 콘텐츠가 신뢰 경계 밖에서 왔다면 새로운 사람의 승인이 필요합니다.
- **태스크별 도구 허용 목록.** 에이전트는 브라우징할 수 있습니다; 그 태스크를 위해 명시적으로 켜지 않았다면 해외 송금을 시작할 수는 없습니다. 레슨 13이 예산을 다룹니다.
- **세션 격리.** 브라우저 에이전트 세션은 범위가 한정된 자격 증명으로만 실행됩니다. 프로덕션 인증 없음, 개인 이메일 없음. 모든 HTTP 요청의 로그를 감사용으로 보관합니다.
- **콘텐츠 살균기(sanitizer).** 가져온 HTML은 모델 컨텍스트에 이어 붙이기 전에 알려진 나쁜 패턴을 걷어냅니다. (쉬운 공격을 줄입니다; 정교한 페이로드는 못 막습니다.)
- **중대한 행동에 대한 HITL.** 제안-후-확정 패턴(레슨 15).
- **메모리에 카나리아 토큰.** 메모리 항목이 발화하면 사용자가 그것을 봅니다(레슨 14).

## 연습 문제

1. `code/main.py`를 실행해 보세요. 살균기는 잡지만 읽기/쓰기 경계는 잡지 못하는 공격이 무엇인지, 그리고 읽기/쓰기 경계만 잡는 공격이 무엇인지 찾아보세요.

2. HashJack 스타일의 URL 프래그먼트 인젝션 한 부류를 탐지하도록 살균기를 확장해 보세요. 정당한 프래그먼트가 있는 정상 URL에서의 오탐 비율을 측정하세요.

3. 여러분이 아는 실제 브라우저 에이전트 워크플로 하나를 고르세요(예: "비행기 예약"). 모든 읽기와 모든 쓰기를 나열하세요. 어떤 쓰기가 HITL이 필요한지와 그 이유를 표시하세요.

4. WebArena-Verified ICLR 2026 논문을 읽어 보세요. 원본 WebArena의 채점이 신뢰할 수 없었던 태스크 카테고리 하나를 찾고, Verified 부분집합이 그것을 어떻게 해결하는지 설명하세요.

5. 브라우저 에이전트 설정을 위한 메모리 카나리아를 설계해 보세요. 무엇을, 어디에 저장하고, 무엇이 경보를 울리게 할까요?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| 간접 프롬프트 인젝션 | "나쁜 페이지 텍스트" | 에이전트가 읽는 페이지의 신뢰할 수 없는 콘텐츠가 에이전트가 실행할 지시를 담음 |
| Tainted Memories | "메모리 공격" | 에이전트가 공격자가 제공한 지시를 영속 메모리에 씀; 다음 세션에서 발화 |
| HashJack | "URL 프래그먼트 공격" | URL 프래그먼트/쿼리 문자열에 숨겨진 페이로드가 에이전트의 컨텍스트에는 있지만 화면에는 안 보임 |
| 원클릭 하이재킹 | "나쁜 버튼" | 눈에 보이는 UI 요소가 에이전트가 실행하는 후속 페이로드를 태우고 감 |
| BrowseComp | "웹 검색 벤치마크" | 열린 웹에서 특정 사실 찾기; 분 단위 수행 |
| OSWorld | "데스크톱 벤치마크" | 완전한 OS 제어; 다단계 GUI 태스크 |
| WebArena-Verified | "고쳐진 웹 태스크 벤치마크" | ServiceNow가 재채점한 WebArena, Hard 부분집합 포함 |
| 읽기/쓰기 경계 | "부작용 게이트" | 읽기는 절대 중대하지 않음; 콘텐츠가 신뢰 밖이면 쓰기에는 새 승인 필요 |
