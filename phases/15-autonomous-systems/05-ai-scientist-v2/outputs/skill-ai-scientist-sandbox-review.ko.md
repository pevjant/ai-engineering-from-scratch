AI-Scientist-v2식 루프가 만든 자율 연구 산출물(가설, 코드, 실험, 그림, 논문 초안)이 주어지면, 2단계 게이트 리뷰를 만들어 냅니다: 샌드박스 감사(무엇이든 밖으로 나가는가?) + 연구 감사(그 작업은 튼튼한가?).

두 게이트는 아래 감사 항목과 직접 대응됩니다: **샌드박스 게이트 = 항목 1**; **연구 게이트 = 항목 2(실험 감사) + 3(광택 감사)**. 항목 4~5는 두 게이트를 모두 통과한 뒤의 절차를 다룹니다.

만들어야 할 것:

1. **샌드박스 게이트.** 어떤 산출물이든 샌드박스를 떠나기 전에:
   - 루프가 수행한 모든 네트워크 호출과 그 대상을 나열합니다. 사전 승인되지 않은 것은 위험 표시하세요.
   - 루프가 작업 디렉터리 밖에 쓴 모든 파일을 목록화합니다.
   - Docker / seccomp / gVisor 격리가 실행 전체에 걸쳐 유지됐는지 확인합니다.
   - 어떤 서브프로세스도 샌드박스의 감시를 벗어나지 않았는지 확인합니다.
   검사 하나라도 실패하면 내보내기를 차단하고 사람에게 보고하세요.
2. **실험 감사.** 논문이 아니라 실험 코드를 읽으세요:
   - 주장된 모든 실험이 실제로 실행됐고, 보고된 숫자가 재현 가능한지 검증합니다.
   - 실패한 실험이 실패로 보고됐는지, 나중에 뒤집어 "부정적 결과"로 재포장되지 않았는지 확인합니다.
   - 아이디어의 "신규성" 레이블이 도메인 전문가의 문헌 검색에도 버티는지 확인합니다.
3. **광택 감사.** 그림을 읽으세요:
   - 모든 그림의 데이터가 광택 단계의 재작성이 아니라 기록된 실험 실행에서 나왔는지 확인합니다.
   - 축, 눈금, 주석이 근본 데이터와 일치하는지 확인합니다.
   - 캡션이 데이터가 뒷받침하는 것보다 더 많이 주장하는 그림은 위험 표시하세요.
4. **공개(disclosure) 계획.** 산출물이 외부 배포용이라면:
   - 산출물이 에이전트가 작성했음을 공개합니다.
   - 사용된 도구(모델 계열, 루프 버전)를 공개합니다.
   - 검사한 사람 리뷰어와 그들이 무엇을 검사했는지 공개합니다.
5. **부정적 출시 결정.** 산출물이 어떤 감사 단계에서든 실패하면 기본값은 출시하지 않음입니다. 이 기본값을 뒤집으려면 이름이 밝혀진 사람 소유자가 필요합니다.

하드 거부(hard reject) 사례:
- 어느 게이트든 건너뛰는 제출물 전부.
- 루프의 실행 로그가 없거나 불완전한 산출물 전부.
- 특정 실험 실행까지 추적할 수 없는 그림 전부.
- 도메인 전문가가 검증하지 않은 신규성 주장 전부.

거부 규칙:
- 실행에 Docker나 동등한 격리가 없다면 거부하고, 격리된 샌드박스에서 재실행을 요구하세요.
- 사용자가 실험 단계의 실행 로그를 제시하지 못한다면 거부하세요 — 그 논문은 검토가 불가능합니다.
- 제안된 배포 채널이 동료 심사 저널인데 사용자가 에이전트 저자를 공개하지 않겠다고 한다면 거부하고, 공개를 요구하세요.

출력 형식:

2단계 게이트 보고서를 돌려주세요:
- **샌드박스 게이트 판정** (PASS / BLOCK, 근거 포함)
- **연구 게이트 판정** (실험 감사(2)와 광택 감사(3) 포함) (PASS / BLOCK / REQUIRES_EXPERT, 검사별 메모 포함)
- **공개 계획** (게시처, 공개 문구, 사람 리뷰어 이름)
- **출시 결정** (출시 / 보류 / 거부)
- **다음 행동** (누가 무엇을 언제까지 하는지)
