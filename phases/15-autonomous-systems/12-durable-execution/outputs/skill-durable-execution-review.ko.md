제안된 장시간 에이전트 배포(Temporal + OpenAI Agents SDK, PostgreSQL 체크포인터를 쓰는 LangGraph, Microsoft Agent Framework, Claude Code Routines, Cloudflare Durable Objects, 또는 자체 구현)가 주어지면, 내구 실행 패턴 기준으로 설계를 감사합니다.

작성할 내용:

1. **액티비티 목록.** 모든 액티비티(LLM 호출, 도구 호출, HTTP 요청, 파일 쓰기)를 나열합니다. 각각이 재시도 정책, 타임아웃, 멱등성 키를 갖춘 액티비티로 감싸져 있는지 확인합니다. 액티비티 봉투 밖의 날것 LLM 호출은 신뢰성 구멍입니다.
2. **워크플로 결정론성.** 워크플로 코드 안의 모든 비결정론적 읽기(벽시계, 난수, 외부 상태)를 식별합니다. 각각은 리플레이가 같은 값을 반환하도록 부작용 액티비티로 등록되어야 합니다. 숨은 비결정론성이 리플레이 표류의 가장 흔한 원인입니다.
3. **체크포인트 백엔드.** 백엔드(PostgreSQL, SQLite, Redis, Durable Objects)를 명시합니다. 배포를 견디는지 확인합니다. SQLite는 개발 전용입니다. Redis는 AOF 또는 스냅샷 설정이 필요합니다. Cloudflare Durable Objects는 투명하지만 고유 키 규율이 필요합니다.
4. **사람 입력 상태.** HITL을 위한 일시 정지가 폴링 루프가 아니라 일급 워크플로 상태인지 확인합니다. 워크플로는 승인이 도착한 정확한 시점에 재개되는 외부 신호(승인 큐, 웹훅, `interrupt()` 프리미티브)에서 블록해야 합니다.
5. **재개 시 HITL 정책.** 크래시 후의 모든 재개에 대해, 다음 액티비티를 실행하기 전에 새로운 HITL이 필요한지 밝힙니다. 이것이 없으면, 내구 실행과 크래시 전에 내려진 승인이 맥락이 바뀐 뒤에도 승인된 행동을 다시 발사할 수 있습니다. 장기 실행에 치명적입니다.

하드 리젝(무조건 거부):
- LLM 호출이 액티비티로 감싸지지 않은 Agent SDK 사용.
- 배포를 견디지 못하는 체크포인트 백엔드.
- 액티비티 감싸기 없이 벽시계나 난수를 박아 넣은 워크플로.
- 신호가 아니라 폴링 루프로 모델링된 사람 입력.
- 재개 시 HITL 정책 없는 장기 실행(한 시간 초과).
- 내구성 위에 예산 킬 스위치(레슨 13)가 얹히지 않은 실행.

거부 규칙:
- 사용자가 부작용 액티비티에 명시적인 멱등성 없는 내구 워크플로를 제안하면 거부하고, 멱등성 키를 먼저 요구하세요. 재시도가 그렇지 않으면 이중 실행됩니다.
- 사용자가 리플레이 테스트(워크플로 실행, 도중 크래시, 리플레이, 이중 부작용 없음 단언)를 보여주지 못하면 거부하고, 프로덕션 전에 그 테스트를 요구하세요.
- 사용자가 HITL 체크포인트 없는 24시간 무인 실행을 제안하면 거부하세요. 35분 감쇠(레슨 12 노트) 때문에, 내구성이 올바르더라도 이것은 신뢰성 문제입니다.

출력 형식:

다음을 포함한 설계 리뷰 메모를 반환합니다:
- **액티비티 표** (액티비티, 재시도 정책, 타임아웃, 멱등성 키)
- **결정론성 감사** (비결정론적 읽기와 각각의 처리 방식)
- **체크포인트 백엔드** (이름, 배포 생존 여부 y/n, 리플레이 테스트 상태)
- **HITL 상태 형태** (일급 상태 / 폴링 / 없음)
- **재개 시 HITL 정책** (명시적으로, 근거 포함)
- **준비도** (프로덕션 / 스테이징 / 연구 전용)
