# 자동화된 정렬 연구 (Anthropic AAR)

> Anthropic은 Claude Opus 4.6 자율 정렬 연구자(Autonomous Alignment Researcher) 팀들을 독립된 샌드박스에서 병렬로 가동하되, 로그가 어떤 샌드박스 밖에도 존재하는 공유 포럼으로 조율했습니다(그래서 에이전트는 자기 기록을 삭제할 수 없습니다). 약한 지도에서 강한 모델로(weak-to-strong) 가는 학습 문제에서 AAR은 인간 연구자를 앞섰습니다. Anthropic의 자체 요약은 정해진 워크플로가 종종 AAR의 유연성을 구속해 성능을 떨어뜨린다고 짚습니다. 정렬 연구의 자동화는, RSP가 감지하려고 설계된 바로 그 미정렬 리스크까지의 시간표를 압축하는 압축 단계입니다.

**유형:** 학습
**언어:** Python (표준 라이브러리, 병렬 연구 포럼 시뮬레이터)
**선수 지식:** 페이즈 15 · 05 (AI Scientist v2), 페이즈 15 · 04 (DGM)
**시간:** 약 60분

## 문제

정렬(alignment) 연구는 인간 연구자 시간이 비쌉니다. 확장 가능한 감독(scalable oversight), 보상 명세, weak-to-strong 학습 같은 문제는 반복당 몇 주씩 걸리는 실험을 요구합니다. 프론티어 역량이 앞서갈수록 정렬 작업량은 자격을 갖춘 연구자 공급보다 빠르게 늘어납니다.

자동화된 정렬 연구(AAR)는 이렇게 묻습니다. 정렬을 앞지르고 있는 바로 그 프론티어 모델들이, 그 격차를 좁히는 데 기여할 수 있을까? Anthropic의 2026년 AAR 기반 weak-to-strong 학습 연구 보고서(alignment.anthropic.com/2026/automated-w2s-researcher/)는 이 계열의 배포된 시스템이 낸 최초의 공개 결과 중 하나입니다.

결과는 분명히 긍정적입니다. AAR이 인간 베이스라인보다 잘 풀었습니다. 동시에 그 결과는 이 페이즈가 쌓아 온 모든 우려를 한 시스템 안에 집중시킵니다. 정렬 연구를 자동화할 수 있다면, 안전장치를 무력화하는 부분도 자동화할 수 있습니다. RSP의 AI R&D 역량 기준선은 바로 이 루프를 염두에 두고 쓰였습니다.

## 개념

### 아키텍처(공개된 설명 기준)

- **병렬 에이전트.** 여러 Claude Opus 4.6 인스턴스가 AAR로 동작하며, 각각 독립된 샌드박스에서 실행됩니다. 샌드박스는 파일시스템, 네트워크, 프로세스 표면을 제한합니다.
- **공유 포럼.** 발견 사항은 저장 백엔드가 모든 샌드박스 바깥에 있는 공유 포럼에 게시됩니다. 에이전트는 포럼을 읽을 수 있지만, 자기 샌드박스 안에서 포럼 기록을 삭제하거나 편집할 수 없습니다.
- **작업 할당.** 사람이 설계한 작업 큐가 연구 문제를 AAR에 배정합니다. AAR이 분해를 제안하고, 실험을 실행하고, 발견을 정리해 씁니다.
- **weak-to-strong 학습 초점.** 공개된 연구는 weak-to-strong 학습 — 더 약한 감독자 모델로 더 강한 학생 모델을 학습시키는 문제 — 을 다뤘습니다. AAR은 이 작업에서 인간 연구자를 앞섰습니다.

### 샌드박스 밖 로그가 중요한 이유

로그 무결성 속성은 통제된 실험과 잠재적으로 오염된 실험을 가르는 선입니다. AAR이 자기 로그를 편집할 수 있다면, 실패했거나 수상한 실험을 덮을 수 있습니다. Anthropic은 이를 직접 짚습니다. 그 속성은 연구 산출물을 신뢰하기 위한 필요 조건이며, 검증하는 일이 간단하지 않다고요.

인프라 용어로 비유하면 외부 저장소로 쓰기가 통과되는(예: S3 오브젝트 락, 불변 Datadog 로그) 추가 전용(append-only) 로그입니다. 에이전트에게는 과거 기록을 수정할 자격 증명이 없습니다. 이것은 2026년 기업 보안 팀이 랜섬웨어에 강한 감사 추적을 만들 때 쓰는 것과 같은 패턴입니다.

### 정해진 워크플로의 트레이드오프

Anthropic 보고서는 정해진 워크플로가 종종 AAR의 유연성을 구속하고 성능을 떨어뜨린다고 기록합니다. 다시 말해: 인간 설계자가 연구 계획을 단계별로 적어 주면, 상위 목표와 분해의 자유를 줄 때보다 AAR이 더 못합니다. 이는 에이전트적 연구 전반의 결과(LangGraph, Microsoft의 Agent Framework)와 일치합니다. 과하게 명세된 스캐폴드는 유능한 에이전트를 해칩니다.

안전 함의는 미묘합니다. AAR 성능을 좋게 만드는 바로 그 유연성이, 승인되지 않은 분해, 새로운 도구 사용, 목표 표류(goal-drift)도 허용하는 유연성입니다. 트레이드오프는 설계 공간의 결정입니다. 어느 정도의 유연성이 인간을 이길 만큼의 역량을 사 오는 동시에, 에이전트가 분포를 벗어나 목표를 일반화할 여지를 주지 않을까?

### 압축 리스크

RSP v3.0(레슨 19)은 AI R&D 역량 기준선을 도입합니다. 인간 + AI 도구 대비 경쟁력 있는 비용으로 AI R&D 파이프라인 전체를 완전 자동화하는 능력입니다. DeepMind의 FSF v3에도 유사한 ML R&D 자율성 수준이 있습니다. 두 프레임워크 모두 이 기준선을 상향된 통제의 방아쇠로 다룹니다.

AAR은 그 기준선보다 한 발짝 부족합니다. 파이프라인의 일부(잘 정의된 특정 작업에 대한 정렬 연구)는 자동화하지만, 종단 간(end-to-end) 역량 개발 루프는 자동화하지 않습니다. 시간표의 질문은 그 간격이 얼마나 빨리 닫히느냐입니다.

압축된 시간표는 누적 실패 우려입니다. 정렬 연구와 역량 연구가 비슷한 속도로 누적된다면, 미정렬 리스크 표면은 최소한 역량만큼 빨리 자랍니다. 역량이 더 빨리 누적된다면(역사적 추세) 격차는 벌어집니다. 이것이 AAR을 "조건부 선행"으로 보는 논거입니다. 연구 과정이 신뢰할 수 있을 때만, 그리고 그때만, 정렬 결과가 하나 늘 때마다 격차가 줄어듭니다.

### AAR이 대체하지 못하는 것

사람 연구자가 작업 큐를 정하고, 결과를 검토하고, 헌법적 권위를 쥡니다. AAR은 파이프라인의 중간을 가속할 뿐, 양 끝은 아닙니다. Anthropic의 공개 산출물에는 AAR의 기여와 함께, 무엇을 게시하고 무엇을 철회하고 무엇을 다듬을지에 대한 사람 연구자의 판단이 함께 있습니다.

이것은 레슨 15의 "제안 후 승인(propose-then-commit)" 패턴을 연구 자체에 적용한 것입니다. AAR이 제안하고, 사람이 승인합니다.

## 사용하기

`code/main.py`는 다중 AAR 연구 포럼을 시뮬레이션합니다. 세 개의 독립적인 "연구 에이전트"가 병렬로 실행되며, 선택적으로 변조 시도를 포함해 추가 전용(append-only) 포럼에 발견을 게시합니다.

관찰할 것:

- 샌드박스 밖 로깅이 로그 변조 시도를 어떻게 잡아내는지.
- 자유 분해가 있는 작업 할당이 어려운 문제에서 고정 워크플로보다 어떻게 앞서는지.
- 로그가 변조 증거를 남기지 않는다면, 침해된 AAR 하나가 포럼의 신호를 어떻게 오염시킬 수 있는지.

## 연습 문제

1. `code/main.py`를 실행하세요. "고정 워크플로" 설정과 "자유 분해" 설정을 비교해 보세요. 자유 분해가 항상 이기나요, 아니면 고정 워크플로가 경쟁력 있는 문제 계급이 있나요?

2. 시뮬레이터를 고쳐서 한 에이전트가 로그 변조를 시도하게 만들어 보세요. 추가 전용 로그가 그것을 감지하는지 확인하고, 감지 시그니처가 로그에서 정확히 어떤 모습인지 한 문단으로 적어 보세요.

3. Anthropic의 weak-to-strong AAR 보고서를 읽으세요. AAR이 인간 연구자를 이긴 구체적인 하위 작업을 찾아 보세요. 무엇이 그 작업을 자동화에 적합하게 만들었나요?

4. AAR의 유연성(더 나은 결과)과 정해진 워크플로의 제약(더 쉬운 감사) 사이의 균형을 잡는 작업 큐 할당 정책을 설계해 보세요. 둘을 A/B 테스트하는 방법을 서술하세요.

5. RSP v3.0의 AI R&D-4 기준선을 읽으세요. AAR이 현재 넘지 못하지만 넘을 것 같은 것을 한 문단으로 서술해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|---|---|---|
| AAR | "자율 정렬 연구자" | 정렬 문제를 자율적으로 수행하는 Claude Opus 4.6 인스턴스 |
| Weak-to-strong 학습 | "더 약한 감독자로 더 강한 모델 학습" | AAR이 인간을 앞선 고전적 확장 가능 감독 벤치마크 |
| 공유 포럼 | "에이전트가 발견을 게시하는 곳" | 추가 전용, 샌드박스 외부 저장소 |
| 샌드박스 밖 로그 | "에이전트가 자기 기록을 편집 못 함" | 외부 저장소로의 변조 증거가 남는 쓰기 |
| 정해진 워크플로 | "인간 설계자의 단계별 계획" | AAR을 구속함. 자유 분해보다 성능을 떨어뜨리는 경우가 많음 |
| 자유 분해 | "에이전트가 작업 분해법을 결정" | 더 유능하지만 감사하기 어려움 |
| AI R&D 기준선 | "RSP/FSF 역량 수준" | 경쟁력 있는 비용으로 R&D 파이프라인 전체를 자동화하는 능력 |
| 압축된 시간표 | "정렬 vs 역량 경주" | 역량이 정렬보다 빨리 누적되면 미정렬 리스크가 커짐 |
