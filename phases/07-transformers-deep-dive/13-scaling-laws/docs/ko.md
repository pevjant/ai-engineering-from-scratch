# 스케일링 법칙

> 2020년 Kaplan 논문은 말했습니다: 모델이 크면 손실이 낮아진다고. 2022년 Hoffmann 논문은 반박했습니다: 그건 학습이 부족했던 것뿐이라고. 연산은 파라미터와 토큰이라는 두 바구니에 나뉘는데, 그 나누는 비율은 자명하지 않습니다.

**유형:** Learn
**언어:** Python
**선수 지식:** 페이즈 7 · 05(풀 트랜스포머), 페이즈 7 · 07(GPT)
**시간:** 약 45분

## 문제 상황

학습 연산 C FLOPs를 갖고 최고의 모델을 만들고 싶다면, 두 개의 다이얼 앞에 섭니다:

1. **파라미터(N)는 몇 개로?** 모델이 클수록 용량이 커집니다.
2. **학습 토큰(D)은 몇 개로?** 데이터가 많을수록 용량을 잘 씁니다.

FLOPs는 대략 `6 × N × D`로 늘어납니다. N을 올리고 D를 내릴 수도, D를 올리고 N을 내릴 수도 있죠. 어느 쪽이 나을까요?

2022년 이전의 답은 "N을 강하게 밀어라"였습니다. GPT-3(2020)는 파라미터 175B를 토큰 약 300B로 학습했습니다. 파라미터당 토큰 비율이 약 1.7이죠. Kaplan 스케일링 법칙이 이를 뒷받침했습니다.

Hoffmann 외(2022)는 Chinchilla라는 작은 모델 군을 학습시키다 다른 사실을 발견했습니다: 최적 비율은 **파라미터당 토큰 20개**에 가깝습니다. GPT-3는 10배나 학습이 부족했던 겁니다. Chinchilla(파라미터 70B, 토큰 1.4T)는 추론 비용이 2.5배 적으면서도 모든 벤치마크에서 GPT-3(175B, 300B 토큰)를 이겼습니다.

2026년은 Chinchilla의 세계입니다 — 단, 중요한 반전이 하나 있습니다. Llama 3 8B는 15조 토큰으로 학습됐습니다. 파라미터당 토큰 1,875개죠. Chinchilla 최적치의 94배입니다. 대규모로 쓰일 모델에게는 학습 비용보다 추론 비용이 더 중요하므로, (Chinchilla를 넘어서까지) 과잉 학습해 배포 부담을 줄이는 것이 2026년의 기본값입니다.

## 개념

![Chinchilla 곡선: 다양한 N/D 비율에서 손실 vs 연산](../assets/scaling-laws.svg)

### Hoffmann 법칙

Chinchilla 논문에 따르면 손실은 다음을 따릅니다:

```
L(N, D) = A / N^α + B / D^β + E
```

- `N` = 파라미터 수(임베딩 제외).
- `D` = 학습 토큰 수.
- `α ≈ 0.34`, `β ≈ 0.28` (거의 대칭).
- `E ≈ 1.69`, 줄일 수 없는 손실의 천장.
- `A ≈ 406`, `B ≈ 411`.

스케일을 키우면 두 항이 서로 맞바꿔집니다. 연산을 고정한 채(C = 6ND) `N`으로 미분해 풀면:

```
N_opt ≈ 0.6 × (C/6)^0.5
D_opt ≈ 0.6 × (C/6)^0.5
D_opt / N_opt ≈ 20
```

연산 최적(compute-optimal): 파라미터당 토큰 20개입니다.

### 그래도 과잉 학습하는 이유

Chinchilla 최적은 학습 FLOP당 학습 손실을 최소화합니다. 하지만 학습 비용은 한 번 내고 끝이고, 추론 비용은 영원히 냅니다.

한 달에 1조 토큰을 서빙하는 챗봇이라면 총비용의 대부분은 추론입니다. Llama의 접근법: 더 작게, 더 오래 학습한다. 15T 토큰으로 학습한 8B는 추론에 깊이 최적화된 모델입니다:

- 소비자용 GPU에 들어갑니다.
- 지연 시간이 Chinchilla 최적 70B의 일부에 불과합니다.
- 품질도 대부분의 작업에 충분히 가깝습니다.

DeepMind의 2024년 논문("Over-training is the new optimal")이 이를 공식화했습니다. 추론 위주의 작업 부하라면 올바른 비율은 서빙량에 따라 파라미터당 토큰 100~500개에 가깝습니다.

### 창발(emergence) vs 매끄러움

주장: 어떤 능력들(산술, 다단계 추론, 사고 과정 따라 하기)은 특정 규모에서 갑자기 '창발'한다.

Schaeffer 외(2023)는 이것이 측정의 착시라고 주장했습니다: 창발 지표로 쓰이는 채점 방식(완전 일치, 임계값 기준 정확도)은 불연속적이라, 로짓이 아래에서 부드럽게 좋아지는 것을 가려 버린다는 겁니다. 연속 지표(교차 엔트로피)로 보면 곡선은 매끄럽습니다.

2026년의 합의는 이렇습니다: 연속 손실을 통한 예측은 신뢰할 수 있습니다. 벤치마크 급등은 종종 채점자의 착시입니다. 예산은 연속 지표 기준으로 세우세요.

### 2026년의 풍경

스케일링 법칙은 여전히 통하지만, 달라진 것들이 있습니다:

| 요인 | 달라진 방식 |
|--------|-------------|
| 데이터 품질 | '좋은' 토큰을 골라 쓰면(Phi 스타일) 실효 연산 2배 이상만큼 곡선이 이동 |
| MoE | 전체 파라미터가 활성 FLOPs와 분리; 활성 FLOP당 스케일링 법칙 |
| 후속 학습(post-training) | 일부 능력(명령 따르기, 코딩)은 사전학습보다 SFT+RLHF에서 더 많이 변함 |
| 멀티모달 | 이미지 + 텍스트 토큰이 함께 스케일; 모달리티별 곡선 분리 |
| 합성 데이터 | 모델이 학습 데이터를 생성; 실효 연산이 복리로 쌓일 수 있음 |

Muon 옵티마이저(Kimi Moonlight, 2024)는 같은 데이터 기준 AdamW 대비 약 2배의 실효 연산 이득을 보였습니다. 2026년 일부 학습 런은 Muon을 기본으로 씁니다. 스케일링 법칙의 절대 상수가 바뀌는 것이지 모양이 바뀌는 것은 아닙니다.

## 만들어 보기

`code/main.py`를 보세요. Chinchilla 손실 식을 구현하고, 여러 연산 예산 각각에 대해 연산 최적 `(N, D)`를 풉니다.

### 단계 1: Chinchilla 손실

```python
def chinchilla_loss(N, D, A=406.4, B=410.7, alpha=0.34, beta=0.28, E=1.69):
    return A / N ** alpha + B / D ** beta + E
```

`C = 6ND`를 고정한 채 `(N, D)` 위에서 `L`의 등고선을 그립니다. 최솟값을 찾으세요.

### 단계 2: 연산 최적 경계선

`1e17`에서 `1e25` FLOPs까지의 연산 예산에 대해 `6ND = C` 조건 아래 손실을 최소화하는 `(N, D)`를 구합니다. 비율 `D/N ≈ 20`을 확인하세요.

### 단계 3: 과잉 학습 비용

10배 작은 모델(최적 N의 1/10, 최적 D의 10배)을 학습할 때 치르는 추가 손실을 계산합니다. 그 대가로 얻는 추론 FLOP 절감(N에 비례)도 함께 보고합니다.

### 단계 4: 실제 모델과 비교

GPT-3, Chinchilla, Llama 3 8B, DeepSeek-V3(활성 파라미터)의 알려진 `(N, D)` 쌍을 넣고, 예측 손실과 보고된 손실을 비교합니다.

## 사용해 보기

여러분이 직접 최전선 모델을 학습시킬 일은 드뭅니다. 하지만 스케일링 법칙은 이런 것을 알려 줍니다:

1. **파인튜닝에 데이터가 충분한지.** 작업별 데이터가 베이스 모델 파라미터당 20토큰 미만이면 어느 손실 바닥에서 포화될 것입니다.
2. **더 큰 베이스 모델을 골라야 하는지.** 예산을 추론에 다 쓰고 있다면, 더 작게 더 오래 학습된 모델이 낫습니다.
3. **수확이 줄어드는 지점.** Chinchilla 최적의 1000배를 넘으면 log-loss 변화는 잡음 수준입니다.

**2026년의 연구 방향:**

- **데이터 제약 구간.** 웹에는 고품질 토큰이 유한하게 있습니다(필터링 후 영어 기준 약 5~10조). 최전선 사전학습이 이 천장에 다가가고 있습니다. 합성 데이터, 다국어, 멀티모달, RLHF로 확장한 파인튜닝이 다음 지렛대입니다.
- **연산 배율 트릭.** Muon 옵티마이저, MoE, 더 나은 데이터 큐레이션 — 각각 절대 상수를 움직이지, 점근선을 움직이지는 않습니다.
- **RL의 스케일링 법칙.** 열린 질문입니다. 초기 근거에 따르면 RL 샘플에서도 멱법칙이 보이지만 사전학습과는 지수가 크게 다릅니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|-----------------------|
| 파라미터(N) | "모델 크기" | 임베딩을 제외한 가중치 수; 용량을 결정합니다. |
| 토큰(D) | "학습 데이터" | 학습에서 본 토큰 수; 파라미터를 얼마나 잘 쓰는지를 결정합니다. |
| 연산(C) | "쓴 FLOPs" | 표준 트랜스포머 기준 대략 `6 × N × D`. |
| Chinchilla 최적 | "D/N ≈ 20" | 사전학습 FLOP당 손실을 최소화하는 비율. |
| 과잉 학습(Over-training) | "Chinchilla 너머" | 추론 FLOPs를 아끼려고 학습 FLOPs를 더 씀; D/N >> 20. |
| 줄일 수 없는 손실(Irreducible loss) | "바닥" | 스케일링 법칙의 `E` 항; 데이터 자체의 엔트로피. |
| 창발 능력(Emergent capability) | "규모를 넘으면 갑자기 튐" | 종종 채점자의 착시; 연속 손실은 매끄럽게 변합니다. |
| 실효 연산(Effective compute) | "학습 효율 배율" | 더 나은 데이터 / 옵티마이저 / 아키텍처가 FLOP 한 닢의 가치를 곱해 줍니다. |
