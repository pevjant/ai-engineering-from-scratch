# MDP, 상태, 행동, 보상

> 마르코프 결정 과정(MDP, Markov Decision Process)은 다섯 가지입니다: 상태, 행동, 전이, 보상, 할인율. 강화 학습의 모든 것 — Q-learning, PPO, DPO, GRPO — 이 이 형태 위에서 최적화합니다. 한 번만 제대로 배워 두면 이후의 강화 학습은 공짜로 읽힙니다.

**유형:** 학습
**언어:** Python
**선수 지식:** 페이즈 1 · 06(확률과 분포), 페이즈 2 · 01(ML 분류 체계)
**시간:** 약 45분

## 문제 상황

체스 봇을 만든다고 합시다. 재고 계획 시스템, 트레이딩 에이전트, 추론 모델을 학습시키는 PPO 루프도 될 수 있죠. 네 개의 전혀 다른 도메인인데 놀라운 사실이 하나 있습니다: 넷 모두 같은 수학적 대상으로 귀결됩니다.

지도 학습은 `(x, y)` 쌍을 주고 함수를 맞추라고 요구합니다. 강화 학습은 레이블을 주지 않습니다 — 오직 상태의 흐름, 당신이 취한 행동, 그리고 스칼라 보상만 줍니다. 그 수가 게임을 이겼나요? 재고 보충 결정이 비용을 아꼈나요? 그 매매가 수익을 냈나요? LLM이 방금 만든 토큰이 심판(저지)으로부터 더 높은 보상을 받았나요?

이 흐름을 정식화하기 전에는 아무것도 배울 수 없습니다. "내가 본 것", "내가 한 것", "그다음에 일어난 것", "그것이 얼마나 좋았는가" — 각각이 추론 가능한 대상이 되어야 합니다. 바로 그 정식화가 마르코프 결정 과정(MDP)입니다. 이 페이즈의 모든 RL 알고리즘, 맨 끝의 RLHF와 GRPO 루프까지, 이 형태 위에서 최적화합니다.

## 핵심 개념

![마르코프 결정 과정: 상태, 행동, 전이, 보상, 할인](../assets/mdp.svg)

**다섯 가지 대상.**

- **상태** `S`. 에이전트가 결정을 내리는 데 필요한 모든 것. GridWorld에서는 셀. 체스에서는 보판. LLM에서는 컨텍스트 윈도우와 모든 메모리.
- **행동** `A`. 선택지들. 위/아래/왼쪽/오른쪽 이동. 수 두기. 토큰 하나 내보내기.
- **전이** `P(s' | s, a)`. 상태 `s`와 행동 `a`가 주어졌을 때 다음 상태의 분포. 체스에서는 결정론적, 재고에서는 확률적, LLM 디코딩에서는 거의 결정론적.
- **보상** `R(s, a, s')`. 스칼라 신호. 승리 = +1, 패배 = -1. 매출에서 비용을 뺀 값. GRPO에서의 로그 가능도 비율 항.
- **할인율** `γ ∈ [0, 1)`. 현재 보상 대비 미래 보상을 얼마나 치는가. `γ = 0.99`는 약 100단계의 시야를, `γ = 0.9`는 약 10단계의 시야를 줍니다.

**마르코프 성질** `P(s_{t+1} | s_t, a_t) = P(s_{t+1} | s_0, a_0, …, s_t, a_t)`. 미래는 오직 현재 상태에만 의존합니다. 그렇지 않다면 상태 표현이 불완전한 것입니다 — 방법의 실패가 아니라 상태의 실패입니다.

**정책과 반환값.** 정책 `π(a | s)`는 상태를 행동 분포로 사상합니다. 반환값 `G_t = r_t + γ r_{t+1} + γ² r_{t+2} + …`는 미래 보상의 할인 합입니다. 가치 `V^π(s) = E[G_t | s_t = s]`는 정책 `π` 하에서 `s`에서 출발했을 때의 기대 반환값입니다. Q-값 `Q^π(s, a) = E[G_t | s_t = s, a_t = a]`는 특정 행동으로 시작했을 때의 기대 반환값입니다. 모든 RL 알고리즘은 이 둘 중 하나를 추정한 다음, 그에 맞춰 `π`를 개선합니다.

**벨만 방정식.** 이 페이즈의 모든 것이 사용하는 고정점 방정식입니다:

`V^π(s) = Σ_a π(a|s) Σ_{s', r} P(s', r | s, a) [r + γ V^π(s')]`
`Q^π(s, a) = Σ_{s', r} P(s', r | s, a) [r + γ Σ_{a'} π(a'|s') Q^π(s', a')]`

기대 반환값을 "이번 스텝의 보상"과 "도착할 상태의 할인된 가치"로 쪼갭니다. 재귀적입니다. 페이즈 9의 모든 알고리즘은 이 방정식을 수렴할 때까지 반복하거나(동적 계획법), 이로부터 샘플링하거나(몬테카를로), 한 스텝만큼 부트스트랩합니다(시간차 학습).

## 직접 만들기

### 단계 1: 아주 작은 결정론적 MDP

4×4 GridWorld입니다. 에이전트는 왼쪽 위에서 시작하고, 종료 지점은 오른쪽 아래, 스텝당 보상은 -1, 행동은 `{up, down, left, right}`. `code/main.py`를 보세요.

```python
GRID = 4
TERMINAL = (3, 3)
ACTIONS = {"up": (-1, 0), "down": (1, 0), "left": (0, -1), "right": (0, 1)}

def step(state, action):
    if state == TERMINAL:
        return state, 0.0, True
    dr, dc = ACTIONS[action]
    r, c = state
    nr = min(max(r + dr, 0), GRID - 1)
    nc = min(max(c + dc, 0), GRID - 1)
    return (nr, nc), -1.0, (nr, nc) == TERMINAL
```

다섯 줄입니다. 이것이 환경의 전부입니다. 결정론적 전이, 고정된 스텝 벌점, 흡수(absorbing) 종료 상태.

### 단계 2: 정책 굴려 보기(rollout)

정책은 상태를 행동 분포로 바꾸는 함수입니다. 가장 단순한 것: 균등 무작위.

```python
def uniform_policy(state):
    return {a: 0.25 for a in ACTIONS}

def rollout(policy, max_steps=200):
    s, total, steps = (0, 0), 0.0, 0
    for _ in range(max_steps):
        a = sample(policy(s))
        s, r, done = step(s, a)
        total += r
        steps += 1
        if done:
            break
    return total, steps
```

무작위 정책을 1000번 실행해 보세요. 이 4×4 보드에서 평균 반환값은 대략 -60~-80입니다. 최적 반환값은 -6(오른쪽 아래로 곧장 가는 경로)입니다. 페이즈 9의 모든 내용은 이 격차를 줄이는 일입니다.

### 단계 3: 벨만 방정식으로 `V^π` 정확히 계산하기

작은 MDP에서는 벨만 방정식이 선형 시스템이 됩니다. 상태를 나열하고, 기댓값을 적용하고, 값이 더 이상 변하지 않을 때까지 반복합니다.

```python
def policy_evaluation(policy, gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in all_states()}
    while True:
        delta = 0.0
        for s in all_states():
            if s == TERMINAL:
                continue
            v = 0.0
            for a, pi_a in policy(s).items():
                s_next, r, _ = step(s, a)
                v += pi_a * (r + gamma * V[s_next])
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            return V
```

이것이 반복적 정책 평가(iterative policy evaluation)입니다. Sutton & Barto의 첫 번째 알고리즘이며, 이후의 모든 RL 방법의 이론적 토대입니다.

### 단계 4: `γ`는 물리적 의미가 있는 하이퍼파라미터

실효 시야(horizon)는 대략 `1 / (1 - γ)`입니다. `γ = 0.9` → 10스텝. `γ = 0.99` → 100스텝. `γ = 0.999` → 1000스텝.

너무 낮으면 에이전트가 눈앞만 봅니다. 너무 높으면 신용 할당(credit assignment)이 시끄러워집니다. 멀리 있는 미래 보상의 책임이 초반의 많은 스텝들에게 나뉘어 돌아가기 때문입니다. LLM RLHF는 보통 `γ = 1`을 씁니다. 에피소드가 짧고 유한하기 때문입니다. 제어 태스크는 `0.95~0.99`, 긴 시야의 전략 게임은 `0.999`를 씁니다.

## 흔한 함정

- **비(非)마르코프 상태.** 마지막 세 개의 관측이 필요해야 결정을 내릴 수 있다면, "상태"는 현재 관측만이 아닙니다. 해결책: 프레임을 쌓으세요(Atari의 DQN은 4개를 쌓음) 또는 순환 상태를 쓰세요(관측 위의 LSTM/GRU).
- **희소 보상.** 이길 때만 주는 보상은 큰 상태 공간에서 학습을 거의 불가능하게 만듭니다. 보상을 설계(shaping, 중간 신호 제공)하거나 모방 학습으로 부트스트랩하세요(페이즈 9 · 09).
- **보상 해킹.** 대리 보상을 최적화하면 종종 병리적 행동이 나옵니다. OpenAI의 보트 레이싱 에이전트는 결승선을 가는 대신 파워업을 모으며 영원히 빙글빙글 돌았죠. 보상은 항상 대리 지표가 아니라 목표 결과 자체로 정의하세요.
- **할인율 잘못 설정.** 무한 시야 태스크에서 `γ = 1`이면 모든 가치가 무한대가 됩니다. 유한 시야 또는 `γ < 1`로 반드시 한계를 두세요.
- **보상 스케일.** {+100, -100}과 {+1, -1}은 최적 정책은 같지만 기울기 크기는 엄청나게 다릅니다. PPO/DQN에 넣기 전에 대략 `[-1, 1]` 범위로 정규화하세요.

## 실전 활용

2026년의 스택은 코드를 만지기 전에 모든 RL 파이프라인을 MDP로 환원합니다:

| 상황 | 상태 | 행동 | 보상 | γ |
|-----------|-------|--------|--------|---|
| 제어(이동, 조작) | 관절 각도 + 속도 | 연속 토크 | 태스크별 shaped 보상 | 0.99 |
| 게임(체스, 바둑, 포커) | 보판 + 히스토리 | 합법 수 | 승=+1 / 패=-1 | 1.0 (유한) |
| 재고 / 가격 | 재고 + 수요 | 발주량 | 매출 - 비용 | 0.95 |
| LLM RLHF | 컨텍스트 토큰 | 다음 토큰 | 마지막 보상 모델 점수 | 1.0 (에피소드 ~200토큰) |
| 추론 GRPO | 프롬프트 + 부분 응답 | 다음 토큰 | 마지막 검증기 0/1 | 1.0 |

학습 루프를 짜기 전에 다섯 개 튜플을 먼저 적으세요. "RL이 안 돼요" 버그 보고의 대부분은 종이 위에서부터 잘못된 MDP 정식화로 거슬러 올라갑니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|-----------------------|
| MDP | "강화 학습 세팅" | 마르코프 성질을 만족하는 튜플 `(S, A, P, R, γ)`. |
| 상태 | "에이전트가 보는 것" | 선택된 정책 클래스 하에서 미래 동역학에 대한 충분 통계량. |
| 정책 | "에이전트의 행동 방식" | 조건부 분포 `π(a \| s)` 또는 결정론적 사상 `s → a`. |
| 반환값 | "총 보상" | 현재 스텝부터의 할인 합 `Σ γ^t r_t`. |
| 가치 | "그 상태가 얼마나 좋은가" | `π` 하에서 `s`부터 출발하는 기대 반환값. |
| Q-값 | "그 행동이 얼마나 좋은가" | `π` 하에서 `s`부터 첫 행동 `a`로 출발하는 기대 반환값. |
| 벨만 방정식 | "동적 계획법 재귀식" | 가치/Q를 한 스텝 보상 + 다음 상태의 할인된 가치로 분해하는 고정점 식. |
| 할인율 `γ` | "미래 vs 현재" | 먼 미래 보상에 붙는 기하급수적 가중치; 실효 시야 `~1/(1-γ)`. |
