# 액터-크리틱 — A2C와 A3C

> REINFORCE는 시끄럽습니다. `V̂(s)`를 학습하는 크리틱을 붙이고 반환값에서 그것을 빼면, 기댓값은 같지만 분산은 훨씬 낮은 어드밴티지가 나옵니다. 그것이 액터-크리틱입니다. A2C는 이것을 동기적으로 돌리고, A3C는 스레드 여러 개로 돌립니다. 둘 다 현대 딥 RL 방법 전체의 멘탈 모델입니다.

**유형:** 빌드
**언어:** Python
**선수 지식:** 페이즈 9 · 04(TD 학습), 페이즈 9 · 06(REINFORCE)
**시간:** 약 75분

## 문제 상황

바닐라 REINFORCE는 동작하지만 분산이 끔찍합니다. 몬테카를로 반환값 `G_t`는 에피소드 사이에 10배 넘게 출렁일 수 있습니다. 그 노이즈에 `∇ log π`를 곱해 평균 낸 기울기 추정량은 정책을 원하는 거리만큼 움직이는 데 수천 에피소드가 필요한 반면, DQN 갱신은 훨씬 적은 횟수로 같은 거리를 갑니다.

분산의 원인은 원시 반환값을 그대로 쓰는 것입니다. 베이스라인 `b(s_t)` — 학습된 가치를 포함한 상태의 임의의 함수 — 를 빼면 기댓값은 그대로인데 분산은 떨어집니다. 다룰 수 있는 범위에서 최고의 베이스라인은 `V̂(s_t)`입니다. 이제 `∇ log π`에 곱해지는 양은 *어드밴티지*입니다:

`A(s, a) = G - V̂(s)`

어떤 행동이 평균 이상의 반환값을 냈다면 좋은 것이고, 그 미만이라면 나쁜 것입니다. 학습된 크리틱을 얹은 REINFORCE가 바로 *액터-크리틱*입니다. 크리틱은 액터에게 저분산 선생님을 제공합니다. 2015년 이후의 모든 딥 정책 방법(A2C, A3C, PPO, SAC, IMPALA)이 이것입니다.

## 핵심 개념

![액터-크리틱: 정책 네트 + 가치 네트, TD 잔차를 어드밴티지로](../assets/actor-critic.svg)

**네트워크 두 개, 손실 하나를 나눠 씀:**

- **액터** `π_θ(a | s)`: 정책입니다. 샘플링해서 행동합니다. 정책 경사로 학습합니다.
- **크리틱** `V_φ(s)`: 상태에서의 기대 반환값을 추정합니다. `(V_φ(s) - target)²`을 최소화하도록 학습합니다.

**어드밴티지.** 표준 형태가 두 가지입니다:

- *MC 어드밴티지:* `A_t = G_t - V_φ(s_t)`. 편향 없음, 분산 높음.
- *TD 어드밴티지:* `A_t = r_{t+1} + γ V_φ(s_{t+1}) - V_φ(s_t)`. 편향 있음(`V_φ`를 쓰므로), 분산 훨씬 낮음. *TD 잔차* `δ_t`라고도 부릅니다.

**n-스텝 어드밴티지.** 둘 사이를 보간합니다:

`A_t^{(n)} = r_{t+1} + γ r_{t+2} + … + γ^{n-1} r_{t+n} + γ^n V_φ(s_{t+n}) - V_φ(s_t)`

`n = 1`은 순수 TD. `n = ∞`는 MC. 대부분의 구현은 Atari에서 `n = 5`, MuJoCo의 PPO에서 `n = 2048`을 씁니다.

**일반화 어드밴티지 추정(GAE).** Schulman et al. (2016)이 모든 n-스텝 어드밴티지에 대해 지수 가중 평균을 제안했습니다:

`A_t^{GAE} = Σ_{l=0}^{∞} (γλ)^l δ_{t+l}`

`λ ∈ [0, 1]`입니다. `λ = 0`은 TD(저분산, 고편향). `λ = 1`은 MC(고분산, 무편향). `λ = 0.95`가 2026년 기본값 — 편향/분산 다이얼을 원하는 위치로 맞출 때까지 조정하세요.

**A2C: 동기식 어드밴티지 액터-크리틱.** `N`개 병렬 환경에서 `T`스텝을 수집합니다. 각 스텝의 어드밴티지를 계산합니다. 합쳐진 배치로 액터와 크리틱을 갱신합니다. 반복합니다. A3C의 더 단순하고 더 잘 확장되는 형제입니다.

**A3C: 비동기식 어드밴티지 액터-크리틱.** Mnih et al. (2016). 워커 스레드 `N`개를 띄우고 각각 환경 하나를 돌립니다. 각 워커는 자기 롤아웃 위에서 기울기를 로컬로 계산한 뒤, 비동기적으로 공유 파라미터 서버에 적용합니다. 리플레이 버퍼가 필요 없습니다 — 워커들이 서로 다른 궤적을 돌며 상관관계를 끊어 주기 때문입니다. A3C는 CPU만으로 대규모 학습이 가능함을 증명했습니다. 2026년에는 GPU가 큰 배치를 원하기 때문에 GPU 기반 A2C(배치화된 병렬 환경)가 지배합니다.

**합친 손실.**

`L(θ, φ) = -E[ A_t · log π_θ(a_t | s_t) ]  +  c_v · E[(V_φ(s_t) - G_t)²]  -  c_e · E[H(π_θ(·|s_t))]`

세 항입니다: 정책 경사 손실, 가치 회귀, 엔트로피 보너스. `c_v ~ 0.5`, `c_e ~ 0.01`이 정석적인 출발점입니다.

## 직접 만들기

### 단계 1: 크리틱

선형 크리틱 `V_φ(s) = w · features(s)`를 MSE로 갱신합니다:

```python
def critic_update(w, x, target, lr):
    v_hat = dot(w, x)
    err = target - v_hat
    for j in range(len(w)):
        w[j] += lr * err * x[j]
    return v_hat
```

표(tabular) 환경에서 크리틱은 몇백 에피소드 만에 수렴합니다. Atari에서는 선형 크리틱을 공유 CNN 트렁크 + 가치 헤드로 바꾸세요.

### 단계 2: n-스텝 어드밴티지

길이 `T`의 롤아웃과 부트스트랩된 마지막 `V(s_T)`가 주어지면:

```python
def compute_advantages(rewards, values, gamma=0.99, lam=0.95, last_value=0.0):
    advantages = [0.0] * len(rewards)
    gae = 0.0
    for t in reversed(range(len(rewards))):
        next_v = values[t + 1] if t + 1 < len(values) else last_value
        delta = rewards[t] + gamma * next_v - values[t]
        gae = delta + gamma * lam * gae
        advantages[t] = gae
    returns = [a + v for a, v in zip(advantages, values)]
    return advantages, returns
```

`returns`가 크리틱 타깃입니다. `advantages`가 `∇ log π`에 곱해질 것입니다.

### 단계 3: 합친 갱신

```python
for step_i, (x, a, _r, probs) in enumerate(traj):
    adv = advantages[step_i]
    target_v = returns[step_i]

    # 크리틱
    critic_update(w, x, target_v, lr_v)

    # 액터
    for i in range(N_ACTIONS):
        grad_logpi = (1.0 if i == a else 0.0) - probs[i]
        for j in range(N_FEAT):
            theta[i][j] += lr_a * adv * grad_logpi * x[j]
```

온폴리시, 갱신당 롤아웃 한 번, 액터와 크리틱의 학습률은 분리해서 씁니다.

### 단계 4: 병렬화(A3C vs A2C)

- **A3C:** 스레드 `N`개를 띄웁니다. 각각 자기 환경과 자기 포워드 패스를 돌립니다. 주기적으로 기울기 갱신을 공유 마스터에 밀어 넣습니다. 마스터에 락은 없습니다 — 경쟁 상태(race)는 괜찮습니다. 그저 노이즈가 조금 더해질 뿐입니다.
- **A2C:** 한 프로세스에서 환경 인스턴스 `N`개를 돌리고, 관측을 `[N, obs_dim]` 배치로 쌓아, 배치 포워드 패스와 배치 백워드 패스를 돌립니다. GPU 활용률이 높고, 결정론적이고, 추론하기 쉽습니다. 2026년의 기본값입니다.

우리 토이 코드는 이해를 위해 단일 스레드입니다. 배치화된 A2C로 바꾸는 건 numpy 세 줄이면 됩니다.

## 흔한 함정

- **액터 기울기 이전의 크리틱 편향.** 크리틱이 무작위 상태라면 베이스라인도 아무 정보가 없어서 순수 노이즈 위에서 학습하게 됩니다. 정책 경사를 켜기 전에 크리틱을 몇백 스텝 워밍업하거나, 액터 학습률을 느리게 두세요.
- **어드밴티지 정규화.** 배치별로 어드밴티지를 평균 0/표준편차 1로 정규화하세요. 거의 공짜로 학습을 대폭 안정시킵니다.
- **공유 트렁크.** 이미지 입력에는 액터와 크리틱이 특성 추출기를 공유하게 하세요. 헤드는 분리합니다. 공유 특성이 두 손실에서 공짜 배움을 얻습니다.
- **온폴리시 계약.** A2C는 데이터를 딱 한 번의 갱신에만 재사용합니다. 그 이상 쓰면 기울기가 편향됩니다(중요도 샘플링 보정이 PPO가 추가하는 것입니다).
- **엔트로피 붕괴.** `c_e > 0`이 없으면 정책이 몇백 갱신 만에 거의 결정론적으로 굳고 탐색을 멈춥니다.
- **보상 스케일.** 어드밴티지 크기는 보상 스케일에 의존합니다. 태스크 전반에서 기울기 크기를 일관되게 유지하려면 보상을 정규화하세요(예: 이동 표준편차로 나누기).

## 실전 활용

2026년에 A2C/A3C가 최종 선택이 되는 경우는 드물지만, 이후 모든 것이 개선해 나가는 아키텍처입니다:

| 방법 | A2C와의 관계 |
|--------|----------------|
| PPO | A2C + 다에포크 갱신을 위한 클리핑된 중요도 비율 |
| IMPALA | A3C + V-trace 오프폴리시 보정 |
| SAC (페이즈 9 · 07) | 소프트 가치 크리틱을 얹은 오프폴리시 A2C(다음 레슨) |
| GRPO (페이즈 9 · 12) | 크리틱 없는 A2C — 그룹 상대 어드밴티지 |
| DPO | A2C를 선호 순위 손실로 압축, 샘플링 없음 |
| AlphaStar / OpenAI Five | 리그 학습 + 모방 사전학습을 얹은 A2C |

2026년 논문에서 "어드밴티지"를 보면 액터-크리틱을 떠올리세요.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|-----------------------|
| 액터 | "정책 네트" | `π_θ(a\|s)`, 정책 경사로 갱신. |
| 크리틱 | "가치 네트" | `V_φ(s)`, 반환값/TD 타깃에 대한 MSE 회귀로 갱신. |
| 어드밴티지 | "평균보다 얼마나 나은가" | `A(s, a) = Q(s, a) - V(s)` 또는 그 추정량. `∇ log π`의 곱수. |
| TD 잔차 | "δ" | `δ_t = r + γ V(s') - V(s)`; 한 스텝 어드밴티지 추정량. |
| GAE | "보간 다이얼" | n-스텝 어드밴티지의 지수 가중 합, `λ`로 파라미터화. |
| A2C | "동기식 액터-크리틱" | 환경들에 걸쳐 배치화; 롤아웃당 기울기 스텝 한 번. |
| A3C | "비동기식 액터-크리틱" | 워커 스레드가 기울기를 공유 파라미터 서버에 밀어 넣음. 원조 논문; 2026년에는 덜 흔함. |
| 부트스트랩 | "시야 끝에서 V를 쓰기" | 롤아웃을 잘라 합을 닫으려고 `γ^n V(s_{t+n})`을 더함. |
