# 신경망 디버그 체크리스트

학습이 잘못됐을 때 쓰는 체계적인 디버깅 프로토콜입니다. 순서대로 진행하세요 — 대부분의 버그는 처음 3단계에서 잡힙니다.

## 학습 전 (버그 예방)

1. 모델 아키텍처와 파라미터 수를 출력합니다. 크기가 데이터에 비해 말이 되나요?
2. 무작위 입력으로 순전파 한 번을 돌립니다. 출력 모양이 목표 모양과 일치하나요?
3. 레이블 dtype이 올바른지 확인합니다 (CrossEntropyLoss는 Long, BCELoss는 Float 필요)
4. 데이터 정규화를 검증합니다: 입력의 평균은 0 근처, 표준편차는 1 근처여야 합니다
5. 무작위 (입력, 레이블) 쌍 5개를 출력합니다. 레이블이 예상과 일치하나요?
6. 학습/테스트 분할에 중복 샘플이 없는지 확인합니다

## 배치 하나 과적합 테스트 (60초, 버그의 80%를 잡아냄)

1. 학습셋에서 샘플 8~32개를 가져옵니다
2. 합리적인 학습률로 200단계 학습합니다
3. 손실은 0에 가까워지고, 학습 정확도는 100%를 찍어야 합니다
4. 실패하면: 버그는 모델, 손실 함수, 학습 루프에 있습니다 — 데이터나 하이퍼파라미터가 아닙니다
5. 통과하면: 본격 학습으로 진행합니다

## 손실이 줄지 않을 때

1. 학습률을 확인합니다. 세 가지 값을 시도합니다: 현재값/10, 현재값, 현재값×10
2. 레이어별 그래디언트 노름을 출력합니다. 전부 0이면 네트워크가 죽었거나 그래프가 떨어져 나갔다는 뜻입니다
3. 파라미터에 `requires_grad=True`가 있는지 확인하고, `loss.backward()`가 호출되는지 확인합니다
4. `loss.backward()` 전에 `optimizer.zero_grad()`가 호출되는지 확인합니다
5. `loss.backward()` 후에 `optimizer.step()`이 호출되는지 확인합니다
6. 모델 파라미터가 옵티마이저에 전달되는지 확인합니다: `optimizer = Adam(model.parameters())`

## 손실이 NaN 또는 Inf일 때

1. 학습률을 10분의 1로 줄입니다
2. 모든 log() 호출에 엡실론을 더합니다: `torch.log(x + 1e-7)`
3. 모든 나누기에 엡실론을 더합니다: `x / (y + 1e-8)`
4. BCE 손실 전에 예측 값을 잘라 둡니다: `torch.clamp(pred, 1e-7, 1 - 1e-7)`
5. `torch.autograd.detect_anomaly()`로 정확히 어떤 연산이 문제인지 찾습니다
6. 입력 데이터에 NaN이 없는지 확인합니다: `assert not torch.isnan(x).any()`

## 손실이 진동할 때

1. 학습률을 3~10분의 1로 줄입니다
2. 배치 크기를 키웁니다(그래디언트 잡음이 줄어듭니다)
3. 그래디언트 클리핑을 추가합니다: `torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)`
4. SGD를 Adam으로 바꿉니다(파라미터별 적응적 학습률)
5. 학습 초반 5~10% 구간에 학습률 워밍업을 추가합니다

## 과적합 (학습 정확도는 높고 테스트는 낮을 때)

1. 드롭아웃을 추가합니다(p=0.1로 시작해 0.5까지 올립니다)
2. 옵티마이저에 가중치 감쇠를 추가합니다: `Adam(params, weight_decay=1e-4)`
3. 모델 크기를 줄입니다(레이어를 줄이거나 좁게 만듭니다)
4. 데이터 증강을 추가합니다
5. 조기 종료를 사용합니다: 검증 손실이 5 에포크 이상 증가하면 멈춥니다
6. 학습셋과 테스트셋 사이의 데이터 누수를 확인합니다

## 과소적합 (학습·테스트 정확도가 둘 다 낮을 때)

1. 모델 용량을 키웁니다(레이어를 더 많이, 더 넓게)
2. 에포크를 더 돌립니다
3. 학습률을 올립니다(신중하게)
4. 정규화를 잠시 제거해서 모델이 학습 가능한지 확인합니다
5. 모델이 과제를 표현하기에 충분한지 확인합니다

## 죽은 ReLU 뉴런

1. 레이어별 0 활성화 비율을 확인합니다. 50%를 넘으면 문제입니다
2. LeakyReLU(0.01)나 GELU로 바꿉니다
3. 가중치에 Kaiming 초기화를 사용합니다
4. 학습률을 낮춥니다(큰 갱신이 뉴런을 죽은 구간으로 밀어 넣을 수 있습니다)
5. 활성화 함수 전에 배치 정규화를 추가합니다

## 빠른 참고: 학습률 시작점

| 옵티마이저 | 작업 | 시작 학습률 |
|-----------|------|------------|
| Adam | 처음부터 학습 | 1e-3 |
| Adam | 사전 학습 모델 파인튜닝 | 1e-5 |
| SGD + momentum | 처음부터 학습 | 1e-1 |
| SGD + momentum | 사전 학습 모델 파인튜닝 | 1e-3 |
| AdamW | Transformer 학습 | 3e-4 |

## 빠른 참고: 배치 크기의 효과

| 배치 크기 | 그래디언트 잡음 | 메모리 | 일반화 |
|-----------|---------------|--------|---------------|
| 8-16 | 높음(잡음 많음) | 낮음 | 흔히 더 좋음 |
| 32-64 | 보통 | 보통 | 좋은 기본값 |
| 128-256 | 낮음(매끄러움) | 높음 | 워밍업이 필요할 수 있음 |
| 512+ | 매우 낮음 | 매우 높음 | 학습률 스케일링 필요 |

## 아무것도 안 될 때

1. 모델을 은닉층 1개로 단순화합니다. 학습하나요?
2. 데이터를 100개 샘플로 단순화합니다. 과적합되나요?
3. 손실을 MSE로 바꿉니다. 수렴하나요?
4. 옵티마이저를 SGD(lr=0.01)로 바꿉니다. 진전이 있나요?
5. 데이터를 합성 데이터로 바꿉니다(예: y = x[0] > 0). 학습하나요?
6. 이 중 아무것도 안 되면: 버그는 지금 보고 있지 않은 코드(데이터 로딩, 전처리, 텐서 모양)에 있습니다
