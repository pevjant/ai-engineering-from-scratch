# 멀티모달 RAG와 크로스 모달 검색

> 비전 네이티브 문서 RAG는 한 조각일 뿐입니다. 프로덕션 멀티모달 RAG는 더 넓게 갑니다 — 여행 계획("자연광이 들고 조용한 비건 브런치를 찾아 줘"), 의료 분류("이 사진 + 이 소견과 맞는 부상이 뭔가요"), 전자상거래("이 셀카와 비슷한 옷을 내 사이즈로 찾아 줘"), 현장 서비스("이 엔진 소리와 부품 사진으로 진단해 줘") 같은 워크플로에서 텍스트, 이미지, 오디오, 비디오를 넘나들며 검색하는 것이죠. 2025년의 세 개 서베이 — Abootorabi et al., Mei et al., Zhao et al. — 는 하위 문제들을 체계화했습니다: 크로스 모달 검색, 검색 융합, 생성 접지(grounding), 멀티모달 평가. 이 레슨에서는 이 서베이들을 읽고 프로덕션 파이프라인을 설계합니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리, 융합이 있는 크로스 모달 검색기 + 접지된 생성기)
**선수 지식:** Phase 12 · 23 (ColPali), Phase 11 (RAG basics)
**소요 시간:** ~180분

## 학습 목표

- 크로스 모달 검색을 설계할 수 있다: 텍스트 → 이미지, 이미지 → 텍스트, 오디오 → 비디오 등.
- 세 가지 융합 전략을 비교할 수 있다: 점수 융합, 어텐션 기반 융합, MoE 융합.
- 생성 접지를 설명할 수 있다: 소스가 여러 모달리티의 혼합일 때 "출처를 밝혀라"가 어떤 모습인지.
- 2025년의 세 개 대표 멀티모달 RAG 서베이와 그 하위 문제 분류법을 설명할 수 있다.

## 문제 상황

단일 모달리티 RAG는 해결된 패턴입니다: 질의 임베딩, 청크 임베딩, 검색, LLM에 넣기. 멀티모달 RAG에는 다음이 필요합니다:

1. 여러 검색 헤드(모달리티마다 호환 가능한 공간의 임베딩이 필요).
2. 모달리티를 넘나드는 검색 결과의 융합.
3. 모달리티를 아우르는 출처를 인용하는 생성 접지.
4. 크로스 모달 신호를 다루는 평가 지표.

2025년 서베이들은 모두 같은 분류법에 도달합니다.

## 개념

### 크로스 모달 검색

모달리티 A의 질의로 모달리티 B의 문서를 검색합니다. 세 패턴이 있습니다:

1. 공유 임베딩 공간. CLIP과 CLAP은 공유 공간에 텍스트 + 이미지 / 텍스트 + 오디오 임베딩을 만듭니다. 모달리티를 넘나드는 코사인 유사도가 바로 통합니다. CLIP이 학습된 쌍으로 제한됩니다.

2. 모달리티별 인코더 + 변역기. 텍스트 인코더 + 이미지 인코더 + 공간 사이를 잇는 작은 번역 모듈. Gupta et al.의 Sen2Sen 등 2024년 설계들입니다. 유연하지만 복잡도가 늘어납니다.

3. VLM을 인코더로. VLM의 은닉 상태를 검색 표현으로 씁니다. VLM이 지원하는 모든 모달리티가 동작합니다. 품질은 더 높고 비용도 더 큽니다.

선택: 텍스트+이미지에는 CLIP / SigLIP 2; 텍스트+오디오에는 CLAP; 프런티어 품질의 크로스 모달에는 VLM 은닉 상태.

### 융합 전략

검색 결과 10개를 얻었다고 합시다: 이미지 5개, 텍스트 구절 3개, 오디오 클립 2개. 어떻게 합칠까요?

점수 융합(가장 저렴). 모달리티마다 자기 검색기가 있고, 각자 점수를 돌려줍니다. 모달리티 내에서 점수를 정규화한 뒤 더합니다. 단순하고 보통은 통합니다.

어텐션 기반 융합. 검색된 모든 항목을 이어 붙이고, 작은 어텐션 네트워크가 가중치를 정합니다. 학습이 필요합니다.

MoE 융합. 게이팅 네트워크가 모달리티별 전문가로 라우팅합니다. 질의 유형에 따라 다르게 라우팅됩니다 — 시각적 질문은 이미지에 더 높은 가중치를 줍니다.

프로덕션 기본값: 질의의 우세한 모달리티에 약간 치우침을 둔 점수 융합. A/B에서 명확한 승리가 보이면 MoE로 업그레이드합니다.

### 생성 접지

LLM은 각 주장이 어떤 검색 결과에서 나왔는지 인용해야 합니다. 멀티모달에서는:

- 텍스트 소스: 표준 인용 `[1]`.
- 이미지 소스: 짧은 캡션과 함께 `[img 3]`.
- 오디오: `[audio 2 at 0:34]`.

접지 인지 데이터로 생성기를 학습시킵니다: 학습 타깃의 각 주장에 소스 인덱스를 태깅하는 것이죠. 그러면 추론 때 모델이 자연스럽게 인용을 내놓습니다.

### 2025년의 서베이들

Abootorabi et al. (arXiv:2502.08826, "Ask in Any Modality"): 멀티모달 RAG의 분류법. 검색, 융합, 생성을 다룹니다. 가장 폭넓은 커버리지.

Mei et al. (arXiv:2504.08748, "A Survey of Multimodal RAG"): 하위 과제 벤치마크와 실패 양상에 초점. 평가 설계에 유용합니다.

Zhao et al. (arXiv:2503.18016): 비전 중심 서베이. ColPali 계열 연구에 강합니다.

세 개를 모두 읽으면 2025년 봄 기준 최신 기술이 보입니다. 하위 문제 대부분은 여전히 풀리지 않았습니다.

### MuRAG — 기초 논문

MuRAG(Chen et al., 2022)가 최초의 멀티모달 RAG였습니다. 멀티모달 지식베이스에서 이미지 + 텍스트를 검색해 답변을 생성했습니다. VLM 물결 이전에 실현 가능성을 보여 줬죠. 현대 시스템들(REACT, VisRAG, M3DocRAG)은 이 위에 세워졌습니다.

### 프로덕션 여행 플래너 예제

질의: "자연광이 들고 조용한 비건 브런치를 찾아 줘."

파이프라인:

1. 질의를 분해합니다. "조용한" → 오디오/리뷰 키워드; "비건 브런치" → 메뉴 항목; "자연광" → 이미지 특성.
2. 모달리티별 검색:
   - 리뷰 텍스트 검색: "비건 브런치, 조용한 분위기."
   - 식당 사진 이미지 검색: "자연광, 쾌적함."
   - 주변 소리 클립 오디오 검색: "낮은 데시벨, 음악 없음."
3. 점수를 융합합니다. 각 식당이 복합 점수를 가집니다.
4. 상위 k개 식당 → 모든 증거를 갖춘 VLM 생성기 → 인용과 함께 답변.

텍스트-RAG를 훌쩍 넘는 일입니다. 각 모달리티가 텍스트만으로는 놓치는 신호를 더합니다.

### 에이전틱 멀티모달 RAG

멀티 홉: 첫 검색이 높은 확신도의 답을 돌려주지 않으면, LLM이 질의를 다시 만들어 재검색합니다. Phase 14의 에이전틱 RAG 패턴이 여기 적용됩니다. 예:

- 초기 상위 10개 검색 → LLM이 "너무 시끄러워요, 40dB 미만으로 필터링" → 재검색.
- 이미지 검색 → LLM이 그중 하나에 메뉴가 보임 → 메뉴 텍스트를 검색 → 답변.

복잡도는 늘지만 1회성 검색으로는 못 하는 질의를 처리합니다.

### 평가

크로스 모달 평가는 아직 미성숙합니다. 흔한 대체 지표:

- 모달리티별 Recall@k.
- 융합 상위 k 정확도.
- 사람이 판단한 엔드투엔드 만족도.
- 과제별 지표(완료된 예약, 발생한 구매).

모든 모달리티를 아우르는 표준 벤치마크는 없습니다. 대부분의 논문은 도메인별 과제로 평가합니다.

## 직접 해보기

`code/main.py`:

- 공유 식당 코퍼스에서 동작하는 목업 검색기 셋(텍스트, 이미지, 오디오).
- 설정 가능한 가중치로 모달리티 점수를 합치는 점수 융합.
- 인용과 함께 최종 답변을 내놓는 생성기 스텁.
- 확신도가 낮으면 질의를 다시 만드는 간단한 에이전틱 루프.

## 연습 문제

1. 의료 분류 멀티모달 RAG를 제안해 보세요: 질의 = 부상 사진 + 텍스트 증상. 어떤 모달리티가 어떤 지식베이스에서 검색할까요?

2. 점수 융합은 단순 가중합입니다. MoE 융합이 피하는 실패 양상은 무엇일까요?

3. Abootorabi et al.의 분류법(3절)을 읽어 보세요. 세 개의 대표 하위 문제는 무엇이고, 여러분이 고른 제품에 어떻게 대응될까요?

4. 여행 플래너 멀티모달 RAG의 평가 사양을 설계해 보세요. 이미지 회상, 오디오 회상, 복합 정확성을 각각 어떤 지표가 다룰까요?

5. 에이전틱 멀티 홉 RAG는 왕복마다 지연 시간 세금을 냅니다. 어느 정도 난이도의 질의부터 정확도 이득이 그 지연을 정당화할까요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| 크로스 모달 검색 (Cross-modal retrieval) | "한 모달리티로 물어 다른 모달리티를 검색" | 텍스트 질의로 이미지를 검색; 이미지 질의로 텍스트를 검색; 공유 공간이나 번역기 필요 |
| 점수 융합 (Score fusion) | "점수 합치기" | 모달리티별 검색 점수의 가중합; 가장 단순한 융합 |
| MoE 융합 | "모달리티 라우팅 전문가" | 게이팅 네트워크가 질의별로 어떤 모달리티의 점수를 신뢰할지 고름 |
| 접지된 생성 (Grounded generation) | "출처 밝히기" | 답변의 각 주장에 소스 인덱스를 태깅 |
| MuRAG | "최초의 멀티모달 RAG" | 멀티모달 RAG 패턴을 확립한 2022년 논문 |
| 에이전틱 멀티 홉 (Agentic multi-hop) | "다시 만들고 재시도" | 1차 검색의 확신도가 낮으면 LLM이 검색기를 다시 질의 |
