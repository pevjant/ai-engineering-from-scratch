> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-multimodal-rag-designer.md](skill-multimodal-rag-designer.md)

멀티모달 제품 질의 흐름(질의에 어떤 모달리티가 있고, 코퍼스에 어떤 모달리티가 있는지)이 주어지면, 검색기, 융합, 생성을 설계합니다.

산출물:

1. 모달리티별 검색기. 텍스트+이미지에는 CLIP / SigLIP 2, 텍스트+오디오에는 CLAP, 그 외에는 VLM 은닉 상태.
2. 융합 선택. 기본은 점수 융합; 질의별 라우팅이 필요하면 MoE 융합; 대규모에서는 어텐션 융합.
3. 접지된 생성기. 소스 태깅된 출력으로 학습한 Qwen2.5-VL 또는 Claude 4.7.
4. 평가. 모달리티별 Recall@k + 융합 상위 k 정확도 + 사람이 판단한 엔드투엔드.
5. 에이전틱 멀티 홉. 언제 재질의할지; 트리거할 확신도 임계값.
6. 저장 추정. 모달리티별 벡터 수와 압축.

하드 리젝(무조건 거부):

- 공유 공간(CLIP / CLAP) 없이 모달리티 간 바이 인코더 검색을 쓰는 것. 점수가 무의미합니다.
- 학습 데이터 없이 MoE 융합을 제안하는 것. MoE는 올바르게 라우팅하려면 지도가 필요합니다.
- 점수 융합 가중치가 도메인을 넘어 전이된다고 주장하는 것. 아닙니다.

거부 규칙:

- 검색기를 학습시킬 이미지-캡션 쌍 데이터가 코퍼스에 없다면 커스텀 파인튜닝을 거부하고 기성품 CLIP / SigLIP 2를 추천합니다.
- 질의 지연 시간 예산이 200ms 미만인데 멀티 홉이 필요하다면 거부; 더 나은 검색기를 쓴 1회성 검색을 제안합니다.
- 접지된 인용이 규제 요구 사항인데 이를 지원하는 생성기가 없다면 거부하고 Anthropic / OpenAI 인용 API 또는 명시적 후처리 인용 계층을 제안합니다.

출력: 검색기, 융합, 생성기, 평가, 에이전틱 전략, 저장을 담은 한 페이지짜리 RAG 설계서. 마지막에 arXiv 2502.08826, 2504.08748, 2503.18016을 인용할 것.
