# 문서와 다이어그램 이해

> 문서는 사진이 아닙니다. PDF, 학술 논문, 청구서, 손작성 양식에는 레이아웃, 표, 다이어그램, 각주, 헤더, 의미 구조가 있고, 단순 이미지 이해로는 이를 담을 수 없습니다. VLM 이전 스택은 파이프라인이었습니다: Tesseract OCR + LayoutLMv3 + 표 추출 휴리스틱. VLM 물결은 그것을 OCR 없는(OCR-free) 모델 — Donut(2022), Nougat(2023), DocLLM(2023) — 로 대체했는데, 이들은 구조화된 마크업을 바로 출력했습니다. 2026년의 프런티어는 그냥 "페이지 이미지를 네이티브 2576px로 Claude Opus 4.7에 넣는 것"이고, 구조화 마크업 출력은 덤으로 따라옵니다. 이 레슨에서는 문서 AI의 3시대 대곡선을 읽어 봅니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리, 레이아웃 인지 문서 파서 스켈레톤)
**선수 지식:** Phase 12 · 05 (LLaVA), Phase 5 (NLP)
**소요 시간:** ~180분

## 학습 목표

- 문서 AI의 세 시대를 설명할 수 있다: OCR 파이프라인, OCR-free, VLM 네이티브.
- LayoutLMv3의 세 입력 스트림 — 텍스트, 레이아웃(bbox), 이미지 패치 — 과 통합 마스킹을 설명할 수 있다.
- Donut(OCR-free, 이미지 → 마크업), Nougat(학술 논문 → LaTeX), DocLLM(레이아웃 인지 생성형), PaliGemma 2(VLM 네이티브)를 비교할 수 있다.
- 새로운 과제(청구서, 학술 논문, 손작성 양식, 중국어 영수증)에 문서 모델을 고를 수 있다.

## 문제 상황

"이 PDF를 이해해 줘"는 겉보기보다 어렵습니다. 정보가 자리하는 곳은:

- 텍스트 내용(신호의 90%).
- 레이아웃(헤더, 각주, 사이드바, 두 단 조판).
- 표(행, 열, 병합 셀).
- 그림과 다이어그램.
- 손글씨 주석.
- 글꼴과 타이포그래피(제목 vs 본문).

날것의 OCR은 텍스트만 덤프하고 나머지를 잃습니다. 청구서를 다루는 시스템이라면 "합계: $1,245"가 각주가 아니라 오른쪽 아래에서 왔다는 걸 알아야 합니다.

## 개념

### 시대 1 — OCR 파이프라인 (2021년 이전)

고전 스택:

1. PDF → 페이지별 이미지.
2. Tesseract(또는 상용 OCR)가 단어별 바운딩 박스와 함께 텍스트를 추출합니다.
3. 레이아웃 분석기가 블록(헤더, 표, 문단)을 식별합니다.
4. 표 구조 인식기가 표를 파싱합니다.
5. 도메인 규칙 + 정규식이 필드를 추출합니다.

깨끗한 인쇄 텍스트에는 통합니다. 손글씨, 기울어진 스캔본, 복잡한 표, 비영어 문자에서는 깨집니다. 모든 실패 양상마다 맞춤 예외 경로가 필요하죠.

### TrOCR (2021)

TrOCR(Li et al., arXiv:2109.10282)는 Tesseract의 고전 CNN-CTC를 합성 + 실제 텍스트 이미지로 학습한 트랜스포머 인코더-디코더로 바꿨습니다. 손글씨와 다국어 텍스트에서 확실한 승리. 여전히 파이프라인(탐지 → TrOCR → 레이아웃)이지만, OCR 단계가 극적으로 좋아졌습니다.

### 시대 2 — OCR-free (2022~2023)

최초의 OCR-free 모델들은 이렇게 말했습니다: 탐지를 아예 건너뛰고, 이미지 픽셀을 구조화된 출력으로 직접 매핑하자.

Donut(Kim et al., arXiv:2111.15664):
- 인코더-디코더 트랜스포머, 인코더는 Swin-B.
- 출력은 양식 이해용 JSON, 요약용 마크다운, 또는 과제별 스키마.
- OCR 없음, 레이아웃 없음, 탐지 없음.

Nougat(Blecher et al., arXiv:2308.13418):
- 학술 논문 전용으로 학습.
- 출력은 LaTeX / 마크다운.
- 수식, 다단 레이아웃, 그림을 처리합니다.
- 모든 arXiv 파서가 부르는 모델.

이들은 전문가지 일반인이 아닙니다. Donut을 학술 논문에 쓰면 실패하고, Nougat을 청구서에 쓰면 실패합니다.

### LayoutLMv3 (2022)

다른 트랙입니다. LayoutLMv3(Huang et al., arXiv:2204.08387)는 OCR을 유지하되 레이아웃 이해를 더합니다:

- 세 입력 스트림: OCR 텍스트 토큰, 토큰별 2D 바운딩 박스, 이미지 패치.
- 세 모달리티 모두를 아우르는 마스킹 학습 목표(마스크 텍스트, 마스크 패치, 마스크 레이아웃).
- 다운스트림: 분류, 개체 추출, 표 QA.

LayoutLMv3는 OCR 기반 문서 이해의 정점입니다. 양식과 청구서에 강합니다. 상류 OCR이 필요하고, 표준화된 문서 벤치마크에서 VLM 이전 최고 정확도를 기록했습니다.

### DocLLM (2023)

DocLLM(Wang et al., arXiv:2401.00908)은 LayoutLM의 생성형 형제입니다. 레이아웃 토큰을 조건으로 자유 형식 답변을 생성합니다. 문서 QA에 더 좋지만, 여전히 OCR 입력에 의존합니다.

### 시대 3 — VLM 네이티브 (2024~)

2024년 VLM은 파이프라인 전체를 대체할 만큼 좋아졌습니다. 고해상도 전체 페이지 이미지를 VLM에 넣고, 질문하고, 답을 받으면 됩니다.

- LLaVA-NeXT의 336타일 AnyRes는 작은 문서에 통합니다.
- Qwen2.5-VL 동적 해상도는 2048픽셀 이상을 네이티브로 처리합니다.
- Claude Opus 4.7은 2576px 문서를 지원합니다.
- PaliGemma 2(2025년 4월)는 문서 + 손글씨 전용으로 학습됐습니다.

VLM 네이티브와 OCR 파이프라인의 격차는 급속히 닫혔습니다. 2026년에는 VLM 네이티브가 이깁니다:

- 장면 텍스트(손글씨 + 인쇄, 섞인 문자 체계).
- 병합 셀이 있는 복잡한 표.
- 텍스트에 삽입된 수학 수식.
- 텍스트 주석이 있는 그림.

OCR 파이프라인이 여전히 이기는 곳:

- 페이지당 지연 시간이 중요한 초대규모 순수 스캔 워크로드.
- 파이프라인 신뢰성(결정론적 실패 vs VLM 환각).
- 감사 가능한 OCR 출력을 요구하는 규제 환경.

### Claude 4.7 / GPT-5 프런티어

2576픽셀 네이티브 입력에서 프런티어 VLM은 준인간 수준의 문서 이해를 합니다. 2026년 초 벤치마크 수치:

- DocVQA: Claude 4.7 ~95.1, PaliGemma 2 ~88.4, Nougat ~77.3, 파이프라인 LayoutLMv3 ~83.
- ChartQA: Claude 4.7 ~92.2, GPT-4V ~78.
- VisualMRC: Claude 4.7 ~94.

클로즈드 모델과의 격차는 대부분 해상도와 베이스 LLM 규모 탓입니다. 7B 오픈 모델은 몇 점 뒤처져 있지만 따라잡는 중입니다.

### 수학 수식과 LaTeX 출력

학술 논문은 수식에 정확한 LaTeX 출력이 필요합니다. Nougat은 이것으로 학습됐습니다. LaTeX 타깃으로 학습한 VLM(Qwen2.5-VL-Math, Nougat 파생)은 쓸 만한 LaTeX을 만들어 냅니다. 명시적 LaTeX 학습이 없으면 VLM은 읽을 수는 있지만 부정확한 전사를 내놓습니다.

2026년 학술 논문 파이프라인: PDF에는 Nougat을 돌리고, 까다로운 페이지에는 VLM을 이어서 씁니다.

### 손글씨

여전히 가장 어려운 하위 과제입니다. 인쇄 + 손글씨 혼합(의사 소견서, 작성된 양식)은 비용 면에서 OCR 파이프라인이 여전히 VLM을 이기는 곳입니다. 손글씨 전용 VLM은 개선 중입니다(Claude 4.7, PaliGemma 2).

### 2026년 레시피

새로운 문서-AI 프로젝트라면:

- 초대규모 순수 인쇄 청구서: LayoutLMv3 + 규칙. 비용 효율적입니다.
- 혼합 문서(학술 + 손글씨 + 양식): VLM 네이티브(PaliGemma 2 또는 Qwen2.5-VL).
- arXiv 전체 수집: 수식은 Nougat, 그림은 VLM.
- 규제 대상: OCR 파이프라인 주력 + VLM 검증기로 교차 확인.

## 직접 해보기

`code/main.py`:

- 장난감 레이아웃 인지 토크나이저: (텍스트, bbox) 쌍을 받아 LayoutLMv3 스타일 입력을 생성합니다.
- Donut 스타일 과제 스키마 생성기: 양식용 JSON 템플릿.
- OCR 파이프라인, Donut, Nougat, VLM 네이티브의 페이지당 토큰 예산 비교.

## 출시하기

이 레슨은 `outputs/skill-document-ai-stack-picker.md`를 만듭니다. 문서-AI 프로젝트(도메인, 규모, 품질, 규제)가 주어지면 OCR 파이프라인, OCR-free 전문 모델, VLM 네이티브 중 하나를 골라 줍니다.

## 연습 문제

1. 여러분의 프로젝트는 하루 1,000만 건의 청구서를 처리합니다. 정확도를 잃지 않으면서 페이지당 비용을 최소화하는 스택은 무엇일까요?

2. LayoutLMv3가 양식 QA에서 순수 CLIP-VLM을 이기면서 장면 텍스트에서는 지는 이유는 무엇일까요? bbox 스트림은 무엇을 포기한 걸까요?

3. Nougat은 LaTeX을 생성합니다. VLM 네이티브 출력이 LaTeX 충실도에서 Nougat을 이기는 테스트 케이스와, Nougat이 이기는 케이스를 하나씩 제안해 보세요.

4. PaliGemma 2 논문(Google, 2024)을 읽어 보세요. PaliGemma 1 대비 문서 정확도를 끌어올린 핵심 학습 데이터 추가는 무엇이었나요?

5. 규제에 안전한 하이브리드를 설계해 보세요: OCR 파이프라인 주력, VLM 보조 교차 확인. 불일치는 어떻게 해결할까요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| OCR 파이프라인 | "Tesseract 스타일" | 단계별 스택: 탐지 → OCR → 레이아웃 → 규칙; 결정론적이지만 취약함 |
| OCR-free | "Donut 스타일" | 명시적 OCR을 건너뛰는 이미지→출력 트랜스포머; 단일 모델 |
| 레이아웃 인지 (Layout-aware) | "LayoutLM" | 입력에 토큰별 bbox 좌표 포함; 모달리티 전반의 통합 마스킹 |
| VLM 네이티브 | "프런티어 VLM" | 페이지 이미지를 고해상도로 Claude/GPT/Qwen VLM에 바로 공급; 파이프라인 없음 |
| DocVQA | "문서 벤치" | 문서 VQA 표준; 가장 많이 인용되는 점수 |
| 마크업 출력 | "LaTeX / MD" | 자유 텍스트 대신 구조화된 출력 형식; 다운스트림 자동화를 가능하게 함 |
