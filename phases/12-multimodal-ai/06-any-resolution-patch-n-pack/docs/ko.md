# 모든 해상도를 다루는 비전: Patch-n'-Pack과 NaFlex

> 실제 이미지는 224x224 정사각형이 아닙니다. 영수증은 9:16, 차트는 16:9, 의료 영상은 4096x4096일 수도 있고, 모바일 스크린샷은 9:19.5입니다. 2024년 이전 VLM의 답 — 전부 고정된 정사각형으로 리사이즈 — 은 OCR, 문서 이해, 고해상도 장면 분석을 가능하게 하는 신호를 그냥 버려버렸습니다. NaViT(구글, 2023)는 가변 해상도 패치를 블록 대각선 마스킹(block-diagonal masking)으로 하나의 트랜스포머 배치에 담아(pack) 넣을 수 있음을 보여줬습니다. Qwen2-VL의 M-RoPE(2024)는 절대 위치 테이블을 아예 없애버렸습니다. LLaVA-NeXT의 AnyRes는 고해상도 이미지를 베이스 + 서브 이미지들로 타일링했습니다. SigLIP 2의 NaFlex 변형(2025)은 이제 모든 가로세로비를 하나의 체크포인트로 처리하고 싶은 오픈 VLM의 기본 인코더가 됐습니다. 이 레슨에서는 patch-n'-pack을 끝까지 구현해 봅니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리, 패치 패커 + 블록 대각선 마스크)
**선수 지식:** 페이즈 12 · 01 (ViT 패치), 페이즈 12 · 05 (LLaVA)
**시간:** 약 120분

## 학습 목표

- 가변 해상도 이미지들로 이뤄진 배치의 패치를 하나의 시퀀스로 포장(pack)하고 블록 대각선 어텐션 마스크를 만든다.
- 주어진 과제에 맞춰 AnyRes 타일링(LLaVA-NeXT), NaFlex(SigLIP 2), M-RoPE(Qwen2-VL) 중 하나를 고른다.
- 리사이즈 없이 OCR, 차트, 사진의 토큰 예산을 계산한다.
- 정사각형 리사이즈의 세 가지 실패 모드를 말할 수 있다: 찌그러진 글자, 잘려나간 내용, 패딩에 낭비되는 토큰.

## 문제 상황

트랜스포머는 시퀀스를 기대합니다. 배치는 같은 길이의 시퀀스가 쌓인 것입니다. 이미지가 전부 224x224라면 항상 196개의 패치 토큰이 나오고, 패딩도 필요 없고, 끝. 224로 학습하고 224로 추론하면 해상도를 다시 생각할 일이 없죠.

그런데 세상이 순순히 응해주지 않습니다. 문서는 세로로 길고(8.5x11인치, 대략 2:3), 차트 스크린샷은 가로로 길고(16:9), 영수증은 길쭉하고 얇으며(1:3), 의료 영상은 2048x2048 이상으로 오고, 모바일 스크린샷은 1170x2532(0.46:1)입니다.

2024년 이전의 세 가지 선택지와, 각각이 왜 실패하는지:

1. 고정 정사각형으로 리사이즈(224x224 또는 336x336). 찌그러짐이 글자와 얼굴을 왜곡합니다. 축소는 차트 라벨과 OCR 내용을 파괴합니다. LLaVA-1.5까지 표준 관행이었습니다.
2. 고정 가로세로비로 크롭. 이미지 대부분을 버리는 셈이고, 크롭 위치를 고르는 것 자체가 또 하나의 비전 문제입니다.
3. 긴 쪽에 맞춰 패딩. 왜곡은 막지만 세로 이미지에서는 토큰의 50% 이상이 패딩에 낭비됩니다. 그 패드 토큰 전부에 어텐션 비용이 제곱으로 붙죠.

2024-2025년의 답: 트랜스포머가 이미지 원래 해상도의 패치를 그대로 먹게 하고, 이질적인 배치를 낭비 없는 연산으로 한 시퀀스에 담는 방법을 고안하는 것.

## 개념

### NaViT와 patch-n'-pack

NaViT(Dehghani 등, 2023)는 이 방식이 대규모로 통한다는 걸 보여준 논문입니다. 아이디어는 기계적입니다:

1. 배치의 각 이미지에 대해, 정한 패치 크기(예: 14)로 원래 해상도 패치 그리드를 계산한다.
2. 이미지별 패치를 각자 자기 길이를 가진 시퀀스로 펼친다.
3. 모든 이미지의 패치를 하나의 긴 시퀀스로 배치 단위에서 연결한다.
4. 블록 대각선 어텐션 마스크를 만들어, 이미지 A의 패치가 이미지 A 안에서만 어텐션하게 한다.
5. 패치별 위치 정보(2D RoPE 또는 분수형 위치 임베딩)를 함께 전달한다.

336x336(576토큰), 224x224(256토큰), 448x336(768토큰) 이미지 세 장의 배치는 1600x1600 블록 대각선 마스크를 가진 1600토큰 시퀀스 하나가 됩니다. 패딩 없음. 낭비 연산 없음. 트랜스포머가 임의의 가로세로비를 처리합니다.

NaViT는 학습 중 분수형 패치 드로핑도 도입했습니다 — 배치 전체에서 패치의 50%를 무작위로 떨어뜨리는 건데, 정규화 효과와 학습 속도 향상을 동시에 줍니다. SigLIP 2가 이를 계승했습니다.

### AnyRes (LLaVA-NeXT)

LLaVA-NeXT의 AnyRes는 실용주의적인 대안입니다. 고해상도 이미지와 고정 인코더(CLIP 또는 SigLIP, 336)가 주어지면 이미지를 타일로 나눕니다:

1. 미리 정해진 그리드 후보 — (1x1), (1x2), (2x1), (1x3), (3x1), (2x2) 등 — 중 이미지의 가로세로비에 가장 잘 맞는 배치를 고른다.
2. 전체 이미지를 그리드로 타일링한다. 각 타일은 336x336 크롭이 됩니다.
3. 썸네일도 하나 만든다: 전체 이미지를 336x336으로 줄인 것으로, 전역 컨텍스트 토큰 역할을 합니다.
4. 모든 타일을 고정된 336 인코더에 통과시키고, 타일 토큰 + 썸네일 토큰을 연결한다.

672x672 이미지를 2x2 그리드 + 썸네일로 처리하면 4 * 576 + 576 = 2880개의 시각 토큰입니다. 비싸지만 효과적 — LLM이 지역 디테일과 전역 컨텍스트를 모두 봅니다.

인코더가 고정돼 있고 하나의 해상도만 지원할 때 AnyRes가 기본 선택입니다. 다만 큰 이미지에서 토큰 수가 폭발합니다(1344x1344 이미지를 4x4 그리드로 하면 9216 + 576 ≈ 9800토큰, 8k LLM 컨텍스트 대부분을 채웁니다).

### M-RoPE (Qwen2-VL)

Qwen2-VL은 멀티모달 회전 위치 임베딩(Multimodal Rotary Position Embedding)을 도입했습니다. NaViT식 분수 위치나 AnyRes식 타일+썸네일 대신, 각 패치가 3차원 위치(시간, 높이, 너비)를 가집니다. 쿼리/키 회전이 임의의 H, W, 시간 길이를 처리하죠.

M-RoPE는 재학습 없이도 네이티브 동적 해상도를 제공합니다. 추론 때 아무 HxW 이미지나 넣으면, 패치 임베더가 H/14 x W/14개 토큰을 만들고, 각 토큰이 (t=0, r=행, c=열) 위치를 받고, RoPE가 맞는 주파수로 어텐션을 회전시킵니다. 끝. Qwen2.5-VL과 Qwen3-VL도 이 방식을 이어갑니다. InternVL3의 V2PE는 모달리티별 가변 인코딩을 곱한 같은 아이디어입니다.

AnyRes와 달리 M-RoPE는 원래 해상도에서 O(H x W / P^2) 토큰 — 곱셈식 타일 오버헤드가 없습니다. NaViT와 달리 여전히 순전파당 이미지 한 장을 기대합니다. 여러 해상도를 묶어 배치하려면 그 위에 patch-n'-pack이 여전히 필요합니다.

### NaFlex (SigLIP 2)

NaFlex는 SigLIP 2 체크포인트의 네이티브 플렉스 모드입니다. 하나의 모델이 추론 때 여러 시퀀스 길이(256, 729, 1024토큰)를 처리합니다. 내부적으로는 학습 때 NaViT 스타일 patch-n'-pack을 쓰고, 패치마다 절대 분수 위치를 사용합니다. 셀링 포인트: 체크포인트 하나로, 과제에 맞춰 추론 때 토큰 예산을 고를 수 있다는 것.

의미적 과제(분류, 검색)에는 256토큰. OCR이나 차트 이해에는 1024토큰. 재학습은 필요 없습니다.

### 포장 마스크

대부분의 구현이 여기서 넘어지는 지점이 블록 대각선 마스크입니다. 길이 `N_total`의 포장된 시퀀스가 길이 `n_i`의 이미지 `i=0..B-1`을 담고 있다면, `(N_total, N_total)` 모양의 마스크 `M`은 두 인덱스가 같은 이미지 블록 안에 있을 때만 1, 아니면 0입니다. 누적 길이 목록으로 만들 수 있습니다:

```
offsets = [0, n_0, n_0+n_1, ..., N_total]
M[i, j] = offsets[b] <= i < offsets[b+1] and offsets[b] <= j < offsets[b+1]을 만족하는 b가 존재할 때만 1
```

PyTorch에서는 `torch.block_diag`나 명시적 gather로 한 줄이면 됩니다. FlashAttention의 가변 길이 경로(`cu_seqlens`)는 마스크를 아예 건너뛰고 누적 길이 텐서를 직접 써서 시퀀스 내부에서만 어텐션합니다 — 일반적인 배치에서 밀집 마스크보다 약 10배 빠릅니다.

### 토큰 예산

과제별 전략을 고르세요:

- OCR / 문서: 1024-4096토큰. 1024의 SigLIP 2 NaFlex 또는 AnyRes 3x3 + 썸네일.
- 차트와 UI: 384-448 네이티브에서 729-1024토큰. 최대 픽셀 상한을 둔 Qwen2.5-VL 동적 해상도.
- 자연 사진: 256-576토큰이면 충분합니다. 다운스트림 LLM이 볼 만큼은 보니까요. 토큰은 내용 밀도가 높은 곳에 쓰세요.
- 비디오: 공간 풀링 후 프레임당 64-128토큰, 2-8 FPS. 레슨 12.17에서 다룹니다.

2026년 프로덕션(운영 환경) 규칙: 과제별 최대 픽셀 상한을 정하고, 그 상한까지 원래 가로세로비로 인코딩하고, 배치를 포장하고, 패딩은 건너뛴다. Qwen2.5-VL은 정확히 이 노브를 `min_pixels`와 `max_pixels`로 노출합니다.

## 직접 써보기

`code/main.py`는 정수 픽셀 좌표의 이질적 이미지 배치에 대한 patch-n'-pack을 구현합니다. 이 코드는:

- (H, W) 이미지 크기 목록을 받는다.
- 패치 크기 14에서 각 이미지의 패치 시퀀스 길이를 계산한다.
- 총 길이 `sum(n_i)`의 시퀀스 하나로 포장한다.
- 블록 대각선 어텐션 마스크를 만든다(이해를 돕도록 밀집 형태로).
- 포장 비용을 정사각형 리사이즈, AnyRes 타일링과 비교한다.
- 혼합 배치(영수증, 차트, 스크린샷, 사진)의 토큰 예산 표를 출력한다.

실행해 보세요. 찍혀 나오는 숫자가 바로 2026년 모든 오픈 VLM이 patch-n'-pack을 쓰는 이유입니다.

## 연습 문제

1. 영수증이 600x1500(1:2.5)입니다. 패치 크기 14에서 원래 해상도 토큰은 몇 개인가요? 336으로 정사각형 리사이즈하면 몇 개인가요? 실제로는 어느 쪽이 OCR 정확도를 더 많이 잃을까요?

2. 길이가 256, 576, 729, 1024인 이미지 네 장의 배치에 대한 블록 대각선 마스크를 만들어 보세요. 어텐션 행렬이 2585x2585이고 0이 아닌 항이 정확히 `256^2 + 576^2 + 729^2 + 1024^2`개인지 확인하세요.

3. 1792x896 이미지를 패치 14로 처리할 때 비교해 보세요: (a) 336으로 정사각형 리사이즈 후 인코딩, (b) AnyRes 2x1 + 썸네일, (c) 네이티브 M-RoPE. 어느 쪽이 토큰을 가장 적게 쓰나요? 어느 쪽이 디테일을 가장 잘 보존하나요?

4. 분수형 패치 드로핑을 구현해 보세요: 포장된 시퀀스가 주어지면 토큰의 50%를 균등하게 무작위로 떨어뜨리고, 블록 대각선 마스크를 그에 맞게 갱신합니다. 마스크 희소성의 변화를 측정하세요.

5. Qwen2-VL 논문(arXiv:2409.12191)의 3.2절을 읽어 보세요. `min_pixels`와 `max_pixels`가 무엇을 제어하는지, 두 경계가 모두 중요한 이유를 두 문장으로 설명하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| Patch-n'-pack | "NaViT 스타일 포장" | 서로 다른 이미지의 가변 길이 패치 시퀀스를 하나의 배치 차원으로 연결 |
| 블록 대각선 마스크 | "포장 마스크" | 각 이미지의 패치가 자기 자신에게만 어텐션하고 포장 속 이웃에게는 못 하게 막는 어텐션 마스크 |
| AnyRes | "LLaVA-NeXT 타일링" | 고해상도 이미지를 고정 크기 타일 그리드 + 전역 썸네일로 나누고, 모든 타일을 고정 인코더로 인코딩 |
| NaFlex | "SigLIP 2 네이티브 플렉스" | 추론 때 256/729/1024토큰 예산을 재학습 없이 처리하는 단일 SigLIP 2 체크포인트 |
| M-RoPE | "멀티모달 RoPE" | 임의의 H, W, T를 위치 테이블 없이 처리하는 3차원 회전 위치 인코딩(시간, 행, 열) |
| cu_seqlens | "FlashAttention 포장" | FlashAttention의 varlen 경로가 밀집 블록 대각선 마스크 대신 쓰는 누적 길이 텐서 |
| min_pixels / max_pixels | "해상도 경계" | 매우 작거나 매우 큰 입력에서 토큰 수를 제한하는 Qwen2.5-VL의 요청별 노브 |
| 시각 토큰 예산 | "이미지당 토큰이 몇 개" | 이미지마다 나오는 패치 토큰의 대략적인 수; LLM의 프롬프트 예산과 어텐션 비용을 결정 |
