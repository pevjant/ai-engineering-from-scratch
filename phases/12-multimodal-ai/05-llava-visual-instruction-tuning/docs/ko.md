# LLaVA와 시각 명령 튜닝(Visual Instruction Tuning)

> LLaVA(2023년 4월)는 지구상에서 가장 많이 베껴 쓴 멀티모달 아키텍처입니다. LLaVA는 BLIP-2의 Q-Former를 2층 MLP로 교체했고, Flamingo의 게이트드 크로스 어텐션(gated cross-attention)을 단순 토큰 연결로 대체했으며, 텍스트 전용 캡션에서 GPT-4가 만들어 낸 158k개의 시각 명령 턴으로 학습했습니다. 2023년부터 2026년 사이에 VLM을 만든 실무자라면 누구나 LLaVA의 변형을 만들었습니다. LLaVA-1.5는 AnyRes를 추가했고, LLaVA-NeXT는 해상도를 올렸으며, LLaVA-OneVision은 이미지·멀티 이미지·비디오를 하나의 레시피로 통합했습니다. 이 레슨에서는 그 레시피를 읽고, 프로젝터를 직접 구현하고, "왜 단순한 쪽이 이겼는지"를 설명합니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리, 프로젝터 + 명령 템플릿 빌더)
**선수 지식:** 페이즈 12 · 02 (CLIP), 페이즈 11 (LLM 엔지니어링 — 명령 튜닝)
**시간:** 약 180분

## 학습 목표

- ViT 패치 임베딩(차원 1024)을 LLM의 임베딩 차원(4096)으로 연결하는 2층 MLP 프로젝터를 만든다.
- LLaVA의 2단계 레시피를 따라간다: (1) 558k 캡션 쌍으로 프로젝터 정렬(alignment), (2) 158k개의 GPT-4 생성 명령 턴으로 시각 명령 튜닝.
- 이미지 토큰 자리표시자(placeholder), 시스템 프롬프트, 사용자/어시스턴트 턴을 갖춘 LLaVA 형식 프롬프트를 구성한다.
- Q-Former가 토큰 예산 면에서 유리함에도 커뮤니티가 Q-Former에서 MLP로 갈아탄 이유를 설명한다.

## 문제 상황

BLIP-2의 Q-Former(레슨 12.03)는 이미지를 32개 토큰으로 압축합니다. 깔끔하고, 효율적이고, 벤치마크 성적도 좋습니다. 하지만 두 가지 문제가 있습니다.

첫째, Q-Former는 학습 가능하지만 그 손실(loss)이 최종 과제가 아니라는 점입니다. 스테이지 1에서는 ITC+ITM+ITG를 학습하고, 스테이지 2에서는 LM 손실을 학습합니다. 쿼리들은 중간 표현을 학습하고, LLM이 그것을 다시 해석해야 하죠. 병목에서 정보가 손실됩니다.

둘째, Q-Former는 1억 8800만 개의 파라미터를 차지하고, LLaVA의 2023년 규모에서는 목표 LLM과 함께 공동 설계해야 했습니다. LLM을 바꾸면 Q-Former를 재학습하고, 비전 인코더를 바꿔도 재학습해야 합니다. 모든 조합이 별개의 R&D 프로젝트였던 셈이죠.

LLaVA의 해답은 단순해서 민망할 지경이었습니다. ViT의 576개 패치 토큰을 가져와 각각을 2층 MLP(`1024 → 4096 → 4096`)에 통과시키고, 576개 전부를 LLM의 입력 시퀀스에 쑤셔 넣는 것입니다. 병목도 없고, 이상한 목적 함수로 하는 스테이지 1 사전학습도 없습니다. 그냥 직접적인 LM 손실로 MLP만 학습하면 됩니다.

그런데 데이터는 어디서 온 걸까요? LLaVA의 두 번째 통찰: GPT-4(텍스트 전용)로 명령 데이터를 생성하라는 것입니다. GPT-4에게 이미지의 COCO 캡션과 바운딩 박스 데이터를 주고, 대화·상세 설명·복잡한 추론 질문을 만들어 달라고 요청합니다. 인간 어노테이션 없이 공짜로 158k개의 명령-응답 턴을 얻은 거죠.

결과: A100 8장으로 하루 동안 학습한 VLM이 MMMU에서 Flamingo를 이겼고, 커뮤니티가 확장할 수 있는 공개 체크포인트를 내놓았습니다. 2023년 말에는 50개가 넘는 포크가 생겨났습니다.

## 개념

### 아키텍처

13B 규모의 LLaVA-1.5:
- 비전 인코더: CLIP ViT-L/14 @ 336 (스테이지 1에서는 고정, 스테이지 2에서는 선택적으로 고정 해제).
- 프로젝터: GELU 활성화 함수를 쓰는 2층 MLP, `1024 → 4096 → 4096`.
- LLM: Vicuna-13B (이후 Llama-3.1-8B).

이미지 + 텍스트 프롬프트에 대한 순전파(forward pass):

```
img -> ViT -> 차원 1024의 패치 576개
patches -> MLP -> 차원 4096의 토큰 576개
prompt: system + "<image>" 자리표시자 + 사용자 질문
<image> 토큰을 투영된 토큰 576개로 교체
전체 시퀀스를 LLM에 입력
응답 디코딩
```

이미지가 LLM 컨텍스트 중 576개 토큰을 차지합니다. 컨텍스트가 2048이면 텍스트에 1472토큰이 남죠. 32k 컨텍스트에서는 자릿수 계산할 때도 잡히지 않는 수준입니다.

### 스테이지 1: 프로젝터 정렬

ViT를 고정합니다. LLM도 고정합니다. 2층 MLP만 학습합니다. 데이터셋: 558k개의 이미지-캡션 쌍(LAION-CC-SBU). 손실: 투영된 이미지 토큰을 조건으로 캡션에 대한 언어 모델링.

배치 128로 한 에포크를 돌리면 몇 시간 안에 끝납니다. 프로젝터는 ViT 공간을 LLM 공간으로 옮기는 법을 배웁니다. 과제 특화 감독 신호는 전혀 없습니다.

### 스테이지 2: 시각 명령 튜닝

프로젝터 고정을 풉니다(계속 학습 가능). LLM 고정도 풉니다(보통 전체, 가끔 LoRA). 158k개의 시각 명령 턴으로 학습합니다.

여기서 핵심은 명령 데이터입니다. Liu 등은 이렇게 만들었습니다:
1. COCO 이미지를 하나 고른다.
2. 텍스트 설명(사람이 쓴 캡션 5개 + 바운딩 박스 목록)을 추출한다.
3. GPT-4에 세 가지 프롬프트 템플릿으로 보낸다:
   - 대화: "이 이미지에 대해 사용자와 어시스턴트가 주고받는 대화를 만들어라."
   - 상세 설명: "이미지를 풍부하고 자세하게 묘사해라."
   - 복잡한 추론: "이미지에 대해 추론이 필요한 질문을 만들고, 답도 써라."
4. GPT-4의 출력을 (명령, 응답) 쌍으로 파싱한다.

이 과정에서 이미지 자체는 전혀 건드리지 않습니다 — 텍스트 설명만 봅니다. GPT-4는 그럴듯한 이미지 내용을 지어냅니다(환각). 노이즈가 있지만, 통했습니다. 158k 턴이면 대화 기능을 여는 데 충분했거든요.

### 커뮤니티가 이 구조를 그대로 베낀 이유

- 튜닝할 스테이지 1 전용 손실이 없습니다. 처음부터 끝까지 LM 손실 하나.
- 프로젝터 학습이 며칠이 아니라 몇 시간 만에 끝납니다.
- 프로젝터만 재학습하면 LLM을 갈아끼울 수 있습니다(LLaVA-Llama2, LLaVA-Mistral, LLaVA-Llama3).
- 시각 명령 데이터 파이프라인은 GPT-4 기반이라, 새 도메인용으로 재생산 비용이 쌉니다.

### LLaVA-1.5와 LLaVA-NeXT

LLaVA-1.5(2023년 10월)의 추가 사항:
- 명령 튜닝에 학술 과제 데이터(VQA, OKVQA, RefCOCO)를 섞음.
- 더 나은 시스템 프롬프트.
- 컨텍스트 2048 → 32k.

LLaVA-NeXT(2024년 1월)의 추가 사항:
- AnyRes: 고해상도 이미지를 336x336 크롭 2x2 또는 1x3 그리드로 나누고, 전체를 담은 저해상도 썸네일 하나를 더함. 크롭 하나가 576토큰이 되어, 이미지당 시각 토큰이 총 약 2880개. OCR과 차트 과제 점수가 확시 뛰었습니다.
- ShareGPT4V(GPT-4V가 만든 고품질 캡션)를 활용한 더 나은 명령 데이터 믹스.
- 더 강한 베이스 LLM(Mistral-7B, Yi-34B).

### LLaVA-OneVision

레슨 12.08에서 OneVision을 자세히 다룹니다. 짧게 요약하면: 프로젝터는 동일하지만, 단일 이미지·멀티 이미지·비디오를 하나의 모델에서 같은 시각 토큰 예산으로 다루는 커리큘럼으로 학습했다는 차이가 있습니다.

### Q-Former와의 비교

| | Q-Former (BLIP-2) | MLP (LLaVA) |
|---|---|---|
| 이미지당 시각 토큰 | 32 | 576 (기본) 또는 2880 (AnyRes) |
| 학습 가능 파라미터 | 188M + LM | 40M + LM |
| 스테이지 1 손실 | ITC+ITM+ITG | LM만 |
| LLM 교체 | 재학습 필요 | 최소 재학습으로 교체 |
| 멀티 이미지 | 다루기 불편 | 자연스러움(연결) |
| 비디오 | 다루기 불편 | 자연스러움(프레임별 연결) |
| 토큰 예산 | 작음 | 큼 |

MLP는 단순함과 토큰 유연성에서 이기고, Q-Former는 토큰 예산에서 이깁니다. 2023년 말부터는 토큰 예산이 더 이상 발목을 잡는 제약이 아니었고(LLM 컨텍스트가 32k~128k 이상으로 자랐죠), 단순함이 승부를 결정했습니다.

### 프롬프트 형식

```
A chat between a curious human and an artificial intelligence assistant. The assistant gives helpful, detailed, and polite answers to the human's questions. USER: <image> Describe this image in detail. ASSISTANT: The image shows ...
```

`<image>`는 자리표시자 토큰입니다. 토큰화 전에 시각 토큰 576개(AnyRes면 2880개)로 교체됩니다. 토크나이저는 학습 때보다 조금 긴 시퀀스를 받지만, LLM은 이 낯선 입력을 잘 처리합니다. 스테이지 1이 그걸 가르쳐 줬으니까요.

### 파라미터 경제학

LLaVA-1.5-7B 구성:
- CLIP ViT-L/14 @ 336: 303M (스테이지 1 고정, 스테이지 2에서는 자주 고정 해제).
- 프로젝터(선형 2개): 학습 가능 약 22M.
- Llama-7B: 7B.
- 합계: 73억 개 파라미터. 스테이지 2에서 학습 가능: 전체 7B + 22M 프로젝터.

스테이지 2 학습 비용: 8xA100으로 약 20시간. 여기가 핵심 숫자입니다 — 노드 하나, 하루면 재현 가능. 그래서 LLaVA가 퍼진 겁니다.

```figure
mm-llava-projector
```

## 직접 써보기

`code/main.py`는 다음을 구현합니다:

1. 2층 MLP 프로젝터 (장난감 규모로 차원 16 → 32 → 32), 순수 Python으로.
2. 프롬프트 생성 파이프라인: 시스템 프롬프트 + `<image>`를 N개의 투영 토큰으로 교체 + 사용자 턴 + 어시스턴트 생성 자리표시자.
3. LLM 컨텍스트에서 576토큰짜리 시각 블록이 얼마나 차지하는지 보여주는 시각화(2k / 32k / 128k 컨텍스트에서의 비율).

## 출시하기

이 레슨은 `outputs/skill-llava-vibes-eval.md`를 만들어 냅니다. LLaVA 계열 체크포인트가 주어지면, 10개 프롬프트로 구성된 바이브스 평가(vibes-eval) 스위트(캡셔닝 3, VQA 3, 추론 2, 거절 2)를 돌리고 사람이 읽기 쉬운 스코어카드를 냅니다. 벤치마크가 아니라, 프로젝터와 LLM이 제대로 연결됐는지 확인하는 스모크 테스트입니다.

## 연습 문제

1. `1024 → 4096 → 4096` 크기의 2층 MLP 프로젝터에서 학습 가능 파라미터 수를 계산해 보세요. GELU와 편향을 포함하면 LLaVA-13B 전체의 몇 퍼센트인가요?

2. "거절" 케이스용 LLaVA 프롬프트를 만들어 보세요 — 이미지에 특정 개인이 등장하는 경우입니다. 기대되는 어시스턴트 응답을 작성하세요. LLaVA가 이를 제로샷에서 거절해야 하는 이유는 무엇이고, 거절을 강화하려면 어떤 학습 데이터가 필요할까요?

3. LLaVA-NeXT 블로그의 AnyRes 섹션을 읽어 보세요. 1344x672 이미지의 AnyRes 시각 토큰 수를 계산하고, 336x336에서의 기본 576토큰과 비교하세요.

4. LLaVA의 스테이지 1 프로젝터는 캡션에 대한 LM 손실로 학습됩니다. 스테이지 1을 건너뛰고 바로 스테이지 2(시각 명령 튜닝)로 가면 어떻게 될까요? 답은 Prismatic VLMs 논문의 ablation(arXiv:2402.07865)에서 찾아 인용하세요.

5. LLaVA-Instruct-150k는 GPT-4와 COCO 캡션으로 명령을 생성합니다. 새 도메인(의료 X-ray, 위성 이미지)을 위한 도메인 명령 생성 4단계 데이터 파이프라인을 설명해 보세요. 각 단계에서 무엇이 잘못될 수 있을까요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| 프로젝터(Projector) | "MLP 다리" | ViT 차원을 LLM 차원으로 바꾸는 GELU가 들어간 2층 MLP |
| 이미지 토큰 | "<image> 자리표시자" | 추론 전에 N개의 투영된 시각 토큰으로 교체되는 프롬프트 표식 |
| 시각 명령 튜닝 | "LLaVA 스테이지 2" | GPT-4가 만든 (이미지, 명령, 응답) 삼중항으로 학습 |
| 스테이지 1 정렬 | "프로젝터 사전학습" | ViT와 LLM을 고정하고, 캡션에 대한 LM 손실로 프로젝터만 학습 |
| AnyRes | "멀티 크롭 타일링" | 고해상도 이미지를 타일 그리드로 나누고 각 타일의 시각 토큰을 연결 |
| LLaVA-Instruct | "GPT-4 생성" | COCO 캡션 + GPT-4로 합성한 158k개의 명령-응답 쌍 |
| 비전 인코더 고정 | "백본 잠금" | 스테이지 1에서는 CLIP 가중치를 갱신하지 않고, 스테이지 2에서도 가끔 갱신하지 않음 |
| ShareGPT4V | "더 나은 캡션" | GPT-4V가 생성한 100만 개의 밀도 높은 캡션 데이터셋, 더 좋은 정렬 품질용 |
| VQA | "시각 질의응답" | 이미지에 대한 자유 형식 질문에 답하는 과제 |
| Prismatic VLMs | "설계 공간 논문" | 프로젝터와 데이터 선택을 체계적으로 실험한 Karamcheti 2024 ablation |
