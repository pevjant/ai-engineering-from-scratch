# Emu3: 이미지·비디오 생성을 위한 다음 토큰 예측

> BAAI의 Emu3(Wang 등, 2024년 9월)는 확산(diffusion) 대 자기회귀 논쟁을 끝장내야 했던 2024년의 결과물입니다. 텍스트 + VQ 이미지 토큰 + 3D VQ 비디오 토큰의 통합 어휘 위에서, 다음 토큰 예측 목표만으로 학습한 Llama 스타일 디코더 전용 트랜스포머 하나가, 이미지 생성에서는 SDXL을, 지각에서는 LLaVA-1.6을 이깁니다. CLIP 손실도 없고, 확산 스케줄도 없습니다. 품질을 위해 추론 때 classifier-free guidance를 쓰긴 하지만, 핵심 학습 목표는 teacher forcing을 곁들인 다음 토큰 예측입니다. Nature에 실렸습니다. 이 레슨에서는 Emu3의 테제 — 더 나은 토크나이저와 스케일이면 충분하다 — 를 읽고, 확산 방식과 대조해 봅니다.

**유형:** 학습
**언어:** Python (표준 라이브러리, 3D 비디오 토크나이저 수학 + 자기회귀 샘플러 골격)
**선수 지식:** 페이즈 12 · 11 (Chameleon)
**시간:** 약 120분

## 학습 목표

- "이미지 품질에는 확산이 필요하다"는 오랜 통념에도 불구하고 Emu3의 단일 손실 다음 토큰 목표가 통하는 이유를 설명한다.
- 3D 비디오 토크나이저를 설명한다: 시공간 VQ 코드북의 모습, 패치가 시간까지 덮는 이유.
- Emu3와 Stable Diffusion XL을 (학습 연산량, 추론 비용, 품질 천장) 기준으로 비교한다.
- 같은 Emu3 모델이 맡는 세 가지 역할을 말할 수 있다: Emu3-Gen(이미지 생성), Emu3-Chat(지각), Emu3-Stage2(비디오 생성).

## 문제 상황

2024년까지의 통념: 이미지 생성에는 확산이 필요하다. 논거는 이렇습니다: 이산 이미지 토큰은 디테일을 재구성하기엔 정보를 너무 많이 잃고, 자기회귀 샘플링은 수천 토큰에 걸쳐 오류가 누적된다. Stable Diffusion, DALL-E 3, Imagen, Midjourney가 모두 어떤 형태의 확산을 씁니다. Chameleon(레슨 12.11)은 소규모에서 이 통념을 부분적으로 반박했지만 품질에서 SDXL에는 못 미쳤습니다.

Emu3는 이 논거에 정면으로 맞섰습니다. 주장: 더 나은 시각 토크나이저 + 충분한 스케일 + 다음 토큰 손실 = 지각까지 하는 같은 모델에서 확산을 이기는 이미지 생성.

발표 당시 이 베팅은 논쟁적이었습니다. 2년이 지난 지금, 오픈소스 통합 생성 계열(Emu3, Show-o, Janus-Pro, Transfusion)은 연구의 기본 경로가 됐고, 프로덕션(운영 환경) 프런티어 모델들도 어떤 변형을 쓰는 것으로 보입니다.

## 개념

### Emu3 토크나이저

핵심 재료는 시각 토크나이저입니다. Emu3는 토큰당 8x8 해상도 축소의 자체 IBQ 계열 토크나이저(Inverse Bottleneck Quantizer, SBER-MoVQGAN 계열)를 학습합니다. 512x512 이미지가 코드북 크기 32768에서 64x64 = 4096토큰이 됩니다.

K=8192에서 512x512당 1024토큰인 Chameleon보다 토큰 수는 크지만 토큰당 비용은 쌉니다(작은 코드북 조회, 더 단순한 코덱). 핵심 지표: 재구성 PSNR 30.5dB, 32dB의 Stable Diffusion 연속 잠재 공간과 경쟁할 만합니다.

비디오: 3D VQ 토크나이저가 시공간 패치(4x4x4 픽셀)를 정수 하나로 인코딩합니다. 8 FPS의 4초 클립은 32프레임이고, 256x256에서 공간 4배·시간 4배 축소면 토큰 수는 (256/4) * (256/4) * (32/4) = 64 * 64 * 8 = 32,768개입니다.

토크나이저 품질이 천장입니다. Emu3의 기여는 부분적으로 "우리는 아주 좋은 토크나이저를 학습했다"입니다.

### 단일 손실 학습

Emu3는 목표가 하나입니다: 텍스트 토큰, 2D 이미지 토큰, 3D 비디오 토큰을 아우르는 공유 어휘 위의 다음 토큰 예측. 학습 중 기여도를 균형 맞추려고 가중치에 모달리티별 배율을 곱하지만, 손실 함수는 동일합니다.

다음 믹스로 학습합니다:
- 이미지 생성: `<text caption> <image> image_tokens </image>`
- 이미지 지각: `<image> image_tokens </image> <question> text_tokens`
- 비디오 생성: `<text caption> <video> video_tokens </video>`
- 비디오 지각: 유사한 형태.
- 텍스트 전용: 표준 NTP.

모델은 데이터 분포에서 이미지 토큰을 내놓을 타이밍과 텍스트 토큰을 내놓을 타이밍을 배웁니다. `<image>` 태그 뒤에 이미지 토큰을 예측하는 데서 생성이 자연스럽게 나옵니다.

### Classifier-free guidance와 온도

자기회귀 이미지 생성은 추론 때 classifier-free guidance(CFG)를 쓰면 훨씬 좋아집니다. Emu3가 이걸 씁니다: 두 번 생성하는데, 한 번은 전체 캡션으로, 한 번은 빈 캡션으로 생성한 뒤 로짓을 가이던스 가중치(보통 3.0-7.0)로 섞습니다. 확산이 쓰는 바로 그 CFG 트릭을 자기회귀 설정으로 가져온 겁니다.

온도도 중요합니다: 너무 높으면 아티팩트, 너무 낮으면 모드 붕괴(mode collapse). Emu3가 권하는 온도는 지각 1.0, 이미지 생성 0.8입니다.

### 세 가지 역할, 하나의 모델

Emu3는 기능적으로 구분되는 세 API로 배포되지만, 밑에 깔린 가중치 세트는 하나입니다:

- Emu3-Gen. 이미지 생성. 텍스트 입력, 이미지 토큰 출력.
- Emu3-Chat. VQA와 캡셔닝. 이미지(토큰) 입력, 텍스트 출력.
- Emu3-Stage2. 비디오 생성과 비디오 VQA. 텍스트 또는 비디오 입력, 텍스트 또는 비디오 출력.

과제 전용 헤드가 없습니다. 프롬프트 템플릿만 다를 뿐입니다. 체크포인트도 같습니다.

### 벤치마크

Emu3 논문(2024년 9월)에서:

- 이미지 생성: SDXL을 MJHQ-30K FID에서 이김(5.4 vs 5.6), GenEval 종합(0.54 vs 0.55 — 통계적으로 동률), Deep-Eval 종합은 대등.
- 이미지 지각: VQAv2에서 LLaVA-1.6을 이김(75.1 vs 72.4), MMMU는 대략 필적.
- 비디오 생성: Sora 시대 공개 벤치마크 모델들과 경쟁력 있는 FVD의 4초 클립 품질.

숫자가 항상 이기는 건 아닙니다 — Emu3는 여기서 1점을 내놓고 거기서 1점을 벌죠. 하지만 "다음 토큰 예측이면 충분하다"는 주장은 모달리티 전체에서 방어 가능합니다.

### 연산 비용

Emu3는 70억 파라미터 모델로 약 3천억 멀티모달 토큰으로 학습됐습니다. GPU시간은 대략 Llama-2-7B 사전학습과 비슷합니다(A100급 실리콘 기준 2k-4k GPU년). Stable Diffusion 3 같은 확산 모델도 비슷한 예산으로 학습하지만, 별도의 텍스트 인코더와 더 복잡한 파이프라인이 필요합니다.

추론 때 Emu3는 이미지당 SDXL보다 느립니다: 4096 이미지 토큰을 30 tok/s로 풀면 512x512 이미지당 약 2분, SDXL은 2-5초죠. Speculative decoding과 KV 캐시 최적화가 격차를 좁히지만 닫지는 못합니다. 자기회귀 이미지 생성은 연산이 무겁습니다. 이게 현재의 트레이드오프입니다.

### 왜 중요한가

Emu3의 깊은 기여는 개념적입니다. 다음 토큰 예측이 이미지 생성에서 확산에 필적할 만큼 확장된다면, 통합 모델 경로(손실 하나, 백본 하나, 모든 모달리티)가 실현 가능한 겁니다. 미래 모델은 별도 텍스트 인코더도, 별도 확산 스케줄러도, 별도 VAE도 필요 없습니다. 트랜스포머 하나, 모달리티당 토크나이저 하나, 그리고 스케일.

Show-o, Janus-Pro, InternVL-U가 모두 이 테제 위에 서거나 이 테제에 도전합니다. 2025년까지 중국 연구실(BAAI, DeepSeek)은 미국 연구실보다 이 방향으로 더 공격적으로 발표합니다.

## 직접 써보기

`code/main.py`는 장난감 부품 두 개를 만듭니다:

- 2D vs 3D VQ 토크나이저 개수 계산기: (해상도, 패치, 클립 길이, FPS)가 주어지면 이미지 vs 비디오의 토큰 수를 계산.
- 온도를 곁들인 classifier-free guidance가 있는 자기회귀 이미지 토큰 샘플러.

CFG 구현은 Emu3의 레시피를 따릅니다 — 조건부 로짓과 무조건부 로짓을 가이던스 가중치로 섞습니다.

## 출시하기

이 레슨은 `outputs/skill-token-gen-cost-analyzer.md`를 만들어 냅니다. 생성 제품 사양(이미지 또는 비디오, 목표 해상도, 품질 등급, 지연 시간 예산)이 주어지면, 토큰 수와 추론 비용을 계산하고 Emu3 계열 vs 확산을 골라 줍니다.

## 연습 문제

1. Emu3는 8x8 축소로 512x512 이미지당 4096토큰을 만듭니다. 1024x1024와 2048x2048의 해당 값을 계산하세요. 추론 지연 시간은 어떻게 되나요?

2. Emu3의 비디오 토크나이저에 관한 3.3절을 읽어 보세요. 3D VQ 패치 모양을 설명하고, 왜 8x8x1이 아니라 4x4x4인지 말해 보세요.

3. Classifier-free guidance 가중치 5.0 vs 3.0: 시각적 효과는 무엇인가요? `code/main.py`의 수학을 따라가 보세요.

4. 3천억 토큰의 Emu3-7B 학습 FLOPs를 계산하고 Stable Diffusion 3와 비교하세요. 어느 쪽이 학습이 더 비쌌나요?

5. Emu3는 FID에서 SDXL을 이기지만, 전문 VLM들과 비교한 VQAv2에서는 이기지 못합니다. 통합 손실 접근이 벤치마크마다 전문가 모델과 다른 강점을 보이는 이유를 설명하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| 다음 토큰 예측 | "NTP" | 표준 자기회귀 손실: token[0..i]가 주어지면 token[i+1]을 예측; 토큰화만 되면 모든 모달리티에서 동작 |
| IBQ 토크나이저 | "Inverse bottleneck quantizer" | Chameleon 것보다 큰 코드북(32768+)과 더 나은 재구성을 가진 VQ-VAE의 한 계열 |
| 3D VQ | "시공간 양자화기" | (시간, 행, 열)로 인덱싱되는 코드북; 토큰 하나가 4x4x4 픽셀 큐브를 덮음 |
| Classifier-free guidance | "CFG" | 조건부 로짓과 무조건부 로짓을 가중치 gamma로 섞는 것; 추론 때 이미지 품질을 끌어올림 |
| 통합 어휘 | "공유 토큰" | 텍스트 + 이미지 + 비디오가 모두 같은 정수 공간에서 뽑힘; 모델은 다음에 오는 모달리티가 무엇이든 예측 |
| MJHQ-30K | "이미지 생성 벤치마크" | 3만 개 프롬프트의 Midjourney 품질 벤치마크; Emu3가 여기 FID를 보고 |
