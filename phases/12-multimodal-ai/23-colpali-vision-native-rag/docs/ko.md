# ColPali와 비전 네이티브 문서 RAG

> 전통적인 RAG는 PDF를 텍스트로 파싱하고, 청크로 나누고, 청크를 임베딩하고, 벡터를 저장합니다. 그런데 매 단계가 신호를 잃습니다. OCR은 차트 데이터를 버리고, 청킹은 표의 행을 끊고, 텍스트 임베딩은 그림을 무시합니다. ColPali(Faysse et al., 2024년 7월)는 더 단순한 질문을 던졌습니다: 애초에 왜 텍스트를 추출하는 걸까요? 페이지 이미지를 PaliGemma로 직접 임베딩하고, ColBERT 스타일의 후기 상호작용(late interaction)으로 검색하면, 문서가 가진 레이아웃, 그림, 글꼴, 서식 신호를 모두 남길 수 있습니다. 공개된 벤치마크: 시각적으로 풍부한 문서에서 텍스트-RAG 대비 엔드투엔드 정확도가 20~40% 더 좋습니다. ColQwen2, ColSmol, VisRAG가 이 패턴을 확장했습니다. 이 레슨에서는 비전 네이티브 RAG 테제를 읽고, 작은 ColPali류 인덱서를 만들어 봅니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리, 멀티 벡터 인덱서 + MaxSim 스코어러)
**선수 지식:** Phase 11 (LLM Engineering — RAG basics), Phase 12 · 05 (LLaVA)
**소요 시간:** ~180분

## 학습 목표

- 바이 인코더 검색(문서당 벡터 하나)과 후기 상호작용 검색(문서당 벡터 여러 개)의 차이를 설명할 수 있다.
- ColBERT의 MaxSim 연산과, ColPali가 이를 텍스트 토큰에서 이미지 패치로 일반화한 방식을 설명할 수 있다.
- 작은 ColPali류 인덱서를 만들 수 있다: 페이지 → 패치 임베딩 → 쿼리 단어 임베딩에 대한 MaxSim → 상위 k개 페이지.
- 청구서 / 재무 보고서 사용 사례에서 ColPali + Qwen2.5-VL 생성기와 텍스트-RAG + GPT-4를 비교할 수 있다.

## 문제 상황

PDF에 텍스트-RAG를 쓰면 문서의 대부분을 버리는 셈입니다. 재무 보고서의 3분기 매출 성장은 보통 차트에 있고, 의료 소견서의 발견 사항은 주석 달린 이미지에 있으며, 법률 계약서의 서명 블록은 텍스트가 아니라 레이아웃의 사실입니다.

텍스트-RAG 파이프라인:

1. PDF → OCR / pdftotext로 텍스트 변환.
2. 텍스트 → 300~500토큰 청크.
3. 청크 → 바이 인코더 임베딩(벡터 하나).
4. 사용자 질의 → 임베딩 → 코사인 유사도 → 상위 k개 청크.
5. 청크 + 질의 → LLM.

다섯 단계 모두 손실이 있습니다. 차트는 담기지 않고, 표는 청크에 걸쳐 찢기고, 다단 레이아웃은 납작해지고, 그림 주석은 사라집니다.

ColPali의 해법: OCR을 건너뛰고 페이지 이미지를 직접 임베딩합니다. 검색에 ColBERT 스타일 후기 상호작용을 써서, 질의 시점에 세밀한 패치에 어텐션할 수 있게 하는 것이죠.

## 개념

### ColBERT (2020)

ColBERT(Khattab & Zaharia, arXiv:2004.12832)는 텍스트 검색 방법입니다. 문서당 벡터 하나 대신 토큰당 벡터 하나를 만듭니다. 질의 시점에:

- 질의 토큰들이 자기만의 임베딩을 가집니다(N_q개 벡터).
- 문서 토큰들이 임베딩을 가집니다(N_d개 벡터, 보통 캐시됨).
- 점수 = 질의 토큰 각각에 대해 문서 토큰 전체에서 코사인 유사도 최댓값을 더한 것: Σ_i max_j cos(q_i, d_j).

이것이 MaxSim 연산입니다. 각 질의 토큰이 자신과 가장 잘 맞는 문서 토큰을 "고르고", 최종 점수는 그 합입니다.

장점: 강한 회상률, 단어 수준 의미를 다룹니다. 단점: 문서당 N_d개 벡터로 저장 비용이 큽니다.

### ColPali

ColPali(Faysse et al., arXiv:2407.01449)는 ColBERT 패턴을 이미지에 적용합니다.

- 각 페이지가 PaliGemma(ViT + 언어)로 인코딩되어 패치 임베딩이 됩니다: 페이지당 N_p개 벡터.
- 사용자 질의(텍스트) 각각이 질의 토큰 임베딩으로 인코딩됩니다: N_q개 벡터.
- 점수 = Σ_i max_j cos(q_i, p_j), 즉 질의-텍스트-토큰과 페이지-이미지-패치 사이의 MaxSim.
- 총점 기준 상위 k개 페이지를 검색합니다.

문서 수집 시: 모든 페이지를 PaliGemma로 임베딩해 모든 패치 임베딩을 저장합니다. 질의 시점: 질의 토큰을 임베딩해 저장된 모든 페이지 임베딩과 MaxSim을 계산하고, 상위 k개 페이지를 돌려줍니다.

장점: 시각적으로 풍부한 문서에서 엔드투엔드로 텍스트-RAG를 20~40% 이깁니다. 각 패치 벡터가 국소 레이아웃과 내용을 담습니다.

단점: 페이지당 N_p 패치 × 4바이트 부동소수점 × D차원 벡터로 저장 공간이 빠르게 늘어납니다. PQ / OPQ 양자화로 완화합니다.

### ColQwen2와 ColSmol

ColQwen2(illuin-tech, 2024~2025)는 PaliGemma를 Qwen2-VL로 바꿨습니다. 더 좋은 베이스 인코더, 더 좋은 검색.

ColSmol은 로컬 / 엣지용 소형 변형입니다. 약 1B 파라미터의 ColSmol 검색기는 소비자용 GPU에서 돌아갑니다.

### VisRAG

VisRAG(Yu et al., arXiv:2410.10594)는 다른 변형입니다. 패치에 MaxSim을 쓰는 대신, 각 페이지를 VLM으로 단일 벡터로 풀링한 뒤 바이 인코더로 검색합니다. 인덱싱이 빠르고 저장이 작지만 회상률은 약합니다.

품질-vs-비용 트레이드오프: 품질은 ColPali, 규모는 VisRAG.

### M3DocRAG

M3DocRAG(Cho et al., arXiv:2411.04952)는 멀티모달 검색을 다중 페이지 다중 문서 추론으로 확장합니다. 문서들에 걸쳐 페이지를 검색하고, VLM에 먹일 다중 페이지 컨텍스트를 구성합니다.

### ViDoRe — 벤치마크

ColPali의 동반 벤치마크입니다. Visual Document Retrieval Evaluation. 재무 보고서, 학술 논문, 행정 문서, 의료 기록, 매뉴얼 과제를 담습니다. 지표는 nDCG@5.

ColPali-v1은 ViDoRe에서 약 80% nDCG@5; 같은 문서의 텍스트-RAG는 약 50~60%입니다.

### 엔드투엔드 RAG 파이프라인

비전 네이티브 RAG라면:

1. 수집: PDF → 페이지 이미지 → PaliGemma 인코딩 → 모든 패치 임베딩 저장.
2. 질의: 사용자 텍스트 → 질의 토큰 임베딩 → 인덱스된 모든 페이지에 MaxSim → 상위 k개 페이지.
3. 생성: 상위 k개 페이지 이미지 + 질의 → VLM(Qwen2.5-VL 또는 Claude) → 답변.

어디에도 OCR이 없습니다. 그림, 차트, 글꼴, 레이아웃이 모두 답변으로 흘러 들어갑니다.

### 저장 공간 산수

페이지당 729개 패치, 128차원 임베딩인 50페이지 재무 보고서:

- ColPali: 50 * 729 * 128 * 4바이트 = 원본 약 18MB, PQ 후 약 4MB.
- 텍스트-RAG: 50청크 * 768차원 * 4바이트 = 약 150kB.

ColPali는 문서당 약 30배 더 많은 저장 공간을 씁니다. 대규모에서는 OPQ / PQ로 약 5~10배까지 줄일 수 있고, 보통은 감수할 만합니다.

### 텍스트-RAG가 여전히 이기는 경우

- 레이아웃 신호가 없는 순수 텍스트 문서(위키 문서, 채팅 로그). 텍스트-RAG가 더 단순하고 저장도 쌉니다.
- 저장 비용이 지배하는 수백만 페이지 규모 아카이브.
- 검색과 함께 추출 가능한 OCR 텍스트를 요구하는 엄격한 규제 요건.

2026년의 그 외 모든 것 — 재무 보고서, 학술 논문, 법률 계약서, 의료 기록, UX 문서 — 에서는 비전 네이티브 RAG가 이깁니다.

## 직접 해보기

`code/main.py`:

- 장난감 패치 인코더: "페이지"(작은 특성 벡터 그리드)를 패치 임베딩 배열로 매핑합니다.
- MaxSim 스코어러: 질의 토큰 임베딩 집합과 페이지 패치 집합 사이의 ColBERT 스타일 점수를 계산합니다.
- 장난감 페이지 5개를 인덱싱하고, 질의 3개를 실행하고, 점수와 함께 상위 k개를 돌려줍니다.

## 연습 문제

1. 페이지당 729개 패치, 128차원 임베딩, 4바이트 부동소수점인 200페이지 연간 보고서입니다. 원본 저장 공간과 PQ 압축(8배) 저장 공간을 계산해 보세요.

2. MaxSim은 Σ_i max_j cos(q_i, p_j)입니다. 이 합이 단순 평균 유사도로는 잡을 수 없는 것은 무엇일까요?

3. ColPali는 페이지를 패치 집합으로 인덱싱합니다. 대신 단어 수준으로 인덱싱하면(ColBERT처럼) 무엇이 바뀔까요? 트레이드오프는?

4. 질의당 지연 시간 예산이 500ms인 100만 페이지 코퍼스의 엔드투엔드 파이프라인을 설계해 보세요. ColQwen2 / VisRAG를 고르고 근거를 들어 보세요.

5. M3DocRAG(arXiv:2411.04952)를 읽어 보세요. 다중 페이지 어텐션 패턴을 설명하고, 단일 페이지 ColPali 검색과 어떻게 다른지 말해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| 후기 상호작용 (Late interaction) | "ColBERT 스타일" | 단일 문서 벡터가 아니라 토큰별/패치별 임베딩 + MaxSim으로 검색 |
| MaxSim | "패치 중 최댓값" | 각 질의 토큰이 가장 유사한 문서 토큰을 고르고, 질의 전체의 합을 구함 |
| 바이 인코더 (Bi-encoder) | "단일 벡터" | 문서당 벡터 하나; 빠르지만 세밀함을 잃음 |
| 멀티 벡터 (Multi-vector) | "문서당 벡터 여러 개" | 문서/페이지당 N_p개 벡터를 저장; 저장 비용은 늘지만 회상률이 좋아짐 |
| 패치 임베딩 (Patch embedding) | "페이지 특성" | VLM 인코더가 이미지 패치마다 만든 벡터, 페이지별로 캐시됨 |
| ViDoRe | "비전 문서 벤치" | 시각 문서 검색을 위한 ColPali의 벤치마크 모음 |
| PQ 양자화 (PQ quantization) | "곱 양자화" | 저장을 약 8배 줄이면서 벡터 유사도를 유지하는 압축 |
