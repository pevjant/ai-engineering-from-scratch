# 오픈 웨이트 VLM 레시피: 실제로 중요한 것

> 2024-2026년 오픈 웨이트 VLM 문헌은 ablation 표의 숲입니다. 애플의 MM1은 이미지 인코더, 커넥터, 데이터 믹스의 13가지 조합을 실험했습니다. Allen AI의 Molmo는 사람이 쓴 상세 캡션이 GPT-4V 증류를 이긴다는 걸 증명했습니다. Cambrian-1은 20개 넘는 인코더 비교를 돌렸습니다. Idefics2는 5축 설계 공간을 정형화했습니다. Prismatic VLMs는 통제된 벤치마크에서 27가지 학습 레시피를 비교했습니다. 그 모든 노이즈 속에서 논문을 넘어 일관되게 유지되는 결과는 소수입니다: 커넥터 아키텍처보다 이미지 인코더가 중요하고, 그 둘보다 데이터 믹스가 더 중요하며, 상세한 인간 캡션이 증류된 합성 데이터를 이긴다는 것. 이 레슨에서는 여러분 대신 그 표들을 읽어 줍니다.

**유형:** 학습 + 실습
**언어:** Python (표준 라이브러리, ablation 표 파서 + 레시피 선택기)
**선수 지식:** 페이즈 12 · 05 (LLaVA 베이스라인)
**시간:** 약 180분

## 학습 목표

- VLM 설계 공간의 다섯 축을 말할 수 있다: 이미지 인코더, 커넥터, LLM, 데이터 믹스, 해상도 스케줄.
- MM1 / Idefics2 / Cambrian-1의 ablation 표를 읽고, 어떤 노브가 주어진 벤치마크를 움직이는지 예측한다.
- 컴퓨팅 예산과 과제 믹스가 주어졌을 때 새 VLM의 레시피(인코더, 커넥터, 데이터, 해상도)를 고른다.
- 같은 토큰 수에서 사람이 쓴 상세 캡션이 GPT-4V 증류를 이기는 이유를 설명한다.

## 문제 상황

오픈 웨이트 VLM은 수백 개가 존재합니다. "괜찮은" 모델과 "최고 수준" 모델 사이 격차의 대부분은 아키텍처가 아닙니다. 데이터, 해상도 스케줄, 인코더 선택입니다. 모델 성능이 기대에 못 미칠 때 어느 노브를 먼저 돌릴지 아는 것만으로 500만 GPU시간짜리 실수를 피할 수 있습니다.

2023년 웨이브(LLaVA-1.5, InstructBLIP, MiniGPT-4)는 캡션 쌍 사전학습 + LLaVA-Instruct-150k로 돌았습니다. 훌륭한 베이스라인이었죠. MMMU 35% 언저리에서 한계에 닿았습니다.

2024년 웨이브(MM1, Idefics2, Molmo, Cambrian-1, Prismatic VLMs)는 전방위 ablation을 돌렸습니다. 결과는 놀랍고도 실용적이었습니다.

## 개념

### 다섯 축의 설계 공간

Idefics2(Laurençon 등, 2024)가 축에 이름을 붙였습니다:

1. 이미지 인코더. CLIP ViT-L/14, SigLIP SO400m/14, DINOv2 ViT-g/14, InternViT-6B. 인코더는 패치 크기, 해상도, 사전학습 목적이 다릅니다.
2. 커넥터. MLP(2-4층), Q-Former(32 쿼리 + 크로스 어텐션), Perceiver Resampler(64 쿼리), C-Abstractor(합성곱 + 이중 선형 풀링).
3. 언어 모델. Llama-3 8B / 70B, Mistral 7B, Phi-3, Gemma-2, Qwen2.5. LLM 크기가 파라미터 비용의 지배 항입니다.
4. 학습 데이터. 캡션 쌍(CC3M, LAION), 인터리브(OBELICS, MMC4), 명령(LLaVA-Instruct, ShareGPT4V, PixMo, Cauldron).
5. 해상도 스케줄. 고정 224/336/448, AnyRes, 네이티브 동적. 학습 중 단계적으로 올리거나 고정.

모든 프로덕션(운영 환경) VLM은 각 축에서 선택을 합니다. MMMU 점수 편차의 대부분은 1, 4, 5번 축으로 설명되지, 어떤 커넥터를 골랐는지가 아닙니다.

### 축 1: 인코더 > 커넥터

MM1의 3.2절이 보여줬습니다: CLIP ViT-L/14를 SigLIP SO400m/14로 바꾸니 MMMU가 3점 이상 올랐습니다. 커넥터를 MLP에서 Perceiver Resampler로 바꾼 것은 1점 미만이었죠. Idefics2도 재현했습니다: 같은 토큰 수에서 SigLIP > CLIP, Q-Former ≈ MLP ≈ Perceiver.

Cambrian-1의 "Cambrian Vision Encoders Match-Up"(Tong 등, 2024)은 20개 넘는 인코더를 비전 중심 벤치마크(CV-Bench)에서 비교했습니다. 리더보드 상위권은 DINOv2와 SigLIP의 혼합이고, CLIP은 중위권, ImageBind와 ViT-MAE는 그 아래입니다. CLIP ViT-L에서 DINOv2 ViT-g/14까지의 격차는 CV-Bench 기준 약 5-7점입니다.

2026년 오픈 VLM의 기본 인코더는 의미적 + 밀집 특성을 위해 SigLIP 2 SO400m/14이며, 때로 DINOv2 ViT-g/14 특성과 연결(concatenate)하기도 합니다(Cambrian의 "Spatial Vision Aggregator"가 정확히 이렇게 합니다).

### 축 2: 커넥터 설계는 효과가 미미하다

MM1, Idefics2, Prismatic, MM-Interleaved 모두 같은 결론에 도달했습니다: 시각 토큰 수를 고정하면 커넥터 아키텍처는 거의 차이를 만들지 않는다. 평균 풀링한 패치 위의 2층 MLP가 같은 토큰 예산의 32쿼리 Q-Former와 1점 이내에서 경합합니다.

진짜 중요한 건 토큰 수입니다. 시각 토큰이 많을수록 = LLM 연산이 많을수록 = 어느 지점까지는 성능이 좋아지고, 그다음엔 수확 체감. 이미지당 64토큰은 OCR에 너무 적습니다. 대부분의 오픈 VLM에서 576-1024토큰이 적정선입니다. 2048+는 문서와 차트에서만 도움이 됩니다.

Q-Former 대 MLP는 품질의 문제가 아니라 비용의 문제입니다: Q-Former는 이미지 해상도와 무관하게 토큰을 32-64로 제한하고, MLP는 모든 패치 토큰을 내보냅니다. 고해상도 입력에서는 Q-Former가 LLM 컨텍스트를 아껴 주고, 저해상도에서는 그 차이가 노이즈 수준입니다.

### 축 3: LLM 크기가 천장을 정한다

LLM을 7B에서 13B로 두 배로 늘리면 모든 VLM 논문에서 MMMU가 안정적으로 2-4점 오릅니다. 70B면 대부분의 벤치마크가 포화됩니다. VLM의 멀티모달 추론 천장은 곧 LLM의 텍스트 추론 천장입니다 — 비전 인코더는 먹이를 줄 뿐, 대신 추론해 주지는 못합니다.

그래서 Qwen2.5-VL-72B와 Claude Opus 4.7이 MMMU-Pro와 ScreenSpot-Pro를 압도하는 겁니다. 언어 두뇌가 거대하기 때문입니다. 7B VLM은 영리한 커넥터 설계로 70B VLM을 대체할 수 없습니다.

### 축 4: 데이터 — 상세한 인간 캡션이 증류를 이긴다

Molmo + PixMo(Deitke 등, 2024)는 모두가 읽어야 하는 2024년의 결과물입니다. Allen AI는 사람 어노테이터에게 1-3분 분량의 밀도 높은 음성-텍스트 변환으로 이미지를 묘사하게 해서 712K개의 밀집 캡션 이미지를 만들었습니다. 학습 데이터 어디에도 GPT-4V 증류가 없습니다.

Molmo-72B는 11개 벤치마크 전부에서 Llama-3.2-90B-Vision을 이겼습니다. 그 격차는 아키텍처가 아닌 캡션 품질에서 나옵니다. 상세한 인간 캡션은 짧은 웹 캡션보다 이미지당 5-10배 많은 정보를 담고, GPT-4V 증류가 환각을 일으키는 지점에서도 사실에 기반합니다.

ShareGPT4V(Chen 등, 2023)와 Cauldron(Idefics2)은 같은 방식을 인간 + GPT-4V 혼합 캡션으로 따라갔습니다. 흐름은 분명합니다: 2026년 프런티어에서는 캡션 밀도 > 캡션 양 > 증류의 편의성.

### 축 5: 해상도와 그 스케줄

Idefics2의 ablation: 384 → 448이면 1-2점. 이미지 분할(AnyRes)과 함께 448 → 980으로 가면 OCR 벤치마크에서 추가로 3-5점. 고정 해상도 학습은 중간 정확도에서 정체되고, 해상도를 점진적으로 올리는 방식(224로 시작해 448 또는 네이티브로 마무리)은 더 빨리 학습하고 더 높은 곳에서 끝납니다.

Cambrian-1은 해상도 vs 토큰 트레이드오프를 다뤘습니다: 고정 연산량에서 저해상도에 더 많은 토큰을 쓰거나, 고해상도에 더 적은 토큰을 쓸 수 있습니다. OCR은 고해상도가 이기고, 일반 장면 이해는 저해상도+많은 토큰이 이깁니다.

2026년 프로덕션(운영 환경) 레시피: 스테이지 1은 384 고정으로, 스테이지 2는 OCR 위주 과제를 위해 최대 1280까지 동적 해상도로.

### Prismatic의 통제 비교

Prismatic VLMs(Karamcheti 등, 2024)는 모든 축을 통제한 논문입니다. 같은 13B LLM, 같은 명령 데이터, 같은 평가 — 한 번에 한 축만 바꿉니다. 결과:

- 이미지당 시각 토큰 수가 편차의 약 60%를 설명.
- 인코더 선택이 약 20%.
- 커넥터 아키텍처가 약 5%.
- 나머지(데이터 믹스, 스케줄러, 학습률)가 남은 약 15%.

대략적인 분해이지만, 문헌에서 "무엇을 먼저 ablation해야 하나"에 대한 가장 깔끔한 답입니다.

### 2026년용 선택기

증거를 종합하면, 2026년 새 프로젝트의 기본 오픈 VLM 레시피는 다음과 같습니다:

- 인코더: 네이티브 해상도의 SigLIP 2 SO400m/14 + NaFlex. 세그멘테이션/그라운딩이 필요하면 밀집 특성용 DINOv2 ViT-g/14를 연결.
- 커넥터: 패치 토큰 위의 2층 MLP. 토큰 제약이 있는 게 아니라면 Q-Former는 건너뛴다.
- LLM: Qwen2.5 / Llama-3.1 / Gemma 2. 비용은 7B, 품질은 70B, 목표 지연 시간으로 선택.
- 데이터: PixMo + ShareGPT4V + Cauldron, 여기에 과제 특화 명령 데이터를 보태기.
- 해상도: 동적 (긴 변 기준 최소 256, 최대 1280 픽셀).
- 스케줄: 스테이지 1 정렬(프로젝터만), 스테이지 2 전체 파인튜닝, 스테이지 3 과제 특화 파인튜닝.

이 기본값 하나하나가 이 레슨 끝에 인용된 논문들의 측정된 ablation으로 거슬러 올라갑니다.

## 직접 써보기

`code/main.py`는 ablation 표 파이자 레시피 선택기입니다. MM1과 Idefics2의 ablation 표(요약본)를 내장하고 다음 질의가 가능합니다:

- "예산 X와 과제 Y가 주어지면 어떤 레시피가 이기나?"
- "7B Llama에서 SigLIP을 CLIP으로 바꾸면 예상 MMMU 변화는?"
- "80% 신뢰도의 답을 얻으려면 어느 축을 먼저 ablation해야 하나?"

출력은 예상 벤치마크 변화와 "먼저 ablation할 축" 추천이 붙은 순위형 레시피 목록입니다.

## 출시하기

이 레슨은 `outputs/skill-vlm-recipe-picker.md`를 만들어 냅니다. 목표 과제 믹스, 컴퓨팅 예산, 지연 시간 목표가 주어지면, 각 선택을 정당화하는 ablation 인용이 붙은 완전한 레시피(인코더, 커넥터, LLM, 데이터 믹스, 해상도 스케줄)를 내놓습니다. 새 VLM 프로젝트가 시작될 때마다 Idefics2 ablation 표를 다시 발명하는 일을 막아 줍니다.

## 연습 문제

1. MM1의 3.2절을 읽어 보세요. 2B LLM, 5천만 이미지 예산이 고정되었을 때 어떤 인코더가 이기나요? 13B LLM이면 답이 뒤집힐까요? 그 이유는?

2. Cambrian-1은 DINOv2 + SigLIP을 연결하면 비전 중심 벤치마크에서 둘 중 하나보다 잘하지만 MMMU에서는 신호가 늘지 않는다고 보고합니다. 어떤 벤치마크가 오르고 어떤 벤치마크가 제자리일지 예측해 보세요.

3. 목표가 2B LLM 기반 모바일 UI 에이전트입니다. 인코더, 커넥터, 해상도, 데이터 믹스를 고르세요. 각 선택을 구체적인 ablation 표로 정당화하세요.

4. Molmo는 4B와 72B 모델을 출시했습니다. 4B는 폐쇄형 7B VLM과 경쟁력이 있고, 72B는 11/11 벤치마크에서 Llama-3.2-90B-Vision을 이깁니다. 이 결과가 LLM 크기 포화 가설에 대해 말해 주는 것은 무엇인가요?

5. 7B VLM에서 데이터 믹스 품질과 인코더 품질을 분리하는 ablation 표를 설계해 보세요. 최소 몇 번의 학습 실행이 필요한가요? 네 가지 축 설정을 제안하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| Ablation | "노브 하나 돌리기" | 다른 조건은 전부 고정하고 설계 공간의 한 축만 다르게 하여 여러 학습을 돌리는 실험 |
| 커넥터(Connector) | "다리" / "프로젝터" | 비전 인코더 출력을 LLM의 토큰 공간으로 보내는 학습 가능 모듈(MLP, Q-Former, Perceiver) |
| 상세 인간 캡션 | "밀집 캡션" | 웹 대체 텍스트보다 풍부한, 사람이 쓴 여러 문장 설명(보통 80-300토큰) |
| 증류(Distillation) | "GPT-4V 캡션" | 더 강한 독점 VLM이 생성한 학습 데이터; 편리하지만 환각을 물려받기 쉬움 |
| AnyRes / 동적 해상도 | "고해상도 경로" | 인코더 기본 해상도보다 큰 이미지를 타일링이나 M-RoPE로 먹이는 전략 |
| 해상도 램프 | "커리큘럼" | 저해상도로 시작해 점차 올리는 학습 스케줄, 정렬 학습을 빠르게 함 |
| 비전 중심 벤치마크 | "CV-Bench / BLINK" | 언어 위주 추론이 아니라 세밀한 시각 지각을 시험하는 평가 |
| PixMo | "Molmo의 데이터" | Allen AI의 712K 밀집 캡션 이미지 데이터셋; 사람의 발화를 밀집 캡션으로 전사 |
