# 옴니 모델: Qwen2.5-Omni와 Thinker-Talker 분리

> 2024년 5월 GPT-4o의 제품 데모가 파괴적이었던 이유는 밑바탕 모델 때문이 아니라 제품의 모양 때문이었습니다 — 말하면 모델이 카메라에 보이는 것을 보고, 250ms 안에 다시 말로 답하는 음성 인터페이스였습니다. 오픈 생태계는 2024년과 2025년 내내 그 제품 표면에 도달하려는 경주를 벌였습니다. Qwen2.5-Omni(2025년 3월)는 참조용 오픈 설계입니다: Thinker(텍스트를 생성하는 큰 트랜스포머)와 Talker(음성을 생성하는 병렬 트랜스포머)를, 스트리밍 음성 토큰으로 연결한 구조죠. Mini-Omni는 이를 단순화했고, Moshi는 그 지연 시간을 따라 잡았고, GLM-4-Voice는 중국어로 확장했습니다. 이 레슨에서는 Thinker-Talker 아키텍처와, 스트리밍 실시간 대화를 가능하게 만드는 지연 시간 예산을 읽어 봅니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리, 스트리밍 파이프라인 지연 시간 시뮬레이터 + VAD 루프)
**선수 지식:** Phase 12 · 19 (audio-LLMs), Phase 12 · 16 (any-to-any)
**소요 시간:** ~180분

## 학습 목표

- 추론 파이프라인을 Thinker(텍스트 추론)와 Talker(음성 합성)로 나누고, 병렬 스트리밍이 왜 통하는지 설명할 수 있다.
- 대화형 상호작용의 첫 오디오 바이트까지 시간(TTFAB) 예산을 구성 요소별로 계산할 수 있다.
- Thinker 안에서 비전, 오디오, 텍스트를 아우르는 TMRoPE의 시간 정렬 위치 인코딩을 설명할 수 있다.
- 세 가지 실시간 대화 패턴의 이름을 꼽을 수 있다: 반이중(half-duplex), 교대(turn-taking), 전이중(full-duplex).

## 문제 상황

실시간 음성 비서는 많은 일을 빠르게 해야 합니다:

1. 사용자의 말을 듣는다. 실시간 음성 토큰화, 그리고 말이 끝났음을 알기 위한 음성 활동 탐지(VAD).
2. 선택적으로 본다. 2~4 FPS 카메라 입력이 오디오와 함께 Thinker로 스트리밍됩니다.
3. 생각한다. 대화 이력을 조건으로 답변을 구성합니다.
4. 말한다. 오디오 토큰을 합성하고, 파형으로 디코딩하고, 사용자의 스피커로 스트리밍합니다.

각 단계가 지연 시간을 더합니다. 대화 느낌에는 총 왕복 500ms 미만이 필요합니다 — 그 아래로 내려가면 사용자는 지연을 인지하지 못합니다. GPT-4o는 ~250ms를, Moshi는 ~160ms를, Qwen2.5-Omni는 ~350~500ms를 주장합니다.

모든 구성 요소가 스트리밍해야 합니다. "전부 모아서 한꺼번에 디코딩"은 불가능합니다.

## 개념

### Thinker와 Talker

Qwen2.5-Omni의 분해:

- Thinker: 7B~80B 텍스트 생성 트랜스포머. 텍스트 + 이미지 + 오디오 토큰이 뒤섞인 것을 소비합니다. 무엇을 말할지를 나타내는 텍스트 토큰을 출력합니다.
- Talker: 더 작은 음성 생성 트랜스포머(200M~1B). Thinker의 텍스트 출력 토큰과 최근 음성 문맥 토큰을 소비합니다. 이산 음성 토큰(잔차 VQ 인덱스)을 출력합니다.
- 음성 디코더: 스트리밍 파형 디코더(SNAC, MoVQGAN 계열)가 음성 토큰을 실시간 오디오 샘플로 바꿉니다.

이 분리가 중요합니다. 좋은 추론을 위해서는 Thinker가 커야 합니다. 반면 Talker는 작아도 됩니다. 할 일이 로컬적이어서입니다 — 텍스트를 음성 토큰으로 바꾸는 것뿐이죠. Talker가 더 크다고 표현력이 좋아지는 게 아니라 느려질 뿐입니다.

둘을 병렬로 돌리면:

1. Thinker가 텍스트 토큰 t_i를 출력합니다.
2. Talker가 (스트리밍으로) t_i를 소비하고 음성 토큰 s_i, s_{i+1}, ..., s_{i+k}를 출력합니다.
3. 음성 디코더는 음성 토큰이 오는 대로 소비해 오디오 샘플을 내보냅니다.
4. Thinker가 텍스트 토큰 t_{i+3}에 도달했을 무렵, Talker는 이미 t_0..t_{i+2}분의 오디오를 스트리밍하고 있습니다.

### TMRoPE — 시간 정렬 멀티모달 위치

Thinker는 이미지 프레임(예: 4 FPS로 도착), 오디오 프레임(초당 50프레임으로 도착), 대화 이력의 텍스트를 통합해야 합니다. 순진한 시퀀스 순서(이미지 전부, 그다음 오디오 전부, 그다음 텍스트)는 시간 정렬을 잃습니다.

TMRoPE는 모든 토큰에 절대 타임스탬프를 부여합니다. t=2.3초의 비전 토큰, t=2.32초의 오디오 토큰, t=2.35초의 사용자 텍스트 토큰 "그만" 같은 식입니다. RoPE가 타임스탬프로 어텐션을 회전하므로, 모델은 이것들을 시간적으로 동시에 일어난 것으로 봅니다.

이것이 "인사하면서 손을 흔든다"가 동작하게 만드는 인프라입니다 — 모델이 비디오 프레임과 오디오를 같은 개념적 시점에서 보는 것이죠.

### 스트리밍 음성 합성

음성 토큰은 반드시 스트리밍해야 합니다. Mini-Omni(Xie & Wu, 2024)가 "언어 모델은 들을 수 있고, 스트리밍으로 생각하면서 말할 수 있다"를 도입했습니다: Thinker의 출력 토큰과 Talker의 출력 토큰이 같은 시퀀스 안에서 인터리브됩니다. Thinker가 다음 텍스트 토큰을 확정하는 즉시 Talker가 발화를 시작합니다. 배치 경계는 없습니다.

Moshi(Défossez et al., 2024년 10월)는 가장 빠른 오픈 구현입니다. A100 한 장에서 160ms TTFAB. 아키텍처는 텍스트와 음성 토큰을 교대 위치에서 출력하는 단일 7B 트랜스포머로, "내적 독백(inner monologue)"이 생각의 스트림과 말하기의 스트림을 분리합니다. 사실상 Thinker + Talker를 신중한 학습으로 한 모델에 융합한 것입니다.

### VAD와 말번대

음성 활동 탐지(VAD)는 입력 쪽에서 돌아갑니다. 두 패턴이 있습니다:

- 반이중: 사용자가 말하면 모델이 듣고, 모델이 말하면 사용자가 듣습니다. VAD 무음 탐지(~200ms)로 명확하게 넘깁니다.
- 전이중: 양쪽이 동시에 말할 수 있습니다. 모델이 끼어들기("음-흠")를 하거나 방해할 수도 있습니다. 훨씬 어렵습니다. Moshi가 이것을 지원합니다.

Qwen2.5-Omni는 기본적으로 반이중이며, 무음 임계값으로 말번대(turn-taking)를 처리합니다. 전이중은 애플리케이션 계층의 처리가 필요합니다.

### Qwen3-Omni (2025년 11월)

후속작입니다. Qwen3-80B Thinker, 더 큰 Talker, 개선된 TMRoPE-v2. 지연 시간은 GPT-4o의 250ms에 근접합니다. 오픈 웨이트. OmniBench 벤치마크에서 Gemini 2.0 Live에 필적합니다.

### 프로덕션 지연 시간 예산

전형적인 스트리밍 상호작용 기준:

- 마이크 → 오디오 토큰: 40~80ms.
- 프리필(프롬프트 + 이력): 7B에서 100~200ms, 70B에서는 훨씬 더.
- Thinker의 첫 텍스트 토큰: 40ms.
- Talker가 첫 텍스트 토큰 처리: 20ms.
- 첫 음성 토큰 확정: 40ms.
- 잔차 VQ 디코드: 30ms.
- 음성 파형 디코드: 50~80ms.

총 TTFAB: 7B에서 320~510ms, 70B에서 600~900ms. 프런티어 품질은 보통 70B 이상을 의미하므로, 프런티어 지연 시간 격차가 생기는 것입니다.

### 토큰 속도 산수

16kHz 음성에서 베이스 음성 토큰이 50Hz라면, 출력 1초당 음성 토큰 50개가 필요합니다. Talker는 따라잡으려면 초당 50토큰 이상을 내보내야 하죠. H100에서 전형적인 LLM 처리량이 초당 30~80토큰이니, 작은(200~300M) Talker는 충분히 빠르지만 7B Talker는 뒤처집니다.

"그냥 본체 모델을 쓰면 되지"가 아니라 작은 전용 Talker 모델이 존재하는 이유가 바로 이것입니다.

```figure
l5-thinker-talker
```

## 직접 해보기

`code/main.py`:

- 목업 토큰 출력 속도로 Thinker-Talker 파이프라인을 시뮬레이션합니다.
- 설정 가능한 모델 크기와 마이크 샘플 레이트에 대한 TTFAB를 계산합니다.
- VAD 무음 임계값을 이용한 반이중 말번대를 시연합니다.

## 출시하기

이 레슨은 `outputs/skill-omni-streaming-budget.md`를 만듭니다. 실시간 음성 제품의 목표 TTFAB와 기능 세트(비전 입력, 이중 언어, 전이중)가 주어지면 Qwen2.5-Omni, Qwen3-Omni, Moshi, Mini-Omni 중 하나를 고르고 Thinker/Talker 크기를 잡아 줍니다.

## 연습 문제

1. 목표 TTFAB가 300ms입니다. 7B Thinker와 300M Talker에서 모든 구성 요소의 지연 시간을 하나하나 적어 보세요.

2. Qwen2.5-Omni는 TMRoPE를 씁니다. 사용자가 t=1초에 말을 시작하고 카메라가 t=1.2초에 제스처를 잡는 프롬프트에서, 모델이 무엇을 보게 되는지 설명해 보세요.

3. 전이중 지원은 듣는 동안 오디오를 출력할 수 있어야 합니다. 이것을 가르칠 학습 데이터 형식을 제안해 보세요.

4. Moshi 논문의 4절을 읽어 보세요. "내적 독백" 분리가 무엇인지, 그리고 왜 Thinker-Talker 분리를 피할 수 있는지 설명해 보세요.

5. 처리량 예산을 계산해 보세요: 초당 50개 베이스 계층 토큰의 16kHz 음성을 따라가려면 Talker는 얼마나 빨라야 할까요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| Thinker | "추론 두뇌" | 무엇을 말할지 만들어 내는 큰 텍스트 생성 트랜스포머 |
| Talker | "음성 생성 입" | Thinker의 텍스트로부터 이산 음성 토큰을 만들어 내는 작은 트랜스포머 |
| TTFAB | "지연 시간 예산" | 첫 오디오 바이트까지 시간: 사용자 발화 종료부터 첫 오디오 샘플 출력까지 |
| TMRoPE | "시간 정렬 RoPE" | 비전, 오디오, 텍스트에 걸쳐 절대 타임스탬프를 쓰는 위치 인코딩 |
| 반이중 (Half-duplex) | "말번대" | 사용자와 모델이 번갈아 말함; VAD 무음 탐지로 사용자 발화 종료 판단 |
| 전이중 (Full-duplex) | "동시 발화" | 모델이 말하면서 동시에 들을 수 있음; 끼어들기(backchannel) 가능 |
| 내적 독백 (Inner monologue) | "Moshi 분리" | 생각의 스트림과 말하기의 스트림이 인터리브되는 단일 모델 설계 |
