# LLaVA-OneVision: 하나의 모델로 단일 이미지·멀티 이미지·비디오까지

> LLaVA-OneVision(Li 등, 2024년 8월) 이전의 오픈 VLM 세계는 갈라진 혈통이었습니다: 단일 이미지용 LLaVA-1.5, Mantis와 VILA 같은 멀티 이미지 모델, Video-LLaVA와 Video-LLaMA 같은 비디오 모델. 각자 자기 벤치마크는 이겨도 다른 쪽은 실패했습니다. LLaVA-OneVision은 하나의 커리큘럼으로 한 모델이 세 시나리오 전부를 지배하게 만들 수 있고, 창발적인 과제 전이 효과(단일 이미지 스킬이 비디오로, 멀티 이미지 추론이 단일 이미지로 넘어감)가 전문가 모델들의 합을 이긴다고 주장했습니다. 레시피는 겉보기에 단순합니다: 시나리오 전체에서 일정하게 유지되는 시각 토큰 예산, 그리고 단일 이미지 → OneVision(멀티 이미지) → 비디오로 이동하는 명시적 커리큘럼. 이 레슨에서는 그 예산과 커리큘럼, 창발 행동을 읽어 봅니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리, 토큰 예산 솔버 + 커리큘럼 플래너)
**선수 지식:** 페이즈 12 · 05 (LLaVA), 페이즈 12 · 06 (모든 해상도)
**시간:** 약 180분

## 학습 목표

- 단일 이미지, 멀티 이미지, 비디오 입력 전체에서 일정하게 유지되는 시각 토큰 예산을 설계한다.
- 치명적 망각(catastrophic forgetting) 없이 단일 이미지 스킬을 비디오로 전이시키는 학습 커리큘럼 순서를 짠다.
- 커리큘럼을 제대로 짜면 같은 파라미터 수의 전문가 모델들을 단일 모델이 이기는 이유를 설명한다.
- LLaVA-OneVision이 보고한 세 가지 창발 능력을 말할 수 있다: 멀티 카메라 추론, set-of-mark 프롬프팅, 아이폰 스크린샷 에이전트.

## 문제 상황

이미지, 멀티 이미지, 비디오는 각각 모델을 다르게 압박합니다.

단일 이미지는 고해상도 토큰(AnyRes, 시각 토큰 약 2880개)을 원합니다. OCR과 잔디 같은 디테일을 잡아야 하니까요. 샘플당 예산: 이미지 한 장, 2880토큰.

멀티 이미지는 중간 해상도(이미지당 약 576토큰)의 이미지 여러 장을 원합니다. 이미지들 사이 추론이 컨텍스트 안에 들어가야 하니까요. 샘플당 예산: 이미지 4-8장, 각 576토큰, 총 2300-4600토큰.

비디오는 낮은 해상도(풀링 후 프레임당 약 196토큰)의 많은 프레임을 원합니다. 시간적 동학(temporal dynamics)을 포착해야 하니까요. 샘플당 예산: 프레임 8-32개, 각 196토큰, 총 1600-6200토큰.

모델을 따로 학습하면 예산 하나를 고르면 됩니다. 모델 하나로 학습하려면, 컨텍스트를 초과하지 않으면서 시나리오마다 예산이 합리적으로 늘어나야 합니다.

OneVision 이전의 기본 답은 "한 시나리오만 학습하고 나머지는 무시"였습니다. Video-LLaVA는 이미지 모델에 학습 스테이지를 추가해 비디오를 덧붙였고, LLaVA-NeXT는 타일링으로 멀티 이미지를 지원했습니다. 셋 전부를 깔끔하게 처리한 모델은 없었습니다.

## 개념

### OneVision 토큰 예산

LLaVA-OneVision은 샘플당 약 3000-4000토큰의 통합 시각 토큰 예산을 고르고, 시나리오마다 다르게 배분합니다:

- 단일 이미지: AnyRes-9 (3x3 타일 + 썸네일), 타일 하나가 384 해상도에 729 패치, 공격적인 2x2 이중 선형 풀링 → 타일당 182. 합계: 9 * 182 + 182 = 1820토큰. 또는 타일당 729인 AnyRes-4 = 2916 + 729.
- 멀티 이미지: 각 이미지가 중간 해상도(384, 타일링 없음), 풀링 없이 729토큰. 이미지 6장 → 4374토큰.
- 비디오: 384 해상도의 32프레임에 공격적인 3x3 이중 선형 풀 → 프레임당 81토큰. 합계: 32 * 81 = 2592토큰.

이 배분은 대략 일정한 총 토큰 수를 유지합니다. LLM은 컨텍스트를 초과하는 배치를 받은 적이 없죠. 인코더는 시나리오마다 다른 기하 구조를 만들지만, LLM은 같은 예산을 소비합니다.

### 3단계 커리큘럼

LLaVA-OneVision은 세 단계로 학습합니다:

1. 단일 이미지 SFT(스테이지 SI). 모든 데이터가 단일 이미지 + 텍스트입니다. 고해상도 AnyRes 입력으로 학습합니다. 지각, OCR, 세밀한 이해를 가르치는 단계죠. LLaVA-NeXT 데이터에 OneVision 전용 단일 이미지 데이터를 더해 사용합니다.
2. OneVision SFT(스테이지 OV). 단일 이미지 + 멀티 이미지 + 비디오(균등 샘플 프레임)를 섞습니다. 통합 토큰 예산으로 학습합니다. 이질적인 배치 모양을 다루는 법을 가르치는 거죠. 가중치 초기화 없이 — 스테이지 SI에서 이어갑니다.
3. 과제 전이(스테이지 TT). 목표 과제 믹스로 계속 학습합니다. 제품에 따라 멀티 이미지나 비디오 비중을 늘리는 식이죠. 배포용 파인튜닝은 선택 사항입니다.

중요한 점: 커리큘럼 순서가 중요합니다. 비디오 우선이나 멀티 이미지 우선으로 학습하면 같은 데이터를 써도 단일 이미지 우선보다 이미지 성능이 나빠집니다. 논문이 이걸 명시적으로 ablation했습니다.

### 커리큘럼이 통하는 이유

단일 이미지 학습이 지각의 기반을 만듭니다. 패치 토큰이 세밀한 시각 특성을 담고, LLM이 그것을 텍스트와 통합하는 법을 배웁니다. 멀티 이미지와 비디오는 구조적 도전(어느 이미지가 어느 것인지, 무엇이 먼저 일어났는지)을 던지는데, 튼튼한 지각 기반이 없으면 배우기 어렵습니다.

모든 시나리오를 처음부터 함께 학습시키면, 모델은 지각을 과소적합하고(배치당 단일 이미지 데이터가 제한됨) 구조를 과적합합니다(멀티 이미지/비디오 데이터가 많으니까). 결과: 이미지 사이 추론 패턴은 따르지만 시각적으로는 얕은 모델이 됩니다.

커리큘럼 순서는 스테이지 SI에서 지각의 힘을, 스테이지 OV에서 구성적/시간적 추론을 주고, 어느 쪽도 잃지 않게 해 줍니다.

### 창발하는 시나리오 간 스킬

LLaVA-OneVision 논문은 세 가지 창발 능력을 보고합니다:

1. 멀티 카메라 추론. 멀티 이미지 + 비디오를 따로따로 학습했는데, 추론 때 멀티 카메라 주행 장면에 대해 추론하라고 요청하면 학습에서 정확히 그 형식을 본 적이 없음에도 시야를 올바르게 통합합니다.
2. Set-of-mark 프롬프팅. 사용자가 이미지 속 객체에 번호 매긴 표시를 남기면, 모델은 "표시 3이 표시 7에 비해 뭐 하고 있나"를 추론합니다. 표시도 어노테이션도 학습한 적 없지만, 공간 그라운딩 + 멀티 이미지 참조의 조합에서 배웠습니다.
3. 아이폰 스크린샷 에이전트. 사용자가 아이폰 화면 스크린샷을 주고 다음 클릭을 계획해 달라고 합니다. UI 스크린샷, 사용자 워크플로 비디오, 멀티 이미지 전/후 쌍으로 학습했고, 에이전트 사용 사례로 일반화됩니다.

이건 학습된 과제가 아닙니다. 커리큘럼의 구성적 구조에서 창발한 겁니다.

### 시각 토큰 풀링

토큰 예산에는 풀링이 필요합니다. OneVision은 2D 패치 그리드에 이중 선형 보간을 씁니다: 24x24 = 576 패치가 12x12 = 144(2배 축소) 또는 8x8 = 64(3배 축소)로 줄어듭니다. 지역성(locality)을 보존하기 위해 풀링은 토큰 공간이 아니라 패치 그리드 공간에서 이뤄집니다.

시나리오별 풀링 비율 선택 자체가 하이퍼파라미터입니다. 풀링이 약할수록 = 토큰이 많을수록 = 표현이 풍부해집니다. 풀링이 강할수록 = 토큰이 적을수록 = 더 많은 프레임/이미지가 들어갑니다.

### LLaVA-OneVision-1.5

2025년 후속작(LLaVA-OneVision-1.5, arXiv 2509.23661)은 학습 데이터, 모델 가중치, 코드가 "완전 공개"입니다. 일부 벤치마크에서 독점 모델 격차를 따라잡고 레시피를 대중화했습니다. 같은 커리큘럼, 더 많은 데이터, 더 나은 베이스 LLM. 아키텍처 변화는 없습니다.

### Qwen2.5-VL과의 대조

Qwen2.5-VL(레슨 12.09)은 다른 선택을 합니다. 고정 풀링 대신 M-RoPE와 동적 FPS를 씁니다. 예산이 입력에 따라 늘어납니다 — 1분짜리 비디오가 5초짜리보다 더 많은 토큰을 쓰죠. LLaVA-OneVision은 예산을 고정하고 풀링을 조절합니다. 둘 다 통합니다. 설정 가능성과 예측 가능성을 맞바꾼 차이입니다.

## 직접 써보기

`code/main.py`는 OneVision 스타일 VLM을 위한 커리큘럼·예산 플래너입니다. 샘플당 토큰 예산과 목표 시나리오 믹스(예: 단일 이미지 40%, 멀티 이미지 30%, 비디오 30%)가 주어지면:

- 시나리오별 해상도, 풀링 비율, 프레임 수를 배분합니다.
- 모든 시나리오가 공유 예산 안에 드는지 확인합니다.
- 예상 토큰 수, LLM FLOPs, 토큰이 부족한 시나리오를 보고합니다.
- 스테이지별 학습 스케줄을 출력합니다.

OneVision 파인튜닝을 계획하거나 VLM 배포의 요청당 비용을 검산할 때 쓰세요.

## 출시하기

이 레슨은 `outputs/skill-onevision-budget-planner.md`를 만들어 냅니다. 목표 과제 분포와 샘플당 예산이 주어지면, AnyRes 배율, 프레임당 풀링, 비디오 프레임 수, 커리큘럼 스테이지 가중치를 내놓습니다. 통합 시나리오 VLM을 학습하거나 파인튜닝할 때마다 사용하세요.

## 연습 문제

1. 제품이 단일 이미지 80%, 멀티 이미지 10%(2-4장), 비디오 10%(8-16프레임)를 지원합니다. 토큰 예산을 설계하세요. 멀티 이미지에 큰 예산을 쓰지 않아 남는 예산은 어디에 배치할 건가요?

2. LLaVA-OneVision 4.3절(창발 능력)을 읽어 보세요. 커리큘럼이 열어줄 것 같은데 논문이 보고하지 않은 네 번째 창발 스킬을 제안해 보세요.

3. 커리큘럼 순서를 바꿔 보세요 — 멀티 이미지 먼저, 그다음 단일 이미지, 그다음 비디오. 어떤 벤치마크가 나빠질지, 왜 그런지 예측하세요.

4. 논문은 샘플당 8프레임만으로 학습한 비디오 벤치마크를 보고합니다. 추론 때 30초 비디오로 일반화될까요? 먼저 깨지는 건 토큰 예산일까요, 시간적 추론일까요?

5. 24x24 패치를 12x12로 이중 선형 풀링하면 각 차원에서 4배 축소입니다(역주: 원문 표현 그대로). 표준 라이브러리 Python으로 풀링을 구현하고, 각 2x2 블록의 평균이 이중 선형 출력과 일치하는지 확인하세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| OneVision 시나리오 | "단일 이미지, 멀티 이미지, 또는 비디오" | 통합 VLM이 다루는 세 입력 모양 중 하나; 예산은 그 전체에서 일정하게 유지됨 |
| 토큰 예산 | "샘플당 토큰이 몇 개" | 학습/추론 샘플 하나에 LLM이 보는 총 시각 토큰 수, 보통 3000-4000 |
| 커리큘럼 | "학습 순서" | 창발적 전이를 위해 고른 스테이지 순서(단일 이미지 → 멀티 이미지 → 비디오) |
| 이중 선형 풀링 | "토큰 축소" | 지역성을 보존하면서 토큰 수를 줄이기 위해 패치 그리드(2D)에 이중 선형 보간을 적용 |
| 창발 스킬 | "학습 안 했는데도 됨" | 커리큘럼 구성 덕에 학습 데이터와 맞지 않아도 추론 때 나타나는 능력 |
| AnyRes-k | "k타일 구성" | 고정 해상도의 k개 서브 타일 + 썸네일 하나, 보통 k ∈ {4, 9} |
| 과제 전이 | "시나리오 간 일반화" | 공유 백본 덕에 단일 이미지에서 배운 스킬이 비디오에(그 반대도) 적용되는 것 |
