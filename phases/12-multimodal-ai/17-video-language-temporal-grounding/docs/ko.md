# 비디오-언어 모델: 시간적 토큰과 그라운딩

> 비디오는 사진을 쌓아 놓은 것이 아닙니다. 5초짜리 클립에는 인과적 순서, 동작 동사, 이벤트의 시점이 있고, 이미지 모델은 이를 표현할 수 없습니다. Video-LLaMA(Zhang et al., 2023년 6월)는 음향-시각 접지를 갖춘 최초의 오픈 비디오-LLM을 내놓았습니다. VideoChat과 Video-LLaVA가 이 패턴을 확장했고, 2025년에는 Qwen2.5-VL의 TMRoPE가 프런티어 독점 모델과의 격차를 메웠습니다. 각 시스템은 시간적 토큰을 서로 다르게 해결했습니다 — 클립마다 Q-former, 프레임마다 concat-pool, 토큰마다 TMRoPE. 이 레슨에서는 이 패턴들을 읽고, 균등 샘플러 vs 동적 샘플러를 만들어 보며, 시간적 그라운딩 과제로 평가해 봅니다.

**유형:** 빌드
**언어:** Python (표준 라이브러리, 프레임 샘플러 + 시간적 그라운딩 평가기)
**선수 지식:** Phase 12 · 08 (LLaVA-OneVision)
**소요 시간:** ~180분

## 학습 목표

- 시간적 위치 인코딩이 비전 인코더와 무관하게 비디오 VLM 성능을 바꾸는 이유를 설명할 수 있다.
- 초당 토큰 수 대 그라운딩 정확도 관점에서 균등 샘플링, 동적 FPS, 이벤트 기반 샘플링을 비교할 수 있다.
- 클립당 Q-former(Video-LLaMA) vs 프레임당 풀링(Video-LLaVA) vs 토큰당 M-RoPE(Qwen2.5-VL) 설계를 설명할 수 있다.
- 네 가지 비디오 벤치마크의 이름을 꼽을 수 있다: VideoMME, TempCompass, EgoSchema, Video-MMMU.

## 문제 상황

30 FPS의 1분짜리 비디오는 1800프레임입니다. 프레임당 196개의 시각 토큰(224 크기 ViT-B 기준)이라면 352k 토큰 — 2024년 당시 어떤 LLM 컨텍스트보다도 큽니다.

축소 전략은 세 가지가 있습니다:

1. 프레임을 서브샘플링한다(콘텐츠에 따라 1~8 FPS).
2. 각 프레임의 패치 토큰을 공격적으로 풀링한다(3x3 또는 4x4 이중 선형 풀).
3. Q-former로 압축한다: 16프레임 클립을 받아 64토큰을 출력.

각각의 트레이드오프는 다릅니다. 서브샘플링은 시간적 디테일을 잃고, 풀링은 공간적 디테일을 잃으며, Q-former는 둘 다 조금씩 잃는 대신 토큰을 절약합니다.

시간적 위치 인코딩은 또 다른 축입니다. 모델은 어떻게 5번 프레임이 6번 프레임보다 앞선다는 걸 알까요? 선택지로는 단순 1D 시간 RoPE(Video-LLaMA), 학습된 시간 임베딩(Video-LLaVA), TMRoPE(Qwen2.5-VL, 완전한 3D)가 있습니다.

## 개념

### Video-LLaMA: 클립당 Q-former + 오디오 브랜치

Video-LLaMA(2023)는 최초의 오픈 비디오-LLM이었습니다. 아키텍처:

- 2 FPS로 16프레임 클립(즉 8초).
- 프레임별 ViT 특성 → 16프레임 전체를 크로스 어텐션하는 비디오 Q-former → 학습된 32개 쿼리 → LLM.
- 병렬 오디오 브랜치: 파형 → ImageBind 오디오 인코더 → 오디오 Q-former → 32개 쿼리 → LLM.

강점: 음향-시각 공동 추론. 약점: 고정된 클립 길이, 임의 시점 그라운딩 불가.

### VideoChat과 Video-LLaVA

VideoChat은 Video-LLaMA의 아이디어를 유지하되 오디오를 빼고 단순화했습니다. Video-LLaVA(Lin et al., 2023)는 이미지와 비디오 프레임 모두에 단일 비전 인코더를 학습시켜("projection 이전에 정렬(alignment)") 통합된 표현을 만들었습니다. 둘 다 "고정 CLIP 인코더 + MLP + LLM" 구성입니다.

어느 쪽도 긴 비디오는 다루지 못합니다. 둘 다 8~16프레임 시스템입니다.

### Qwen2.5-VL과 TMRoPE

Qwen2.5-VL은 TMRoPE — 시간-모달리티 회전 위치 임베딩(Temporal-Modality Rotary Position Embedding) — 를 도입했습니다. 각 패치 토큰은 (t, h, w) 위치를 가지며, t는 프레임 인덱스가 아니라 실제 타임스탬프입니다.

단순 시간 임베딩과의 핵심 차이:

- 인덱스가 아닌 절대 시간. 모델은 "15번 프레임에서"가 아니라 "4.2초 시점에"를 봅니다.
- 클립 단위가 아닌 토큰 단위 회전. 각 시각 토큰이 자기 타임스탬프로 독립적으로 회전합니다.
- 동적 FPS와 호환. 어디선가 2 FPS, 어디선가 4 FPS로 샘플링해도 TMRoPE는 고르지 않은 간격을 기본적으로 처리합니다.

TMRoPE 덕분에 "고양이가 몇 초에 뛰어내리나요?" 같은 질의가 가능합니다. 모델이 "4.2초에"라고 답할 수 있죠. Video-LLaMA는 "클립 초반에"라고밖에 말할 수 없었습니다.

### 프레임 샘플링 전략

균등(uniform): 전체 재생 시간에 걸쳐 N프레임을 고르게 샘플링. 간단하지만 움직임의 피크를 놓칩니다.

동적 FPS: 움직임 강도에 따라 적응적으로 샘플링. 광학 흐름(optical flow)이나 프레임 차분으로 움직임이 많은 구간을 골라 더 촘촘히 샘플링합니다. Qwen2.5-VL이 이 방식으로 학습합니다.

이벤트 기반: 가벼운 탐지기를 돌려서, 동작이 일어나는 곳을 더 많이 샘플링. VideoAgent가 사용합니다.

키프레임 + 문맥: 샷 경계에서 샘플링 + 인접 프레임 몇 개. 영화적 콘텐츠에 사용합니다.

### 프레임당 풀링

1 FPS, 프레임당 576토큰이면 5분짜리 클립이 172,800토큰입니다. Qwen2.5-VL-72B의 128k 컨텍스트로 처리할 수는 있지만 비쌉니다.

3x3 이중 선형 풀을 쓰면 프레임당 64토큰으로 줄어 5분에 19,200토큰입니다. 대부분의 과제에서 가장 적절한 지점(sweet spot)입니다.

공간 디테일이 덜 중요한 에이전트 워크플로라면 더 공격적으로 풀링합니다(6x6 → 프레임당 16토큰).

### 네 가지 비디오 벤치마크

- VideoMME: 포괄적인 비디오 이해, 짧은 + 중간 + 긴 영상.
- TempCompass: 세밀한 시간적 추론, "이전" / "이후" 질문.
- EgoSchema: 긴 시야(long-horizon) 1인칭 비디오.
- Video-MMMU: 멀티모달 다분야 비디오 질문.

제대로 된 비디오-VLM 평가는 넷 모두를 다룹니다. 강조하는 축이 다릅니다 — TempCompass는 순서, EgoSchema는 3분 이상 추론, VideoMME는 재생 시간 범위를 담당합니다.

### 그라운딩 출력 형식

시간적 그라운딩의 출력 형식:

- 자유 텍스트: "고양이는 4초 무렵에 뜁니다." 파싱은 쉽지만 부정확합니다.
- 구조화된 JSON: `{"event": "jump", "start": 4.1, "end": 4.3}`. Qwen2.5-VL이 이 형식으로 학습합니다.
- 토큰 기반: 답과 섞어서 `<time>4.1</time>` 같은 특수 토큰 사용. Qwen2.5-VL의 내부 형식.

다운스트림 활용에는 토큰 기반이 가장 정확합니다. Qwen2.5-VL의 JSON 출력 형식은 그대로 파싱됩니다.

### 2026년의 모범 사례

2026년의 비디오 VLM이라면:

- 인코더: M-RoPE 또는 TMRoPE를 적용한 SigLIP 2 (Qwen2.5-VL).
- 프레임 샘플링: 최대 프레임 상한을 두고 동적 FPS(움직임에 따라 1~4).
- 프레임당 풀링: 3x3 이중 선형.
- 출력: 시간 + 이벤트 필드를 가진 구조화된 JSON.
- 벤치마크: 일반용으로 VideoMME + TempCompass; 긴 시야용으로 EgoSchema.

## 직접 해보기

`code/main.py`에는 다음이 포함됩니다:

- 균등 샘플러와 동적 FPS 샘플러.
- 장난감 시간적 그라운딩 평가기: 시각 T에 "정답" 이벤트와 모델 출력이 주어지면 허용 오차 안에서 정확도를 채점.
- Video-LLaMA(16프레임, Q-former), Video-LLaVA(8프레임, MLP), Qwen2.5-VL(동적 FPS + TMRoPE)의 비교.

## 출시하기

이 레슨은 `outputs/skill-video-vlm-frame-planner.md`를 만듭니다. 비디오 과제(모니터링, 동작 인식, 시간적 그라운딩, 요약)가 주어지면 프레임 샘플러, 풀링 배율, 출력 형식, 기대 정확도 등급을 골라 줍니다.

## 연습 문제

1. 3분짜리 요리 데모에는 균등 샘플링과 동적 FPS 중 무엇을 고를까요? 토큰 수로 근거를 들어 보세요.

2. TMRoPE가 단순 시간 임베딩 테이블로는 할 수 없는 것을 구체적으로 어떻게 추가할까요?

3. VLM이 학습해서 내놓을 수 있는 시간적 그라운딩 JSON 스키마를 작성해 보세요. 오류 사례도 포함합니다.

4. Video-LLaVA의 3절 "Alignment Before Projection"을 읽어 보세요. 이미지 인코더와 비디오 인코더를 따로 학습시키는 것보다 왜 더 나을까요?

5. VideoMME 리더보드에서 2026년 현재 최고 오픈 모델과 최고 독점 모델의 격차는 얼마인가요? 그 격차 중 시간적 인코딩 탓과 베이스 LLM 규모 탓은 각각 어느 정도일까요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| 시간적 그라운딩 (Temporal grounding) | "시간으로 찍어 주는 답" | VLM이 이벤트가 일어나는 구체적 타임스탬프 구간을 출력하는 것 |
| TMRoPE | "Time-Multimodal RoPE" | 절대 타임스탬프를 쓰는 3D 회전 위치. Qwen2.5-VL이 사용 |
| 동적 FPS (Dynamic FPS) | "움직임 인지 샘플링" | 움직임이 많은 구간은 프레임을 더 많이, 정적인 구간은 더 적게 샘플링 |
| 프레임 풀링 (Frame pooling) | "프레임별 공간 압축" | LLM 이전에 이중 선형 보간으로 프레임당 패치 수를 줄이는 것 |
| 비디오 Q-former (Video Q-former) | "클립 압축기" | N개 프레임을 학습된 K개 쿼리로 매핑하는 크로스 어텐션 병목 |
| VideoMME | "비디오 벤치" | 짧은/중간/긴 비디오를 아우르는 포괄 벤치마크, 2500+ 샘플 |
