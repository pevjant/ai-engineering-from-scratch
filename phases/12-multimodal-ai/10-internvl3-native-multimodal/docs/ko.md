# InternVL3: 네이티브 멀티모달 사전학습

> InternVL3 이전의 모든 오픈 VLM은 같은 3단계 레시피를 따랐습니다: 조 단위 텍스트 토큰으로 학습된 텍스트 LLM을 가져오고, 비전 인코더를 덧붙인 다음, 이음새를 파인튜닝합니다. 되긴 하지만 정렬 부채(alignment debt)가 생깁니다 — 텍스트 LLM은 사전학습 예산 전부를 순수 텍스트에 썼기 때문에 시각 토큰을 태생적으로 이해하지 못합니다. 비전을 사후에(post-hoc) 붙이면, LLM은 텍스트를 잊지 않으면서 시각 입력과 자기 텍스트 추론의 관계를 다시 배워야 하죠. InternVL3(Zhu 등, 2025년 4월)는 이 사후 접근을 거부합니다: 사전학습 한 번, 첫 스텝부터 텍스트와 멀티모달을 섞어서 돌립니다. 그 결과 78B 파라미터 오픈 모델이 MMMU-Pro에서 Gemini 2.5 Pro와 필적합니다. 이 레슨에서는 네이티브 사전학습의 논거와, 그걸 택하면 무엇이 달라지는지 읽어 봅니다.

**유형:** 학습
**언어:** Python (표준 라이브러리, 학습 코퍼스 믹서)
**선수 지식:** 페이즈 12 · 05, 페이즈 12 · 07 (레시피)
**시간:** 약 120분

## 학습 목표

- 사후(post-hoc) VLM 학습이 정렬 부채를 쌓는 이유를, 측정 가능한 세 증상(치명적 망각, 답변 드리프트, 시각-텍스트 불일치)을 들어 설명한다.
- InternVL3의 네이티브 사전학습 코퍼스 믹스를 설명하고, 텍스트 : 인터리브 : 캡션 비율이 왜 중요한지 말한다.
- V2PE(가변 시각 위치 인코딩)를 Qwen2-VL의 M-RoPE와 비교한다.
- Visual Resolution Router(ViR)와 Decoupled Vision-Language(DvD) 배포 최적화를 말할 수 있다.

## 문제 상황

사후 VLM 학습이 기본값입니다. LLaVA, BLIP-2, Qwen-VL, Idefics — 전부 이미 사전학습된 LLM(Llama, Vicuna, Qwen, Mistral)을 가져다 비전을 붙입니다. 학습 스테이지는 대체로 이렇습니다:

1. 고정 LLM + 고정 비전 인코더 + 학습 가능 프로젝터를 캡션 쌍으로 학습해 임베딩을 정렬.
2. LLM 고정을 풀고 명령 데이터(LLaVA-Instruct, ShareGPT4V)로 학습.
3. 선택 사항인 과제 특화 파인튜닝.

정렬 부채의 세 증상이 나타납니다:

- 치명적 망각. 사후 VLM은 텍스트 전용 스킬을 잊습니다. GSM8K 점수가 5-10점 떨어집니다. Hellaswag 점수도 떨어집니다. 순수 텍스트 에이전트는 퇴보합니다.
- 답변 드리프트. 같은 시각 질문의 사소한 표현 변화가 다른 답을 냅니다. 비전 인코더가 LLM에 연결된 결합이 LLM 자기 토큰보다 약한 겁니다.
- 시각-텍스트 불일치. VLM은 이미지를 올바르게 묘사해 놓고, 자기 묘사와 모순되는 답을 질문에 줄 수 있습니다. 시각 토큰은 텍스트처럼 LLM의 내적 일관성 검사에 참여하지 못합니다.

이 증상들은 잘 문서화돼 있습니다. MM1.5의 4절이 수치로 보여주고, LLaVA-OneVision의 ablation도 암시합니다. 네이티브 사전학습이 해답입니다.

## 개념

### 네이티브 멀티모달 사전학습

InternVL3는 첫 스텝부터 네이티브 멀티모달인 코퍼스로 처음부터 학습합니다. 믹스는:

- 40% 텍스트 전용 데이터 (FineWeb, Proof-Pile-2 등)
- 35% 인터리브 이미지-텍스트 데이터 (OBELICS, MMC4 스타일)
- 20% 이미지-캡션 쌍 데이터
- 5% 비디오-텍스트 데이터

시각 토큰, 텍스트 토큰, 교차 모달 상호작용이 모두 첫 그래디언트 스텝부터 같은 손실에 참여합니다. 정렬 사전학습도, 프로젝터 고정 스테이지도, 회복해야 할 치명적 망각도 없습니다.

학습은 베이스 모델 기준 단일 스테이지입니다. 명령 튜닝이 뒤따르지만, 베이스 모델은 이미 시각 토큰을 1급 시민으로 이해하고 있습니다.

### V2PE (가변 시각 위치 인코딩)

Qwen2-VL은 축 배분이 고정된 M-RoPE를 씁니다. InternVL3는 V2PE를 도입했습니다: 위치 인코딩이 모달리티 타입(텍스트, 이미지, 비디오)별로 다르고, 스케일링을 학습합니다. 실제로는:

- 텍스트 토큰은 1D 위치(텍스트 인덱스)를 받는다.
- 이미지 패치는 2D 위치(행, 열)를 받는다.
- 비디오 프레임은 3D 위치(시간, 행, 열)를 받는다.

셋이 같은 RoPE 주파수 기저를 공유하지만, 밴드별 히든 차원 배분은 고정 분할이 아니라 학습되는 파라미터입니다. 사전학습 중 시간 주파수 해상도와 공간 주파수 해상도의 균형을 스스로 조절할 수 있는 자유죠.

V2PE의 ablation 주장: 같은 연산량에서 M-RoPE보다 비디오 벤치마크 1-2점. 혁명은 아니지만 더 깔끔합니다.

### Visual Resolution Router (ViR)

배포 최적화입니다. 모든 이미지가 풀 해상도 인코딩이 필요한 건 아닙니다. 저디테일 객체 하나 있는 사진을 1280px 네이티브로 인코딩하면 토큰 낭비죠. ViR은 인코딩 전에 질문에 답하는 데 필요한 최소 해상도를 예측하는 작은 분류기입니다.

라우팅은 세 등급입니다: 저해상도(256토큰), 중간(576), 고해상도(2048+). 프로덕션(운영 환경) 트래픽 질문의 60%는 저/중간이면 충분합니다. 순 효과: 같은 품질에서 2-3배 처리량.

### Decoupled Vision-Language 배포 (DvD)

큰 VLM을 서빙할 때 비전 인코더는 이미지당 한 번 도는데, LLM은 출력 토큰마다 자기회귀적으로 돕니다. 두 구성 요소는 병목이 다릅니다(비전 = 합성곱 + 어텐션의 GPU 메모리 대역폭; LLM = KV 캐시). DvD는 둘을 별도 GPU로 나누고 사이에 스트리밍을 둡니다.

8B + 4억 인코더 모델 기준으로 DvD는 같은 노드 배치(co-located) 대비 노드당 처리량을 약 두 배로 만듭니다.

### 단일 스테이지 vs 다중 스테이지 품질

InternVL3의 대표 벤치마크 주장: 78B 파라미터에서 Gemini 2.5 Pro의 MMMU-Pro와 필적. 38B에서는 GPT-4o와 필적. 8B에서는 오픈 8B 리더보드 선두. 전부 단일 스테이지 사전학습 + 명령 튜닝 레시피로 달성합니다.

정렬 부채 가설은 측정 가능합니다: InternVL3-8B는 비전 벤치마크 이득 단위당 MMLU, GSM8K 같은 텍스트 벤치마크 손실이 Qwen2.5-VL-7B보다 적습니다. 학습이 둘로 쪼개진 게 아니라 한 덩어리였기에, 이 모델은 더 범용주의자입니다.

### InternVL3.5와 InternVL-U

InternVL3.5(2025년 8월)는 레시피를 확장합니다. 같은 네이티브 사전학습 방식에, 더 많은 데이터, 더 많은 파라미터. MMMU 개선은 점진적입니다.

InternVL-U(2026)는 통합 생성을 추가합니다 — 같은 백본 위에 MMDiT 헤드로 이미지 출력을 냅니다. "U"는 "Understanding + generation"(이해 + 생성)의 U로, Transfusion 스타일 통합 모델(레슨 12.13)을 좇습니다. 같은 네이티브 사전학습 백본이 이해 헤드와 생성 헤드를 모두 지지합니다.

### 네이티브 사전학습의 트레이드오프

네이티브 사전학습은 공짜가 아닙니다:

- 연산. 새 VLM을 처음부터 학습하면 텍스트 LLM 학습과 같은 비용이 듭니다 — 수백만 GPU시간. 사후 적응은 기존 LLM 가중치를 재사용해 대부분의 비용을 아낍니다.
- 데이터. 규모 있는 인터리브 이미지-텍스트 코퍼스는 희귀합니다. OBELICS는 1억 4100만 문서, MMC4는 5억 7100만. 텍스트만은 15조 토큰으로 나오죠. 멀티모달 사전학습 데이터의 희소성은 단단한 제약입니다.
- 베이스 LLM 재사용. 네이티브 사전학습은 나중에 새 LLM을 끼워 넣는 선택지를 포기합니다. 사후 방식은 어댑터만 재학습해서 Llama-3.1을 Llama-4로 바꿀 수 있죠.

InternVL3가 거는 베팅: 정렬 부채가 재사용 상실보다 더 나쁘다는 것. 벤치마크가 그 주장을 뒷받침합니다. 만드는 비용이 뒤따르는 연구실들의 값싼 복제를 막습니다. 사후 VLM은 대부분의 프로젝트에서 여전히 더 저렴하니 계속 존재할 겁니다.

## 직접 써보기

`code/main.py`는 학습 코퍼스 믹서이자 ViR 라우터 시뮬레이터입니다. 이 코드는:

- 목표 코퍼스 믹스(%텍스트, %인터리브, %캡션, %비디오)를 받아 모달리티별 예상 스텝 수를 계산합니다.
- 질문 배치(분포: 저디테일 50%, 중간 30%, 고디테일 20%)에 ViR 라우팅을 시뮬레이션하고 평균 토큰 수를 보고합니다.
- 인코더 vs LLM FLOPs가 주어지면 DvD 처리량 추정치를 보고합니다.
- 사후 vs 네이티브 사전학습을 파라미터, 연산, 데이터, 예상 정렬 부채 증상 기준으로 나란히 출력합니다.

## 출시하기

이 레슨은 `outputs/skill-native-vs-posthoc-auditor.md`를 만들어 냅니다. 제안된 VLM 학습 계획이 주어지면, 네이티브로 갈지 사후로 갈지 감사(audit)하고, 정렬 부채 위험을 표시하며, 코퍼스 믹스를 권합니다. 새 오픈 VLM 프로젝트 크기를 잡고 학습 전략을 골라야 할 때 사용하세요.

## 연습 문제

1. InternVL3-8B(네이티브 사전학습)와 LLaVA-OneVision-7B(사후) 사이 연산 차이를 추정해 보세요. GPU시간 비율은 대략 얼마인가요? 그 격차를 설명하는 것은 무엇인가요?

2. InternVL3는 텍스트 40% / 인터리브 35% / 캡션 20% / 비디오 5%를 보고합니다. 목표 과제가 비디오 위주라면 새 비율을 제안하고, 베이스 모델이 여전히 상당한 텍스트와 캡션 데이터가 필요한 이유를 논증하세요.

3. MM1.5의 망각에 관한 4절을 읽어 보세요. 사후 학습이 가장 큰 퇴보를 보인 벤치마크의 정확한 이름을 말하세요. 그 퇴보의 비용은 얼마였나요?

4. ViR은 트래픽의 60%를 저해상도 인코딩으로 보냅니다. 어떤 종류의 질문을 잘못 라우팅할까요(고해상도가 필요한데 저해상도로 보내는 경우)? 라우터 실패 모드 세 가지를 제안하세요.

5. DvD는 비전과 LLM을 별도 GPU로 나눕니다. 어떤 트래픽 패턴에서 DvD는 도움이 아니라 처리량을 해치나요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| 네이티브 멀티모달 사전학습 | "처음부터 함께" | 텍스트 + 이미지 + 비디오 토큰이 나중에 덧붙여지는 게 아니라 스텝 1부터 손실에 참여 |
| 정렬 부채(alignment debt) | "사후 패널티" | 고정 LLM에 비전을 덧붙여서 생기는, 측정 가능한 텍스트 스킬·답변 일관성 퇴보 |
| V2PE | "가변 시각 위치 인코딩" | 모달리티별 학습 가능한 위치 인코딩 배분; InternVL3의 M-RoPE 후속 |
| ViR | "해상도 라우터" | 인코딩 전에 질문별 최소 필요 해상도를 골라 추론 토큰을 아끼는 작은 분류기 |
| DvD | "분리 배포" | 비전 인코더는 한 GPU에, LLM은 다른 GPU에 두고 스트림으로 넘기는 방식; 큰 VLM의 처리량을 두 배로 |
| InternVL-U | "통합 이해 + 생성" | 네이티브 사전학습 백본에 이미지 생성 헤드를 더한 2026년 후속작 |
| 인터리브 코퍼스 | "OBELICS / MMC4" | 텍스트와 이미지가 자연 독서 순서로 섞인 문서; 네이티브 사전학습의 원료 |
