대화형 제품(음성 입력 / 음성 출력, 선택적으로 비전, 선택적으로 음악), 모델 크기, 목표 지연 시간이 주어지면, any-to-any 설계를 감사(audit)하고 실현 가능한 구성을 산출합니다.

산출물:

1. 모달리티 믹스. 어떤 모달리티가 들어오고 나가는지. 계열 선택: MIO / AnyGPT(이산 토큰, 4모달리티), Moshi(음성+텍스트 중심, 내적 독백), Unified-IO 2(비전 풍부).
2. 공유 어휘 계획. 텍스트 + 이미지 + 음성 + 음악 + 구분자의 ID 구간. 총 크기는 보통 40~50k.
3. 토크나이저 스택. BPE + SEED + SpeechTokenizer-RVQ + Encodec. 어느 것이 여전히 병목인지 표시(보통 음성 품질).
4. 학습 커리큘럼. 4단계 MIO 레시피, 또는 음성 중심인 Moshi용 2단계.
5. TTFAB 지연 시간 예산. 마이크 인코더 + 프리필 + 첫 토큰 + 잔차 디코드 + 음성 디코더. 약 500ms 대화 기준 바와 비교.
6. 품질-지연 시간 파레토. 낮은 지연 시간에는 작은 모델, 높은 품질에는 큰 모델; A100/H100 기준 대략적인 수치.

하드 리젝(무조건 거부):

- 대화 유창성이 요구 사항인데 모달리티마다 별도 모델을 제안하는 것. 파이프라인 지연 시간이 누적되어 체감이 더 나빠집니다.
- 코드북 계층이 1개뿐인 음성 토크나이저를 쓰는 것. 어떤 프로덕션 보이스든 품질이 기계적으로 들립니다.
- MIO의 TTFAB가 GPT-4o와 맞먹는다고 주장하는 것. 아직 아닙니다; Moshi의 160ms가 가장 가까운 오픈 수치입니다.

거부 규칙:

- 목표 TTFAB가 200ms 미만이라면 MIO급(8B 이상)을 거부하고 Moshi급(7B, 음성에 특화 튜닝) 또는 더 작은 음성 전문 모델을 추천합니다.
- 스튜디오급 음성 출력을 원한다면 오픈 잔차 VQ를 거부하고, 오픈 품질이 따라잡을 때까지(Qwen3-Omni / Moshi2) ElevenLabs / 체인 TTS를 추천합니다.
- 음성 통화 중 이미지 생성을 원한다면 스트리밍 음성 우선 설계를 거부하고, 모드 전환이 있는 분할 파이프라인을 제안합니다.

출력: 모달리티 믹스, 어휘 계획, 토크나이저 스택, 커리큘럼, TTFAB 지연 시간, 품질-지연 시간 파레토를 담은 한 페이지짜리 감사 보고서. 마지막에 arXiv 2409.17692 (MIO), 2410.00037 (Moshi), 2402.12226 (AnyGPT)를 인용할 것.
