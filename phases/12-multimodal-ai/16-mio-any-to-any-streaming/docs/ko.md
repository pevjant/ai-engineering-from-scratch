# MIO와 Any-to-Any 스트리밍 멀티모달 모델

> GPT-4o는 오픈 모델이 따라 하기 어려운 제품을 내놓았습니다. 음성을 듣고, 영상을 보고, 실시간으로 말로 답하는 에이전트입니다. 2024년 말 오픈 생태계의 답이 MIO(Wang et al., 2024년 9월)였습니다. MIO는 텍스트, 이미지, 음성, 음악을 토큰화하고, 뒤섞인 시퀀스 전체에 걸쳐 하나의 인과적(causal) 트랜스포머를 학습시키며, 어떤 모달리티든 어떤 모달리티로든 생성합니다. AnyGPT(Zhan et al., 2024년 2월)가 개념 증명이었고, MIO가 그 규모 확장이며, Unified-IO 2(Allen AI, 2023년 12월)는 비전 + 행동 접지를 얹은 사촌 격입니다. 이 레슨에서는 any-to-any 패턴 — 네 개의 토크나이저, 하나의 트랜스포머, 스트리밍 친화적 디코딩 — 을 읽어 봅니다.

**유형:** 학습
**언어:** Python (표준 라이브러리, 4모달리티 토큰 할당기 + 스트리밍 디코드 루프)
**선수 지식:** Phase 12 · 11 (Chameleon), Phase 6 (Speech and Audio)
**소요 시간:** ~120분

## 학습 목표

- 텍스트, 이미지, 음성, 음악 토큰을 충돌 없이 담을 수 있는 공유 어휘(vocabulary)를 설계할 수 있다.
- SEED-Tokenizer(이미지)와 SpeechTokenizer 잔차 VQ(음성)를 압축률과 재구성의 트레이드오프 관점에서 비교할 수 있다.
- any-to-any 생성을 단계적으로 완성시키는 4단계 커리큘럼을 설명할 수 있다.
- 세 가지 오픈 any-to-any 레시피와 각각의 주요 트레이드오프를 꼽을 수 있다: MIO, AnyGPT, Unified-IO 2.

## 문제 상황

통합 멀티모달 모델은 입으로는 쉽게 말할 수 있지만 규모 있게 만들기는 어렵습니다. 2024년까지의 대부분 "any-to-any" 시스템은 파이프라인 방식이었습니다. 비전 모델 → 텍스트 표현 → 음성 모델 → 오디오 순으로 잇는 방식이죠. 홉(hop)을 거칠 때마다 정보가 손실되고, 지연 시간이 늘어나고, 학습도 복잡해집니다. GPT-4o의 데모 영상은 1초 미만의 응답으로 이를 대체할 단일 모델 방식을 보여 주었고, 오픈 시스템은 그로부터 몇 달 뒤처져 있었습니다.

공학적 과제들은 이렇습니다:

- 모든 모달리티마다 토크나이저가 존재해야 하고, 재구성에 충분할 만큼 손실이 적어야 하며, 트랜스포머가 소화할 수 있는 속도로 토큰을 만들어 냅니다.
- 하나의 어휘가 텍스트(32k 이상), 이미지(16k 이상), 음성(4k 이상), 음악(8k 이상) 공간을 배분해야 합니다. 최소 4만 개가 넘는 항목이 필요하죠.
- 학습 데이터가 모든 입력-출력 쌍(텍스트→이미지, 이미지→음성, 음성→이미지 등)을 커버하거나, 모델이 그 조합을 스스로 구성(compose)할 수 있어야 합니다.
- 추론은 대화 지연 시간(첫 오디오 바이트까지 500ms 미만)을 맞출 만큼 빠르게 출력 토큰을 스트리밍해야 합니다.

## 개념

### 네 모달리티, 네 토크나이저

MIO의 토크나이저 스택:

- 텍스트: 표준 BPE, 어휘 약 32000.
- 이미지: SEED-Tokenizer(2023) — 이산 코드북을 가진 양자화 VAE, 4096개 항목, 이미지당 32x32 토큰.
- 음성: SpeechTokenizer 잔차 VQ(2023) — 16kHz 파형을 8개의 계층적 코드북으로 인코딩. 첫 계층은 대략적인 내용을 담고, 이후 계층들이 운율과 화자 정체성을 더합니다.
- 음악: 유사한 잔차 VQ(Meta의 MusicGen / Encodec 계열), 4~8개 코드북.

각 모달리티는 정수 토큰을 만들어 냅니다. 토큰들은 공유 어휘 안에서 서로 겹치지 않는 ID 구간을 배정받습니다:

```
text:   0..31999
image:  32000..36095  (4096 image tokens)
speech: 36096..40191  (4096 speech base tokens, plus residual layers)
music:  40192..48383  (8192 music tokens)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, etc.)
```

총 약 48k 어휘입니다. 입력 임베딩과 출력 프로젝션은 이 전체를 모두 포괄합니다.

### 스트리밍 디코드

음성 생성은 잔차 VQ를 사용합니다. 트랜스포머가 베이스(0계층) 음성 토큰을 예측하면, 병렬 디코딩되는 잔차 양자기(residual quantizer)가 이후 계층들을 예측합니다. 0계층 토큰 하나는 16kHz 기준 대략 50ms 분량의 오디오입니다.

스트리밍 패턴은 이렇습니다:

1. 사용자가 마이크로 말하면, 실시간 오디오 토크나이저가 50ms마다 음성 토큰을 만들어 냅니다.
2. MIO는 토큰이 도착하는 대로 소비합니다(프롬프트 프리필 + 증분 순전파).
3. 출력 토큰은 생성되는 대로 흘러나가고, 병렬 음성 디코더가 이를 약 50~150ms 지연으로 오디오 샘플로 변환합니다.
4. 첫 오디오 바이트까지 시간: MIO 논문 기준 약 300~500ms로, GPT-4o의 약 250ms에 근접합니다.

Mini-Omni(arXiv:2408.16725), GLM-4-Voice(arXiv:2412.02612), Moshi(arXiv:2410.00037)는 상호 보완적인 스트리밍 음성-LLM 설계입니다. 특히 Moshi는 GPU 한 장으로 160ms 왕복을 달성합니다.

### 4단계 커리큘럼

MIO의 학습 커리큘럼:

1. 1단계 — 정렬(alignment). 대규모 모달리티 쌍 말뭉치: 텍스트-이미지, 텍스트-음성, 텍스트-음악. 각 쌍은 자기만의 어휘 구간을 사용합니다. 공유 어휘를 학습시키는 단계죠.
2. 2단계 — 인터리브. 모달리티가 뒤섞인 문서(이미지 + 영상이 들어간 블로그, 전사본이 있는 팟캐스트 등). 모달리티 간 문맥을 학습시킵니다.
3. 3단계 — 음성 강화. 텍스트 능력을 잃지 않으면서 음성 품질을 끌어올리는 추가 오디오 데이터.
4. 4단계 — SFT. 모달리티 전반에 걸친 지시문 튜닝: VQA, 캡셔닝, 내레이션, 음성 대 음성 대화.

한 단계라도 빠지면 특정 능력이 떨어집니다. 2단계를 건너뛰면 모달리티 간 문맥을 잃고, 3단계를 건너뛰면 음성 품질이 나빠집니다.

### 시각적 사고 연쇄(chain-of-visual-thought)

MIO는 시각적 사고 연쇄를 도입했습니다. 모델이 추론 단계로 중간 이미지 토큰을 내놓는 것이죠. "고양이가 나무를 타고 있나요?"라는 질문에 모델은:

1. 장면을 그려내는 `<image>` 토큰을 출력합니다(입력 이미지에서 따오거나 스케치 형태로).
2. 그 스케치를 분석하는 텍스트를 출력합니다.
3. 최종 답을 출력합니다.

그려진 중간 이미지는 메모장(scratchpad) 역할을 합니다. 공간 추론 과제에서 벤치마크 점수가 올라갑니다. 텍스트 추론의 사고 연쇄(chain-of-thought)를 그대로 거울처럼 반영한 아이디어입니다.

### any-to-any의 경쟁자들

- AnyGPT(arXiv:2402.12226): 4개 모달리티(텍스트, 이미지, 음성, 음악), 유사한 설계.
- Unified-IO 2(arXiv:2312.17172): 비전 행동 출력, 깊이, 노멀까지 추가. 과제 다양성은 넓지만 규모는 작음.
- NExT-GPT(arXiv:2309.05519): LLM + 모달리티별 디퓨전 디코더. 단일 모델 방식은 아님.
- CoDi(arXiv:2305.11846): 조합 가능한 디퓨전; 공유 잠재 공간을 통한 any-to-any.

MIO는 순수 토큰 기반 any-to-any에 가장 가까운 모델입니다. AnyGPT는 그 개념적 조상입니다.

### 지연 시간 예산

대화형 제품이라면 모든 구성 요소의 지연 시간이 중요합니다:

- 마이크에서 오디오 토큰까지: ~50ms.
- 프리필(오디오 토큰 + 대화 이력): 8B 모델 기준 ~100ms.
- 첫 출력 토큰: ~50ms.
- 병렬 잔차 VQ + 음성 디코더: ~100~150ms.

첫 오디오 바이트까지 총 시간: 최소 ~300ms. GPT-4o는 ~250ms를 주장하고, Moshi는 160ms를 주장합니다. 공개 벤치마크 기준 MIO/AnyGPT는 400~600ms 범위입니다.

### any-to-any가 여전히 어려운 이유

2026년인 지금도 오픈 any-to-any 모델은 두 축에서 폐쇄 모델을 따라갑니다:

- 음성 품질. 잔차 VQ 토크나이저는 손실이 있어서, 대화 음성이 ElevenLabs급 목소리에 비해 기계적으로 들립니다.
- 모달리티 간 추론. 모델에게 "보이는 것에 대해 노래해 줘"라고 하면 순수 비전 과제보다 실패 빈도가 여전히 높습니다.

둘 다 열려 있는 연구 과제입니다. Qwen3-Omni(레슨 12.20)가 2025년 가장 진보된 오픈 시도입니다.

## 직접 해보기

`code/main.py`:

- 4모달리티 어휘 배분을 정의하고 출력합니다.
- 멀티모달 입력 목록(텍스트, 이미지, 오디오 클립, 음악)을 토크나이저 라우터로 보냅니다.
- 텍스트-투-스피치 응답의 스트리밍 디코드를 지연 시간 카운트와 함께 시뮬레이션합니다.
- 인코더, 프리필, 디코더 지연 시간으로부터 기대되는 첫 오디오 바이트 시간을 계산합니다.

## 연습 문제

1. 여러분의 제품이 음성 입력을 받아 음성 출력을 돌려줍니다. 엔드투엔드 지연 시간 예산 목표는 얼마로 잡아야 할까요? 시간을 소모하는 구성 요소들을 나열해 보세요.

2. SpeechTokenizer 잔차 VQ는 코드북 8개를 씁니다. 잔차 계층을 순차가 아닌 병렬로 디코딩해야 하는 이유와, 그로 인한 지연 시간 절감을 설명해 보세요.

3. 여러분의 어휘가 텍스트 32k + 이미지 4k + 음성 4k입니다. 여기에 음악 8k와 구분자 약 10개를 추가합니다. 은닉 차원 4096일 때 임베딩 행렬의 파라미터 비용은 얼마일까요?

4. 시각적 사고 연쇄는 중간 이미지를 출력합니다. 어떤 종류의 질문이 이득을 보고, 어떤 종류는 추가 토큰 때문에 오히려 손해를 볼까요?

5. Moshi(arXiv:2410.00037)를 읽어 보세요. "inner monologue(내적 독백)" 기법을 설명하고, MIO의 시각적 사고 연쇄와 비교해 보세요.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| Any-to-any | "멀티모달 입출력" | 텍스트, 이미지, 음성, 음악을 어떤 방향으로든 받고 낼 수 있는 단일 모델 |
| 잔차 VQ (Residual-VQ) | "음성 토크나이저 스택" | 계층마다 정보를 더해 가는 다중 코드북 토큰화. 베이스 계층은 내용, 이후 계층은 운율 |
| SEED-Tokenizer | "이미지 코드" | MIO가 쓰는 4096항목 코드북의 이산 이미지 토크나이저 |
| 시각적 사고 연쇄 (Chain-of-visual-thought) | "시각 메모장" | 최종 답 전에 추론 단계로 중간 이미지를 생성하는 것 |
| 첫 오디오 바이트까지 시간 (Time-to-first-audio-byte) | "TTFAB" | 사용자 발화에서 첫 오디오 출력까지의 지연 시간. 대화 느낌에는 500ms 미만 필요 |
| 4단계 커리큘럼 | "학습 레시피" | 정렬 → 인터리브 → 음성 강화 → SFT, 순서대로 진행 |
