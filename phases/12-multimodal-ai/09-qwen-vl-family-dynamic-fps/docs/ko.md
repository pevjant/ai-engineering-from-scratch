# Qwen-VL 계열과 동적 FPS 비디오

> Qwen-VL 계열 — Qwen-VL(2023), Qwen2-VL(2024), Qwen2.5-VL(2025), Qwen3-VL(2025) — 은 2026년 가장 영향력 있는 오픈 비전-언어 모델 혈통입니다. 세대마다 단 하나의 결정적인 아키텍처 베팅을 했고, 오픈 생태계는 12개월 안에 그것을 베껴 갔습니다: M-RoPE를 통한 네이티브 동적 해상도, 절대 시간 정렬이 있는 동적 FPS 샘플링, ViT의 윈도우 어텐션, 구조화된 에이전트 출력 형식. Qwen3-VL에 이르면 레시피가 안정됐습니다: 네이티브 가로세로비 입력을 받는 2D-RoPE-ViT 인코더, 큰 Qwen3 언어 베이스로 들어가는 MLP 프로젝터, OCR·그라운딩·에이전트 행동을 1급 목표로 삼은 학습 스테이지. 이 레슨에서는 이 계열을 연대기 순으로 읽어서, 모든 노브가 왜 지금 자리에 있는지 이해하게 합니다.

**유형:** 학습
**언어:** Python (표준 라이브러리, M-RoPE 인코더 + 동적 FPS 샘플러)
**선수 지식:** 페이즈 12 · 06 (patch-n'-pack)
**시간:** 약 120분

## 학습 목표

- M-RoPE의 3축 회전(시간, 높이, 너비)을 계산하고, 왜 세 축이 모두 필요한지 설명한다.
- 비디오에 맞는 동적 FPS 샘플링 전략을 고르고, 초당 토큰 수 vs 이벤트 감지 정확도의 관계를 추론한다.
- Qwen-VL의 네 세대 업그레이드를 순서대로 말하고, 각각이 무엇을 가능하게 했는지 설명한다.
- Qwen2.5-VL 스타일의 JSON 에이전트 출력 형식을 조립하고, VLM 응답에서 구조화된 도구 호출을 파싱한다.

## 문제 상황

Qwen-VL은 2023년 8월 LLaVA-1.5와 BLIP-2에 대한 직접적인 대응으로 출시됐습니다. Qwen 팀이 겨냥한 격차는 세 가지였습니다: 해상도, 비디오, 구조화된 출력.

해상도: LLaVA-1.5는 336x336으로 돌았습니다. 사진엔 괜찮지만 중국어 청구서나 빽빽한 스프레드시트 스크린샷엔 무용지물이죠. Qwen-VL의 첫 혁신은 448x448과 그라운딩 바운딩 박스 출력이었습니다. 모델이 물건을 가리킬 수 있게 된 거죠.

비디오: Video-LLaMA는 프레임별 인코더를 쌓아 LLM에 넣었습니다. 짧은 클립엔 통했지만, 시간축 자체가 신호인 몇 분짜리 비디오엔 통하지 않았습니다. Qwen 팀은 시간을 이해하는 단일 인코더를 원했습니다.

구조화된 출력: LLaVA는 자유 형식 텍스트를 내놨습니다. 에이전트에는 JSON이 필요합니다. Qwen-VL은 바운딩 박스 좌표를 텍스트로 포함하는 명시적 JSON 출력 형식으로 학습했습니다.

Qwen-VL의 모든 세대는 이 세 축 중 하나를 확장합니다.

## 개념

### Qwen-VL (2023년 8월)

1세대: 인코더로 OpenCLIP ViT-bigG/14(25억 파라미터), LLaMA 호환 Q-Former(256 쿼리 1단계), Qwen-7B 베이스. 기여:

- 448x448 해상도(당시 오픈 VLM 최고 수준).
- 그라운딩: 좌표 토큰 출력이 명시된 이미지-텍스트 쌍으로 학습. "The cat is at <box>(112, 204), (280, 344)</box>".
- 처음부터 중국어 + 영어 다국어 학습.

당시 벤치마크: 영어에서 GPT-4V와 경쟁력, 중국어에서 압도. 진짜 헤드라인은 그라운딩 감독이었습니다.

### Qwen2-VL (2024년 9월) — M-RoPE와 네이티브 해상도

Qwen2-VL은 고정 해상도 + Q-Former 스택을 네이티브 동적 해상도 ViT 인코더로 교체했습니다. 핵심 변화:

- 네이티브 동적 해상도. ViT는 28로 나누어 떨어지는 어떤 HxW도 받아들입니다(패치 14에 2배 공간 병합). 1120x672(병합된 패치 40x24) 이미지는 시각 토큰 960개를 만듭니다. 리사이즈도, 타일링도, 썸네일도 없습니다.
- M-RoPE(멀티모달 RoPE). 각 토큰이 1차원 대신 3차원 위치 (t, h, w)를 가집니다. 이미지는 t=0, 비디오는 t = 프레임 인덱스. RoPE가 축마다 주파수로 쿼리/키 벡터를 회전시킵니다. 위치 임베딩 테이블이 필요 없습니다.
- MLP 프로젝터. Q-Former를 버리고 병합된 패치 토큰 위에 2층 MLP를 사용.
- 동적 FPS 비디오. 비디오는 기본 1-2 FPS로 샘플링하지만, 모델은 임의의 프레임 수를 받아들입니다.

결과: Qwen2-VL-7B가 여러 멀티모달 벤치마크에서 GPT-4o에 필적했고 DocVQA에서는 이겼습니다(94.5 vs 88.4). 아키텍처 변경이 결정타였습니다.

### Qwen2.5-VL (2025년 2월) — 동적 FPS + 절대 시간

Qwen2.5-VL의 큰 변화는 비디오였습니다. 동적 FPS는 단순히 "필요하면 프레임을 더 뽑아라"가 아닙니다. 논문이 정식화했습니다:

- 절대 시간 토큰. 위치 인덱스(프레임 0, 1, 2...) 대신 실제 타임스탬프를 씁니다. "0:04에 고양이가 뛰어 올라간다." 모델은 프레임 토큰 사이에 `<time>0.04</time>` 토큰을 끼워 넣은 형태로 봅니다.
- 동적 FPS. 느린 영상은 1 FPS, 액션은 4+ FPS로 샘플링. 사용자나 학습자가 고르며, M-RoPE가 맞춰 줍니다.
- ViT의 윈도우 어텐션. 처리량을 위해 공간 어텐션을 윈도우(블록 내 지역)로 제한하고, 몇 층마다 전역 어텐션을 넣습니다.
- 명시적 JSON 출력 형식. 도구 호출 데이터로 학습: "{\"tool\": \"click\", \"coords\": [380, 220]}". 개봉 즉시 에이전트 준비 완료.
- MRoPE-v2 스케일링. 위치가 최대 입력 크기에 맞춰 스케일되어, 10분짜리 비디오가 주파수 범위를 다 써버리는 일이 없습니다.

벤치마크: Qwen2.5-VL-72B는 대부분의 비디오 벤치마크에서 GPT-4o를 이기고, 문서에서는 Gemini 2.0에 필적하며, GUI 그라운딩의 오픈 모델 SOTA를 세웁니다(ScreenSpot: 84% 정확도 vs GPT-4o의 38%).

### Qwen3-VL (2025년 11월)

Qwen3-VL은 재창조가 아니라 정착시키는 점진적 업그레이드입니다: 더 큰 LLM 백본(Qwen3-72B), 확장된 학습 데이터, 개선된 OCR, Qwen3 "생각 모드"를 통한 강화된 추론. ViT와 M-RoPE는 그대로입니다. 논문은 아키텍처보다 데이터와 학습 개선에 초점을 맞춥니다.

계열의 교훈: 2025년까지 Qwen-VL 아키텍처는 안정됐습니다. 추가 세대는 원시 구조가 아니라 연산과 데이터를 늘립니다.

### 수학으로 보는 M-RoPE

고전적 RoPE는 차원 `d`의 쿼리 `q`를 위치 `m`으로 쌍 좌표를 이용해 회전시킵니다:

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE는 히든 차원을 세 밴드로 나눕니다. `d = 96`이라 합시다. 32차원은 시간에, 32는 높이에, 32는 너비에 배정합니다. 각 밴드는 자기 축 위치로 회전합니다. (t=5, h=10, w=20) 패치는 세 밴드에 각각 `R_t(5)`, `R_h(10)`, `R_w(20)` 회전을 받습니다.

텍스트 토큰은 `t = 텍스트 인덱스, h = 0, w = 0`(또는 정규화된 선택)을 써서 호환성을 유지합니다. 비디오 프레임은 `t = 프레임 시간, h = 행, w = 열`. 단일 이미지는 `t = 0`.

이득: 하나의 위치 인코딩이 코드 분기나 별도의 위치 테이블 없이 텍스트, 이미지, 비디오를 모두 처리합니다.

### 동적 FPS 샘플링 로직

길이 `T`초 비디오와 목표 토큰 예산 `B`가 주어지면:

1. 감당할 수 있는 최대 FPS를 계산합니다: `fps_max = B / (T * tokens_per_frame)`.
2. `fps <= fps_max`를 만족하는 목표 FPS를 `{1, 2, 4, 8}`에서 고릅니다.
3. 움직임이 크면(광학 흐름 휴리스틱 또는 사용자 명시 요청) 더 높은 FPS를 고릅니다. 움직임이 작으면 더 낮게.
4. 고른 FPS로 균등 샘플링하고, 프레임 사이에 `<time>t</time>` 토큰을 넣습니다.

Qwen2.5-VL은 이 로직을 암묵적으로 학습했고, 추론 때는 사용자가 `fps` 파라미터로 제어합니다. 프레임당 81토큰으로 4 FPS의 60초 액션 시퀀스 = 19440토큰, 32k 컨텍스트에서 감당 가능합니다.

### 구조화된 에이전트 출력

Qwen2.5-VL의 에이전트 학습은 구조화된 도구 호출을 명시적으로 겨냥합니다:

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

파싱은 결정적입니다: 모델 출력에 JSON.parse를 적용하면 끝. 정규식과 모호성 처리가 필요했던 "click at (1024, 512)" 같은 자유 형식과 비교해 보세요. 이 전환 때문에 Qwen2.5-VL의 ScreenSpot 점수가 Qwen2-VL의 55%에서 84%로 뛰었습니다.

```figure
mm-mrope-axes
```

## 직접 써보기

`code/main.py`는 다음을 구현합니다:

- 텍스트, 이미지 패치, 비디오 프레임이 섞인 포장된 시퀀스에 대한 M-RoPE 위치 계산.
- 동적 FPS 샘플러: (길이, 예산, 움직임 수준)이 주어지면 FPS를 고르고 프레임 타임스탬프를 내놓는다.
- 좌표 필드가 있는 도구 호출 응답을 처리하는 장난감 Qwen2.5-VL JSON 출력 파서.

실행해 보고, 5분짜리 비디오에서 고정 FPS를 동적 FPS로 바꿨을 때의 차이를 느껴 보세요.

2. 1 FPS의 10분짜리 보안 카메라 녹화는 프레임이 몇 장인가요? 384 해상도에 3배 풀링이면 총 토큰은 몇 개인가요? Qwen2.5-VL 기본 32k 컨텍스트가 감당할 수 있나요?

4. Qwen2.5-VL은 Q-Former를 완전히 버립니다. 단순한 MLP가 2025년엔 되고 2023년엔 안 됐던 이유는 무엇일까요? (힌트: 데이터 규모와 인코더 품질.)

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| M-RoPE | "멀티모달 RoPE" | 히든 차원에 시간·높이·너비 밴드를 둔 3차원 회전 위치 임베딩 |
| 동적 FPS | "스마트 샘플링" | 움직임, 길이, 토큰 예산에 따라 비디오마다 고르는 프레임 샘플링 비율 |
| 절대 시간 토큰 | "타임스탬프 토큰" | 시퀀스에 끼워 넣어 모델이 프레임 인덱스가 아닌 실제 초를 보게 하는 `<time>t</time>` |
| 윈도우 어텐션 | "지역 어텐션" | 속도를 위해 작은 윈도우로 제한한 공간 셀프 어텐션; 주기적으로 전역 어텐션을 추가 |
| 구조화된 에이전트 출력 | "JSON 모드" | VLM이 좌표와 도구 이름이 있는 파싱 가능한 JSON을 내놓게 가르치는 학습 데이터 감독 |
| min_pixels / max_pixels | "해상도 경계" | 총 픽셀 수, 즉 토큰 수를 제한하는 Qwen2.5-VL의 요청별 제어 |
| 그라운딩 | "저기 가리키기" | 바운딩 박스 좌표를 텍스트 토큰으로 출력하는 것; Qwen-VL v1부터 사용 |
