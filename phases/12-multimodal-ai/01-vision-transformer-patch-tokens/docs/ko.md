# Vision Transformer와 패치 토큰 기본 요소

> 멀티모달 무엇보다도 먼저, 이미지는 트랜스포머가 먹을 수 있는 토큰 시퀀스가 되어야 합니다. 2020년 ViT 논문이 이 질문에 16x16 픽셀 패치, 선형 투영, 위치 임베딩으로 답했습니다. 5년 뒤인 2026년에도 모든 최신 모델(네이티브 2576px의 Claude Opus 4.7, Gemini 3.1 Pro, Qwen3.5-Omni)은 여전히 이 방식으로 시작합니다. 인코더는 ViT에서 DINOv2를 거쳐 SigLIP 2로 바뀌었고, 레지스터 토큰이 추가됐으며, 위치 체계는 2D-RoPE가 됐지만, 그 기본 요소(primitive)는 그대로입니다. 이 레슨은 패치 토큰 파이프라인을 처음부터 끝까지 읽고 stdlib Python으로 직접 만들어 봅니다. 페이즈 12의 나머지 부분이 "시각 토큰"에 대한 구체적인 멘탈 모델을 갖도록 하기 위함입니다.

**유형:** Learn
**언어:** Python (stdlib, 패치 토크나이저 + 기하 계산기)
**선수 지식:** 페이즈 7(트랜스포머), 페이즈 4(컴퓨터 비전)
**소요 시간:** 약 120분

## 학습 목표

- HxWx3 이미지를 올바른 위치 인코딩을 갖춘 패치 토큰 시퀀스로 변환할 수 있습니다.
- 주어진 (패치 크기, 해상도, 히든 차원, 깊이)의 ViT에 대해 시퀀스 길이, 파라미터 수, FLOPs를 계산할 수 있습니다.
- ViT를 2020년 연구에서 2026년 프로덕션(운영 환경)으로 옮긴 세 가지 업그레이드를 꼽을 수 있습니다. 자기지도 사전학습(DINO / MAE), 레지스터 토큰, 네이티브 해상도 패킹입니다.
- 다운스트림 작업에 맞춰 CLS 풀링, 평균 풀링, 레지스터 토큰 중에서 선택할 수 있습니다.

## 문제 상황

트랜스포머는 벡터 시퀀스를 다룹니다. 텍스트는 이미 시퀀스입니다(바이트 또는 토큰). 이미지는 색 채널 셋을 가진 2D 픽셀 격자일 뿐, 시퀀스가 아닙니다. 모든 픽셀을 펼치면 224x224 RGB 이미지가 150,528개 토큰이 되고, 그 길이의 셀프 어텐션은 시작조차 불가능합니다(시퀀스 길이의 제곱에 비례).

2020년 이전 방식은 앞에 CNN 특성(feature) 추출기를 붙였습니다. ResNet이 2048차원 벡터의 7x7 특성 맵을 만들면 그 49개 토큰을 트랜스포머에 먹이는 거죠. 동작은 하지만 CNN의 편향(평행 이동 등변성, 국소 수용 영역)을 물려받고, 트랜스포머의 스케일에 대한 식욕은 잃습니다.

Dosovitskiy 등(2020)은 뻔뻔한 질문을 던졌습니다. CNN을 건너뛰면 어떨까? 이미지를 고정 크기 패치(예: 16x16 픽셀)로 자르고, 각 패치를 선형 투영으로 벡터로 바꾸고, 위치 임베딩을 더하고, 그 시퀀스를 순수 트랜스포머에 넣으면 어떨까 하는 것이죠. 당시에는 이단이었습니다. 합성곱 없는 비전이라니요. 그런데 데이터가 충분하면(JFT-300M, 이후 LAION) ImageNet에서 ResNet을 이기고 계속 좋아졌습니다.

2026년이 된 지금 ViT 기본 요소는 논쟁의 여지가 없는 토대입니다. 모든 오픈 웨이트 VLM의 비전 타워(vision tower)는 그 후손입니다(DINOv2, SigLIP 2, CLIP, EVA, InternViT). 이제 질문은 "패치를 써야 하나?"가 아니라 "어떤 패치 크기, 어떤 해상도 일정, 어떤 사전학습 목표, 어떤 위치 인코딩?"입니다.

## 개념

### 토큰으로서의 패치

형태가 `(H, W, 3)`인 이미지 `x`와 패치 크기 `P`가 주어지면, 이미지를 `(H/P) x (W/P)` 격자의 겹치지 않는 패치들로 자릅니다. 각 패치는 `P x P x 3` 픽셀 큐브입니다. 각 큐브를 `3 P^2` 벡터로 펼치고, 형태가 `(3 P^2, D)`인 공유 선형 투영 `W_E`를 적용해 각 패치를 모델의 히든 차원 `D`로 사상합니다.

ViT-B/16 표준 구성 기준:
- 해상도 224, 패치 크기 16 → 격자 14x14 → 패치 토큰 196개.
- 각 패치는 `16 x 16 x 3 = 768`개 픽셀 값이며 `D = 768`로 투영됩니다.
- 학습 가능한 `[CLS]` 토큰을 하나 더하면 → 시퀀스 길이 197.

패치 투영은 커널 크기 `P`, 스트라이드 `P`, 출력 채널 `D`인 2D 합성곱과 수학적으로 동일합니다. 프로덕션 코드가 실제로 구현하는 방식이 바로 이것입니다. `nn.Conv2d(3, D, kernel_size=P, stride=P)`. "선형 투영"이라는 틀은 개념적인 설명이고, 커널이라는 틀이 효율적인 구현입니다.

### 위치 임베딩

패치에는 태생적인 순서가 없습니다. 트랜스포머는 그것들을 가방에 담긴 물건처럼 봅니다. 초기 ViT는 학습 가능한 1D 위치 임베딩을 더했습니다(위치마다 768차원 벡터 하나, 총 197개). 동작은 하지만 모델이 학습 해상도에 묶입니다. 추론 때 격자 크기를 바꾸려면 위치 테이블을 보간해야 하죠.

현대의 비전 백본은 2D-RoPE(Qwen2-VL의 M-RoPE, SigLIP 2의 기본값)나 인수분해된(factorized) 2D 위치를 씁니다. 2D-RoPE는 패치의 (행, 열) 인덱스에 따라 쿼리와 키 벡터를 회전시키므로, 모델이 회전 각도에서 상대적인 2D 위치를 추론합니다. 위치 테이블이 필요 없습니다. 추론 때 임의의 격자 크기를 다룰 수 있습니다.

### CLS 토큰, 풀링된 출력, 레지스터 토큰

이미지 수준의 표현은 무엇일까요? 세 가지 선택지가 공존합니다:

1. `[CLS]` 토큰. 학습 가능한 벡터를 패치 시퀀스 맨 앞에 붙입니다. 모든 트랜스포머 블록을 지난 뒤 CLS 토큰의 히든 상태가 이미지 표현이 됩니다. BERT에서 물려받았으며 원조 ViT와 CLIP이 사용합니다.
2. 평균 풀링. 패치 토큰들의 출력 히든 상태를 평균 냅니다. SigLIP, DINOv2, 대부분의 현대 VLM이 사용합니다.
3. 레지스터 토큰. Darcet 등(2023)은 명시적인 싱크(sink) 토큰 없이 학습된 ViT가 셀프 어텐션을 납치하는 노름이 큰 "아티팩트" 패치를 만들어낸다는 것을 관찰했습니다. 학습 가능한 레지스터 토큰을 4~16개 추가하면 이 부하를 흡수하고 조밀 예측(dense prediction) 품질(세그멘테이션, 깊이)이 좋아집니다. DINOv2와 SigLIP 2는 모두 레지스터를 탑재하고 나옵니다.

이 선택은 다운스트림 작업에 영향을 줍니다. 분류에는 CLS로 충분합니다. 패치 토큰을 LLM에 먹이는 VLM이라면 풀링을 아예 건너뜁니다. 모든 패치가 LLM 입력 토큰이 되니까요. 레지스터는 인계 전에 버립니다(내용물이 아니라 비계(scaffolding)이므로).

### 사전학습: 지도 학습, 대조 학습, 마스킹, 자기 증류

2020년 ViT는 JFT-300M으로 지도 분류 학습을 했습니다. 이내 다음 방식들로 대체됐습니다:

- CLIP(2021): 4억 개 쌍의 이미지-텍스트 대조 학습. 레슨 12.02.
- MAE(2021, He 등): 패치의 75%를 가리고 픽셀을 복원합니다. 자기지도 학습이며 순수 이미지만으로 동작합니다.
- DINO(2021) / DINOv2(2023): 학생-교사 방식의 자기 증류. 레이블도 캡션도 없습니다. 2023년 DINOv2 ViT-g/14는 가장 강한 순수 시각 백본이며 "조밀 특성(dense features)" 용도의 기본값입니다.
- SigLIP / SigLIP 2(2023, 2025): 시그모이드 손실을 쓰는 CLIP이며, NaFlex로 네이티브 종횡비를 지원합니다. 2026년 오픈 VLM의 지배적 비전 타워입니다(Qwen, Idefics2, LLaVA-OneVision).

사전학습 선택이 백본의 용도를 결정합니다. 텍스트와의 의미적 매칭에는 CLIP/SigLIP, 조밀한 시각 특성에는 DINOv2, 다운스트림 파인튜닝의 출발점으로는 MAE입니다.

### 스케일링 법칙

ViT 스케일링(Zhai 등 2022)은 ViT의 품질이 모델 크기, 데이터 크기, 연산량에 대해 예측 가능한 법칙을 따른다는 것을 확립했습니다. 고정된 연산량에서:
- 더 큰 모델 + 더 많은 데이터 → 더 좋은 품질.
- 패치 크기는 시퀀스 길이 대 충실도의 레버입니다. 패치 14(DINOv2/SigLIP SO400m의 전형값)는 패치 16보다 이미지당 토큰이 더 많습니다. OCR과 조밀 작업에는 더 좋고 속도에는 나쁩니다.
- 해상도가 또 하나의 큰 레버입니다. 224에서 384, 512로 올리면 FLOPs는 제곱으로 늘지만 거의 항상 도움이 됩니다.

ViT-g/14(파라미터 10억, 패치 14, 해상도 224 → 256토큰)와 SigLIP SO400m/14(파라미터 4억, 패치 14)가 2026년 오픈 VLM의 두 주력 인코더입니다.

### ViT 파라미터 수

전체 계산은 `code/main.py`에 들어 있습니다. 224 해상도의 ViT-B/16 기준:

```
patch_embed = 3 * 16 * 16 * 768 + 768  =  591k
cls + pos    = 768 + 197 * 768          =  152k
block        = 4 * 768^2 (QKVO) + 2 * 4 * 768^2 (MLP) + 2 * 2*768 (LN)
             = 12 * 768^2 + 3k          =  7.1M
12 blocks    = 85M
final LN    = 1.5k
total       ≈ 86M
```

체크포인트를 로드하기 전에 이런 식으로 모든 ViT를 대략 가늠하세요. 백본 크기가 어떤 다운스트림 VLM에서든 VRAM 하한을 정합니다.

### 2026 프로덕션 구성

2026년 대부분의 오픈 VLM이 탑재하는 인코더는 네이티브 해상도(NaFlex)의 SigLIP 2 SO400m/14입니다. 구성은 다음과 같습니다:
- 파라미터 4억 개.
- 패치 크기 14, 기본 해상도 384 → 이미지당 패치 토큰 729개.
- 이미지 수준 작업에는 평균 풀링. VQA에서는 729개 패치 전부가 LLM으로 흘러 들어갑니다.
- 레지스터 토큰 4개. LLM 인계 전에 버려집니다.
- 네이티브 종횡비를 위한 이미지 수준 스케일링이 적용된 2D-RoPE.

그 구성의 모든 결정은 여러분이 읽을 수 있는 논문으로 거슬러 올라갑니다.

## 사용해 보기

`code/main.py`는 패치 토크나이저이자 기하 계산기입니다. (이미지 H, W, 패치 P, 히든 D, 깊이 L)을 받아 다음을 보고합니다:

- 패칭 뒤의 격자 모양과 시퀀스 길이.
- 8x8 픽셀 장난감 이미지의 토큰 시퀀스(펼치기 + 투영 경로를 따라가 봄).
- 패치 임베딩, 위치 임베딩, 트랜스포머 블록, 헤드별로 나눈 파라미터 수.
- 목표 해상도에서 순전파당 FLOPs.
- ViT-B/16 @ 224, ViT-L/14 @ 336, DINOv2 ViT-g/14 @ 224, SigLIP SO400m/14 @ 384를 비교하는 표.

실행해 보세요. 파라미터 수가 공개된 숫자와 맞는지 확인하고, 패치 크기와 해상도를 만져 보며 토큰 수 비용을 몸으로 느껴 보세요.

## 출시하기

이 레슨은 `outputs/skill-patch-geometry-reader.md`를 만들어 냅니다. ViT 구성(패치 크기, 해상도, 히든 차원, 깊이)이 주어지면 근거와 함께 토큰 수, 파라미터 수, VRAM 추정치를 산출합니다. VLM용 비전 백본을 고를 때마다 이 스킬을 사용하세요. "토큰이 폭발해서 LLM 컨텍스트 윈도우가 가득 찼다"는 놀람을 막아 줍니다.

## 연습 문제

1. 패치 크기 14로 네이티브 1280x720 입력을 넣을 때 Qwen2.5-VL의 패치 토큰 시퀀스 길이를 계산합니다. CLS만 있는 표현과 비교하면 어떤가요?

2. 패치 14로 1080p 프레임(1920x1080)은 토큰을 몇 개 만들까요? 30 FPS로 5분짜리 비디오라면 총 시각 토큰은 몇 개일까요? 풀링, 프레임 샘플링, 토큰 병합 중 어느 것이 비용을 가장 많이 아낄까요?

3. 순수 Python으로 패치 토큰 위의 평균 풀링을 구현합니다. DINOv2 출력의 196개 토큰에 대한 평균 풀링이, 풀링된 임베딩을 요청했을 때 모델의 `forward`가 반환하는 것과 일치하는지 확인합니다.

4. "Vision Transformers Need Registers"(arXiv:2309.16588)의 3절을 읽습니다. 레지스터가 흡수하는 아티팩트가 무엇인지, 그것이 다운스트림 조밀 예측에 왜 중요한지 두 문장으로 설명합니다.

5. `code/main.py`를 고쳐 patch-n'-pack을 지원하게 만듭니다. 서로 다른 해상도의 이미지 목록이 주어지면 하나의 패킹된 시퀀스와 블록 대각선 어텐션 마스크를 만들어 냅니다. 레슨 12.06에 도달하면 그것과 대조해 검증합니다.

## 핵심 용어

| 용어 | 흔히 하는 말 | 실제 의미 |
|------|----------------|------------------------|
| 패치 | "16x16 픽셀 정사각형" | 입력 이미지의 고정 크기, 겹치지 않는 영역. 토큰 하나가 됨 |
| 패치 임베딩 | "선형 투영" | 펼친 패치 픽셀을 D차원 벡터로 사상하는 공유 학습 행렬(또는 stride=P인 Conv2d) |
| CLS 토큰 | "클래스 토큰" | 맨 앞에 붙는 학습 가능한 벡터. 최종 히든 상태가 이미지 전체를 대표. 2026년엔 선택 사항 |
| 레지스터 토큰 | "싱크 토큰" | ViT가 사전학습 중에 만드는 노름이 큰 어텐션 아티팩트를 흡수하는 추가 학습 토큰 |
