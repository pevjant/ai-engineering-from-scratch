# 멀티모달 에이전트와 컴퓨터 사용 (캡스톤)

> 2026년의 프런티어 제품은 스크린샷을 읽고, 버튼을 클릭하고, 웹 UI를 탐색하고, 양식을 채우고, 워크플로를 엔드투엔드로 완수하는 멀티모달 에이전트입니다. SeeClick과 CogAgent(2024)는 GUI 접지 원시 개념을 증명했습니다. Ferret-UI는 모바일을 더했고, ChartAgent는 차트를 위한 시각적 도구 사용을 소개했습니다. VisualWebArena와 AgentVista(2026)는 프런티어가 쫓는 벤치마크인데, Gemini 3 Pro와 Claude Opus 4.7조차 AgentVista의 어려운 과제에서 ~30%입니다. 이 캡스톤은 Phase 12의 모든 실을 한데 묶습니다: 지각(고해상도 VLM), 추론(도구 사용이 되는 LLM), 접지(좌표 출력), 긴 시야의 메모리, 그리고 평가.

**유형:** 캡스톤
**언어:** Python (표준 라이브러리, 행동 스키마 + 에이전트 루프 스켈레톤)
**선수 지식:** Phase 12 · 05 (LLaVA), Phase 12 · 09 (Qwen-VL JSON), Phase 14 (Agent Engineering)
**소요 시간:** ~240분

## 학습 목표

- 멀티모달 에이전트 루프를 설계할 수 있다: 지각 → 추론 → 행동 → 관찰 → 반복.
- VLM이 JSON으로 내놓을 수 있는 GUI 접지 출력 스키마(클릭 좌표, 텍스트 입력, 스크롤, 드래그)를 만들 수 있다.
- 스크린샷 전용 에이전트 vs 접근성 트리 에이전트 vs 하이브리드 에이전트를 비교할 수 있다.
- 작은 VisualWebArena 슬라이스에서 멀티모달 에이전트 벤치마크 평가를 세팅할 수 있다.

## 문제 상황

예약 사이트 워크플로: "4월 15일 도쿄행 항공편을 찾아 줘. 통로 좌석에 800달러 이하면 예약해."

멀티모달 에이전트는 이렇게 해야 합니다:

1. 브라우저 스크린샷을 찍습니다.
2. 스크린샷 + URL + 목표를 계획으로 파싱합니다.
3. 구조화된 행동을 출력합니다: 클릭((x,y)에서), 입력 "Tokyo"(요소 E에서), 아래로 스크롤, 선택(라디오 버튼).
4. 그 행동을 브라우저에 적용합니다.
5. 새 상태를 관찰합니다(다음 스크린샷).
6. 과제가 끝날 때까지 반복합니다.

각 단계가 멀티모달 VLM 호출입니다. VLM 출력은 반드시 파싱 가능한 JSON이어야 하고, 오류는 단계마다 누적되므로 복구가 중요합니다.

## 개념

### GUI 접지 — 원시 개념

GUI 접지란: 스크린샷과 자연어 지시가 주어지면, 클릭할 (x, y) 좌표(또는 다른 행동)를 출력하는 것입니다.

SeeClick(arXiv:2401.10935)이 규모 있게 이룬 최초의 오픈 결과입니다: 합성 + 실제 GUI 데이터로 VLM을 파인튜닝해, 좌표를 일반 텍스트 토큰으로 출력합니다. 통합니다.

CogAgent(arXiv:2312.08914)는 조밀한 UI를 위해 1120x1120 고해상도 인코딩을 추가했습니다. 점수: 웹 내비게이션에서 ~84%.

Ferret-UI(arXiv:2404.05719)는 모바일 UI에 초점을 맞추고 iOS 접근성 데이터와 통합됩니다.

출력 형식은 보통 JSON입니다:

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc`는 복구에 도움이 됩니다. 스크린샷 사이에서 좌표가 흐트러져도, 이 의미 힌트가 시스템이 다시 접지하게 해 줍니다.

### 행동 스키마

전형적인 행동 스키마는 6~10개의 행동 유형을 가집니다:

- `click`: (x, y)
- `type`: (text, x?, y?)
- `scroll`: (direction, amount)
- `drag`: (x0, y0, x1, y1)
- `select`: (option_index)
- `hover`: (x, y)
- `navigate`: (url)
- `wait`: (ms)
- `done`: (success, explanation)

에이전트는 스텝마다 행동 하나를 출력합니다. 브라우저 래퍼가 이를 실행하고 새 상태를 돌려줍니다.

### 스크린샷 전용 vs 접근성 트리

두 입력 모드:

- 스크린샷 전용: 전체 이미지, 구조 정보 없음. 가장 범용; 어떤 앱에서도 통합니다.
- 접근성 트리: 구조화된 DOM / iOS 접근성 정보. 접지에는 훨씬 신뢰할 수 있지만, 트리가 있는 곳에서만 통합니다.
- 하이브리드: 둘 다 사용. 원자적 행동의 신뢰할 수 있는 접지기로 트리를, 의미적 문맥으로 스크린샷을 씁니다.

프로덕션 에이전트는 가능하면 하이브리드를 씁니다. 브라우저 자동화(Selenium + 접근성)는 항상 트리가 있고, 데스크톱 앱은 때때로 있습니다.

### 긴 시야의 메모리

20스텝 워크플로는 스크린샷 20장을 만듭니다. VLM의 컨텍스트는 빠르게 찹니다. 세 가지 압축 전략:

- 요약 체인: 5스텝마다 지금까지 일어난 일을 요약하고 오래된 스크린샷은 버립니다.
- 스킵 프레임: 첫 번째, 마지막, 3번째마다의 스크린샷만 유지합니다.
- 도구 기록 로그: 행동을 실행하면서 무엇을 했는지 텍스트 로그를 남기고, 오래된 스크린샷은 다시 보지 않습니다.

Claude의 컴퓨터 사용 API는 로그 패턴을 씁니다. 더 단순하고 신뢰할 수 있죠.

### 시각적 도구 사용

ChartAgent(arXiv:2510.04514)는 차트 이해를 위한 시각적 도구 사용을 도입했습니다: 자르기(crop), 확대(zoom), OCR, 외부 탐지 호출. 에이전트가 "영역 (100, 200, 300, 400)으로 자른 뒤 OCR 호출"을 도구 호출로 출력할 수 있습니다. 도구가 텍스트를 돌려주면 VLM이 추론을 이어갑니다.

이 패턴은 일반화됩니다: set-of-mark 프롬프팅, 영역 주석, 외부 탐지 도구 모두 "도구 호출을 출력하고, 구조화된 응답을 받는다"는 같은 스키마에 맞습니다.

### 2026년의 벤치마크

- ScreenSpot-Pro. 약 1천 개 웹 스크린샷의 GUI 접지. 오픈 SOTA Qwen2.5-VL-72B ~85%. 프런티어 ~90%.
- VisualWebArena. 엔드투엔드 웹 과제(쇼핑, 포럼, 중고 거래). 오픈 SOTA ~20%. Gemini 3 Pro ~27%.
- AgentVista(arXiv:2602.23166). 2026년 가장 어려운 벤치마크. 12개 도메인에 걸친 현실적인 워크플로. 프런티어 모델은 27~40%; 오픈 모델은 10~20%.
- WebArena / WebShop. 더 오래된 벤치마크; 프런티어가 포화시켰습니다.

### 여전히 어려운 이유

에이전트 성능의 병목:

1. 세밀한 규모의 시각적 접지. "작은 X를 클릭해"는 모바일 해상도에서 자주 실패합니다.
2. 긴 시야의 계획. 10행동이 지나면 에이전트가 목표에서 흘러갑니다.
3. 오류 복구. 클릭이 실패했을 때(잘못된 버튼) 이를 감지하고 복구하는 것은 학습 데이터에서 드뭅니다.
4. 페이지 간 문맥. 탭 사이나 긴 양식을 오가면 상태를 잃습니다.

연구 방향: 메모리 아키텍처, 명시적 재계획, 멀티모달 검증(행동 성공 여부의 스크린샷 대조).

### 캡스톤 빌드 과제

캡스톤 과제: 다음을 하는 컴퓨터 사용 에이전트를 만드는 것입니다:

1. 예약 사이트 목업 페이지의 HTML + 스크린샷을 읽습니다.
2. 다단계 시퀀스를 계획합니다: 검색 → 선택 → 양식 작성 → 제출.
3. 행동 스키마에 맞는 JSON 행동을 출력합니다.
4. 고정된 10과제 슬라이스로 평가합니다.

레슨은 실제 브라우저로 확장하기 쉬운 스캐폴드 코드를 제공합니다.

```figure
mm-agent-loop
```

## 직접 해보기

`code/main.py`는 캡스톤 스캐폴드입니다:

- 행동 스키마 JSON 정의(10개 행동).
- 딕셔너리로 만든 목업 브라우저 상태.
- 에이전트 루프 스켈레톤: 상태를 받고, 행동을 출력하고, 적용하고, 반복.
- 엔드투엔드 성공률을 측정하는 10과제 미니 벤치마크(합성 페이지).
- 행동이 실패했을 때의 오류 복구 훅.

## 출시하기

이 레슨은 `outputs/skill-multimodal-agent-designer.md`를 만듭니다. 컴퓨터 사용 제품(도메인, 행동 집합, 평가 목표)이 주어지면 전체 에이전트 루프, 메모리 전략, 접지 모드, 기대 벤치마크 점수를 설계해 줍니다.

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|-----------------|------------------------|
| GUI 접지 (GUI grounding) | "클릭 좌표" | 스크린샷 위 지시 대상의 (x,y)를 모델이 출력하는 것 |
| 행동 스키마 (Action schema) | "도구 정의" | 유효한 행동의 JSON 설명(click, type, scroll, drag) |
| 접근성 트리 (Accessibility tree) | "구조화된 DOM" | 브라우저/iOS API가 주는 기계 판독 가능한 UI 계층 |
| 하이브리드 에이전트 | "스크린샷 + 트리" | 이미지와 구조 정보를 모두 사용; 어느 하나 단독보다 신뢰할 수 있음 |
| 시각적 도구 사용 (Visual tool use) | "확대/자르기/탐지" | 에이전트가 계획 도중 외부 비전 도구(OCR, 탐지)를 호출 |
| 요약 체인 (Summary-chain) | "메모리 압축" | 주기적 텍스트 요약으로 긴 스크린샷 이력을 대체 |
| VisualWebArena | "E2E 웹 벤치" | 엔드투엔드 웹 과제용 2024년 벤치마크 |
| AgentVista | "2026 하이드 벤치" | 12개 도메인의 현실적 워크플로; Gemini 3 Pro조차 ~30% |
