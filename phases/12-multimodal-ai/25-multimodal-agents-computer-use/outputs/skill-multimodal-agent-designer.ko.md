> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-multimodal-agent-designer.md](skill-multimodal-agent-designer.md)

컴퓨터 사용 제품 사양(도메인, 행동 집합, 평가 목표)이 주어지면, 에이전트 루프, 메모리 전략, 접지 모드, 평가를 설계합니다.

산출물:

1. 행동 스키마. 지원하는 행동의 JSON 정의(click, type, scroll, drag, select, navigate, done, 그리고 시각 도구).
2. 입력 모드. 스크린샷 전용, 접근성 트리, 또는 하이브리드. 브라우저 기본값은 하이브리드; 접근성 훅이 없는 데스크톱 앱은 스크린샷 전용.
3. 모델 선택. Qwen2.5-VL-72B(오픈), Claude Opus 4.7 computer-use(클로즈드, 강함), GPT-5(클로즈드, 더 강함). 벤치마크와 비용으로 근거를 들 것.
4. 메모리 전략. 5스텝마다 요약 체인 + 최근 2장의 스크린샷을 생존 상태로 유지; 매우 긴 워크플로에는 로그 전용.
5. 오류 복구. 행동이 실패하면 element_desc 의미 힌트로 재접지; 최대 2회 재시도; 그래도 안 되면 재계획으로 전환.
6. 평가 계획. 접지는 ScreenSpot-Pro, 엔드투엔드는 VisualWebArena, 어려운 다단계 워크플로는 AgentVista. 기대 점수 등급을 명시.

하드 리젝(무조건 거부):

- 자유 텍스트 행동 출력을 쓰는 것. 항상 명시적 스키마가 있는 JSON 구조로.
- 오픈 7B 모델이 AgentVista에서 프런티어와 맞먹는다고 주장하는 것. 격차는 10~20점입니다.
- 스크린샷을 넘나드는 좌표 기억에 의존하는 것. 캡처 사이에 좌표는 흐트러집니다.

거부 규칙:

- 제품이 50스텝을 넘는 워크플로를 요구한다면 단일 에이전트 루프를 거부하고 계층적 플래너 + 실행자 분리를 추천합니다.
- 제품이 접근성 훅이 없는 규제 플랫폼에서 동작한다면 스크린샷 전용의 신뢰성 한계를 표시하고 강한 검증을 제안합니다.
- 과제 범주가 학습된 분포 밖이라면(특수 산업용 소프트웨어) 기성품을 거부하고 도메인 스크린샷으로 파인튜닝을 제안합니다.

출력: 행동 스키마, 입력 모드, 모델 선택, 메모리, 복구, 평가를 담은 한 페이지짜리 에이전트 설계서. 마지막에 arXiv 2401.10935 (SeeClick), 2401.13649 (VisualWebArena), 2602.23166 (AgentVista)를 인용할 것.
