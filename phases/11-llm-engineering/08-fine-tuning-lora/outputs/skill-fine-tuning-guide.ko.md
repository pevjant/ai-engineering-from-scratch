# 파인튜닝 의사결정 가이드

파인튜닝 전에 다음을 순서대로 시도해 보세요:

```
1. 프롬프트 엔지니어링 (몇 분, $0)
2. 프롬프트에 few-shot 예시 넣기 (몇 분, $0)
3. 지식 검색용 RAG (며칠, 월 $10-100)
4. LoRA/QLoRA 파인튜닝 (며칠, 실험당 $5-50)
5. 전체 파인튜닝 (몇 주, 실행당 $100-10,000)
```

이전 단계가 실측상 부족할 때만 다음 단계로 넘어갑니다.

## 파인튜닝해야 할 때

- 프롬프트로는 만들 수 없는 일관된 출력 스타일이나 형식이 필요할 때
- 더 큰 모델을 증류할 때(8B 모델에서 GPT-4급 품질)
- 지연 시간이 중요한데 few-shot 예시가 토큰을 너무 많이 먹을 때
- 모델이 복잡한 추론 패턴을 안정적으로 따라가야 할 때
- 원하는 입력-출력 동작의 고품질 예제가 1,000개 이상 있을 때

## 파인튜닝하면 안 되는 때

- 올바른 프롬프트만으로 모델이 이미 원하는 일을 할 때
- 모델이 사실을 알아야 할 때(RAG를 사용하세요)
- 학습 예제가 500개 미만일 때(과적합 위험이 큽니다)
- 작업이 자주 바뀔 때(재학습 비용이 큽니다)
- 특정 출력에 어떤 데이터가 영향을 줬는지 감사해야 할 때(파인튜닝은 블랙박스입니다)

## 방식 선택

| GPU VRAM | 7B 모델 | 13B 모델 | 70B 모델 |
|----------|----------|-----------|-----------|
| 16GB (T4) | QLoRA | 불가능 | 불가능 |
| 24GB (3090/4090) | QLoRA 또는 LoRA | QLoRA | 불가능 |
| 40GB (A100) | LoRA 또는 전체 | QLoRA 또는 LoRA | QLoRA |
| 80GB (A100/H100) | 전체 | LoRA 또는 전체 | QLoRA 또는 LoRA |

## LoRA 설정 체크리스트

1. r=16, alpha=32로 시작(대부분의 작업에 안전한 기본값)
2. 먼저 q_proj와 v_proj를 대상으로 삼기(최소 구성의 LoRA)
3. 학습률은 QLoRA 2e-4, LoRA fp16 5e-5
4. lora_dropout=0.05로 설정
5. 1~3 에포크 학습(더 돌리면 과적합 위험)
6. 100단계마다 홀드아웃 세트로 평가
7. 체크포인트를 저장하고 평가 손실이 가장 낮은 것 선택

## 흔한 실수

- 에포크를 너무 많이 돌리기(작은 데이터셋에서는 2~3 에포크 이후 과적합)
- 전체 파인튜닝과 같은 학습률 쓰기(LoRA는 더 높은 학습률이 필요합니다)
- 패드 토큰 설정을 잊기(Llama 계열에서 NaN 손실을 일으킵니다)
- 베이스 모델을 동결하지 않기(LoRA의 존재 이유가 사라집니다)
- 학습 데이터로만 평가하기(항상 10~20%는 평가용으로 남겨 두세요)
- 프롬프트 엔지니어링 베이스라인 건너뛰기(프롬프트로 이미 해결되는 문제를 파인튜닝하는 꼴)

## 품질 검증

학습 후 홀드아웃 예제 200개 이상으로 비교하세요:
1. 최선의 프롬프트를 쓴 베이스 모델(베이스라인)
2. LoRA 어댑터를 얹은 베이스 모델(파인튜닝된 모델)
3. 같은 프롬프트를 쓴 GPT-4 또는 Claude(상한선)

LoRA 모델이 프롬프트만 쓴 베이스라인을 못 이긴다면, 더 많은 컴퓨팅이 아니라 학습 데이터나 설정을 손봐야 합니다.

## 어댑터 관리

- 멀티태스크 서빙에는 어댑터를 따로 보관(요청마다 어댑터 교체)
- 단일 작업 배포에는 어댑터를 베이스 가중치에 병합
- 어댑터는 Hugging Face Hub에 저장(10~100MB, 버전 관리와 공유가 쉬움)
- 배포 전에 병합 모델 출력이 미병합 출력과 같은지 테스트
- 여러 어댑터를 하나로 합칠 때는 TIES-Merging이나 DARE 사용

## 학습 디버깅

손실이 줄지 않는다면:
1. 학습률 확인(LoRA에는 너무 낮을 수 있음. 2e-4를 시도)
2. LoRA 레이어가 실제로 그래디언트를 받고 있는지 확인
3. 베이스 모델 가중치가 동결됐는지 확인
4. 데이터 형식 확인(토크나이저가 모델이 기대하는 형식과 일치해야 함)

손실은 줄지만 평가 품질이 나쁘다면:
1. 학습 데이터 품질 문제(쓰레기가 들어가면 쓰레기가 나옵니다)
2. 과적합(에포크 줄이기, 드롭아웃 늘리기, 데이터 더 넣기)
3. 잘못된 대상 모듈(복잡한 작업에는 MLP 레이어 추가)
4. 랭크가 너무 낮음(r=32나 r=64 시도)
