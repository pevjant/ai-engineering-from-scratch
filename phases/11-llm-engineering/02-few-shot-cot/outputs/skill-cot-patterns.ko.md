# 추론 기법 선택 가이드

LLM에게 문제를 추론하게 해야 할 때는 프롬프트를 쓰기 전에 먼저 기법을 고르세요. 기법이 추론 아키텍처를 결정하고, 프롬프트가 그것을 채웁니다.

## 빠른 의사 결정 트리

1. 작업이 단순 사실 조회나 한 단계짜리 분류인가?
   - 예: **zero-shot**을 사용한다. CoT는 정확도 이득 없이 비용만 더한다.
   - 아니오: 계속 진행.

2. 작업이 다단계 추론(수학, 논리, 계획)을 필요로 하는가?
   - 예: **Chain-of-Thought**를 사용한다. 3단계로 진행.
   - 아니오: 형식이 중요하면 **few-shot**, 아니면 zero-shot을 사용한다.

3. 추론 오류가 하나 있어도 괜찮은가?
   - 예: **few-shot CoT**를 사용한다 (단일 샘플, 온도 0.0).
   - 아니오: **self-consistency**를 사용한다 (N=5, 온도 0.7). 4단계로 진행.

4. 문제가 가능한 경로가 많은 탐색/계획 문제인가?
   - 예: **Tree-of-Thought**를 사용한다.
   - 아니오: self-consistency면 충분하다.

5. 작업이 외부 정보나 계산을 필요로 하는가?
   - 예: **ReAct**를 사용한다 (추론 + 도구 호출).
   - 아니오: 순수 추론 기법이면 충분하다.

## 기법 매트릭스

| 기법 | 정확도 향상 | 비용 배수 | 지연 시간 | 가장 알맞은 용도 |
|-----------|--------------|-----------------|---------|----------|
| Zero-shot | 베이스라인 | 1x | 약 1초 | 간단한 작업, 사실 질의응답 |
| Few-shot | +5-15% | 1.2x | 약 1초 | 형식 매칭, 분류 |
| Zero-shot CoT | +10-20% | 1.3x | 약 1.5초 | 빠른 추론 부스트 |
| Few-shot CoT | +15-25% | 1.5x | 약 2초 | 수학, 논리, 다단계 |
| Self-Consistency (N=5) | CoT 대비 +2-5% | 5x | 약 5초 | 중요한 추론 |
| Self-Consistency (N=10) | N=5 대비 +1-2% | 10x | 약 10초 | 아주 중요한 의사 결정에만 |
| Tree-of-Thought | 작업에 따라 다름 | 10-40x | 약 30초 이상 | 탐색, 계획, 퍼즐 |
| ReAct | 작업에 따라 다름 | 3-10x | 약 5-15초 | 지식 기반 작업 |
| 프롬프트 체이닝 | 단일 대비 +5-10% | 2-5x | 약 5-10초 | 복잡한 다중 파트 작업 |

## 모델별 가이드

### GPT-4o / GPT-4.1
- 탄탄한 기본 추론 성능. Zero-shot CoT로 대체로 충분하다.
- 예시 3개의 few-shot CoT가 GSM8K에서 95%를 기록한다.
- Self-consistency의 이득은 미미하다(95%에서 97%) — 중요한 작업에만 쓸 만하다.
- 답 추출을 위해 구조화된 출력을 네이티브로 지원한다.

### Claude 3.5 Sonnet / Claude 3.7 Sonnet
- 구조화된 프롬프트 형식(XML 태그) 따르기에 탁월하다.
- XML 구분자로 구획된 예시를 쓴 few-shot CoT가 가장 잘 작동한다.
- Extended thinking(Claude 3.7)은 네이티브 CoT다 — 프롬프트로 요청할 필요가 없다.
- Claude의 추론은 온도 0.7에서 폭넓게 달라지기 때문에 self-consistency가 효과적이다.

### Llama 3.1/3.3 70B
- few-shot CoT가 가장 큰 효과를 낸다 (zero-shot 대비 정확도 격차가 크다).
- 추론 작업에는 N=5 self-consistency를 권장한다.
- 상용 모델보다 더 명시적인 형식 지시가 필요하다.
- ToT는 로컬 추론에서 비싸다 — 배치 처리에만 고려하라.

### Gemini 2.5 Pro
- 별도 설정 없이도 다단계 추론이 강하다.
- Thinking 모드가 프롬프트 엔지니어링 없이 내장 CoT를 제공한다.
- Few-shot 예시는 정확도보다 형식 일관성에 더 도움이 된다.
- 큰 컨텍스트 윈도우(1M) 덕분에 예시를 넉넉히 쓰는 few-shot이 실용적이다.

## 안티 패턴

**간단한 작업에 CoT**: "What is 2+2? Let's think step by step"라고 묻는 것은 토큰 낭비입니다. 모델은 추론 흔적 없이도 간단한 산술은 맞힙니다. CoT가 도움이 되는 것은 단계가 3개 이상일 때입니다.

**온도 0.0에서의 self-consistency**: N개 샘플이 모두 동일해집니다. 다양한 추론 경로를 얻으려면 온도 > 0(0.5-0.8 권장)을 써야 합니다.

**모든 것에 ToT**: ToT는 분기 계수 b, 깊이 d에 대해 O(b^d)번의 LLM 호출을 요구합니다. b=3, d=3 트리는 최대 39번 호출이 필요합니다. 더 싼 기법이 실패하는 문제에만 아껴 쓰세요.

**나쁜 예시를 쓴 few-shot**: 추론 오류가 있는 예시는 모델에게 그 오류를 가르칩니다. 모든 예시는 검증되어야 합니다. 잘못된 예시 하나가 예시 0개보다 정확도를 더 크게 떨어뜨릴 수 있습니다.

**일관된 형식 없이 답 추출하기**: self-consistency는 샘플들 사이에서 답을 비교해야 합니다. 답 형식이 들쭉날쭉하면("$18", "18 dollars", "eighteen") 투표가 실패합니다. 항상 이 형식을 강제하세요: "The answer is [number]."

## 비용 최적화

하루 10,000 쿼리를 GPT-4o 가격(입력 $2.50/1M, 출력 $10/1M)에 처리하는 프로덕션(운영 환경) 시스템 기준:

| 기법 | 쿼리당 평균 토큰 | 일일 비용 | 정확도 |
|-----------|-----------------|------------|----------|
| Zero-shot | ~200 | ~$5 | 78% |
| Few-shot CoT | ~600 | ~$15 | 95% |
| Self-Consistency (N=5) | ~3,000 | ~$75 | 97% |
| ToT (b=3, d=2) | ~6,000 | ~$150 | 작업에 따라 다름 |

대부분의 애플리케이션에서 비용 최적 전략: few-shot CoT로 시작한다. 확신도가 낮은 쿼리에만 self-consistency를 추가한다(직접 만들어 보기 섹션의 격상 패턴).

## 프롬프트 체이닝과의 결합

추론 기법은 프롬프트 체이닝과 조합할 수 있습니다:

**체인 단계 1** (추출): zero-shot, 온도 0.0
**체인 단계 2** (추론): few-shot CoT, 온도 0.0
**체인 단계 3** (검증): self-consistency N=3, 온도 0.7

이 3단계 체인은 단일 CoT 호출의 약 3배 비용이 들지만, 추출 오류와 추론 오류를 잡아 내고 검증 단계에서 확신도 점수를 제공합니다.

## 프롬프팅을 넘어서야 할 때

프롬프트 엔지니어링에 애플리케이션 코드 작성보다 더 많은 시간을 쓰고 있다면 다음을 고려하세요:

1. **파인튜닝**: 레이블 달린 예시가 500개 이상 있고 작업 범위가 좁을 때
2. **DSPy 컴파일**: 자동화된 프롬프트 최적화가 필요할 때
3. **에이전트 프레임워크**: 작업이 여러 턴에 걸친 도구 사용을 필요로 할 때 (Phase 14)
4. **RAG**: 모델이 비공개/최신 지식에 접근해야 할 때 (레슨 06-07)

프롬프팅 기법은 기초입니다. 어떤 모델, 어떤 제공사와도 작동하고 학습 데이터가 필요 없습니다. 하지만 한계가 있습니다. 다음 단계로 넘어갈 시점을 아는 것은 기법 자체를 마스터하는 것만큼이나 중요합니다.
