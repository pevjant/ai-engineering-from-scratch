# 컨텍스트 엔지니어링

LLM 애플리케이션을 만들 때 이 프레임워크를 적용해 컨텍스트 조립 파이프라인을 설계하세요.

## 핵심 원칙

1. **컨텍스트는 희소합니다.** 128K 윈도우는 커 보이지만 금방 채워집니다. 구성 요소마다 예산을 명시적으로 세우세요.
2. **어텐션은 고르지 않습니다.** 모델은 시작과 끝에 더 주목합니다. 중요한 정보를 그곳에 두세요. 중간은 사각지대입니다.
3. **동적이 정적을 이깁니다.** 쿼리마다 필요한 컨텍스트가 다릅니다. 시작할 때 한 번 하는 게 아니라 쿼리마다 조립하세요.
4. **적을수록 많습니다.** 선별된 10K 컨텍스트가 쏟아부은 100K 컨텍스트를 이깁니다. 총 정보량보다 신호 대 잡음비가 중요합니다.
5. **모든 것을 측정합니다.** 측정하지 않는 것은 최적화할 수 없습니다. 요청마다 구성 요소별 토큰 수를 세세요.

## 컨텍스트 예산 가이드라인

| 구성 요소 | 일반적 범위 | 우선순위 | 압축 전략 |
|-----------|-------------|----------|---------------------|
| 시스템 프롬프트 | 200-1,000 토큰 | 고정, 높음 | 간결하게 쓰고 중복 제거 |
| 도구 정의 | 500-3,000 토큰 | 동적, 중간 | 쿼리 의도로 가지치기 |
| 검색된 컨텍스트 | 1,000-5,000 토큰 | 동적, 높음 | 리랭크 + 임계값 + 중복 제거 |
| 대화 이력 | 500-5,000 토큰 | 동적, 중간 | 오래된 턴 요약 |
| 퓨샷 예시 | 500-2,000 토큰 | 동적, 높음 | 작업 유사도로 선택 |
| 사용자 쿼리 | 50-500 토큰 | 고정, 최상위 | 해당 없음 |
| 생성 예약분 | 2,000-8,000 토큰 | 고정 | 예상 출력 길이에 맞게 조정 |

## 메모리 유형별 사용 시점

**단기(대화 이력):** 현재 세션입니다. 요약으로 관리합니다. 5-10번의 교환보다 오래된 턴은 압축하고, 마지막 3-4턴은 그대로 유지합니다.

**장기(사실 데이터베이스):** 세션을 넘어 유지되는 선호와 프로젝트 사실입니다. 세션 시작 때 불러옵니다. 예시: "사용자는 Python 선호", "프로젝트는 PostgreSQL 사용", "팀은 트렁크 기반 개발을 따름". CLAUDE.md, 데이터베이스, 또는 구조화된 메모리 시스템에 저장합니다.

**에피소드(과거 상호작용):** 현재 작업과 관련 있는 구체적인 과거 대화입니다. 임베딩으로 저장하고 유사도로 불러옵니다. "지난주에 비슷한 auth 문제를 디버깅했다"는 에피소드 기억입니다.

## 도구 선택 전략

모든 요청에 모든 도구를 넣지 마세요. 토큰을 낭비하고 모델을 혼란스럽게 합니다.

1. 쿼리 의도를 분류합니다(code, email, calendar, research, data)
2. 의도를 도구 카테고리에 연결합니다
3. 일치하는 도구만 포함합니다
4. 의도가 모호하면 상위 2개 카테고리의 도구를 포함합니다
5. 만일을 위해 "범용" 도구(웹 검색 등)는 항상 포함합니다

예상 절감 효과: 의도가 뚜렷한 쿼리에서 도구 정의 토큰의 60-80%를 아낍니다.

## 검색 모범 사례

- **검색 후 리랭크합니다.** 벡터 유사도는 대략적인 필터입니다. 리랭커(크로스 인코더 또는 LLM 기반)가 정밀도를 크게 끌어올립니다.
- **관련성 임계값을 정합니다.** 코사인 유사도 0.3 미만 청크는 넣지 마세요. 잡음만 더합니다.
- **중복을 제거합니다.** 두 청크가 내용의 80% 이상을 공유하면 점수가 높은 쪽만 남깁니다.
- **lost-in-the-middle 배치를 적용합니다.** 가장 관련성 높은 청크를 맨 앞과 맨 뒤에 둡니다.
- **검색 토큰 총량을 제한합니다.** 매우 관련성 높은 청크 3-5개가 무난한 청크 15개를 이깁니다.

## 이력 관리

- 마지막 3-4턴은 그대로 유지합니다(모델에는 최근 컨텍스트가 필요합니다)
- 더 오래된 턴은 요약본으로 묶습니다("X를 논의했고, Y로 결정했으며, Z에서 막혀 있다")
- 정보를 더하지 않는 시스템 생성 턴은 버립니다(사용자에게 보이는 내용이 없는 도구 호출 등)
- 이력이 가용 예산의 30%를 넘으면 압축을 실행합니다

## 경고 신호

- 시스템 프롬프트가 2,000토큰을 넘습니다: 동적으로 처리해야 할 정보가 들어 있을 가능성이 큽니다
- 모든 요청에 모든 도구가 포함됩니다: 의도 기반 선택을 구현하세요
- 검색에 관련성 필터가 없습니다: 잡음을 윈도우에 쏟아붓고 있는 셈입니다
- 이력이 무한히 늘어납니다: 요약이 구현되지 않았습니다
- 생성 예약분이 없습니다: 모델이 응답을 잘라내게 됩니다
- 같은 정보가 세 곳(시스템 프롬프트, 검색된 문서, 이력)에 있습니다: 중복을 제거하세요
- 컨텍스트 사용률이 60%를 넘습니다: 모델이 "생각할" 공간을 너무 적게 남겨두고 있습니다
