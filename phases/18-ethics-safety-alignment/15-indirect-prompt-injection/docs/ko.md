# 간접 프롬프트 인젝션 — 프로덕션 공격 표면

> 간접 프롬프트 인젝션(IPI)은 외부 콘텐츠 — 웹 페이지, 이메일, 공유 문서, 지원 티켓 — 안에 지시를 심어서, 사용자의 명시적 행동 없이 에이전틱 시스템이 그것을 소비하게 만듭니다. IPI는 2026년의 지배적인 프로덕션(운영 환경) 위협입니다: 공격자는 사용자를 전혀 건드리지 않으므로 사용자 입력 필터를 우회하고, 에이전트가 더 많은 외부 콘텐츠를 처리할수록 조용히 확대되며, 프롬프트를 읽는 사람이 아무도 없는 자동화 워크플로를 겨냥합니다. MDPI Information 17(1):54 (2026년 1월)는 2023~2025년 연구를 종합합니다. NDSS 2026의 IPI 방어 논문은 핵심 과제를 이렇게 프레이밍합니다: 주입된 지시는 의미상 무해할 수 있으므로("please print Yes"), 탐지에는 키워드 필터링 이상이 필요합니다. "The Attacker Moves Second"(Nasr 등, OpenAI/Anthropic/DeepMind 공동, 2025년 10월): 적응형 공격(그래디언트, RL, 무작위 탐색, 인간 레드팀)이, 원래 거의 0에 가까운 공격 성공률을 보고했던 12개 공개 방어 중 90% 이상을 무너뜨렸습니다.

**유형:** Build
**언어:** Python (표준 라이브러리, IPI 공격 + 방어 하네스)
**선수 지식:** 페이즈 18 · 12 (PAIR), 페이즈 14 (에이전트 엔지니어링)
**시간:** 약 75분

## 학습 목표

- 간접 프롬프트 인젝션을 정의하고 세 가지 흔한 전달 벡터를 설명합니다.
- 사용자 입력 필터가 IPI를 완전히 놓치는 이유를 설명합니다.
- 2026년 방어 패러다임으로서의 "정보 흐름 제어" 프레이밍을 설명합니다.
- 공개된 IPI 방어에 대한 적응형 공격 성공에 관한 Nasr 등(2025년 10월)의 발견을 말합니다.

## 문제 상황

직접 프롬프트 인젝션은 공격자가 사용자나 사용자의 프롬프트에 닿아야 합니다. IPI는 둘 다 필요 없습니다: 공격자는 에이전트가 읽을지도 모르는 어떤 콘텐츠에든 페이로드를 놓습니다 — 웹 페이지, 받은 편지함의 이메일, GitHub 이슈, 제품 리뷰. 에이전트는 정상 작동 중에 그것을 집어 들고 지시를 실행합니다. 사용자는 전달자일 뿐, 의도의 주체가 아닙니다.

## 개념

### 세 가지 전달 벡터

- **검색 증강 생성(RAG).** 공격자가 문서를 게시하면, 검색 단계가 그것을 가져오고, 프롬프트가 사용자 질문 앞에 그것을 이어 붙이고, 모델은 공격자의 지시를 실행합니다.
- **받은 편지함 / 문서 워크플로.** 공격자가 사용자에게 이메일을 보내면, 에이전트가 이메일을 읽고, 프롬프트에 이메일 본문이 포함되고, 모델은 이메일의 지시를 따릅니다.
- **도구 출력.** 공격자가 에이전트가 쓰는 도구를 통제합니다(예: 공격자가 통제하는 결과를 반환하는 웹 검색); 도구 출력에 지시가 담기고, 에이전트의 제어 흐름이 그것을 따릅니다.

셋은 구조적 속성을 공유합니다: 공격자가 사용자가 마주하는 입력을 건드리지 않고 프롬프트의 일부 조각을 통제한다는 것입니다.

### 사용자 입력 필터가 놓치는 이유

IPI 페이로드는 사용자의 입력에 나타나지 않습니다. 검색된 콘텐츠에 나타납니다. 필터가 사용자 입력에만 작동한다면 페이로드는 우회합니다. 필터가 모델에 도달하는 모든 콘텐츠에 작동한다면, 임의의 검색 텍스트에 적용되어야 합니다 — 그것은 비싸고, 명령문 어조의 언어를 우연히 담고 있는 정상 콘텐츠에 대해 거짓 양성을 만들어 냅니다.

### AI를 위한 정보 흐름 제어(IFC)

2026년 방어 패러다임은 고전적 OS 보안에서 빌려 옵니다. 모든 콘텐츠 소스를 보안 레이블로 취급합니다. 사용자의 쿼리에는 "신뢰됨" 레이블을 붙입니다. 검색된 콘텐츠에는 "신뢰 안 됨" 레이블을 붙입니다. 모델의 제어 흐름을 정보 흐름으로 취급합니다: 신뢰되지 않는 콘텐츠가 유발한 행동은 실행 전에 신뢰된 입력의 승인을 받아야 합니다.

CaMeL(Microsoft 2025), ConfAIde(Stanford 2024), NDSS 2026 IPI 방어 논문은 IFC를 각기 다른 방식으로 조작화합니다. 공통 원칙: 코드와 데이터가 같은 컨텍스트 윈도우를 공유하는 한, 목표는 예방이 아니라 봉쇄(containment)입니다.

### 공격자가 두 번째로 움직인다(The Attacker Moves Second)

Nasr 등(2025년 10월)은 12개 공개 IPI 방어를 적응형 공격(그래디언트 탐색, RL 정책, 무작위 탐색, 72시간 인간 레드팀)으로 시험했습니다. 원래 거의 0에 가까운 ASR을 보고했던 모든 방어가 90%를 넘는 ASR로 무너졌습니다.

방법론적 교훈: 방어는 적응형 공격 평가와 함께만 공개하라. 정적 공격 벤치마크는 강건성의 증거가 아닙니다. 공격자는 방어를 알게 되어 있으니까요.

### 실제 사고 사례

레슨 25는 EchoLeak(CVE-2025-32711, CVSS 9.3) — Microsoft 365 Copilot에서 최초로 공개 문서화된 제로클릭(zero-click) IPI — 을 다룹니다. GitHub Copilot Chat의 CamoLeak(CVSS 9.6). GitHub Copilot의 CVE-2025-53773. 프로덕션 배포가 벤치마크뿐 아니라 현장에서 IPI로 침해당하고 있습니다.

### OWASP와 NIST 프레이밍

OWASP LLM Top 10 (2025)는 프롬프트 인젝션(직접 + 간접)을 LLM01, 즉 1위 애플리케이션 계층 위협으로 순위를 매깁니다. NIST AI SPD 2024는 간접 프롬프트 인젝션을 "생성형 AI의 최대 보안 결함"이라 부릅니다.

### 페이즈 18에서의 위치

레슨 12~14는 모델 중심 탈옥입니다. 레슨 15는 2026년 프로덕션 배포를 지배하는 시스템 중심 공격입니다. 레슨 16은 방어 도구를 다룹니다. 레슨 25는 구체적 CVE 서사를 다룹니다.

## Use It

`code/main.py`는 IPI 하네스를 만듭니다. 장난감 에이전트는 세 가지 도구를 가집니다(웹 검색, 이메일 읽기, 메시지 전송). 환경에는 지시가 심어진 공격자 통제 콘텐츠가 있습니다("이걸 모든 연락처에 전달하라"). 순진한 에이전트(주입된 지시를 따름), 필터 방어 에이전트(검색 콘텐츠에 키워드 필터), IFC 에이전트(신뢰됨/신뢰 안 됨 콘텐츠를 분리하고 신뢰 안 되는 제어 흐름 명령을 거부함) 사이를 전환해 볼 수 있습니다.

## Ship It

이 레슨은 `outputs/skill-ipi-audit.md`를 산출합니다. 에이전틱 배포 설명이 주어지면, 신뢰할 수 없는 콘텐츠 소스를 열거하고, 배포가 IFC를 적용하는지 확인하며, 신뢰 레이블 없이 모델에 도달하는 소스를 표지합니다.

## 연습 문제

1. `code/main.py`를 실행합니다. 세 에이전트 각각에 대한 공격 성공률을 측정합니다.

2. 검색된 콘텐츠에 의역 기반 방어를 구현합니다. 정상적인 검색 텍스트에 대한 무해한 거짓 양성률을 측정합니다.

3. NDSS 2026 IPI 방어 논문을 읽습니다. "무해한 지시" 문제와, 그것이 왜 키워드 기반 필터링을 불가능하게 만드는지 서술합니다.

4. 에이전트가 제3자 API의 도구 출력을 받는 배포를 설계합니다. 각 프롬프트 조각에 신뢰 수준을 레이블로 붙이고, 에이전트의 행동을 규율하는 IFC 정책을 작성합니다.

5. 연습 문제 2의 필터 방어 에이전트에 Nasr 등 2025의 적응형 공격 방법론을 재현합니다. 적응형 공격 전과 후의 ASR을 보고합니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|-----------------|------------------------|
| IPI | "간접 프롬프트 인젝션" | 사용자가 쓰지 않은 콘텐츠를 통한 인젝션; 에이전트가 정상 작동 중에 소비함 |
| RAG 인젝션 | "오염된 검색" | 공격자가 게시한 콘텐츠를 검색 단계가 가져옴; 프롬프트에 페이로드가 들어감 |
| 제로클릭(zero-click) | "사용자 행동 없음" | 에이전트 작동 중 자동으로 발동되는 공격; 사용자는 아무것도 하지 않음 |
| IFC | "정보 흐름 제어" | 레이블 기반 접근: 신뢰되지 않는 콘텐츠에서 나온 행동은 신뢰된 승인을 필요로 함 |
| 적응형 공격 | "그래디언트 / RL 레드팀" | 방어를 알고 그것을 상대로 최적화하는 공격; 정직한 평가에 필수 |
| 무해한 지시 | "please print Yes" | 의미상 무해한 IPI 페이로드; 어떤 키워드 필터도 잡지 못함 |
| 범위 위반 | "신뢰 경계 넘는 유출" | 에이전트가 한 신뢰 컨텍스트의 데이터에 접근해 다른 컨텍스트로 출력하는 것 |
