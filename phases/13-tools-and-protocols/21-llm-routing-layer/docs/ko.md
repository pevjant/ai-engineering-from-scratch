# LLM 라우팅 계층 — LiteLLM, OpenRouter, Portkey

> 특정 공급자에게 갇히는 것(lock-in)은 비용이 큽니다. 도구 호출 워크로드마다 어울리는 모델이 다릅니다. 라우팅 게이트웨이는 하나의 API 표면, 재시도, 페일오버, 비용 추적, 가드레일을 제공합니다. 2026년을 지배하는 세 가지 원형이 있습니다: LiteLLM(오픈소스 셀프호스팅), OpenRouter(관리형 SaaS), Portkey(프로덕션 등급, 2026년 3월 오픈소스화). 이 레슨은 결정 기준을 짚고 stdlib 라우팅 게이트웨이를 따라가 봅니다.

**유형:** Learn
**언어:** Python (stdlib, 라우팅 + 페일오버 + 비용 추적기)
**선수 지식:** 페이즈 13 · 02(함수 호출), 페이즈 13 · 17(게이트웨이)
**소요 시간:** 약 45분

## 학습 목표

- 셀프호스팅, 관리형, 프로덕션 등급 라우팅 옵션을 구분할 수 있다.
- 정의된 우선순위 순서로 공급자 실패 시 재시도하는 폴백 체인을 구현할 수 있다.
- 공급자를 넘나드는 요청별 비용과 토큰 사용량을 추적할 수 있다.
- 주어진 프로덕션(운영 환경) 제약에 대해 LiteLLM, OpenRouter, Portkey 중 하나를 고를 수 있다.

## 문제 상황

공급자 라우팅이 중요해지는 시나리오:

1. **비용.** Claude Sonnet은 Haiku의 3배 가격입니다. 분류(triage) 작업에는 Haiku면 충분하고, 종합(synthesis) 작업에는 Sonnet이 값어치를 합니다. 요청별로 라우팅하세요.

2. **페일오버.** OpenAI에 좋지 않은 한 시간이 옵니다. 모든 요청이 실패합니다. 재배포 없이 Anthropic으로 자동 폴백되길 원합니다.

3. **지연 시간.** 실시간 채팅 UI는 첫 토큰까지 빨리 도달해야 합니다. 배치 요약기는 그렇지 않습니다. 지연 시간 SLA로 라우팅하세요.

4. **컴플라이언스(규제 준수).** EU 사용자는 EU 리전에 머물러야 합니다. 리전으로 라우팅하세요.

5. **실험.** 같은 워크로드에서 두 모델을 A/B 테스트합니다. 테스트 버킷으로 라우팅하세요.

이 모든 것을 통합마다 손으로 코딩하는 것은 반복 노동입니다. 라우팅 게이트웨이는 하나의 OpenAI 호환 API를 주고 나머지는 알아서 처리합니다.

## 개념

### OpenAI 호환 프록시 형태

모두가 OpenAI 형태를 말합니다. 라우팅 게이트웨이는 `/v1/chat/completions`를 노출하고, OpenAI 스키마를 받아들이고, 내부적으로 Anthropic / Gemini / Cohere / Ollama / 무엇이든 프록시합니다. 클라이언트는 신경 쓸 필요가 없습니다.

### 모델 별칭(alias)

고정된 스냅샷 id 대신 코드가 `our_smart_model`이라 말합니다. 게이트웨이가 별칭을 실제 모델로 매핑합니다. 공급자가 새 세대를 출시하면 별칭만 서버 측에서 바꾸면 됩니다. 코드는 아무것도 건드리지 않습니다.

### 폴백 체인

```
primary: openai/gpt-4o
on 5xx: anthropic/claude-3-5-sonnet
on 5xx: google/gemini-1.5-pro
on 5xx: refuse
```

게이트웨이는 이것을 구성(config)으로 정의합니다. 재시도는 예산 안에서 세어지므로 폴백 연쇄가 비용을 폭발시키지 않습니다.

### 시맨틱 캐싱

동일하거나 거의 동일한 프롬프트는 공급자 대신 캐시에 걸립니다. 반복되는 에이전트 루프에서 30~60퍼센트의 절감이 가능합니다. 키는 임베딩 기반이며, 거의 동일한 프롬프트는 같은 캐시 슬롯을 공유합니다.

### 가드레일

게이트웨이 수준:

- **PII 마스킹.** 프롬프트를 보내기 전에 정규식 또는 ML 기반 처리를 통과.
- **정책 위반.** 금지된 콘텐츠가 담긴 프롬프트를 거부.
- **출력 필터.** 유출이 있는 완성문을 걷어냄.

Portkey와 Kong은 독단적인(opinionated) 가드레일을 함께 제공합니다. LiteLLM은 선택 사항으로 남겨 둡니다.

### 키별 속도 제한

API 키 하나 = 한 팀. 키별 예산이 한 팀이 공유 쿼터를 다 먹어 치우는 것을 막습니다. 대부분의 게이트웨이가 이것을 지원합니다.

### 셀프호스팅 vs 관리형 트레이드오프

| 요소 | LiteLLM (셀프호스팅) | OpenRouter (관리형) | Portkey (프로덕션) |
|--------|----------------------|----------------------|----------------------|
| 코드 | 오픈소스, Python | 관리형 SaaS | 오픈소스(2026년 3월) + 관리형 |
| 설정 | 프록시 배포 | 가입 | 어느 쪽이든 |
| 공급자 | 100+ | 300+ | 100+ |
| 결제 | 내 키 사용 | OpenRouter 크레딧 | 내 키 사용 |
| 관측 가능성 | OpenTelemetry | 대시보드 | 풀 OTel + PII 마스킹 |
| 최적 용도 | 완전한 통제를 원하는 팀 | 빠른 프로토타이핑 | 컴플라이언스가 필요한 프로덕션 |

SRE 팀이 있고 데이터 주권을 원한다면 LiteLLM이 이깁니다. 구독 하나와 인프라 없음을 원한다면 OpenRouter가 이깁니다. 가드레일과 컴플라이언스를 기본으로 갖추고 싶다면 Portkey가 이깁니다.

### 비용 추적

모든 요청은 `provider`, `model`, `input_tokens`, `output_tokens`를 실습니다. 모델별 토큰당 가격(게이트웨이가 관리하는 가격표에서 끌어 온 것)을 곱합니다. 사용자별 / 팀별 / 프로젝트별 집계.

### MCP 더하기 라우팅

게이트웨이는 LLM 호출과 MCP 샘플링 요청을 모두 라우팅할 수 있습니다. 샘플링 요청의 modelPreferences가 특정 모델을 선호하면, 게이트웨이가 그것을 올바른 백엔드로 번역합니다. 페이즈 13 · 17(MCP 게이트웨이)과 이 레슨의 라우팅 게이트웨이가 하나의 서비스로 합쳐지는 지점이 바로 여기입니다.

### 라우팅 전략

- **정적 우선순위.** 목록의 첫 번째; 에러 시 폴백.
- **부하 분산.** 라운드 로빈 또는 가중치 기반.
- **비용 인지.** 지연 시간 / 품질을 만족하는 가장 싼 모델을 고름.
- **지연 시간 인지.** 최근 N분에서 가장 빠른 모델을 고름.
- **작업 인지.** 프롬프트 분류기가 코딩은 한 모델로, 요약은 다른 모델로 라우팅.

```figure
tp-router-failover
```

## 활용하기

`code/main.py`는 약 150줄짜리 라우팅 게이트웨이를 구현합니다: OpenAI 형태의 요청을 받아들이고, 공급자별 스텁으로 번역하고, 우선순위 폴백 체인을 돌리고, 요청별 비용을 추적하고, 입력에 PII 마스킹 처리를 적용합니다. 세 가지 시나리오로 실행하세요: 평범한 요청, 기본 공급자 장애로 폴백이 트리거되는 경우, 마스킹에 걸린 PII 유출.

볼 지점:

- `ROUTES` 딕셔너리: 별칭 -> 우선순위 정렬된 구체적 공급자 목록.
- 폴백 루프가 5xx에서 재시도합니다.
- 비용 추적기가 토큰 사용량에 모델별 단가를 곱합니다.
- PII 마스커가 전달 전에 SSN 형태 패턴을 걷어냅니다.

## 출시하기

이 레슨은 `outputs/skill-routing-config-designer.md`를 산출합니다. 워크로드 프로필(지연 시간, 비용, 컴플라이언스)이 주어지면, 이 스킬은 LiteLLM / OpenRouter / Portkey 중 고르고 라우팅 구성을 산출합니다.

## 연습 문제

1. `code/main.py`를 실행하세요. 장애 시나리오를 트리거하고, 폴백이 두 번째 공급자에 안착하고 비용이 올바르게 귀속되는지 확인하세요.

2. 시맨틱 캐싱을 추가하세요: 프롬프트의 SHA256이 조회 키이고, 캐시 히트는 즉시 돌아갑니다. 반복 호출에서 비용 절감을 측정하세요.

3. 프롬프트 분류기를 추가하세요. "code ..." 프롬프트는 지능을 선호하는 별칭으로, "summarize ..." 프롬프트는 속도를 선호하는 별칭으로 라우팅합니다.

4. 팀별 예산을 설계하세요: 각 팀에 월 지출 상한이 있고, 상한에 도달하면 게이트웨이가 요청을 거부합니다. 집행 세분성(요청별 또는 윈도우 방식)을 고르세요.

5. LiteLLM, OpenRouter, Portkey 문서를 나란히 읽으세요. 셋 중 자기것만 출시하는 기능을 각각 하나씩 말하세요.
