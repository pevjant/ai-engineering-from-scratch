# 이식 가능한 계약 체크리스트

- 번들은 일반 `SKILL.md` 파일을 담은 디렉터리여야 합니다.
- 프론트매터는 첫 줄에서 시작하고 닫는 구분자가 있어야 합니다.
- `name`이 있어야 하고, 64자를 넘지 않으며, 소문자·숫자·단일 하이픈만 사용해야 합니다.
- `name`은 번들 디렉터리 이름과 일치해야 합니다.
- `description`이 있어야 하고, 1024자를 넘지 않으며, 스킬이 언제 유용한지 밝혀야 합니다.
- 선택적인 `compatibility`는 있을 경우 1~500자여야 합니다.
- 선택적인 `metadata`는 문자열 키에 문자열 값을 대응시켜야 합니다.
- 선택적인 실험적 `allowed-tools`는 비어 있지 않은 공백 구분 문자열이어야 하고, 그 동작은 대상 호스트에서 검증되어야 합니다.
- 알 수 없는 런타임 필드는 이식 가능한 패키지 계약과 분리되고, 명시적인 어댑터로 처리되어야 합니다.
- Markdown 본문에 절차가 들어 있어야 합니다.
- 선택적인 이식 가능 메타데이터와 호스트 전용 확장이 서로 구별 가능한 상태로 유지되어야 합니다.

이 체크리스트를 통과하면 패키지가 구조적으로 로드 가능해집니다. 그렇다고 파일시스템, 네트워크, 시크릿, 서브프로세스, 도구 권한이 생기는 것은 아닙니다.
