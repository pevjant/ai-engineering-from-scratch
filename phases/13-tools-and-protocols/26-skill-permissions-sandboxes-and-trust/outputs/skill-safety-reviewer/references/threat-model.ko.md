# 위협 모델

다음 경계들을 독립적으로 검토하세요:

- 권한: 지침은 호스트 권한을 다시 쓸 수 없습니다.
- 파일시스템: 대상을 해석하고 작업 공간 루트 안에 가둡니다. 심볼릭 링크 탈출을 거부합니다.
- 명령: argv 배열만 받고, 셸 메타문자와 파괴적인 실행 파일은 거부하며, 실행 파일 허용 목록을 요구합니다.
- 네트워크: HTTPS와 정확한 오리진 허용 목록을 요구합니다. 실효 포트를 정규화합니다. 그래서 `https://api.example.test`와 `https://api.example.test:443`은 매칭되고, `8443` 포트는 자체 항목이 필요합니다. URL userinfo에 담긴 자격 증명은 받지 않습니다.
- 외부 콘텐츠: 가져온 텍스트는 데이터로 취급하고, 절대 정책이나 승인으로 취급하지 않습니다.
- 시크릿: 값을 로그에 남기지 않으면서 시크릿이 담겼을 가능성이 있는 페이로드를 탐지합니다.
- 파괴적 행동: 호스트 정책에 따라 거부하거나, 기록된 사람의 승인을 요구합니다.

`allow` 판정은 시뮬레이션된 요청이 공급된 정책을 충족한다는 뜻일 뿐입니다. 이 번들은 어떤 행동도 실행하지 않습니다.
