# 호출 모델

| 통로 | 시작자 | 선택 방식 | 전형적인 용도 |
|---|---|---|---|
| 명시적 사람 | 사용자 | 정확히 발견된 이름 | 의도적인 워크플로 선택 |
| 암시적 모델 또는 에이전트 | 모델 또는 자율 에이전트 | description 관련성 + 호스트 정책 | 컨텍스트 민감 라우팅 |
| 프로그래밍 방식 애플리케이션 | 제품 런타임 | 설정된 정확한 이름과 대상 허용 목록 | 결정론적 제품 워크플로 |
| 스킬 조합 | 다른 스킬 또는 서브에이전트 | 정확한 대상, 호출자 신원, 깊이 정책 | 한정된 워크플로 의존성 |
| 프로그래밍 방식 하네스 | 평가 런타임 | 설정된 정확한 이름과 대상 허용 목록 | 결정론적 평가 |

사람과 모델의 활성화는 2x2를 이룹니다. 둘 다 아니요, 사람만, 모델만, 둘 다 예. 애플리케이션, 조합, 하네스 활성화는 대상·호출자·깊이 정책을 따로 가진 별개의 통로입니다.

암시적 라우팅에서는 관련성 순위 매기기 전에 행위자와 호스트 확장 자격을 적용합니다. 점수가 높은 차단된 스킬은 승자가 아닙니다. 선택 집합에서 제거하고 남은 자격 후보를 평가하세요. 자격 집합이 비었거나 최고 점수가 임계값에 못 미치면 기권합니다.

`user-invocable`이나 `disable-model-invocation` 같은 필드는 특정 호스트에서 의미가 있을 수 있습니다. 어댑터가 이를 강제할 수는 있지만, 이식 가능한 문서가 모든 런타임이 같은 필드나 값을 인식한다고 주장해서는 안 됩니다.
