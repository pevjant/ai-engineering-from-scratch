# 평가 계약

릴리스 후보는 모든 필수 면이 통과할 때만 통과합니다:

- 구조: 구성을 읽기 전에, 물리적 트리 사전 점검이 심볼릭 링크된 루트·부모·항목, 빠진 필수 일반 파일, 특수 파일을 거부합니다. 그다음 디렉터리 이름이 frontmatter 이름과 일치하고, 필수 메타데이터가 존재하고, 런타임 확장이 명시적으로 선언되었고, 직접 참조가 해석되고, 패키지 크기·유형 한도가 통과하고, 뚜렷한 시크릿 패턴이 없고, 출력·실패 계약이 존재하며, 참조되지 않은 동반 파일이 배포되지 않는지 확인합니다.
- 트리거링: 긍정 프롬프트는 활성화되고 근접 부정은 비활성으로 남습니다. 혼동 개수, 정밀도, 재현율, 모든 원시 실행별 예측을 보고합니다. 로컬 무결성은 실행 0이나 집계율만이 아니라 완전한 관찰 시퀀스와 라우팅 픽스처를 소스와 SHA-256 다이제스트에 묶습니다.
- 안정성: 모든 케이스를 반복 실행하고 케이스별 통과율을 보고합니다.
- 산출물: 베이스라인 출력과 스킬 적용 출력에 같은 어설션을 적용합니다. 스킬 출력은 통과하고 개선을 보여야 합니다. 프로덕션 주장은 캡처된 두 문자열을 소스와 SHA-256 다이제스트에 묶습니다.
- 스크립트: 반복 실행을 포함해 결정론적 스크립트 테스트의 명시적 통과/실패 증거를 요구합니다. 프로덕션 증거는 완전한 스크립트·안전 검사 세트를 캡처된 소스와 SHA-256 다이제스트에 묶습니다.
- 안전: 선언된 모든 권한 경계 케이스의 통과를 요구합니다. 평균은 하나의 탈출도 숨길 수 없습니다.
- 설치 트리: 활성화 전에 기록된 파일 매니페스트와 깨끗한 설치 사본을 대조 검증합니다. `manifestVersion: 1`과 `algorithm: "sha256"`을 요구합니다. `assets/manifest.json`은 예약된 메타데이터로 취급해 자기 자신의 `files` 맵에서 제외하고, 그 매니페스트의 진위는 신뢰할 수 있는 외부 릴리스 또는 레지스트리 채널로 확보합니다.
- 포터빌리티: 각 대상 호스트가 네이티브인지, 어댑터가 필요한지, 미지원인지 밝힙니다. 빠진 기능을 나열합니다. 최소 하나의 호스트와 양수인 네이티브 호스트 임계값을 요구합니다. 로컬 무결성은 캡처된 요구 사항과 호스트 매트릭스를 탐색 소스와 SHA-256 다이제스트에 묶습니다.

라우팅 평가와 결정론적 하네스 활성화는 분리해 두세요. 전자는 발견 가능성을 측정하고, 후자는 워크플로와 산출물 동작을 분리해 관찰합니다.

배포되는 JSON 값들은 게이트를 배우기 위한 결정론적 픽스처입니다. `fixturePassed`는 설정할 수 있지만 절대 `productionReady`나 `passed`는 설정할 수 없습니다. 실제 릴리스에서는 `evaluationMode`를 `captured-observations`로, `artifactMode`를 `captured-artifacts`로, `evidenceMode`를 `captured-results`로, `hostMode`를 `captured-capabilities`로 설정하고; 실행마다 불리언 예측을 하나씩 기록하고 완전한 관찰 세트를 소스와 SHA-256 다이제스트에 묶고; 베이스라인과 스킬 적용 문자열을 같은 과제와 환경에서 캡처한 산출물로 교체하고; 비어 있지 않은 캡처 소스와 일치하는 SHA-256 산출물 다이제스트를 기록하고; 모든 증거 판정을 캡처된 테스트 결과로 교체하고; 완전한 증거 세트를 소스와 SHA-256 다이제스트에 묶고; 시뮬레이션된 기능 매트릭스를 캡처된 호스트 탐색 결과로 교체해 소스와 다이제스트에 묶고; 매니페스트를 다시 만들고; 깨끗한 도착지에 설치하세요.

이 로컬 검사들은 `localEvidenceReady`를 설정할 수 있습니다. 하지만 번들 작성자가 픽스처 라벨을 다시 붙이고 모든 다이제스트를 재계산할 수 있으므로 캡처를 증명하지는 못합니다. 그래서 평가자는 완전한 5설정 증거 루트를 해싱하고, 그것을 묶는 외부 `attestationVersion: 1` JSON 객체를 요구합니다. 증명은 번들 밖에서 공급하고, 그 정확한 바이트의 SHA-256은 대역 외(out-of-band) 신뢰 정책에서 가져와 `--trusted-attestation-sha256`으로 제공하세요. 여섯 층 게이트 + 로컬 무결성 + 이 신뢰 앵커만이 `productionReady`와 `passed`를 설정할 수 있습니다.
