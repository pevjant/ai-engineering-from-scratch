MCP 클라이언트, 서버, 게이트웨이, SDK, 트랜스포트 중 무언가가 바뀌었을 때, 와이어 수준 적합성 스위트와 함께 레닥션된 증거에 기반한 릴리스 결정을 만들어 냅니다.

## 필수 입력

- 지원하는 최신·레거시 프로토콜 버전, 그리고 배포 대상별 정책
- SDK 디코딩 전의 raw 요청·응답 캡처 지점
- 미러링된 HTTP 헤더, JSON-RPC 본문, 상태 코드, 콘텐츠 타입, 중개자 토폴로지
- 광고된 클라이언트·서버·확장 기능(capabilities)
- SDK 이름, 버전, 정규화된 값, 예외
- 헬스 임계값, 카나리 윈도우, 최소 샘플 수, 베이스라인 측정값
- 정확한 롤백 버전, 입장 심사 증거 다이제스트, SHA-256 아티팩트·설명자 핀, 레지스트리 상태, 현재 헬스, 신뢰할 수 있는 릴리스 서명자, 롤백 페이로드 전체에 대한 증명서
- 레닥션·보존·증거 접근 정책

## 절차

1. 프로토콜 시대를 명시적으로 정의합니다. 최신 분기에서는 정확한 `io.modelcontextprotocol/protocolVersion`과 `io.modelcontextprotocol/clientCapabilities` 키를 요구합니다. `2025-11-25`까지의 초기화 시대 동작은 별도의 레거시 어댑터로 분리합니다.
2. 대상별로 엄격 모드 또는 범위가 제한된 폴백 정책을 고릅니다. 성공한 `server/discover`나 알려진 최신 오류는 최신 분기의 증거입니다. 타임아웃이나 빈 응답은 아무것도 증명하지 못합니다. 레거시 프로브는 설정되었거나 허용 목록에 오른 엔드포인트에만 허용하고, 핀된 레거시 리비전에 대한 긍정적인 `initialize` 결과를 검증한 뒤에만 레거시를 선택합니다. `-32020`, `-32021`, `-32022` 뒤에는 절대 다운그레이드하지 않습니다.
3. 받아들여지는 요청, 유효한 메서드별 결과, 광고된 확장 결과, 선택된 레거시 동작, 그리고 "알림에는 응답하지 않는다"는 불변식에 대한 골든 트랜스크립트를 만듭니다.
4. 잘못된 봉투, 응답 버전·ID 불일치, result·error 상호 배타성, 잘못된 오류, 잘못된 HTTP 매핑, 누락된 메타데이터, 헤더·본문 불일치, 누락된 서버 오류 응답, 미지원 버전, 누락된 최신 `resultType`, 잘못된 메서드 페이로드, 알 수 없거나 광고되지 않은 결과 타입, 금지된 알림 응답에 대한 네거티브 트랜스크립트를 만듭니다. 로컬 검증이 `HeaderMismatch`를 관측하면 항상 실제 HTTP 400 JSON-RPC `-32020` 응답을 요구하고 구조적으로 검증합니다. 로컬 예외만으로는 그 케이스를 절대 통과시키지 않습니다.
5. JSON-RPC 메타데이터 타입을 먼저 검증합니다. HTTP 헤더 이름은 대소문자 구별 없이 매칭하고, 충돌하는 중복은 거부하고, 안전하지 않은 `Mcp-Name` 값은 정확한 Base64 센티널로 디코딩한 뒤, 매칭된 값의 지원 여부를 확인하기 전에 `MCP-Protocol-Version`, `Mcp-Method`, 해당하는 `Mcp-Name` 값을 본문과 비교합니다. 앞뒤 공백은 안전하지 않은 것으로 취급하며, 본문 값과 같더라도 raw로 전송되면 거부합니다.
6. 알려진 최신 `complete`와 `input_required` 결과는 받아들입니다. 확장 판별자는 그 기능이 광고된 경우에만 받아들입니다. 알 수 없거나 광고되지 않은 `resultType`은 모두 거부합니다. 그다음 메서드 페이로드를 검증합니다. `tools/list`의 완전한 도구 설명자, task 결과의 필수 라이프사이클 필드, `completion/complete`의 개수가 제한된 문자열 값 completion 객체가 여기에 포함됩니다.
7. raw 상태의 추가된 result·`_meta` 필드를 증거에 보존합니다. 각 컴포넌트가 그것들을 무시해도 되는지 전달해야 하는지 명시적으로 결정합니다.
8. 위험도가 높은 모든 트랜스크립트를 출시하는 각 SDK로 실행합니다. raw 와이어 의미와 정규화된 반환값을 비교하고, 만들어지거나 옮겨 담아지거나 제거되거나 바뀐 모든 필드를 보고합니다.
9. 스위트를 직접 실행과 모든 프로덕션 중개자 경유 실행 양쪽으로 돌립니다. 레닥션된 인그레스·오리진·이그레스 증거를 캡처합니다. 상태 뭉개기, JSON-RPC 본문 재작성, 라우팅 헤더 불일치, 버퍼링, 콘텐츠 협상 변화를 탐지합니다.
10. 직렬화, 해싱, 로깅, 업로드 전에 레닥션을 적용합니다. 필드·헤더 이름의 대소문자를 통일하고 구분 기호를 제거해서 camelCase, 하이픈, 밑줄, 점 변형이 같은 거부 목록을 공유하게 한 뒤, `Authorization`, `Set-Cookie`, `X-Api-Key`, `accessToken`, `clientSecret`, `registrationAccessToken` 같은 자격 증명과 메서드별 민감 인자를 제거합니다. 레닥션된 증거 번들을 해시합니다.
11. 후보를 비어 있지 않은 결정적 트랜스크립트·SDK 차이 비교·프록시 증거와, 최소 샘플 수가 양수인 미리 선언된 헬스 윈도우로 평가합니다. 모든 소스에서 유효한 증거 다이제스트를 요구합니다. 생략된 경계는 통과한 빈 목록이 아니라 게이트 실패입니다.
12. 승격 전에 정확하게 입장 심사되고, 핀되고, 활성화되고, 건강한 롤백 대상을 검증합니다. 정확한 필드 타입과 SHA-256 다이제스트를 검증한 뒤, 신뢰할 수 있는 릴리스 컨트롤러 신원과 대조해 증명서를 암호학적으로 검증합니다. 적합성·SDK·프록시·헬스·롤백 준비 증거가 모두 통과할 때만 승격합니다. 후보가 실패하면 그 검증된 대상으로만 롤백하고, 그렇지 않으면 hold(대기)합니다.

## 필수 매트릭스

모든 케이스마다 다음을 보고합니다:

- 안정적인 케이스 이름과 규범적 불변식
- 프로토콜 시대와 선택 증거
- 클라이언트·서버·SDK·프록시·빌드 버전
- 기대 상태, 응답 형태, 결과 타입 또는 오류 코드
- 관측된 인그레스·오리진·이그레스 증거 다이제스트
- SDK 정규화 차이
- 각 경계에서의 통과·실패
- 레닥션 정책 버전
- 최종 사유 코드

최소한 다음 케이스들을 포함합니다:

- 골든: 최신 discovery 또는 메서드 호출
- 골든: 추가 필드가 있는 알려진 완료 결과
- 골든: 선택된 레거시 시대에서 `resultType`이 없는 레거시 결과
- 골든: 광고된 확장 결과
- 골든: 유효한 `completion/complete` 결과
- 골든: JSON-RPC 응답이 없는 알림
- 네거티브: 헤더·본문 불일치
- 네거티브: 기능 누락
- 네거티브: 매칭됐지만 미지원 버전
- 네거티브: 최신 `resultType` 누락
- 네거티브: 알 수 없거나 광고되지 않은 `resultType`
- 네거티브: 프록시의 상태·본문 변형
- 네거티브: SDK의 의미 필드 손실
- 네거티브: 잘못된 `completion/complete` 결과

## 절대 거부 항목

- raw 와이어 증거 없이 SDK 반환값만으로 적합성을 주장하는 것
- 최신과 레거시 형태를 조용히 모두 받아 주는 파서 하나
- 알려진 최신 오류 뒤의 레거시 폴백
- 타임아웃, 침묵, 연결 종료, 알 수 없는 응답만 근거로 한 레거시 폴백
- 서버 오류 응답을 캡처·검증하지 않고 네거티브 요청 케이스를 통과시키는 것
- 로컬 `HeaderMismatch` 탐지 뒤에 HTTP 400 JSON-RPC `-32020` 증거를 선택 사항으로 만드는 것
- 레거시 시대를 선택하기 전에 누락된 `resultType`을 완료로 추론하는 것
- 알 수 없는 판별자를 완료로 취급하는 것
- 예약 필드 사유 없이 추가된 알 수 없는 필드를 전부 거부하는 것
- 알림에 어떤 JSON-RPC 응답이든 보내는 것
- 메서드별 페이로드를 검증하지 않고 알려진 `resultType`을 받아들이는 것
- 본문과의 일치를 확인하지 않고 미러링된 헤더를 승인하는 것
- HTTP 필드 이름을 대소문자를 구별하는 것으로 취급하거나, 정확한 센티널 디코딩 없이 인코딩된 `Mcp-Name`을 비교하는 것
- 센티널 인코딩을 요구하는 대신 앞뒤 공백이 있는 raw `Mcp-Name`을 받아들이는 것
- 유효한 개수 제한 문자열 값 completion 객체 없이 completion 결과를 받아들이는 것
- 프록시가 만든 500을 오리진 프로토콜 오류와 동일하게 취급하는 것
- 베어러 토큰, 쿠키, 시크릿, 민감 인자를 증거에 기록하는 것
- camelCase나 구분 기호 변형이 정규 자격 증명 거부 목록을 우회할 수 있는 레닥션 정규화를 사용하는 것
- 샘플 0개짜리 카나리를 건강하다고 선언하는 것
- 비어 있는 트랜스크립트·SDK·프록시 증거를 통과한 경계로 취급하는 것
- 참 같은 문자열이나 인증되지 않은 롤백 딕셔너리를 검증된 증거로 취급하는 것
- 정확한 입장 심사·핀·상태·헬스 증거 없이 버전으로 롤백하는 것
- 건강한 롤백 대상을 증명하기 전에 프로덕션 후보를 승격하는 것

## 산출 형식

다음 섹션들을 반환합니다:

1. 시대 정책(Era Policy): 최신 증명, 엄격 대상, 범위가 제한된 폴백 트리거, 금지된 다운그레이드 신호
2. 트랜스크립트 매트릭스(Transcript Matrix): 기대되는 와이어 결과를 갖춘 골든·네거티브 케이스
3. 결과 호환성(Result Compatibility): 핵심 판별자, 광고된 확장, 추가 필드 정책, 레거시 추론 경계
4. SDK 차이 비교(SDK Differential): raw·정규화 다이제스트와 옮겨 담아지거나 제거되거나 만들어지거나 바뀐 필드
5. 프록시 증거(Proxy Evidence): 실패한 정확한 홉과 함께하는 인그레스·오리진·이그레스 결과
6. 레닥션 보고서(Redaction Report): 정책 버전, 제거된 필드 클래스, 레닥션된 증거 다이제스트
7. 헬스 윈도우(Health Window): 샘플, 오류율, 지연 시간, 포화도, 지속 시간, 임계값, 베이스라인 비교
8. 롤백 증명(Rollback Proof): 정확한 대상, 입장 심사 다이제스트, 핀, 레지스트리 상태, 헬스, 서명자 신원, 검증된 증명서, 라우트 복원 계획
9. 결정(Decision): 안정적인 사유 코드와 완전한 증거 다이제스트와 함께 `promote`, `hold`, `rollback` 중 하나

첫 번째로 실패한 경계로 끝냅니다. 모든 경계가 통과했다면 전면 승격을 허가하는 카나리 완료 조건을 명시합니다.
