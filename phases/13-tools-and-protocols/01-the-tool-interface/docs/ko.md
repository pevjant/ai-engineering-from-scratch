# 도구 인터페이스 — 에이전트에는 왜 구조화된 입출력이 필요한가

> 언어 모델은 토큰을 만들어 냅니다. 프로그램은 행동을 합니다. 이 둘 사이의 간격을 메워 주는 것이 바로 도구 인터페이스입니다. 다시 말해 모델이 행동을 요청하고 호스트가 그 행동을 실행하게 해 주는 약속(계약)이죠. 2026년의 모든 스택 — OpenAI, Anthropic, Gemini의 함수 호출, MCP의 `tools/call`, A2A의 태스크 파트 — 은 결국 같은 4단계 루프를 각자 다른 방식으로 인코딩한 것입니다. 이 레슨은 그 루프에 이름을 붙이고, 루프를 돌리기 위해 꼭 필요한 최소한의 장치를 보여 줍니다.

**유형:** Learn(학습)
**언어:** Python(표준 라이브러리만 사용, LLM 없음)
**선수 지식:** 페이즈 11(LLM 완성 API)
**시간:** 약 45분

## 학습 목표

- 텍스트 생성만 가능한 LLM이 그 자체만으로는 현실 세계에 대한 행동을 할 수 없는 이유를 설명할 수 있습니다.
- 4단계 도구 호출 루프(describe → decide → execute → observe)를 그리고, 각 단계를 누가 담당하는지 말할 수 있습니다.
- 도구 설명을 세 부분 — 이름, JSON Schema 입력, 결정론적 실행기(executor) 함수 — 로 작성할 수 있습니다.
- 순수(pure) 도구와 부수 효과가 있는 도구를 구분하고, 이 구분이 안전 면에서 왜 중요한지 말할 수 있습니다.

## 문제

LLM은 다음 토큰에 대한 확률 분포를 내놓는 것이 전부입니다. 그것이 LLM의 출력 표면 전부죠. 챗 모델에게 "지금 벵갈루루 날씨가 어때?"라고 물으면 그럴듯한 문장은 써 줄 수 있어도, 날씨 API에 전화를 걸 수는 없습니다. 그 문장은 우연히 맞았을 수도 있고, 사흘 전의 낡은 정보일 수도 있습니다.

이 간격을 메우는 것이 도구 인터페이스의 목적입니다. 호스트 프로그램 — 여러분의 에이전트 런타임, Claude Desktop, ChatGPT, Cursor, 또는 직접 만든 스크립트 — 는 호출 가능한 도구 목록을 모델에게 알려 줍니다. 모델은 행동이 필요하다고 판단하면 도구 이름과 인자를 담은 구조화된 페이로드를 내보냅니다. 호스트는 그 페이로드를 해석해 실제로 도구를 실행하고, 그 결과를 다시 모델에게 먹여 줍니다. 이 루프는 모델이 더 이상 호출이 필요 없다고 판단할 때까지 계속됩니다.

이 계약의 첫 버전은 2023년 6월 OpenAI의 "functions" 파라미터로 세상에 나왔습니다. Anthropic이 Claude 2.1에서 `tool_use` 블록으로 뒤따랐고, Gemini는 몇 달 뒤 `functionDeclarations`를 추가했습니다. 이제 모든 프로바이더가 같은 모양을 노출합니다. JSON Schema로 타입이 지정된 도구 목록을 넣으면, JSON 페이로드 형태의 도구 호출이 나오는 것이죠. MCP(Model Context Protocol, 2024년 11월)는 이 계약을 일반화해서 하나의 도구 레지스트리로 모든 모델을 서빙할 수 있게 했습니다. A2A(2026년 4월, v1.0)는 같은 원시 기능(primitive)을 에이전트 간 위임용으로 한 층 더 얹었습니다.

4단계 루프는 이 모든 것의 밑바닥에 깔린 불변의 구조입니다. 페이즈 13의 나머지 전부는 이 루프의 확장판입니다.

## 개념

### 1단계: describe(기술하기)

호스트는 각 도구를 세 필드로 선언합니다.

- **이름.** 안정적이고 기계가 읽을 수 있는 식별자. "weather thing"이 아니라 `get_weather`여야 합니다.
- **설명.** 한 문단짜리 자연어 브리핑. "사용자가 특정 도시의 현재 상황을 물을 때 사용. 과거 데이터에는 사용하지 말 것."
- **입력 스키마.** 도구의 인자를 기술하는 JSON Schema 객체(draft 2020-12).

모델은 이 목록을 받습니다. 최근 프로바이더들은 이 선언들을 프로바이더 고유의 템플릿으로 시스템 프롬프트에 직렬화해 넣어 주기 때문에, 호출자인 여러분은 구조화된 형태만 다루면 됩니다.

### 2단계: decide(결정하기)

사용자 메시지와 사용 가능한 도구가 주어지면, 모델은 세 가지 행동 중 하나를 고릅니다.

1. **텍스트로 바로 답합니다.** 도구 호출 없음.
2. **하나 이상의 도구를 호출합니다.** 구조화된 호출 객체를 내보냅니다. `parallel_tool_calls: true`(OpenAI와 Gemini는 기본값, Anthropic은 옵트인)이면 모델이 한 턴에 여러 개의 호출을 내보낼 수 있습니다.
3. **거절합니다.** strict 모드의 구조화된 출력은 호출 대신 타입이 지정된 `refusal` 블록을 만들어 낼 수 있습니다.

도구 호출 페이로드에는 안정적인 필드가 셋 있습니다. 호출 `id`, 도구 `name`, 그리고 JSON `arguments` 객체죠. id가 존재하는 이유는 호스트가 나중에 결과를 특정 호출과 연결 짓기 위함인데, 병렬 호출의 결과가 순서가 뒤엉켜 도착할 때 이게 중요해집니다.

### 3단계: execute(실행하기)

호스트는 호출을 받아 선언된 스키마를 기준으로 인자를 검증하고, 실행기를 돌립니다. 인자가 잘못됐다는 것은 모델이 필드를 환각했거나 타입을 잘못 썼다는 뜻인데, 약한 모델에서 아주 흔한 실패 양상입니다. 프로덕션(운영 환경)의 호스트는 잘못된 인자를 만나면 셋 중 하나를 합니다. 실패를 즉시 인정하고 에러를 모델에게 보여 주거나, 제약 파서로 JSON을 고치거나, 검증 에러를 프롬프트에 포함해 모델을 다시 호출합니다.

실행기 자체는 평범한 코드입니다. Python, TypeScript, 셸 명령, 데이터베이스 쿼리 등이죠. 실행기는 결과를 만들어 내는데, 보통 문자열이지만 어떤 JSON 값이든 될 수 있고 구조화된 콘텐츠 블록(MCP에서는 텍스트, 이미지, 리소스 참조)일 수도 있습니다. 결과는 반드시 직렬화 가능해야 합니다.

### 4단계: observe(관찰하기)

호스트는 도구 결과를 대화에 추가하고(`id`가 맞는 `tool` 역할 메시지로) 모델을 다시 호출합니다. 이제 모델은 컨텍스트 안에 도구 출력을 가지고 있으므로 최종 답을 내거나 호출을 더 요청할 수 있습니다. 모델이 호출을 멈추거나, 호스트가 반복 횟수 안전 한도에 도달할 때까지 이 과정이 반복됩니다.

### 신뢰의 구분

도구는 안전 면에서 중요한 두 가지 부류로 나뉩니다.

- **순수(pure).** 읽기 전용, 결정론적, 부수 효과 없음. `get_weather`, `search_docs`, `get_current_time`. 탐색 삼아 호출해도 안전합니다.
- **결과가 큰(consequential).** 상태를 바꾸고, 돈을 쓰고, 사용자 데이터를 만집니다. `send_email`, `delete_file`, `execute_trade`. 반드시 게이트(gate)를 두어야 합니다.

Meta의 2026년 에이전트 보안 "Rule of Two"에 따르면 한 턴은 신뢰할 수 없는 입력, 민감한 데이터, 결과가 큰 행동이라는 셋 중 최대 두 가지만 결합할 수 있습니다. 도구 인터페이스가 바로 이 규칙을 강제하는 자리입니다. 호출을 거부하거나, 사용자 확인을 요구하거나, 권한 범위를 상승시키는 방식으로요. 전체 보안 챕터는 페이즈 13 · 15를, 에이전트 수준 권한 정책은 페이즈 14 · 09를 보세요.

### 루프는 어디에 사는가

| 맥락 | 누가 기술하는가 | 누가 결정하는가 | 누가 실행하는가 |
|---------|---------------|-------------|--------------|
| 단일 턴 함수 호출(OpenAI/Anthropic/Gemini) | 앱 개발자 | LLM | 앱 개발자 |
| MCP | MCP 서버 | MCP 클라이언트를 통한 LLM | MCP 서버 |
| A2A | 에이전트 카드 게시자 | 호출하는 에이전트 | 호출받는 에이전트 |
| 웹 브라우저(함수 호출 에이전트) | 브라우저 확장 / WebMCP | LLM | 브라우저 런타임 |

어디서든 같은 네 단계입니다. 열의 이름만 바뀔 뿐, 구조는 바뀌지 않습니다.

### 그냥 JSON으로 답하라고 프롬프트하면 안 되나?

"모델에게 JSON으로 답하라고 부탁하기"는 함수 호출 이전 시절의 패턴이었습니다. 프론티어(최상위) 모델에서도 약 5~15퍼센트는 실패하고, 작은 모델에서는 훨씬 더 자주 실패합니다. 실패 양상으로는 중괄호 누락, 마지막 쉼표, 환각된 필드, 잘못된 타입 등이 있습니다. 그러면 JSON 복구 패스, 재시도, 제약 디코더 중 하나가 필요해집니다.

네이티브 함수 호출이 더 나은 이유는 세 가지입니다. 첫째, 프로바이더가 정확한 호출 형태 그대로 모델을 엔드투엔드로 학습시키기 때문에 strict 모드에서는 유효한 JSON 비율이 98~99퍼센트까지 올라갑니다. 둘째, 호출 페이로드가 자유 텍스트 속이 아니라 자체 프로토콜 슬롯에 들어가므로 도구 호출이 사용자에게 보이는 답변으로 새어 나가지 않습니다. 셋째, 프로바이더들이 제약 디코딩(OpenAI의 strict 모드, Anthropic의 `tool_use`, Gemini의 `responseSchema`)으로 스키마 준수를 강제합니다. 출력이 스키마 검증을 통과한다고 보장되는 거죠.

페이즈 13 · 02에서는 세 프로바이더 API를 나란히 비교하고, 페이즈 13 · 04에서는 구조화된 출력을 깊게 다룹니다.

루프는 모델이 호출을 멈추거나 호스트가 최대 턴 수에 도달하면 끝납니다. 프로덕션 호스트는 이 값을 5~20턴 사이로 둡니다. 그 이상이면 거의 확실히 모델이 스스로 빠져나가지 못하는 루프에 빠진 것입니다. Claude Code는 기본값이 20, OpenAI Assistants는 10, Cursor의 에이전트 모드는 25입니다.

## 활용하기

`code/main.py`는 LLM 없이 4단계 루프를 돌려 줍니다. 가짜 "결정자(decider)" 함수가 사용자 메시지를 패턴 매칭해 모델을 흉내 내지만, 실행기와 스키마 검증기, observe 단계 하네스는 진짜입니다. 실행해 보면 중간 상태까지 보기 좋게 출력되는 전체 요청/응답 흐름을 볼 수 있습니다. 이후 레슨에서 가짜 결정자를 실제 프로바이더로 바꿔 보면 됩니다.

볼 포인트:

- 도구 레지스트리는 도구마다 세 필드를 담습니다. 이름, 설명, 스키마, 그리고 실행기 참조.
- 검증기는 표준 라이브러리만으로 쓰인 최소한의 JSON Schema 서브셋(타입, required, enum, min/max)입니다. 페이즈 13 · 04에서 더 완전한 버전을 제공합니다.
- 루프는 반복 횟수를 5로 제한합니다. 프로덕션 에이전트에는 정확히 이런 서킷 브레이커가 필요합니다.

## 출시하기

이 레슨은 `outputs/skill-tool-interface-reviewer.md`를 만듭니다. 도구 정의 초안(이름 + 설명 + 스키마 + 실행기 개요)이 주어지면, 이 스킬이 루프 적합성을 감사합니다. 이름이 기계적으로 안정적인지, 설명이 완전한 사용 지침인지, 스키마가 JSON Schema 2020-12를 올바르게 쓰는지, 순수/결과형 구분이 명시적인지를 검사합니다.

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 도구(Tool) | "모델이 호출할 수 있는 것" | 이름 + JSON Schema 타입의 입력 + 실행기 함수의 삼중짝 |
| 함수 호출(Function calling) | "네이티브 도구 사용" | 산문 대신 구조화된 도구 호출을 내보내도록 지원하는 프로바이더 수준 API |
| 도구 호출(Tool call) | "모델의 행동 요청" | 모델이 내보내는 `id`, `name`, `arguments`를 담은 JSON 페이로드 |
| 도구 결과(Tool result) | "도구가 돌려준 것" | 실행기의 출력을 id가 맞는 `tool` 역할 메시지로 감싼 것 |
| 병렬 도구 호출(Parallel tool calls) | "한 번에 여러 호출" | 한 모델 턴 안의 여러 호출 객체. 서로 독립적이고 id로 순서를 매길 수 있음 |
| Strict 모드 | "JSON 보장" | 모델 출력이 선언된 스키마를 통과하도록 강제하는 제약 디코딩 |
| 순수 도구(Pure tool) | "읽기 전용 도구" | 부수 효과 없음. 다시 실행해도 안전 |
| 결과형 도구(Consequential tool) | "행동 도구" | 외부 상태를 변경함. 게이트, 감사, 사용자 확인 필요 |
| 4단계 루프 | "도구 호출 주기" | describe → decide → execute → observe |
| 호스트(Host) | "에이전트 런타임" | 도구 레지스트리를 쥐고, 모델을 호출하고, 실행기를 돌리는 프로그램 |
