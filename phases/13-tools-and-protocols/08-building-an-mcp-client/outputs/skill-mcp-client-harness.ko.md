> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-mcp-client-harness.md](skill-mcp-client-harness.md)

MCP 서버 전송 목록이 주어지면, MCP `2026-07-28`을 선호하고 레거시 호환성을 고립시키는 클라이언트 하네스를 만들어 냅니다.

산출물:

1. 피어 설정. 안정적인 서버 이름을 고정된 명령 또는 엔드포인트, 인자, 환경 허용 목록, 인가 컨텍스트, 전송 종류, 그리고 기본값이 false인 명시적 `allow_legacy` 플래그에 매핑합니다.
2. 현대 요청 빌더. 직렬화 직전에 모든 `params._meta`에 프로토콜 버전, 현재 클라이언트 기능, 권장 클라이언트 신원을 도장 찍습니다.
3. stdio 시대 탐침. `server/discover`를 먼저 보냅니다. 유효한 DiscoverResult를 받아들이고, 상호 지원되는 현대 버전에서 `-32022`를 재시도하고, `-32020`과 `-32021`을 교정 가능한 현대 에러로 취급합니다.
4. 레거시 호환성 탐침. 인식되지 않은 에러, 타임아웃, 연결 종료, 빈 응답은 모호한 것으로 취급합니다. 그 정확한 피어가 `allow_legacy: true`일 때만 마감 시한이 묶인 `initialize` 하나를 보냅니다. 설정된 레거시 리비전, 객체 기능, 비어 있지 않은 서버 신원을 담은 상관관계가 맞는 JSON-RPC 성공 뒤에만 레거시를 선택합니다. 그 밖에는 실패로 닫습니다.
5. 도구 캐시. 협상된 인가 컨텍스트 안에서 `ttlMs`와 `cacheScope`를 존중합니다. 없는 레거시 `resultType`은 `"complete"`로 취급합니다.
6. 네임스페이스 병합. 피어와 도구를 정렬합니다. 충돌은 접두사를 붙이거나 거부합니다. 조용한 덮어쓰기를 금지합니다.
7. 라우터. 정규 도구 이름을 피어 + 로컬 이름으로 매핑하고, 새 요청 id를 만들고, 시대에 맞는 요청을 보내고, 응답 id를 검증합니다.
8. 복구. 전송 손실 시 진행 중인 작업을 실패 처리하고, 재시작 또는 재연결하고, 디스커버리와 목록을 반복하고, 구독을 다시 열고, 안전 정책이 허용하는 작업만 재시도합니다.

즉시 반려 사항:

- 현재 `_meta` 없이 현대 요청 보내기.
- 인식된 현대 에러 뒤에 초기화로 폴백하기.
- 레거시 호환성으로 명시적으로 허용 목록에 오르지 않은 피어에게 `initialize` 보내기.
- 타임아웃, 연결 종료, 빈 응답, 인식되지 않은 에러, 잘못된 결과, 미지원 리비전을 레거시 동작의 증거로 취급하기.
- 프로세스, 연결, 또는 `Mcp-Session-Id`를 현대 프로토콜 상태로 취급하기.
- 인가 컨텍스트를 넘어 비공개 캐시 목록 공유하기.
- 중복 도구 이름을 조용히 덮어쓰기.
- `resultType` 없는 현대 성공 받아들이기.

거절 규칙:

- 고정된 허용 목록 밖의 명령 실행은 거부합니다.
- 소유자가 모호한 도구의 라우팅은 거부합니다.
- 애플리케이션 멱등성 키나 사용자 결정 없이 비멱등 호출의 자동 재시도는 거부합니다.

출력: 완전한 Python 하네스, 최소 여섯 개의 적합성 테스트, 그리고 피어, 선택된 시대, 선택된 버전, 캐시 범위, 정규 도구 이름을 나열한 시작 보고서.
