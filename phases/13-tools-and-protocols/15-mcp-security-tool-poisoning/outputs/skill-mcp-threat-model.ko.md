MCP 배포가 주어지면 증거 기반의 위협 모델을 산출하세요. 어떤 서버, 패키지, 캐시, 레지스트리 항목, 게이트웨이 경로든 침해될 수 있다고 가정합니다.

## 필수 입력

- 클라이언트, 게이트웨이, 서버, 권한 서버, 레지스트리의 신뢰 경계.
- 완전한 정규화된 도구 디스크립터와 승인된 다이제스트.
- 인증 주체, 발급자(issuer), 청중(audience), 스코프, 도구 정책.
- 수용하는 현재 및 레거시 프로토콜 리비전.
- MRTR 연산, 입력 스키마, 상태 보호, 재생 정책.
- 캐시 범위, TTL, 구독 경로, 감사 보존.

## 산출물

1. 와이어 검증. 요청별 버전과 역량을 검증한 뒤, 버전 지원 여부 이전에 라우팅 헤더 일치를 검증합니다. 불일치에는 HTTP 400 `-32020`, 미지원이면서 일치한 버전에는 정확한 supported·requested 데이터가 있는 HTTP 400 `-32022`, 알 수 없는 메서드에는 HTTP 404 `-32601`, 수락된 알림에는 빈 본문 202를 요구합니다.
2. 디스크립터 검토. 오염 지표, 디스크립터 전체 다이제스트 변경, 알 수 없는 도구, 스키마 또는 어노테이션 변경을 보고합니다.
3. 이름공간 맵. 모든 백엔드 도구에 하나의 한정된 공개 이름을 부여하고, 조용한 충돌 해결을 거부합니다.
4. 권한 매트릭스. 인증된 주체와 발급자를 리소스, 도구, 인자 제약, 스코프에 매핑합니다. `clientInfo`나 `serverInfo`를 신원으로 쓰지 않습니다.
5. MRTR 검토. 모든 `inputRequests` 항목이 클라이언트가 선언한 역량이 지원하는 완전한 포함 요청임을 확인합니다. `elicitation: {}`를 암묵적 폼 지원으로, `elicitation: {form: {}}`를 명시적 폼 지원으로 취급합니다. URL 전용 일론은 HTTP 400 `-32021`과 `data.requiredCapabilities.elicitation.form`으로 거부합니다. 보호된 `requestState`를 메서드, 도구, 정확한 인자, 주체, 목적, 만료, 논스에 묶습니다. 모든 핸들러 인스턴스가 공유하는 유계·TTL 정리 재생 저장소에서 논스를 원자적으로 소비하기 전에 모든 `inputResponses` 항목을 키로 매칭하고 검증합니다.
6. 위험 축 검토. 신뢰할 수 없는 입력, 민감한 데이터, 결과가 큰 동작을 결합하는 자동 단계를 표시합니다.
7. 캐시·구독 검토. 사용자 의존적 결과는 비공개로 하고, 장수 알림은 `subscriptions/listen`을 쓰게 보장합니다.
8. 호환성 경계. 구형 핸드셰이크, 세션, GET 스트림, 서버 콜백, 실험적 작업 동작을 명시적인 버전 게이트 뒤에 격리합니다.
9. 전송 경계. 구현이 완전한 HTTP 어댑터인지 프로세스 내 프로토콜 모델인지 식별합니다. 모델이라면 레슨 09에 연결해 JSON Content-Type과 JSON 더하기 SSE Accept 검증을 받게 합니다.
10. 시정 순서. 소유자와 수용 증거와 함께 가장 영향력 큰 세 가지 수정을 제시합니다.

## 하드 리젝(필수 반려 사항)

- 디스커버리 순서에 의한 조용한 도구 덮어쓰기 또는 경로 선택.
- 사람이나 정책의 재승인 없이 디스크립터 다이제스트를 갱신하는 것.
- 스스로 보고한 클라이언트 또는 서버 정보를 인증으로 취급하는 것.
- 선언된 역량을 권한으로 취급하는 것.
- 결과가 큰 동작에 대해 평문이거나 서명되지 않은 `requestState`를 신뢰하는 것.
- 유일한 재생 장부를 하나의 게이트웨이나 서버 인스턴스 안에 두는 것.
- 속도 제한이나 승인 상태를 `Mcp-Session-Id`로만 매기는 것.
- 폐기된 샘플링, 루츠, 로깅, 또는 레거시 HTTP+SSE를 새 구현 경로로 내미는 것.

## 출력 형식

Trust Boundaries, Wire Findings, Descriptor Findings, Route Map, Authorization Matrix, MRTR Findings, Compatibility Findings, Remediation라는 이름의 섹션을 돌려주세요. 확인된 증거와 가정을 분리하세요. 마지막에 현재 가장 많은 경계를 넘는 단 하나의 공격 경로를 적습니다.
