# MCP 보안: 오염된 메타데이터, 라우팅, MRTR 상태

> 상태 없다(stateless)는 것이 신뢰 없다(trustless)는 뜻은 아닙니다. 모든 요청이 서버와 게이트웨이가 호출을 독립적으로 검증할 수 있는 증거를 드러낸다는 뜻입니다.

**유형:** Learn(배우기)
**언어:** Python
**선수 지식:** 페이즈 13 · 07(MCP 서버), 페이즈 13 · 08(MCP 클라이언트)
**시간:** 약 60분

## 학습 목표

- 도구 설명, 어노테이션, 클라이언트 정보, 서버 정보를 신뢰할 수 없는 데이터로 다룹니다.
- 메타데이터 오염, 디스크립터 변경, 서버 간 이름 충돌을 탐지합니다.
- 2026-07-28 요청 메타데이터와 Streamable HTTP 라우팅 헤더를 검증합니다.
- MRTR `requestState`를 변조로부터 보호하고 확인을 정확한 인자에 묶습니다.
- 제거된 프로토콜 세션이 아니라 주체(principal)에 권한 부여와 속도 제한을 적용합니다.

## 문제

모델은 도구 설명을 읽고 무엇을 호출할지 판단합니다. 라우터는 도구 이름을 읽고 요청을 어디로 보낼지 정합니다. 사용자는 라벨을 읽고 무엇을 승인할지 정합니다. 하나의 악의적인 디스크립터가 이 셋 모두를 겨냥할 수 있습니다.

공식 MCP 보안 가이던스는 직설적입니다. 설명과 어노테이션은 신뢰할 수 있는 서버에서 온 것이 아니라면 신뢰할 수 없는 것으로 취급해야 합니다. 심지어 그렇더라도 배포 신뢰는 바뀔 수 있습니다. 서버 업데이트, 침해된 패키지, 레지스트리 실수, 게이트웨이 병합이 모델이 보는 것을 바꿔버릴 수 있습니다.

현재 프로토콜은 보안 경계도 바꿉니다. 2026-07-28에는 코어 핸드셰이크도 전송 세션도 없습니다. 승인, 속도 제한, 감사 이력을 `Mcp-Session-Id`로만 매기는 보안 설계는 현재 설계가 아닙니다.

## 개념

### 검사할 가치가 있는 7개 공격 표면

"조심하라"는 막연한 지시 대신 구체적인 목록을 쓰세요.

1. **메타데이터 오염.** 설명이 선언된 도구 동작과 무관한 지시를 담고 있다.
2. **디스크립터 러그풀(rug pull).** 이전에 승인된 이름, 설명, 스키마, 어노테이션이 바뀐다.
3. **서버 간 섀도잉(shadowing).** 두 백엔드가 같은 한정되지 않은 도구 이름을 노출하고 라우팅이 조용히 하나를 고른다.
4. **헤더·본문 혼동.** `Mcp-Method`나 `Mcp-Name`이 JSON-RPC 요청과 어긋난다.
5. **역량 에스컬레이션.** 피어가 확장이나 클라이언트 기능을 주장하고 서버가 그 선언을 권한으로 착각한다.
6. **MRTR 상태 변조.** 클라이언트가 `requestState`를 바꾸거나, 다른 질문에 답하거나, 다른 인자로 확인을 재사용한다.
7. **공급망 신원 혼동.** 익숙한 표시 이름이 게시자나 서버 신원의 증거로 취급된다.

이 표면들은 서로 겹칩니다. 해시 고정(hash pinning)은 디스크립터 변경에 도움이 되지만 첫 디스크립터가 안전했는지는 증명하지 못합니다. 정적 스캔은 노골적인 문구는 잡지만 미묘한 지시는 못 잡습니다. 이름공간화(namespacing)는 한 부류의 충돌을 막을 뿐 악의적인 이름공간 서버까지는 막지 못합니다. 통제를 겹겹이 쌓으세요.

### 현재 요청 봉투는 신원이 아니라 증거다

모든 2026-07-28 요청에는 다음이 들어 있습니다:

```json
{
  "_meta": {
    "io.modelcontextprotocol/protocolVersion": "2026-07-28",
    "io.modelcontextprotocol/clientCapabilities": {
      "elicitation": {"form": {}}
    },
    "io.modelcontextprotocol/clientInfo": {
      "name": "security-lab",
      "version": "1.0.0"
    }
  }
}
```

요청마다 버전과 역량 형태를 검증하세요. 역량은 호환되는 응답 형태를 고르는 데 씁니다. `clientInfo`를 인증된 주체로 쓰지 마세요. 스스로 보고한 값입니다.

같은 경고가 결과 메타데이터의 `io.modelcontextprotocol/serverInfo`에도 적용됩니다. 로그와 디버깅에는 유용하지만, 인증서도 레지스트리 증명도 권한 결정도 아닙니다.

### 정책 이전에 라우팅을 검증한다

`tools/call`에서 Streamable HTTP에는 다음이 포함됩니다:

```text
MCP-Protocol-Version: 2026-07-28
Mcp-Method: tools/call
Mcp-Name: notes.export
```

헤더의 메서드는 본문의 메서드와 같아야 합니다. 헤더의 이름은 `params.name`과 같아야 합니다. 백엔드를 고르거나 RBAC을 적용하거나 속도 제한 토큰을 소비하기 전에, 어긋남은 `-32020`으로 거부하세요.

이 순서는 흔한 모호성을 닫습니다. 한 컴포넌트는 본문을 승인하고 다른 컴포넌트는 헤더로 라우팅하는 식의 사고입니다.

와이어 검증은 정확히 하나의 시퀀스를 따릅니다. JSON-RPC와 메타데이터 타입을 검증하고, 헤더 값과 본문을 비교하고, 그다음 일치한 버전이 지원되는지 확인합니다. 어긋난 헤더는 `-32020`과 함께 HTTP 400을 돌려줍니다. 헤더와 본문이 미지원 버전으로 일치한다면 `-32022`와 `data`가 정확히 `{"supported":["2026-07-28"],"requested":"<actual>"}`인 HTTP 400을 돌려줍니다. 알 수 없는 메서드는 `-32601`과 함께 HTTP 404를 돌려줍니다.

모든 오류 객체는 계약이 구조화된 복구 정보를 필요로 할 때 선택적 `data`를 포함합니다. 알림에는 `id`가 없으므로 JSON-RPC 성공이나 오류 응답을 절대 받지 않습니다. 수락된 HTTP 알림은 빈 본문의 202를 돌려줍니다.

### 디스크립터 전체를 고정한다

설명 해시만으로는 스키마와 어노테이션 변경을 놓칩니다. 사용자가 승인한 디스크립터 필드를 정규화하고 해시하세요:

```python
normalized = json.dumps(tool, sort_keys=True, separators=(",", ":"))
digest = hashlib.sha256(normalized.encode()).hexdigest()
```

이 장난감 예제 밖에서 게시자 증거와 승인 시각과 함께, `notes.export` 같은 한정된(qualified) 키 아래 다이제스트를 저장하세요.

새로고침 때마다:

- 알 수 없는 키: 검토 전까지 격리(quarantine).
- 같은 키, 다른 다이제스트: 재승인 전까지 러그풀로 격리.
- 중복된 한정되지 않은 이름: 결정론적인 이름공간화 요구.
- 스캐너 적중: 차단하고 완전한 디스크립터를 검토.

해시 일치는 안정성을 증명할 뿐 안전성을 증명하지 않습니다. 오염된 디스크립터는 완벽하게 고정되어도 오염된 채입니다.

### 정적 스캐닝은 트립와이어(tripwire)다

단순한 패턴은 역할 태그, 지시 덮어쓰기, 은폐, 비밀 접근, 흐릿한 네트워크 목적지를 표시할 수 있습니다. 설치 시점과 CI에 쓰기에 충분히 값쌉니다.

그러나 의미론적 증명은 아닙니다. 안전한 설명도 정당한 경고 안에 표시된 문구를 담을 수 있습니다. 악의적인 설명은 모든 문구를 피할 수 있습니다. 스캐너 출력을 자동 면죄부 점수가 아니라 검토 증거로 다루세요.

### 병합 전에 이름공간화한다

두 서버가 모두 `search`를 노출한다고 해 보세요. 디스커버리 순서로 승자를 정하게 두지 마세요.

```text
notes.search
issues.search
```

한정된 이름이 공개 게이트웨이 이름입니다. 백엔드 매핑은 별도로 기록하세요. 안정적인 이름 덕분에 승인, 감사, 해시 고정, `Mcp-Name` 라우팅이 같은 객체를 가리킵니다.

### 역량은 호환성 선언이다

요청별 `clientCapabilities`는 서버에게 클라이언트가 어떤 프로토콜 기능을 처리할 수 있는지 알려 줍니다. 클라이언트에게 도구·데이터·동작에 대한 접근을 주지는 않습니다.

권한은 여전히 인증된 주체와 리소스 정책에서 옵니다. 시퀀스는 다음과 같습니다:

1. 전송 자격 증명을 인증한다.
2. 버전, 헤더, 요청 형태를 검증한다.
3. 역량 호환성을 확인한다.
4. 주체, 도구, 리소스, 인자를 승인한다.
5. 실행하거나 사용자 입력을 요구한다.

### 상태 없는 MRTR 확인을 보호한다

결과가 큰 도구는 사용자 확인이 필요할 수 있습니다. 현재 MCP는 서버→클라이언트 콜백 대신 다중 왕복 요청(MRTR)을 씁니다.

첫 응답:

```json
{
  "resultType": "input_required",
  "inputRequests": {
    "confirm": {
      "method": "elicitation/create",
      "params": {
        "mode": "form",
        "message": "Export notes to archive?",
        "requestedSchema": {
          "type": "object",
          "properties": {
            "confirm": {"type": "boolean"}
          },
          "required": ["confirm"]
        }
      }
    }
  },
  "requestState": "opaque-integrity-protected-value"
}
```

클라이언트는 입력을 얻고 새 JSON-RPC id로 원래 메서드를 재시도합니다:

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "notes.export",
    "arguments": {"query": "private", "destination": "archive"},
    "requestState": "opaque-integrity-protected-value",
    "inputResponses": {
      "confirm": {
        "action": "accept",
        "content": {"confirm": true}
      }
    },
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {
        "elicitation": {"form": {}}
      }
    }
  }
}
```

각 `inputRequests` 값은 `method`와 `params`를 갖춘 완전한 포함 요청입니다. 그 키는 `inputResponses`의 대응 항목과 일치해야 합니다. 폼 일론은 객체 루트의 `requestedSchema`를 쓰며, 서버가 요구하기 전에 클라이언트가 폼 일론 역량을 선언했어야 합니다.

현재 역량에는 유효한 폼 선언이 두 가지 있습니다. `{"elicitation":{}}`은 폼 일론을 암묵적으로 지원하고, `{"elicitation":{"form":{}}}`은 명시적으로 밝힙니다. `{"elicitation":{"url":{}}}` 같은 URL 전용 선언은 폼 요청을 지원하지 않습니다. 서버는 `-32021`과 `data.requiredCapabilities`가 `{"elicitation":{"form":{}}}`인 HTTP 400을 돌려줍니다.

`requestState`는 적대적인 입력으로 취급하세요. 서명하거나 암호화하고, 검증하고, 메서드·도구·정확한 인자·목적·만료·주체·(재생이 중요하다면) 1회용 논스에 묶으세요. 레슨 코드는 HMAC과 정확한 인자 매칭으로 경계를 눈에 보이게 만듭니다.

논스 장부는 하나의 게이트웨이 객체 안에 살아 있으면 안 됩니다. 실행 가능한 모델은 여러 게이트웨이 인스턴스가 공유할 수 있는, 유계이고 TTL로 정리되는 재생 저장소를 주입합니다. 그 원자적 클레임이 실행 경계입니다. 검증된 수락이나 명시적 종결 거절만 상태를 소비합니다. 형식이 잘못된 응답이나 `cancel`은 아무것도 실행하지 않고 만료까지 재시도 가능하게 남습니다. 프로덕션 플릿은 공유 오래가는 저장소에 같은 조건부 클레임이 필요합니다.

숨겨진 확인 컨텍스트를 프로토콜 세션에 저장하지 마세요. 어떤 서버 인스턴스든 재시도를 검증할 수 있어야 합니다.

### 고위험 호출을 위한 2인 룰

호출을 세 축으로 분류하세요:

- 신뢰할 수 없는 입력을 소비한다.
- 민감한 데이터에 접근할 수 있다.
- 결과가 큰 외부 동작을 일으킨다.

하나의 자동 단계가 이 셋을 모두 결합해서는 안 됩니다. 분리하거나, 권한을 줄이거나, MRTR로 명시적인 사용자 입력을 요구하세요. 이것은 설계 휴리스틱이지 프로토콜 기능이 아닙니다.

### 실행 전에 권한을 줄인다

상태 없음만으로 안전하지는 않습니다. 숨겨진 프로토콜 이력을 없앨 뿐, 자기완결적인 요청은 여전히 과도한 권한을 가진 핸들러에게 데이터 유출이나 되돌릴 수 없는 변경을 요구할 수 있습니다. 안전은 각 경계에서 권한을 줄이는 데서 옵니다:

1. **타입이 지정된 동사.** `archive_note`처럼 하나의 유계인 연산을 노출하세요. 무관한 권한을 표현할 수 있는 범용 `run`이나 `request` 도구가 아니라.
2. **검증된 인자.** 실현 가능하면 닫힌 스키마를 쓰고, 알 수 없는 필드를 거부하고, 식별자를 한 번 정규화하고, 크기를 제한하고, 정책 평가 전에 목적지·테넌트·리소스 소유권을 검증하세요.
3. **현재 권한 부여.** 인증된 주체를 정확한 동사, 리소스, 환경, 정규화된 인자에 묶으세요. 도구 어노테이션과 클라이언트 역량은 이 권한을 주지 못합니다.
4. **동작에 묶인 승인.** 결과가 큰 호출에 대해서는 승인을 타입이 지정된 동사와 정규화된 인자의 다이제스트, 그리고 주체·만료·1회용 정책에 묶으세요. 바뀐 필드가 하나라도 있으면 새 결정이 필요합니다.
5. **1급(first-class) 거부.** 거부(deny), 만료된 승인, 사용자 거절, 안전하지 않은 목적지를 부작용 없이 실행되는 평범한 결과로 모델링하세요. 거부를 더 약한 폴백 도구로 번역하지 마세요.
6. **가려진 감사 증거.** 누가 요청했는지, 어떤 승인된 디스크립터와 정책 버전이 쓰였는지, 어떤 정규화된 대상이 승인되었는지, 왜 결정이 허용 또는 거부되었는지, 실행이 시작되었는지를 기록하세요. 비밀값 대신 다이제스트나 가려진 값을 저장하세요.

각 단계는 다음 컴포넌트가 할 수 있는 일을 좁힙니다. 최종 핸들러는 이미 검증된 도메인 명령을 받아야지, 원시 모델 텍스트에 넓은 자격 증명이 더해진 것을 받으면 안 됩니다. MRTR 재시도, 작업 업데이트, 게이트웨이 전달 호출에서도 전체 체인을 반복하세요. 이전 승인이 이후 요청을 신뢰할 수 있는 세션 트래픽으로 만들지는 못합니다.

### 현재 및 레거시 상호작용 경로

루츠, 샘플링, 로깅은 새 2026-07-28 구현에서 폐기되었습니다. 게이트웨이는 구형 요청 채널 코드를 버전 게이트가 있는 호환 경로로만 유지할 수 있습니다.

세션별 샘플링 제한기 같은 새 방어를 만들지 마세요. 할당량은 인증된 주체, 발급자(issuer), 리소스, 도구, 시간 윈도우에 적용하세요. 현재의 인터랙티브 작업에서는 MRTR 입력 요청과 응답을 들여다보세요.

### 상태 없는 전송 검사

- 단일 POST 엔드포인트에서 현대식 MCP 메시지를 받습니다.
- 현대식 GET과 DELETE에는 405를 돌려줍니다.
- `Mcp-Session-Id`를 발급하거나 의존하지 않습니다.
- 레거시 세션·재생 헤더를 권한 입력으로 무시합니다.
- 그 POST에 대해 JSON 또는 요청 범위 SSE를 돌려줍니다.
- `subscriptions/listen`은 옵트인한 장수 변경 알림에만 사용합니다.

```figure
tp-tool-poisoning
```

## 만들기

`code/main.py`는 작은 프로세스 내 보안 게이트웨이 모델을 구현합니다. 완전한 도구 디스크립터를 정규화하고 고정하고, 메타데이터 오염과 섀도잉을 보고하고, 현대적 요청 봉투와 라우팅 값을 검증하고, 서명된 `requestState`와 주입된 공유 재생 저장소로 2라운드 확인된 내보내기를 수행합니다.

이 모델은 HTTP 어댑터가 JSON 본문과 라우팅 헤더를 파싱한 뒤에 시작합니다. `Content-Type`이나 `Accept`를 검증하지 않습니다. 같은 디스패처를 레슨 09의 완전한 Streamable HTTP 어댑터에 연결하세요. 그 어댑터는 `Content-Type: application/json`과 `application/json`과 `text/event-stream`을 모두 포함하는 `Accept` 값을 요구합니다.

실행:

```bash
cd phases/13-tools-and-protocols/15-mcp-security-tool-poisoning
python3 code/main.py
python3 -m unittest discover code/tests -v
```

샘플은 의도적으로 디스크립터를 변조합니다. 스캐너와 다이제스트 비교가 독립적인 발견 항목을 냅니다. 그다음 내보내기가 `input_required` 응답과 상태 없는 재시도를 시연합니다.

## 사용하기

`SAFE_TOOLS`를 여러분의 승인된 서버들에서 온 정규화된 스냅샷으로 교체하세요. 자격 증명과 비밀값은 스냅샷에 넣지 마세요. 다이제스트를 갱신하기 전에 새 디스크립터나 바뀐 디스크립터를 모두 검토하세요.

게이트웨이에서는 디스커버리 때와 디스패치 전에 같은 검사를 실행하세요. 캐시가 디스커버리 작업을 줄일 수 있지만, 캐시된 승인은 디스크립터가 바뀌면 만료되거나 무효화되어야 합니다.

## 연습 문제

1. 인증된 주체와 현재 권한 결정을 봉인된 MRTR 상태에 묶고, 다른 주체 아래의 재시도를 거부합니다.
2. 메모리 재생 저장소를 영구적인 조건부 삽입으로 교체하고, 두 프로세스가 같은 논스를 클레임할 수 없음을 증명합니다.
3. 재생 클레임 이후, 시뮬레이션된 내보내기 이전에 실패를 주입합니다. 복구를 안전하게 만드는 트랜잭션이나 멱등성 규칙을 정의하고 테스트합니다.
4. 설명을 바꾸지 않고 도구의 `inputSchema`를 바꿔 보세요. 디스크립터 전체 고정이 이를 잡아내는지 확인합니다.
5. `tools/list`가 주체에 따라 다를 때 공개 캐싱을 거부하는 정책을 추가합니다.
6. 게이트웨이 뒤의 구형 서버를 모델링하세요. 모든 핸드셰이크와 세션 동작을 명시적인 `2025-11-25` 호환 분기 뒤에 둡니다.

## 핵심 용어

| 용어 | 의미 |
|------|---------|
| 메타데이터 오염(Metadata poisoning) | 도구 디스크립터에 박힌 지시 또는 기만적 주장 |
| 러그풀(Rug pull) | 이전에 승인된 디스크립터의 변경 |
| 도구 섀도잉(Tool shadowing) | 중복된 한정되지 않은 이름이 낳는 모호한 라우팅 |
| 헤더 불일치(Header mismatch) | 라우팅 헤더와 JSON-RPC 본문의 어긋남. 오류 `-32020` |
| 해시 고정(Hash pin) | 완전한 승인된 디스크립터의 다이제스트 |
| MRTR | 서버가 요구한 입력을 위한 상태 없는 응답·재시도 패턴 |
| `requestState` | 신뢰할 수 없는 입력으로 다뤄야 하는 불투명 왕복 값 |
| 역량 선언(Capability declaration) | 프로토콜 호환성의 진술. 권한 부여가 아님 |
| 암묵적 폼 지원 | 빈 `elicitation` 역량 객체. 폼 지원과 동등 |
| 한정된 도구 이름(Qualified tool name) | `notes.search` 같은 안정적인 게이트웨이 이름 |
