프로토콜 버전 `2026-07-28`을 기준으로 제공된 MCP 도구 표면을 검토하세요.

없으면 다음 입력을 요청하세요:

1. 모든 `nextCursor` 필드를 포함한 완전한 `tools/list` 디스크립터 페이지들.
2. 도구마다 최소 하나의 성공 결과와 하나의 실패 결과.
3. 사용한다면 Streamable HTTP 파라미터 헤더 매핑.
4. 컴플리션 참조, 호출자 클래스, 예시 제안들.
5. 보이는 도구 세트를 바꿀 수 있는 권한 컨텍스트.

다음 섹션들을 갖춘 압축된 보고서를 만드세요.

## 디스크립터 수용

각 도구에 대해:

- 비어 있지 않은 안정적인 이름을 검증;
- 객체 `inputSchema`를 요구;
- JSON Schema 방언을 식별(생략 시 2020-12 기본);
- 있으면 `outputSchema`를 검증;
- 애너테이션을 정책이 아닌 신뢰할 수 없는 힌트로 나열;
- 하나의 정확한 이유와 함께 `ADMIT`, `REJECT`, 또는 `CONDITIONAL`을 반환.

잘못된 형식의 디스크립터 하나를 거부하더라도 관련 없는 유효한 도구는 함께 거부하지 마세요.

## 결과 계약

`isError: true`인 결과를 포함한 모든 완전한 결과에 대해:

- `resultType: complete`를 요구;
- 모든 콘텐츠 블록을 타입별로 검증;
- `structuredContent`를 객체 전용이 아니라 임의의 JSON 값으로 취급;
- `structuredContent`의 존재와, 출력 스키마가 있다면 그 적합성을 요구;
- 구조화 결과에 호환성 텍스트 블록을 요구;
- 리소스 링크와 내장 리소스를 구분;
- 크기와 미디어 타입 한도를 명시.

잘못된 형식의 요청은 JSON-RPC 오류로 분류합니다. 실행 가능한 실행 실패는 게시된 출력 계약을 우회하지 않고 `isError: true`인 완전한 결과로 분류합니다.

## 파라미터 헤더

모든 `x-mcp-header`에 대해:

- 유효하고 비어 있지 않은 HTTP 필드 이름 토큰을 요구;
- 대소문자 무관 고유성을 요구;
- string, integer, 또는 boolean 타입을 요구;
- 중첩 properties, 조합자(combinator), 배열 items, `$ref`가 쓰는 정의를 포함한 입력 스키마 전체를 탐색;
- 애너테이션은 직접적인 `inputSchema.properties` 멤버에만 허용하고, 그 밖의 어디에서 발견되거나 `outputSchema`에 있는 모든 애너테이션은 거부;
- `number`와 `-9007199254740991`부터 `9007199254740991` 범위 밖의 정수 값은 거부;
- 자격 증명, 토큰, 시크릿, 비밀번호, 인증(authorization), 개인 식별 정보(PII) 필드는 배포 정책으로 거부;
- 값이 비어 있지 않은 보이는 ASCII이고 `=?base64?`로 시작하지 않을 때만 평문 전송;
- 그 외에는 원래 값을 자르거나 정규화하지 않고 정확히 `=?base64?{Base64UTF8}?=`로 출력;
- 유니코드, 빈, 공백, 제어, CR/LF, 패딩된, 센티넬처럼 보이는 문자열은 인코딩하고 불리언은 소문자 텍스트로 렌더링;
- HTTP 경계에서 인식된 `Mcp-Param-*` 값을 디코딩하고, 헤더 이름은 대소문자 무관으로, 디코딩된 값은 정확히 JSON 본문과 비교하며, 없거나, 중복되거나, 뜻밖이거나, 형식이 틀리거나, 일치하지 않는 사본은 HTTP `400`과 JSON-RPC `-32020`으로 거부;
- 최종 헤더 이름과 거부 범주만 기록하고, 인자 값이나 인코딩된 페이로드는 절대 기록하지 않음.

## 페이지네이션

모든 목록 요청을 추적하세요. `nextCursor`가 존재하고 null이 아닌 동안은 빈 문자열인 경우를 포함해 계속하세요. 커서를 절대 디코딩, 수정, 증가, 정렬, 의미 도출하지 마세요. 중복 도구, 빠진 페이지, 불안정한 순서를 보고하세요.

## 컴플리션

각 프롬프트 또는 리소스 참조에 대해:

- 참조와 인자를 검증;
- 호출자의 권한으로 제안을 필터링;
- 결과를 100개 값으로 제한;
- 클라이언트 디바운스와 서버 속도 제한을 정의;
- 숨겨진 테넌트, 리소스, 환경 이름이 새어 나가지 않는지 테스트.

## 검증 매트릭스

최소 다음 검사들을 반환하세요:

| 검사 | 픽스처 | 기대 결과 |
|------|---------|-----------------|
| 비객체 구조화 출력 | 유효한 배열, 스칼라, 또는 null 스키마 | 적합할 때 수용 |
| 출력 불일치 | 잘못된 JSON 타입 또는 빠진 속성 | 모델 사용 전 거부 |
| 오류 출력 불일치 | 빠지거나 잘못된 구조화 콘텐츠를 가진 `isError: true` | 모델 사용 전 거부 |
| 빈 커서 | `nextCursor: ""` | 후속 요청이 정확한 커서를 보냄 |
| 안전하지 않은 헤더 | 토큰 또는 잘못된 필드 이름 | 디스크립터 거부 |
| 중첩 헤더 애너테이션 | `oneOf`, `items`, 중첩 객체, 또는 `$ref` 정의 | 전체 트리 수용 중 디스크립터 거부 |
| 인코딩된 헤더 값 | 유니코드, 줄바꿈, 패딩, 또는 센티넬처럼 보이는 텍스트 | 정확한 base64 UTF-8 센티넬이 원래 값으로 왕복 |
| 정수 헤더 값 | 양쪽 안전 경계와 각 경계 밖의 값 하나 | 안전 경계는 통과, 안전하지 않은 값은 거부 |
| 헤더-본문 일치 | 대소문자 변형, 없는 사본, 디코딩 불일치 | 대소문자 변형은 통과, 없거나 불일치는 HTTP 400과 JSON-RPC -32020 |
| 혼합 콘텐츠 | 텍스트, 미디어, 링크, 내장 리소스 | 각 블록을 독립적으로 검증 |
| 컴플리션 격리 | 낮은 권한 호출자 | 권한 있는 제안이 반환되지 않음 |
| 오류 계층화 | 모르는 도구와 비즈니스 실패 | JSON-RPC 오류와 `isError: true`가 구분됨 |

증거가 성공한 도구 호출 하나뿐이라면 승인을 거부하세요. 발견 페이지, 수용 결정, 검증된 결과 픽스처를 요구하세요.
