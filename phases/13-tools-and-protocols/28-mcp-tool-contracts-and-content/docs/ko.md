# MCP 도구 계약과 콘텐츠

> 발견(discovery), 인자, 결과, 페이지네이션, 전송 메타데이터가 하나의 계약 위에서 서로 일치할 때만, 도구를 자동화하는 것은 안전합니다.

**유형:** Build
**언어:** Python
**선수 지식:** 페이즈 13, 레슨 07, 09, 10
**시간:** 약 120분

## 학습 목표

- JSON Schema 2020-12로 도구 입력과 출력을 정의합니다.
- 구조화된 결과를 JSON 객체라고 가정하지 않고 검증합니다.
- 텍스트, 이미지, 오디오, 리소스 링크, 내장 리소스 중에서 선택합니다.
- 도구가 모델에 도달하기 전에 안전하지 않은 `x-mcp-header` 정의를 거부합니다.
- 파라미터-헤더 값을 인코딩하고 헤더-본문이 정확히 일치하는지 검증합니다.
- 커서 값을 해석하지 않으면서 커서 페이지네이션을 순회합니다.
- `completion/complete` 제안에 경계를 두고 권한을 부여합니다.

## 문제 상황

파이썬 함수 호출은 쉽습니다. AI 호스트를 통해 원격 기능을 호출하는 것은 계약 문제입니다.

서버가 디스크립터(descriptor)를 게시합니다. 클라이언트는 그 디스크립터를 모델 컨텍스트와 사용자 인터페이스로 바꿉니다. 모델이 인자를 만듭니다. 게이트웨이가 미러링된 헤더에서 요청을 라우팅할 수 있습니다. 서버가 도구를 실행합니다. 그다음 클라이언트는 그 결과가 모델에 돌려주기에 안전하고 충분히 유효한지 판단합니다.

경계 하나가 약해지면 체인 전체가 오염됩니다.

다섯 가지 실패를 생각해 보세요:

- 디스크립터는 결과가 객체라고 하는데 서버는 배열을 돌려줍니다.
- 클라이언트가 `nextCursor`가 빈 문자열일 때 페이지네이션을 멈춥니다.
- 토큰 파라미터가 HTTP 헤더로 미러링되어 중개자에게 노출됩니다.
- 유니코드 라우팅 값이 날 헤더로 보내지고, 게이트웨이와 오리진이 서로 다른 바이트를 해석합니다.
- 컴플리션 엔드포인트가 접근 권한이 없는 운영 환경(production)을 호출자에게 제안합니다.

이런 실패는 더 나은 프롬프팅으로 고쳐지지 않습니다. 명시적인 프로토콜과 애플리케이션 계약이 필요합니다.

## 계약 파이프라인

각 도구 호출을 다섯 개의 게이트로 다루세요:

1. **발견(Discover).** 결정론적이고 페이지네이션된 도구 목록을 읽습니다.
2. **수용(Admit).** 각 디스크립터를 검증하고 로컬 보안 정책을 적용합니다.
3. **호출(Invoke).** 인자를 검증하고 전송 메타데이터를 만듭니다.
4. **실행(Execute).** 핸들러를 실행하고 실패를 올바르게 분류합니다.
5. **소비(Consume).** 모델 사용 전에 콘텐츠 블록과 구조화 출력을 검증합니다.

```figure
mcp-contract-pipeline
```

호스트가 수용과 소비 게이트를 소유합니다. 서버가 클라이언트에게 자기 애너테이션, 스키마, 출력을 강제로 신뢰시킬 수는 없습니다.

## JSON Schema는 런타임 경계다

MCP `2026-07-28`에서 `inputSchema`와 `outputSchema`는 JSON Schema를 사용합니다. `$schema`가 없으면 기본 방언(dialect)은 2020-12입니다.

입력 스키마는 스키마 객체여야 합니다. 인자가 없는 도구라도 자기가 받는 것을 정확히 말해야 합니다:

```json
{
  "type": "object",
  "additionalProperties": false
}
```

이것은 임의의 속성을 받아들이는 `{ "type": "object" }`보다 엄격합니다.

출력 스키마는 선택입니다. 서버가 한 번 게시하면, 모든 완전한 도구 결과는(`isError: true`인 결과 포함) 그에 맞는 `structuredContent`를 돌려주기로 약속합니다. 오류 플래그는 실행 결과를 분류할 뿐, 게시된 출력 계약을 면제해 주지 않습니다. 클라이언트는 디스크립터를 믿는 대신 결과를 검증해야 합니다.

### 구조화 콘텐츠는 임의의 JSON 값이다

`structuredContent`를 사전(dictionary)이라고 못 박지 마세요. 다음이 될 수 있습니다:

- 객체;
- 배열;
- 문자열;
- 숫자;
- 불리언;
- `null`.

이 도구는 배열을 돌려줍니다:

```json
{
  "name": "tag_catalog",
  "inputSchema": {
    "type": "object",
    "additionalProperties": false
  },
  "outputSchema": {
    "type": "array",
    "items": {"type": "string"}
  }
}
```

성공 결과는 유효합니다:

```json
{
  "resultType": "complete",
  "content": [
    {
      "type": "text",
      "text": "[\"contracts\", \"mcp\", \"stateless\"]"
    }
  ],
  "structuredContent": ["contracts", "mcp", "stateless"],
  "isError": false
}
```

호환성을 위해 구조화 결과는 텍스트 블록에 직렬화된 JSON도 함께 담는 것이 좋습니다. 하지만 텍스트는 검증 출처가 아닙니다. `structuredContent`가 검증 출처입니다.

### 작은 검증기도 경계를 가르친다

레슨은 파이썬 표준 라이브러리 안에 머물기 위해 의도적으로 JSON Schema 부분집합을 사용합니다. 예시 도구들이 쓰는 메커니즘을 검사합니다:

- object, array, string, integer, number, boolean, null 타입;
- 필수 속성;
- `additionalProperties: false`;
- 배열 items;
- enum 값;
- 최소 문자열 길이.

이것은 완전한 프로덕션 검증기의 대체품이 아닙니다. 재사용할 레슨은 검증이 어디에서 일어나는가입니다: 발견 후에는 디스크립터를, 실행 전에는 인자를, 소비 전에는 구조화 결과를 검증하는 것.

## 콘텐츠 블록은 서로 다른 비용을 지닌다

`content` 배열은 여러 콘텐츠 타입을 조합할 수 있습니다.

| 타입 | 용도 | 주요 경계 |
|------|------------|---------------|
| `text` | 사람과 모델이 읽는 요약 | 텍스트를 신뢰할 수 없는 출력으로 취급 |
| `image` | base64로 인코딩된 시각적 증거 | 미디어 타입과 크기 검증 |
| `audio` | base64로 인코딩된 음성 또는 녹음 출력 | 미디어 타입과 길이 한도 검증 |
| `resource_link` | 클라이언트가 나중에 가져올 수 있는 URI | 나중의 리소스 읽기를 다시 권한 검사 |
| `resource` | 결과에 직접 내장된 데이터 | 지금 페이로드와 콘텐츠 한도 강제 |

리소스 링크는 그 리소스가 `resources/list`에 나타난다는 증거가 아닙니다. 이 도구 호출이 돌려준 참조일 뿐입니다. 클라이언트는 URI를 따라갈 때 자기 리소스 정책을 그대로 적용합니다.

내장 리소스는 왕복 하나를 줄여주지만 현재 응답 크기를 키웁니다. 크거나 독립적으로 바뀌는 산출물에는 링크를, 결과와 함께 원자적으로 이동해야 하는 작은 증거에는 내장 리소스를 사용하세요.

레슨의 `evidence_bundle` 결과는 다섯 타입을 모두 포함합니다. 클라이언트는 결과를 받아들이기 전에 각 블록을 검증합니다.

## `x-mcp-header`는 라우팅 메타데이터다

`inputSchema` 안의 속성은 `x-mcp-header`를 선언할 수 있습니다. Streamable HTTP에서 클라이언트는 그 인자를 `Mcp-Param-{name}`으로 미러링합니다.

```json
{
  "region": {
    "type": "string",
    "x-mcp-header": "Region"
  }
}
```

`region: "eu-west"`이면 전송 계층은 다음을 내보낼 수 있습니다:

```http
Mcp-Param-Region: eu-west
```

이 애너테이션이 존재하는 이유는 로드 밸런서, 게이트웨이, 정책 엔진이 JSON 본문을 파싱하지 않고도 라우팅할 수 있게 하기 위해서입니다. 자격 증명을 담는 자리가 아닙니다.

프로토콜은 애너테이션을 제한합니다:

- 헤더 이름은 비어 있지 않고 HTTP 필드 이름 토큰 문법을 따름;
- 헤더 이름은 대소문자 구분 없이 고유함;
- 속성 타입은 string, integer, boolean;
- `number`는 허용되지 않음;
- 애너테이션은 `inputSchema.properties`의 직접 멤버에만 나타남;
- 정수 값은 `-9007199254740991`부터 `9007199254740991` 사이.

위치 규칙은 구문적(syntactic)이고 실패 시 차단(fail-closed)됩니다. 검증기가 우연히 이해하는 속성뿐 아니라 스키마 트리 전체를 탐색하세요. 중첩 객체의 `properties` 아래, `oneOf` 분기, `items`, `$ref`로 도달한 정의, 또는 어떤 출력 스키마 아래의 애너테이션도 거부하세요. 참조를 해석한다고 해서 참조된 노드가 직접적인 최상위 속성이 되는 것은 아닙니다.

이 레슨은 배포 정책을 하나 추가합니다: `password`, `secret`, `token`, `api_key`, `authorization` 같은 이름을 미러링하는 디스크립터를 거부합니다. 공식 명세는 서버 작성자에게 민감한 파라미터를 미러링하지 말라고 권고합니다. 클라이언트는 그 권고를 강제 수용 규칙으로 바꿀 수 있습니다.

감사할 대상은 헤더 값이 아니라 헤더 이름입니다. 예시 코드는 `eu-west`를 감사 이벤트에 넣지 않으면서 `Mcp-Param-Region`을 기록합니다.

### HTTP 헤더를 만들기 전에 값을 인코딩하기

파라미터 값이 평문으로 이동할 수 있는 경우는, `!`부터 `~`까지의 보이는(visible) ASCII 문자로 이루어진 비어 있지 않은 문자열이고 인코딩 센티넬(sentinel)과 닮지 않은 경우뿐입니다. 그 외 모든 것은 이 정확한 형태를 사용합니다:

```text
=?base64?{Base64UTF8}?=
```

`Base64UTF8`은 정확한 UTF-8 바이트 위의 표준 base64입니다. 먼저 값을 자르거나, 정규화하거나, 치환하지 마세요. 유니코드, 빈 문자열, 공백, 탭, 제어 문자, CR/LF, 앞뒤 공백, `=?base64?`로 시작하는 모든 값을 인코딩하세요. 센티넬처럼 보이는 값을 다시 한 번 인코딩하는 것이, 수신자가 그것을 전송 문법으로 디코딩하는 대신 원래 문자 그대로의 텍스트를 복구할 수 있게 해줍니다.

불리언은 소문자 `true` 또는 `false`로 렌더링됩니다. 정수는 10진수로 렌더링되며 자바스크립트 안전 정수 범위 안에 있어야 합니다. 범위 밖의 값은 중개자가 반올림하게 두는 대신 거부됩니다.

### 서버가 미러링된 사본을 검사한다

헤더 생성은 클라이언트 쪽 절반일 뿐입니다. Streamable HTTP 경계에서 서버는 다음을 해야 합니다:

1. 대소문자 구분 없이 인식되는 `Mcp-Param-*` 이름을 찾음;
2. 있을 때 정확한 base64 센티넬 형태를 디코딩;
3. 디코딩된 텍스트를 대응하는 JSON 본문 인자와 정확히 비교;
4. 디스패치 전에 없거나, 중복되거나, 뜻밖이거나, 형식이 틀리거나, 일치하지 않는 인식된 헤더를 거부.

거부는 JSON-RPC 오류 코드 `-32020`을 담은 HTTP `400`입니다. 본문 값이나 그 인코딩된 헤더 형태는 감사 기록에 들어가지 않습니다. 인식된 헤더 이름과 거부 범주만 기록하세요.

`code/main.py`는 이 경계를 직접 모델링합니다. [레슨 09](../../09-mcp-transports/)가 메서드·프로토콜 버전 일치를 포함한 더 넓은 Streamable HTTP 검증 순서를 다룹니다.

## 페이지네이션 커서는 불투명하다

MCP 목록 연산은 커서 페이지네이션을 사용합니다. 페이지 크기와 커서 형식은 서버가 정합니다. 클라이언트가 내릴 결정은 하나입니다:

```python
if result.get("nextCursor") is None:
    break
cursor = result["nextCursor"]
```

이렇게 쓰지 마세요:

```python
if not result.get("nextCursor"):
    break
```

빈 문자열도 유효한 커서입니다. 참(truthiness) 검사는 너무 일찍 멈춥니다.

클라이언트는 커서를 디코딩하거나, 증가시키거나, 순서를 위해 이전 커서와 비교하거나, 페이지 번호를 추론해서는 안 됩니다. 서버는 커서에 서명하거나, 카탈로그 버전에 묶거나, 비공개 상태로 매핑할 수 있습니다. 그것은 서버의 구현 디테일입니다.

예시 서버는 첫 페이지 다음에 의도적으로 `""`를 돌려줍니다. 클라이언트는 두 번째 요청에 그 정확한 값을 보내야 합니다. 그 트레이스는:

```text
<커서 없는 첫 요청>
<커서 ""를 담은 두 번째 요청>
```

잘못된 커서는 JSON-RPC invalid params, 코드 `-32602`를 만듭니다.

## 컴플리션은 권한 경계다

`completion/complete`는 프롬프트 인자와 리소스 템플릿 인자에 대한 제안을 제공합니다. 대화형 폼에 유용하지만, 평범한 목록 메서드가 지키는 이름들을 새어 나르게 할 수 있습니다.

컴플리션 요청은 참조와 채우고 있는 인자를 이름으로 지정합니다:

```json
{
  "method": "completion/complete",
  "params": {
    "ref": {
      "type": "ref/prompt",
      "name": "deployment_review"
    },
    "argument": {
      "name": "environment",
      "value": "st"
    }
  }
}
```

결과는 최대 100개의 값을 돌려주고 `total`과 `hasMore`를 함께 보고할 수 있습니다.

참조된 프롬프트나 리소스가 쓰는 것과 같은 권한 경계를 적용하세요. 예시의 분석가는 `development`와 `staging`을 받습니다. `production`은 운영자만 받을 수 있습니다.

프로덕션 컴플리션에는 또한 다음이 필요합니다:

- 입력 검증;
- 호출자 인식 필터링;
- 클라이언트의 요청 디바운싱;
- 서버의 속도 제한;
- 경계가 있는 결과 개수;
- 민감한 제안 값을 노출하지 않는 로그.

컴플리션은 도움말이지 발견 우회 수단이 아닙니다.

## 두 개의 오류 층

프로토콜 오류와 도구 실행 오류를 분리해 두세요.

MCP 요청을 올바르게 디스패치할 수 없을 때는 JSON-RPC 오류를 사용합니다:

- 모르는 도구 이름;
- 잘못된 요청 모양;
- 빠진 요청 메타데이터;
- 잘못된 커서.

호출이 도구에 도달했고 도구가 실행 가능한(actionable) 실패를 보고할 때는 `isError: true`인 완전한 도구 결과를 사용합니다:

- 보고서 소스를 사용할 수 없음;
- 날짜가 지원 범위 밖;
- 비즈니스 규칙이 요청된 작업을 거부.

모델은 도구 실행 오류를 스스로 수리할 때가 많습니다. 하지만 자기 출력 스키마를 어긴 서버는 수리할 수 없습니다.

도구가 출력 스키마를 선언했다면, 실행 가능한 실패를 그 스키마 안에서 모델링하세요. 예시 `route_report` 실패는 사람이 읽는 오류 텍스트와 `isError: true`와 함께 요청된 리전(region)을 `accepted: false`로 돌려줍니다.

## 직접 만들기

`code/main.py`는 파이썬 표준 라이브러리로 경계의 양쪽을 만듭니다.

서버는 다음을 구현합니다:

- 요청별 MCP 메타데이터 검증;
- 도구와 컴플리션 기능을 갖춘 `server/discover`;
- 결정론적 `tools/list` 페이지네이션;
- 하나는 반드시 거부되어야 하는 네 개의 도구 디스크립터;
- 배열 구조화 출력;
- 현재의 모든 도구 콘텐츠 블록 타입;
- 인식된 파라미터 헤더를 디코딩하고 불일치에 HTTP `400`과 JSON-RPC `-32020`을 돌려주는 Streamable HTTP 일치 게이트;
- 권한이 검사되고 속도 제한된 컴플리션.

클라이언트는 다음을 구현합니다:

- 디스크립터 수용;
- 전체 트리 `x-mcp-header` 위치 검증과 민감 필드 정책;
- 정확한 평문-보이는-ASCII 또는 base64 UTF-8 값 인코딩;
- 빈 문자열을 따라가는 불투명 커서 루프;
- 인자와 결과 검증;
- 콘텐츠 블록 검증;
- 이름만 담고 값은 담지 않는 헤더 감사 이벤트.

의도적으로 안전하지 않은 디스크립터는 교육 데이터입니다. 하나의 거부된 도구가 유효한 도구의 로딩을 막지 않음을 증명합니다.

## 대화형 실습

`code/main.py`를 열고 `TOOLS`를 찾으세요.

1. `tag_catalog.outputSchema.type`을 `array`에서 `object`로 바꿉니다.
2. 데모를 실행합니다. 클라이언트가 돌아온 배열을 거부해야 합니다.
3. 스키마를 복원합니다.
4. 첫 페이지의 `nextCursor`를 `""`로 둔 채, 마지막 페이지가 필드를 생략하는 대신 `nextCursor: None`을 돌려주게 만듭니다.
5. 테스트를 실행하고 커서 트레이스를 비교합니다.
6. 문자열 속성에 `x-mcp-header: "Authorization"`을 추가합니다.
7. 디스크립터 수용이 호출 전에 그것을 거부하는지 확인합니다.
8. 유니코드, 줄바꿈, 앞뒤 공백, 그리고 리터럴 텍스트 `=?base64?SGVsbG8=?=`를 담은 `region` 값을 시도합니다. 내보낸 각 헤더를 디코딩하고 원래 값이 정확히 살아남는지 증명합니다.
9. 애너테이션을 `oneOf`, `items`, 또는 `$ref` 정의 아래로 옮깁니다. 데모가 그 분기를 결코 사용하지 않더라도 각 디스크립터가 거부되는지 확인합니다.
10. 인식된 헤더를 제거하거나 디코딩된 값을 바꿉니다. HTTP 경계가 상태 `400`과 JSON-RPC 코드 `-32020`을 돌려주는지 확인합니다.

요점은 JSON 모양을 외우는 것이 아닙니다. 각 게이트가 자기를 소유한 경계에서 실패하는 것을 지켜보는 것입니다.

## 실습 과제

`search_evidence` 도구로 계약 실습을 확장하세요.

요구 사항:

1. 입력 스키마는 `query`, `limit`, 안전한 `region` 라우팅 필드를 받습니다.
2. 출력 스키마는 `uri`, `title`, `score`를 가진 객체들의 배열입니다.
3. 결과는 호환성 텍스트와 항목별 리소스 링크를 포함합니다.
4. 인자는 모르는 속성을 거부합니다.
5. `limit`는 애플리케이션 검증으로 경계가 정해집니다.
6. 한 URI에 접근할 수 없는 호출자는 컴플리션이나 도구 출력으로도 그 URI를 보지 못합니다.
7. 테스트에는 맞지 않는 점수, 잘못된 헤더 애너테이션, 두 페이지짜리 목록이 포함됩니다.
8. 헤더 값 테스트는 보이는 ASCII, 유니코드, 제어 문자, 공백, 센티넬처럼 보이는 텍스트, 그리고 양쪽 자바스크립트 안전 정수 경계를 다룹니다.
9. HTTP 픽스처는 대소문자 무관 헤더 이름은 받아들이지만, 없거나 일치하지 않는 인식된 값은 상태 `400`과 코드 `-32020`으로 거부합니다.

## 검증하기

다음 진술들이 참일 때 이 레슨은 완성입니다:

- `tools/list`는 반복 호출에서 같은 논리적 순서를 돌려줍니다.
- 클라이언트는 `nextCursor`가 `""`일 때 두 번째 요청을 수행합니다.
- 안전하지 않은 민감 헤더 디스크립터는 제외되고 다른 도구는 계속 사용할 수 있습니다.
- 배열은 배열 출력 스키마를 통과합니다.
- 객체는 같은 배열 스키마에서 실패합니다.
- 오류 결과는 게시된 출력 스키마를 생략하거나 어길 수 없습니다.
- 텍스트, 이미지, 오디오, 리소스 링크, 내장 리소스 블록이 검증됩니다.
- 헤더 감사 이벤트는 이름만 담고 값은 없습니다.
- 평문 보이는 ASCII는 평문으로 남고, 유니코드, 제어 문자, 패딩된, 빈, 센티넬처럼 보이는 값은 정확한 base64 UTF-8 인코딩으로 왕복합니다.
- 자바스크립트 안전 범위 밖의 미러링된 정수는 거부됩니다.
- `oneOf`, `items`, 중첩 객체, `$ref` 정의, 출력 스키마 아래의 애너테이션은 수용 중에 거부됩니다.
- 대소문자 무관 인식된 헤더 이름은 디코딩된 값이 본문과 정확히 일치할 때만 통과하고, 없거나 일치하지 않는 사본은 HTTP `400`과 JSON-RPC `-32020`을 만듭니다.
- 분석가 컴플리션은 절대 `production`을 돌려주지 않습니다.
- 도구 실패는 `isError: true`를, 잘못된 프로토콜 호출은 JSON-RPC `error`를 사용합니다.

| 헤더와 본문 불일치 | 게이트웨이는 한 대상으로 라우팅하고 오리진은 다른 것을 실행 | 디스패치 전에 HTTP `400`과 JSON-RPC `-32020`으로 거부 |
| 출력 스키마 무시 | 다운스트림 코드가 오염된 구조를 소비 | 모델이나 애플리케이션 사용 전에 검증 |

| 컴플리션이 전역 제안 공유 | 숨겨진 테넌트 이름이 새어 나감 | 호출자, 참조, 권한으로 필터 |
| 도구 애너테이션을 정책으로 취급 | 파괴적 작업이 확인을 우회 | 애너테이션 밖에서 권한과 승인 강제 |
| 잘못된 도구 하나가 발견을 맺음 | 서버 전체가 사용 불가 | 잘못된 디스크립터를 거부하고 유효한 도구는 독립적으로 수용 |

## 핵심 용어

| 용어 | 의미 |
|------|---------|
| `inputSchema` | 받아들이는 도구 인자를 정의하는 JSON Schema 객체 |
| `outputSchema` | `structuredContent`를 정의하는 선택적 JSON Schema |
| `structuredContent` | 도구 결과가 만드는 임의의 JSON 값 |
| 콘텐츠 블록 | 타입이 지정된 텍스트, 이미지, 오디오, 리소스 링크, 내장 리소스 |
| `x-mcp-header` | 원시(primitive) 인자를 Streamable HTTP 메타데이터로 미러링하는 스키마 애너테이션 |
| 불투명 커서 | 클라이언트가 값을 해석하지 않는 서버 발행 페이지네이션 토큰 |

| 수용(Admission) | 발견된 디스크립터를 노출하거나 거부하는 클라이언트 결정 |
