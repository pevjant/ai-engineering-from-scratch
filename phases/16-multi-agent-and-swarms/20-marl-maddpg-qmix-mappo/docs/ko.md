# MARL — MADDPG, QMIX, MAPPO

> 멀티 에이전트 협조(coordination)의 강화 학습 유산입니다. 2026년에도 LLM 에이전트 시스템에 계속 영향을 주고 있습니다. **MADDPG**(Lowe 등, NeurIPS 2017, arXiv:1706.02275)는 중앙 집중 학습 + 분산 실행(Centralized Training, Decentralized Execution; CTDE) 패턴을 도입했습니다: 학습 중에는 각 크리틱(critic)이 모든 에이전트의 상태와 행동을 봅니다. 테스트 시에는 지역 액터(actor)만 실행됩니다. 협력, 경쟁, 혼합 상황 모두에서 작동합니다. **QMIX**(Rashid 등, ICML 2018, arXiv:1803.11485)는 단조(monotonic) 혼합 네트워크를 곁들인 가치 분해(value decomposition) 기법입니다. 에이전트별 Q값이 결합 Q로 합쳐져 `argmax`가 깔끔하게 분산 적용됩니다 — StarCraft Multi-Agent Challenge(SMAC)에서 압도적인 성적을 냈습니다. **MAPPO**(Yu 등, NeurIPS 2022, arXiv:2103.01955)는 중앙 집중 가치 함수를 갖춘 PPO입니다. 파티클 월드, SMAC, Google Research Football, Hanabi에서 최소한의 튜닝만으로 "놀랍도록 효과적"이었습니다. 이 알고리즘들은 분산적으로 행동해야 하는 에이전트 팀의 정책(policy) 학습을 떠받치고 있습니다. MAPPO는 **2026년 협력 MARL의 기본 베이스라인**입니다. 이 레슨에서는 작은 그리드 월드 장난감 환경에서 각 알고리즘을 직접 만들어 보며, LLM 에이전트 학습에 손대기 전에 세 가지 아이디어를 몸에 익힙니다.

**유형:** Learn
**언어:** Python (표준 라이브러리, NumPy 없는 경량 구현)
**선수 지식:** 페이즈 09 (강화 학습), 페이즈 16 · 09 (Parallel Swarm Networks)
**시간:** 약 90분

## 문제

LLM 에이전트 시스템은 점점 더 에이전트 간 협조를 위한 정책을 학습하고 있습니다: 언제 양보하고, 언제 행동하고, 어떤 동료를 호출할지 말이죠. 이런 정책을 학습하는 방법을 알려 주는 문헌이 바로 다중 에이전트 강화 학습(Multi-Agent Reinforcement Learning, MARL)입니다. MARL은 LLM 물결보다 먼저 등장했고, 지배적인 알고리즘은 몇 되지 않습니다.

패턴 어휘 없이 MARL 논문을 읽으면 고통스럽습니다. 중앙 집중 학습 + 분산 실행(CTDE), 가치 분해, 중앙 집중 크리틱은 유행어가 아니라, 구체적인 문제에 대한 구체적인 해답입니다:

- 독립 RL(각 에이전트가 따로 학습)은 각 에이전트의 입장에서 비정상적(non-stationary)입니다. 나쁩니다.
- 중앙 집중 RL(하나의 에이전트가 전부 조종)은 확장되지 않고 실행 제약도 어깁니다.
- CTDE는 양쪽의 장점을 취합니다: 전역 정보로 학습하고, 지역 정책으로 배포합니다.

## 개념

### 논문들이 사용하는 세 가지 환경

- **Particle World (multi-agent particle env).** 협력/경쟁 태스크가 있는 단순한 2D 물리 환경. MADDPG의 원조 테스트베드.
- **StarCraft Multi-Agent Challenge (SMAC).** 부분 관측 상황의 협력적 세부 지휘(micro-management). QMIX의 테스트베드. 이산적 행동, 연속적 상태.
- **Google Research Football, Hanabi, MPE.** MAPPO의 베이스라인 환경들.

환경마다 행동/관측 유형이 다릅니다. 알고리즘들은 그에 맞게 선택됩니다.

### MADDPG (2017) — CTDE 패턴

각 에이전트 `i`는 자신의 관측을 행동으로 바꾸는 액터 `mu_i(o_i)`를 갖습니다. 또한 학습 중에는 모든 관측과 모든 행동을 보는 크리틱 `Q_i(x, a_1, ..., a_n)`도 갖습니다. 액터는 크리틱의 평가를 기준으로 정책 그래디언트로 업데이트됩니다.

```
actor update:    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) at a_i=mu_i(o_i)]
critic update:   TD on Q_i(x, a_1..n) given next-state joint estimate
```

CTDE인 이유: 학습 시점에는 모두의 행동을 알 수 있고, 우리는 그것으로 각 크리틱의 분산을 줄입니다. 배포 시점에는 각 에이전트가 `o_i`만 보고 `mu_i(o_i)`를 호출합니다.

실패 양상: 크리틱은 에이전트 수 N에 비례해 커집니다(입력에 모든 행동이 포함). 근사 기법 없이는 대략 10개 에이전트를 넘어서 확장되지 않습니다.

### QMIX (2018) — 가치 분해

협력 전용입니다. 전역 보상이 에이전트별 Q값의 단조 함수의 합으로 표현됩니다:

```
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

단조성 덕분에 `argmax_a Q_tot`은 각 에이전트가 `argmax_{a_i} Q_i`를 독립적으로 선택하는 방식으로 계산할 수 있습니다. 이것이 바로 우리가 필요로 하는 **분산 실행 속성 그 자체**입니다. 학습 시점에는 혼합 네트워크(mixing network)가 에이전트별 Q값들로부터 `Q_tot`을 만들어 냅니다.

QMIX가 SMAC에서 이기는 이유: 협력적 스타크래프트 세부 지휘는 동질적인 에이전트, 지역 관측, 전역 보상을 갖추고 있어서 가치 분해에 완벽히 들어맞습니다.

실패 양상: 단조성 제약은 꽤 까다롭습니다. 일부 태스크는 단조 분해가 불가능한 보상 구조를 갖습니다(한 에이전트가 팀을 위해 희생하는 경우). 확장 기법들(QTRAN, QPLEX)이 이 제약을 완화합니다.

### MAPPO (2022) — 뒤늦게 인정받은 기본값

Multi-Agent PPO: 중앙 집중 가치 함수를 곁들인 PPO입니다. 각 에이전트는 자기만의 정책을 갖고, 모든 에이전트는 전체 상태를 보는 가치 함수를 공유합니다(또는 에이전트별로 가집니다). Yu 등(2022)은 다섯 개 벤치마크에서 MAPPO를 MADDPG, QMIX 및 그 확장들과 비교했고 다음을 발견했습니다:

- MAPPO는 파티클 월드, SMAC, Google Research Football, Hanabi, MPE에서 off-policy MARL 방법들과 대등하거나 더 좋았습니다.
- 하이퍼파라미터 튜닝이 거의 필요 없습니다.
- 학습이 안정적이고, 시드를 바꿔도 재현됩니다.

이 논문 전까지 커뮤니티는 on-policy MARL을 과소평가하고 있었습니다. 2026년 현재 MAPPO는 협력 MARL의 기본 베이스라인이며, 어떤 새 방법이든 이것을 이겨야 합니다.

### LLM 에이전트 엔지니어가 왜 신경 써야 하나

세 가지 직접적인 활용처가 있습니다:

1. **라우터 학습.** 메타 에이전트가 어떤 하위 에이전트가 태스크를 맡을지 고릅니다. N개의 분산 하위 에이전트와 하나의 중앙 라우터가 있는 MARL 문제입니다. MAPPO가 잘 맞습니다.
2. **역할의 자발적 등장.** 생성형 에이전트 시뮬레이션에서, 에이전트들이 시간이 지나며 상호 보완적인 역할을 갖도록 학습시키는 것은 사실상 MARL 문제입니다. QMIX 스타일의 가치 분해는 구조적으로 보완성을 강제합니다.
3. **멀티 에이전트 도구 사용.** 에이전트들이 도구를 공유하고 예산을 두고 경쟁할 때, CTDE로 학습하면 자원 제약을 지키는 배포 가능한 지역 정책이 만들어집니다.

실전 유의점: 2026년 현재 대부분의 프로덕션(운영 환경) LLM 에이전트 시스템은 정책을 학습시키기보다 프롬프트로 조율합니다. MARL이 등장하는 경우는 (a) 상호작용 데이터가 많고, (b) 명확한 보상 신호가 있고, (c) 학습 인프라에 투자할 의지가 있을 때입니다.

### RL을 넘어선 설계 패턴으로서의 CTDE

학습을 하지 않더라도 CTDE는 유용한 아키텍처 패턴입니다:

- *설계* 단계에서는 팀 전체 가시성을 가정합니다.
- *런타임*에는 분산 실행을 강제합니다: 각 에이전트는 `o_i`만 봅니다.

이 패턴은 에이전트별 상태를 명시적으로 유지하고 부분 관측 가능성을 미리 고민하게 만듭니다. 많은 프로덕션 멀티 에이전트 시스템이 어디서나 공유 상태를 은근히 가정하곤 하는데 — CTDE 규율이 그런 설계를 막아 줍니다.

### 비정상성(non-stationarity) 문제

여러 에이전트가 동시에 학습하면, 각 에이전트의 환경(다른 에이전트들의 정책을 포함)이 계속 바뀝니다. 고전적인 단일 에이전트 RL의 증명들은 무너집니다. 이 레슨의 MARL 알고리즘들은 모두 이 문제를 다룹니다:

- MADDPG: 전역 크리틱이 모든 행동을 보므로, 가치 추정치가 안정적(정상적)입니다.
- QMIX: 가치 분해가 학습을 최적성이 잘 정의되는 결합 Q 공간으로 옮깁니다.
- MAPPO: 중앙 집중 가치 함수가 타인의 정책 변화에서 오는 분산을 흡수합니다.

LLM 에이전트 시스템에서 비정상성은 이런 식으로 나타납니다. "내 에이전트는 지난달까지 잘 됐는데, 상류의 다른 에이전트가 바뀌자 내 에이전트가 오작동한다." CTDE로 MARL을 학습시키는 것이 원칙적인 해법이고, 프롬프트 수준의 수정은 빠르지만 오래가지 못합니다.

### 이 레슨에서 다루지 않는 것

실제 네트워크를 학습시키는 것은 페이즈 09의 주제입니다. 이 레슨은 그래디언트 업데이트 없이 CTDE, 가치 분해, 중앙 집중 가치 패턴을 보여 주는 스크립트 기반 정책 버전을 만듭니다. 목표는 본격적인 MARL 라이브러리(PyMARL, MARLlib, RLlib multi-agent)를 집어 들기 전에 패턴을 몸에 익히는 것입니다.

## 직접 만들기

`code/main.py`는 작은 2에이전트 협력 그리드 월드 위에서 세 가지 패턴 시연을 구현합니다:

- 환경: 4x4 그리드 위의 2개 에이전트, 보상 펠릿 1개. 어떤 에이전트든 펠릿에 도달하면 보상 = 1이고 태스크가 끝납니다.
- `IndependentAgents` — 각 에이전트가 다른 에이전트를 환경의 일부로 취급합니다. 베이스라인.
- `MADDPGStyle` — 중앙 집중 크리틱이 결합 가치를 계산하고, 액터 정책이 그것을 기준으로 업데이트됩니다. 스크립트 기반 정책 개선.
- `QMIXStyle` — 단조 혼합기를 갖춘 가치 분해.
- `MAPPOStyle` — 중앙 집중 가치 함수; 정책들이 공유 베이스라인을 기준으로 업데이트됩니다.

네 가지 모두 같은 에피소드를 실행하고 목표 도달까지 평균 걸음 수를 보고합니다. CTDE 변형들이 독립 베이스라인보다 더 짧은 경로로 수렴합니다.

실행:

```
python3 code/main.py
```

예상 출력: 독립 에이전트는 평균 약 6걸음이 걸립니다. CTDE 변형들은 약 3.5걸음 쪽으로 수렴합니다(4x4 그리드의 최적은 3걸음). 스크립트 기반 정책임에도 패턴의 차이가 드러납니다.

## 출시하기

프로덕션에서 MARL은 드뭅니다. 그래도 쓴다면:

- **MAPPO로 시작하세요.** 2022년 논문이 이것을 베이스라인으로 만들었습니다. 이것부터 재현하면 더 화려한 방법을 쫓으며 헤매는 몇 주를 아낄 수 있습니다.
- **모든 에이전트의 관측과 행동 스트림을 기록하세요.** 에이전트별 트레이스 없이 MARL을 디버깅하는 것은 절망적입니다.
- **학습 코드와 실행 코드를 분리하세요.** CTDE는 규율입니다. 실행 경로가 정말로 `o_i`만 보게 하세요.
- **보상 설계 경고.** MARL은 보상 설계에 극도로 민감합니다. 설계에 협조 버그가 하나만 있어도 에이전트들은 그 버그를 이용하는 법을 배웁니다. 적대적 테스트를 돌리세요.
- **LLM 에이전트라면**, 먼저 프롬프트 수준의 정책을 고려하세요. 상호작용 데이터 + 보상 신호 + 인프라가 모두 갖춰졌을 때만 MARL 학습에 투자하세요.

3. MADDPG(arXiv:1706.02275)의 3절을 읽으세요. 정확한 크리틱 업데이트 규칙을 자기 말로 의사코드에 상징적으로 옮겨 적어 보세요.
4. MAPPO(arXiv:2103.01955)를 읽으세요. 저자들은 왜 중앙 집중 가치 + PPO가 그들의 벤치마크에서 off-policy MARL을 이긴다고 주장하나요? 가장 강력한 주장 세 가지를 나열하세요.
5. 가상의 LLM 에이전트 시스템(예: 리서치 에이전트 + 요약기 + 코더)에 CTDE를 설계 패턴으로 적용해 보세요. 설계 시점에는 있지만 런타임에는 없는 결합 정보는 무엇인가요?

| CTDE | "Centralized Training, Decentralized Execution" | 전역 정보로 학습; 지역 정책으로 배포. |
| MADDPG | "Multi-Agent DDPG" | 모든 관측 + 행동을 보는 에이전트별 크리틱을 갖춘 CTDE. |
| QMIX | "가치 분해" | 에이전트별 Q값의 단조 혼합. 협력 전용. |
| MAPPO | "Multi-Agent PPO" | 중앙 집중 가치 함수를 갖춘 PPO. 2026년 기본 베이스라인. |
| 가치 분해 | "개별 Q의 합" | 결합 Q를 에이전트별 Q의 단조 함수로 표현. |
| 비정상성 | "움직이는 과녁" | 타인이 학습할수록 각자의 환경이 바뀜. MARL의 핵심 문제. |
| On-policy / off-policy | "현재 정책 / 리플레이로 학습" | PPO는 on-policy(MAPPO); DDPG와 Q-learning은 off-policy. |
| SMAC | "StarCraft Multi-Agent Challenge" | 협력적 세부 지휘 벤치마크; QMIX의 고향 무대. |
