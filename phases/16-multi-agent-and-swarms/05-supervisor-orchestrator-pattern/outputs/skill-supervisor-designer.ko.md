> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-supervisor-designer.md](skill-supervisor-designer.md)

병렬 서브에이전트 리서치의 이득을 보는 사용자 쿼리가 주어지면, 어떤 프레임워크(LangGraph, OpenAI Agents SDK, CrewAI Hierarchical)에든 바로 연결할 수 있는 슈퍼바이저 패턴 설계를 만드세요.

만들어야 할 것:

1. **복잡도 추정.** 이 쿼리는 단순(에이전트 1개, 도구 호출 3~10회)인가요, 중간(워커 2~4개)인가요, 복잡(워커 5개 이상)인가요? Anthropic의 노력-규모 조정 휴리스틱을 들어 한 문장으로 근거를 대세요.
2. **리드 시스템 프롬프트.** 반드시 포함할 것: (a) 분해 지침, (b) 종합 지침, (c) 리드는 원본 소스 내용을 절대 읽지 않고 워커 요약만 읽는다는 명시적 규칙.
3. **워커 시스템 프롬프트.** 역할마다 하나씩, 각각 자기 좁은 범위와 리드가 기대하는 출력 형식을 명시합니다.
4. **서브 질문 분해 규칙.** 리드는 쿼리를 어떻게 쪼개나요? 넓게 시작해서 좁히는 방식인가요, 직접 분해인가요? 서브 질문을 탈락시키는 기준은 무엇인가요(다른 질문과의 중복, 너무 넓음)?
5. **종합 템플릿.** 명시적인 충돌 처리 규칙: 두 워커가 상충하는 사실을 반환하면, 종합은 조용히 한쪽을 고르는 것이 아니라 불일치를 표면화해야 합니다.
6. **모델 페어링.** 리드에는 어떤 모델(추론 등급), 워커에는 어떤 모델(더 빠르고 싼 등급). 그 트레이드오프를 설명하세요.
7. **관측 가능성 요구사항.** 최소 추적 지점: 계획, 각 워커의 시작/종료, 종합 입력, 종합 출력.

하드 리젝트(무조건 거부):

- 리드가 직접 도구를 사용하는 설계. 리드는 계획과 종합만 합니다.
- 범위 표류를 허용하는 워커 프롬프트(예: 경계 없이 "X와 관련된 것은 뭐든 리서치해라").
- 충돌을 숨기는 종합 템플릿.

거절 규칙:

- 쿼리가 단순하다면(총 도구 호출이 10회 미만으로 추정), 설계를 거절하고 단일 에이전트를 대신 추천하세요. Anthropic의 15배 토큰 비용 발견을 인용하세요.
- 쿼리가 순차적이라면(2단계가 1단계의 출력을 필요로 함), 거절하고 파이프라인/체인 패턴을 대신 추천하세요.
- 사용자가 결정성과 감사를 위해 최적화하고 있다면, 슈퍼바이저를 거절하고 LangGraph 정적 그래프를 추천하세요.

출력: 한 페이지짜리 설계 브리프. 복잡도 추정과 패턴 적합 판정("슈퍼바이저가 적합")으로 시작하세요. 시스템이 계속 돌아갈 예정이라면 레인보우 배포 리마인더로 닫습니다.
