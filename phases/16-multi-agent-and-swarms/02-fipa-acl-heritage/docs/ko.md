# FIPA-ACL과 발화 행위(Speech Acts)의 유산

> MCP 이전, A2A 이전에 FIPA-ACL이 있었습니다. 2000년 IEEE Foundation for Intelligent Physical Agents는 스물 개의 퍼포머티브(performatives, 수행 동사), 두 개의 콘텐츠 언어, 그리고 일련의 상호작용 프로토콜 — 컨트랙트 넷, 구독/통지, request-when — 을 갖춘 에이전트 통신 언어를 비준했습니다. 온톨로지 오버헤드가 웹에는 너무 무거워서 업계에서 잊혀졌지만, 멀티 에이전트 시스템의 LLM 부흥은 형식 의미론 없이 조용히 같은 아이디어를 다시 구현하고 있습니다: JSON 계약이 퍼포머티브를 대신하고, 자연어가 온톨로지를 대신합니다. 이 레슨은 FIPA-ACL을 진지하게 읽어서, 2026년 프로토콜 결정 중 무엇이 재발명이고 무엇이 참신한지, 그리고 현재의 물결이 2000년대에 이미 해결된 문제를 어디서 재발견하게 될지를 볼 수 있게 합니다.

**언어:** Python (표준 라이브러리)
**선수 지식:** 페이즈 16 · 01 (왜 멀티 에이전트인가)
**시간:** 약 60분

## 문제 상황

2026년 에이전트 프로토콜 지형은 매우 붐빕니다: 도구용 MCP, 에이전트용 A2A, 엔터프라이즈 감사용 ACP, 분산 신뢰용 ANP, 자연어 콘텐츠용 NLIP, 거기에 CA-MCP와 수십 개의 연구 제안까지. 각 명세는 자신을 기반 기술로 내세웁니다.

솔직하게 읽으면, 그 대부분은 아주 구체적인 20년 된 판정 트리를 재발견하는 것입니다. Austin(1962)과 Searle(1969)의 발화 행위 이론은 "발화는 행위다"라는 통찰을 줬습니다. KQML(1993)은 그것을 와이어 프로토콜로 만들었습니다. FIPA-ACL(2000년 비준)은 참조 표준을 만들어냈습니다: 스물 개의 퍼포머티브, 콘텐츠 언어 SL0/SL1, 컨트랙트 넷과 구독-통지를 위한 상호작용 프로토콜. JADE와 JACK이 Java 참조 플랫폼이었습니다. 이 노력은 온톨로지 오버헤드가 너무 무겁고 웹이 이기고 있어서 2010년경 기울었습니다.

MCP의 `tools/call`, A2A의 과제 라이프사이클, CA-MCP의 공유 컨텍스트 저장소를 볼 때, 여러분은 FIPA 결정의 더 부드럽고 JSON 네이티브인 리해시(rehash)를 보고 있는 것입니다. 이 유산을 알면 두 가지를 알 수 있습니다: 어떤 새로운 "혁신"이 실은 재발명인지, 그리고 어떤 옛 실패 양상을 새 명세들이 재발견하게 될지.

## 핵심 개념

### 발화 행위, 한 문단 요약

Austin은 어떤 문장은 세계를 기술하지 않는다는 것을 알아챘습니다 — 그 문장들은 세계를 바꿉니다. "약속합니다." "요청합니다." "선언합니다." 그는 이것을 수행 발화(performative utterance)라고 불렀습니다. Searle은 다섯 범주로 형식화했습니다: 단언(assertive), 지시(directive), 약속(commissive), 표현(expressive), 선언(declarative). KQML(Finin 등, 1993)은 이것을 소프트웨어 에이전트용으로 작동 가능하게 만들었습니다: 메시지는 퍼포머티브(행위)와 콘텐츠(그 행위의 대상)로 이뤄집니다. FIPA-ACL은 KQML의 빈틈을 정리하고 스물 개의 퍼포머티브 중심으로 표준화했습니다.

### FIPA의 스물 개 퍼포머티브 (일부 목록)

| 퍼포머티브 | 의도 |
|---|---|
| `inform` | "P가 참이라고 알린다" |
| `request` | "X를 해달라고 요청한다" |
| `query-if` | "P가 참인가?" |
| `query-ref` | "X의 값은 무엇인가?" |
| `propose` | "X를 하자고 제안한다" |
| `accept-proposal` | "그 제안을 받아들인다" |
| `reject-proposal` | "그 제안을 거절한다" |
| `agree` | "X를 하기로 동의한다" |
| `refuse` | "X를 하는 것을 거부한다" |
| `confirm` | "P가 참임을 확인한다" |
| `disconfirm` | "P를 부인한다" |
| `not-understood` | "네 메시지를 해석하지 못했다" |
| `cfp` | "X에 관한 제안을 모집한다" |
| `subscribe` | "X가 바뀌면 알려달라" |
| `cancel` | "진행 중인 X를 취소한다" |
| `failure` | "X를 시도했지만 실패했다" |

전체 목록은 `fipa00037.pdf`(FIPA ACL 메시지 구조)에 있습니다. 요점은 이것을 암기하는 것이 아니라, 이 목록의 모든 항목에 대응하는 원시 개념을 LLM 프로토콜이 결국 다시 추가하게 된다는 것입니다.

### 정전(正典) FIPA-ACL 메시지

```
(inform
  :sender       agent1@platform
  :receiver     agent2@platform
  :content      "((price IBM 83))"
  :language     SL0
  :ontology     finance
  :protocol     fipa-request
  :conversation-id   conv-42
  :reply-with   msg-17
)
```

일곱 개 필드가 프로토콜 봉투(envelope)를 담고, 한 개 필드(`content`)가 페이로드를 담습니다. 나머지 필드들은 여러분이 JSON 프로토콜에 재시도, 스레딩, 온톨로지를 덧붙일 때마다 매번 재발명하는 바로 그것들입니다.

### 두 개의 레거시 플랫폼

**JADE**(Java Agent DEvelopment framework, 1999–2020년대)는 가장 많이 쓰인 FIPA 호환 런타임이었습니다. 에이전트는 베이스 클래스를 확장하고, ACL 메시지를 교환하고, 컨테이너 안에서 실행되며, "behavior"로 조율했습니다. 상호작용 프로토콜 라이브러리에는 컨트랙트 넷, 구독-통지, request-when, propose-accept가 포함돼 나왔습니다.

**JACK**(Agent Oriented Software, 상용)은 FIPA 메시지 위에 BDI(Belief-Desire-Intention, 신념-욕망-의도) 추론을 강조했습니다. 더 형식적이었지만 채택은 덜 됐습니다.

둘 다 웹 스택이 멀티 에이전트 사용 사례를 삼키면서 쇠퇴했습니다. MCP와 A2A는 2026년의 런타임 "컨테이너"입니다.

### FIPA가 왜 기울었나

- **온톨로지 오버헤드.** FIPA는 `content`를 해석하기 위해 공유 온톨로지를 요구했습니다. 온톨로지 합의는 수년 걸리는 표준화 과정입니다. 웹은 그냥 HTTP + JSON을 썼습니다.
- **아무도 안 쓴 형식 의미론.** SL(Semantic Language)은 엄밀한 진리 조건을 줬지만, 대부분의 프로덕션(운영 환경) 시스템은 자유 형식 콘텐츠를 쓰고 그 형식주의를 무시했습니다.
- **도구 잠금.** JADE는 Java 전용이었고 JACK은 상용이었습니다. 다양한 언어를 쓰는 팀들은 둘 다 우회했습니다.
- **인터넷이 스택을 이겼습니다.** REST, 이어서 JSON-RPC, 이어서 gRPC가 ACL의 전송 계층을 대체했습니다.

### LLM 부흥은 FIPA-lite다

FIPA `request`와 MCP `tools/call`을 비교해 봅시다:

```
(request                                {
  :sender  agent1                         "jsonrpc": "2.0",
  :receiver tool-server                   "method":  "tools/call",
  :content "(lookup stock IBM)"           "params":  {"name":"lookup_stock",
  :ontology finance                                   "arguments":{"symbol":"IBM"}},
  :conversation-id c42                    "id": 42
)                                        }
```

같은 봉투, 다른 문법입니다. 둘 다 담는 것: 누가, 누구에게, 의도, 페이로드, 상관관계 id(correlation id). 어느 쪽도 다른 쪽에 대한 혁명이 아닙니다 — 같은 설계 위의 서로 다른 트레이드오프입니다.

Liu 등의 2025년 서베이("A Survey of Agent Interoperability Protocols: MCP, ACP, A2A, ANP", arXiv:2505.02279)는 이 계보를 명시적으로 보여줍니다: MCP는 도구 사용 발화 행위에 대응하고, A2A는 에이전트 피어 발화 행위에, ACP는 감사 추적 발화 행위에, ANP는 분산 신원 확장에 대응합니다. 새 명세들은 JSON 문법과 더 느슨한 의미론을 가진 ACL의 후손들입니다.

### 트레이드오프, 솔직하게 말하면

**FIPA가 줬는데 현대 명세가 버린 것:**

- 형식 의미론 — `inform`이 발신자가 콘텐츠를 믿음을 함축함을 증명할 수 있습니다.
- 퍼포머티브의 정전 카탈로그 — "우리에게 `cancel`이 필요한가?"를 다시 논쟁할 필요가 없습니다.
- 수십 년 검증된 상호작용 프로토콜 패턴 — 컨트랙트 넷, 구독-통지, propose-accept — 과 알려진 정확성 특성.

**현대 명세가 주는데 FIPA에 없었던 것:**

- 모든 현대 도구와 호환되는 JSON 네이티브 페이로드.
- 손으로 짠 온톨로지 없이도 LLM이 해석할 수 있는 자연어 콘텐츠.
- 웹 스택 전송(HTTP, SSE, WebSocket).
- 라이브 MCP `server/discover`와 A2A Agent Card를 통한 능력 탐색.

구현을 쉽게 하려고 의도 의미론을 느슨하게 한 것. 그것이 바로 그 트레이드입니다.

### 포팅할 가치가 있는 상호작용 프로토콜

FIPA는 약 15개의 상호작용 프로토콜을 함께 출시했습니다. 이 중 셋은 LLM 멀티 에이전트 시스템으로 가져올 가치가 있습니다:

1. **컨트랙트 넷 프로토콜(CNP).** 매니저가 `cfp`(제안 모집)를 발행하고; 입찰자들이 `propose`로 응답하고; 매니저가 받아들이거나 거절합니다. 이것이 정전적인 과제 시장 패턴입니다(페이즈 16 · 16 협상).
2. **구독/통지.** 구독자가 `subscribe`를 보내면; 발행자는 주제가 바뀔 때마다 `inform`을 보냅니다. 2026년의 모든 이벤트 버스가 이것입니다.
3. **Request-When.** "조건 Y가 성립하면 X를 해라." 전제 조건이 붙은 지연 실행. 2026년의 대응물은 내구성 워크플로 엔진의 지연 과제입니다(페이즈 16 · 22 프로덕션 스케일링).

각각은 현대 메시지 큐, HTTP + 폴링, SSE 스트리밍에 깔끔하게 대응됩니다.

### 온톨로지를 버리면 무엇이 무너지나

공유 온톨로지가 없으면 에이전트는 자연어 콘텐츠에서 의미를 추론합니다. 문서화된 2026년 실패 양상은 **의미 표류(semantic drift)**입니다: 두 에이전트가 미묘하게 다른 개념에 같은 단어(`"customer"`)를 쓰고, 수신 쪽 에이전트가 잘못된 해석으로 행동하는데, 어떤 스키마 검증기도 이것을 잡지 못합니다. FIPA의 온톨로지 요구사항이라면 해석 시점에 그 메시지를 거부했을 것입니다.

풀 온톨로지로 가지 않는 완화책:

- `content`에 JSON Schema 적용 — 구조적 오류를 와이어에서 거부.
- 타입 있는 산출물(A2A) — 잘못된 모달리티를 거부.
- 봉투에 명시적 퍼포머티브 — 콘텐츠가 자연어여도 의도가 애매하지 않게 함.

### 2026년 명세들, 발화 행위 유산에 대응시키기

| 현대 명세 | FIPA 대응물 | 유지하는 것 | 버리는 것 |
|---|---|---|---|
| MCP `tools/call` | `request` | 명시적 의도, 상관관계 id | 형식 의미론, 온톨로지 |
| MCP `resources/read` | `query-ref` | 명시적 의도, 상관관계 id | 형식 의미론 |
| A2A Task 라이프사이클 | 컨트랙트 넷 + request-when | 비동기 라이프사이클, 상태 전이 | 형식적 완전성 보장 |
| A2A 스트리밍 이벤트 | 구독/통지 | 비동기 푸시 | 타입 있는 술어 구독 |
| CA-MCP 공유 컨텍스트 | 블랙보드(Hayes-Roth 1985) | 다중 쓰기 공유 메모리 | 논리적 일관성 모델 |
| NLIP | 자연어 콘텐츠 | LLM 네이티브 | 스키마 |

표를 위에서 아래로 읽으면 패턴이 보입니다: 구조적 원시 개념은 유지하고, 형식주의는 버리고, 모호함은 LLM에게 떠넘깁니다.

## 만들어 보기

`code/main.py`는 순수 표준 라이브러리 FIPA-ACL 변환기를 구현합니다. 정전 ACL 봉투를 인코딩·디코딩하고, 모든 MCP / A2A 메시지 형태가 같은 일곱 필드로 환원되는지를 보여줍니다. 데모 내용:

- 다섯 개의 MCP 스타일 및 A2A 스타일 메시지를 FIPA-ACL로 인코딩합니다.
- FIPA-ACL을 현대식 등가물로 다시 디코딩합니다.
- 하나의 매니저와 세 명의 입찰자 사이에서 `cfp`, `propose`, `accept-proposal`, `reject-proposal`을 사용하는 장난감 컨트랙트 넷 협상을 실행합니다.

실행:

```
python3 code/main.py
```

출력은 각 현대 메시지를 2026년 JSON 형태와 FIPA-ACL 형태로 나란히 보여주는 추적 결과, 그다음 컨트랙트 넷 입찰의 왕복(round-trip)입니다. 같은 프로토콜 원시 개념이 왕복을 거쳐 살아남습니다; 문법만 다를 뿐입니다.

## 출시하기

FIPA-ACL을 되살리지 마세요. 체크리스트를 되살리세요:

- 각 메시지의 의도 원시 개념(퍼포머티브)은 무엇인가?
- 요청-응답과 취소를 위한 상관관계 id가 있는가?
- 명시적 콘텐츠 언어가 있는가(JSON-RPC, 일반 텍스트, 구조화된 타입 산출물)?
- 상호작용 프로토콜이 일급(first-class)인가, 아니면 컨트랙트 넷을 처음부터 다시 구현하고 있는가?
- 두 에이전트가 콘텐츠 의미에 대해 불일치하면(의미 표류) 어떻게 되는가?

## 핵심 용어

| 용어 | 사람들이 말하는 것 | 실제 의미 |
|------|----------------|------------------------|
| 발화 행위 | "무언가를 수행하는 발화" | Austin/Searle: 발화를 행위로 보는 관점. ACL의 이론적 부모. |
| FIPA | "그 옛날 XML" | IEEE Foundation for Intelligent Physical Agents. 2000년 ACL을 표준화. |
| ACL | "에이전트 통신 언어" | FIPA의 봉투 형식: 퍼포머티브 + 콘텐츠 + 메타데이터. |
| 퍼포머티브 | "그 동사" | 메시지의 의도 클래스: `inform`, `request`, `propose`, `cfp` 등. |
| KQML | "FIPA의 전신" | Knowledge Query and Manipulation Language(1993). 더 단순하고 더 좁았다. |
| 온톨로지 | "공유 어휘" | 콘텐츠 언어가 다루는 개념들의 형식적 정의. |
| SL0 / SL1 | "FIPA 콘텐츠 언어" | Semantic Language 0과 1 수준 — 형식 콘텐츠 언어 계열. |
| 컨트랙트 넷 | "과제 시장" | 매니저가 cfp 발행; 입찰자가 제안; 매니저가 수락. 정전적 상호작용 프로토콜. |
| 상호작용 프로토콜 | "메시지 패턴" | 알려진 정확성을 가진 퍼포머티브의 나열: request-when, 구독-통지 등. |
