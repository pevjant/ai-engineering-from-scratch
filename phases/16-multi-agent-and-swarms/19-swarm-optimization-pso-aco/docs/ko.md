# LLM을 위한 스웜 최적화 (PSO, ACO)

> 생체 모방 최적화가 LLM 분야에 다시 주목받고 있습니다. **LMPSO**(arXiv:2504.09247)는 PSO를 활용하는데, 각 입자(particle)의 속도가 곧 프롬프트이고 LLM이 다음 후보를 생성합니다. 수식, 프로그램 같은 구조화된 시퀀스 출력에서 잘 작동합니다. **Model Swarms**(arXiv:2410.11163)는 각 LLM 전문가(expert)를 모델 가중치 공간 위의 PSO 입자로 취급하며, 단 200개 인스턴스만으로 9개 데이터셋에서 12개 베이스라인 대비 평균 **13.3% 향상**을 보고했습니다. **SwarmPrompt**(ICAART 2025)는 PSO와 회색 늑대(Grey Wolf) 최적화를 결합해 프롬프트를 최적화합니다. **AMRO-S**(arXiv:2603.12933)는 ACO에서 영감을 받은 페로몬 기반 전문가 시스템으로, 멀티 에이전트 LLM 라우팅에 쓰입니다 — **4.7배 속도 향상**, 사람이 읽을 수 있는 라우팅 근거, 그리고 추론과 학습을 분리하는 품질 게이트 기반 비동기 업데이트가 특징입니다. 이 레슨에서는 프롬프트 파라미터 공간에 PSO를, 에이전트 라우팅에 ACO를 직접 구현하면서, 이 고전 알고리즘들이 왜 LLM 시대에 여전히 잘 맞는지, 그리고 언제 맞지 않는지 측정해 봅니다.

**선수 지식:** 페이즈 16 · 09 (Parallel Swarm Networks), 페이즈 16 · 14 (Consensus and BFT)

## 문제

당신의 태스크 평가에서 62%를 기록하는 프롬프트가 있습니다. 이걸 개선하고 싶은데요. 가장 단순한 방법은 그래디언트 없이 손으로 하나하나 고치는 것이지만, 이건 규모가 커지면 감당이 안 됩니다. 강화 학습은 보상 신호와 충분한 롤아웃(rollout) 데이터가 필요합니다. 프롬프트를 통한 역전파는 사실상 불가능합니다 — 프롬프트는 미분 가능한 파라미터가 아니라 이산적인(discrete) 문자열이니까요.

고전적인 생체 모방 최적화 — 연속 탐색 공간용 PSO, 경로 선택용 ACO — 는 바로 이런 상황을 위해 설계된 도구입니다: 그래디언트가 필요 없고, 집단(population) 기반이고, 평가당 비용이 쌉니다. 여기에 LLM을 결합해 그래디언트 없는 탐색 단계를 맡기면, 의외로 실용적인 옵티마이저가 완성됩니다.

같은 패턴은 멀티 에이전트 시스템의 에이전트 *라우팅*에도 적용됩니다. ACO 방식의 페로몬 흔적(pheromone trail)은 어떤 에이전트가 어떤 태스크 유형에서 가장 잘했는지를 기록하고, 라우터가 그 흔적을 활용하게 하며, 페로몬을 서서히 증발시켜 경로를 다시 발견할 수 있게 합니다.

## 개념

### PSO 복습 (Kennedy & Eberhart 1995)

입자 군집 최적화(Particle Swarm Optimization)는 연속 탐색 공간 속 입자들의 집단을 사용합니다. 각 입자는 위치 `x_i`와 속도 `v_i`를 갖습니다. 매 반복마다:

```
v_i <- w * v_i + c1 * r1 * (p_best_i - x_i) + c2 * r2 * (g_best - x_i)
x_i <- x_i + v_i
evaluate fitness(x_i)
update p_best_i if improved
update g_best if global best
```

여기서 `p_best`는 각 입자 자신의 최고 기록, `g_best`는 군집 전체의 최고 기록이며, `w, c1, c2`는 각각 관성, 인지, 사회적 가중치이고 `r1, r2`는 무작위 계수입니다.

### LLM 출력에 적용한 PSO — LMPSO

arXiv:2504.09247은 PSO를 LLM이 생성하는 구조화된 출력(수식, 프로그램)에 맞게 변형했습니다. 각 입자는 후보 출력 하나입니다. 속도(velocity)는 현재 출력을 개인 최고 기록/전역 최고 기록 쪽으로 어떻게 수정할지 설명하는 *프롬프트*입니다. 그러면 LLM이 이 속도 프롬프트를 받아 새 출력을 생성합니다. 속도의 "관성"은 "작은 수정을 조금씩만 하라" 같은 프롬프트로 표현됩니다.

이 방식이 잘 작동하는 조건은 다음과 같습니다:
- 출력이 구조화되어 있을 때(파싱과 평가가 가능할 때).
- 적합도(fitness)가 자동으로 계산될 때(테스트 실행, 수식 계산 등).
- 집단이 작을 때(입자 약 10~30개). 전체 LLM 호출 수를 감당할 수 있는 수준으로 유지하려면 필수입니다.

반면, 적합도 평가에 사람의 검토가 필요하면 잘 맞지 않습니다 — 반복당 비용이 감당할 수 없을 만큼 커져 버립니다.

### Model Swarms

arXiv:2410.11163은 PSO를 출력 층에서 한 단계 위인 *모델* 층으로 옮깁니다. 각 "입자"는 전문가 LLM(파라미터)입니다. 군집은 그래디언트 없는 업데이트를 통해 파라미터를 집단의 최적 쪽으로 이동시킵니다. 보고된 결과: 9개 데이터셋에서 12개 베이스라인 대비 평균 13.3% 향상, 반복당 인스턴스는 단 200개뿐입니다.

핵심 통찰은 이렇습니다. LLM 전문가 모델들은 이미 공유된 파라미터 다양체(어댑터 가중치, LoRA 델타 등) 위에서 서로 가까이 있다는 것입니다. 이 저차원 부분 공간에서의 PSO는 비용이 낮으면서도 효과적입니다.

### ACO 복습 (Dorigo 1992)

개미 군집 최적화(Ant Colony Optimization)는 개미들이 그래프 위를 이동하고 각 경로에 페로몬 흔적이 남는 방식입니다. 개미의 이동 확률은 페로몬 농도에 비례해 가중됩니다. 태스크를 완수한 개미는 풀이(solution) 품질에 비례하는 양의 페로몬을 남깁니다. 페로몬은 시간이 지나면 증발합니다.

### AMRO-S — 에이전트 라우팅을 위한 ACO

arXiv:2603.12933은 멀티 에이전트 라우팅에 ACO를 사용합니다. 각 태스크 유형이 "목적지"이고, 각 에이전트가 가능한 경로입니다. 좋은 출력을 만들어 내는 경로일수록 페로몬이 강해집니다. 핵심 기여는 다음과 같습니다:

- **해석 가능한 라우팅 근거.** 페로몬 농도가 사람이 읽을 수 있는 신호라는 점입니다.
- **품질 게이트 기반 비동기 업데이트.** 품질 검사를 통과한 뒤에만 페로몬을 갱신하므로, 추론과 학습이 분리됩니다.
- 멀티 에이전트 라우팅 벤치마크에서 **4.7배 속도 향상**.

품질 게이트가 중요한 이유는 이렇습니다. 게이트가 없으면 "빠르지만 틀린" 에이전트도 페로몬을 쌓게 되고, 시스템 전체가 나쁜 경로에 고정되어 버립니다.

### LLM에 PSO / ACO를 쓸 때와 쓰지 말아야 할 때

**PSO를 쓰면 좋은 경우:**
- 탐색 공간이 연속적이거나 연속 파라미터로 사상될 수 있을 때(프롬프트 임베딩, LoRA 가중치, 수치 생성 파라미터 등).
- 적합도 평가가 저렴하고 자동일 때.
- 집단을 작게 유지할 수 있을 때(10~30).

**ACO를 쓰면 좋은 경우:**
- 라우팅이나 경로 선택 문제일 때.
- 결정이 시간이 지나며 누적 강화될 때(같은 태스크 유형이 반복해서 들어올 때).
- 라우팅 결정에 대해 해석 가능한 근거가 필요할 때.

**둘 다 쓰면 안 되는 경우:**
- 적합도 평가에 사람의 검토가 필요할 때(반복당 비용이 너무 큽니다).
- 탐색 공간이 PSO가 다루지 못하는 방식의 이산적·조합적 문제일 때(대신 유전 알고리즘을 쓰세요).
- 실시간 결정에 엄격한 지연 시간이 요구될 때(PSO/ACO는 단일 패스 휴리스틱에 비해 수렴이 느립니다).

### 생체 모방 기법이 여전히 강한 이유

그래디언트 기반 방법은 미분 가능한 신호가 필요합니다. 하지만 LLM의 출력이나 라우팅 결정은 간단히 미분할 수 없습니다. 유사 그래디언트 방법(강화 학습 기반 라우터, DPO 스타일 프롬프트 튜너)도 있지만 비용이 큰 학습이 필요합니다.

PSO와 ACO는 *평가기(evaluator)* 함수만 있으면 됩니다. 후보 출력이나 라우팅 결정에 점수를 매길 수만 있다면, 그 공간 위에서 최적화할 수 있습니다. 적용 문턱이 훨씬 낮아지는 이유입니다.

### 실전상 한계

- **집단 예산.** N개 입자 × T번 반복 × 평가당 비용입니다. LLM 평가가 호출당 약 $0.02라면, 입자 20개짜리 PSO를 50번 반복하는 데 약 $20이 듭니다. 미리 계획하세요.
- **탐색과 활용의 균형.** 페로몬 증발률과 PSO 관성은 서로 상충합니다. 증발이 너무 빠르면 → 풀이를 잊어버리고, 너무 느리면 → 초기의 국소 최적에 갇힙니다.
- **급격한 드리프트.** 두 알고리즘 모두 수렴한 뒤에도 적합도 지형이 바뀌면(새로운 데이터 분포 등) 다시 벗어날 수 있습니다. 최고 적합도의 안정성을 계속 관찰하세요.

## 직접 만들기

`code/main.py`는 다음을 구현합니다:

- `LMPSO` — 수치형 프롬프트 파라미터(temperature, top_k 가중치)에 대한 PSO. 각 입자의 "LLM 생성"은 스크립트로 작성된 적합도 함수로 시뮬레이션됩니다. 알고리즘을 30회 반복 실행하고 g_best의 수렴 과정을 보여 줍니다.
- `AMRO_S` — ACO 방식의 라우팅. 에이전트 3개, 태스크 유형 4개, 페로몬 행렬, 100개의 라우팅 태스크. 시간에 따른 (태스크 유형 → 에이전트 선택) 분포를 출력해 흔적(trail)이 형성되는 과정을 보여 줍니다.
- 비교: 같은 태스크 스트림에 대해 무작위 라우팅 vs ACO 라우팅. 품질과 지연 시간을 측정합니다.

실행:

```
python3 code/main.py
```

예상 출력:
- LMPSO: g_best 적합도가 무작위 수준에서 30회 반복에 걸쳐 거의 최적에 가깝게 개선됩니다.
- AMRO-S: 페로몬 테이블이 태스크 유형별 올바른 에이전트에 안정화됩니다. ACO 라우팅은 품질 면에서 무작위 라우팅보다 약 30~40% 좋고, 지연 시간도 줄어듭니다(재시도가 줄어서입니다).

## 출시하기

- **작게 시작하세요.** 입자 10~20개, 반복 20~50회. 수렴 곡선이 뚜렷한 이득을 보일 때만 규모를 키웁니다.
- **반복마다 페로몬이나 g_best를 기록하세요.** 흔적 없이 스웜 옵티마이저를 디버깅하는 것은 고통스럽습니다.
- **업데이트에 품질 게이트를 적용하세요.** 특히 ACO 라우팅에서: 빠르지만 틀린 에이전트가 페로몬을 쌓게 해서는 안 됩니다.
- **분포가 바뀌면 감쇠를 리셋하세요.** 평가 분포가 바뀌면 오래된 페로몬은 쓸모없어진 상태입니다. 리셋하거나 감쇠율을 일시적으로 두 배로 높이세요.
- **반복당 비용에 상한을 두세요.** 반복당 비용 지표를 출력하세요. 반복에 $500이 들고 0.5% 개선에 그치는 PSO는 출시할 수 없습니다.

## 연습 문제

1. `code/main.py`를 실행하고 LMPSO의 수렴을 관찰하세요. 집단 크기를 5, 10, 20, 50으로 바꿔 보세요. 어느 크기부터 수렴 시간이 포화 상태가 되나요?
2. "급격한 드리프트" 실험을 구현하세요: 30회 반복 후에 적합도 함수를 바꿉니다. PSO는 얼마나 빨리 적응하나요? `p_best`를 리셋하면 도움이 되나요?
3. AMRO-S에 품질 게이트를 추가하세요: 평가 점수가 0.7을 넘는 실행에만 페로몬을 쌓습니다. 게이트 없는 버전과 비교해 수렴이 어떻게 달라지나요?
4. LMPSO(arXiv:2504.09247) 논문을 읽으세요. 논문의 "프롬프트로서의 속도"를 여러분의 수치적 속도에 대응시켜 보세요. 시뮬레이션에서 무엇이 사라지고 무엇이 보존되나요?
5. AMRO-S(arXiv:2603.12933) 논문을 읽으세요. 비동기 페로몬 업데이트와 결합된 분리형 "추론 고속 경로"를 구현하세요. 지속적인 부하 상황에서 시스템 지연 시간이 어떻게 달라지나요?
