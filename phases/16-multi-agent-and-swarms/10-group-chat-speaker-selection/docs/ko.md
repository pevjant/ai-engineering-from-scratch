# 그룹 채팅과 발언자 선택

> 공유 대화 오케스트레이션은 N개의 에이전트를 하나의 대화에 넣고, 셀렉터 함수(LLM, 라운드 로빈, 또는 커스텀 로직)가 다음에 누가 말할지 고릅니다. 이것이 바로 창발적(emergent) 멀티 에이전트 대화의 원형입니다 — 에이전트는 정적 그래프 속에서 자기 역할을 미리 알지 못하고, 그저 공유 풀에 반응할 뿐입니다. AutoGen GroupChat과 AG2 GroupChat이 참조 구현체입니다. AutoGen v0.2의 GroupChat 의미론은 AG2 포크에서 그대로 보존되었고, AutoGen v0.4는 이를 이벤트 기반 액터 모델로 다시 썼습니다. Microsoft는 2026년 2월 AutoGen을 유지 보수 모드로 전환하고 Semantic Kernel과 통합해 Microsoft Agent Framework(2026년 2월 RC)로 만들었습니다. GroupChat 프리미티브는 AG2와 Microsoft Agent Framework 양쪽 모두에 살아 있습니다 — 한 번 배워서 어디서나 쓰세요.

**유형:** 학습 + 빌드
**언어:** Python(표준 라이브러리)
**선수 지식:** 페이즈 16 · 04(프리미티브 모델)
**시간:** 약 60분

## 문제

정적 그래프(LangGraph)는 워크플로가 정해져 있을 때 강력합니다. 하지만 실제 대화는 정적이지 않습니다. 코더가 리뷰어에게 물을 때도 있고, 리서처에게 물을 때도 있고, 작가에게 물을 때도 있죠. 가능한 모든 인계(handoff)를 하드코딩하면 엣지가 폭발적으로 늘어납니다. 여러분이 원하는 것은 *공유 풀에 반응하는 에이전트들*, 그리고 다음으로 누가 말할지 정해 주는 어떤 함수입니다.

그게 바로 AutoGen GroupChat이 하는 일입니다.

## 개념

### 모양새

```
              ┌─── 공유 풀 ────┐
              │   m1  m2  m3  ...  │
              └─────────┬──────────┘
                        │ (모두가 전부 읽음)
      ┌───────┬─────────┼─────────┬───────┐
      ▼       ▼         ▼         ▼       ▼
  에이전트 A  에이전트 B  에이전트 C  에이전트 D  셀렉터
                                           │
                                           ▼
                                  "다음 발언자 = C"
```

모든 에이전트가 모든 메시지를 봅니다. 매 턴마다 셀렉터 함수가 호출되어 다음 발언자를 고릅니다.

### 셀렉터의 세 가지 방식

**라운드 로빈.** 정해진 순서를 돌고 도는 방식. 결정론적이고 에이전트 수 N에 대해 선형으로 확장되지만, 문맥을 무시합니다 — 주제가 법률 검토인데도 코더에게 순서가 돌아올 수 있죠.

**LLM 선택.** 최근 메시지 풀을 읽고 가장 적임자를 반환하도록 LLM을 호출하는 방식. 문맥을 이해하지만 느립니다. 매 턴마다 LLM 호출이 한 번씩 더해지니까요. AutoGen의 기본값입니다.

**커스텀.** 원하는 로직을 담은 파이썬 함수. 전형적인 형태는 폴백 규칙을 얹은 LLM 선택입니다(예: "코더 다음 턴은 언제나 검증자에게 준다").

### ConversableAgent API

```
agent = ConversableAgent(
    name="coder",
    system_message="You write Python.",
    llm_config={...},
)
chat = GroupChat(agents=[coder, reviewer, tester], messages=[])
manager = GroupChatManager(groupchat=chat, llm_config={...})
```

`GroupChatManager`가 셀렉터를 보관합니다. 에이전트가 한 턴을 마치면 매니저가 셀렉터를 호출하고, 셀렉터는 다음 에이전트를 반환합니다. 이 루프는 종료 조건이 충족될 때까지 계속됩니다.

### 종료 조건

흔히 쓰는 세 가지 패턴:

- **최대 라운드 수.** 전체 턴 수에 대한 하드 리밋.
- **"TERMINATE" 토큰.** 에이전트가 센티널(sentinel, 신호용 특수 메시지)을 내보낼 수 있고, 매니저는 그것이 나타나면 멈춥니다.
- **목표 달성 확인.** 가벼운 검증자가 매 턴 실행되며, 목표가 달성되면 대화를 멈춥니다.

### 계보: 포크와 통합

2025년 초, Microsoft는 AutoGen을 이벤트 기반 액터 모델 중심으로 대대적으로 다시 쓰기 시작했습니다(v0.4). 커뮤니티는 초기 도입자들이 이미 통합해 쓰던 API를 지키기 위해 AutoGen v0.2의 GroupChat 의미론을 포크해 AG2를 만들었습니다.

2026년 2월, Microsoft는 AutoGen을 유지 보수 모드로 전환하고, 이벤트 기반 액터 모델을 **Microsoft Agent Framework**(2026년 2월 RC, 현재는 Semantic Kernel과 통합)로 병합한다고 발표했습니다. GroupChat 개념은 두 계보 모두에서 살아남았고, 구현 세부만 다릅니다. v0.2 호환 코드라면 AG2가 선호되는 업스트림입니다.

### GroupChat이 어울리는 경우

- **창발적 대화.** 가능한 다음 발언자 조합을 전부 미리 연결해 두고 싶지 않을 때.
- **역할이 섞이는 작업.** 코더가 리서처에게 묻고, 리서처가 기록 보관자에게 묻고, 기록 보관자가 다시 코더에게 묻는 식. 흐름이 DAG가 아닙니다.
- **탐색적 문제 해결.** "조립 라인"보다는 "브레인스토밍 회의"를 떠올리세요.

### 실패하는 경우

- **엄격한 결정론이 필요할 때.** LLM 셀렉터는 일관성이 없을 수 있습니다. 같은 프롬프트인데 실행마다 다음 발언자가 달라집니다.
- **아첨 연쇄(sycophancy cascade).** 에이전트들이 가장 자신 있게 말한 쪽의 말을 그대로 받아들입니다. 프롬프트로 명시적으로 반박하게 만드세요.
- **컨텍스트 비대(context bloat).** 모든 에이전트가 모든 메시지를 읽으므로 10턴쯤 지나면 컨텍스트가 거대해집니다. 프로젝션(15레슨)으로 보는 범위를 좁히세요.
- **과열 발언자(hot speaker).** 셀렉터가 특정 에이전트의 전문 분야만 선호하면 그 에이전트 하나가 대화를 지배합니다. 발언자 균형(speaker balance)을 셀렉터 기능으로 넣으세요.

### 그룹 채팅 vs 슈퍼바이저

같은 프리미티브, 다른 기본값:

- 슈퍼바이저: 한 에이전트가 계획하고 나머지가 실행합니다. 셀렉터는 "플래너에게 다음을 물어본다"입니다.
- 그룹 채팅: 모든 에이전트가 대등하며, 셀렉터는 공유 풀 위에서 돌아가는 함수입니다.

둘 다 04레슨의 네 가지 프리미티브를 사용합니다. 그룹 채팅은 LLM 선택 오케스트레이션과 전체 풀 공유 상태가 기본값입니다.

```figure
swarm-speaker
```

## 만들어 보기

`code/main.py`는 표준 라이브러리만으로 GroupChat을 처음부터 구현합니다. 세 에이전트(코더, 리뷰어, 매니저), 라운드 로빈과 LLM 선택 변형, 그리고 `TERMINATE` 토큰에 의한 종료가 들어 있습니다.

데모는 두 변형 모두에 대해 대화 전사(transcript)와 셀렉터의 판단 추적을 함께 출력합니다.

실행:

```
python3 code/main.py
```

## 활용하기

`outputs/skill-groupchat-selector.md`는 주어진 작업에 맞게 GroupChat 셀렉터를 구성하는 방법을 담고 있습니다 — 라운드 로빈 vs LLM 선택 vs 커스텀 중 무엇을 쓸지, 그리고 셀렉터 입력으로 무엇(최근 메시지, 에이전트 전문 분야, 턴 수)을 쓸지 말이죠.

## 출시하기

체크리스트:

- **최대 라운드 상한.** 무조건 두세요. 일반적인 작업이면 10~20.
- **발언자 균형 지표.** 에이전트별 턴 수를 추적하고, 불균형이 임계값을 넘으면 알림을 보내세요.
- **종료 토큰.** `TERMINATE` 또는 전용 검증 에이전트.
- **프로젝션 또는 범위 제한 메모리.** 약 10메시지가 지나면 각 에이전트에게 범위를 좁힌 뷰만 주는 것을 고려하세요. 컨텍스트 비대를 막기 위함입니다.
- **셀렉터 로깅.** LLM 선택 변형에서는 셀렉터의 입력과 선택을 모두 기록하세요. 안 그러면 디버깅이 불가능합니다.

## 연습 문제

1. `code/main.py`를 실행하세요. 라운드 로빈과 LLM 선택에서 대화가 어떻게 다른지 비교해 보세요. 각 방식에서 어떤 에이전트가 대화를 지배하나요?
2. 셀렉터에 "에이전트당 최대 발언 횟수" 규칙을 추가해 보세요. 대화 전사가 어떻게 달라지나요?
3. 목표 달성 종료를 구현해 보세요. 리뷰어가 "approved"를 반환하면 멈추는 식입니다. 라운드 상한에 걸리기 전에 얼마나 자주 발동되나요?
4. GroupChat에 관한 AutoGen 안정 버전 문서(https://microsoft.github.io/autogen/stable/user-guide/core-user-guide/design-patterns/group-chat.html)를 읽고, `GroupChatManager`가 기본으로 쓰는 셀렉터가 무엇인지 찾아보세요.
5. AG2 저장소(https://github.com/ag2ai/ag2)를 읽고 v0.2 GroupChat과 v0.4 이벤트 기반 버전을 비교해 보세요. v0.4가 추가하는 구체적인 속성(처리량, 내결함성, 조합 가능성)은 무엇인가요?

## 핵심 용어

| 용어 | 사람들이 말하는 표현 | 실제 의미 |
|------|----------------|------------------------|
| GroupChat | "하나의 채팅방에 모인 에이전트들" | 공유 메시지 풀 + 셀렉터 함수. AutoGen / AG2의 프리미티브. |
| 발언자 선택(speaker selection) | "다음에 누가 말할까" | 다음 에이전트를 고르는 함수. 라운드 로빈, LLM 선택, 커스텀. |
| GroupChatManager | "회의 진행자" | 셀렉터를 소유하고 턴을 반복 도는 AutoGen 컴포넌트. |
| ConversableAgent | "기본 에이전트" | AutoGen 베이스 클래스. 메시지를 주고받을 수 있는 에이전트. |
| 종료 토큰(termination token) | "'멈춤' 단어" | 대화를 끝내는 센티널 문자열(보통 `TERMINATE`). |
| 과열 발언자(hot speaker) | "한 에이전트가 대화를 독점" | 셀렉터가 같은 에이전트만 계속 고르는 실패 양상. |
| 컨텍스트 비대(context bloat) | "풀이 무한히 커짐" | 각 에이전트가 이전 메시지를 전부 읽어 턴 수에 비례해 컨텍스트가 자람. |
| 프로젝션(projection) | "범위를 좁힌 뷰" | 컨텍스트 비대를 막으려고 공유 풀을 역할별로 좁혀 본 뷰. |
