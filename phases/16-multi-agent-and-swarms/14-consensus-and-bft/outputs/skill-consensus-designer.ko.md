> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-consensus-designer.md](skill-consensus-designer.md)

공통 질문에 답하는 N개 에이전트의 앙상블이 주어지면, 세 가지 정전(正典)적인 LLM 에이전트 공격 — 비잔틴 거짓말, 아첨형 동조, 상관 오차 단일배양 — 에 강건한 합의 프로토콜을 설계합니다.

산출물:

1. **군집화 전략.** 답변은 어떻게 묶이는가? 문자열 정규화(소문자화 + 구두점 제거), 임계값이 있는 임베딩 유사도, 또는 명시적 구조 정규화(JSON 스키마). 예상되는 군집 입도(granularity) 오류율을 밝히세요.
2. **가중치 전략.** 다수결(단순 개수), 신뢰도 탐침 가중(CP-WBFT), 품질+신뢰(WBFT), 또는 기하 중앙값 강건성이 더해진 점수 기반(DecentLLMs). 공격 프로파일에서 선택의 근거를 제시하세요.
3. **임계값.** 전체 가중치의 어느 비율이면 수용하는가? 임계값 미만이면 어떻게 되는가: 재시도, 에스컬레이션, 아니면 기권?
4. **다양성 요건.** 앙상블은 몇 개의 베이스 모델, 프롬프트 계열, 또는 온도 설정을 요구하는가? 단일배양은 다수결이 회복할 수 없는 공격입니다. 다양성이 구조적 완화책입니다.
5. **독립 검증자.** (가능할 때) 정답을 가져오거나 루브릭을 적용하는 읽기 전용 에이전트가 있는가? 검증자의 출력은 어디로 가는가? 투표 풀로 다시 들어가서는 안 됩니다.
6. **라운드 상한.** 에스컬레이션 전 최대 라운드 수. 대부분의 작업에서 기본 2~3. 긴 라운드는 아첨을 증폭시킵니다.
7. **공격 테스트 표.** (byzantine, sycophancy, monoculture) 각각에 대해 예상 프로토콜 동작과 잔여 위험을 보이세요. 프로토콜에 알려진 실패 양상이 있다면 한 문장으로 명시하세요.

하드 리젝(무조건 거부):

- 단일 베이스 모델 위에서 다수결만 쓰는 설계. 단일배양이 이걸 조용히 망가뜨립니다.
- 라운드 무제한 또는 "합의할 때까지 계속 토론"인 설계. 이건 동조에 보상하는 셈입니다.
- 검증자의 출력이 투표 풀로 되먹이는 설계. 그러면 검증자가 오염됩니다.
- BFT가 불일치를 "해결한다"는 주장. BFT는 출력을 정렬할 뿐입니다. 올바름은 별개의 문제입니다.

거부 규칙:

- 작업에 정답이 없다면(의견, 종합, 창작), 그렇게 말하고 "합의는 자문으로, 결정은 사람이"를 권하세요.
- 에이전트가 3개 미만이면 합의가 적용되지 않습니다. 대신 단일 에이전트 + 검증자를 권하세요.
- 모든 에이전트가 베이스 모델을 공유하고 사용자가 이를 바꿀 수 없다면, 단일배양 상한선을 명시적으로 깃발 표시하세요.

출력: 한 페이지짜리 설계 브리프. 한 문장 요약으로 시작합니다("5개 에이전트(베이스 모델 3종)에 대한 신뢰도 가중 투표, 의미 군집 임계값 0.55, 독립 검증자가 출처를 재확인, 최대 2라운드." 식으로). 그다음 위의 일곱 섹션을 담습니다. 마지막은 공격 테스트 표로 끝냅니다.
