> 🇰🇷 이 문서는 한국어 번역본입니다(ELI5 스타일). 원문: [skill-handoff-designer.md](skill-handoff-designer.md)

사용자 대면 작업(주로 트리아지나 스킬 기반 라우팅)이 주어지면, OpenAI Swarm이나 OpenAI Agents SDK에 바로 옮겨 탑재할 수 있는 인계 토폴로지를 만들어 냅니다.

산출물:

1. **에이전트 명단.** 각 에이전트마다: 이름, 한 문장짜리 목적, 도구, 그리고 어느 에이전트에게 인계할 수 있는지.
2. **인계 함수.** 에이전트별 도구 시그니처. 각 인계 함수는 대상 Agent를 반환합니다.
3. **컨텍스트 이전 정책.** 인계 엣지마다: 전체 기록, 최근 N메시지, 또는 요약 스냅샷. 근거도 함께 제시합니다.
4. **가드레일.** 에이전트별 입력 검증(어떤 프롬프트가 민감한 전문 에이전트로의 인계를 트리거할 수 있는지), 필요한 곳의 인계 시 인증.
5. **루프 감지.** 핑퐁을 감지하는 규칙(예: "A가 B에게 인계; B가 다시 A에게 인계"가 연달아 한 번을 넘게 발생).
6. **폴백 동작.** 인계 대상이 없을 때(제거된 에이전트, 인증 실패) 어떤 에이전트가 세션을 이어받는지.
7. **세션/메모리 계획.** Agents SDK 세션을 쓸지, 호출자가 메모리를 직접 관리할지, 아예 메모리 없이 갈지.

하드 리젝(무조건 거부):

- 루프 감지가 없는 인계 설계.
- 서로 다른 도구 권한을 가진 전문 에이전트에게 전체 기록을 넘기는 인계 함수(보안 위험).
- Swarm의 무상태 동작을 전제하면서 다중 턴 메모리를 요구하는 설계 — 대신 Agents SDK 세션을 쓰세요.

거부 규칙:

- 작업이 병렬 실행을 필요로 한다면 Swarm을 거부하고 슈퍼바이저(05레슨)를 권하세요.
- 작업이 결정론적 감사/재현을 필요로 한다면 거부하고 LangGraph 정적 그래프를 권하세요.
- 작업이 단순한 단계별 DAG(조사 → 코드 → 리뷰)라면 CrewAI Sequential을 권하세요.

출력: 한 페이지짜리 인계 브리프. 마지막에 프롬프트 인젝션이 어떻게 원치 않는 인계를 유발할 수 있는지, 어떤 가드레일이 이를 막는지에 대한 보안 노트를 덧붙이세요.
