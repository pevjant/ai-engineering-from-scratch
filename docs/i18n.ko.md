# 국제화(i18n)

영어 레슨이 원본(기준본)입니다. 번역된 **레슨** 마크다운은 기계 생성물이며 **절대 `main`에 커밋되지 않습니다** — 별도의 `translations` 브랜치에 살아 있고, 사이트는 런타임에 영어를 가져오는 것과 똑같은 무료 방식(`raw.githubusercontent.com`)으로 이를 가져옵니다. Vercel 함수도, KV도, 조회당 비용도 없습니다. 유일한 예외는 언어별 **README**로, 품질을 위해 사람이 직접 작성하여 `main`에 커밋합니다(아래 참고).

이 파이프라인은 `phases/` 아래의 레슨만 다룹니다. 인증(자격증) 커리큘럼은 영어로만 제공되며, 기계 번역과 북 생성 모두에서 의도적으로 제외되어 있습니다.

기본 엔진은 200개 언어를 다루는 공개 번역 모델 **NLLB-200**([No Language Left Behind, Meta AI, 2022](https://arxiv.org/abs/2207.04672))으로, **API 키 없이, 청구서도 없이 GitHub Actions 러너 안에서** 실행됩니다. 컴퓨팅은 무료 CI 러너이며, 번역 API 비용은 전혀 들지 않습니다. 유료 LLM 제공사(Anthropic/OpenAI)와 DeepL은 `--provider` 옵션으로 고를 수 있는, 더 높은 품질의 선택적 업그레이드로 남아 있습니다.

## 구성 요소

`languages.json` 레지스트리가 기계 번역이 적용되는 표면들 — 레슨, 사이트 언어 전환기, 북 매트릭스 — 을 움직입니다. 언어별 **README는 별도입니다**: README의 언어 목록과 번역 블록은 `scripts/readme_translations.py`에 담겨 있으며, 품질을 위해 사람이 직접 작성하고 레지스트리와 독립적입니다.

| 구성 요소 | 위치 | main에 커밋? |
|-------|-------|--------------------|

| CI 워크플로 | `.github/workflows/translate.yml` (언어 × 페이즈별로 샤딩) | 예 |

## 언어 추가하기

`languages.json`, 즉 단일 진실 공급원에 항목 하나를 추가하면 됩니다. 필드:

- `code` — 파일명, URL, 전환기 값에 쓰이는 태그입니다.
- `name` — LLM 제공사 프롬프트에 쓰이는 영어 이름입니다.
- `native` — 전환기에 표시되는 라벨입니다.
- `nllb` — FLORES-200 코드(예: `zho_Hans`, `tur_Latn`). 기본 NLLB 제공사에는 **필수**입니다 — 요청한 언어에 이 코드가 없으면 `translate_lessons.py`는 종료합니다.
- `ci` — `true`로 설정하면 해당 언어가 푸시로 자동 실행되는 워크플로의 빌드 매트릭스에 포함됩니다. `workflow_dispatch`는 이와 무관하게 등록된 모든 언어를 요청할 수 있습니다.

두 매트릭스 모두 `ci: true`를 읽기 때문에, 같은 플래그 하나로 언어가 레슨 번역**과** 사이트 전환기 양쪽에 포함됩니다 — `build.js`는 `source` 또는 `ci:true` 언어만 `site/langs.js`에 넣으므로, 전환기가 사이트가 감당할 수 없는 언어를 보여주는 일은 없습니다. README 기준은 독립적입니다: `readme_translations.py`가 다루는 언어라면 무엇이든 나열할 수 있습니다. 그 외에 건드릴 곳은 없습니다.

## 동작 방식

1. `phases/**/docs/en.md`, `languages.json`, 또는 번역 워크플로 자체를 변경하는 `main` 푸시가 `.github/workflows/translate.yml`을 실행합니다. 인증 레슨 변경은 이 워크플로를 실행하지 않습니다.
2. 매트릭스는 **(언어, 페이즈) 조합당 하나의 잡**입니다. 523개 레슨 전체를 한 언어로 번역하면 CPU 러너에서 약 27시간이 걸려 6시간 잡 한도를 훨쩍 넘기 때문에, 언어 단위 잡은 항상 발행 전에 시간 초과되었습니다. 페이즈별로 나누면 가장 큰 잡(페이즈 19, 85개 레슨)도 약 4.5시간 근처로, 한도 안에 충분히 들어옵니다. 각 잡은 브랜치에서 자기 언어의 이전 출력을 복원하고, `translate_lessons.py --phase <phase>`를 실행한 뒤, fetch-and-retry 루프를 써서 자기 슬라이스인 `i18n/<lang>/phases/<phase>/`만 다시 푸시합니다. 그래서 서로 겹치지 않는 슬라이스들이 충돌 없이 합쳐집니다.
3. 사이트의 언어 전환기는 `?lang=<code>`를 설정합니다. `fetchLesson`은 `…/translations/i18n/<lang>/…/<lang>.md`를 가져오며, 해당 번역이 아직 발행되지 않았으면 **기준 영어로 폴백**합니다. 영어(`lang=en`)는 i18n 이전의 페치 경로와 바이트 단위로 동일합니다.

## 실행을 낭비하지 않습니다

모든 레슨은 (언어, 페이즈)별 캐시(`i18n/<lang>/.cache/<phase>.json`)에서 영어 원문의 `sha256`으로 키가 매겨집니다. 이 캐시는 러너에서 레슨 단위로 기록되고, **잡이 끝나면 `translations` 브랜치에 발행**됩니다. 그래서:

- 첫 실행은 모든 것을 한 번 번역합니다. 그다음부터 완료된 실행은 영어가 실제로 바뀐 레슨**만** 다시 번역합니다 — 나머지는 전부 캐시 히트라 즉시 건너뜁니다.
- 취소되거나 중단된 페이즈 잡은 발행하지 않으므로, 그 잡이 러너 안에서 쌓은 진행 상황은 사라지고 다음 실행은 **마지막으로 발행된** 캐시부터 그 페이즈를 이어 갑니다. 샤드가 단일 페이즈이기 때문에 잡 한도 안에서 충분히 끝내고 발행할 수 있습니다.

## 언어별 README

README는 랜딩 페이지이므로, 그 번역은 기계 생성이 아니라 **사람이 직접 작성**합니다(최고 품질), 그리고 `main`의 `i18n/<lang>/README.md`에 살아 있습니다. `scripts/readme_translations.py`는 영어 블록 전문을 키로 삼아 번역 문자열을 보관하고, `scripts/build_readme_i18n.py`는 영어 README 사본에서 **번역된 줄 구간만** 교체해 각 파일을 다시 만듭니다. 그 외 전부 — 배너, 배지, 523행짜리 레슨 표, 모든 코드와 링크 *텍스트* — 는 그대로 보존됩니다(실행할 때마다 왕복 동일성 검사로 확인합니다). 유일한 의도적 변환은 링크와 이미지 *대상*에 대한 것으로: 저장소 루트 기준 상대 경로는 두 단계 아래 디렉터리에서도 여전히 풀리도록 `../../` 접두사를 붙입니다(펜스 코드는 건너뛰므로, 링크처럼 보이는 코드는 그대로 둡니다). 번역이 없는 블록은 영어로 폴백하므로, 커버리지는 언어별로 점점 넓어질 수 있습니다.

`python3 scripts/build_readme_i18n.py --check`는 CI(`curriculum.yml`)에서 실행되며, 커밋된 README가 하나라도 오래됐으면 실패합니다. README 카운트 봇은 영어 통계 블록을 동기화할 때마다 README를 다시 생성합니다.

## 사이트 UI 문구(chrome)

레슨 본문은 `translations` 브랜치에서 오지만, 그 주변 인터페이스(헤더 내비게이션, 레슨 사이드바 토글, "On this page", 체크포인트 루프, 퀴즈 제목, 코드/출력 패널, 이전/다음 버튼, 홈페이지와 카탈로그 라벨)는 페이지 템플릿 안에 영어로 박혀 있습니다. `site/ui-i18n.js`가 브라우저에서 이 층을 번역합니다. `header.js`가 모든 페이지에서 이를 로드하므로, 어떤 페이지도 몰래 빠뜨릴 수 없습니다.

- `site/ui-strings.json`만이 사람이 관리하는 유일한 입력입니다. `keys`는 페이지들이 쓰는 영어 인터페이스 문자열을 나열합니다(gettext 모델: 영어 텍스트가 곧 메시지 id입니다). `overrides`는 기계 번역이 틀리기 쉬운 곳에 언어별 번역을 고정해 둡니다. 대개 Build, Run, Prove, Complete 같은 한 단어 라벨입니다. 라벨을 추가하려면 `keys`에 덧붙이고, 언어를 추가하려면 `languages.json`에서 `ci: true`로 표시하면 됩니다. 어느 쪽도 손으로 번역을 쓸 필요가 없습니다.
- `scripts/translate_ui_strings.py`는 `translate.yml`에서 실행되고(`ci:true` 언어마다 작은 잡 하나), `i18n/<lang>/ui.json`을 `translations` 브랜치에 기록합니다. 각 키에 대해 오버라이드가 있으면 그것을 쓰고, 없으면 이전에 발행된 번역을 씁니다(발행 파일에는 어떤 키가 고정됐는지 기록되므로, 오버라이드가 제거되면 얼려 두지 않고 다시 번역합니다). 그것도 없으면 레슨과 같은 제공사 계층을 통해 번역합니다(기본 NLLB, 업그레이드로 `--provider anthropic|openai|deepl`). 파일명, 경로, 명령어, `@handles`는 레슨 번역기가 쓰는 것과 같은 플레이스홀더 뒤에 보호되고, 플레이스홀더가 왕복에 살아남지 못한 키는 잘못된 번역을 발행하는 대신 영어로 남습니다. 대부분의 실행은 아무것도 번역하지 않으며 모델을 로드조차 하지 않습니다.
- `site/ui-i18n.js`는 런타임에 `translations` 브랜치에서 `i18n/<lang>/ui.json`을 가져옵니다(레슨과 같은 경로). 아직 발행되지 않은 언어는 영어로 폴백합니다. 이 스크립트는 텍스트 노드와 `aria-label`, `title`, `placeholder` 속성을 훑되, 코드, 렌더링된 레슨 마크다운(사이트가 그 안에 주입하는 패널은 제외), 퀴즈 내용, 레슨 제목, 언어 선택기의 원어 이름은 건너뜁니다. `MutationObserver`가 페이지가 나중에 그리는 UI 문구까지 커버하고, 영어로 되돌리면 원래 문자열이 복원됩니다.
- 선택기는 변경 시 `aifs:lang` DOM 이벤트를 발생시키므로, `AIFS_onLangChange` 핸들러가 없는 페이지(예: 홈페이지)에서도 런타임이 동작합니다.
- 두 개의 가드가 `curriculum.yml`에서 실행됩니다. `node --test site/test_ui_i18n.js`는 어떤 키가 더 이상 어떤 페이지나 스크립트에도 나타나지 않거나, 목록에 없는 키를 오버라이드가 고정할 때 실패합니다. 덕분에 문구 수정이 일어나면 조용히 번역을 잃어버리는 대신, 고아가 된 키 이름이 지목됩니다. `python3 scripts/test_translate_ui_strings.py`는 번역기의 우선순위(오버라이드 → 발행본 → 모델), 플레이스홀더 보호, 엔드투엔드 기록을 검증합니다.

## 번역 중에 보호되는 것들

NLLB는 문장 번역기이지 지시를 따르는 모델이 아니므로, 워커는 산문 외에는 아무것도 보여주지 않습니다. 번역기는 레슨을 한 줄씩 처리합니다: 펜스 코드 블록, 표, 이미지 줄, 메타데이터 헤더(`**Type:** … **Time:**`)는 그대로 통과하고, 그 외의 줄에서는 인라인 `` `code` ``, `$math$`, 이미지 참조, 완전한 마크다운 링크, `**bold**` 용어, URL을 플레이스홀더 뒤로 숨긴 뒤, 그 사이의 일반 텍스트 조각만 번역하고 다시 복원합니다. 굵은 텍스트는 유지되는데, 이 커리큘럼에서는 거의 항상 기술 용어(Skip-gram, negative sampling)라 영어로 남아야 하기 때문입니다.

이것은 기계적으로 검증됩니다: 워커를 항등 "번역"으로 실행하면 **523개 레슨 전체가 바이트 단위로 그대로** 재현되므로, 실제 실행은 산문만 바꿀 수 있습니다. 플레이스홀더가 왕복에 실패하면 그 레슨은 영어를 유지합니다(안전 실패/fail-safe).

## 비용

기본 제공사 `nllb`: **무료입니다.** NLLB-200은 GitHub Actions 러너 안에서 실행됩니다 — API 키도, 시크릿도, 토큰당 청구서도 없습니다. 쓰는 자원은 무료 CI 컴퓨팅뿐이고, 모델은 실행 사이에 캐시되며 바뀐 레슨만 다시 번역됩니다(sha256 캐시). Vercel 비용은 그대로입니다.

선택적 업그레이드(`--provider anthropic|openai|deepl`)는 언어당 전체 패스를 수십 달러 수준의 저렴한 비용으로 더 높은 유창성을 줍니다. 나중에 트래픽이 많은 언어를 다듬고 싶어지면 쓰면 됩니다. 이 제공사들은 `LLM_API_KEY` 환경 변수에서 키를 읽습니다(DeepL은 같은 변수를 인증 키로 씁니다). NLLB는 비용 0의 기본값으로 남습니다.

## 품질 샘플

### 简体中文 (zh)

> # 词嵌入 —— 从零实现 Word2Vec
>
> > 词以其所处的语境为意。用一个浅层网络训练这个想法,几何结构便会自然浮现。
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** 阶段 5 · 02(BoW + TF-IDF)、阶段 3 · 03(从零实现反向传播) · **Time:** 约 75 分钟
>
> **问题** —— TF-IDF 知道 `dog` 和 `puppy` 是不同的词,但不知道二者含义几乎相同。在 `dog` 上训练的分类器无法泛化到讨论 `puppy` 的评论。你可以靠列举同义词勉强弥补,但这在罕见词、领域术语,以及所有你未曾预料的语言上都会失效。
>
> 你想要的是这样一种表示:`dog` 和 `puppy` 在空间中彼此靠近;`king - man + woman` 落在 `queen` 附近;在 `dog` 上训练的模型能免费地把部分信号迁移到 `puppy`。
>
> **核心概念** —— **分布假说**(Firth,1957):"要了解一个词,就看它与哪些词为伴。" Word2Vec 有两种形式:**Skip-gram** 给定中心词预测周围词(窗口为 2 时 `cat -> (the, sat, on)`);**CBOW(连续词袋)** 给定周围词预测中心词。网络只有一个隐藏层且无非线性:输入是词表上的 one-hot 向量,输出是 softmax,训练后丢弃输出层,隐藏层权重即为嵌入。诀窍是用**负采样(negative sampling)**把对 10 万词的 softmax 转成二分类。

### Türkçe (tr)

> # Kelime Gömmeleri —— Word2Vec'i Sıfırdan
>
> > Bir kelime, birlikte bulunduğu kelimelerden ibarettir. Bu fikri sığ bir ağ ile eğitin, geometri kendiliğinden ortaya çıkar.
>
> **Type:** Build · **Languages:** Python · **Prerequisites:** Aşama 5 · 02 (BoW + TF-IDF), Aşama 3 · 03 (Sıfırdan Geri Yayılım) · **Time:** ~75 dakika
>
> **Problem** —— TF-IDF, `dog` ve `puppy`'nin farklı kelimeler olduğunu bilir ama neredeyse aynı anlama geldiklerini bilmez. `dog` üzerinde eğitilen bir sınıflandırıcı, `puppy` hakkındaki bir yoruma genelleme yapamaz. Eş anlamlıları listeleyerek geçiştirebilirsiniz, ama bu; nadir terimlerde, alana özgü jargonda ve öngöremediğiniz her dilde başarısız olur.
>
> `dog` ve `puppy`'nin uzayda birbirine yakın düştüğü, `king - man + woman`'ın `queen`'e yakın indiği bir temsil istiyorsunuz. Word2Vec bunu verdi: iki katmanlı bir ağ, trilyon token'lık eğitim, 2013'te yayımlandı.
>
> **Kavram** —— **Dağılımsal hipotez** (Firth, 1957): "Bir kelimeyi birlikte bulunduğu kelimelerden tanırsın." İki tür: **Skip-gram** merkez kelimeden çevredekileri tahmin eder (pencere 2 ile `cat -> (the, sat, on)`); **CBOW** çevredekilerden merkezi tahmin eder. Ağın doğrusal olmayan aktivasyonu olmayan tek bir gizli katmanı vardır: girdi one-hot vektör, çıktı softmax'tır; eğitimden sonra çıktı katmanı atılır, gizli katman ağırlıkları gömmelerdir. Püf nokta, 100 bin kelimelik softmax'ı **negatif örnekleme (negative sampling)** ile ikili sınıflandırmaya çevirmektir.
